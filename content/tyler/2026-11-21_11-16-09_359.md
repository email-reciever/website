### 一种新的流动状态

通常，在 ViteConf _Stays_ at ViteConf 会发生什么。 （至少那是埃文你在酒吧桌上跳舞时对我尖叫的东西。）

但是我们在 Stackblitz 主题演讲中得到了一些重大新闻，所以让我们在 [Codeflow](https://stackblitz.com/codeflow) 上溢出茶叶——一种新的一键式 GitHub 集成，将您的桌面 VS Code 环境带入浏览器。

**我们是如何到达这里的：** 与 CodeSandbox 类似，Stackblitz 最初是一个在线开发环境，非常适合快速旋转简单的项目。 但在过去的三年里，他们一直在努力使用 Codeflow 构建“Figma for Web 开发人员”。

和大多数怀孕期为 36 个月的东西（例如 [Canadian Basking Shark](https://www.dfo-mpo.gc.ca/species-especes/profiles-profils/baskingshark-requinpelerin-atl-eng.html#:~:text=Reproduction,2%2D3%20years.)）一样，似乎值得等待。

这是因为它不仅将本地 VS Code env 带入浏览器，而且还将您的所有设置、扩展和工具链带入浏览器——同时（据说）启动比本地 env 快 10 倍，并且默认是安全的。

**它是如何工作的：** 魔法和 [web containers](https://blog.stackblitz.com/posts/introducing-webcontainers/) 的非常具体的组合。

让我们看看 Codeflow 的一些潜在用例：

*   创建和查看拉取请求。 单击 GitHub 中的一个按钮会在浏览器中打开桌面版 VS Code，您可以在其中运行 Code Live 和 Review/进行更改，而无需在本地运行或存储任何内容。
    
*   OSS 维护者可以轻松地重现和修复问题，而无需在本地下载和运行代码。
    
*   CodeFlow的[Web Publisher](https://twitter.com/stackblitz/status/1579877556576169986?s=20&t=baH-wOzt470aTo6ei0_T9Q)为您提供了一个单一的文件编辑视图，以便轻松地将文档贡献给任何OSS项目。
    

**底线：** 在短期内，Codeflow 的目标是简单地“消除本地切换的痛苦”。 但从长远来看，很容易看出它们（连同 GH 代码空间和其他代码空间）是如何努力让本地主机永久退休的。

Swyx在引导他内心的莎士比亚时预测了这一点[post-Localhost future](https://www.swyx.io/the-end-of-localhost)，并写了“所有云都是一个暂存的环境，所有的笔记本电脑都是客户端。” 我们可能比我们想象的要快。

本周趋势
------------------

![jasmine vs jest vs mocha vs vitest](https://bytes.dev/images/content/test-runner-trend.jpg)

测试跑步者趋势 - 数据 [npmtrends.com](https://npmtrends.com/jasmine-vs-jest-vs-mocha-vs-vitest)

如果软件开发人员喜欢一件事，那就是 100% 测试覆盖的虚假安全感。 但是如果没有一个优秀的测试跑步者，你就无法做到这一点，所以让我们仔细看看测试天灾的 4 骑士，以更好地了解我们去过哪里以及我们可能去哪里。

*   **Jasmine：** OG 测试跑步者。 虽然它从来都不是最受欢迎的，但它是第一个出现在现场的，并且一直是一个强大、稳定的选择。 趋势表明，现在它绝对不是新项目的首选选择，但它是稳定的，如果您已经在使用它，它应该在未来几年保持正常运行。
    
*   **Mocha:** 当 Jasmine 是第一个时，节点库的经验法则总是“如果 TJ HolwachuchayHfdchuck（这个姓氏是不可能拼写的）构建它……他们会来的。” 他们做到了。 Mocha 是多年来最受欢迎的试运行者，今天仍在增长。 你去吧，格伦·可可。
    
*   **Jest：**你可能在想，“WTF发生在2019年？” （与所有看过电影_cats_的人一起）。 那时，Jest（由 Facebook 创建）已经存在了一段时间，但最初受到大多数开发人员的鄙视——直到 Chrisoph Nakazawa 成为其（收养的）父亲。 将其与 Create React 应用程序的版本（它是默认的测试运行器）结合起来，您可以看到 Jest 的流行性爆发的原因。 像任何流行的工具一样，它得到了相当多的批评，人们已经开始寻找新的神。
    
*   **VITEST：** 由于我们仍然处于 ViteConf 的高度，我们决定投入 Vite，这是一个新的、Vite 驱动的测试框架，它已经得到了大量的炒作。 它速度快，兼容开玩笑，并支持 ESM，因此即使它只是雷达上的一个小插曲，我们预计未来几年将出现迅速增长的速度。

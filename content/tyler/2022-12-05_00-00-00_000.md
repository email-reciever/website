### 基准营销 101

FOMO是一种毒药。 这就是为什么，无论我们多么理性，我们的蜥蜴大脑根本无法抗拒新 OSS 工具的“10 倍闪电般的快速”基准。

OSS 的创作者知道这一点，这就是为什么他们中的一些人花费大量时间制作始终显示他们的工具是**#1最耀眼的基准。 可能会引起一些真正的混乱。

Vercel 最近 [came under fire](https://github.com/yyx990803/vite-vs-next-turbo-hmr/discussions/8) 对于他们的 Turbopack-VS-Vite 基准测试，BUN 受到质疑（但主要是 [defended](https://twitter.com/Steve8708/status/1561417527300788224) 的 SSR 基准测试，而且列表还在继续。 评估各种 OSS 声明。

让我们从一些**红旗开始吧🚩:**

*   **不公开：**如果您无法自己运行基准测试，您可能应该持怀疑态度。
    
*   **缺乏上下文：** 基准是否包含有关其假设的上下文？ 衡量“Hello World”的性能可能与巨大的应用程序大不相同。
    
*   **不明确的方法：**诸如基准运行在哪台机器上，它们运行了多少次，以及涵盖了哪些用例，这一切都很重要。 如果这些东西不清楚，你的蜘蛛感应该会消失。
    

以下是我们喜欢看到的一些**最佳实践🤩：**

*   **每个人都同意测量什么：** 标准化基准 FTW。 对于像浏览器这样的大型和更成熟的项目来说，代码化的标准更为常见——但我们越能达成一致，就越好。
    
*   **您对自己进行基准测试：**这是进行真正🍎的比较的最佳方式，透明地进行自己的比赛有很多话要说。
    

**底线：** 在一个完美的世界中，我们将拥有某种第三方基准来衡量每个基准的质量。 但由于这份工作听起来像是真正的地狱，我们可能只需要继续尝试自己破译数据——并庆祝 [great benchmarking](https://twitter.com/manucorporat/status/1588506463986933761?s=20&t=9KMSKYd3IghbzzZHekykAg) 帮助我们所有人获胜的时代。

#### 赞助[JSworld Conference 2023](https://jsworldconference.com/?utm_source=newsletter&utm_medium=bytes&utm_campaign=jsworldlaunch)

记录什么？

for (var i = 0; i < 5; i++) {
setTimeout(() => console.log(i), 1000)
}
    

为你们所有的老头回去一点。 这曾经是每个人最喜欢的 JavaScript 面试问题。

此代码将记录 `5` 5 次。

原因是我们用 `var` 声明了我们的变量，它是函数范围的。 当我们给 `setTimeout` 的函数运行时，`i` 已经是 `5` 并且每个函数都会引用相同的变量。 要解决此问题，请使用 `let` 的块范围，并将为我们的 for 循环提供自己的每次迭代 `i`。

for (let i = 0; i < 5; i++) {
setTimeout(() => console.log(i), 1000)
}

我们学到的 10 件事 100
--------------------------------

就像现实生活一样，我们的晚年给我们带来了智慧、视角和 IBS 的完美结合。 我们将尝试与您分享过去 100 周中我们学到的 10 件事的列表中的所有三个。

**1\。 良好的框架借用，优秀的框架窃取。** 本月早些时候，当他们 [announced](https://twitter.com/leeerob/status/1521659624516030466) 将使用 Remix 的杀手功能 [nested routes](https://remix.run/docs/en/v1/guides/routing#what-is-nested-routing) 中的一项功能 [nested routes](https://remix.run/docs/en/v1/guides/routing#what-is-nested-routing) 到下一个路由器时，他们证明了它的伟大之处。 但是，嘿，框架竞争/创新对开发人员来说非常棒，所以我们没有抱怨。

**2\。 如果我们的“发现错误”部分中有一个无意的错误，我们将收到来自每个人的电子邮件。** 谢谢你们（你们中的所有 101,741 人）[your vigilance](https://www.youtube.com/watch?v=xjyC5pv-hGc)。

**3\。 Rust 并没有像我们想象的那样吃网。

**4\。 在您的投资组合中只有高增长的科技股是一个坏主意。** 询问您所在的初创公司的清算偏好可能会有所帮助。

**5\。 开发人员喜欢编写 CSS……只要您可以欺骗他们认为他们正在编写 HTML。** 向 Tailwind 致敬，以解决这一点并成为游戏中最受欢迎的框架。

[Sleuth.io](https://www.sleuth.io/) 实际上可以使您的团队更有效率
-------------------------------------- --------------------------------------

跟踪“开发人员生产力”是愚蠢的。

两个原因：

1.  开发人员讨厌它（监视我，看看我是否是一个“高效的开发人员”，实际上使我的生产力降低了）
2.  它不起作用（“谁写的代码最多/关闭最多的门票是最好的开发人员”是……真的很愚蠢吗？）

这就是为什么侦探是最好的。 它不跟踪开发人员的生产力——它只衡量 _team_ 输出。 它实际上有效。

那是因为它捕捉到了你团队的 [DORA metrics](https://www.sleuth.io/post/dora-metrics)——多项研究表明，这是唯一真正重要的统计数据。 没有毫无价值的虚荣指标，也没有个人统计数据。

与大多数仅收集 Git 或发布跟踪器数据的服务不同，Sleuth 会自动为您（包括部署）收集所有这些数据。 所以你可以相信这些数字是合法的。

还值得注意的是，**Atlassian 使用侦探。** 这就像成为厨师 Gordon Ramsey 最喜欢的餐厅——如果它对他们有用，它可能也会对您有所帮助。

我们学到的 10 件事 100 年级——第 2 部分
----------------------------------------

**6\。 共有三种方式可以为开源提供资金。** 1) GitHub 赞助商 (LOL)。 2) 成立一家假装非常真实的公司并从 VC 筹集资金。 3）通过Vercel获取[hired](https://vercel.com/blog/vercel-welcomes-rich-harris-creator-of-svelte)和/或[acquired](https://vercel.com/blog/vercel-acquires-turborepo)。 我们不制定规则。

**7\。 我们不够谈论 Bruno CSS。** 这份时事通讯主要是关于 JavaScript（并以小众幽默的方式处理我们的童年创伤），但 CSS 就在我们眼前有一个 [Aubrey Graham style glow-up](https://hollywoodlife.com/pics/hot-male-celebrities-before-and-after-transformation-photos/drake-19/)。 经过数十年的痛苦，一堆令人惊叹的新 CSS 功能是 [landing this year](https://web.dev/state-of-css-2022/) — 级联层、容器查询、颜色函数等等。 一方面，我很高兴写少一点 JS。

**8\。 你的孩子长得太快了。** 人们试图警告你，但你眨眼——突然 Deno（我们在第一期中写到）是 [turning 4 years old](https://twitter.com/deno_land/status/1525119512277725184?s=20&t=qBjc-m3wNITeygnuKInjNw)，与 Netlify 合作提供 [Edge Functions](https://www.netlify.com/blog/announcing-serverless-compute-with-edge-functions/)，并尖叫着观看另一集 Daniel Tiger。

**9\。 任何可以生活在边缘的东西，最终都会生活在边缘。**首先它是 JavaScript，现在它是数据库，这要归功于 Cloudflare 带来的 [SQL to the edge with D1](https://blog.cloudflare.com/introducing-d1/)。 我们正在经历边缘的辉煌岁月，就像生活中的大多数事情一样，Lady Gaga 已经为这一刻写了 [the perfect song](https://www.youtube.com/watch?v=QeWBS0JBNzQ)。

**10\。 在我妈妈的地下室制作 JavaScript 模因比我们想象的要耗时得多。** 但值得我们每个星期天晚上感到的极度焦虑。 感谢阅读❤️

🔬 发现错误解决方案 — [CarbonQA](https://carbonqa.com/?utm_source=bytes&utm_medium=ql&utm_campaign=apr4)
--------------------------------------------------------- ---------------------------------------------------------

for 循环通过为每个迭代赋值给变量一个值而工作，但无法重新分配用 `const` 定义的变量。 相反，我们应该使用 `let` 来定义我们的变量。

函数因子(n) {
让结果 = 1；
for (let i = 1; i < n + 1; i++) {
结果 *= i；
}
返回结果；
}

[Basecamp releases Hotwire](https://hotwire.dev/)
---------------------------------------------

![DHH](https://bytes.dev/images/content/dhh.png)

Hotrod，认识 Hotwire

**首先，他们为您带来了 Ruby on Rails……** 早在 2004 年。然后@DHH 和朋友们得到了 [a few million bucks from Jeff Bezos](https://m.signalvnoise.com/the-deal-jeff-bezos-got-on-basecamp/)，开始赛车 F-1 赛车，并在 Startup Equity 上开发了 [terrible takes](https://twitter.com/callmevlad/status/1233181204452528129)。

**但现在他们通过新版本 Hotwire 回到了技术领域**——Hotwire 是一种新的、JavaScript 轻松构建 Web 应用程序的方法。 这是他们用来实现 Hey.com 的所有前端元素的东西，这是您可能因为 [slow](https://twitter.com/ryanflorence/status/1301870899671437312) 不是免费而使用的付费电子邮件服务的。

**它是如何工作的？** Hotwire 发送 HTML 而不是 JSON 在线，这（理论上）允许更快的首次加载页面、更少的 JavaScript、服务器上的模板渲染和更简单的开发体验。

它是三个框架的集合——**Turbo、Stimulus 和 Strada**——它们共同提供了上述所有好处，而不会（再次，理论上）牺牲传统 SPA 的速度或响应能力。 让我们仔细看看每一个。

*   [**Turbo:**](https://turbo.hotwire.dev/) 一组 4 种“互补技术”，大大减少了您需要编写的自定义 JavaScript 数量。 它加快页面更改和表单提交的速度，将复杂的页面划分为组件，并为您在 WebSocket 上流式传输部分页面更新。 Turbo 是 Hotwire 餐盘的肉和土豆。
    
*   [**Stimulus:**](https://stimulus.hotwire.dev/) 一个“适度”的 JavaScript 框架，可帮助您在需要时编写自定义 JS。 它实际上并没有呈现 HTML，但它确实为状态和布线等事物提供了一种“以 HTML 为中心”的方法。 这是热线的晚餐卷和馅料。
    
*   **STRADA:** 提供了用于移动混合应用程序的 Web 和本机部分相互通信的桥接工具。 它还没有发布，但听起来像是整个热线晚餐的肉汁。
    

如需更深入的潜水，请查看 Adam Wathan 的 [DHH’s appearance on the Full Stack Radio Podcast](https://fullstackradio.com/151)。

### 底线

Hotwire 是游戏规则的改变者吗？ _可能_不是。 是否值得一试，因为它是构建 Web 应用程序的一种有趣方法，并且您想对冲自己的缺点，以防它们实际上是正确的？ 当然。

黑客一团糟

**Adobe 上周正式停产 Flash**，标志着 1993 年 PJS（JavaScript 之前）开始的时代的结束。当时，Flash 被称为 SmartSketch，是一家名为 FutureWave Software 的公司开发的矢量绘图应用程序。

该公司被 Macromedia 收购，并于 1996 年底重新命名为 Flash，其功能扩展到一个由两部分组成的系统——一个称为 Macromedia Flash 的图形和动画编辑器，以及一个被称为 Macromedia Flash Player 的播放器。

Adobe 于 2005 年收购了 Macromedia，这为接下来的 7-8 年迎来了 Flash 的黄金时代。 可悲的是，所有美好的事物都发生了，闪电侠的日子屈指可数。

Steve Jobs Flash 无法通过不断发展的网络进行创新和扩展，最终注定了它。 Flash 网站永远无法达到我们今天在网络上假装拥有的速度、可访问性、可靠性和移动友好性的可接受标准。

js 提示 - React 的 Useref 钩子
-----------------------------

`React.useState` 的营销宣传是它允许您将状态添加到功能组件。 这是真的，但我们可以进一步分解它。 从根本上说，`useState` 钩子给了你两件事——一个将在渲染中持续存在的值和一个用于更新该值并触发重新渲染的 API。

const [值，setValueAndRerender] = react.useState(
'初始价值'
)
    

在构建 UI 时，两者都是必要的。 如果没有能够在渲染中保留值的能力，您将失去在应用中拥有动态数据的能力。 如果没有更新值并触发重新渲染的能力，UI 将永远不会更新。

现在，如果您有一个不处理任何 UI 的用例，因此您不关心重新渲染，但您确实需要在渲染中保留一个值怎么办？ 在这种情况下，就像您需要 `useState` 的一半，让您在渲染中保留一个值，而不是触发重新渲染的另一半 - 类似于此。

函数 UsePersistentValue (InitialValue) {
返回 react.useState({
当前：初始值
})[0]
}
    

剧透警报，我们的自定义 `usePersistentValue` 钩子的功能与内置的 `React.useRef` 钩子非常相似。

如果您想将状态添加到在渲染中持续存在的组件中，并且可以在更新时触发重新渲染，请使用 `useState`（或 `useReducer`）。 如果要在渲染中持续存在但在更新时不会触发重新渲染的组件的状态，请使用 `useRef`。

有关 `useRef` 的更多信息（以及 `useState` 与 `useRef` 相似的更深入解释），请访问 [Understanding React’s useRef Hook](https://ui.dev/useref)

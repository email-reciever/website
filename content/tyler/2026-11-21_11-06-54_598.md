### JavaScript 开发人员如何处理数据

很长一段时间，人类一直在看星星并问自己像这样的普遍问题，例如，我们是孤独的宇宙吗？

有人告诉我，获得前两个答案的最佳方法是尝试 DMT。 但不幸的是，获得最后一个问题的答案并不是那么简单。

这就是为什么[Directus](https://directus.io/)在几个月前创建了这种数据状态调查的原因——因为他们（和我们一起）对2024年专业JavaScript开发人员的处理方式感到好奇。因此，不用多说，让我们深入了解我们的调查中的前五个要点：

**1\。 Postgres 赢得了人气竞赛。 当您考虑 Postgres 充满活力的扩展生态系统、活跃的开源社区和一流的 JSON 支持时，看看 JS 社区如何完全接受它是有意义的。

**2\。 开发人员喜欢他们的数据_relational_。 （第十）。 除非您是亚马逊试图在 Prime Day 从您的数据库中挤出每一盎司的性能，否则为 NoSQL 设计最佳数据模型的前期成本使关系数据库看起来更具吸引力。

**3\。 每个人都需要一个数据库，但没有人愿意管理它们。** 开发人员绝大多数选择由 AWS、GCP 或 Supabase 或 PlanetScale 等服务提供商托管的解决方案。 事实证明，没有人愿意处理维护自己的数据库所带来的 [the problems](https://www.youtube.com/watch?v=RfiQYRn7fBg)，我们不会责怪你。

**4\。 REST 回来了，宝贝。** 老实说，它从来没有 _really_ 离开，而是有一段时间，JS 社区使用 GraphQL 或直接从客户端代码运行他们的“实时”数据库。 但现在感觉就像我们已经完成了完整的 MidWit 模因，并立即用 RESTful API 包装了我们的 DBS，因为 94% 的受访者将其作为使用 API 的首选方式。

**5\。 开发人员并不真正关心成本。** CFO 正在阅读本文，但大多数开发人员在选择数据库托管解决方案时并不认为成本是主要因素（令人震惊，我知道）。 事实证明，开发人员往往更关心性能、可靠性和易用性——至少在他们被提升到 VP 级别之前，他们的奖金与节省成本有关。

**底线：**如果您对纯粹的后端开发人员的受众进行调查，您可能会在这里看到一些略有不同的答案。 但随着 JavaScript 继续吞噬世界，前端、后端和全栈之间的界限看起来比以往任何时候都更加模糊——因此（IMO）了解非传统后端开发人员在 2024 年更喜欢使用哪些工具更有趣（IMO）。

如果您想要更多有趣的见解，我们将在下周公开发布时发布完整调查结果的链接。

发现错误：解决方案
-----------------------

#### 赞助[Callstack](https://www.callstack.com/ebook/the-ultimate-guide-to-react-native-optimization)

`??` 运算符的优先级高于 `&&` 运算符。 这意味着表达式 `user && user.id ?? fallback` 等价于 `user && (user.id ?? fallback)`。 这不是我们想要的。 如果 `user` 是 `null` 或 `undefined`，我们希望返回 `fallback`，否则返回 `user.id`。

要解决此问题，我们需要使用括号来更改评估的顺序：

函数 getId(用户，回退) {
返回（用户 && user.id）？？ 回退；
}
    

甚至更好，只需使用可选链接：

函数 getId(用户，回退) {
返回用户？.ID？？ 回退；
}

### 为什么您认为我们目前正在从 NoSQL 到 SQL 的过渡，您认为这种趋势会持续到未来吗？

一句话：可靠性。 不是在“数据库不崩溃”的意义上，而是你知道你得到了什么。 显然，这超出了明显的“了解数据结构”，但更重要的是，SQL 是标准化的，并且已经被证明了几十年。 工程师们很清楚，它是完整的文档，并且有许多可供选择的口味（分布式、边缘、极光等）来支持大多数用例。 最后，我只是不认为许多大型企业的移动速度足够快，可以显着切换到 NoSQL……现在最初的浪潮已经消退，由于其资源丰富和可用的开发人员数量众多，他们选择继续使用 SQL。

– 本杰明·海恩斯，[Directus](https://directus.io/) 创始人兼首席执行官

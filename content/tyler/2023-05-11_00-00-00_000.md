### 不要称之为（虚拟）卷土重来

虚拟 DOM 已经听到了你在过去几年背后一直在说的所有卑鄙的话。

好吧，也许不是_you_，而是JS生态系统的很大一部分。 而且我并不是想用香肠指责，但是当里奇哈里斯在2018年将VDOM称为[pure overhead](https://svelte.dev/blog/virtual-dom-is-pure-overhead)时，许多批评就开始了。

但里奇提出了一些很好的观点。 VDOM 确实会产生更高的计算成本——因为与生活中最好的东西不同，差异并不免费。 这就是为什么像 Svelte 和 Solid.js 这样的下一代框架根本不使用一个的原因。

但是，如果有一种方法可以以原始 JavaScript 的速度获得 React 的 VDOM 的所有声明性优点呢？

这就是驱动 [Million.js](https://millionjs.org/) 的问题——由 Aiden Bai 创建的 React 的 VDOM 替代品，声称速度快了 70%。

**如何？** 不是按元素表示 DOM 元素，而是使用 [blockdom approach](https://github.com/ged-odoo/blockdom) 逐块执行。 在这种情况下，“块”是一个元素，它的所有静态内容和一些特殊的标签用于指示动态内容——有点像一个特殊的高阶组件。

您可以通过将它们包装在 `block()` 函数中从 React 组件创建块。 这意味着它们将使用Million.js vdom进行渲染，它使用[static analysis and dirty checking](https://millionjs.org/blog/virtual-dom#the-block-virtual-dom)以比传统差异更少的计算来更新DOM——大多数时候。

当您有大量静态内容且动态内容不多时，这种对 VDOM 的块方式非常快，但更多动态内容将导致更少的性能提升。

这就是为什么 Aiden 建议使用 Million.js 精细地而不是作为每个组件的灵丹妙药。 值得庆幸的是，使用 `block()` 功能很容易做到这一点。

**底线：** 也许我们还不需要把 VDOM 婴儿和洗澡水一起扔掉。

记录什么？

常量 myObject = {};
    
常量键 = 符号('键');
    
myObject[key] = '这是键的值';
    
console.log(myObject[symbol('key')]);
console.log(json.stringify(MyObject));
    

1.  `undefined` - `Symbol` 构造函数创建一个唯一值，因此用于设置 `myObject[key]` 值的 `Symbol` 与用于获取 `myObject[key]` 的值的 `Symbol` 不同。
    
2.  `{}` - `JSON.stringify` 在字符串化对象时忽略 `Symbol` 属性。
    

这对于在对象外部无法访问或修改的对象上创建私有属性很有用。 您可以阅读有关符号 [here](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol) 的更多信息。

### 混音的回归

Remix v2 刚刚问世，在该框架首次宣布筹集了 300 万美元的 VC 以组建 OSS 公司几乎整整两年后。

在过去的 23 个月里，在 Remix-land 发生了一个 _lot_，所以在我们深入了解 V2 亮点之前，让我们快速回顾一下。

*   **remix v1** 于 2021 年 11 月推出，作为“边缘优先的 Web 框架”推出，主要依赖于 `Request`、`Response` 和 `FormData` 等标准 Web API。
    
*   **React Router** 是整个 2022 年的一个长达数月的过程，其中 Remix 团队将 Remix 的所有数据 API 移至 React 路由器中。 这允许 RR 拥有整个应用程序的数据编排，并使 RR 开发人员轻松采用 Remix。
    
*   **Shopify 于 2022 年 10 月收购了 Remix**，以“为开发人员提供世界级的共享基础设施，以便他们可以专注于独特的业务需求和差异化因素。” 我不懂 Corp-Speak，所以我不知道 _exactly_ 这意味着什么——但我知道 remix 现在是构建 Shopify 管理应用程序的 [recommended way](https://shopify.engineering/shopifys-platform-is-the-web-platform)，而且 remix 不必再担心经营一家公司了。
    

这将我们带到了本月的 [Remix v2 release](https://remix.run/blog/remix-v2)，它有望成为有史以来最顺利的框架升级之一，这要归功于它们大量使用弃用警告和未来的标志。

大多数 Juicy 新功能已经在各种 V1 版本中推出——诸如“扁平”路由以简化嵌套布局、改进对各种 CSS 策略的支持以及同时执行 HMR 和 HDR 的新开发服务器。 但是 v2 确实带有全新的 `create-remix` CLI 体验，它应该明显更小、更快。

就是这样。 有人需要告诉 Remix 团队，简单、稳定的主要版本会为无聊的时事通讯内容提供帮助。 不确定他们的优先事项在哪里。

**底线：** 在两年内，Remix 已经从付费使用的产品转变为 VC 支持的 OSS 初创公司，再到 Shopify 的内部开源框架。 通过这一切，他们建立了一个充满激情的混音学家社区，他们仍然喜欢使用它为网络构建。 我们很高兴看到未来两年的发展方向。

发现错误：解决方案
-----------------------

#### 赞助[Datadog](https://www.datadoghq.com/bytes/)

Const Newsletter = "字节"
const tagline = "您每周的 JavaScript 剂量"
    
[通讯，标语].forEach((El) => Console.log(El))
    

得知此代码未执行，您可能会感到惊讶。 如果你尝试，你会得到一个错误——`Uncaught ReferenceError: tagline is not defined`。 但很明显，对吧？ 错了。

这是 _very_ 罕见的情况，不使用分号会咬你。 因为我们有一个字符串后面跟 _no_ 分号后面跟一个开口数组括号，所以 JavaScript 会像这样解释我们的代码，就好像我们试图从字符串中访问元素一样。

“您每周的 JavaScript 剂量”[通讯，标语].forEach();
    

当然，这会引发错误，因为标语没有定义。 要解决此问题，请在数组之前添加 `+` 符号。

Const Newsletter = "字节"
const tagline = "您每周的 JavaScript 剂量"
    
+[时事通讯，标语].forEach((el) => console.log(el))
    

这主要是一个笑话，但它确实有效……

相反，只需使用分号。

Const 时事通讯 = “字节”；
const tagline = "您每周的 JavaScript 剂量";
    
[时事通讯，标语].forEach((El) => Console.log(el));

------------------------------------------ ------------------------------------------

![Node.js 15](https://bytes.dev/images/content/node15.png)

展示所有你最喜欢的艺术家！ （瑞恩·达尔除外）

** OG JavaScript 运行时**上周为我们提供了一个主要版本，这意味着 Node.js 15 现在是获得所有有趣新功能的“当前”版本。 这也意味着，如果您仍在使用 Node 14，您要么是 N00B，要么是在 JavaScript-land (Gross) 之外拥有平衡、充实的生活的人。

无论哪种方式，Node.js 14 将在本周晚些时候转移到长期支持 (LTS)，所以这里有 Node 15 的新功能：**

*   **未处理的拒绝不再发出警告**。 在节点 15 中，如果未设置 `unhandledRejection` 钩子，它将作为未捕获的异常引发并_终止应用程序_（而不是像节点 V6 天后那样使用 `UnhandledPromiseRejectionWarning` 警告您）。 Node 根据“用户洞察调查”进行了此更改，因此请享受一年中这个时候实际听到您的声音的一件事……
    
*   **升级的 V8**（引擎，而不是果汁——每当我们提到 V8（引擎，而不是果汁）时，我们都会开这个玩笑，而且我们永远不会停止）。 Node 15 升级到 V8 8.6，它带来了改进的性能和一些新的（ISH）JavaScript 特性，比如逻辑赋值运算符、`Promise.any()` 和 `String.prototype.replaceAll()`。
    
*   **实验支持** `AbortController` — 一种促进本地 Promise 取消的新方法。
    
*   **npm 7** 包含在我们上周写的节点 15 中。 **tl;dr** - npm 现在有工作区并支持 `yarn.lock` 文件，因为 _good 包管理器复制，但伟大的包管理器窃取。_

TWIH：AngularJS 打击了十年
-----------------------------

![AngularJS](https://bytes.dev/images/content/angularjs.png)

AngularJS 拥有 10 周年纪念日的开发者

10 年前的上周，AngularJS 向全世界公开发布。 它是由 [Misko Hevery](https://twitter.com/mhevery) 在 Google 创建的，作为允许网页设计师与前端和后端进行交互的工具。 Misko 最初将其命名为 GetAngular，因为 HTML 的 _angular_ 括号 (`<>`)。

但在 2009 年底，Getangular 似乎注定永远是一个小项目。 直到米斯科与他的老板打赌改变了网络历史的进程。

当时，Misko 正在为小型 Google 反馈团队工作，该团队在 6 个月内研制了 17,000 多行代码。 随着应用程序的代码库的增长，Misko 和他的队友们对测试和修改代码的难度感到沮丧。 所以 Misko 做了任何开发人员都会做的事情：他打赌他的经理可以在 2 周内使用他的项目 JavaScript 框架（GetAngular）从头开始重写整个应用程序。

Misko 输掉了赌注，因为从技术上讲，他花了整整 3 周的时间才重写了该应用程序。 在此过程中，他设法将代码库从 17,000 行减少到 1,500 行。 不错。

那时，经理意识到我们的男孩 Misko _Might_ 对整个“JavaScript 框架”的事情有所了解，并决定投资一些 Google-Bucks 来构建它。 我们不完全确定名称何时正式更改为 Angular，但它适用于所有人，除了 [this guy](https://twitter.com/getangular) 可以卖出相当多的手柄……经过几个月的工作，AngularJS 于 2010 年 10 月 20 日首次公开发布。

**那么这里的教训是什么？**如果你在一个大型、不守规矩的代码库上工作，只需停止你正在做的事情并快速发明你自己的 JavaScript 框架。 这样会容易得多。

js提示：== vs ===
------------------

> _我们这周要做实验。 lmk 如果您更喜欢这些长表单细分，或者如果您更喜欢简单的“发现错误”类型的帖子。

在编写软件时，更简单的解决方案几乎总是更好的解决方案。 如果为了使用一个功能，我首先必须学习并记住与之相关的 [list of rules](https://ui.dev/this-keyword-call-apply-bind-javascript)，我会尽力避免它。 不是因为该功能可能没有价值，而是因为我不相信自己会记住每一个细微的规则。 该逻辑是为什么我总是使用 Triple Equals (`===`) 而不是 Double Equals (`==`) 的主要决定。 他们都完成了类似的事情，但是三重等于的[Pit of Success](https://english.stackexchange.com/questions/77535/what-does-falling-into-the-pit-of-success-mean)要大得多，让我们看看原因。

### 身份运算符（三等于，===）

使用 Triple Equals `===` 时，您需要记住两个规则 - 严格等式（用于比较原始值时）和引用相等性（用于比较参考值时）。

### 严格平等

严格相等性检查 **Type** (`number`、`string`、`boolean` 等) ** 和 **VALUE** 是相同的。 如果 **type** 相同但不是该值，您将得到 false。 如果 **value** 是相同的，但不是类型，您将得到 false。 如果 **Value** 和 **Type** 都相同，您将得到 true。

5 === 5 // true。 相同的类型，相同的值。
5 === 4 // 假。 相同类型，不同值。
5 === "5" // 假。 不同的类型，相同的值。
    
true === true // true。 相同的类型，相同的值。
true === false // 假。 相同类型，不同值。
true === 'true' // 假。 不同的类型，相同的值。
    

看起来很简单，但是如前所述，当我们开始比较参考值（或不是原语的值）时，此规则会分解。

### 参考平等

正如我们在前面的示例中看到的，原始语由它们的值进行比较。 但是，如果您使用 Triple Equals 和参考值，它将比较 **References**（或内存中的点）。

{} === {} // 错误。 相同的类型，相似的值，不同的参考。 ❌
[] === [] // 假。 相同的类型，相似的值，不同的参考。 ❌
{ name: 'meg' } === { name: 'meg' } // 错误。 相同的类型，相似的值，不同的参考。 ❌
    

尽管上面的每个示例都具有相同的类型，并且 ****** 看起来是相同的值，但因为它们是引用值，JavaScript 会比较内存中的引用，而不是实际值。 在每个示例中，内存中的引用或位置都是不同的，这就是为什么我们总是会得到错误的原因。

我们可以通过将两个变量分配给内存中的相同引用，然后在它们上使用身份运算符来进一步看到这一点。

常数用户 = {
名称：“泰勒”
}
    
常人 = 用户
    
person === 用户 // true。 相同的类型，相同的值，相同的参考。
    

在示例中，`person` 和 `user` 都引用了内存中的同一个点，这就是我们得到 `true` 的原因。

总而言之，当使用标识符（`===`）时，假设您知道引用相等性，一切都按您的预期工作。 这是一个平等表来证明这一点。

### 等式运算符（双等于，==）

与身份运算符 (`===`) 不同，除非您非常熟悉它，否则相等运算符 (`==`) 的行为可能与您期望的不一样。 这里只是一些例子，

"1" == 1 // true
null == 未定义 // true
0 == '' // true
'0' == false // true
[1] == true // true 🤷‍♂️
    

那么这里到底发生了什么？ 请注意，在不同类型之间进行了每次比较。 正如我们之前使用的身份运算符（`===`）所看到的，所有这些都会返回 false，因为它们都是不同的类型。 使用等式运算符（`==`），就不是那么简单了。 当类型不匹配时，它不会返回 false，而是尝试将它们转换为相同的类型。

所以在第一个示例中，`"1" == 1` 因为 JavaScript 引擎会将字符串“1”转换为数字 1，然后计算为 `1 == 1` 为 true。

正是这种类型的强制阶段使等式运算符（`==`）变得如此不可预测。 这是我们之前看到的相同的相等表，除了现在`==`。

[![Double equals equality table](https://ui.dev/post-images/double-equals.png)](https://dorey.github.io/JavaScript-Equality-Table/)

如果您和任何在您的代码库中工作的人都对 JavaScript 的所有类型强制规则充满信心，请随意使用您想要的任何运算符。 但是，如果您像我一样使用可以按照您期望的方式工作的工具，请坚持使用身份运算符（===）。

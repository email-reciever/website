### 反应时代

上一期，为了庆祝泰勒斯威夫特正式开始她的 ERAS 巡演，我们崩溃了 [The Eras of Electron](https://bytes.dev/archives/171)。 因为它永远不会过时，所以我们今天会做同样的事情，但为了 React。

**~2014**：如果你经历了这个 React 时代，你可能有一个无法摆脱的肛门裂缝。 这是互操作时代。 很少有人有幸为一个全新的应用程序提供了绿地，因此我们只剩下将 React 融入更大的（通常是骨干网）应用程序中。 回到过去，这是 React 的主要 [selling points](https://web.archive.org/web/20140531020259/http://facebook.github.io/react/#markdownExample) 之一。

**~2018**：这是 BYO 建筑时代。 水疗中心风靡一时，如果你幸运的话，你的团队中有一个文档扭结不好的人，所以你可以自己跳过配置 webpack。 更不用说您可能使用 15KB 库来连接表单。 是的，生态系统一团糟，是的，将所有东西混合在一起是令人困惑的。 但是一旦设置好，React 的 _your view 就是您状态的函数_心理模型使这一切都值得。

**2023**：……水疗中心已经死了——显然。 当 React 上周发布他们的新文档时，“开始新的 React 项目”部分明显缺少与 SPA（或 Vite，现代 webpack）相关的任何内容。 具体来说，他们提到“如果你想用 React 完全构建一个新的应用程序或一个新网站，我们建议选择社区中流行的 React 驱动的框架”，然后他们继续推荐 Next.js、Remix 或 Gatsby。 曾经构建 React 应用程序的默认方式现在已经成为例外。

要了解为什么会这样，您必须了解 React 团队的愿景。 您可能听说过 React Server 组件。 您可能_haven't_听说的是_how_ react团队将它们描述为[“a new application architecture”](https://react.dev/blog/2023/03/22/react-labs-what-we-have-been-working-on-march-2023)。 RSC 不仅仅是“在服务器上渲染组件”——它是一种架构，而且是一种很难自己创建的架构。 因此，框架。

React 团队可以与一些框架（现在是 Next.js）紧密合作，以创建支持 React 团队在过去 5 年以上工作的所有架构的适当架构——包括服务器组件、悬念资产加载、屏幕外渲染和优化 编译器。

**底线：**他们说一切都很好，结局很好，但我们会看看这对 React 有什么影响。

什么会记录到控制台？

const res = ["👨", "‍", "👩", "‍", "👧", "‍", "👦"].join('')
    
console.log(res) // 👨‍👩‍👧‍👦
    

这是“👨‍👩‍👧‍👦”表情符号。

这是有效的，因为 Unicode 标准支持将单个表情符号与零宽度连接器映射以创建新的表情符号。 在我们的例子中，使用单独的表情符号并加入他们的家庭表情符号。 哇编程。

可视化未来，我们可以再次留在 Airbnbs

**Tony Robbins 教我们成功可视化……** 上周，Airbnb 正式发布了 Visx 1.0，这是一组可重复使用的低级可视化组件，结合了 React 和 D3 的强大功能（JavaScript 库，不，遗憾的是，强大的鸭子）。

Airbnb 已经在内部使用 Visx 两年多来“统一我们公司的 _Visualization 堆栈_”。 “可视化堆栈”，它们绝对是指“我们所有的随机图表和图表”，但这不应该阻止您将自己列为 _full-stack 可视化工程师。

**为什么？** Visx 的主要销售宣传是它足够低级，足以强大但足够高，足以变得有用。 它的方式是利用 UI 层的 React 和 D3 的引擎盖下的东西。 不同的说——在街上做出反应，在床单上的 D3。

库本身具有 30 个独立的 React 可视化原语包，与其他可视化库相比具有 3 个主要优势：

1.  **较小的捆绑包：** 因为 Visx 被拆分为多个包。
    
2.  **BYOL：** 就像你男朋友在晚餐时间一样，Visx 故意毫无意见。 使用您想要的任何动画库、状态管理解决方案或 CSS-in-JS 工具 - Visx DGAF。
    
3.  **不是图表库：** Visx 想教你如何钓鱼，而不是为你钓到鱼。 它的设计是建立在上面的。

[Elder.js 1.0 - a new Svelte framework](https://github.com/elderjs/elderjs)
----------------------------------- ------------------------------------

![Very nice elderly couple](https://bytes.dev/images/content/elders.jpg)

谁把它放走，亲爱的处理它

**尊重您的生成器……** Elder.js 1.0 是一个非常专注于 SEO 的新型、固有的 Svelte 框架和静态站点生成器。 它是由 [Nick Reese](https://twitter.com/nickreese) 创建的，以尝试解决构建具有 10-100K+ 页面的旗舰 SEO 站点所带来的一些独特挑战，例如他的网站 [elderguide.com](https://elderguide.com/)。

** 快速 svelte 评论：** svelte 是一个 4 年前首次发布的 JavaScript 库生活方式。 它在构建时将所有代码编译为 Vanilla JS，依赖性较少且没有虚拟 DOM，其语法以非常简单和可读性而闻名。

**那么，Elder.js 有什么独特之处？**

*   ** 部分水合：** 它仅为客户的部分需要互动，从而显着减少您的有效载荷，并且仍然可以完全控制组件延迟加载、预加载和急切加载。
    
*   **hooks、shortcodes 和插件：** 您可以使用设计为“模块化、可共享且轻松捆绑到 Elder.js 插件中的常见用例的挂钩”来自定义框架。
    
*   **直接的数据流：**在`route.js`中关联`data`函数，让您在将数据发送到Svelte模板之前完全控制如何获取、准备和操作数据。
    

这些功能（加上其微小的捆绑包大小）应该使 Elder.js 成为 Sapper（默认 Svelte 框架）的更快、更简单的替代方案，适用于许多用例。 如果您正在构建一个成熟的 Svelte 应用程序，Sapper 可能仍然是您的最佳选择，但 Elder.js 对于内容繁琐的 Svelte 网站来说似乎非常棒。

js测验 - 回答

const friends = ['alex', 'ab', 'mikenzi']
friends.hasownProperty('push') // false
    

如前所述，如果您查看 `Array.prototype`，它没有 `hasOwnProperty` 方法。 那么，`friends` 数组如何访问 `hasOwnProperty` 呢？

原因是 `Array` 类扩展了 `Object` 类。 因此，当 JavaScript 解释器看到 `friends` 没有 `hasOwnProperty` 属性时，它会检查 `Array.prototype` 是否有。 当 `Array.prototype` 没有时，它会检查 `Object.prototype` 是否这样做，然后调用它。

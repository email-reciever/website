当我构建协作应用程序时的振动

### 让我们聚会吧

上周，当 Sunil Pai 在 React Miami 登台并宣布他的项目 [PartyKit](https://github.com/partykit/partykit) 将开源时，我们举办了相当于性别揭露派对的开发人员。

值得庆幸的是，没有蓝色/粉红色的烟火，但这仍然是一个非常令人兴奋的公告，原因有几个：

1.  **PartyKit 看起来真的很酷。** 它是一个用于构建实时协作应用程序的 SDK（稍后会详细介绍）。
    
2.  **Sunil 过去曾建立过伟大的东西。** 他创建了 [Glamor](https://github.com/threepointone/glamor)，一个流行的 css-in-js 库； 从头开始构建 Cloudflare 的 Wrangler CLI，并作为 React 核心团队的成员。
    

**为什么派对套件？** Web 套接字早在 2009 年就首次登陆 Chrome，但从那时起，就构建了相对较少的实时多人应用程序。 根据 Sunil 的说法，那是因为 1) 运行这些应用程序在操作上很困难且非常昂贵，而且 2) 由于分布式系统问题，开发人员在技术上很难构建这些应用程序。

多亏了边缘计算，Cloudflare 和其他公司已经能够解决第一个问题——使运行这些应用程序变得更便宜、更容易。 但是_build_他们仍然很棘手……直到现在。

**PartyKit 希望成为下一个.js/vercel 的实时多人应用程序。** 这意味着他们希望为您提供一个包含电池的平台，用于启动实时应用程序。 让我们放大：

*   您带来了有趣的部分（您的代码、JS 或 WASM），PartyKit 带来了无聊的部分（Infra，部署在边缘）。
    
*   您可以获得有用的平台好东西，例如环境变量、预览 URL、管理 API 等。 PartyKit 公开承认从 Vercel、Cloudflare 页面和 Heroku 中窃取了许多好主意——而我，一方面，我在这里。
    
*   您可以使用 Y.JS、Automerge 和 Replicache 等流行的协作框架获得一流的集成。
    

**底线：** PartyKit 希望您在这里度过一段美好的时光，并且很长一段时间。

#### 赞助[Snyk](https://resources.snyk.io/nodejs-api-gateway?utm_campaign=aom_2023&utm_medium=paid-email&utm_source=bytes-advertiser&utm_content=nodejs-api-gateway)

设总和 = 0；

如果我们传递一个包含 `0` 的数组，因为我们正在过滤掉虚假值（其中 `0` 是 1），我们的计算将是错误的。

为了修复我们的功能，我们可以摆脱我们的真值检查（`arr[i]`）并验证元素是一个数字。

函数 calculateAverage(arr) {
设总和 = 0；
让计数 = 0；
    
for (let i = 0; i < arr.length; i++) {
if (typeof arr[i] === "数") {
总和 += arr[i];
计数++；
}
}
    
返回总和/计数；
}

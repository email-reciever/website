### Turso 将 SQLite 带入边缘

如果我从 2006 年在 _warped tour_ 遇到的那些 45 岁的 emo 家伙那里学到了一件事，那就是前卫并不总是_更好。

构建现代 Web 应用程序也是如此。 “The Edge”，真正代表“尽可能靠近用户的运行服务器”的营销，实际上只是_半个_图片。 没有_也_把你的数据放在边缘，这有点像亲吻你的兄弟姐妹。 此刻可能感觉很好，但归根结底，它可能弊大于利。

**那么我们如何解决这个问题？** 与治疗师交谈——并将您的数据也放在边缘。 但这说起来容易做起来难。 值得庆幸的是，Chiselstrike 的疯狂混蛋在构建 [Turso](https://blog.chiselstrike.com/announcing-chiselstrike-turso-164472456b29) — SQLite\* for the Edge 时已经准备好迎接挑战。

**他们是怎么做到的？** [forking SQLite](https://github.com/libsql/libsql)。 他们疯了，我告诉过你。 如果您不熟悉 SQLite，它会受到喜爱，因为它轻量、无服务器且可嵌入 - 这使得它非常适合边缘（和分叉），原因有几个：

*   您可以通过关系数据库引擎获得SQL的全部表达能力
    
*   您在用户附近获得本地副本的低延迟
    
*   它的占地面积小，内存要求低，这使得它非常适合资源受限的系统
    

**它是如何工作的？** Turso 建立在他们的分叉之上，它利用了 SQLite 的提前写入日志 (WAL)。 因为我知道您刚刚在整个职业生涯中使用了 Firebase……与 WAL 相比，写入单独的日志文件而不是数据库文件，然后将更改检查点返回到数据库文件中。 这允许多个事务同时发生，并使数据库更能抵御崩溃和停电。

Turso 也可以通过 HTTP 访问，这意味着它可以直接从非常受限制的环境（如 Cloudflare Workers 和基于 Deno 部署的环境（如 Netlify Edge 函数））工作。 除此之外，这意味着使用 Turso，您可以通过 HTTP 查询并复制到世界各地的许多地区。

**底线：** 流行的元框架，如 Next、Remix 和 Sveltekit 正在帮助将边缘功能带入主流。 但要实现前卫未来的全部承诺，我们还需要像 Turso 这样的分布式数据库。

常量范围 = (开始, 停止, step=1) => {
返回数组.from(
{ 长度：（停止 - 开始）/步骤 + 1 }，
（值，i）=> 开始 + i * 步
)
}
    

该函数使用 `Array.from()` 生成指定 `length` 的数组，并使用提供的函数生成的值填充它。 `length` 计算为 `(stop - start) / step + 1`，表示所需范围内的元素数。 传递给 `Array.from()` 的函数通过从 `start` 开始生成每个元素，添加 `i * step` 的增量，其中 `i` 是当前元素的索引。

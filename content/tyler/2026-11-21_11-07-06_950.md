### React的传统与众不同

你好朋友。

欢迎回到与其他任何不同的传统——React 团队的第三届年度“我们一直在努力”的博客文章。

[2022 Edition](https://react.dev/blog/2022/06/15/react-labs-what-we-have-been-working-on-june-2022) 为我们带来了服务器组件、资产加载的更新，并向我们介绍了 React Forget – 一个用于 React 的优化编译器。

[2023 Edition](https://react.dev/blog/2023/03/22/react-labs-what-we-have-been-working-on-march-2023) 为我们带来了更多关于服务器组件、资产加载和 React Forget 的更新。

现在，[2024 Edition](https://react.dev/blog/2024/02/15/react-labs-what-we-have-been-working-on-february-2024) 为我们带来了更多关于服务器组件、资产加载和 React 编译器的更新（这似乎是 React Forget 的新名称）。

然而，与过去几年不同的是，今年我们终于有了一些运动——最大的反应编译器不再是一个研究项目，因为它现在正在为 Instagram.com 提供支持。

在我们深入了解公告的其他部分之前，让我们回答一个您可能已经尴尬地问的问题：**WTF 是 React 编译器？**

React 的核心思想是将 UI 定义为当前状态的函数。 这意味着每当你的应用程序的状态发生变化时，React 就会重新渲染，但也意味着 React 可以重新渲染 _Too 的 _ degrading 性能。

您可以使用 `useMemo`、`React.memo` 和 `useCallback` 的神奇组合来防止这种情况。 不幸的是，你不是魔术师，手动记忆仍然有缺点：

*   它使您的代码不那么简洁、不清晰和可组合，尤其是在您的团队/代码库扩展时。
    
*   它要求你命令式地告诉 React _how_ 处理你的代码，从而杀死一些 React 的声明性魔法。
    
*   你的团队中总有一个人被说服让你快速做出反应，你需要记住一切。 事实证明，这会使 React 变慢。
    

**这是 React 编译器的用武之地。 没有更多的 `useMemo`、`useCallback` 或与 Memo 先生的尴尬对话。

仍然没有关于发布日期的讨论，但该团队似乎乐观地认为它很快就会发货。

**与 React 编译器一起，其他重大更新包括……**

*   “动作”，允许 React 管理数据提交的生命周期（想想 `<form />`），让您更轻松地将数据从客户端发送到服务器。
    
*   “文档元数据”为组件树中的任何位置提供了对渲染元数据标记（`<title>`、`<meta>`等）的内置支持——包括在完全客户端代码中。
    
*   React Server 组件、资产加载、文档元数据和操作均已登陆 `react@canary`，并将其文档添加到 React.dev 中
    
*   React 的下一个版本将是 React 19，它将包含 `@latest` 中当前的所有内容，以及对 Web 组件的支持。
    

**底线：** 在我们的 [2024 predictions](https://bytes.dev/archives/250) 中，我们预测“反应忘记将_not_ 发货”。 看起来这个预测与我们自己在预测方面很糟糕的传统是一致的。

在下面的代码片段中，`a` 和 `b` 评估的是什么？

设总和 = 0；
常量平方 = [1, 2, 3, 4, 5].map((x) => (
（总和 += x），x * x
));
    
console.log(sum) // 15
console.log(squares) // [1, 4, 9, 16, 25]
    

这是一个有趣的。 最奇怪的部分可能是逗号 `,` 运算符。

如果您不熟悉，`,` 计算其每个操作数（从左到右）并返回最后一个操作数的值。 这允许我们在一行中将 `sum` 增加 `x` **和** 返回 `x` 的平方。 完成后，我们得到数组的 `sum` 以及 `squares` 的新数组。

### 增强网络

你知道像Kix这样的“健康”谷物曾经有过像“孩子测试吗？妈妈批准”这样的口号？

好吧，可能是时候为 [Enhance](https://enhance.dev/docs/) 清除这个流行语了——一个全新的 JavaScript HTML 框架，它提供了一种易于使用的方式来使用 Web 组件，就像 Next.js 和 Remix 一样。

_开发者测试。 平台批准。_

**我们是如何到达这里的：** 如果您从未为 Google 工作过，您可能不知道 Web 组件实际上已经存在了十多年。

它们是一组 Web 平台 API，可让您根据现有的 Web 标准创建自定义、可重复使用的 HTML 标记——这使它们具有出色的性能。 但是，即使是官方的 Web Components 网站也试图 [talk you out of](https://www.webcomponents.org/libraries) 从头开始构建您自己的，它们的使用非常痛苦。

这就是为什么许多 Web 开发人员在历史上使用 JavaScript 框架的原因之一，尽管这会**经常**会引入不必要的膨胀和复杂性。

因此，让我们更深入地了解 Enhance 的“两全世界”方法如此引人注目的原因：

*   **基于文件的路由使用纯HTML** — 想象一下，但您打开 `/pages` 目录，并以 `.html` 的结尾中的文件感到惊讶。
    
*   **单个文件组件** — 当您以逐步增强的方式命名框架时，您最好相信您会获得无依赖的纯 Web 组件作为可重用的构建块。
    
*   **State Management** — Enhance 有自己的 `store` 解决方案，适用于与 WC 不匹配的复杂数据类型（数组、对象），而 `attrs` 适用于其他属性。
    
*   **API 路由** — 除非您有 API 路线，否则您无法在饥饿元框架游戏中竞争。 这些路由可以发送 JSON 或 text/html 并处理所有 rest-y 内容。
    

**底线：** 肯定有一些讽刺性的增强，这似乎已经是使用 Web 组件的最适合开发人员的方式，看起来 [a lot like React](https://twitter.com/tmcw/status/1565351049086414849)（至少在某些示例中是这样）。

但是，嘿，有时妈妈需要欺骗他们的孩子吃得健康，而框架作者需要欺骗开发人员使用该平台。

发现错误：解决方案
-----------------------

#### 赞助[Mergify](https://mergify.com/?utm_source=newsletter&utm_medium=email&utm_campaign=Bytes)

`todos` 变量在同一块中被重新声明。 用 `const` 和 `let` 声明的变量是块作用域的，这意味着它们不存在于它们被调用的块之外。块是用 `if/else` 语句、循环和函数周围的 `{}` 括号创建的。

有许多解决方案，包括在不同情况下更改变量名称或完全删除变量。 我们还可以将每个案例包装在一个块中以隔离变量。

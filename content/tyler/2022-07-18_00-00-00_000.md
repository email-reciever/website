当你最终给 GitHub Copilot 你的信用卡时

爱、死亡和（编码）机器人
-----------------------------

去年，GitHub 向我们介绍了 CodePilot，也就是 T9Word for 开发人员。

它是在 OpenAI 的 Codex 上训练的，它由数十亿行开源代码组成，因此它可以在编写代码时在编辑器中实时建议代码和整个函数。

超过 120 万开发人员在其 1 年的“技术预览”阶段使用了它，上个月 GH 将其广泛使用时，该阶段 [just ended](https://github.blog/2022-06-21-github-copilot-is-generally-available-to-all-developers/)。 哦，现在每月也要花 10 美元（惊喜！）——但稍后会详细介绍。

Copilot 绝对是一个两极分化的工具，所以让我们做你妈妈总是告诉你做的负责任的事情，并写下利弊的清单。

**Copilot 优点：**

*   它使编写代码更容易和更快。 （Copilot 在启用的文件中写入了几乎 40% 的代码。）

**Copilot 缺点：**

*   它训练的开源代码是由\*人工\*开发人员编写的，他们从未明确同意将其代码用于此目的。
    
*   Copilot 有时会推荐直接从训练集中复制粘贴的较大代码片段。
    
*   它可能会推荐带有错误和不安全/过时编码模式的代码。
    
*   现在需要花钱，10 美元是我 [Flamin’ Hot Mtn Dews](https://www.pennlive.com/life/2022/04/mountain-dew-says-welcome-to-hell-with-national-retail-release-of-flamin-hot-flavor.html) 的确切每月预算。
    

好的，这是很多缺点，但是为了添加一点细微差别_(gasp)_，这里有一些对每个con的需要考虑的对位：

*   副驾驶 [isn’t committing copyright infringement](https://www.fsf.org/licensing/copilot/copyright-implications-of-the-use-of-code-repositories-to-train-a-machine-learning-model)。 在公共数据上训练ML系统属于合理使用范围（至少目前），输出属于运算符，类似于编译器——正如Nat Friedman所论证的那样[last year](https://twitter.com/natfriedman/status/1409914420579344385)。
    
*   它仅推荐超过 150 个字符的训练集中的片段 1% 的时间。 你可以打开一个过滤器来制作它，这样这些结果就不会向你展示，如果你愿意的话。
    
*   您每天都在编写带有错误和不安全/过时编码模式的代码。
    
*   在 GPU 机架上运行需要为高质量 AI 提供大规模支持的机架的成本 [a lot of money](https://twitter.com/rakyll/status/1539398214519951360?s=20&t=Er9u8PDKF1I6zF3ASfXdIg)。 永远免费赠送 Copilot 可能是不可持续的，即使对于微软也是如此。
    

**底线：** 爱它或恨它，机器人不会很快消失。 Jeffrey B 的旧队伍上个月刚刚推出了 [Amazon CodeWhisperer](https://aws.amazon.com/blogs/aws/now-in-preview-amazon-codewhisperer-ml-powered-coding-companion/) 的预览，[Tabnine](https://www.tabnine.com/) 和 Kite 等其他工具继续获得动力。

让我们希望 AI 编写的代码不像 DALL-E [creates](https://www.reddit.com/r/weirddalle/comments/v9ai16/karl_marx_slimed_at_kids_choice_awards/) 的图像那样被诅咒。

你离家很远

速度与激情：引擎战争
--------------------------------

上周我们在烤箱里很热的时候写了关于面包的文章，但这仍然是人们唯一在谈论的事情——所以我们想在引擎盖下方的一个峰值，看看是什么让它如此快速地变得如此疯狂。

是的，这很像在盒子里问道，“你到底在炸玉米饼里放了什么让它们如此美味”，但我们还是在这样做。

**速度的需要：** BUN 和 Deno 等竞争对手之间最大的区别之一是它使用 JavaScriptCore 而不是 V8 作为其运行时的引擎。 这两个 JS 引擎已经竞争了一段时间，但值得注意的是，React Native 七年前选择了 JSC 而不是 V8 [because it was faster](https://twitter.com/Vjeux/status/1546440856059666432?s=20&t=IeIL3nYIDtbdBkaSfU8-Yw)（在它们构建 [Hermes](https://hermesengine.dev/) 之前）。

那么JSC和V8之间究竟有什么区别呢？

当我们谈论速度时，我们实际上是在谈论速度的 _types_ （因为 JS 引擎需要考虑很多 [tradeoffs](https://mathiasbynens.be/notes/prototypes#tradeoffs) ）。 让我们看看一些🌮肉：

*   JSC优先考虑更快的启动时间，而V8优先执行快速执行（这是一个半手波概括）
*   JSC 有 3 个优化编译器（更复杂，但更快），而 V8 有 2 个优化编译器（不太复杂且更容易使用，但速度不快）
*   JSC 的架构使用的内存更少（在苹果向您出售的设备上，电池寿命很长），但执行代码的速度要慢一些
*   v8 进行了更多的运行时优化，但这需要更多的内存——这就是当您打开超过 3 个 Chrome 选项卡时，您的笔记本电脑着火的原因
*   这里有一个[few more tradeoffs](https://twitter.com/jarredsumner/status/1548072064501747712?s=20&t=i1jdCTDRq_1_pm8mtvaa4g)来自Jarred Sumner，CBO（Bun-Boi主任）

**底线：** Vin Diesel 需要 Dwayne “The Rock” Johnson 来激活他的鼻孔发作游戏，就像 V8 需要 JSC 为它的钱奔跑（Lil' Bun 骑着那波）。 获胜者：JavaScript 开发人员 — [salute mi familia](https://www.youtube.com/watch?v=-NrU1IJGMZM)。

发现错误解决方案 — 由 [Raygun](https://raygun.com/?utm_medium=sponsorship&utm_source=bytes&utm_campaign=bytes-spot-the-bug&utm_content=blog) 赞助
------------------------------------ -------------------------------------- -------------------------------------- --------------------------------------

React 将 ref 视为一个“盒子”，可以在其 `.current` 属性中保存可变值，包括 DOM 元素。 由于 React 需要一种方法来更新 ref 的值而不完全覆盖它，因此 ref 本身是一个具有可变 `.current` 属性的对象，可以在不更改对象引用的情况下随时更改。

当我们尝试 `.focus()` `inputRef` 时，会发生错误。 输入 DOM 元素存储在 `.current` 属性中，因此聚焦输入的正确方法是调用 `inputRef.current.focus()`。

这是解决方案-

导出默认函数 inputModal({isOpen, close}) {
const inputRef = useRef(null)
    
useEffect(() => {
如果（isopen）{
inputRef.current.focus()
}
},[ISOpen])
    
// ...
    
}
    

refs 可以存储的不仅仅是 DOM 元素——它们可以存储组件需要保留的任何值，而不会在值更改时引起重新渲染。

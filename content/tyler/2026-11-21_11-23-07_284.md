[npm 7.0.0 Released](https://github.blog/2020-10-13-presenting-v7-0-0-of-the-npm-cli/)
----------------------------------------- -----------------------------------------

![npm v7](https://bytes.dev/images/content/npm7.png)

B̶O̶X̶中有什么更新？？！？

**已经 11 年了……** 自从 NPM 被引入 JavaScript 生态系统以来（当我们对 Kevin Spacey 最令人毛骨悚然的事情是他的连环杀手角色时）。

上周，NPM 发布了 V7.0——将成为本周晚些时候即将推出的 Node.js 15.0.0 版本的主要更新。 但是，如果您是 Eager Beaver，您可以通过在终端中运行 `npm i -g npm@7` 来安装 NPM 7。

### 亮点

**工作空间：** 到目前为止，NPM 用户请求最多的功能，这套新的 NPM CLI 功能允许您从单数的顶级根包中管理多个包。 这是任何软件包管理器（未命名为 Y\*rn）首次提供此功能🙃。

**自动安装对等依赖：** npm v6（因为编程很难），默认情况下`peerDependencies`没有安装。 使用 V7（因为我们可以做困难的事情），他们是。

**package-lock v2 _and_ 支持 yarn.lock:** 当你的父母分开但他们抛开他们的分歧来支持你时。 V7 现在将支持 `yarn.lock` 文件。 还有一种新的 `package-lock` 格式，它将（显然）“允许您进行‘确定性可重现的构建’，并包括 npm 完全构建包树所需的一切。”

其他很酷的功能包括改进的 `npm audit` 输出以及在使用 `--ignore-scripts` 时跳过预/发布脚本的能力。

### 底线

这是 NPM 的第一个主要版本，因为它为股东创造了很多价值，早在 3 月就被 GitHub 收购。 当这笔交易发生时，GitHub 的首席执行官承诺将微软（GitHub 的母公司）中的一些甜蜜 PowerPoint 资金投入到现代化 NPM 中并使其更快、更具可扩展性。

随着 npm v7 的发布，看起来 GitHub 开始兑现该承诺，同时朝着 [its bigger goals of integrating npm into GitHub itself.](https://thenewstack.io/github-acquires-npm-buying-microsoft-a-presence-in-the-node-javascript-community/) 努力

[Grain - A New Web Staple](https://github.com/grain-lang/grain)
-----------------------------------------------------------

![Cereal](https://bytes.dev/images/content/cereal.jpg)

当然，他们是健康的，他们有全谷物

**不要和我们谈论古……**因为谷物回来了。 至少我们上周听到的关于 Grain™ 时的想法——一种让“学术功能”发挥作用的新编程语言。

**WTF 这是否意味着？** Grain 希望将功能和学术语言的各种功能现代化，这些功能和学术语言通常会被绝大多数开发人员忽略，因为它们要么太抽象，要么太难学习（或两者兼而有之）。 Grain 正试图通过让我们这些没有从麻省理工学院获得计算机科学博士学位的人更容易使用和理解这些功能成为主流。

这个项目仍然是新的，但这里有关于谷物的 3 个很酷的事情：**

**编译为 WASM：** 又名 WebAssembly 又名未来，如果您阅读黑客新闻。 这意味着 Grain 可以在浏览器、计算机或服务器上运行。 而且速度很快。

**明智类型：** 您可以定义自己的类型，而不会出现任何运行时类型错误。 文档承诺“你写的每一个_bit_bit 都是类型错误的彻底_sifted_，不需要类型注释。” 他们真的倾向于在这里的隐喻。

**功能性，但寒冷：** 谷物是一种功能性语言，但它不是一个 d\*ck。 它有一个强大的类型检查器，但它足够灵活，可以允许不同的编程风格，这使得它更实用。 它目前正在采用像 Rust 的 `let mut` 这样的功能，这些功能在技术上绝对不是“功能性的”，但应该使谷物更容易使用。

### 底线

不乏自称是“未来新的现代语言”的项目。 然后……没有人使用它们。 因此，看到谷物创作者将可访问性、易用性和主流采用率作为他们第一天的主要目标是很酷的。

js 提示
-------

你用过数组的 `fill` 方法吗？ 可能不是。 定义，`fill`“用静态值填充数组的所有元素，从开始索引到结束索引”。 这听起来很没用，但我发现了一种情况，它实际上很有帮助。

当你开始使代码更具功能性时，你自然会开始避免使用常规的 for 循环来支持 `.map`、`.reduce` 等。假设我们的用例是我们想执行一个任意次数的函数，比如 10。我们如何做到这一点并避免使用 for 循环？ 您的第一个直觉可能是使用带有 `.map` 的数组构造函数。

数组(10).map(() => {
返回 dothing()
})
    

您会注意到如果您运行该代码，它将不起作用。 当您执行 `Array(10)` 时，您将创建一个包含 10 个未设置或“空”值的数组。 不幸的是，当您使用任何数组方法时，它们将无法在具有空值的数组上工作。

这就是 `.fill` 发挥作用的地方。 如果你这样做`Array(10).fill()`，你会得到一个10`undefined`而不是空元素的数组。

数组(10).fill().map(() => {
返回 dothing()
})
    

不是 _super_ 有用，但如果您需要它，很高兴知道它的存在。

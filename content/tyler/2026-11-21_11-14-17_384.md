### 塔玛吉的大目标

一月是每个人最喜欢设定目标的时间——比如阅读更多书籍、学习 Vim，或者，如果你是 [Tamagui 1.0](https://tamagui.dev/blog/version-one)，帮助开发人员“将跨平台的 React 应用程序“以 2 倍的时间”交付。

既然每个人都已经放弃了前两个，让我们分解一下每个人最喜欢的“神奇宝贝或反应库”项目。

如果您不熟悉，Tamagui 是 React Native 和 Web 的通用 UI 套件和样式系统。 wtf这意味着吗？ 很高兴你问了。 它有三个部分。

*   **tamagui core:** 是一个跨平台样式库，位于 React Native 的顶部，从理想语法向后工作（对于内联样式和钩子）。 这允许您创建和使用功能齐全的设计系统，这些系统具有类型、主题和能够在 Web 和本机上运行的功能。 这种增加的代码共享（理论上）可以显着减少跨平台的开发时间。
    
*   **tamagui static:** 是一个优化编译器，位于核心库的顶部是 Tamagui 性能声明的关键。 它使用 AST 和 Node VM 代码评估将所有样式组件和内联样式转换为 Atomic CSS 和最小 JavaScript。 这会使您的视野树变平，并为您提供一些美味的性能。
    
*   **tamagui ui _(发音为“tamag-we-we”)_:** 是一个组件套件，它建立在核心库的主题原语之上，可以在网络和本地无缝地工作。 Composable Component API 为您提供对样式的高度精细化的控制，并且 v1.0 添加了许多新组件。
    

**底线：** Tamagui Hype 火车已经滚动了几个月。 现在我们有一个稳定的 1.0 版本，我们将能够看到该库是否能够获得更多主流采用并兑现其在更深层次上解锁 React Native 的跨平台优点的承诺。

![Fast-element vs Stencil vs Lit vs Skatejs](https://bytes.dev/images/content/wc-framework-trend.jpg)

即将推出的 Web 组件框架 – [npmtrends.com](https://npmtrends.com/@microsoft/fast-element-vs-@stencil/core-vs-lit-vs-skatejs) 的数据

一些前端开发人员很容易对 Web 组件及其……_Zealous_ 社区不屑一顾。 但对于 Web 组件和#useThePlatform 帮派来说，2022 年是令人惊讶的大年份。 虽然框架统计数据并没有考虑到所有的 WC 使用情况（把你的干草叉放下，_please_），但我们今天的趋势有一些很好的见解。

1.  ** Web 组件比大多数人意识到的更受欢迎：** LIT 和模板的每周下载量明显多于 Solid、Astro、Remix 甚至 svelte 等下一代框架，这并不考虑 WC 的所有使用情况 npm之外。
    
2.  **LIT 正在获胜：** 很少有框架见过 Lit 去年经历的那种增长，当时它从每周的 40,000 次下载量上升到超过 600,000 次。 作为一个社区，我们可能应该比现在更频繁地谈论它。 在 12 个月内增长 15 倍不是开玩笑。
    
3.  **Web 组件仍然存在 SSR 问题：** 阻碍 WC 的最大问题是它们被设计为在浏览器中运行。 为了真正支持 SSR（不带黑客），声明式阴影 DOM 规范 [needs better support](https://caniuse.com/declarative-shadow-dom)。 像 LIT 这样的框架有 polyfills 和实验性 SSR 支持，但在它成为规范的一流部分之前，它可能很难成为真正的主流。
    

**要点：** 在过去的 12 个月中，Web 组件开发人员从 [“there are dozens of us”](https://www.youtube.com/watch?v=lKie-vgUGdI) 发展到临界质量。 如果这种增长在 2023 年继续，你会看到我们写了更多关于 LIT 的故事（谢天谢地，这很适合关于大麻香烟的不成熟笑话）。

1.  Tobias Koppers 在 React Day Berlin 发表了 25 分钟的谈话 [Turbopack’s Vision](https://vercel.com/blog/the-turbopack-vision)。 那个来自_that's raven_ 的女孩被跳上太多的鞋面时，不就是“涡轮视觉”吗？
    
2.  Chrome Devrel 团队分享了他们的 [Top recommendations for improving Core Web Vitals in 2023](https://web.dev/top-cwv-2023/)。 这有点像旧约——不是最轻的读物，但你可能会在此过程中获得一些见解。
    
3.  永远不要再构建通知服务。 Courier 构建了 [a notification API](https://www.courier.com/engineering/?utm_campaign=ui.dev&utm_source=email&utm_medium=bytes-newsletter-1-12-quick-link&utm_content=notification-service) 来管理 Twilio、SendGrid、APN、Firebase 和 Slack 等多个提供商的模板和路由逻辑。 \[赞助\]

简单的 JavaScript-ing
--------------------

谷歌最近在 JavaScript 发布 [zx](https://github.com/google/zx) 时将 _script_ 放回了 JavaScript 中——这是 Bash 和 JavaScript 的邪恶结合。

**它有什么作用？** 有时你有一个你想用一点代码自动化的过程。 你_可以_用纯bash写它，但这很复杂，文档很糟糕，而且你的头发不够白。 Node 可以使用一些更好的功能，但不如 Bash 强大。

ZX（发音为“ZX”）结合了 Bash 和 Node 的最佳部分，为您提供了一个简单但功能强大的自动化工具，内置了一堆迷你工具。您有 `fetch` 用于 HTTP 请求，`question` 用于接受用户输入，`globby` 获取与全局模式相匹配的文件等。

让我给你一个例子。 假设我将我的节点项目从 CommonJS 迁移到 ESM。 迁移时，我需要将现有文件从 `.js` 重命名为 `.cjs`。 使用 ZX，我只需五行代码就可以做到这一点。

// cjsmigrate.mjs
#!/usr/bin/env zx
    
const jsfiles = await globby("./src/**/*.js")
for (jsfiles 的路径) {
const newPath = path.replace('.js','.cjs')
等待 $`mv ${path} ${newPath}`
}
    

好! 注意到顶部的 `#!/usr/bin/env zx` 吗？ 这让我执行这个脚本，就好像它是一个普通的bash脚本一样。 我所要做的就是设置正确的权限。

chmod +x ./cjsmigrate.mjs
./cjsmigrate.mjs
    

ZX 的魔力在于 `$`。 它可能看起来像 jQuery，但不要被愚弄——无论你放入反引号中的内容都会作为 bash 命令执行。 花括号之间的插值部分将自动转义，因此它应该“正常工作”。

您可以自行运行它，将结果传递到控制台，或将结果放入变量中并在脚本的其他地方使用它。

**底线：** 如果您曾经很难编写 Bash 脚本，ZX 可能适合您。 它可能会说它在自述文件的底部是_“不是官方支持的谷歌产品”_，但 ZX 的使用寿命可能比 Google Reader [(RIP in peace)](https://killedbygoogle.com) 的使用寿命更长。

Twih — GraphQL 诞生
-----------------------

**六年前的本周，**当Facebook开源的GraphQL——一种以一些有意义的方式将自己与传统的REST API区分开来的API的查询语言时，数据获取预言就实现了：

*   GraphQL API 可以在单个请求中获取应用所需的所有数据（REST API 通常需要从多个 URL 加载）。
    
*   GraphQL 查询反映了他们的响应，这使得预测从查询返回的数据的形状变得更加容易。
    
*   GraphQL 具有自然遵循对象之间的关系的层次结构（不需要多次往返行程或复杂的 SQL 语句）。
    

以一种或另一种方式，所有这些功能（并且仍然是）旨在使数据获取过程对前端开发人员更加直观，并且对应用程序本身的效率更高。

[Lee Byron](https://twitter.com/leeb) 写道，他和他的团队最初创建了 GraphQL，因为当时（早在 2012 年），Facebook 的原生移动应用程序需要一个“强大到足以描述整个 Facebook 的强大功能，但又简单到易于被我们的产品开发人员学习和使用的数据 API。”

事实证明，这对许多其他开发人员来说也是一个非常有价值的道具，因此他们在 2015 年 9 月开源了它。

快进到今天，GraphQL 每周下载 550 万 npm 很酷，同时帮助催生一些 VC Wet Dreams _Oss-As-Marketing Unicorns_，如 Apollo 和 Hasura。 下面是关于“GraphQL vs. Rest”的六年思考片段。

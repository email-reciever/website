Partytown 希望加快您的 Javascript
----------------------------------------------

**这有点像PartyCity……**但不是你去购买万圣节服装和偶尔的皮纳塔的半令人毛骨悚然的转换仓库，party_town_是一个很酷（仍在实验性的）新库，使加载第三方脚本变得更容易和更快 使用 Web 工作人员和一些老式的 JavaScript Voodoo。

**它解决了什么问题？** 第三方脚本（如跟踪器、广告网络等）经常加载和执行大量 JavaScript。 这可能会减慢主线程，从而使用户界面无响应，并且您的用户明显生气_NOT TO PARTY_。 [PartyTown](https://github.com/BuilderIO/partytown) 通过在 Web Worker 中运行这些第三方脚本来解决此问题，因此它们不会阻塞主线程。

这听起来很简单，但这是 Web 开发中比听起来要棘手得多的（许多）事物之一。

一方面，第三方脚本通常需要访问 DOM API 和 `window` 对象——但您不能直接在 Web 工作者中执行此操作。 此外，Web 工作人员和主线程之间的桥梁必须是异步的——但第三方脚本希望 DOM/Window API 调用是 _synchronous_。

**它是如何工作的？** 就像我们说的，它是巫毒教。 PartyTown 首先在 Web 工作器中为 DOM/Window API 创建一个 JavaScript 代理，它可以在其中拦截这些请求。 从那里，它将消息发送到主线程，获取响应，并将其传递给第三方脚本。 对于异步问题，它（非常巧妙地）使用同步 XHR 请求，该请求在发出请求时阻止线程。

_“但是等等，不是阻塞线程吗? JavaScript是一种单线程语言！！”_这是正确的，除了这没有阻塞主线程-它阻塞了工作线程。 只要主线程保持响应#bigbrain，我们不在乎这是否被阻止。

**底线：** 第三方在工人中运行，但仍然可以在不知道更好的情况下调用 DOM/Window API——两全其美。 也许他们应该重命名库，_partyintheusa_town？

这么小的东西

下一站，小镇
---------------------

[Motion One](https://motion.dev/) 上周刚刚发布，它自称是“最小的全功能动画库”。 它是由 [Matt Perry](https://twitter.com/mattgperry) 创建的，他也是 Framer Motion 的创造者（当他没有在_friends_ 中扮演钱德勒时）。

**秘密在 waapi 中。** 我们不是在谈论“锅中的通心粉”——我们说的是不超知名的 [Web Animations API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Animations_API/Web_Animations_API_Concepts)。 这个本机浏览器 API 是六年前发布的，试图填补声明式 CSS 动画和过渡与动态 JavaScript 动画之间的差距。 但它从来没有真正流行起来，因为它又大又笨重。

**输入 Motion One。

这种基于 WAAPI 的方法为 Motion One 提供了一些关键优势：

*   **较小的捆绑包大小** — 因为它不需要强制用户下载浏览器中已经存在的代码。
    
*   **硬件加速** — 即使您的应用程序已经在运行一堆其他 JavaScript，您的动画也会保持流畅，因为它们可以在主要 JavaScript 线程之外（通常在 GPU 上）运行。
    
*   **better value interpolation** — Motion One 能够使用浏览器的插值代码，这通常会更好，并且使您的相关动画更具性能。
    

**Motion One 最大的权衡**是 WaAPI 只能为 CSS 样式设置动画（不是 JavaScript 值、SVG 属性或 HTML 文本）。 未来的 Polyfills 可以让 Motion One 在某个时候支持这些动画，而 Matt 应该有更多的时间来研究它，因为 _Friends_ Reunion 刚刚结束了拍摄。

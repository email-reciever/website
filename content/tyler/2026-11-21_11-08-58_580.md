### 层的力量

React Aria 团队最近发布了一个 [new library of unstyled components](https://react-spectrum.adobe.com/react-aria/react-aria-components.html)，它建立在现有的 Aria React Hooks 库之上。

这听起来可能不是什么大不了的，但深入挖掘一点，你会发现这将 React Aria 提升到了一个全新的水平。 所以让我们开始挖掘。

**快速审查：** React Aria 最初由 Devon Govett 创建，作为一个 Hooks 库，为您的设计系统提供有用的 UI 原语。 它为您提供内置 A11Y、I18N 和自适应交互 _(A18S?)_ 的元素，然后让您控制渲染和样式选择。

但事实证明，这只是冻结的基础层。

通过构建 Hooks 库的组件库 _On Top_，React Aria 现在为您提供了一种简单的方法来构建具有自定义样式的可访问组件，但也可以灵活地让您可以灵活地下拉到钩子并自定义您想要的任何内容，而无需重新开始。

这解决了大多数组件库面临的最大问题之一，如果一个特定组件不适合您公司的设计系统或提供您需要的功能，您就是 SOL 并且需要从头开始构建它。

但是 React Aria 为您提供了三种不同的使用方式并避免了这个问题：

1.  使用开箱即用的顶层组件，只需添加样式即可。
    
2.  下到 React Hooks 层来构建您自己的设计系统或更低层次的定制，因此您不必完全从头开始构建组件。
    
3.  将组件和挂钩与上下文、槽和状态混合并匹配以构建 [custom compositional APIs](https://react-spectrum.adobe.com/react-aria/advanced.html)。
    

**底线：** 史莱克早在 2001 年就向我们介绍了层的力量，我很高兴年轻的德文·戈维特正在关注。

发现错误：解决方案
-----------------------

#### 赞助[Bugherd](https://bugherd.com/lp/bug-tracker-developers-new?utm_source=referral&utm_medium=newsletter&utm_campaign=bytes)

指定 `<meta charset="ISO-8859-1" />` 的字符集将导致特殊字符和表情符号无法正确呈现。

为了正确呈现表情符号，文档需要使用 Unicode 转换格式 (UTF)，`UTF-8` 是 Web 开发中最常用的编码方式。 大多数浏览器将编码默认为UTF-8（或尝试自动检测），但对于较旧的渲染引擎（咳嗽电子邮件），您需要明确设置您的字符集，或者像我们一样，您可能要花费数小时来找出表情符号不会渲染的原因 😭。

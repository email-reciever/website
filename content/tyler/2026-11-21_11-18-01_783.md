Air Bud 和 Angular 有什么共同点？ 真正的问题是，他们有什么共同点？

Air Bud 凭借 14 部电影在该系列中获得了超过 2 亿美元的收入。 Angular 上周刚刚发布了 [its 14th version](https://blog.angular.io/angular-v14-is-now-available-391a6db736af)，就像 Air Bud 一样，它也一直在悄悄地争夺 W（即使它不是一代人的篮球天才）。

虽然 JavaScript 世界的其他部分一直在忙于 Twitter 上的争论，但 Angular 团队只是不断推出一致的、增量的改进。 他们显然花了很多时间来修改他们的文档，添加有用的例子，并整体改善开发人员的体验。

老实说，我们现在唯一不喜欢 `nG` 的是它们全力以赴装饰器🤮。 但我们暂时让它下滑，因为它们确实带来了 Angular 14 的热量。让我们进入亮点。

*   **独立组件：**这些有助于解决每个开发人员最喜欢抱怨的问题——样板（你现在得到的东西少了很多）。
    
*   **更快的构建 + 较小的捆绑包：** 在 V14 中，构建占用的资源减少了 90%，而捆绑包的数量减少了 30%。
    
*   **Forms Baby：**我们都喜欢表格（从未说过开发人员），但通过此版本，Angular 的类型化表单可帮助您减少错误并构建更安全的表格。
    
*   **自动版本迁移：** Angular 学会了向后兼容很难的艰难方式，但现在它们为您提供了 [playbook](https://update.angular.io/) 和自动化脚本来帮助您迁移版本（企业经理停止流口水）。
    

**底线** 有时我们会忘记一个团队只和上面的人（或狗）一样好，而且谷歌显然已经组建了一支 S 级球队。 结果不言自明。 #Angbudforever。

如果你喜欢 Pinia coladas
--------------------------

_ 并陷入……_ 互联网奇怪的角落，陌生人热情地辩论利基国家管理解决方案。 那么今天是你的幸运日，我的朋友。

因为我们说的是 [Pinia](https://pinia.vuejs.org/) — Vue 核心团队最近被 Vue 应用程序作为 Vue 应用程序的官方推荐™️状态管理库。

除了 Pinia 拥有游戏中最可爱的 OSS 徽标这一事实外，Vue 团队决定全力投入 Pinia 和 Shank _demote_ Vuex 到维护模式还有几个实际原因。

*   **More Modular** — Pinia 被构建为拥有多个商店，而不仅仅是一家具有子模块的全球商店（如 Vuex）。 每个 PINIA 模块都可以是自己的商店，可以直接导入到特定的组件中。 这提供了更好的开发体验，还允许更好的类型推断和自动代码拆分。
    
*   **更直观** — Pinia 基于 Vue 3 的 Composition API，它要简单得多，需要少得多的样板。 这与上面提到的模块化相结合，使编写不是 Janky AF 的组织良好的商店变得更加直观。
    
*   ** 更多功能** — Pinia 内置支持SSR 和热模块更换的支持，它连接到所有[Vue devtools](https://devtools.vuejs.org/)。 它是可扩展的，所以它也带有一堆有用的 [plugins](https://pinia.vuejs.org/core-concepts/plugins.html)。
    

**底线：** 与 Vue 2 → Vue 3 升级类似，从 Vuex 到 Pinia 的过渡似乎侧重于使 Vue 成为大型应用程序和团队更具吸引力的选择。

`React.useState` 的营销宣传是它允许您将状态添加到功能组件。 这是真的，但我们可以进一步分解它。 从根本上说，`useState` 钩子给了你两件事——一个将在渲染中持续存在的值和一个用于更新该值并触发重新渲染的 API。

const [值，setValueAndRerender] = react.useState(
'初始价值'
)
    

在构建 UI 时，两者都是必要的。 如果没有能够在渲染中保留值的能力，您将失去在应用中拥有动态数据的能力。 如果没有更新值并触发重新渲染的能力，UI 将永远不会更新。

现在，如果您有一个不处理任何 UI 的用例，因此您不关心重新渲染，但您确实需要在渲染中保留一个值怎么办？ 在这种情况下，就像您需要 `useState` 的一半，让您在渲染中保留一个值，而不是触发重新渲染的另一半 - 类似于此。

函数 UsePersistentValue (InitialValue) {
返回 react.useState({
当前：初始值
})[0]
}
    

剧透警报，我们的自定义 `usePersistentValue` 钩子的功能与内置的 `React.useRef` 钩子非常相似。

如果您想将状态添加到在渲染中持续存在的组件中，并且可以在更新时触发重新渲染，请使用 `useState`（或 `useReducer`）。 如果要在渲染中持续存在但在更新时不会触发重新渲染的组件的状态，请使用 `useRef`。

有关 `useRef` 的更多信息（以及 `useState` 与 `useRef` 相似的更深入解释），请访问 [Understanding React’s useRef Hook](https://ui.dev/useref)

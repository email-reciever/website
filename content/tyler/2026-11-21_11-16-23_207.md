### 十年的类型

周六 TypeScript 满 10 岁，由于你们都没有参加生日派对，我们决定自己举办一场。

因此，无论您从第一天开始就一直是真正的信徒，还是您还没有输入您的第一个脚本——是时候站出来喝一大碗 Blue Kool-Aid 并喝一口了。

**我们去过的地方：**如果你认为JavaScript今天是一个SH\*TSHOW，你应该在2007年看到它。不仅语言本身不如现在那么强大，而且TC39委员会的成员无法达成一致意见 前进。

尤其是微软，反对当时在ES4中提出的许多较大的更改，因为他们认为对于这种简单的脚本语言来说，它们太大且风险太大，这是（在他们看来）[“never designed to be a programming language for big applications.”](https://youtu.be/EUlM3wx546o?t=75)

因此，在 ES4 未能达成共识之后，Anders Hejlsberg 和他的团队深入研究了 Microsoft Lair 几年，并最终采用了 TypeScript ——一个 JavaScript 超集，它通过添加新的“应用程序规模”功能（如类、模块和静态类型）来 [augmented](https://www.infoworld.com/article/2614863/microsoft-augments-javascript-for-large-scale-development.html) JS。

但是，如果我们快进到今天，JavaScript 现在已经将这些功能中的大部分添加到规范中。 那么，为什么打字稿仍然比 Harry Styles 穿着一件完全正常的热门衣服更热，也许像炉子一样？

TypeScript 的受欢迎程度有很多原因，但其中大多数属于**三个类别之一：**

*   **ts 语言** — 因为它建立在 JavaScript 之上，任何有效的 TS 程序也是一个有效的 JavaScript 程序。 这使您可以导入您想要的任何 JS 模块，并且它允许您逐渐将 TS 功能引入您的代码库中，因此它不必是全有或全无的体验（与您的第一个人脸纹身不同）。
    
*   **ts linter** — 因为它了解代码库中类型之间的关系，TS 可以帮助消除所有类型的错误（尤其是与兼容的 IDE 配对时）。 就像你的中学篮球教练一样，_它只会因为它在乎而对你大喊大叫。_
    
*   **ts 文档工具** — 类型注释使您的团队（以及未来的您自己）更容易提供有关您的代码在做什么的有用上下文，而无需编写一堆注释（粗略）。
    

**我们从这里去哪里：** TypeScript 在过去 10 年中的迅速崛起似乎会持续一段时间的流星雨。 越来越多的公司将它用于他们的企业应用程序（安德斯称之为他的投篮）——所以如果你还没有学习它，这可能只是时间问题。

再加上像Copilot这样的人工智能辅助编程工具的激增（在Typescript代码库中使用时更强大），TypeScript似乎准备在未来10年变得更加根深蒂固。 2032年见到大家。

发现错误：解决方案
-----------------------

#### 赞助[Trunk](https://trunk.io/?utm_source=sponsorship&utm_medium=newsletter&utm_campaign=bytes&utm_term=october)

常数用户 = {
名称：“泰勒”，
年龄：32岁，
问候（）{
警报(`Hello, my name is ${this.name}`)
},
妈妈：{
名称：“一月”，
问候（）{
警报(`Hello, my name is ${this.mother.name}`)
}
}
}
    
user.mother.greet()
    

当我们调用 `user.mother.greet` 时，我们可以通过查看调用的“点的左侧”来判断 `this` 关键字引用的内容——在这种情况下，`mother`。

所以在 `greet` 的内部，就好像我们有 `my name is ${mother.mother.name}`，这显然是错误的。 相反，由于 `this` 关键字是引用 `mother`，我们可以只做 `this.name`。

名称：“泰勒”，
年龄：32岁，
问候（）{
警报(`Hello, my name is ${this.name}`)
},
妈妈：{
名称：“一月”，
问候（）{
警报(`Hello, my name is ${this.name}`)
}
}
}
    
user.mother.greet()

### SHADCN/UI 是新的引导程序吗？

上周，Vercel 聘请了名为 `shadcn/ui` 的 React 组件的同名集合的匿名创建者 Shadcn 时，收购了另一款 OSS Infinity Stone。 _(周六准备词 ftw.)_

尽管它的名字不那么吸引人，但`shadcn/ui`在过去几个月中一直在爆发。 其中一个关键原因是因为它拒绝称自己为库。 所有组件都是复制/粘贴，它们不是作为依赖项打包的，也不是作为 npm 包发布的。

[docs](https://ui.shadcn.com/docs) 说这种方法为您提供了“对代码的所有权和控制权，允许您决定组件的构建和样式”。 通过不将组件包装在 npm 包中，您可以将组件的设计与它们的实现分开。

对于你们中的一些人来说，这种方法可能会让你想起另一组 UI 组件，比如 Carly Rae Jepsen，它在 2012 年开始席卷世界。它与 _tootstrap 押韵。_

从技术上讲，Bootstrap 是一个可以 `npm install` 的库，但关于它的最好的部分之一是您可以简单地复制/粘贴您需要的组件的代码。 一段时间后，我们都厌倦了我们的网站看起来一样，因为那些自定义覆盖是痛苦的 AF。 这最终导致了更多特定于 React 的 UI 库的兴起，例如 Material UI 和 Chakra。

这些 CSS-in-JS 库通过动态样式和更好的样式范围使定制变得更加容易。 但随着 React 开始从 SPA 转向 SSR 和 RSC，我们已经看到 CSS-in-JS 开始失宠。

**这就是 `shadcn/ui` 的用武之地。** 它提供了 Bootstrap 的复制/粘贴功能以及 Chakra 和 Mui 的轻松定制。 而且因为它是建立在顺风CSS上的，所以它可以比CSS-in-JS库更好地使用现代的React。

这些组件为您提供“一些合理的默认设置”，然后让您轻松定制它们以满足您的需求。 成千上万的开发人员现在已经使用 `shadcn/ui` 来构建自己的 UI 或自己的成熟组件库。

**底线：** 很高兴看到这个组件库 _collection_ 能够从这里去哪里，因为 Shadcn 能够在 Vercel 全职工作。 要赶上 Bootstrap 的受欢迎程度还有很长的路要走，但早期的回报看起来很有希望。

默认情况下，JavaScript中的字符串比较对语言不敏感（这意味着它不考虑特定语言的规则或像重音这样的特殊字符），这导致排序列表不符合正确的顺序。

解决方案是利用 `Intl.Collator` 来实现对语言敏感的字符串比较。

函数 sortAlphabetical(arr) {
const collator = new intl.collator("en", { 灵敏度："base" });
return arr.sort((a, b) => collator.compare(a.firstname, b.firstname));
}

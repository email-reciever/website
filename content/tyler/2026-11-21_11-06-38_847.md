### 万格拉尔诞生了

24 小时前，我们准备了一个完全不同的故事来解决这个问题。 但后来 Angular 团队决定发布一个重大声明并炸毁我的整个晚上——就像他们几年前在我的新婚之夜所做的那样（不要问）。

**大新闻？** 根据您问的人，Angular 是 [definitely](https://twitter.com/sarah_edo/status/1770478763253379488) 或 [maybe](https://x.com/mgechev/status/1770597775010623653) 与 Wiz 框架合并。

如果您不熟悉，Wiz 是 Google 的内部 JavaScript 框架，由 Malte UBL 创建，目前为搜索、Gmail、照片等应用程序提供支持。 马耳特现在 [wishes he had open-sourced Wiz](https://www.industrialempathy.com/posts/11-years-at-google/)，但他当时“没有意识到它是多么强大和独特”。

**它是如何发生的：** 去年，Angular 和 Wiz 团队都在努力将 [Signals](https://blog.angular-university.io/angular-signals/) 添加到各自的框架中。 因此，他们决定共享代码并与_synergize_一起工作，以将Wiz + Angular Signals Primitives采用到Google的生产应用程序之一中。

但他们不只是选择了谷歌计划在一年内杀死的随机应用程序。 他们选择了大卡胡纳——YouTube。

**快进到今天，**和Wangular Signals™️现在正用于100%的YouTube移动网络流量的生产中，并取得了一些有希望的结果：

*   默认情况下性能更好，包括在低端设备上的35％的输入延迟，无需开发人员考虑。
    
*   简化的框架概念，如记忆化、陈旧的闭包和意外的重新渲染。
    
*   具有自动依赖跟踪、自动清理和动态依赖关系的更可维护的代码。
    

**底线：** 就像我们之前提到的，Angular 和 Wiz 是否会完全合并到 Wangular 中仍然有点不清楚。 但看到 Angular 继续依赖于反应性信号并继续自我改造，这真是令人着迷。 无论如何，很高兴看到

6.  文员团队在 [Comparing Authentication in React vs. Next.js](https://go.clerk.com/jpOLLxy) 上写了一个很好的深入了解，其中包含一个现实世界的项目和许多有用的代码示例。 \[赞助\]

发现错误：解决方案
-----------------------

#### 赞助[Datadog](https://www.datadoghq.com/bytes/)

默认情况下，`html` 和 `body` 元素作为块级元素。 这意味着它们只会占用其内容所需的空间。 因此，如果内容不够长，页脚将不会被推到页面底部。 要解决此问题，您可以将 `html` 和 `body` 元素设置为占用视口高度的 100%。

<!doctype html>
    <html lang="en">
      <head>
        <meta charset="utf-8" />
        <meta name="viewport" content="width=device-width" />
<title>粘性页脚</title>
        <style>
HTML，
身体{
身高：100%；
}
    
身体{
字体系列：无衬线；
填充：0；
边距：0；
}
    
身体 > DIV {

显示：网格；
网格模板行：自动 1fr 自动；
}
    
标题，

填充：20px；
}

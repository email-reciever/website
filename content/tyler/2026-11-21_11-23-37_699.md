[Cypress releases v5 to make testing a little less painful](https://docs.cypress.io/guides/references/migration-guide.html#Migrating-to-Cypress-5-0)
----------------------------------- ----------------------------------- ----------------------------------- -----------------------------------

![Kobe Bryant](https://bytes.dev/images/content/kobe5.png)

嘿，科比，我们现在在哪个版本的赛普拉斯上？

**还记得你有的那个很酷的高中老师……**如果你失败了，谁会让你重新参加考试？ Cypress 想要像你的 JavaScript 代码一样酷的老师，它甚至会为你重做测试，而不会让你重写任何测试代码。

**[Test retries](https://cypress.io/blog/2020/08/19/introducing-test-retries-in-cypress-5-0/?utm_content=137773401&utm_medium=social&utm_source=twitter&hss_channel=tw-2774638535)** 是赛普拉斯 V5 的热门新功能。 通过此更新，赛普拉斯将自动重试失败的测试，然后再将其标记为失败。

**为什么这有帮助？**

由于各种原因，测试可能会失败，这并不总是意味着您的代码有问题。 也许您有竞争条件或随机网络故障，或者您的集成依赖项暂时脱机。

在将测试标记为失败之前重试测试有助于确保测试失败，因为您的代码中存在持续错误，而不是因为一些随机中断。 这应该有助于节省时间和麻烦，尤其是在 E2E 测试大型应用程序时。

大多数其他新功能都相当次要，并且 [you can check them out in the changelog](https://docs.cypress.io/guides/references/changelog.html#5-0-0)。

### 底线

自 5 年前推出以来，赛普拉斯迅速发展，迅速成为最受欢迎的 E2E JavaScript 测试框架（抱歉，Selenium）。 添加有用的新功能，如测试重试应该有助于提高赛普拉斯的知名度并扩大其企业用户的付费用户群。

考虑到赛普拉斯已经筹集了 1500 万美元的风险投资，这种快速增长将很重要。 但是，如果他们的增长计划是继续发布使 e2e 测试变得不那么糟糕的新功能，那么我们全力以赴。

发现错误 - 答案
----------------------

我们对 `leo.eat` 的呼叫将失败。 这样做的原因是因为从 `Animal` 返回的对象没有委托给 `Animal.prototype` ，因此 `leo.eat` 将是未定义的。

为了解决这个问题，我们可以使用 `Object.create` 或 `this` 关键字与 `new` 的组合。

功能动物（名称，能量）{
让 animal = object.create(animal.prototype)
animal.name = 名称
动物.能量 = 能量
    
返回动物
}
    
// 或
    
功能动物（名称，能量）{
this.name = 名称
this.energy = 能量
}
    
const leo = 新动物('狮子座', 7)
    

有关更多详细信息，请查看 [A Beginner’s Guide to JavaScript’s Prototype](https://ui.dev/beginners-guide-to-javascript-prototype/)。

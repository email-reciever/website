### 反应原生振动检查

React Native 即将发布 [v0.71](https://github.com/facebook/react-native/releases)，因此现在似乎是将脚趾浸入跨平台水域以进行快速气氛检查的好时机。

**我们是如何来到这里的：** 就像 _Glee_ 中的每个演员一样，自从大约 8 年前首次推出以来，React Native 的崛起就充满了争议。 事实上，前 React 核心团队经理 Tom Occhino [recently](https://youtu.be/C1m5hQDjk20?t=1102) 称 React Native 是“有史以来最具争议的技术之一”。

让我们通过仔细研究 RN 的一些批评来解开双方的包装，然后讨论一些积极的近期发展，这些事态让我们对更光明的跨平台未来充满希望。

**中调：**

*   **性能问题。** 在最坏的情况下，React Native 应用程序会比原生 iOS 和 Android 应用程序感觉更慢、更笨、更有问题。 这通常来自 1) 运送过多的 JavaScript 和 2) 我的个人专长，优先考虑开发人员的体验而不是用户体验。
    
*   **生态系统。** 从历史上看，React Native 依赖于许多经常过时或不稳定的第三方库。 这是一个很大的挑战，因为包作者必须编写两次代码（iOS 一次，Android 一次），而移动端始终是 PITA。
    
*   **路由不良和其他DX问题。 尤其是路由，一直不理想。
    

但变化的风一直在吹，让位于**一些完美的氛围：**

*   **TGFE — 感谢世博会。 Expo 47 最近为 RN 带来了基于文件的路由和并发功能，并帮助改进了上述许多（尽管不是全部）问题。
    
*   **性能改进。** RN V0.70 与新的 Hermes 引擎在 9 月份作为默认值一起提供，这显着 [improved performance](https://reactnative.dev/blog/2022/07/08/hermes-as-the-default#benchmarking)。 即将推出的 0.71 版本将提供一流的 TypeScript 支持。
    
*   **将叙述从“写一次，到任何地方”转移到“一次学习，在任何地方写作”。 这有助于校准期望并减少 Jank，因为开发人员意识到任何移动应用程序通常仍有很多特定于平台的工作。
    
*   **大型应用程序切换到 RN。** 对于框架来说，看到 Discord、Coinbase 和 Shopify 等流行应用程序迁移并给予 [glowing reviews](https://shopify.engineering/migrating-our-largest-mobile-app-to-react-native) 始终是一个积极的信号。
    

**底线：**在跨平台世界中，我们还有很长的路要走，但你可以说 React Native 的氛围比以往任何时候都更强大。

![Tailwind vs Bootstrap](https://bytes.dev/images/content/tailwind-bootstrap-trend.jpg)

Tailwind 超越 Bootstrap – [npmtrends.com](https://npmtrends.com/bootstrap-vs-tailwindcss) 的数据

经过 10 年的运行，Bootstrap 刚刚放弃了“NPM 下载量最高的 CSS 框架”的王冠。 Tailwind现在拥有王位，这要归功于2022年增长了2.65倍。 可能会让你睡觉）。

让我们来看看顺风是如何成为新的顶级狗的：

**组件：** 组件已成为重用样式的事实上的方式，使得构建网站的全局选择器变得不必要。 Tailwind 的实用风格 CSS 接受了这一点，组件 + Tailwind 成为了天作之合。

**性能：** Tailwind 最大的创新是将实用类与工具相结合，以清除未使用的样式。 因此，与其拥有一个非常大的样式表，不如只发布您的网站实际使用的样式。

**开发人员体验：** JIT 编译、[arbitrary variants](https://tailwindcss.com/blog/tailwindcss-v3-1) 和开箱即用的设计系统的默认设置使您的设计系统比以往任何时候都更容易造型。

**Modern CSS:** 一旦浏览器发布新的 CSS 功能，感觉就像 Tailwind 立即将它们集成到其框架中。

最大的问题是，Tailwind 在 2033 年还会有王冠吗？ 到那时，他们可能还制作了多少头像电影？

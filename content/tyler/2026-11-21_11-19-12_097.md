Safari ❤️移动网络
---------------------

在情人节那天，Safari 通过发布 [conservative approach](https://webkit.org/blog/12257/the-file-system-access-api-with-origin-private-file-system/) 来支持 [File System Access API](https://developer.mozilla.org/en-US/docs/Web/API/File_System_Access_API) 来表达他们对强大的 Web 应用程序的永恒热爱——它允许您构建具有直接创建、打开、读取和写入文件的能力的 Web 应用程序。

这听起来可能不是大新闻，但如果您对 Safari、Apple 或 Mr. Timmy Tim 了解很多（这次是 Cook，不是 Chalamet），您还会知道这是一个很大的转变——因为从历史上看，他们对强大的 Web 应用程序的想法表现出了近乎零的热爱。 （尤其是移动网络应用程序）。

**为什么？** 用户隐私。 钱（显然）。 您可能知道，Apple 在所有应用内购买中的 30% 减少了大量现金。 （他们很容易从我妈妈的 Candy Crush 升级中赚取 10 万美元。）而且由于在 Safari 网络浏览器中购买东西时，Apple 赚了 _zero_ 美元，所以很容易理解为什么他们在采用某些方面比 Chrome 慢了 阿普斯。

**但是隐私呢？**人们经常指出隐私问题是Safari对支持“原生API”的犹豫的正当理由。 但这不就是在未经我们同意的情况下将有史以来最糟糕的 U2 专辑下载到世界上每部 iPhone 上的公司吗？ 所以，是的，不确定我是否购买了这种推理方式。

**为什么现在支持这个API？ 重要的是……开发人员一直恳求 WebKit 团队让他们构建很酷的东西。

发现错误 - 解决方案
------------------------

React 将 ref 视为一个“盒子”，可以在其 `.current` 属性中保存可变值，包括 DOM 元素。 由于 React 需要一种方法来更新 ref 的值而不完全覆盖它，因此 ref 本身是一个具有可变 `.current` 属性的对象，可以在不更改对象引用的情况下随时更改。

当我们尝试 `.focus()` `inputRef` 时，会发生错误。 输入 DOM 元素存储在 `.current` 属性中，因此聚焦输入的正确方法是调用 `inputRef.current.focus()`。

这是解决方案-

导出默认函数 inputModal({isOpen, close}) {
const inputRef = useRef(null)
    
useEffect(() => {
如果（isopen）{
inputRef.current.focus()
}
},[ISOpen])
    
// ...
    
}
    

refs 可以存储的不仅仅是 DOM 元素——它们可以存储组件需要保留的任何值，而不会在值更改时引起重新渲染。

### 下一个

去年 10 月，Next.js 13 推出了新的 `app` 路由器，该路由器采用了全新的、革命性的路由和布局方法……适用于以前从未使用过 Remix 的每个人。

该路由器支持 React Server 组件、布局、流式传输和用于数据提取的悬念——这促使 React Core 团队成员（以及最近的 Vercel 员工）Andrew Clark 将 Next 13 命名为“_Real_ React 18 版本”。

**快进到今天，** 并且 `app` 路由器仍处于测试阶段（而 Remix 团队仍然不喜欢被复制）。 但上周的 [Next 13.2](https://nextjs.org/blog/next-13-2) 版本引入了一系列新的改进，旨在让 `app` 为黄金时段做好准备。

以下是亮点：

*   ** 新元数据 API** 通过让您设置具有显式元数据配置的静态和动态 `meta` 标签，为 `app` 路由器提供了更好的 SEO 支持。
    
*   **路由处理程序**让您通过网络的 `Request` 和 `Response` API 为给定路由创建自定义请求处理程序。 这是一个更新的、现代化的 API 路由版本，深入集成到 `app` 中。
    
*   **Next.js Cache (beta)** 是增量静态再生的演变，它在组件级别解锁渐进式 ISR。 这建立在 `app` 路由器中的 React Server 组件和共置数据提取上。
    
*   **静态键入链接（测试版）** 在 `app` 目录中的页面之间导航时提高了类型安全性。
    

**底线：** 最后我们尝试过，Next 的应用程序目录仍然有一些粗糙的边缘，但我们很高兴看到一些进展。

如前所述，如果您查看 `Array.prototype`，它没有 `hasOwnProperty` 方法。 那么，`friends` 数组如何访问 `hasOwnProperty` 呢？

原因是 `Array` 类扩展了 `Object` 类。 因此，当 JavaScript 解释器看到 `friends` 没有 `hasOwnProperty` 属性时，它会检查 `Array.prototype` 是否有。 当 `Array.prototype` 没有时，它会检查 `Object.prototype` 是否这样做，然后调用它。

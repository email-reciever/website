太阳出来的包子出来了
--------------------

谁会赢？ 基于 Rust 和 V8 的 JavaScript、TypeScript 和 WebAssembly 运行时，以及来自世界上最好的 VCS 的 [$26,000,000 in funding](https://techcrunch.com/2022/06/21/deno-raises-21m-to-launch-a-fully-managed-runtime-service/)，或 [one determined boi](https://twitter.com/jarredsumner/status/1544821137128927232)。

**Meet** [Bun](https://bun.sh/)：全新的多合一 JavaScript 运行时，可以安装 npm 包的速度比 yarn 快 20 倍，比 npm 安装快 49 倍，每秒可以捆绑超过 100 万行 JS，并声称比两个 Deno 快 3 倍 和节点。 哦，这一切都是由[one person](https://twitter.com/jarredsumner)建造的。

**特点：**

*   bun 是 node 和 deno 的替代运行时。 但更重要的是，它还旨在成为捆绑器、翻译器和包管理器——这使得它成为 Webpack 之类的其他构建工具的可行替代品（从长远来看）。
    
*   bun 带有内置的 Web API，如 `fetch` 和 `WebSocket`（提醒 Node 几个月前刚刚添加了本机 `fetch` 支持。），它本机实现了 90% 的 node-api 函数。 它还带有一个超快的内置 SQLite3 客户端。
    
*   它实现了节点的模块解析算法，因此您可以在 BUN 中使用大多数 npm 包。
    
*   每个文件都被转译，因此TypeScript和JSX可以正常工作。
    

这已经很多了，但这只是乐趣的一半。 让我们放大为什么 Bun 能够如此快速地令人麻木：

1.  与 Node 和 Deno 不同，Bun 使用 WebKit 的 JavaScriptCore 引擎而不是 V8。 JSC 以比 V8 更难使用而闻名，但在某些情况下要快一点。
    
2.  它是用 Zig 编写的，而不是 Rust 或 C++。 根据 Jarred 的说法，Zig 之所以出色，是因为它“对内存的低级控制和缺乏隐藏的控制流，这使得编写快速软件变得更加简单。” （我们会相信他的话。）
    
3.  Jarred 从头开始写出大部分的 Bun，并且痴迷于对所有的基准测试和手工优化。
    

**底线：** 唯一比 BUN 运行时间更快的是 Bun Hype 火车——GH 仓库在上周 V0.1.0 测试版的前 24 小时内从 1,700 颗星增加到 13,000 多颗。 而且它看起来不会很快放慢速度。

Vue 2 开发人员耐心等待新功能

Vue 回到未来的过去
--------------------------------

我们的最后一个故事很长，所以让我们快点。

[Vue just released v2.7](https://blog.vuejs.org/posts/vue-2-7-naruto.html)（“火影忍者释放”），但如果你一直在家中记分，你可能会想，“等等，Vue 3 现在不是默认值吗？”

是的，但是由于 Vue 2 → Vue 3 迁移一直是 [hairier than expected](https://bytes.dev/archives/89)，因此 Vue 团队决定发布 v2.7，与仍在使用 Vue 2 的开发人员分享一些很酷的新 Vue 3 功能。（他们称之为 Evan You _Benevolent_ 独裁者。）

此版本的最大亮点是它将完整的 [Composition API](https://vuejs.org/guide/extras/composition-api-faq.html) 带到 Vue 2。这个集合允许您使用导入的函数而不是声明选项来编写 Vue 组件 - 这允许更好的类型推断、更好的逻辑重用和更灵活的代码组织。

这在尝试扩展 Vue 应用程序时提供了更好的体验。

**底线：**此版本讲述了将应用从Vue 2迁移到Vue 3的升级体验，但它也说明了Vue团队愿意倾听Vue开发人员并与他们见面的意愿 🙏。

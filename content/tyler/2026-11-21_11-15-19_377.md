### Expo 47 落下和肮脏

我退出了构建移动应用程序的原因与我在犹他州南部胃肠疾病中心志愿服务退休的原因相同：他们没有付出足够的钱来处理所有这些混乱。

但是一些开发人员仍然在与良好的移动战斗战斗——即使这意味着处理多个代码库、多个应用程序商店以及尝试为数十种不同的设备类型构建本机体验所带来的所有问题。 但是，嘿，有人需要确保我的孩子可以玩地铁冲浪者，而爸爸则毁灭了推特，所以感谢您的服务。

Expo（又名 React Native 的 Next.js）一直在努力让移动开发人员减少六年多的痛苦 - 他们刚刚发布了 [a major SDK update](https://blog.expo.dev/expo-sdk-47-a0f6f5c038af) 看起来像是向前迈出的一大步（我们希望 🙏）。

**快速审查：** Expo 是框架及其背后的公司的名称（一点也不混乱）。 expo-the-company_ 具有自动化构建过程和应用商店提交过程的服务。 expo-the-framework_ 是 React Native 的 SDK，它带来了路由和跨平台模块等基本功能，用于与设备的摄像头、传感器和联系人列表进行交互。 在这一点上，它基本上是使用 React Native 的默认方式。

以下是世博会47中令人兴奋的新内容：

*   **基于文件的路由：** 尝试实现跨平台路由通常是混乱和破坏的秘诀。 但是我们在移动设备之类的网络平台上看到了 47 号世博会 [brings the FBR magic](https://blog.expo.dev/rfc-file-system-based-routing-in-react-native-7a35474722a)。
    
*   **本机模块 API：** Expo 具有 [a new API](https://docs.expo.dev/modules/module-api/)，使 H4RDC0R3 移动工程师可以使用 Swift (iOS) 或 Kotlin (Android) 的语言轻松创建本机模块，这些语言与 React Native 无缝协作。
    
*   **Hermes 默认情况下：** React Native 的新 JavaScript 引擎 [improves cold start times](https://reactnative.dev/blog/2022/07/08/hermes-as-the-default#ios-benchmarking-data) 超过 50%。 不要与“默认情况下的疱疹”混淆，如果您参加在巴哈马的 FTX 公司静修会，您可以期待。
    
*   **Concurrent React:** Expo 47 将 React 18 和 React 的并发功能带到您的移动应用程序中，使其成为“Real React 18 版本”第 2 部分（这次用于移动设备）。
    

**底线：** 就像 React.js 一样，Expo 越来越像 [the future of React Native](https://twitter.com/jamonholmgren/status/1593319397573394432?s=20&t=MAGzF-b_0rae9wh8OpOSpw)。 而这个版本_\*可能\*_足以吸引我摆脱移动开发人员的退休生活。

#### 赞助[Sleuth](https://www.sleuth.io/accuracy-matters?utm_source=newsletter&utm_medium=email&utm_campaign=bytes)

让我 = 0
    
函数 x() {
i++
返回 10
}
    
i += x()
    
console.log(i) // ?
    

答案是`10`。 这是它的工作方式。

为了清楚起见，我们可以将`i += x()`重构为`i = i + x()`。 从那里，解释器开始评估我们的代码。 在它评估函数调用之前，似乎 `i` 计算为 `0`，所以现在我们的代码是 `i = 0 + x()`。 调用 `x` 返回 `10`，所以现在是 `i = 0 + 10`，它给了我们 `i = 10`。

请注意，如果您交换 `i` 和 `x()` 的顺序，例如 `i = x() + i`，您将获得不同的值 - 🫂。

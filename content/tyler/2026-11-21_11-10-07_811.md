### 查询的安魂曲

jQuery 下周就满 17 岁了，这意味着旧的 Dollar-Tree 库终于能够看到一部 R 级电影，而不必偷偷溜到后面（就像我第一次看到 _Tropic Thunder_ 时所做的那样）。

尽管我们大多数人已经有一段时间没有啜饮JQ Juice了，但你可以很容易地说它是🐐 JS框架——因为它出现在JavaScript最需要它的时候。 让我解释一下。

**当 2006 年 jQuery 出现时，网络是一个非常不同的地方。** 和“不同”，我的意思是更糟。

Chrome距离上线还有两年的时间，当时占主导地位的浏览器（Firefox，IE和Safari）都使用了不同的浏览器引擎，这些引擎以略微不同的方式实现了JavaScript和DOM。 这迫使开发人员花费大量时间来确保他们的网站“跨浏览器兼容”，而仅仅在2023年阅读这句话，可能就给了每个40岁以上的开发人员一系列痛苦的闪回。 _（抱歉没有触发警告。）_

更糟糕的是，Vanilla JavaScript 已经 [nowhere close](https://youtu.be/EUlM3wx546o?t=31) 到了今天的样子。 我们仍然停留在 ECMAScript 3 上，而 ES4 未能在 TC39 委员会中达成共识。 我们现在认为理所当然的基本任务，例如获取异步数据和基本的 DOM 操作，需要大量复杂且冗长的代码。

**走出这黑暗，我们的英雄出现了。**

jQuery 通过抽象出浏览器引擎之间的差异来规范浏览器行为，并为我们提供了一种统一的方法来与每个浏览器上的 DOM 进行交互。 它还提供了比 Vanilla JS 更简单、更具表现力的语法，用于选择和操作 DOM 元素 — `$` ftw。

这些抽象实际上并没有“解决”网络的任何问题，但它们提供了一种有用的创可贴，可以保护开发人员免受当时 Web 开发人员最痛苦的部分的影响。

但最终，创可贴是打算被移除的。 在 2010 年代中期——随着 Vanilla JavaScript 在 ES5 和 ES6 中变得越来越强大，网络浏览器围绕共同标准结合在一起——我们不再像以前那样需要 jQuery。

就像警察局长詹姆斯·戈登终于控制了哥谭的罪行一样，所以这座城市不再需要蝙蝠侠了。 因此，jQuery 开始让位于帮助抽象出新的和不同问题的下一代框架。

**但这里有一个有趣的问题需要考虑：**如果 jQuery 在像 React 或 Angular 这样的大型科技公司中孵化会发生什么？

我们显然不能确定，但 React 提供了一个有趣的反例。 尽管核心原则基本保持不变，但 React 本身在过去 10 年中发生了巨大变化。

如果 John Resig 和一个“jQuery 核心团队”获得了全职工作的报酬，他们会尝试创新更多，并将 jQuery 变成它从未打算成为的东西来证明他们的薪水是合理的吗？ 他们肯定会有强大的动力这样做。 谁知道呢，也许我们今天仍然像 2009 年一样啜饮 JQ 果汁。

**底线：** 生日快乐，国王。

发现错误：解决方案
-----------------------

#### 赞助[Secureframe’s free demo](https://secureframe.com/request-demo-4?utm_source=partner&utm_medium=newsletter&utm_campaign=082123-bytes-newsletter)

如果您运行原始代码，您将获得“未捕获的 TypeError：无法读取未定义的属性（读取‘长度’)”。 我们使用的唯一位置 `.length` 是在 `reduceLanguages` 函数中，因此我们可以推断 `this.languages` 是 `undefined` 并且我们错误地使用了 `this` 关键字。

每当您试图弄清楚 `this` 关键字引用的内容时，您需要查看使用 `this` 关键字的函数在哪里被调用。 在我们的示例中，我们不知道，因为它是在 `reduce` 的实现中。 为了确保在正确的上下文中调用 `reduceLanguages` 并因此具有正确的 `this` 绑定，我们有两个选择。 首先，老派的方式-使用`.bind`。

问候（）{
常量 Hello = `Hello, my name is ${this.name} and I know`;
    
const langs = this.languages.reduce(reduceLanguages.bind(this), "");
    
返回 Hello + Langs；
}
    

其次，更好的方法 - 使用箭头函数。

问候（）{
常量 Hello = `Hello, my name is ${this.name} and I know`;
    
const langs = this.languages.reduce((str, lang, i) => {
如果 (i === this.languages.length - 1) {
返回 `${str} and ${lang}.`；
}
    
返回 `${str} ${lang},`；
}, "");
    
返回 Hello + Langs；
}
    

之所以有效，是因为在箭头函数中`this`是_lexically_确定的。 箭头函数没有自己的`this`。 相反，就像变量查找一样，JavaScript 解释器将查看封闭（父级）范围以确定 `this` 应该引用的内容。

想阅读更多？ 退房[Understanding the “this” keyword, call, apply, and bind in JavaScript](https://ui.dev/this-keyword-call-apply-bind-javascript)。

### 原子CSS的Draw-4通配符

玩 Uno 和写作 CSS 都教会了我一些宝贵的人生课程——主要是幸福是短暂的，痛苦是不可避免的。

因此，当我看到一个名为 [UnoCSS](https://unocss.dev/) 的快速增长的原子 CSS 引擎周围的所有嗡嗡声时，我知道我必须调查它（并希望在此过程中处理一些未解决的创伤）。

**快速背景：** unocss 由 Anthony Fu 创建，他是一位 _PROLIFIC_ OSS 作者，他帮助创建和维护了 Vite、Vue、Nuxt 和 [lots more](https://antfu.me/projects) 等项目。 Uno的想法是在几年前提出的，当时Anthony正在创建Vitesse，这是一个最初使用Tailwind的流行的Vite Starter模板。

当时，Tailwind 遵循传统的原子 CSS 模型——它为您提供了您可能需要的所有 CSS 实用程序，然后使用 PurgeCSS 扫描您的捆绑包并删除您未使用的内容。 问题是，这种方法可能非常缓慢（尤其是在开发中）——这是您可以对 Vite 开发人员进行的最严重的侮辱。

2021 年，Tailwind 通过引入按需 JIT 引擎解决了这个问题，该引擎可以预先扫描您的源代码并仅生成您需要的实用程序。 但由于 Tailwind 的 API 和插件系统仍然是为“传统”原子 CSS 设计的，因此 Anthony 觉得有机会从头开始 [reimagine Atomic CSS](https://antfu.me/posts/reimagine-atomic-css)。 所以他做到了。

** UNOCSS 的独特之处的大部分原因**来自于它是一个稍低级别的_engine_，而不是一个框架。 这是给你带来的：

*   **更多的灵活性** — 它与各种构建工具具有一流的集成，可以在许多不同的地方使用。
    
*   **易于定制**——它不那么固执，也没有核心实用程序； 所有功能都来自[presets](https://unocss.dev/presets/uno)。
    
*   **better performance** — 没有解析、没有 AST 和不扫描使它比 Tailwind JIT 快 5 倍。
    

**底线：**这种“在堆栈中走一层，让它更快/更灵活”的策略对 Vite 来说效果很好。 它也适用于 unocss 吗？ 早期回报是[looking good](https://npmtrends.com/@unocss/core-vs-windicss)。

一个对象的深拷贝是一个副本，其属性与复制的源对象不共享相同的引用。 在 JavaScript 中进行深度复制的一种方法是使用 `JSON.stringify` 和 `JSON.parse`。

这种情况适用于我们的情况，但它会将 `created` 转换为字符串。 为了防止这种情况，您可以使用 `window.structuredClone` 来代替（假设浏览器支持）。

返回窗口.StructuredClone(obj)

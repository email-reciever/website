### css-in-js 如此回归

如果你最近一直在 React Dark Web 上闲逛，你可能会注意到一个令人惊讶的趋势——新的 CSS-in-JS 库正在像 2017 年一样重新出现。

[Panda](https://panda-css.com/) 去年夏天推出，Meta 开源的 [StyleX](https://stylexjs.com/blog/introducing-stylex) 在 12 月，Material UI 上个月发布了 [PigmentCSS](https://mui.com/blog/introducing-pigment-css/)，[Restyle](https://www.restyle.dev/) 刚刚推出。

**为什么突然复苏？**在我看来，有两个潜在的原因：

1.  时间是一个扁平的圆圈
2.  React中的新功能

这不是深入尼采的时间或地点，所以让我们讨论第二个原因。

`styled-components` 和其他 CSS-in-JS 库在 2010 年代后期开始流行，因为它们帮助解决了按需解决样式封装和渲染样式等问题。

但是这种方法在服务器渲染中从来没有很好地发挥作用，通常会迫使您跳过一圈，例如在服务器上渲染您的应用程序两次以使事情顺利进行。 随着服务器渲染变得越来越普遍，开发人员逐渐远离 CSS-in-JS 库，转而采用其他方法。

但是 React Server 组件和其他新的 React 功能可以改变这一切。 例如，React 19 在组件内部如何处理 `<script>` 和 `<style>` 标记方面具有新的功能。 这包括支持 [style hoisting](https://react.dev/blog/2024/04/25/react-19#support-for-stylesheets)，其中 React 根据它们的 `precedence` 属性将这些标签移动到文档的头部 - 同时支持客户端上的并发渲染和服务器上的流渲染。

ReStyle 利用此功能以 _just works_ 在服务器上的方式按需加载样式 - 因此您可以在 JavaScript 中编写样式并将它们通过有线发送为 CSS。

**底线：** 上周，我走进一家古董店，看到两个少年在争论我在 2003 年在中学自豪地穿的那双厚实的 etnies 滑板鞋。是的，这让我觉得自己老了，但它也提供了一个完美的 隐喻 React 造型解决方案的隐喻——只需等待几年，无论您以前喜欢什么，都可能会再次变得酷。

记录什么？

函数 getport(url) {
const { port } = 新网址(url);
    
如果（端口 === '80'）{
console.log("你使用的是默认端口");
}
    
如果（端口 === '443'）{
console.log("您使用的是默认的安全端口");
}
    
控制台.log(`You are running on port "${port}"`);
}
    
getport(`http://example.com:80`) // 你在端口“”上运行
getport(`http://example.com:8080`) // 你在端口 "8080" 上运行
getport(`https://example.com:443`) // 你在端口“”上运行
getport(`https://example.com:3000`) // 你在端口“3000”上运行
    

JavaScript 中的 `URL` 构造函数即使明确提供了默认端口，也会剥离默认端口。 由于端口 `80` 是 HTTP 的默认值，而端口 `443` 是 HTTPS 的默认值，因此该端口会从 URL 中剥离，从而导致一个空字符串。 在您可能不需要知道的JavaScript Quirks下将此归档，但可以为未来的调试节省数小时。

### HTML，但要让它额外

您最近很可能听到了很多关于 HTMX 的消息——我们都知道这代表 _hyper-text markup x gon' 把它给你。_

我们在 10 月份写过关于 UI 库的文章，但让我们快速回顾一下它是如何工作的，为什么我们会看到它到处都出现，以及它可能会从这里去哪里。

**快速审查：** HTMX 结合了 Ajax、WebSockets 和服务器发送的事件，并通过属性将它们直接放入您的 HTML 中。 它允许任何 HTML 元素（不仅仅是锚点和表单）发出 HTTP 请求，并且允许任何事件触发请求。

如果这听起来很熟悉，那是因为它与 Phoenix LiveView 和 Ruby on Rails 的 Hotwire 等框架非常相似，但还有更多…… `x`。

**它是如何工作的：** 不是发送 JSON 并使用 JavaScript 将其转换为 HTML，而是发送 HTML ——但它的架构允许您向客户端发送小片段（仅更新或交互所需的内容）。 服务器处理所有应用程序状态（因此它不会在客户端和服务器上重复）并发送特殊的 HTTP 标头，让客户端知道要进行哪些更新。

**那么为什么我们突然到处看到 HTMX？** 几周前，当 HTMX 团队全力以赴进行狂欢推文 [rusty memes](https://twitter.com/htmx_org/media) 时，它就开始了。

这些推文帮助各种科技 YouTuber 和内容创作者关注，他们总是在缓慢的夏季寻找半有趣的话题_（我可以联系）_。 从那里开始，HTMX被#useThePlatform硬线支持，他们渴望支持一个声称“允许您直接从HTML访问现代浏览器功能的库，而不是使用JavaScript”。

**只有一个问题：** 这是一个谎言。

好吧，这可能有点苛刻，但事实证明，如果不使用 _some_ javascript，就不可能使用 htmx。 如果只有外面有人提到了这个事实[284 days ago](https://bytes.dev/archives/129#:~:text=How%20does%20the%20client%20do%20this%3F%20It%20rhymes%20with%20%E2%80%9CLavascript%E2%80%9D%2C%20but%20shhh%20don%E2%80%99t%20spoil%20the%20narrative%20%F0%9F%A4%AB.)🙃。

HTMX 仍然是保持客户端轻量化的好方法，几乎可以在后端完成所有工作，并利用 HTML 所提供的所有功能。 但像所有事情一样，它有权衡取舍，可能不会在一夜之间取代 JavaScript 来构建 Web 应用程序。

**底线：** 看看 HTMX 从这里去哪里会很有趣。 它只是 Twitter 平板中的一个闪光点，还是会成为更多合法应用程序（如 [this one](https://www.youtube.com/watch?v=3GObi93tjZI)）在生产中使用的解决方案？ 继续关注。

#### 赞助[Courier](https://www.courier.com/inbox/?utm_content=homepage&utm_medium=bytes-newsletter-7-31&utm_source=email&utm_campaign=ui.dev)

函数差数毫秒(date1, date2) {
常量 t1 = 新日期(date1).gettime();
const t2 = 新日期(date2).gettime();
返回 T1 - T2；
}
    
差距毫秒（'2021-01-01'，'2021-01-02'）；
    

在 JavaScript 中，类方法不是实例的直接属性，而是属于类的原型。 当您尝试对方法进行解构时，您会尝试直接从实例中提取它，这不起作用，因为 `getTime` 不是直接属性。 另一方面，`new Date().getTime()` 之所以有效，是因为 JavaScript 检查 `prototype` 链并在 `Date` 原型上找到 `getTime`。

如果您想了解更多信息，这是我们不久前关于该主题的文章。 – [A Beginner’s Guide to JavaScript’s Prototype](https://ui.dev/beginners-guide-to-javascript-prototype)。

毛毛雨。

### 是否有一个松散的棱镜杀手？

肯定有。 它的名字是毛毛雨——例如，“请在这把甜蜜的饼干上淋上一些甜的、类型安全的蜂蜜。” （是的，我饿了。）

更少的比喻，[Drizzle](https://github.com/drizzle-team/drizzle-orm) 是 SQL 数据库的 TypeScript ORM。

**好的，但这听起来不像 Prisma 吗？** 是的，但有一些关键的区别。 要了解它们是什么，让我们先仔细看看 Prisma 本身：

*   Prisma 为您提供类型安全的客户端，让您可以从应用程序查询数据库。 为此，您必须以 Prisma 特定的格式定义 DB 架构，然后运行 Code Gen 步骤以定位所需的语言（这需要一些额外的工具）。
    
*   这种方法允许 Prisma 模式文件成为中性的真实来源，因此您可以为任何语言生成客户端。 但是当 Prisma 意识到大多数开发人员只是想使用 TypeScript 时，他们就停止了支持 Go 并放弃了支持其他语言的计划。
    
*   这个最初决定优先考虑多语言支持的决定伴随着一些至今仍存在的权衡——比如增加的复杂性和一些[performance issues](https://youtu.be/3tl9XCiQErA?t=65)（尤其是对于无服务器环境，它们可能会经历长时间的冷启动）。
    

另一方面，Drizzle 从第一天开始就与 TypeScript 保持着独家关系，并且从未尝试过与其他语言约会。 这种一夫一妻制的重点使其能够优化 TS 开发人员的最大类型安全性、性能和易用性。

**这是它的工作原理：**

*   Drizzle 说“如果你知道 SQL，你就会知道 Drizzle Orm。” 那是因为它基本上只是 SQL 的类型安全版本。 而且因为您的模式是用 TS 编写的，因此您可以避免 Prisma 的代码生成步骤（以及潜在的性能问题）。 这一切都是通过推理完成的。
    
*   [Drizzle Kit](https://github.com/drizzle-team/drizzle-kit-mirror) 类似于 Prisma 的声明式模式管理工具，它允许您定义架构并允许它对您的数据库进行更改。 但是再一次，你在普通的 TypeScript 中完成了这一切——没有安装额外工具的复杂性，就像你使用 Prisma 一样。
    

**底线：** 还处于早期阶段，但在 TypeScript 上加倍似乎总是一个明智的策略。 而且我学会了永远不要与类型的书呆子打赌，所以我们将密切关注毛毛雨，fo' shizzle。

尖端

#### 由[Datadog](https://datadoghq.com/bytes)呈现

_他们的 [Front-end Developer Kit](https://datadoghq.com/bytes) 充满了最佳实践指南、解决方案简介和视频，以帮助您更好地了解应用的用户活动。_

我最喜欢的使按钮感觉更多_alive_的技巧之一是当它处于活动状态时将其位置以1px进行翻译。 这给人的感觉是它正在被压制并且很容易实现。 我们需要做的就是向 `active` 伪选择器添加一个变换，并向按钮转换以使其变得漂亮和平滑。

按钮{
过渡：所有 0.2 的轻松进出；
}
    
按钮：活动{
转换：翻译（1px）；
}
    

由于按钮有可能被禁用，因此 `:not` 选择器仅在按钮未禁用时才会派上用场。

按钮{
过渡：所有 0.2 的轻松进出；
}
    
按钮：不（：禁用）：活动{
转换：翻译（1px）；
}
    

不错，点击更令人满意。

### Turso 又做了一次

在 Rust 中成功重写 SQLite 后，Turso 团队感到 Tyrone Biggums 渴望再次这样做。 但这一次，他们是 [rewriting Postgres](https://turso.tech/blog/a-new-modern-version-of-postgres-in-rust)。 您可能会认为这是另一个面包风格的斜坡端口，但（幸运的是）它比这更有趣。

**我们是如何到达这里的：**

就像我们之前提到的，Turso 在过去几年中的大部分时间都在 Rust 中重写 SQLite。 该项目的最初目标是将异步 I/O 等功能添加到 SQLite 中（这是他们的“开放式分叉”`libSQL` 无法支持的）。 但重写的副作用之一是它将数据库的后端从 SQLite 中抽象出来，打开了支持他们想要的任何 SQL 方言的大门。 在这种情况下，Postgres。

**这是它的工作原理：**

*   **Common AST:** Turso 将查询解析为公共抽象语法树 (AST)。
*   **字节码编译器：** AST 编译成可以在虚拟机上运行的字节码。 **扩展 VDBE：** Turso 扩展了 VDBE，SQLite 的数据库特定字节码引擎，而不是从头开始构建 VM。 虽然它不是像 JVM 或 Wasm 那样的通用 VM，[it passes the most important test (running Doom)](https://turso.tech/blog/a-new-modern-version-of-postgres-in-rust#it-really-is-a-virtual-machine-)。
*   **存储引擎：** 接收到字节码后，存储引擎将数据读写到文件系统，并可扩展以支持不同方言支持的各种索引策略。

**底线：** 虽然 Turso 可能不会完全支持 Postgres 扩展之类的内容，但您可以拥有一个可以支持 SQL 方言的可嵌入数据库这一事实客观上很酷。

让我们小心不要过多地称赞他们，因为 Pekka 和 Glauber 未经检查的锈瘾已经走得太远了。

发现错误：解决方案
-----------------------

#### 赞助[Unblocked](https://srv.buysellads.com/ads/long/x/T6MLWUSPTTTTTTCRQMZCWTTTTTT36PBW2VTTTTTTODAMOBETTTTTTJB4PJIWEIIF574ICBPLKMIN5JBP237D5JI62RWT?cid=387721)

堆栈是 LIFO（后进先出），但 `peek` 返回数组中的第一个项目，而不是最后添加的项目。

改为返回最终数组元素：

类堆栈 {
构造函数() {
this.Items = [];
}
    
推（元素）{
this.items.push(元素);
}
    
弹出（）{
如果 (this.isEmpty()) {
抛出新错误（“堆栈为空”）；
}
返回 this.items.pop();
}
    
偷看（）{
如果 (this.isEmpty()) {
抛出新错误（“堆栈为空”）；
}
返回 this.items[this.items.length - 1];
}
    
是空的（）{
返回 this.items.length === 0;
}
    
大小（）{
返回 this.items.length;
}
    
清除（）{
this.Items = [];
}
}

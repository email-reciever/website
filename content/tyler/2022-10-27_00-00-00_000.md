### 来自下一个配置的热议

上周下一个会议的主题与其他下一个会议的主题相同：“我们都穿黑色。”

但今年，他们可以很容易地使用，“你不会在不制造一些敌人的情况下获得 1400 万个朋友_Monthly Downloads_。” 这是因为即使他们在过去几天宣布了很多很酷的东西，但一些开发人员出于两个原因中的一个（或两者）而成为 Big Mad™️：

1.  接下来与 React 团队“太近”。 这主要是为了响应 React Core 团队成员，Andrew Clark 在主题演讲中上台，并说这个新的 Next 13 版本是“真正的 React 18 版本”，因为它为 React Server 组件和其他 React 18 功能提供了实用的 DX。
    
2.  下一个从其他框架或构建工具中复制的功能，而不给出“适当的归因”，无论这意味着什么。 （也许吉列尔莫可以寄给他们一个可食用的安排，上面写着“你是归功于”的。）
    

我们注意到，大多数在 Twitter 上发泄最困难的人都是那些在看到 Next、Vercel 和/或 React 失败时具有既得利益（财务或声誉）的人。 React 会给下一个不公平的特殊待遇吗？ _它绝对是_，根据`[insert competing VC-backed frontend framework]`。

像往常一样，现实更加微妙。 React 与 Vercel 团队的合作可能比与下一个用户数量为 0.1% 的元框架更紧密地协作 - 原因与 YouTube 与 MrBeast 的协作更紧密的原因与我的 YT 频道的关于微妙的社会评论的视频文章的协作更为密切 光环 1 故事情节（537 名订阅者和计数）。 但这并不一定意味着有一些更大的阴谋不公平地破坏竞争（但去他妈的，MrBeast）。

好吧，这已经足够戏剧了，让我们进入酷炫的下一个新事物：

**[Next.js 13](https://nextjs.org/blog/next-13)** 采用全新的（取决于您问谁）来处理网站布局、数据获取和服务器渲染的方法。 一个新的 `app/` 目录支持布局、服务器组件、流式传输和 _(暂停效果)_ 悬念用于使用新的 `use` 钩子获取数据。

此版本还带有一个新的 `next/image` 组件、一个全新的字体系统和新的 OG 图像生成。 在这个幸运的 #13 版本中有一个 _lot_ 正在进行，所以如果您已经感觉有点失落并想要一个有用的迁移指南，请查看此 [tweet thread](https://twitter.com/shadcn/status/1584971527820541953?s=20&t=2fOMSS5-gx94UZd5hNXO2Q)。

**[Turbopack](https://turbo.build/pack)** 是一个全新的（仍然是 alpha）基于 Rust 的增量捆绑器，自称是“Webpack 的继任者”（可以说，因为它是由 Webpack 的创建者 Tobias Koppers 领导的）。

它集成了 Turborepo 以缓存重复操作，并声称其更新速度比 Vite 快 10 倍，速度比 Webpack 快 700 倍。 这些是早期的，樱桃挑选的_internal_基准，所以如果你从Vite的角度对他的想法感兴趣，请对这些数字持保留态度。

**[Vercel acquired Splitbee](https://vercel.com/blog/vercel-acquires-splitbee)** 在不使用 Google Analytics 的情况下为您提供符合 GDPR 的第一方分析。 跳出率和 A/B 测试并不是世界上最性感的东西，但如果这有助于摆脱每个怪异网站上的 GDPR 弹出式横幅，Vercel 真的可以拥有我所有的钱。

**底线：** Twitter 上的一些人可能会对这一切的进展感到不安，但 Vercel 提醒我们所有人，历史是由获胜者撰写的。 我只希望明年仇恨者不要冲上舞台，把汤扔在吉列尔莫身上，把自己粘在李身上以示抗议（😉😉）。

MDX vs Markdown 它与标记与备注解析 - 数据按 [npmtrends.com](https://npmtrends.com/@mdx-js/mdx-vs-markdown-it-vs-marked-vs-remark-parse)

尽管不是“真正的”编程语言，但对于大多数开发人员来说，HTML 显然是太多的工作。 书写标签和尖括号？ 格罗斯。 我们显然更喜欢编写我们无法记住的语法，也无法完成 HTML 可以做的大部分工作——这就是我们喜欢 Markdown 的原因，宝贝！

它是如此之少，所以 [clean](https://youtu.be/cISYzA36-ZY?t=159)，你最好相信我正在用它写这份时事通讯。 那么是什么让这些 `.md` 处理器的上涨速度比汽油价格更快呢？

1.  SSGS：2016 年左右，静态站点生成器变得非常流行。 很大一部分网络远离了 WordPress，但仍然想要一些简单的内容来编写内容——输入 Markdown。
    
2.  插件：当你在解析AST时，想要“在你在那里做事”的诱惑是真实的。 事实上，几乎每个 Markdown 解决方案都有一个插件系统来提供代码片段的语法突出显示、自动链接等功能。
    
3.  灵活性和力量正在获胜：Remark 拥有最大的插件生态系统，使其非常强大，这显然对开发人员很有吸引力。 MDX 将其嵌入您选择的框架中的组件的能力将其提升到一个新的水平。 Astro 全力以赴地使用 MDX，因此我们希望看到它们继续增长。
    
4.  性能：这是速度不是一切的实例之一。 鉴于 Markdown 仍主要用于静态站点生成器，它并不是一个大考虑，但我希望随着 Web 转向更动态的解决方案而改变。

YARN 3 希望你这次_\*实际上\*_升级
------------------------------------------------

YARN 上周发布了 V3 具有一些很酷的新功能，但 [breaking changes](https://github.com/yarnpkg/berry/blob/master/CHANGELOG.md) 的 _much_ 列表比 Yarn 2 版本更短（谢天谢地）。

**我们是如何到达这里的？** YARN 是像 npm 这样的开源软件包管理器，它是在 2016 年创建的，用于解决 npm 的性能和安全问题。 从那时起，NPM 已经大大提高了它的性能和安全性，并复制了一些关键的 YARN 功能（👋 workspaces），因此它们实际上并没有以前那么不同。

许多开发人员在2020年1月基本上从头开始重写它时，许多开发人员都在努力升级到Yarn 2，其最初的创作者之一甚至都在努力_NOT_火焰整个YARN项目[on Twitter](https://twitter.com/sebmck/status/1300655408688709633?s=20)。

无论如何，**这是 YARN 3 的新功能：**

*   **更容易升级** — 给人们他们想要的东西🙏。 即使您从 v1 跳到 v3，迁移也不会那么痛苦，因为 YARN 现在可以检测到这种情况并自动启用一些主要的新功能，例如 [`node-modules` 链接器](https://yarnpkg.com/features/pnp#pnp-loose-mode)。
    
*   **better performance** — 由 [esbuild](https://esbuild.github.io/) 带给您，它也用于创建一个新的 [`@yarnpkg/esbuild-plugin-pnp`](https://github.com/yarnpkg/berry/tree/master/packages/esbuild-plugin-pnp) 包，让您可以使用默认的 YARN 安装模式透明地构建代码。
    
*   **New Plugin APIs** — Yarn 现在支持可以将自己注入到各个地方并利用核心提供的一些内置模块的插件。
    

**底线：** 如果您曾经是纱线风扇，但被 v2 迁移关闭，现在可能值得重新访问它。

Safari 会杀死网络吗？
---------------------------

[Tim Perry](https://twitter.com/pimterry) 这么认为。 他上周在 [well-researched article](https://httptoolkit.tech/blog/safari-is-killing-the-web/) 中陈述了一个非常有说服力的案例，该案认为 Safari 并没有保护网络免受 Chrome 的侵害（正如某些人声称的那样），而是慢慢地杀死了它。 整篇文章值得一读，但我们想强调几点并给出我们的看法。

** Safari 正在杀死网络的三种方式：**

*   **[By omitting key stable features](https://httptoolkit.tech/blog/safari-is-killing-the-web/#safari-is-killing-the-web-by-omitting-easy-safe-features)** — 根据 [Can I Use](https://caniuse.com/) 的说法，Safari 的功能支持落后 10%，落后 Chrome 15%。 我们也不是在谈论随机的、深奥的功能——除了 Safari 之外，几乎所有其他浏览器都支持特定的 CSS 属性和其他功能。
    
*   **[By not fixing bugs](https://httptoolkit.tech/blog/safari-is-killing-the-web/#safari-is-killing-the-web-through-show-stopping-bugs)** — Safari 的 [failed web standards tests](https://wpt.fyi/results/?label=experimental&label=master&aligned) 比 Chrome 和 Firefox 多 2 倍。 Safari 发布每六个月发布一次，每六周或更短时间更新一次，所有其他浏览器都会发布更新，从而使错误变得更加复杂。
    
*   **[By ignoring newly proposed APIs](https://httptoolkit.tech/blog/safari-is-killing-the-web/#safari-is-killing-the-web-by-ignoring-proposed-new-apis)** — Safari（与 Firefox 一起）拒绝了 Chrome 的提议，让浏览器能够使用蓝牙、写入本地文件以及与后台服务器同步内容。 这里有合法的隐私和安全问题，但完全忽略这些API（而Chrome向前推进）可能会导致某些网站抛出“为了获得最佳体验，切换到Chrome”的横幅。
    

**为什么会发生这种情况？**

世界上最有价值的公司（实际上是 Mozilla 的员工数量是 50 倍）如何监督性能如此持续不佳的浏览器？ 像往常一样，Charlie Munger 和 Wu-Tang 联手给了我们答案：**“激励措施统治着我周围的一切。”**

事实证明，Apple 有很多 [more to gain](https://mobile.twitter.com/elonmusk/status/1421152540394143746) 来自本机应用程序的“围墙花园”，而不是从免费和开放的互联网上获得的（确切地说是 30% 的应用内购买）。 这并不是说这是一个明确的策略，或者说是 Safari/Webkit 团队中非常有才华的开发人员应该受到责备，但很明显，苹果并没有将其近乎无限的资源用于浏览器。

不管是什么原因，如果 Safari 没有尽快发挥作用，Chrome 将变得比现在更受欢迎/占主导地位——这最终将赋予它充分的力量来塑造它认为合适的整个网络。 没有人想要那样。

### 100年的HTMX

[htmx 4.0 was released this week](https://four.htmx.org/announcements/2026-08-28-htmx-4.0.0-is-released) _Only_ 在他们宣布 Alpha 8 个月后，所以正如任何不耐烦的开发人员优秀的记者都会做的那样，我问的是什么花了这么长时间？

首先，我们心爱的超文本媒体系统的这个版本被重写在 `fetch` API 的顶部，以支持流媒体、SSE 和其他 2020 年时潮人不关心的现代浏览器功能。 团队花了很多时间进行迭代和精炼。 那个……并构建一个 `htmx` Game Boy 游戏。 谁能说哪一个得到了更多的关注，但这既不是这里也不是那里。

重要的是它是稳定的，随时准备为 [the next 100 years](https://four.htmx.org/announcements/2026-08-28-htmx-4.0.0-is-released#:~:text=have%20made%20explicit%20choices%20that%20we%20feel%20will%20put%20htmx%2Dbased%20applications%20in%20a%20good%20spot%20for%20being%20100%2Dyear%20web%20services) 服务人类。 既然这是你的曾孙要写的，让我们快速回顾一下 `htmx` 的工作原理。

`htmx` 4.0 的工作原理：

*   **事件：** 在您的 HTML 模板中，特殊 `hx-*` 属性声明要监听哪些事件、发出哪些请求以及应如何处理响应。 `htmx` 客户端处理这些属性并附加必要的事件侦听器。
    
*   **请求：** 当声明事件发生时，`htmx` 客户端收集相关值，并使用 `hx-get`、`hx-post` 或其他 `hx-*` 操作向服务器发送 HTTP 请求。
    
*   **响应：** 服务器处理请求并返回一个 HTML 片段。 `htmx` 然后选择 `hx-target` 声明的元素，然后使用 `hx-swap` 应用片段，替换、插入、删除或变形 DOM 的该区域。
    
*   **扩展：** 可选的客户端插件连接到请求响应生命周期中，以添加流、WebSocket、预加载和自定义交换等功能——保持专门的 JavaScript 可重用和超出您的应用程序逻辑。
    

**底线：** 如果开发人员在 100 年后使用 `htmx` ，我会收回我曾经说过的关于 HTML 的所有坏话。

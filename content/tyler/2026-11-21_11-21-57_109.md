全新改进配方！

**Vite Team** 刚刚发布了前端构建工具的 v2.0，旨在“精简且快速”。 Vite 是 Vue.js 的创建者 Evan You 的另一个创意，但它旨在解决所有 JavaScript 开发人员面临的问题，无论框架如何。

**问题：** 大型 JavaScript 项目（包含大量模块）最终开始遇到性能瓶颈，这导致开发服务器的启动时间过长和文件更新速度较慢。 虽然非常适合查看 Twitter，但这些缓慢的反馈循环可能会导致最坚忍的开发人员像中学的孩子一样倾斜，就像一个缓慢的 Roblox 连接。

**解决问题：** Vite 通过 1) 利用浏览器的本机 ES 模块支持来提高性能，以及 2) 使用 [esbuild](https://esbuild.github.io/faq/#benchmark-details) 和 [Rollup](https://rollupjs.org/guide/en/) 等新的、更快的工具进行构建和捆绑。 查看 `create-react-app` 与 Vite React 的 [this demo](https://twitter.com/amasad/status/1355379680275128321) 以了解速度差异（n=1 实验 ftw 🙃）。

** V2 有什么新功能：**

*   **Framework Agnostic** — Vite 最初是作为 Vue.js 工具开始的，但 Vite 2.0 可以与任何框架一起使用，这要归功于其内部架构的完整重建。 与_all_框架共享他强大的新工具，而不仅仅是Vue？ Evan 是否刚刚成为 JavaScript 生态系统的 [Avatar](https://www.youtube.com/watch?v=d1EnW4kn1kg)？
    
*   **新插件格式** — 一个新的插件系统扩展了 Rollup 的插件界面，并带有一堆与 Vite 2 兼容的 [Rollup plugins](https://vite-rollup-plugins.patak.dev/)。
    
*   **其他新东西** — Vite 的编程 API 的许多改进、对 CSS 和服务器端渲染的新添加支持以及选择加入的旧版浏览器支持。
    

想知道 Vite 与 Snowpack 和 _\[insert-other-random-bleeding-edge-build-tool\]_ 有何不同？ 有[a post](https://vitejs.dev/guide/comparisons.html)。

Blitz.js 推出测试版
---------------------------

![Framework inception](https://bytes.dev/images/content/inception.png)

框架起始😵

**它是一个框架……**对于构建在每个人最喜欢的 JavaScript 框架（显然是 React）之上的框架（Next.js）。

我们谈论的是 **[Blitz.js](https://blitzjs.com/)** — 一个开源框架（上次我们要使用这个词），它可以让你利用 Next.js 的力量并做出反应来构建 _fullstack_ 应用程序。

**它是如何工作的：**

*   **Monolithic（以一种好的方式）** — 这是一个_有点_自命不凡的术语，它（通常）意味着从数据库到前端的所有内容都包含在一个应用程序中，因此您只有一件事可以开发和部署。 MonoLiths 历来在扩展方面苦苦挣扎，但 Serverless DB （默认情况下使用 [Prisma 2](https://www.prisma.io/)）和 Next.js 等工具应该允许 Blitz 应用程序更好地扩展。
    
*   **“零 API”数据层** — Blitz 杀死了 API 😱。 好的，从技术上讲，它只是_abstracted_它进入编译步骤，以便您可以将服务器代码直接导入组件中。 您仍然可以获得客户端渲染，而无需手动添加用于客户端获取和缓存的 API 端点的肮脏工作。
    
*   **(松散地) 固执己见的 AF** — Blitz 带有由其不断增长的社区为路由、文件结构、身份验证等方面设置的默认值和约定。 其他工具，如 eslint、prettier 和 jest 也为您设置，但您可以轻松更改/覆盖预设。
    

Blitz 提供了一种令人兴奋的新方法来简单快速地启动 Fullstack React 应用程序，但它确实带有一些 [tradeoffs](https://blitzjs.com/docs/tradeoffs)（因为它确实如此）。 最大的集中在 Monoliths 自然而然地缺乏定制和可扩展性。

### 底线

Blitz.js Creator [Brandon Bayer](https://twitter.com/flybayer)（Great Buy，BTW）将他的 fr\*MeWork 称为“Ruby on Rails for React 和 JavaScript”，并希望帮助恢复 2000 年代中期流行的 ROR 的整体结构。 他在 [The Blitz.js Manifesto](https://blitzjs.com/docs/manifesto) 中阐述了这个想法，我们假设这是一个激动人心的呼吁，要求受压迫的工人阶级巨石崛起并推翻资产阶级的网络开发。

如果我们正在复活 2000 年中期的趋势，你们中的一个人能否努力将 [shutter shades](https://amzn.to/3k8Pwgk) 带回来？

如果您像我一样，您可以使用这些策略之一将值记录到控制台。

常量名称 = '泰勒'
    
console.log('name', name) // 名字 Tyler

console.log('sefkjse', name) // sefkjse 泰勒

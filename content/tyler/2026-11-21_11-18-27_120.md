开发人员仍在使用 lerna

安息吧，勒纳
--------------------

上周，Lerna 正式放弃了幽灵，并宣布失去一个朋友总是很痛苦，但至少 Lerna 死于做它喜欢的事情——让我们等待它建立。

让我们仔细看看 Monorepos _\*实际上\*_ 做了什么，发生在 Lerna 身上的事情，以及我们在后 Lerna 世界中从哪里走的地方。

**WTF 是一个单仓库？ 这允许在软件包之间轻松共享代码——在与大型团队一起处理大型项目时，这可以节省大量时间、开销和复杂性。

这就是为什么他们在 Big Enterprises 开始的原因（Google 的整个代码库仍然位于一个 Monorepo _mega_repo 中）。 Lerna 为开发人员提供了一种在 JavaScript 和 React 项目中使用它们的简单方法，将 Monorepos 带给了大众。

**为什么 lerna 死了？** 简单的答案——真的很慢。 Monorepos 的一个问题是，每当您进行代码更改时，您都必须重建取决于您更改的模块的所有内容。 对于庞大的代码库，这是一个巨大的 PITA。

更复杂的答案——该项目缺乏一致的领导和维护者。 其他 Monorepo 工具（如 NX 和 Turborepo）通过 [remote caching](https://turborepo.org/docs/core-concepts/remote-caching) 等创造性解决方案解决了缓慢的构建问题。 但如果没有一致的贡献者，Lerna 无法效仿（这不是任何人的错，OSS 很难）。

**底线：** 让我们为我们倒下的朋友喝上美好的时光和 [pour one out](https://www.youtube.com/watch?v=QACY04l5OHo) ——以及仍然以 lerna 作为依赖的 40,000 个 GitHub 存储库。 保持坚强。

Zag.js 可以将我们从设计系统中拯救出来
----------------------------------------

上周，设计系统之王 Sengun Adebayo 再次与 [Zag.js](https://zagjs.com/) 一起回归它——这是一个用于构建复杂交互的框架。

**我们是如何到达这里的？** Sengun 创建了 [Chakra](https://chakra-ui.com/)，这是最流行的 React 组件库之一。 它变得足够流行，开发人员开始要求他们支持其他框架，因为如果你给鼠标一个 cookie，他总是会要求 Vue。

但事实证明，跨框架支持 UI 交互并不容易。 这就是 ZAG 的用武之地。它允许您共享组件的“行为”，同时将其余的 UI（样式和标记）留给您选择的框架。

为了实现这种魔力，Zag 在引擎盖下做了一些非常酷的事情：

*   **State Machines** — 帮助书呆子让您感觉良好，您的 UI 组件将考虑所有数学上可能的状态
    
*   **Accessibility** — 处理与键盘交互、焦点管理、ARIA 角色和属性相关的棘手细节
    
*   **Headless** — 提供行为并将样式留给您（让开发人员处理 css 似乎有风险，但 yolo）
    
*   **Modular** — 如果您还没有准备好整袋 Zags™️，您可以一次采用它们
    

**底线：**如果你幸运/不幸地从事设计系统工作，Zag 似乎是天赐之物。 对于我们其他人来说，我们想知道在面临另一个跨框架拒绝之后，Web 组件是否会 [find love](https://www.youtube.com/watch?v=J9DzAjOe7sY)。

Remix vs Next.js — 对决
------------------------------

**让我们准备隆隆声……** Remix 上周用 [6,700 word essay](https://remix.run/blog/remix-vs-next) 说明了为什么它们比 Next.js 更好。 它写得很好，但很长，所以我们为你做了这个 [13-second video summary](https://video.twimg.com/ext_tw_video/1424050741778403333/pu/vid/360x360/2AdfLnYANcS80PQk.mp4?tag=12)。

**我们是如何到达这里的：** Remix 是一个 React 元框架，仅限 SSR，由 React Router 背后的人创建。 它是“边缘优先的”，能够在任何地方部署，并且自 11 月推出 V1 以来已经获得了 [lots of hype](https://twitter.com/jaffathecake/status/1483706092215586816?s=20)。

**但是这与 Next.js 有何不同？** 事实证明，Remix 团队已经厌倦了每个人都在问这个问题，所以这篇文章使用了许多细致入微的测量方法来直接比较 Next.js 应用程序和 Remix 应用程序。 从那里，他们分享了以下科学结论：

*   混音更快
*   Next.js 较慢
*   remix的爸爸可以打你爸爸

**[HOW?](https://www.youtube.com/watch?v=W-TGdhurBdU)** remix 应用程序服务器渲染的每一页，而不是使用 SSG。 他们可以比 next.js 更快地做到这一点，因为他们使用 Redis 数据库“在边缘”缓存数据，并且还在“边缘”运行他们的服务器。 （不是每个人都同意什么“边缘”[actually means](https://twitter.com/crim_codes/status/1484594510483054592?s=20)，而是想象服务器接近用户。）

**但是如果您必须运行分布式服务器_and_一个分布式数据库_and_一个redis缓存，那么“一流的性能”真的值得吗？ 那个混音示例甚至包括一个 [Docker Compose file](https://github.com/jacob-ebey/remix-ecommerce/blob/main/docker-compose.yml) - 现在我的时间线上有 Egghead Push [Docker courses for Remix devs](https://twitter.com/eggheadio/status/1484548808742563841?s=20)。 至少我们都获得了分布式系统硕士学位，对吧？ 💀

**remix _is_ on to something，但** — 托管更接近用户的网站确实提供了更好的体验，Vercel 也知道这一点。 很快，Vercel 将通过提供 [edge-rendered sites](https://twitter.com/leeerob/status/1484340768290471936) 来跟随 Remix Over the Edge，这要归功于它们的新 Edge 功能功能（又名 Cloudflare 工作人员 [trench coat](https://www.youtube.com/watch?v=D1RgdMLbx3M) 中的两个）。 边缘渲染的所有速度和灵活性_没有_所有额外的基础设施现在听起来都不错。

**底线：** 当框架竞争时，[developers win](https://twitter.com/leeerob/status/1465702417513680897)。 当框架涌现出大量的 VC 现金时，它们往往会更加努力地竞争。 就个人而言，我还在等待 [this livestream](https://twitter.com/mjackson/status/1459656714362310658?s=20) 发生。

具有索引访问类型的更好的类型推断

打字稿 4.6
---------------

Typescript 刚刚宣布了它的 v4.6 测试版——但与我们上一个故事不同，他们甚至没有写一篇博客文章，点名他们的竞争对手之一（无聊）。 希望他们能尽快启动 Hot Take 机器，并写下我们一直在等待的灼热的“TypeScript vs. Flow”博客文章（自 2014 年以来）。

与此同时，TypeScript 4.6 中有 _a lot_ of [new features and improvements](https://devblogs.microsoft.com/typescript/announcing-typescript-4-6-beta/)。 你会注意到他们中的大多数吗？ 可能不是，但这里有亮点：

*   TypeScript 现在警告您更多错误，例如重复的 `const` 语句或在函数中使用静态 `import`。
    
*   如果您正在编写扩展类，您现在可以编写代码 _before_ calling `super()`。 以前，您无法在 `super()` 之前包含任何代码，因为您需要在访问 `this` 之前调用 `super()`。 我们警告你这会很干，但你在这里，还在读——对你好。
    
*   TypeScript 在进行递归类型检查时具有更好的性能，例如似乎无限嵌套在自身内部的类型。
    
*   在使用索引访问类型和依赖参数时，有更好的类型推断和类型检查。 我们也不知道这意味着什么，但我相信这很棒。
    

**底线：** 这是 TypeScript 的另一个可靠版本——但 Zuck 刚刚告诉我，Flow 几年前已经具有完全相同的功能。 我想是时候让他和萨蒂亚从 _remix vs. next.js_ playbook 中取出一页了，一劳永逸地解决这个问题……通过写长篇博客文章和互相转发，同时假装他们在同一个团队中。

很酷的位
----------

1.  有一个新的 [Chrome DevTools feature](https://developer.chrome.com/docs/devtools/recorder/) 可让您记录、重播和测量用户流量。 我不知道这个功能是否会取代产品经理的 50% 的工作，或者导致更多的产品经理被聘用。 大概两者兼得。
    
2.  Kyle Simpson（又名 Getify 又名 LinkedIn 先生）写了 [Expansive Intro to Monads](https://github.com/getify/monio/blob/master/MONADS.md#fp--monads)。 读完之后，你可能还有一些问题，比如_什么是monads？_和_是一个真实的词吗？ 它让人们前进。
    
3.  [TinyBase](https://tinybase.org/) 是一种新的“更智能的方式”，以更像数据库的方法来构建您的应用程序状态。 如果这件事流行起来，他们甚至可能会得到自己的“Remix vs Tinybase”热门作品。
    
4.  [Deno 1.18](https://deno.com/blog/v1.18) 刚刚发布，它带有一个花哨的新 Web 加密 API。 如果您对 _Web 加密 API_ 是什么感到困惑，请重新阅读 Cool Bit #2 的最后一句话以获得解释。
    
5.  Orta Theroux（来自 TypeScript 团队）创建了 4 个看起来很有用的 [TypeScript cheat sheets](https://www.typescriptlang.org/cheatsheets)。 但是，如果教授在期中发现你使用它们，你没有从我这里得到它们，好吗？ 我需要这门课毕业。
    
6.  [Simple.css](https://github.com/kevquirk/simple.css) 是一个无类 CSS 模板，可让您快速制作好看的网站。 现在，您需要做的就是添加一些渐变，升级到 Web 加密 API 的 Deno 1.18，使用 TypeScript 4.6 进行递归类型检查，加入一些单子（正确的声音），然后迁移到 Remix - 其必备的分布式服务器、分布式数据库、Redis 缓存和 Docker Compose 文件。 然后，您最终将为您的个人博客提供一个_simple_现代网站。 有那么难吗？
    
7.  [Dioxus](https://dioxuslabs.com/blog/introducing-dioxus/) 是一个新的 Rust 框架，用于构建受 React 启发的 UI。 因为生命中只有三种保证：死亡、税收和生锈。 沙拉手指试图警告我们。

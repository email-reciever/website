### 杰克变得灵活，杰克是Qwik

经过数月的炒作，Qwik 1.0 于周一推出🚀。 他们的公告帖子有一个直接从JavaScript Fortune Cookie中发出的关键线：

_“Qwik的理念是确保简单的路径是高性能的路径。”_ 🧘‍♂️

这很酷，现在我渴望熊猫快递，但我们已经从许多 JS 框架中听到了这种“两全其美”的宣传。 那么是什么让 Qwik 与众不同呢？

一言以蔽之：**可再生性。**

这就是 Qwik 独特的渲染方法的名称，它不需要传统保湿带来的任何纯粹的开销。 以下是有关其工作方式的快速TLDR：

*   完全交互式站点能够加载少量的 JavaScript，然后从服务器停止的位置获取。 当用户与您的网站交互时，IT 的相关部分按需加载。
    
*   这种“精确延迟加载”是可能的，因为 Qwik 应用程序完全序列化为 HTML。 因此，使用 SSR，整个应用程序可以将整个应用程序作为 HTML 发送到浏览器，在那里它将在停止的地方继续加载 - 无需执行任何 JavaScript。
    
*   这意味着您无需担心要添加多少 JavaScript 或您的网站延迟加载。 你可以随心所欲地构建任何你想要的东西，Qwik 确保你总是获得完美的灯塔分数——因为它只下载了每次交互所需的最少量的 JavaScript。
    

说到 DX，Qwik 的方法最独特的地方可能是它实际上并不是独一无二的。 它不会尝试将 React 视为“反模式”——相反，Qwik 及其 Qwik City 元框架包含来自 React 和 Next.js 等许多核心概念，例如 JSX、基于目录的路由、中间件等。

现在他们已经发布了 [Qwik React](https://qwik.builder.io/docs/integrations/react/) — 它允许您在 Qwik 本身中使用 React（以及每个 React 组件和库）。 这为 React 开发人员提供了一种增量方式来试用 Qwik，而无需从头开始重写他们的应用程序。

**底线：** 尽可能多的 JavaScript，我的网站仍然会很快燃烧？ 下一步是什么，零卡路里的橙子鸡？ 🙏

您是否知道您可以在没有 JavaScript 的情况下进行前端表单验证？

1.  `required` 确保在提交表单之前必须填写表单输入字段。

    <input type="text" name="username" required>
    

2.  `minlength` 和 `maxlength` 设置输入字段的最小和最大允许字符数。

    <input type="text" name="username" minlength="4" maxlength="20">
    

3.  `pattern` 允许您定义输入值必须匹配的正则表达式。

    <input type="text" name="username" pattern="[a-zA-Z0-9]{4,20}">
    

4.  `type` 可用于指定输入字段的预期数据类型，这有助于基本验证。 例如，您可以使用 `type="email"` 进行电子邮件验证，`type="url"` 用于 URL 验证，`type="number"` 用于数字验证。

    <input type="email" name="user_email">
    <input type="url" name="website">
    <input type="number" name="age">
    

话虽如此，您可能也想要后端验证。

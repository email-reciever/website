### ️Rust™®️戏剧

如今有这么多的在线部门，当整个科技社区能够聚集在一起并围绕一个共同的事业团结起来时，这真是太好了。

我们看到上周发生了 Rust 的确切事情。 除了在这种情况下，每个人都齐心协力，告诉 Rust 他们有多讨厌它——或者至少他们有多讨厌 Rust️ 基金会的新 [trademark policy](https://docs.google.com/forms/d/e/1FAIpQLSdaM4pdWFsLJ8GHIUFIhepuq0lfTg_b0mJ-hvwPdHa4UTRaAg/viewform)，这读起来就像是甲骨文、迪斯尼和金凯瑞的律师起草的 _骗子骗子._

以下是新政策的一些亮点：

*    禁止使用“Rust”或 Rust 标志来销售任何产品（贴纸、衬衫、帽子、书籍、课程、咨询服务等），并且不得在任何域名中使用“Rust”一词。
    
*   除了改变尺寸之外，不以任何方式调整锈迹或颜色。
    
*   Rust “用户组”（我猜，如 Discords 和 Subreddits，我猜？）只有在正式采用和执行“Robust Codes of Code”并将大部分讨论集中在 Rust 主题上时，才允许使用 Rust 一词。
    
*   如果您在一开始就包含了关于“此材料未被 Rust 基金会审查或认可”的样板说明，您只能在博客文章或视频的标题中使用“Rust”一词。
    
*   如果非营利，禁止携带枪支，遵守当地卫生法规，并首先让每个人都站起来唱Rust Foundation的《Allegiance Anthem》，才能在会议或活动中使用Rust徽标和“Rust”一词。 （好吧好吧，我编了最后一部分）
    
*    禁止在任何第三方软件工具、库、插件或软件包的名称中使用“Rust”一词——除非您联系 Rust Foundation 并获得（又名_Purchase_）许可。
    
*   在最后，他们鼓励每个人_请_向Rust Inquisitorial Squad基金会报告他们看到的任何潜在违规行为。 因为没有什么能帮助培养一个充满活力的 OSS 社区，因为他们会因为潜在的商标纠纷而互相争吵🥴。

#### 赞助[Datadog](https://www.datadoghq.com/bytes/)

_他们在一个统一的平台上为您提供了检测、诊断和解决问题所需的所有工具。 试试他们的 [14-day free trial](https://www.datadoghq.com/bytes/)._

你用过数组的 `fill` 方法吗？ 可能不是。 定义，`fill`“用静态值填充数组的所有元素，从开始索引到结束索引”。 这听起来很没用，但我发现了一种很有帮助的场景。

当您开始使代码更具功能性时，您自然会开始避免使用常规 for 循环来支持 `.map`、`.reduce` 等。假设我们的用例是我们想执行一个任意次数的函数，例如 `10`。 我们如何做到这一点并避免使用 for 循环？ 您的第一个直觉可能是使用 `.map` 的数组构造函数。

数组(10).map(() => {
      
})
    

您会注意到如果您运行该代码，它将不起作用。 当您执行 `Array(10)` 时，您将创建一个包含 10 个未设置或“空”值的数组。 不幸的是，当您使用任何数组方法时，它们将无法在具有空值的数组上工作。

这就是 `.fill` 发挥作用的地方。 如果你这样做`Array(10).fill()`，你会得到一个10`undefined`而不是空元素的数组。

数组(10).fill().map(() => {
      
})
    

不是 _super_ 有用，但如果您需要它，很高兴知道它的存在。

很酷的位
----------

1.  [OXC](https://github.com/Boshen/oxc) 是一个 JavaScript 氧化编译器，它在 R\*ST 中创建一套工具——比如 AST、解析器、linter 和 transpiler。
    
2.  [Airplane.dev](https://www.airplane.dev/?utm_source=bytesapr2023_coolbits) 是构建自定义内部工具的开发平台，比您说“字节是我这一代的定义性文学作品”。 他们的代码优先方法使构建客户入职流程、管理操作 UI、客户支持应用程序等变得容易。 \[赞助\]
    
3.  山姆·罗斯写了这篇[Animated guide to HTTP load balancing algorithms](https://samwho.dev/load-balancing/)。 动画不像超级马里奥兄弟电影那么复杂，但它可能更具教育意义。
    
4.  Nike 为在设计现代前端应用程序时寻求避免最常见陷阱的工匠写了 [a practical guide](https://nikoheikkila.fi/blog/clean-frontend-architecture-with-sveltekit/)。 作为一个工匠🎩我自己，我发现它很有帮助。
    
5.  LangchainJS 刚刚为其语言模型框架宣布了 [Support for Multiple New Environments](https://blog.langchain.dev/js-envs/)（Vercel、Workers、Supabase Edge 函数等）。
    
6.  伊莉丝·海因写了关于 [Fighting inter-component HTML bloat](https://elisehe.in/2023/03/27/minimal-html-in-design-systems) 的文章。 现在，我在砸了两品脱珍妮的冰淇淋后，正在与自己的腹胀问题作斗争。
    
7.  [Nuxt 3.4](https://nuxt.com/blog/v3-4) 上周推出，支持 View Transitions API 和 Object-Syntax Nuxt 插件等新功能。
    
8.  [Sveltris](https://github.com/mokshit06/sveltris) 是一种黑魔法，可以让你用 Svelte 拼凑出 React 原语，比如钩子和组件。 目前还没有关于 Rust 基金会的律师是否会代表俄罗斯方块制造商起诉的消息。

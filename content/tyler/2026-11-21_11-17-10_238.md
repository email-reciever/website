迟到总比不到好
-----------------------

Astro v1.0 是 [released this week](https://astro.build/blog/astro-1/)，这意味着它的正式准备生产（就像曾经阻止过你们野蛮人一样）。

该版本原本应该 [come out on June 8](https://astro.build/blog/astro-1-beta-release/#:~:text=In%20addition%2C%20we%20are%20thrilled%20to%20announce%20that%20the%20official%20Astro%20v1.0.0%20release%20will%20be%20available%20on%20June%208%2C%202022.)，但由于我们使用的是 React 团队的时间线，因此在技术上仍提前 3.5 年。 最大的问题是……值得等待吗？

事实证明，很多进入主要版本。 Astro 团队削减了 73 个测试版和 8 个候选版本，导致 V1（基本上是 `astro_final_final_v3.psd` 的开发人员版本供您设计人员使用）。

花时间完善您的 API、修复错误、更新文档并在主要版本之前让您的房子井井有条，有话要说。 但此版本还带来了许多重大升级：

1.  图像优化 — V1 添加了两个新组件，`<Picture` 和 `<Image />`，它们建立在 [sharp](https://sharp.pixelplumbing.com/) 上并进行内置图像优化。
    
2.  MDX 迁移——在第 11 小时，团队将他们自制的 Markdown 解决方案换成了更成熟、更快的 `MDX`。 [Bryce felt good about it](https://www.brycewray.com/posts/2022/07/astro-move-to-mdx/)。
    
3.  Vite 3.0 — Astro 现在正在运行最新最好的 Vite 所提供的功能，改进了捆绑大小、SSR 支持和更快的本地开发服务器等功能。
    
4.  SSR 构建 — 不再是实验性的，ASTRO 为您喜爱的所有 FAAS 提供商提供适配器支持 SSR，以便您可以融入 MPA Island Boy 的生活方式。
    

**底线：**当 CEO 可以 [admit when they are wrong](https://twitter.com/FredKSchott/status/1554187175146663936?s=20&t=KN5hn_XO6Msl_L_nAokAZw) (👋 Fred) 时，这是一个很好的品质，但是在您拖延发布 _CEOING_ 时为您创建一个机器人来编码是下一个级别。 我看到你[fredkbot](https://github.com/fredkbot)。

盖茨比是后退吗？
--------------------

有时，当其他 React 框架忙于在 Twitter 上启动 [flame wars](https://twitter.com/swyx/status/1557730698407989248?s=20&t=4kkdL7M6Z18Nl9XzeNqVrw) 时，很容易忘记 Gatsby，使新的 React 18 功能 [actually usable](https://twitter.com/acdlite/status/1549853625673023488)，并且……做任何 RedwoodJS 所做的事情。

但 React 的 OG SSG 框架一直在进行一些重大变化，首席执行官 Kyle Matthews (👋 Kyle) 上周在 [re-introduced Gatsby](https://www.gatsbyjs.com/blog/re-introducing-gatsby-a-reactive-site-generator) 作为“反应式站点生成器”(RSG) 时公布了这一点。 RSG 与 SSR/SSG/ISR/SPA/MPA/AT&T/BBQ/HAGS 相比如何？

**臭名昭著的 RSG:** 带有“反应式构建”，每页通过 GraphQL 声明其数据依赖关系，然后 Gatsby 确保所有无效的页面在数据更改时都会更新。 但现在，他们已将该架构移植到 Gatsby Cloud（他们的自定义 CDN）中，后者将站点构建为可以立即对数据更改做出反应的 RSG 服务。

Kyle 将其称为“热重新加载，但对于您的生产网站”，它带来了一些稳固的性能收益（根据他们的基准测试）：

*   Gatsby Cloud 现在可以在一秒钟内发布更改 - 比在 Netlify 或 Vercel 等标准 CI/CD 服务上构建的完全相同的 Gatsby 站点快 100 倍。 [(See demo)](https://twitter.com/GatsbyJS/status/1558194772237582336)。
    
*   Gatsby Cloud 上所有 Gatsby V4 站点的内容更新的中值发布时间为 5 秒。
    
*   RSG（这会成为现在的事情吗？）比 SSG 快得多，同时击败或匹配 SSR 缓存技术以进行实时数据更新。
    

**底线：**我们在这里是为了 Gatsby 2022 Glow Up - 就像我们会在这里，当有人决定使用 [this glow up](https://bytes.dev/images/content/skeet.jpg) 的旧经典时，我们会在这里。

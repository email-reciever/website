Brave Browser 希望通过新协议去中心化 Web
-----------------------------------------------------------

![Mel Gibson](https://bytes.dev/images/content/mel.png)

勇敢的心自由

**“他们可能会夺走我们的生命……**但他们永远不会夺走我们的自由开放的互联网。” 至少，如果 Brave 的首席执行官 Brendan Eich 对此有任何话要说（是的，_that_ Brendan Eich），那就不会了。 这是因为上周，[Brave became the first browser to offer native integration with IPFS](https://brave.com/ipfs-support/) — 一种对等的超媒体协议，它说它想要_“超越 HTTP 以为我们所有人构建更好的 Web。”_

欢迎来到革命，[comrades.](https://www.youtube.com/watch?v=4DcGBE-F9hk)

** IPFS 的工作原理：** 不是像现在使用 HTTP 那样访问中央服务器上的信息的浏览器，而是在“分布式节点”网络上访问它——也就是可以接收 _and host_ 内容的用户。 有点像 BitTorrent，但对于整个网络。

**IPFS 福利：**

*   **Faster & cheaper —** Since there’s no specified location for content, IPFS can download pieces of files from multiple computers simultaneously, which saves big on download time, bandwidth, and server costs for the original publishers.
    
*   **不那么集中——** 消除对集中式服务器的需求，使得政府或科技巨头更难审查网络内容。 您已经可以使用 Brave & IPFS 查看数以千计的网站，这些网站被世界各地的政府禁止。
    

### 底线

您可能还不需要将您的 AWS 认证扔进垃圾桶，因为这仍然是 _early_ 日子。 但 Brave 和 IPF 都将在这种伙伴关系中获得很多收益：

*   IPFS获得了Brave的2400万用户的Primo访问权限（更多用户=更强大的网络）
*   无疑希望 IPFS 能够帮助吸引更多以隐私为中心的用户进入其浏览器，从而获得一些甜蜜的曲棍球增长果汁 [DuckDuckGo’s been sipping on](https://www.bleepingcomputer.com/news/technology/privacy-focused-search-engine-duckduckgo-is-growing-fast/)

IPFS 背后的公司也支持 Filecoin，这是一种市值 **1B 美元的加密货币（+/- 5 亿美元，具体取决于您阅读的日期）。 所以我猜他们做得很好。

JavaScript + Rust = 蟒蛇？
-------------------------

![Going to flavor town](https://bytes.dev/images/content/flavor.png)

进去，我们要去低级JS Flavortown

**当 TC39 代表对新的编程语言有一个徘徊的眼光时会发生什么？** 事实证明，他们实际上没有被带到委员会面前，被迫交出他们的徽章和枪支，并永远从 JavaScript-land 中被暴力地流放出来， tbh)。

在 [Jason Williams’](https://twitter.com/jason_williams) 的案例中，他只是想出了一种方法，通过使用 Rust 构建 [a JavaScript engine named Boa](https://docs.rs/Boa/0.11.0/boa/index.html) 来结合他的初恋和第二次爱情。 当他开始爱上 Rust 时，他（与近年来的其他人一样）看到了将 Rust 引入 JavaScript 生态系统的好处，反之亦然。

上周，当 [it released v0.11](https://boa-dev.github.io/2021/01/14/boa-release-11.html) 时，Boa 朝着这个目标迈出了一大步——这是迄今为止最大的发布。

**BOA 将自己描述为“实验性 JavaScript 词法分析器、解析器和编译器”（也就是 JavaScript 引擎所做的所有事情）。 它仍然不完全符合 JavaScript 规范（好词，对吗？），但这个 v0.11 版本的规格一致性从上周的 18% 到 31% 达到了 31%。 3个月内有了稳健的跳跃。 BOA 切换到使用 `regress` 引擎进行正则表达式后的执行速度也快了近 6 倍。

如果 BOA 想要更多的主流采用，更快的执行和更大的一致性是游戏的名称，所以这些都是积极的信号。

### 谁会使用这个？

*   希望在Rust代码中包含可嵌入的JavaScript实现的Rust开发人员
*   对Rust和Wasm的炒作感到好奇的JavaScript开发人员想要一个借口将其带入浏览器
*   你讨厌的同事，总是想使用前沿技术

但是现在您已经阅读了这篇文章，您可以开始在 [the Boa Playground](https://boa-dev.github.io/boa/) 上玩几分钟，_you_ 可能会成为那个令人讨厌的同事。 不客气。

发现错误 - 答案
----------------------

我们对 `leo.eat` 的呼叫将失败。 这样做的原因是因为从 `Animal` 返回的对象没有委托给 `Animal.prototype` ，因此 `leo.eat` 将是未定义的。

为了解决这个问题，我们可以使用 `Object.create` 或 `this` 关键字与 `new` 的组合。

功能动物（名称，能量）{
让 animal = object.create(animal.prototype)
animal.name = 名称
动物.能量 = 能量
    
返回动物
}
    
// 或
    
功能动物（名称，能量）{
this.name = 名称
this.energy = 能量
}
    
const leo = 新动物('狮子座', 7)
    

有关更多详细信息，请查看 [A Beginner’s Guide to JavaScript’s Prototype](https://ui.dev/beginners-guide-to-javascript-prototype)。

### React Native 正在听

React Native 团队听取了您对去年社区调查的反馈意见，并在昨天的 [React Native 0.72 release](https://reactnative.dev/blog/2023/06/21/0.72-metro-package-exports-symlinks) 中优先考虑。 万岁，高效，非间谍聆听！

很多反馈集中在对 Metro 的改进——React Native 的 JavaScript 捆绑器。 值得庆幸的是，v0.72 引入了三个高度要求的 Metro 功能：

*   **SymLink Support** 允许 React Native 与 Monorepo 设置和 PNPM 一起透明地工作，而无需使用 Janky 解决方法。 我的大脑最初将其读作“系统链接支持”，我对我们即将举办 LAN 派对感到非常兴奋——但这更有意义。
    
*   **`package.json` 导出支持** 允许 React Native 项目使用更多的 npm 包，它为包提供了定义其 API 和目标 RN 的新功能。 Alex Hunt 写了一篇 [great article](https://reactnative.dev/blog/2023/06/21/package-exports-support)，介绍了包导出的工作方式，以及它们将如何改进 React Native 项目与更广泛的 JS 生态系统一起工作的方式。
    
*   **新的 `metro.config.js` setup** 在 React Native CLI 中意味着像 `metro get-dependencies` 这样的独立 Metro CLI 命令现在可以工作了。
    

SymLink 和 Package Exports 仍处于测试阶段，但这些改进有助于引入新的架构更新，这些更新应该可以使 Metro（和 React Native）[even faster and more reliable](https://twitter.com/motiz88/status/1671581214002540544) 向前发展。

**底线：** 很高兴知道 React Native 团队正在为您听到。

发现错误：解决方案
-----------------------

#### 赞助[Brilliant](https://brilliant.org/uidev/)

从“反应”导入 { useState }；
    
导出默认函数 counter() {
const [number, setNumber] = useState(0);
    
返回（
<>
<h1>{编号}</h1>
<button onClick={() => {
setNumber(数字+1);
setNumber(数字+1);
setNumber(数字+1);
}}>增量</button>
        </>
)
}
    

这一款直接来自新的（测试版）[React Docs](https://beta.reactjs.org/learn/queueing-a-series-of-state-updates)。 您可能会期望单击按钮会将我们的 `number` 状态增加 3，但这不是它的工作方式。 简而言之，JavaScript 围绕 `number` 变量创建了一个闭包，就好像我们在做

setNumber(0 + 1);
setNumber(0 + 1);
setNumber(0 + 1);
    

当然，这将始终将 `number` 设置为 1。

相反，如果我们想在下一次渲染之前多次更新相同的状态，我们可以像这样将函数传递给我们的 setter 函数 -

setNumber(n => n + 1);
setNumber(n => n + 1);
setNumber(n => n + 1);
    

现在 React 会将所有这些函数添加到队列中，在下一次渲染期间，React 会通过队列中的前一个项目的结果传递到下一个项目，最终导致 3 的 `number`。

0 + 1 = 1
1 + 1 = 2
2 + 1 = 3

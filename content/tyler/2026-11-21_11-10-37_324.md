### 视图过渡可以欺骗您使用更少的 JavaScript 吗？

Astro 正在投注是的，这就是为什么他们刚刚为 [View Transitions browser API](https://astro.build/blog/astro-290/) 引入了实验支持。 他们并不孤单。 Nuxt 提供了实验支持 [earlier this year](https://nuxt.com/blog/v3-4)，Sveltekit 也是 [working on it](https://github.com/geoffrich/sveltekit-view-transitions)。

那么这个 API 实际上做了什么，它如何改变我们为 Web 构建的方式呢？ 让我们潜入。

**它的作用：** 视图转换让您在一个步骤中更新 DOM，同时在两个状态之间生成 CSS 控制的动画过渡。

这意味着您可以在 HTML 页面之间创建柔滑的动画 _without_ 不需要使用客户端路由 ([see demo](https://live-transitions.pages.dev/))。 并且您可以执行元素转换以在页面__without_中重新排序多个元素，而不需要使用JavaScript（[see demo](https://www.youtube.com/shorts/Qwgc_pJ2OOw)）。

**它是如何工作的（Astro 示例）：**

*   对于页面转换，您只需将 `<ViewTransitions />` 组件添加到您的通用 `<head>` 或共享布局组件，然后 Astro 在旧页面和新页面之间创建默认动画（对于当前不支持的非 Chromium 浏览器，使用回退行为）。
    
*   您可以使用 `transition:animate` 与 Astro 的内置动画或您想要的任何 CSS 动画属性创建各种元素转换。
    
*   在场景的背后，浏览器使用View Transition API拍摄您正在转换的DOM元素的前后状态的图像。 然后它完全_animorphs_，通过用新图像热交换旧图像并使用交叉淡入淡出对更改进行动画处理。 查看 MDN 的 [breakdown](https://developer.mozilla.org/en-US/docs/Web/API/View_Transitions_API#the_view_transition_process) 了解所有肮脏的细节。
    

**这意味着：** MPA 变得更好了。 对于视图转换，用户每次导航时都不会看到整页刷新。 相反，它们将获得与 SPA 和移动应用程序相同的平滑过渡和动画——无需大量额外的 JavaScript。

与某些浏览器 API 不同，视图转换看起来非常简单且直观。 因此，一旦所有供应商都支持 API，我们就应该开始看到它们。

**底线：** 随着 Web 平台继续变得更加强大，我们可能不需要像以前那样多的 JavaScript 来构建复杂的 Web 应用程序。

发现错误：解决方案
-----------------------

#### 赞助[Secureframe](https://secureframe.com/request-demo-4?utm_source=partner&utm_medium=newsletter&utm_campaign=072723-bytes-newsletter)

console.log(shouldAlert(5, 26)); // true（应该是假的）
console.log(shouldAlert(8, 26)); // true
console.log(shouldAlert(8, 32)); // true
    

在 JavaScript 中，`&&` 运算符的优先级高于 `||` 运算符。 这意味着在这两个运算符的语句中，部分带有 `&&`` will be evaluated first. To fix the issue, we need to add parentheses around the` ||\` 的语句部分。

功能 shouldAlert(DurationInWarehouse, 温度) {
const critical_temperature = 30; // °C
const secondary_temperature = 25; // °C
const critical_duration = 7; // 天
    
返回温度 > critical_temperature
|| (
DurationinWarehouse > Critical_Duration
&& 温度 > 次级温度
);
}
    

或者，您可以通过使用适当的 if/else 语句来避免三元组，并避免您的队友和未来的自我痛苦🙃。

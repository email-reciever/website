### Web组件的Davos

本月早些时候，W3C Web Components Community Group 召开会议，讨论 2024 年的 [new Web Components features](https://eisenbergeffect.medium.com/web-components-2024-winter-update-445f27e7613a) 和平台改进。

这次 W3CWCCG (?) 会议邀请了来自大型科技公司、开源库和浏览器供应商的代表——它几乎是 Web 标准世界的 Davos，只是拥有更少的私人飞机和稍微少的板球面粉。

我们不够优雅，无法获得邀请，但我们仍然设法了解了您附近的浏览器即将推出的三个最具影响力的平台开发项目的内幕消息：

**声明性影子 DOM** 将于 2 月 20 日在 Firefox V123 中发货，这将为其提供全面的跨浏览器支持🥳。 这个 API 允许您在 HTML 中直接使用 Shadow DOM，而无需编写任何 JavaScript — 允许您执行许多很酷的事情，例如服务器渲染 Web 组件，而无需使用 `attachShadow()` js 元素。

**作用域元素注册**最近在Chrome中进行了原型化，以允许单个标记名称在页面中存在多个自定义元素定义。 这使您可以选择不在 HTML 中全局定义所有自定义元素，这对于较大、更复杂的应用程序特别有用。 可悲的是，我们可能需要一段时间才能获得所有三种浏览器的全面支持。

**CSS 样式查询** 让您 [query a CSS property or variable](https://ishadeed.com/article/css-container-style-queries/#introducing-style-queries) 用于容器并基于此设置孩子的样式。 今天，我们对容器 _size_ 查询提供了完整的跨浏览器支持，但目前只有 Chrome 支持样式查询。 WebKit 和 Firefox 在会议上讨论了他们实施此功能的计划，因此我们希望在不久的将来看到跨浏览器对样式查询的支持。

**底线：** 将网络平台持续发光的兴奋与 React 社区中的 [frustration](https://x.com/tannerlinsley/status/1746970043836158330) 和糟糕的氛围进行对比是很有趣的。 我们能否看到更多的 React 开发人员转向以平台为重点的库，如 Lit 和 Astro 以推进更多项目？ 这绝对值得监控。

首先，记录 `Error in p1`，然后记录 `[ 'p2 resolved', undefined ]`。 由于 P1 捕获了拒绝，因此它不会传播到 `Promise.all` 捕获处理程序允许 `p2` 解析。 但是，由于 `p1` 没有返回任何内容，因此它的结果是 `undefined`。

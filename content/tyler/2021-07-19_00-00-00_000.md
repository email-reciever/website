阿波罗服务器 3.0 为人迈出了一小步
-------------------------------------------

**…上周发布了V3.0（这是自2018年以来的首次主要版本），GraphQL 服务器到处都是 GraphQL 服务器的一个巨大飞跃。

**快速审查：** Apollo Server 是一个开源的 GraphQL 服务器，采用模式优先的方法。 它可以用作独立的 GraphQL 服务器、联合数据图的网关或作为现有 Node.js 中间件的附加组件（如 Express 或 Fastify）。

**变得灵活：** Apollo Server 2 有一堆硬编码的依赖项，这使得构建新功能变得困难。 因此，像我们许多人在隔离期间一样，阿波罗服务器在亚马逊上买了一个便宜的瑜伽垫，并决定开始研究它的灵活性。

在这种情况下，这需要删除大多数硬编码依赖项，增加可扩展性，并使整个代码库现代化。 这些引擎盖下的改进是此 V3 版本的主要焦点，但还有其他一些 **酷炫的新功能：**

*   [Apollo Sandbox](https://studio.apollographql.com/sandbox/explorer?) 是用于本地开发的新 GraphQL IDE，它是查询服务器的主要推荐工具
    
*   新增对Fastify和Hapi的最新版本的支持
    
*   AWS Lambda 和 Google Cloud Functions 集成现在直接构建在 Express 集成的基础上——这意味着新的 Apollo 服务器功能将在 Lambda 和 Cloud 函数中运行，而不会让您编写相同的代码 3 次
    

******本版本的内容不是引入大量令人兴奋的新功能，而是构建可扩展的基础，以便阿波罗服务器在未来实际构建这些新功能。 有点像 Venusaur 必须花一整圈来充电它的太阳光束移动才能使用它来释放地狱。

快速 TC39 更新
--------------------

当我们看到即将到来的 ECMA TC39 第 84 次会议的 [the agenda](https://github.com/tc39/agendas/blob/master/2021/07.md) 时，我们**Ecstatic**。 “查找志愿者进行笔记”、“INTL 语言环境信息更新”、“模块碎片当前方向”让我们——我不能强调这一点——引人入胜。 以至于我们申请加入 TC39。

不幸的是，我们的申请被拒绝了“我们不聪明”和“我们甚至没有那么有趣”。 谢天谢地，TC39 代表 [Hemanth](https://twitter.com/GNUmanth) 在那里，[wrote a recap](https://dev.to/hemanth/updates-from-the-84th-meeting-of-tc39-c41)：

**第一阶段：**

*   [ArrayBuffer to/from base64](https://github.com/tc39-transfer/proposal-arraybuffer-base64) — ArrayBuffer ↔️ base64 字符串函数，这将为 JavaScript 提供内置机制，将二进制数据编码为 base64

**第3阶段：**

*   [Array find from last](https://github.com/tc39/proposal-array-find-from-last) — 数组和类型数组的 `.findLast()` 和 `.findLastIndex()` 方法的提议
*   [Intl Enumeration API](https://github.com/tc39/proposal-intl-enumeration) — 返回支持的选项值，例如时区、日历、编号系统、货币、单位

**第4阶段：**

*   [Ergonomic brand check for Private Fields](https://github.com/tc39/proposal-private-fields-in-in) — 使用 `in` 关键字检查对象是否具有私有字段，如果没有，则具有一些回退行为。

**底线：** 是的，这是 JavaScript-land 的缓慢一周。 谢谢你的提问。

很酷的位
----------

1.  从1990年到今天，Gigi用JavaScript写了一篇深入的[the evolution of graphics](https://blog.sessionstack.com/how-javascript-works-the-evolution-of-graphics-500e0eb764a0)。 我们已经在 30 年中取得了长足的进步，但事实证明，如果您愿意，您仍然可以在 [Casio graphing calculator](http://fxip.as203478.net/) 上托管一个网站。
    
2.  [Tempura](https://github.com/lukeed/tempura) 是一个“轻巧、香脆、美味的模板引擎”，听起来比他将其命名为 _DeepFried.js_ 更经典。
    
3.   Brendan Eich 和 Allen Wirfs-Brock 在 [The First 20 Years of JavaScript](https://www.pldi21.org/prerecorded_hopl.12.html) 上发表了长达一小时的演讲。 这是一种更快的方式来消耗他们在去年写的关于这个主题的超长论文中涵盖的大量材料。
    
4.  [Dinero.js](https://github.com/dinerojs/dinero.js) 是一个库，可让您在 JavaScript 和 TypeScript 中安全地创建、计算和格式化金钱，显然受到 2018 年 J-LO 和 DJ Khaled [song](https://www.youtube.com/watch?v=aEM2kOrrNJI) 的启发。
    
5.  [Firefox 90](https://hacks.mozilla.org/2021/07/getting-lively-with-firefox-90/) 上周发布了一些新功能，供开发人员使用。 还有 10 次更新，它将演变成 Icefox。
    
6.  [FracturedJson](https://j-brooke.github.io/FracturedJson/) 是一个 JSON 格式化程序，它可以生成一个可读但相当紧凑的输出。
    
7.  [esbuild-loader](https://github.com/privatenumber/esbuild-loader) 通过提供更快的翻译替代方案，您可以利用 Webpack 构建中的 ESBuild 的速度。
    
8.  Átila 用 Netlify 和 Next.js 写了关于 [Breaking Down Bulky Builds](https://www.smashingmagazine.com/2021/06/breaking-down-bulky-builds-netlify-nextjs/) 的文章。 真的很期待他发布同名的家庭锻炼 DVD。 “分解笨重的建筑——[I hate it… but I love it](https://www.youtube.com/watch?v=ERR5Sdm7mA8)。”

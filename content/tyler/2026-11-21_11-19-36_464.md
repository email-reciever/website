SOLIDJS 获得 SSR 发光
----------------------------

[The release notes](https://github.com/solidjs/solid/releases/tag/v1.3.0) for solidJS v1.3 的标题是“Spice Must Flow”——来自_Dune_的一行，它可能是对风险投资家和大型技术对OSS框架过度商品化的隐喻批评，以及更大的系统性问题 困扰我们当前版本的后期技术资本主义。

或者也许 SolidJS 团队只是喜欢 Dune。 [I guess we’ll never know.](https://www.youtube.com/watch?v=GzlKja1ySzo&t=10s)

**快速回顾：** SOLIDJS是一个新的JavaScript框架，它在2021年获得了[a lot of buzz](https://risingstars.js.org/2021/en#section-framework)，因为它的_[why-not-both](https://www.youtube.com/watch?v=vqgSO8_cRio&t=5s)_提供了“React的所有灵活性和Svelte的简单心理模型”的方法。

**这实际上意味着什么？** Solid 拥有所有您最喜欢的 React 功能，例如片段、上下文、并发渲染、SSR 等——但没有虚拟 DOM。 相反，Solid 的每个部分（包括它的渲染器）都建立在可组合的“反应式原语”的相同基础上，这些基元非常可扩展且 [very fast.](https://krausest.github.io/js-framework-benchmark/current.html)

此 1.3 版本旨在加强 SOLID 的 SSR 功能。 以下是如何：

*   **[HTML Streaming](https://www.youtube.com/watch?v=8hlo9uPrpr4)** — 一旦 HTML 可供用户使用，它就会立即流式传输和插入（即使 JavaScript 包尚未加载），这要归功于新的 `renderToStream` API。
    
*   **同构错误边界** — 使所有渲染方法（包括流）捕获和解决渲染错误变得更加容易。
    
*   **多个异步水合路线** — 您现在可以在所有 Solid 的服务器渲染方法和 Hydrate 函数上传递一个唯一的 `renderId`。 这可以隔离所有水合作用，并让您在同一页面上渲染和水合多个实体应用程序。

2022年GraphQL状态
-----------------------------

2021年对于GraphQL世界来说是一个重要的一年。 让我们来看看2022年发生了什么以及我们所处的位置。

**剩下的是 GraphQL？** 它是由 _Lee_ Byron 勋爵和他的（旧）团队在 Meta 创建的一种 API 查询语言，用于在 Web 和移动应用程序之间共享 API。 GraphQL 没有为每个 API 使用不同的 URL，而是使用单个端点并具有您希望随请求一起发送的确切数据。

像大多数 React 团队一样，GraphQL 迫不及待地想摆脱 Facebook 元数据——它最终在 2018 年成立了 GraphQL 基金会。 从那时起，它产生了一个生动的社区，[companies](https://www.the-guild.dev) 中的 [lots](https://graphcdn.io) 尝试 [commercialize](https://www.apollographql.com) GraphQL、许多 [services](https://supabase.com) 支持 GraphQL 和 _Many_ [packages](https://github.com/chentsulin/awesome-graphql#implementations) 来实现 GraphQL。

2021年GraphQL发生了什么大事？

*   Apollo 发布了 [Odyssey](https://odyssey.apollographql.com)，这是一系列用于学习 GraphQL 的免费教程，这些教程被适当地命名（和样式化），以跟上 Apollo 的 _ancient-greeks-in-space_ 品牌。
    
*   公会发布[Envelop](https://www.envelop.dev)，这是一个插件系统，可以更轻松地向GraphQL服务器添加功能和集成。
    
*   GraphQL 基金会出版了 [2021 Spec](https://spec.graphql.org/October2021/) — 一份很长的文件（就像这本书 _infinite jest_ 一样）没有人拥有 [actually read](https://mobile.twitter.com/miragonz/status/983057575972192256) 的完整性。 但它仍然是一个很好的资源。
    
[GraphQL-JS](https://github.com/graphql/graphql-js/releases/tag/v16.0.0)的*   V16（大家使用的GraphQL的参考实现）已发布。 他们_finally_踢到路边并在打字稿中重写了整个东西🙏。
    

**我们在 [Relay 13.0](https://github.com/facebook/relay/releases/tag/v13.0.0) 的发布中以风格开始了 2022**，其中包括他们花哨的新 [Rust compiler](https://relay.dev/blog/2021/12/08/introducing-the-new-relay-compiler/)（因为法律上每个 OSS 项目都被法律要求在 Rust 中重写他们的编译器）。

Relay 是 Meta 的 GraphQL 客户端首选。 仅当您的 GraphQL 服务器 [follows the Relay specification](https://relay.dev/docs/guides/graphql-server-specification/) 时，它才起作用，但它承诺 [declarative](https://www.youtube.com/watch?v=E7Fbf7R3x6I) 数据获取、查询优化和更少的样板。 这个新的 Rust 编译器，以及他们去年发布的尖端 [React hooks API](https://relay.dev/blog/2021/03/09/introducing-relay-hooks/) 使 Relay 成为一个引人注目的选择——特别是如果您在元宇宙中构建 [dystopian Wal-Mart hellscape](https://twitter.com/DigitalisHomo/status/1478094074909540354)。

**底线：** 看起来 GraphQL 股票将在 2022 年继续上涨（与字面上的每一个真实股票不同）。

### NX 挖出一些主要的干粉

上周，我们提到NRWL/NX在VC中筹集了860万美元，以“将Monorepos主流化”。 我们没有提到，他们的音高平台只是 CEO Jeff Cross [pig named Cheddar](https://twitter.com/search?q=Cheddar%20\(from%3Ajeffbcross\)&src=typed_query 的单张幻灯片）举着一个标语，上面写着“让我们把培根带回家。” （不是真的，但我敢打赌A16Z会喜欢的。）

因此，让我们仔细看看 Monorepos 解决了哪些问题，是什么让 NX 在单片土地中成为独特的雪花，以及它们将从这里走向何处，因为他们已经出卖了自己的灵魂，筹集了一些可观的现金。

**MonorePos 101:** Monorepos 让您将大型代码库拆分为独立的独立版本包。 这使您可以轻松地在软件包之间共享代码——在与大型团队一起处理大型项目时，可以节省大量时间、开销和复杂性。

像谷歌这样的大型企业帮助推广了这种方法，但早期的 JavaScript 开源 Monorepos（如 Lerna）折磨了开发速度非常慢的开发人员。 每次进行代码更改时，您都必须重建_Everything_，这取决于您更改的模块。

**NX 早在 2017 年就推出了第一款 MonoRepo**，其明确目标是加快这些构建时间并为大众带来 Monorepos。 他们是如何做到的：

*   他们的“计算缓存”使用远程缓存和本地缓存等技术，以确保您永远不会重建相同的代码两次。
    
*   一个特殊的 `affected` 命令绘制您的代码的图表，计算出更改的位置，并且仅构建受当前 PR 影响的应用程序/包的部分。
    
*   分布式任务执行并行运行所有必要的任务，以确保它们以正确的顺序尽可能快地执行。
    

**他们从这里去哪里？** 像大多数 VC 支持的 OSS 项目一样，NX 的游戏名称是“让尽可能多的公司使用我们的 OSS，并希望以后在高级企业功能上推销它们。” 到目前为止，它似乎进展顺利。

他们的 npm 下载量今年增长了 5 倍，达到 300 万，通过接管 lerna 的主动管理，他们现在控制了所有 JS Monorepo 工具中的 75%。 在这一点上，Turborepo（最近被 Vercel 收购）是唯一阻碍他们完全单一的垄断的东西。

**底线：** NX 的下一步是继续谈论它的书，并希望他们能让 Monorepos 比我的新生宿舍里的单声道更快地接触到开发人员。

这里有很多误导。 错误发生在我们的 `if (!completed)` 检查中。 `completed` 是一个布尔值，意思是当 `completed` 是 `false` （使它为假）时，我们的代码会抛出一个错误。 相反，我们可以检查 `completed` 是否属于 `boolean` 类型，而不是它是否为假。

if (typeof completed !== 'boolean') {
抛出新错误（“完成是必需的参数”）；
}

不是车，是司机

音量上升，踏板向下
----------------------

我们和大多数人一样，欣赏一个好的司机。 米妮、亚当、宝贝……一切都很棒。 因此，PlanetScale 上周在宣布“PlanetScaleless for JavaScript 驱动程序”（显然灵感来自“Dwight Schrute 的肌肉健身房”的灵感）时，无疑引起了我们的注意。

如果你还没有听说过PlanetScale，它是在GitHub的一堆兄弟决定将它们的脚趾浸入托管的MySQL的温暖水域并创建一个非常像Git的数据库时开始的（你可以分支和合并，使迁移和更新变得像拉动一样容易 请求）。

以前，您需要进行“原始 TCP 连接”（听起来很脏）才能将 sweet nothes _sql statements_ 到 pScale 中低声说——但现在有了他们的无服务器驱动程序，您可以使用 JavaScript 完成所有这些操作。 为此，团队必须重建整个 HTTP 基础架构。

以下是一些值得注意的细节：

1.  全局路由——边缘、节点、连接池——所有的好东西。 但实际上你需要知道的是它比 100ms 更快（求解一些 [issues common to edge ↔️ db connections](https://youtu.be/yOP5-3_WFus?t=294)）
    
2.  建立在Fetch API上——您可以在任何地方使用他们的驱动程序`fetch`（即使是混乱邪恶象限中的人的浏览器选择）
    
3.  安全性 — 这个新驱动程序对您的查询进行了消毒以防止 SQL 注入（我们将利用此时刻提醒您对 Hydroflask 进行了数月的清理——我们知道你们会很讨厌）
    
4.  目前处于测试阶段——就像 Beta 软件曾经阻止过你一样（但它可能不会对 [try before you buy](https://planetscale.com/docs/tutorials/planetscale-serverless-driver) 造成伤害）
    

**底线：** 另一个巨大的 W 用于边缘、无服务器和获取（如果 🌎规模团队想要向我们发送其中一个 [bomber jackets](https://twitter.com/isamlambert/status/1550193516139098112)），也不介意。

明星们在Bootfest

靴子的11岁生日狂欢
----------------------------

为了庆祝上周年满 11 岁的 Bootstrap，我们想举办一个大型的 2011 年主题派对，一个全 Dubstep 舞池、一个 jQuery 纹身站和 Justin Bieber 的 _Never Say Never_ 纪录片重复播放。

但是，由于你们没有人回复我们的 Bootfest 2022 电子签证，我们只需要以电子邮件的形式庆祝。

**我们是如何到达这里的：** Bootstrap 永远不应该是下一件大事。 Mark Otto 和 Jacob Thornton 只是想帮助他们在 Twitter 上的团队构建看起来不那么简陋的内部工具（重组还没有出现😢）。

但在公司的 Hackweek 上推出了他们的第一个版本的“Twitter Bootstrap”后，它立即在 Twitter 的其他团队中起飞。 因此，Mark 和 Jacob 开始与设计师和工程师的同等组合合作，创建一个更广泛的组件库，这些组件看起来很棒，并且很容易通过在您的 HTML 中添加一些类来实现。

当他们在 2011 年 8 月开源的 Bootstrap 时，开发人员把它吃掉了。 Web 应用程序仍然刚刚开始成为一种东西，Bootstrap 为那些不习惯为 Web 构建（或样式）更丰富、更具交互性的体验的开发人员提供了一个有用的起点。

尽管我们最终都厌倦了在任何地方看到相同的引导网站，但它的 11 年运行（即 77 年的网络年份）仍然令人印象深刻。 他们经历了重大的重写——整合了响应式设计，从少量切换到 Sass，添加了 Flexbox 支持，消除了 JQery 的依赖性——同时添加了数十个新组件。

今天，Bootstrap 仍然是 GitHub 上排名第 7 的项目，并且比 Tailwind CSS 获得了更多的 [npm installs](https://npmtrends.com/bootstrap-vs-tailwindcss)。 事实证明，设计精良且易于使用仍然是 OSS 中不败的组合。

**底线：** Bootfest 可能很简短，但它肯定比今年夏天的一半技术会议更有趣（它也闻起来更好）。

如前所述，如果您查看 `Array.prototype`，它没有 `hasOwnProperty` 方法。 那么，`friends` 数组如何访问 `hasOwnProperty` 呢？

原因是 `Array` 类扩展了 `Object` 类。 因此，当 JavaScript 解释器看到 `friends` 没有 `hasOwnProperty` 属性时，它会检查 `Array.prototype` 是否有。 当 `Array.prototype` 没有时，它会检查 `Object.prototype` 是否这样做，然后调用它。

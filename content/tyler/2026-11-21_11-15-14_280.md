### Angular做自己的事情

与我的大家庭在感恩节晚餐上谈论政治教会了我一件事：有时当桌上的其他人都_zigging_时，_zag_会很有趣。 （虽然我没想到我的奶奶会如此热情地为拉尔夫·纳德辩护。）

Angular 也欣赏好的曲折的艺术——尤其是当他们将“包含电池”的理念加倍时，而大多数其他 JS 框架越来越多地转向 BYO-Everything 模型。 让我们确切地分解这个不断增长的鸿沟是什么样的，然后仔细看看上周的 [Angular 15 release](https://blog.angular.io/angular-v15-is-now-available-df7be7f2f4c8)。

** 两种意识形态的故事：** 就像 90 年代的美国制造业一样，JS 框架如 React、Vue、Svelte、Solid 和 Qwik 外包了他们的许多核心能力。 在不同程度上，这包括路由、UI 组件、数据获取、设计系统、国际化、SSR 等功能。 这种方法为开发人员提供了很多细粒度的灵活性并有助于推动创新，但它也可能带来两个潜在的挑战：1）开发人员需要学习一堆不同的元框架和库的怪癖；2）框架的生态系统经常会因重大突破性变化而破裂 （Vuetify v3 是 _finally_ 刚刚发布，在 Vue 3 之后的两年）。

另一方面，Angular 采用了我们前面提到的“包含电池”的方法。 他们创建了自己的表单库、自己的国际化工具、用于数据获取的内置 HTTP 解决方案、用于 SSR 的 Angular Universal 以及用于各种 UI 样式和元素的官方 Angular 包。 这也需要权衡：开发人员获得的灵活性较小，第三方项目更少可能意味着更少的创新。 但它确实有助于最大限度地减少复杂性和破坏性变化的痛苦（对于基于 Angular 的大型企业应用程序来说，这两个特别重要的点）。

Angular 15 通过为 Angular 核心添加更多功能来扩展这一多合一的想法。 其中一些功能已经在 v14 中可用，但现在稳定并准备好生产：

*   **稳定的独立API** — 无需使用ngModules即可构建应用程序，这意味着要少得多的样板。
    
*   **Router 和 HttpClient 树状可摇动的独立 API** — 您可以使用新的独立 API 构建多路由应用程序，并且它们是可树状的。
    
*   **Directive Composition API** — 允许您使用指令增强主机元素，并为您提供强大的代码重用策略。
    

**底线：**有很多获胜的方法，很高兴看到 Angular 继续以自己独特的方式推动网络向前发展。

本周趋势
------------------

![less vs sass vs stylus](https://bytes.dev/images/content/css-trends.jpg)

哪个CSS最好？ – 数据 [npmtrends.com](https://npmtrends.com/less-vs-sass-vs-stylus)

即使您通常不庆祝今天以食物为中心的怪异的美国假期，我希望您仍然享用饱和脂肪、简单碳水化合物和热食的均衡餐点。 如果您感觉不太臃肿，让我们齐聚一堂，尝试解决 2015 年每个人最喜欢的辩论：CSS 的哪种风格是最好的？

让我们会见竞争者，看看是否有足够的时间最终宣布获胜者：

**SASS：** 创建于 2002 年，最初是为 Ruby 生态系统设计的，并为 CSS 带来了函数、变量和嵌套。 最终，它被移植到 JavaScript（现在是编译为 JS 的 Dart），每周 1000 万次下载甚至不包括 Ruby 版本（和其他端口）。

**less:** OG CSS-in-JS 于 2009 年创建，旨在成为 JavaScript 生态系统的 Sass。 它在各个方面都明显优于 Sass，除了大多数人更喜欢 Sass 的事实。 它仍然以每周 500 万次下载而出人意料地受欢迎。

**Stylus:** 如果有一个流行的 Node.js 库，很可能是 [TJ Holowaychuk](https://github.com/tj) 写的（他做到了，早在 2010 年）。 虽然 Stylus 一直是一个小众市场，但它仍然每周下载 360 万次，并且是 [greatest CSS dev](https://lynnandtonic.com/) 的首选工具（嗨 lynn 👋）。 就像 T-Swift 一样，它永远不会过时（双关语非常有意）。

**获胜者：** Sass 显然是人民冠军，但由于现代 CSS 拥有大部分相同的功能和更少的包袱，这种胜利可能是短暂的。

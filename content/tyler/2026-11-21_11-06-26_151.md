### Bundows 在这里

BUN今天早些时候刚刚推出[v1.1](https://bun.sh/blog/bun-v1.1)，这是一个巨大的版本。

我们终于获得了完整的 Windows 支持，这意味着 BUN 的运行时、测试运行器、包管理器和捆绑程序都可以在 Windows 上运行。 因为它是面包，所以它们都是快速的 AF。 以下是一些快速统计：

*   在安装 Vite React 应用程序时，BUN 的包管理器 `bun install` 在 Windows 上的运行速度比 `yarn` 和 `pnpm` 快 30 倍，速度快 30 倍。
    
*   `bun run` 是运行脚本的 `npm run` 快 11 倍的替代方案。 他们通过创建新的 `.bunx` 文件格式在 Windows 上使它更快，这是一个 [cross-filesystem symlink](https://bun.sh/blog/bun-v1.1#bun-run-on-windows)，可以使用 bun 或 node.js 启动脚本或可执行文件。
    
*   他们优化了大量的Node API，以使用Windows上最快的系统调用，显着提高了性能。
    

这个 Bun 1.1 [launch video](https://www.youtube.com/watch?v=yXTFOeGly9o) 详细介绍了所有 Windows 更新。 但是当我们观看它时，我们学到了两个令人惊讶但重要的事实：1）Jarred Sumner 的黄油光滑男中音非常适合 90 年代的动作片预告片，以及 2）这个版本不仅仅是 Windows 支持。

在 BUN 1.1 中，Bun 现在是一个 [cross-platform shell](https://bun.sh/docs/runtime/shell)，可以在 Windows、Linux 和 macOS 上无缝运行，无需任何其他依赖项。 它具有熟悉的功能，如重定向、管道和环境变量——但它还引入了内置 [Glob API](https://bun.sh/docs/api/glob) 和增强的 JavaScript 互操作等新功能。

此版本还改进了 BUN 的 Node.js 与 Node API 的新修复和改进兼容性以及对 PlayWright、Puppeteer 和 TensorFlowJS 等 npm 软件包的新支持。 Bun 仍然旨在成为 Node 的替代品，Bun 团队表示“如果它在 Node.js 中但不适用于 Bun，它是 BUN 中的错误。”

BUN 1.1 还引入了许多其他速度和性能升级，但我们可以写的方式只有这么多，“bun 比 `[insert build tool]` 快 100 倍”——所以如果你想了解更多细节，请查看公告帖子。

**底线：** _\*\*Jarred Sumner Voice\*\*_ 在一个每隔一个周末都会出现新的 JavaScript 运行时的世界中，仍有一个团队比其他团队更快地发布新更新。 但是 Bun 是否能够做得足以将 Node.js 赶出王位？ 继续关注。

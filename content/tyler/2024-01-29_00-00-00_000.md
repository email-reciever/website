### 最好远离 zed

上周，Zed 宣布他们是他们的下一代编辑器和为其提供支持的 UI 框架的 [open-sourcing](https://zed.dev/blog/zed-is-now-open-source)，开发人员被 _hyped._

公告推文爆炸，Zed Repo 立即增加了 13,000 多颗 GitHub 明星，黑客新闻充满了如此多的积极评论，我认为 Pebble 正在推出另一款智能手表 (RIP)。

为什么所有的兴奋？ 两个原因：

1.  每个人都喜欢免费软件。
2.  ZED 可能是将我们所有人从 VS Code 滞后中拯救出来的选择之一。

Zed 的主要卖点是它为您提供了一个成熟的 IDE 之类的 VS Code 的所有功能，以及 Sublime Text 等轻量级编辑器的响应能力。

为了实现这种黑魔法，Zed 团队为 Rust 构建了自己的 GPU 加速 UI 框架，称为 [GPUI](https://zed.dev/blog/gpui-ownership)，然后他们用它来构建 Zed 编辑器本身。 这种感觉就像从头开始建立一个整个奶牛场只是为了开一家冰淇淋店，但你认为 Ben & Jerry's 如何成为众神的奶油花蜜呢？

值得庆幸的是，这不是 Zed 团队第一次构建这样的农场到餐桌软件。 十年前，他们的创始人还在 GitHub 上构建了 Atom 编辑器，以及 Atom Shell Electron.js，这是一个为 Atom 提供动力的跨平台框架，至今仍为 VS Code 提供支持。

**但是等等，VS Code 的主要原因不是 Electron 会感觉迟缓和缓慢吗？** 是的，情节扭曲是什么。

通过使用 Rust 和 GPUI 构建本地桌面应用程序，Zed 的创建者采取了相反的方法来构建 Atom 和 Electron。 这让 Zed 感觉比 VS Code 更快、更流畅，同时仍然提供您所期望的所有 [modern IDE features](https://zed.dev/features) 以及您可能意想不到的杀手级功能——多人模式。

这使多个开发人员可以在共享的工作空间中一起导航和编辑代码，并讨论您正在使用类似 Slack 的聊天面板进行的更改。 即使有所有这些实时协作，它仍然是 [fast af](https://zed.dev/blog/videogame)。

这些团队协作功能可能是 Zed（一家由 VC 支持的初创公司）在未来赚钱的方式，因为他们承诺 IDE 本身将永远是免费和开源的。

**底线：** 恭喜 Zed 团队从 Ryan Dahl 学校毕业，“几年后开始一个新项目，以更好的方式解决我最初的问题”，以及 Godspeed on your quest。 我们都支持你。

您将如何在 JavaScript 中重新创建它？ 有几种方法，其中一种是以下。

常量范围 = (开始, 停止, step=1) => {
返回数组.from(
{ 长度：（停止 - 开始）/步骤 + 1 }，
（值，i）=> 开始 + i * 步
)
}
    

该函数使用 `Array.from()` 生成指定 `length` 的数组，并使用提供的函数生成的值填充它。 `length` 计算为 `(stop - start) / step + 1`，表示所需范围内的元素数。 传递给 `Array.from()` 的函数通过从 `start` 开始生成每个元素，添加 `i * step` 的增量，其中 `i` 是当前元素的索引。

### OSS 项目死后去哪儿了？

阅读一个旧的 OSS 库被转换成恶意软件的感觉就像在观看有关热狗是如何制作的 YouTube 视频之一——这非常令人不安，但我还期待什么？

最新的受害者是 Polyfill.js，它使具有现代 JavaScript 功能的网站能够在旧版浏览器中运行。 在 Evergreen 浏览器使该项目过时后，它正走上了缓慢、不起眼的互联网死亡的道路。 但作为 SANSEC 研究 [recently discovered](https://sansec.io/research/polyfill-supply-chain-attack)，该项目成为大规模供应侧攻击的主题。

**这是它发生的事情：**库是由一个名为`polyfill.io`的CDN分发的，它读取请求的`User-Agent`并返回该特定浏览器所需的polyfills。 早在 2 月，一家中国公司购买了 CDN 的 GitHub 仓库和域名，并开始在使用该服务的 100,000 多个网站上注入 `www.googie-anaiytics.com` 的虚假分析脚本。

好的，但是_为什么_他们这样做了？ 为什么这种情况会一直发生？

当然是钱。 我们已经 [previously written](https://bytes.dev/archives/134) 关于粗略的网站，兜售从 CBD 软糖到 Wiener Pills _Herbal Supplements for Men 的所有内容，_ 将赞助开源项目，以从项目的赞助商页面获得反向链接。 这种供应侧攻击感觉就像该战略的下一次演变。

Shady Companies 可以购买像 Polyfill.js 这样的项目，并用它在数千个页面上注入其体育博彩网站的链接，而不是支付每月费用来获得一个好的反向链接。 作为额外的好处，这种特殊的攻击还秘密地将受影响网站的移动用户随机转移到公司的博彩网站。 令人愉快。

**底线：** 幸运的是，一旦被发现，`polyfill.js`（不是[owner of the domain](https://x.com/gwillem/status/1805732247665811662)）的创建者就告诉大家停止使用该项目，以及Cloudflare和快速发布的安全版本的服务，供用户迁移。 但只要粗略的公司仍然是 OSS 最愿意的支持者，我们就有可能在未来用这些问题玩 whack-a-mole。

发现错误：解决方案
-----------------------

#### 赞助[Apryse](https://apryse.com/products/fluent?utm_source=bytes.dev&utm_medium=newsletter&utm_campaign=july0124)

如果您运行原始代码，您将获得“未捕获的 TypeError：无法读取未定义的属性（读取‘长度’)”。 我们使用的唯一位置 `.length` 是在 `reduceLanguages` 函数中，因此我们可以推断 `this.languages` 是 `undefined` 并且我们错误地使用了 `this` 关键字。

每当您试图弄清楚 `this` 关键字引用的内容时，您需要查看使用 `this` 关键字的函数在哪里被调用。 在我们的示例中，我们不知道，因为它是在 `reduce` 的实现中。 为了确保在正确的上下文中调用 `reduceLanguages` 并因此具有正确的 `this` 绑定，我们有两个选择。 首先，老派的方式-使用`.bind`。

问候（）{
常量 Hello = `Hello, my name is ${this.name} and I know`;
    
const langs = this.languages.reduce(reduceLanguages.bind(this), "");
    
返回 Hello + Langs；
}
    

其次，更好的方法 - 使用箭头函数。

问候（）{
常量 Hello = `Hello, my name is ${this.name} and I know`;
    
const langs = this.languages.reduce((str, lang, i) => {
如果 (i === this.languages.length - 1) {
返回 `${str} and ${lang}.`；
}
    
返回 `${str} ${lang},`；
}, "");
    
返回 Hello + Langs；
}
    

之所以有效，是因为在箭头函数中`this`是_lexically_确定的。 箭头函数没有自己的`this`。 相反，就像变量查找一样，JavaScript 解释器将查看封闭（父级）范围以确定 `this` 应该引用的内容。

想阅读更多？ 退房[Understanding the “this” keyword, call, apply, and bind in JavaScript](https://ui.dev/this-keyword-call-apply-bind-javascript)。

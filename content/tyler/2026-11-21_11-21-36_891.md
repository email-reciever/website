金钱和名望
================

问题 #42.April 5, 2021.2 分钟阅读。

![Bytes](https://bytes.dev/images/bytes-banner-rounded.png)

那是_deno-the-company_，给你
--------------------------------

![Two dinosaurs](https://bytes.dev/images/content/deno-money.png)

是你吗，妈妈？

**像我这样的运行时间是 490 万美元，** 你能提醒我吗？

我们知道 Ryan Dahl 整个周末都在为自己唱这首歌，此前他筹集了一大堆现金并宣布这一点 [Deno is a company now](https://deno.com/blog/the-deno-company)。

**这是什么意思？** Deno 是自由开源的、安全的 JavaScript/TypeScript 运行时，它希望成为 Node.js 的精神继承者（也由 Ryan Dahl 创建）。 值得庆幸的是，“免费开源”部分并没有随着 Deno Corp™ 的形成而改变。

不会有免费增值或“开放核心”模式，用户可以获得一些 Deno 功能，但必须为其他人付费。 相反，瑞安说：“这一轮融资将确保我的家庭在子孙后代的财务独立。” 好吧，这是一个笑话，但他确实说 Deno 业务“将建立在开源项目的基础上，而不是试图直接将其货币化。”

它已经在 [Deno Deploy](https://deno.com/deploy) 中执行此操作——一个用于在边缘运行 JavaScript、TypeScript 和 WebAssembly 的新分布式 VM。

乍一看，部署平台看起来很酷：它与 Daphne V8 深度集成，并建立在 Rust 之上（所以它很快），它可以让您在本地开发和全球部署，它有一个“许可许可的 CLI”，可以让您使用任何您想要的云服务（或自主机）， 登陆页面有非常可爱的恐龙插图。

**Deno 为什么要走这条路？** 两个重要原因：

1.  金钱和名望。
    
2.  在公告帖子中，Ryan 解释说，服务器端 JavaScript 未能跟上我们在浏览器中看到的创新。 他在 Node.js (LOL) 上拍了几张照片，并通过创建一组可重新用于为不同应用程序创建 _custom runtimes_ 的技术，阐述了 Deno 的“为生态系统注入新生命”的愿景。 490 万美元将允许 Deno 雇用一名全职工程师员工，剩余的 400 万美元用于 101 号的 COVID 后 Soma 办公空间和广告牌，取笑 Node。

Cloudflare 的耐用对象
-----------------------------

![Twinkies](https://bytes.dev/images/content/twinkies.png)

原始的“耐用物体”

**Cloudflare 宣布了 Durable Objects 的公开测试版**，这是他们新的无状态服务器数据库，它在长期运行的服务器的棺材上再加上一颗钉子。 万岁无服务器！

**我们是如何到达这里的？** Cloudflare 的主要产品是全球 CDN 和 DDoS 保护，有超过 2500 万个网站使用他们的产品。 2017 年，他们发布了一个名为 Cloudflare Workers 的无服务器平台，该平台 0ms Cold 启动（以 AWS Lambda 为例）。

9 月，Cloudflare 宣布了耐用对象的封闭测试版，_非常巧妙地_ 命名的存储解决方案为工人提供了有状态的超能力。 看，老式无服务器无法像老式服务器那样保留任何数据或上下文。 函数完成后，运行无服务器代码的“服务器”就会消失。 另一方面，耐用的物体……嗯……耐用。

*   耐用对象**用类**定义，通常用JavaScript编写。 该类定义了对象的方法和属性，然后 Cloudflare 使用该类实例化对象。
    
*   持久物体**保持其状态**，即使它们不活跃。 对于每个对象来说，它就像一个超快的私有数据库。
    
*   每个耐用的物体都是**唯一的**，这意味着全世界只有一个，因此它们可以互相发送消息。
    

假设您有一个聊天室持久物体。 它可以跟踪连接到它的 WebSockets，每当用户发送消息时，它都会将该消息广播给所有连接的客户端。 此外，使用该私有数据库，它可以存储访问者首次连接时的聊天室历史记录。 由于它是无服务器的，因此它可以扩展到大量独特的房间和用户，而无需开发人员配置任何内容。

此外，耐用的物体位于边缘，靠近请求的来源； 从自己的耐用对象请求数据的用户将获得邪恶的快速响应时间！ 生活在边缘是值得的。

js 提示
-------

你用过数组的 `fill` 方法吗？ 可能不是。 定义，`fill`“用静态值填充数组的所有元素，从开始索引到结束索引”。 这听起来很没用，但我发现了一种情况，它实际上很有帮助。

当你开始使代码更具功能性时，你自然会开始避免使用常规的 for 循环来支持 `.map`、`.reduce` 等。假设我们的用例是我们想执行一个任意次数的函数，比如 10。我们如何做到这一点并避免使用 for 循环？ 您的第一个直觉可能是使用带有 `.map` 的数组构造函数。

数组(10).map(() => {
返回 dothing()
})
    

您会注意到如果您运行该代码，它将不起作用。 当您执行 `Array(10)` 时，您将创建一个包含 10 个未设置或“空”值的数组。 不幸的是，当您使用任何数组方法时，它们将无法在具有空值的数组上工作。

这就是 `.fill` 发挥作用的地方。 如果你这样做`Array(10).fill()`，你会得到一个10`undefined`而不是空元素的数组。

数组(10).fill().map(() => {
返回 dothing()
})
    

不是 _super_ 有用，但如果您需要它，很高兴知道它的存在。

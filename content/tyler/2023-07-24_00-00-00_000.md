### Framework Barbie，我们去派对吧

欢迎来到 _framework Barbie Land,_ 您最喜欢的 JavaScript 框架是不同的芭比娃娃，而且原子弹从未被发明出来。

FBL 是一个具有 100% 积极氛围的神奇场所。 在这里，Barbies 没有一个框架互相转发，关心谁发明了什么，他们甚至做梦也想不到因为一个人为的性能基准而互相呼唤。

因此，本着这种精神，请允许我向您介绍我们每个人才华横溢、同样受人喜爱的框架芭比娃娃：

**Malibu Barbie — React.** 这不是第一个芭比/框架，但它可能是大多数人想到的第一个。 当然，它们对于延续不切实际的身体图像/捆绑尺寸可能有点问题，但它们之所以受欢迎是有原因的。 由于他们都继续自我改造，你知道他们不会很快消失。 _（是的，这确实意味着 next.js 是 ken。）_

**Darwinian Barbie — Angular.** 自 Angular.js 时代以来，“Adapt and Survival”一直是 Barbie 的座右铭，从那以后它就一直没有停止发展。 它最近的主要版本引入了一些主要的 SSR 升级，并使其成为第一个引入细粒度反应性的主要框架。 它会在未来几年适应和_thrive_。

**时髦芭比娃娃 — 苗条。 它不像这个列表中的其他一些人那样主流，但它总是领先于创建令人难以置信的简洁组件，不使用虚拟 DOM 并将一些很酷的交互元素融入到他们的文档中的新想法。

**独立芭比 — Vue.** 与此列表中的所有其他框架芭比娃娃不同，Vue 是唯一一家目前没有一家数十亿美元的科技公司支持的公司（取决于您目前对 Vercel 的评价）。 自 Vue 首次发布以来，它已经快整整十年了，在那段时间里，它设法不断增长其市场份额、推出强大的新功能并建立一个充满激情的社区——同时保持完全独立和财务可行性。

**底线：** 读完这篇文章后，您可能会想知道——整个故事基本上是一个美化的 BuzzFeed 测验，字节是否以某种方式与华纳兄弟和美特尔达成了一个奇怪但利润丰厚的跨界品牌交易？ 还有，我在发烧梦中吗？_

不，至少我们不这么认为。

发现错误：解决方案
-----------------------

#### 赞助[Datadog](https://www.datadoghq.com/bytes/)

执行此代码时将记录到控制台的内容？

window.name = “迈克泰森”；
    
常数我 = {
名称：“泰勒”，
姓名（）{
console.log(this.name);
},
};
    
const sayname = me.sayname;
说出名（）；
    

答案？ “迈克泰森”。

由于我们不处于严格模式，`sayName` 不是一种方法，我们不使用 `call` 或 `apply` ，`sayName` 内的 `this` 将默认为 `window` 对象。

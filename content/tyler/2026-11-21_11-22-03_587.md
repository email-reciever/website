Vuex 发布 V4.0
-------------------

![The Weeknd](https://bytes.dev/images/content/vuex-bugs.png)

使用 Vuex 以可预测的方式变异状态时的错误

**快速 re-_vue_:** Vuex 是 Vue.js 的 [default state management pattern and library](https://next.vuex.vuejs.org/)。 它由 Vue 团队的成员创建，并按照您在 Redux 中看到的相同的通量模式和架构进行设计。 Redux 和 Vue 之间的主要区别与不可变性有关。 当你在 Redux 中发生变异状态时，Dan 会出现并礼貌地向你的方向皱眉。 当您在 Vuex 中发生变异状态时，假设您遵守规则，Evan 会出现并给您一个微妙但认可的微笑。

**新增功能：** 为了与 Vue 保持紧密集成，此新 Vuex 版本侧重于与去年 9 月发布的 Vue 3 发布的所有新更新的兼容性。 这包括对 Vue 3 的 [Composition API](https://v3.vuejs.org/guide/composition-api-introduction.html) 的新添加支持、更大的 TypeScript 支持以及更简化的 Vuex 一般使用方法。

**突破性变化：**

*   **新安装过程** — 在 Vuex 4.0 中，您使用新的 `createStore` 函数创建一个新的 store 实例。
    
*   **Vue Components 中 `this.$store` 的全局类型的移除** — 旨在使 TypeScript 用户能够在组件中编写完整的类型图层，包括启用完全类型化结构的手动声明。
    
*   **New Bundles** — 自动生成四个捆绑包以与 Vue 3 对齐。 [Check out the docs](https://github.com/vuejs/vuex/releases/tag/v4.0.0) 如果您想查看它们是什么，因为我拒绝将它们全部输入到此电子邮件中。

NPM 7 是 `latest` 和最大的
------------------------------------

![npm v7](https://bytes.dev/images/content/npm-vs-yarn.png)

叫救护车，但不适合我

**npm 7 上周刚刚发布**作为 `latest` 到 npm 注册表，它现在是您运行时获得的默认版本 `npm install --global npm`。 我们在去年 10 月首次宣布此更新时写了有关此更新的文章，但由于当时你们中的大多数人都没有和我们在一起，而你们其他人忘记了它，我们为您整理了这个小的 NPM 7 刷新。

**3 大亮点：**

*   **Workspaces** — 到目前为止，NPM 用户请求最多的功能，这套新的 NPM CLI 功能允许您从单数的顶级根包中管理多个包。 这是任何软件包管理器（未命名为 y\*rn）首次提供此功能。
    
*   **自动安装对等依赖项** — 使用 npm v6（因为编程很难），`peerDependencies` 默认未安装。 使用 V7（因为我们可以做困难的事情），他们是。
    
*   **package-lock v2 和对 yarn.lock 的支持。lock:** _当你的父母分开但他们无论如何都搁置分歧来支持你时。_ v7 现在支持 `yarn.lock` 文件。 还有一种新的 `package-lock` 格式，它将（显然）“允许您进行‘确定性可重现的构建’，并包括 npm 完全构建包树所需的一切。”
    

其他很酷的新功能包括改进的 `npm audit` 输出以及在使用 `--ignore-scripts.` 时跳过预/发布脚本的功能

### 底线

这是 NPM 自 3 月被 GitHub/Microsoft 收购以来的第一个主要版本。 当这笔交易发生时，GitHub 的首席执行官承诺将微软的一些甜蜜 PowerPoint 资金用于现代化 NPM 并使其更快、更具可扩展性。

这个大版本让 GitHub 似乎开始兑现这一承诺，同时朝着将 npm 集成到 GitHub 本身的长期目标而努力。 继续关注。

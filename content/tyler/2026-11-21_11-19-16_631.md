庄严的人工智能——无代码的未来？
---------------------------------

[Piano Man himself](https://twitter.com/DavidKPiano) 将状态图带给大众——这是一个刚刚进入公共测试版的新 [statechart editor](https://stately.ai/blog/stately-editor-public-beta)。

**听起来很酷，但是wtf是一个状态图？

**听起来很酷，但 wtf 是一个状态机？** 你可能以前甚至没有意识到这一点——你的应用程序的一部分在特定状态之间转换以响应事件，那是一个状态机。 一个典型的例子是处理 HTTP 请求：状态从 `idle` 转换到 `loading` 并以 `resolved` 或 `error` 结尾。

凭借庄严的，David K（他也是 XState 的创建者，其姓氏实际上不是钢琴）的使命是让您的团队中的每个人都可以访问所有应用逻辑——包括设计师、PM 和营销人员（是的，这些人在技术上是在您的 团队）。

Stately 的可视化编辑器使这些人无需编写代码即可轻松创建、修改和测试应用程序的状态逻辑。 理论上，它也会使协作更加紧密：当您编辑代码时，它会实时更新编辑器的状态图——如果您（或团队中的其他人）对编辑器的图表进行更改，您将看到 _the code_ 实时更新（如果您正在使用 [XState VS Code extension](https://marketplace.visualstudio.com/items?itemName=statelyai.stately-vscode))。 可能出什么问题？

Webflow 和 Wix 等工具在 _designing_ 网站方面引领了无代码革命。 也许 Stately 将能够在定义应用程序逻辑和行为方面做同样的事情。 这一切都是可能的，因为宇宙中最大的力量：爱情状态机器和状态图。

🔬发现bug - 解决方案
---------------------------

这个 `import` 语句实际上是一个 [dynamic import](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/import#dynamic_imports)。 当它第一次调用时，它将从 CDN URL 中获取模块的代码并异步解析，这意味着 `import()` 返回一个 Promise。 我们需要使用 `.then()` 方法或 `async/await` 来访问模块。

异步函数 makeCamelCase(文本) {
const changeCase = await import('https://cdn.skypack.dev/change-case')
    
返回 ChangeCase.CamelCase(文本)
}

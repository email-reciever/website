谷歌点亮
----------------

![Pineapple Express Meme](https://bytes.dev/images/content/pine.png)

这是未来。 你的孙子们会抽烟的。

**我很确定_这只是一个巧合**，谷歌在 4/20 周发布了一个名为 **lit** 的新 Web 组件库。 但 420 友好的发布日期实际上非常合适，因为构成库的大多数工具现在都被重新命名和重新包装，与魔鬼的生菜本身一样多。

这是我们如何到达这里的快速时间表：

*   **2011** — Chrome 团队发布了 **Web 组件**。 这些 Web 平台 API 为我们提供了一种使用普通 JavaScript 创建自定义、可重复使用和封装的 HTML 标记的方法（它们也可以与其他 JS 框架集成）。 Web Components 的最大卖点是（现在仍然是）它们的互操作性——它们可以在 HTML 的任何地方工作。
    
*   **2015** — Google 发布了 **[Polymer](https://polymer-library.polymer-project.org/3.0/docs/devguide/feature-overview)** 的 v1.0，这是用于构建带有 Web 组件的 Web 应用程序的 OG 库。 Polymer 项目源于 Google 的 polyfilling 努力，使 Web 组件在 Chrome 以外的其他浏览器中运行。
    
*   **2017** — Polymer 团队开始听一堆 [Travis Scott](https://www.youtube.com/watch?v=y3FCXV8oEZU)（显然）并发布了 **LIT-HTML**，这是一个用 JavaScript 制作快速、富有表现力的 HTML 模板的小库。
    
*   **2018** — 聚合物通过释放 SICKOMODEELEMENT **LITELEMENT** 来加倍混淆的伪品牌，这是一种“样板杀伤”的 Web 组件基类，有点取代了许多原始的聚合物库。
    
*   **上周** — 他们终于通过将 lit-html 和 litelement 结合到 **lit 2.0** 中结束了疯狂，使用一个统一的 npm 包 `lit`、一组文档、一个新的 lit 组织和一个新网站 — [lit.dev](https://lit.dev/) （嫉妒）。 将原始聚合物库移至 LTM 模式。
    

LIT 2.0 还为快速、流式传输 SSR 和灵活的客户端补水引入了新的基础，这使它能够与 Next.js 和各种静态站点生成器等框架集成。 查看上周的 [launch event](https://www.youtube.com/watch?v=f1j7b696L-E) 以了解更多新功能的细分。

### 底线

Polymer/LIT 一直是构建可共享组件和设计系统的首选选择。 但随着新的和改进的品牌、功能的增强以及对性能的持续关注，LIT 2.0 也可能成为构建完整网站和应用程序的流行工具。

无论哪种方式，迫不及待地等待他们在六个月内发布 `Litty-Lit-AF-NoCap-Fam-html` 库。

超级甜蜜的Node.js 16
-----------------------

![Node 16 meme](https://bytes.dev/images/content/ss16.png)

我希望瑞恩达尔给他的孩子买了一辆雷克萨斯来庆祝

**最初的 JavaScript 运行时** 上周我们推出了一个主要版本，这意味着 Node.js 16 现在是获得所有有趣新功能的“当前”版本，而 Node 15 正式发粘和粗糙。

**节点 16 亮点：**

*   **Stable Timers Promise API** — 这提供了一组可返回 Promise 对象的定时器函数，这意味着不再需要使用 `util.promisify()`
    
*   **v8升级到v9.0** —它仍然没有被重命名为daphne（内部笑话，iykyk），但是这个v8升级带有很酷的东西，比如regex和faster的新匹配索引和faster `super` 属性访问
    
*   ** Web Crypto API 的实验实现** — 一种有趣且性感的新 JavaScript API，用于在 Web 应用程序中执行“基本加密操作”，如哈希、签名生成和验证以及加密。 当（_if?_）所有加密资产决定停止坦克时，我们迫不及待地使用它来发布一些不可替代的字节令牌（NFBT）。
    

此版本还带有预构建的 Apple Silicon 二进制文件和一些您可以在 [announcement post](https://nodejs.medium.com/node-js-16-available-now-7f5099a97e70) 中阅读的其他稳定 API。

### 底线

自从 Ryan 完成他的热门新项目以来，Node.js 可能会遇到一些放弃问题，但由于像这样可靠、一致的版本，这对我们大多数人来说仍然是“当下的运行时间”。

热规格夏天又回来了

与众不同的传统
-----------------------------

上周，我们在格里高利字节日历上观察了唯一的宗教节日：新版本的 ECMAScript 上线。

为了庆祝，我们带回了**热规格的夏季**——我们根据对JavaScript开发人员的感知效用的多变量分析（也就是他们的热度分数🔥）对每个新功能进行评分。

我知道在我参加的开发者训练营的那一天半的 CS 算法中，我知道有一天会派上用场。

**让我们认识新人：**

**Regexp Match Indices** — 这会创建一个新标志 `/d`，您可以将其放在正则表达式的末尾以获取捕获组的开始和结束索引。

🔥 评分：2.3/5 — _绝对有助于做更复杂的正则表达式的东西，但是如果你实际上在你的工作中做了很多复杂的正则表达式，你有更大的问题需要担心（比如找到不同的工作）。_

**类字段声明** — 允许您在类上直接声明类属性和方法，而无需使用构造函数。

🔥 评分：3/5 — _Lots 框架（包括 React）多年来已经有了这个功能，这要归功于 Babel。 但是现在很高兴将它内置到JS规范中。

**顶级 await** — 您过去只能在异步函数中使用 `await` 关键字。 但是现在您可以在程序的顶层使用 `await`，这在编写脚本以执行异步操作时很有帮助，而不是使用 IIFE (LOL)。

🔥 评分：4.2/5 _很多人很高兴使用此功能，因为它似乎对一些相当常见的用例很有帮助。 它几乎没有错过赢得最高奖项，就像杰西·平克曼在普莱斯的比赛中输了 [the most heartbreaking Showcase Showdown ever](https://www.youtube.com/watch?v=_SEL27xiJGQ&t=53s) 是对的那样。_

**error.cause** — `new Error()` 进行了升级，现在允许您指定实际导致当前错误的原因。

试试{
// 做东西
} 捕获（错误）{
抛出新错误（'解决这个问题 -', { 原因：错误});
}
    

🔥 评分：4.6/5 _老实说，无论如何你都会忽略你的应用程序中的错误，但至少知道它的存在是很好的。_

**.at()** — 数组上的这个新方法让我们获得特定索引的值，包括负索引。 这非常神奇，因为负索引从数组的末尾返回一个值，从而更容易抓取数组的最后一项。

🔥 评分：5/5 — _Great New Feature 非常简单，将使我们的生活更轻松。 最重要的是，它为 JavaScript 提供了 Python 多年来所拥有的东西，因此它给了他们一件废话的事情。

**底线：** 请记住负责任地庆祝炎热的夏季。

实时查看您的团队进行 UI 测试

是时候停止在UI错误中溺水了
---------------------------------

在应用的 UI 中为所有不同的状态和布局构建视觉测试是一种特殊的噩梦燃料。

基本上我们大多数人都可以通过两种方式来做到这一点：投入大量时间来构建一堆 _kind-sorta_ 工作的片面测试，或者只是决定让您的用户成为您的新 QA 团队并希望获得最好的结果。

值得庆幸的是，StorybookJS 的维护者聚集在一起，创建了第三个选项 — [Chromatic](https://www.chromatic.com/features/test)。 它实际上非常光滑。

**TLDR：** 它基本上是一个大型自动化游戏，即 _Spot the Difference_，只是使用您的软件，而不是您的孩子在 IHOP 的孩子菜单背面的两张图片。

**它是如何工作的：**

1.  彩色_\*\*实际上在云中呈现\*\*_每个组件（使用真实代码和样式），并拍摄快照。
2.  它将该快照与以前的组件版本进行比较，并通知您任何差异。
3.  与您的团队一起查看更改的速度非常快，因为每个组件都已完全索引且易于复制。

它需要大约 5 分钟才能成为您最喜欢的新工具。 [Check it out](https://www.chromatic.com/features/test)。

“我们现在可以在游泳池里玩美人鱼吗？” -shopify，可能

氢进入元框架领域
---------------------------------------

Shopify 的团队刚刚发布了 V1.0.0 的氢气，他们的 React 元框架用于构建 Shopify 店面，[this past week](https://shopify.engineering/how-we-built-hydrogen)。

如果您厌倦了听说元框架，我们厌倦了写它们——但迟早你会被束缚在“帮助”你的朋友在线销售他们的自制精油，我们希望你做好准备。

好的，那么什么是氢气，它与“其他”有何不同？

氢，或我们喜欢称之为大的H，与Next.js等框架非常相似，提供许多相同的功能（服务器渲染、API路由等）。

最大的区别是，Big H 配备了与 Shopify 电子商务平台无缝集成的组件。 这个想法是，许多网站往往会超出他们一开始的模板，而氢能让它们保持在 Shopify 上，但提供只有使用 React 的“H4RDC0RE 工程师”才能提供的自定义体验（如何以 10 个字内触发平台 Devrel）🙃。

**这里有一些大灯光：**

*   建立在Vite之上——所以它的速度非常快（[kitty gawd](https://bytes.dev/archives/105)得分另一个W）
    
*   React Server Components (RSC) — 使它们可以成为游戏中最前沿、Buzzword 丰富的 FW （而且客户端上的 JS 也更少）
    
*   并行数据获取 — 嵌套路由是如此 2000&late。 氢气使用一些GraphQL魔法做同样的事情（平行数据获取）
    
*   支持开箱即用的顺风——这样你就可以通过3个简单的步骤成为一个ECOMM神：1）从TW购买一个完整的设计，2）将ISH直接扔到Big H中，3）利润
    
*   托管在氧气上——除了喜欢周期表隐喻外，Shopify 还希望通过自己的平台托管您的应用程序。 但如果你想[be a cowboy](https://www.youtube.com/shorts/feMwFuihX2o)，他们也在努力支持Vercel和Netlify
    

**底线：** 氢气可能是 2022 年建立电子商务网站的最佳方式，但它仍然不是出售像 [Allbirds](https://hydrogen.shopify.dev/case-studies/allbirds) 这样丑陋的东西的借口。

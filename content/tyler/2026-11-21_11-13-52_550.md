### Netlify 购买盖茨比

我为自己在本周早些时候的工作并开始写今天的故事而感到自豪，但后来_bam_——我不得不放弃整个事情，因为Netlify昨天决定[acquire Gatsby](https://www.netlify.com/press/netlify-acquires-gatsby-inc-to-accelerate-adoption-of-composable-web-architectures/)。 （这是我不拖延所得到的。）

但是关于我的事情就够了，让我们去看看场上的球员**他们在说什么：**

*   Netlify 对整合 Gatsby 的新 [Valhalla Content Hub](https://www.gatsbyjs.com/products/valhalla-content-hub/) 感到兴奋，它使企业更容易通过统一的 GraphQL API 跨多个源管理内容。 这非常适合 Netlify 自己的产品路线图，该产品路线图专注于构建和启用“可组合架构”。 我不确定这意味着什么，但这主要是因为我仍在试图弄清楚 JamStack 的含义。
    
*   Gatsby 也在喝那个可组合的建筑 Kool-Aid。 他们“兴奋”地将他们的云产品插入 Netlify 的平台，并将其覆盖范围扩展到 Gatsby 网站之外。 此次收购还将使团队能够将更多的精力重新集中在 Gatsby _Framework_ 而不是 Gatsby 业务上。
    

但是当这样的交易下降时，仔细看看**他们在说什么而不_\*技术上\*_说：**也很有帮助。

*   Netlify （可能）很高兴将 Gatsby Cloud 的企业和中端市场客户直接注入其脉络中。 即使它有点人为，这种即时的收入增长也可能有助于 Netlify，因为它希望在充满挑战的宏观环境中筹集更多的投资者资金。 Gatsby 还在其 OSS 皇冠上再为 Netlify 提供了一颗宝石，与 SolidJS 和 110 一起。
    
*   盖茨比（可能）开始没钱了，（可能）有点累了。 他们现在已经使用了 8 年，从过去的几个开始到 [drop off](https://2022.stateofjs.com/en-US/libraries/rendering-frameworks/)。 此次收购（可能）是一项全股票交易（这意味着 Gatsby 是用 Netlify 股票而不是现金支付的）——但它仍然应该帮助他们的投资者和团队主要是软着陆。
    

**底线：** 鉴于当前的气候，我们可能会在 2023 年看到 VC 支持的 OSS 初创公司的更多此类交易，但我们不能忽视 Gatsby 对 React 生态系统的巨大影响。 自从 Kyle Matthews (🫶) 在 2015 年的一周内首次将 V0 的框架合并在一起，Gatsby npm 包已被下载超过 8500 万次，超过 4,000 人在 `gatsbyjs/gatsby` 中进行了提交。

我确信该团队将在Netlify期间继续创新-但值得指出的是，Gatsby不仅仅是另一家筹集了几百万美元的Pan OSS初创公司，并决定在两年后结束，当时创始人决定他们没有 玩得开心。 Gatsby 是第一个基于 React 的突破性 OSS 项目之一，它开创了 React Frameworks 的早期阶段，它对 React 本身的早期发展起到了重要作用。 谢谢你所做的一切，旧运动。

1.  [Jotai just released v2](https://jotai.org/) 其“自下而上的方法”用于全局 React 状态管理。 不幸的是，有些人不喜欢自下而上的某些活动的方法——我在上一节热瑜伽课上学到了艰难的方式。
    
2.  Courier 构建了一个 [out of the box notification service](https://www.courier.com/?utm_campaign=ui.dev&utm_source=email&utm_medium=bytes-newsletter-2-2-quick-link&utm_content=content)，用于管理 Twilio、SendGrid、APNS、FCM 和 Slack 等多个提供商的模板和路由逻辑。 亲自查看，永远不要再构建通知服务。 \[赞助\]
    
3.  Dave Farley 发表了 40 分钟的演讲，题为 [Taking Back Software Engineering](https://www.youtube.com/watch?v=ephM9Nw9pAA)。 这是一个很棒的谈话，但我期待更多关于某个被低估的双关语 [emo band](https://www.youtube.com/watch?v=ap0mqwvf7H0)。
    
4.  去年，Riffle 研究项目团队在 [Building data-centric apps with a reactive relational database](https://riffle.systems/essays/prelude/) 上写了一篇有趣的文章，值得强调。 当我认为它们被称为 _Ruffle_ 研究项目时，我有点兴奋——但这只是因为那些酸奶油和切达干酪片占我童年核心记忆的 40% 左右。

6.  Andy Jiang 在 Deno 博客上写了一篇不错的文章，名为 [Back to the SSR](https://deno.com/blog/back-to-the-ssr)。 是的，这是披头士乐队歌曲的演奏，是的，封面图片是两个 Deno Dinos 打扮得像保罗·麦卡特尼和林戈·斯塔尔的可爱插图。 但文章本身也很好地分享了我们多年来呈现网站的演变。
    
7.  Adam Rackis 写了关于 [Caching Data in SvelteKit](https://css-tricks.com/caching-data-in-sveltekit/) 的文章。 我们是否确定_一些粗略的男性减肥补充剂公司还没有拥有“Sveltekit”的商标？
    
8.  [RedwoodJS v4](https://community.redwoodjs.com/t/redwood-v4-0-0-is-now-available/4538) 刚刚推出了新的 Auth API 和增强的 GraphQL 安全性。 我的消息来源告诉我，它还没有被 Netlify 收购——还没有。

在 CSS 中使用新的 `:has` 选择器，我们可以使用 General Sibling Selector 和 `:hover` 伪选择器在 CSS 的 3 行中和之后定位元素。

在行动中看到它 [here](https://codesandbox.io/s/bytes-has-selector-lg94f7?file=/src/styles.css)。

乌尔{
显示：弹性；
间隙：8px；
}
    
李{
显示：块；
光标：指针；
过渡：不透明度 0.3s 轻松进出；
}
    
li:has(~ li:hover),
李：hover ~ 李 {
不透明度：0.5；
}
    

向 [Stephanie Eckles](https://twitter.com/5t3ph) 大喊，他们写了一个 [fantastic article](https://www.smashingmagazine.com/2023/01/level-up-css-skills-has-selector/) 涵盖 `:has` 选择器。

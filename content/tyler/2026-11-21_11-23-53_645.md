[Apollo Client 3.0 finally gets released, and we’re over the moon about it](https://www.apollographql.com/docs/react/migrating/apollo-client-3-migration/#whats-new-in-30)
---------------------------------------- ----------------------------------------- ---------------------------------------- -----------------------------------------

![Apollo Client 3.0](https://bytes.dev/images/content/apollo.png)

这么久，2.0。 在另一面抓住你。

**休斯顿，我们有起飞……** 上周，阿波罗祝福我们获得了我们等待了 11 个月（和 55 个测试版）的主要版本。

对于外行来说，这里是 CTO Matt Debergalis 的 Quick [Apollo Client elevator pitch](https://thenewstack.io/apollo-client-3-for-graphql-leave-the-api-plumbing-behind/)：

“在许多方面，React 为 UI 所做的事情，这就是 Apollo 为您的 API 所做的：它为 IT 带来了结构，以便您可以专注于与您的应用程序和数据有关的细节，并将管道和复杂性留给整个系统。”

### 阿波罗客户端3.0的亮点

*   **Cache 规则我周围的一切：** Apollo Client 3.0 使用新的 `InMemoryCache` API 引入了多个新的缓存功能和策略。 其中包括类型和字段、垃圾收集、分页助手等的可配置缓存策略。 以一种或另一种方式，它们都有助于使 Apollo 客户端的缓存更加灵活和高性能。
    
*   **反应变量：** 如果您使用新的 `makeVar` 函数创建变量并稍后对其进行修改，Apollo Client 将自动更新依赖于该变量值的每个活动查询。 与新的缓存策略相结合的反应变量应该使本地状态管理变得不那么痛苦。
    
*   ** Squeaky Clean 入口点：** 您现在可以使用单个合并的 `@apollo/client` 包设置客户端。
    

### 底线

GraphQL 的 Value 支持一直致力于提供比标准 REST API 更高效和可定制的 API 体验。 但是由于通用 HTTP 缓存不适用于 GraphQL，因此需要像 Apollo 这样的库来使其适用于依赖缓存的更大、更复杂的应用程序。 这可能就是为什么 Apollo Client 说他们专注于“不仅仅是一个用于执行 GraphQL 操作的库，而是一个用于与客户端数据图进行交互的库”。

Apollo Client 3.0 中的新功能在该任务中加倍努力，并提供了有助于加速我们已经看到的 UI 反应性更强的趋势的工具。 考虑到 Apollo 客户占 GraphQL 所有使用的 95%（根据 CTO Matt 的说法），这是一件大事。

[Super Expressive turns Regex into a piece of cake](https://github.com/francisrstokes/super-expressive)
----------------------------------------------- ------------------------------------------------

![It's cake](https://bytes.dev/images/content/cake.png)

[Don’t trust anyone, not even yourself.](https://twitter.com/fueiho_boogie_/status/1282287264752689152)

**很多开发人员讨厌正则表达式……**但这只是因为它很糟糕。 您需要编写正则表达式的所有奇怪的、神秘的语言会让人觉得它们比它们的价值更麻烦（特别是如果您以后必须进行大量的代码审查）。 正因为如此，许多开发人员完全避免了正则表达式。

### 对救援有超强的表现力吗？

Super Expressive 是一个新的 JavaScript 库，可让您使用更自然的语言构建正则表达式，以便以编程方式和人类方式读取表达式。 两全其美，汉娜蒙大拿。

属性和方法用简单的英语描述了它们的功能，因此最初编写代码并在以后（理论上）修复错误更容易。 它也非常轻巧，没有任何额外的依赖项。

但每一种新技术（甚至像这样一个相对较小的库）都会带来权衡取舍。 在这种情况下，最大的一种可能是，是否值得花时间学习新的语法和术语，特别是如果其他开发人员还不熟悉它？

你可以 [check out some examples of Super Expressive here](https://github.com/francisrstokes/super-expressive#example) 看看它是否是你想开始玩的东西。 谁知道呢，也许它会帮助你克服你的正则表达式焦虑。

`reducer` 函数被调用了多少次？

常数数 = [2,4,6]
    
const reducer = (prev, current) => {
console.count('调用')
返回上一个 + 电流
}
    
nums.reduce(减速器)
    

**答案：两次**

如果未提供初始值，则数组中的第一个元素将用作初始值，并且将跳过 reducer 函数的第一次调用。

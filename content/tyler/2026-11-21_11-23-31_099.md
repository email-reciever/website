### 逻辑赋值运算符

为这些新操作员带上一个桶和一个拖把，`||=`、`&&=`和`??=`

/*
||= 返回其右侧
当它的左侧是虚假的时
    
&&= 返回其右侧
当它的左侧是真实的
    
??= 返回其右侧
当其左侧为空或未定义时。
*/
    
// 转动此代码
函数 isundefinedornull（输入）{
返回输入 === 空 || 输入 === 未定义
}
    
函数计算账单（选项）{
选项。名称 || （options.name = '来宾'）
options.greeting && (options.greeting = '欢迎回来！')
options.tax = isundefinedornull(options.tax)
? 0.05
: options.tax
options.discount = isundefinedornull(options.discount)
? 0
: options.discount
    
返回 // 数学
}
    
// 进入这段代码
函数计算账单（选项）{
options.name ||= '来宾'
options.greeting &&= '欢迎回来！'
options.tax ??= 0.05
options.discount ??= 0
    
返回 // 数学
}
    

### 数字分隔符

事实证明，人类不擅长阅读大数。 数字分隔符允许开发人员使用 `_` 在数字组之间创建可视化分离，从而使这一点变得更加容易。

const oldandbusted = 1000000000
常量新热度 = 1_000_000_000
    
oldandbusted === newHotness // true
    

逻辑赋值运算符和数字分隔符目前都是 ECMAScript 过程中的第 4 阶段——现在又回到了 ESLint。

### 路线图

公共路线图更令人兴奋，包含三个主要举措：

**1\。 lint 文件并行：** 就像听起来一样，这种新功能将允许您并行地对多个文件进行 lint，这应该会显着加快 linting 过程。 这也是 ESLint 粉丝一直在乞求耐心请求的东西 [over 5 years](https://github.com/eslint/eslint/issues/3565)。

**2\。 新的配置系统：** 团队已经在新配置上努力工作了几个月，旨在使 ESLint 整体更简单、更快。 他们还计划更轻松地创建插件和可共享的配置，以便您可以尝试使用新的配置，除了过度自以为是的 Airbnb 配置。

**3\。 参加 Google 的文档季节：** 这有点像去 OSS 文档夏令营，但一些 ESLint 维护者将学习如何彻底修改和简化文档，以便它们更有用。

### 为什么现在发布这个路线图？

2个词：金钱谈话。

微软、Salesforce 和其他一些大牌公司最近向 ESLint 捐赠了数万美元。 这使 ESLint 团队能够为他们的所有工作支付一些维护人员（兼职），并开始从事这些更大的长期项目。 万岁资本主义！……呃，我的意思是支持开源！

NativeScript 在其核心上努力工作

**Man 的一小步……** NativeScript 表示，他们上周发布了 v7.0 的“重大进步”，其中一些重要的新功能侧重于改进框架的核心。

**ICYMI** NativeScript 是一个框架，于 2015 年首次发布，用于构建“真正的本机”iOS 和 Android 应用程序，使用 JavaScript 和其他前端技术，如 Angular、Vue 和 TypeScript。

**感觉您以前听说过这种推销？** 这可能是因为您有。 但与 Ionic、Cordova 或 Phone Gap (LOL) 不同，NativeScript 使用真正的本机组件而不是 WebView 来做到这一点。

现在让我们跳入 **V7 中的新增功能：**

*   ** ES2017 及更高版本的新构建定位** 应该可以实现更快、更高效的代码，从而使您能够利用所有最新和最大的 ES 功能。
    
*   **V8 iOS Engine** 表示Android和iOS现在都在V8上运行，这应该使维护两个运行时间变得更容易。 （永远再见，JavaScriptCore。）
    
*   **新的 `@NativeClass()` 装饰器** 用于 TypeScript/JavaScript 类的，从本机 iOS 和 Android 类继承。
    
*   **`nativescript.config.ts`**是一个新的强类型NativeScript配置模块，它是自我记录的
    

此更新还引入了一个新的 Monorepo 结构，它可以使更多的开发人员更容易为项目和测试驱动器 NativeScript 做出一些新的演示应用程序。

### 底线

（相比之下）NativeScript 在过去的 5 年里没有获得大量的主流采用，但它确实有一个非常投入的社区（不像 Rust 狂热者那么激烈，但仍然很稳定）。 通过与现代 JS 标准保持一致并引入其他一些核心改进，此版本应该使 NativeScript 成为所有移动开发人员更具吸引力的选择。

发现错误 - 答案
----------------------

当我们调用 `toUpperCase` 时，我们假设我们正在修改传递给函数的字符串。 但是，由于字符串是 [primitive values](https://ui.dev/primitive-vs-reference-values-in-javascript)，这意味着它们是不可变的，一旦创建就无法修改。 我们需要在将第一个字符大写后返回一个新字符串，而不是尝试直接修改字符串。

const Capitalize = ([firstletter, ...restofword]) => {
返回 FirstLetter.ToUpperCase() + restOfWord.join('')
}
    

欲了解更多信息，请访问 [How to capitalize the first letter of a string in JavaScript](https://ui.dev/capitalize-first-letter-of-string-javascript)

[MobX 6 Released](https://github.com/mobxjs/mobx/blob/mobx6/CHANGELOG.md)
---------------------------------- -----------------------------------

![mobx killing decorators](https://bytes.dev/images/content/mobx-decorators.jpg)

@装饰器是 sus

**已经 5.5 年了……** 世界对马尼托瓦克县着迷，我们都在争论一件衣服是什么颜色，第一次承诺是对 Mobx 的。 2015 年情况大不相同，但上周的 V6 版本表明，MobX 仍在坚持其“简单、可扩展的状态管理”的原始愿景。

[Michel Weststrate](https://twitter.com/mweststrate)（暴民父亲本人）说，这个版本并没有包含新功能，而是“巩固了 JavaScript 中当前状态”。

以下是**主要亮点：**

*   **👋 Bye Bye Decorators (Kind of):** Mobx 是第一个大型 JavaScript 库（我知道请不要给我发邮件），因为它的公共 API 而使用装饰器，现在它正在唱 Tom Petty 并改变主意。 也就是说，它们仍然受到支持，但使用完全不同的实现，与当前的 TypeScript 和 Babel 实现完全不同。 这可以说是 V6 中最大的变化，因为历史上需要使用装饰器已经关闭了许多开发人员。
    
*   **`makeAutoObservable`:** 这个新的便利实用程序通过为类中的每个成员自动选择最佳注释来自动化注释过程。 这应该特别有用，因为这些注释不再与它们正在装饰的字段相邻（见上文）。
    
*   ** 支持更多浏览器：** Mobx 5 所需的代理支持，这使得它不适合 IE 和 React Native。 Mobx 6 仍然可以，但如果您需要支持旧引擎，您可以选择退出它。
    

### 底线

V6 似乎是为了让 Mobx 更容易为以前没有使用过它的开发人员提供，同时将其长期用户喜爱的功能加倍。 它是每个人最喜欢的状态管理解决方案（\*\*除了组件状态、上下文、Redux 和 Recoil）的可靠版本。

\*\* 这是个笑话，Mobx 很棒。

[Elsa - A New Runtime with a Modern Twist](https://github.com/elsaland/elsa)
------------------------------------ ------------------------------------

![Ice King](https://bytes.dev/images/content/iceking.jpg)

真正的艾尔莎之一

**你有一个运行时间！ 和 _you_ 得到一个运行时！** 这些新运行时在 2020 年随处可见。ELSA 是最新的运行时——它是上周发布的，它是在 Go 中编写的 JavaScript 和 TypeScript 的“最小、快速和安全”的运行时。 _我们仍在等待臃肿、缓慢和不安全的运行时发布。 还没有消息。_

以下是将 Elsa 与 **Anagrams™**（又名 Node 和 Deno）区分开来的三个主要因素：

**1\。 不同的引擎：** 代替 V8（JS 引擎，而不是 Juice），Elsa 使用 QuickJS 和 Esbuild。 QuickJS 是一款小型且可嵌入的引擎，它声称比 V8 有更好的启动时间，尽管它几乎没有功能齐全。 Esbuild 是一个极快的构建器和迷你器，也是用 Go 编写的，由 Figma 的首席技术官 Evan Wallace 创建。

这种 QuickJS 和 ESBuild 的组合可能会使 ELSA 成为 CLI 应用程序的有吸引力的选择，即使这对于需要更多运行时功能的其他项目来说不是最佳选择。

**2\。 最小但可扩展：** ELSA 团队的目标是创建一个可以“满足基本项目的最低要求”的运行时，但仍然可以通过插件进行扩展。 一些当前未包含但可以通过扩展添加的功能，包括用于格式化、linting 和分析的工具。

**3\。 不是由 Ryan Dahl 建造的：** 至少我们不认为它是。 但事实证明，这 3 位 ELSA 创作者也是 Deno 的贡献者，所以谁知道呢。

其他值得注意的 ELSA 功能包括基于 URL 的导入、模块缓存以及轻松将脚本捆绑到单个文件中的功能。 退房 [the full comparison of Elsa, Deno, and Node.js for more.](https://github.com/elsaland/elsa/blob/master/COMPARISON.md)

js（反应）测验 - 答案
-------------------------

为了得到答案，让我们从 React 的绝对基础开始。 什么是反应？ 它是一个用于构建用户界面的库。 无论 React 或 React 生态系统看起来多么复杂，这都是 React 的核心——构建 UI。 考虑到这一点，我们得出了第一个定义，即“元素”。 简单地说，一个 React 元素描述了你想在屏幕上看到的内容。 不简单地说，React 元素是 DOM 节点的对象表示。

为了创建一个 React 元素，我们可以使用 React 的 `createElement` 方法。

常量元素 = react.createElement(
'div'，
{ID：'登录-BTN'}，
'登录'
)
    

当它渲染到DOM（使用`ReactDOM.render`）时，我们将有一个新的DOM节点，看起来像这样，

<div id='login-btn'>登录</div>
    

我们更接近，但我们还需要回答这个问题的更多知识，这就是 JSX“在幕后”的工作方式。

Web 浏览器不了解 JSX，但是，它们了解 JavaScript™。 在编译过程中（通常使用 Babel），JSX 被转换为普通的旧 JavaScript（或者更具体地说，我们刚刚了解的 `React.createElement` 调用）。

// jsx
功能按钮 ({ addfriend }) {
返回（
<button onClick={addFriend}>添加朋友</button>
)
}
    
函数用户 ({ name, addfriend }) {
返回（
        <div>
<p>{名称}</p>
          <Button addFriend={addFriend}/>
        </div>
)
}
    
// 编译后
功能按钮 ({ addfriend }) {
返回 react.createElement(
“按钮”，
{ OnClick: AddFriend },
“添加朋友”
)
}
    
函数 user({ name, addfriend }) {
返回 react.createElement(
“分”，
空，
react.createElement(
“P”，
空，
名称
)，
react.createElement(button, { addfriend })
)
}
    

那么最后，我们怎么称呼这个，`<Icon/>`？ 我们称之为“创建一个元素”，因为在 JSX 编译后，这正是正在发生的事情。

有关该主题的更深入的帖子，请访问 [React Elements vs React Components](https://ui.dev/react-elements-vs-react-components)

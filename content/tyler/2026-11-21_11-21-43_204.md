V8 发布 V9
---------------

![Daphne](https://bytes.dev/images/content/daphne.png)

速度的新符号

**V8（引擎，而不是果汁）** 上周发布了 V9.0，有一些显着的改进。 在等待与 Chrome 90 协调发布时，它仍处于测试阶段，但如果您感到辛辣，您今天可以试一试。

**我们是如何到达这里的？** V8 是 Google 的开源 JavaScript 和 WebAssembly 引擎，由 Lars Bak 于 2008 年创建——他还发明了 Dart（以及一堆其他东西）。

据推测，Lars 喜欢快车，所有这些都可能由 V8 发动机提供动力。

虽然是 2008 年的一个好名字，但 V8 并没有像以前那样具有相同的魅力。 **这就是为什么我们要将 V8 的名称更改为 [Daphne](https://twitter.com/JoeBriggsEsq/status/1372348676723511301) — 2021 年的速度和力量的终极符号**。

如果您不使用它来促进您想在世界上看到的变化，那么拥有大型新闻稿有什么用？

**Daphne 9.0 的新功能：**

*   **[New match indices for regex](https://v8.dev/features/regexp-match-indices)** — 对于阅读此 regex 的 4 个人来说 - 正则表达式的新 `indices` 数组允许您存储每个匹配的捕获组的开始和结束位置。
    
*   **[更快`super`属性访问](https://v8.dev/blog/fast-super)** — `super` 关键字是访问对象父级属性和函数的好方法，但它总是很慢，因为它是通过运行时调用实现的…… _until now._ v8v9 现在使用 内联缓存系统，这使得 `super` 属性访问速度更快。
    
*   **[Faster JS-to-Wasm Calls](https://docs.google.com/document/d/1mXxYnYN77tK-R1JOVo6tFG3jNpMzfueQN1Zp5h3r9aM/edit#heading=h.z7cfruiwxfup)** — 当 JavaScript 调用导出的 WebAssembly 函数时，调用必须通过 JS-to-Wasm 包装器以使其正常工作。 不出所料，这使得这些呼叫慢了很多。 V9.0 通过内联调用站点上的 JS-to-WASM 包装器代码来缓解此问题。

流血的边缘——克里奥
-------------------------

![Bobby](https://bytes.dev/images/content/bobby.png)

给我看网络的最前沿🔮

**我们今天强调**一个_非常_新项目，所以系好安全带，穿上你的比尔Nye领结。

**[Clio](https://clio-lang.org/)** 是一种新的函数式编程语言，它针对分布式系统并编译为 JavaScript。

我们可以将 Clio 分成三个主要部分：

*   通过使用**函数编程**，CLIO 开发人员比非函数式开发人员更聪明、更好看，并且通常更正确。
    
*   **分布式系统**采用一台计算机完成的计算任务，并将它们分散到许多计算机上，以便它们可以更快地执行并且不依赖任何单个计算单元。 Clio 使用“默认情况下的多个 CPU 和 CPU 内核（并行）”，并具有非常简洁的语法——因此您可以像正常那样编写代码，并且它将以分布式/并行方式自动执行。
    
*   **编译为 JavaScript** 使 Clio “快速、易于移植、易于扩展”。 它还允许 Clio 利用 JavaScript 的工具和库生态系统，在 JavaScript 可以运行的任何地方运行。
    

查看其创建者 [Pouya Eghbali](https://twitter.com/pouya_eghbali) 上关于 [How to Make a Reactive To-do App With Clio](https://medium.com/@pouyae/making-a-reactive-to-do-app-with-clio-ac7bf8b93959) 的本教程。

### 不要被起诉

如果您觉得_clio_这个名字听起来很熟悉，那是因为它也是一堆其他东西的名称，包括雷诺最畅销的超小型车和为律师事务所生产软件的SaaS公司。

所以，我们会告诉 Clio 团队，当我们开始写字节时，我们每周都会告诉自己：_玩得开心，但尽量不要被起诉。_

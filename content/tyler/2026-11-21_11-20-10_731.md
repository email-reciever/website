nuxtjs 3 版本
-----------------

NuxTJS刚刚推出了V3的公开测试版——这是他们自2020年7月以来一直在开发的一个拥挤的版本。

**等等，WTF 是 nuxtjs？** 它基本上是 _next_js，但是对于名称中有“u”（不是 jQuery）的 JavaScript 框架来说。 N_U_XT 是一个渐进的元框架，通过提供基于文件的路由、SSR 和 SSG 等功能，可以更轻松地构建高质量、高性能的 Vue 应用程序。

Nuxt 的创作者最近还推出了 NuxtLabs 公司，并在 5 月份筹集了 200 万美元，允许他们购买比 Vercel 多一个三角形的三角形。 _你的举动，吉列尔莫。

**Nuxt 3 中有什么新功能？** 有 [a lot](https://www.youtube.com/watch?v=yzEsXBkWwYg)。 我们不能涵盖所有内容，但这里是亮点：

*   ** 新服务器引擎** — 它的代号为“Nitro”（Sick Bro），它形成了 Nuxt 的 [brand new foundation](https://v3.nuxtjs.org/concepts/server-engine/)，它允许添加其他很酷的功能——包括对 Node、Deno、Service Workers、Browser 和 Node、Deno、Service Workers、浏览器和 更多。 它是第一个跨 [all major cloud hosting providers](https://youtu.be/yzEsXBkWwYg?t=754) 可移植的 JavaScript 应用程序服务器，它使 Nuxt 本身更小、更快。
    
*   **suspense** — 您可以在导航之前或之后在任何组件中获取数据（类似于 React 18 中的 Suspense 功能）。
    
*   ** 支持最新和最伟大的技术** — Nuxt 3 现在支持开箱即用的 TypeScript 和 ESM，以及对 Vue 3、Webpack 5 和 [Vite](https://vitejs.dev/) 的新支持——现在可以为 Nuxt 应用程序更换热模块。
    

无论如何，Nuxt 3 看起来像一个游戏规则改变者，它应该让使用 Vue 构建酷炫的东西比以往任何时候都更容易、更流畅。

哦，Parcel _also_ 刚刚发布了期待已久的 OG no-config bundler [2.0 release](https://parceljs.org/blog/v2/)。

**我们是如何到达这里的：** Parcel 于 2017 年出现，以响应 Webpack 带来的配置地狱。 您可以将 Parcel 指向您的 HTML、JavaScript、CoffeeScript (#tbt)、Sass 或任何您喜欢的奇怪东西（没有判断力），它会将它们全部捆绑到一个整洁的小包中。 Parcel 不会_expect_您自己配置任何内容，但如果您需要在构建过程中添加一些特殊行为，它确实支持插件。

2.0 保持与以前版本相同的广泛文件支持和无配置态度，同时引入了一堆 _bundle_ 新功能：

*   改进的插件系统，以防您需要
*   JavaScript和CSS模块的自动代码分割和树抖动（保持文件精简）
*   用于 React 和 Vue 的 Blazing-Hot Reloading 和 Fast-Refresh
*   除了Web 应用程序之外，还支持构建库
*   内置图像处理

它还以优异的颜色通过[Bundler Tooling Tests](https://bundlers.tooling.report/#overview)（仍在等待捆绑图灵测试中的结果）。

在速度方面，Parcel 2 的新型 Rust 驱动编译器使其比 V1 快得多，尽管它仍然无法与其 ESBuild 的荒谬速度相匹配（正如 Evan Wallace 在本 A 级中所指出的那样 [humble brag](https://twitter.com/evanwallace/status/1448714353386086405)。 esbuild，包裹_does_支持插件。

**为什么使用它？**如果您想要一个 _just works_ 并且速度快的捆绑器，则 Parcel 是一个不错的选择，而无需您使用一堆配置。 React, Vue, _elm_…它甚至可以让你导入 GLSL 文件，这样你就可以用你令人敬畏的 WebGL 技能给你的迷恋留下深刻印象。 Parcel 以前是一个不错的选择，但这个新的更新使它成为 Web 应用程序捆绑的更引人注目的选择。

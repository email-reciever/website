### 向 Sveltekitty 1.0 问好

你能听到吗？ 这是所有 Svelties 都被新发现的力量喝醉的声音——因为 Seveltekit 1.0 在它的所有荣耀中都是 [finally here](https://svelte.dev/blog/announcing-sveltekit-1.0)。

对于初学者来说，Sveltekit 是一个元框架，通过附加功能扩展了 Svelte。 与 React 和 Nuxt for Vue 一样，Sveltekit 可以帮助您避免使用一些**酷功能**的样板，从而更轻松地构建可扩展的 svelte 应用程序：

*   服务器端渲染
*   简单的静态站点生成
*   基于目录的路由
*   内置代码拆分
*   对热模块重新加载和打字稿的开箱支持，感谢Vite

好的，这是一个很酷的功能列表，但是与其他框架 + MetaFramework 组合相比，Svelte + Sveltekit 的独特之处是什么？

*   ** 多页应用的性能更好：** 在初始服务器渲染页面加载后，sveltekit 默认为客户端导航。 这为您提供了更快的页面过渡和跨页面持续存在的状态。
    
*   **像你在乐队营地的道德一样灵活：** Sveltekit 不会强迫你做出全有或全无的渲染决定。 您可以轻松地 [switch between](https://www.youtube.com/watch?v=860d8usGC0o) 预渲染页面并使用单行代码动态呈现数据。 这为您提供了大量的粒度和出色的性能。
    
*   ** 为边缘打造：** Svelte 得到了 Vercel 及其 Edgelords 团队的大力支持。 Sveltekit 支持 Vercel 的新边缘功能，允许它以与从 CDN 提供静态文件的速度相同的速度提供动态渲染的页面。
    

**底线：** Svelte 多年来一直受到开发人员的喜爱，这要归功于其出色的 DX 和性能。 通过明智地从 Next.js 和 Remix 等框架中导入最佳创意，Sveltekit 1.0 使开发人员比以往任何时候都更容易开始构建 Svelte 应用程序。

这是否足以帮助 Svelte 从 JS 框架领域的“酷独立乐队”转变为“主流流行巨星”？ 继续关注。

本周趋势
------------------

![jotai vs mobx vs recoil vs zustand](https://bytes.dev/images/content/state-management-libs.jpg)

React 的下一代状态管理库 – [npmtrends.com](https://npmtrends.com/jotai-vs-mobx-vs-recoil-vs-zustand) 的数据

自从赢得 2015 年的大规模战争以来，Redux 一直是 React 的事实上的国家管理库。 但就像某个 80 年代的想成为说唱歌手的男孩乐队一样，我们开始看到一些 [New Kids on the Block](https://www.youtube.com/watch?v=ay6GjmiJTPM) 出现。 在我们见到新手之前，让我们简要谈谈是什么推动了这一新的国家管理解决方案。

使用 React 18，管理 SSR、并发和优化渲染与以前完全不同。 像 Redux 这样的工具在掌握这些新功能方面做得很好，但它们并没有为这个勇敢的新世界而明确设计——这为我们的新面孔创造了一个机会：

*   **Mobx:** 许多开发人员更喜欢 Mobx 的“反应式”风格，其样板更少，对渲染的控制更精细。 这是这些下一代工具中的第一个出现，并且真正弥合了几代人之间的差距。
    
*   **recoil:** Facebook 的实验库不是 React 的正式一部分，而是在内部使用。 这很像 Redux、React 和 Mobx 都有一个孩子。
    
*   **JOTAI：** 另一个反应与 Mobx 相似的反应框架，由 [pmdrs](https://github.com/pmndrs) 创建。 由于出色的异步和 TypeScript 支持，它最近增长了很多。
    
*   **zustand:** 它声称是解决“僵尸子问题、反应并发性和混合渲染器之间的上下文丢失”等问题的唯一框架。 它也是由 PMDRS 创建的，并具有与 React 没有直接联系的“外部存储”。
    

**外卖：** 就像马克马克一样，Zustand 看起来像是从街区的新孩子毕业成为一个成熟的主流超级巨星的最安全的选择。

3.  Jeremy Wagner 和 Philip Walton 写了如何通过 [Optimizing Interaction to Next Paint](https://web.dev/optimize-inp/) 更快地提高用户交互。 这有点像“绘画的乐趣”——但不是鲍勃·罗斯，而是两位谷歌工程师向您展示了如何解决“快乐的小（性能）事故”。
    
4.  Miguel Piedrafita 创建了 [`plz-cli`](https://github.com/m1guelpf/plz-cli) 是“您的终端的副驾驶”。 这意味着我距离实际使用 `grep` 只有一个 OpenAI 令牌。
    
5.  Supabase 推出了一些 [updates to its Storage API](https://supabase.com/blog/storage-image-resizing-smart-cdn)，其中包含图像调整大小、网络挂钩和“智能 CDN”。 看起来他们必须将标语更新为“Firebase 和 Cloudinary 的开源替代方案”。
    
6.  [Lit 2.5 was released](https://github.com/lit/lit/commit/b152db291932aa25356543395251a9b42e12292d) 上周对 SSR、上下文、虚拟化列表甚至 React _(gasp)_ 的支持更好。 我想知道下一个版本是否会提供有关如何以冷漠的面孔非出乎意地说[“lit”](https://www.youtube.com/watch?v=4SqTTwVQwgc&t=21s)的支持。
    
7.  Eric Wendell 为 Node 的测试运行程序添加了 `mocks`](https://github.com/nodejs/node/pull/45608) 的 [Native Support for `mocks`](Notive Support) （明年在 Node 20 中可用）。 我喜欢能够摆脱另一个测试库（`sinon`），但我有点失望，当你的测试失败时，它没有烤掉你的 TF。
    
8.  Kirk Elliott Created [Kwyjibo](https://github.com/dmvjs/kwyjibo) — JavaScript 支持的 DJ 技术，利用 Web 音频 API，并以 1990 年 _Simpsons_ 剧集的虚构词命名。 我不得不读两遍这句话以确保我不高。

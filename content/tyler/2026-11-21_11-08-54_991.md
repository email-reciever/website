### 捆绑还是不捆绑？

上周，DHH 从赛车 F1 赛车中休息一下，沉迷于他最喜欢的其他爱好——让 JavaScript 开发人员生气。

他的最新目标？ 捆绑。

他在[Rails World Conf](https://youtu.be/iqXjGiQ_D-A?t=1656)的舞台上说：“最先进的方式不再是寻找更复杂的方式来构建JavaScript或CSS，这根本不是为了构建……并避免捆绑。”

#TeamNoBundle 的队长说，这就是为什么：

*   从历史上看，捆绑有助于提高瀑布、代码分割等的性能——但它通常会增加复杂性并增加构建时间。
    
*   由于导入地图和HTTP2等现代浏览器创新，我们可以按原样发送我们的JavaScript文件，而不必担心使用Webpack、Esbuild或Bun。
    
*   这仅在您使用的 JavaScript 不多时才有效，但不用担心，因为像 DHH 的 Hotwire 这样的框架可以方便地让您默认提供更多的 HTML 和更少的 JS。
    

这一切听起来都很棒……在会议舞台上。 但正如许多开发人员所指出的那样，这并不是那么简单：

*   即使使用 HTTP2 和导入地图，仍然可以有显着的 [performance implications](https://x.com/cramforce/status/1712265070213050390)，并发限制，增加的每个请求开销等等。
    
*   编译器（即 TypeScript）仍然为大型 JS 应用程序提供了许多好处，例如类型安全、代码拆分和其他性能优化。
    
*   不是每个人都试图尽可能少地编写 JavaScript。 对于较大的 JS 项目，放弃捆绑器可能会为许多潜在的不利因素提供很少的好处。
    

**底线：** 公开演讲的规则 #1 是了解您的听众。 因此，请记住这是在 Rails 会议上进行的，大多数人可能希望编写尽可能少的 JavaScript，因为他们想编写更多的 Ruby 代码。

在这种情况下，#TeamNoBundle 可能效果很好。 如果你不同意，只要知道 DHH 是愤怒驱动的营销的🐐，所以你的愤怒只会让他变得更强大。

记录什么？

常量数组 = 新数组(3).fill([])
数组[0].push("字节")
console.log(array) // [ ["bytes"], ["bytes"], ["bytes"] ]
    

理解这一点的关键是知道 JavaScript 中的数组是 [reference values](https://ui.dev/primitive-vs-reference-values-in-javascript)。

当你调用 `.fill([])` 时，你真正在做的是用三个 _references_ 将数组“填充”到同一个数组中。 你可以这样想。

常量引用 = []
常量数组 = 新数组(3).fill(参考)
    

现在，`array` 有三个元素，它们都引用了相同的 `reference` 数组。 因此，如果您将一个项目添加到三个元素中的任何一个，因为它们都指向同一个数组，那么它是 _as if_ 向所有元素添加一个项目。

要获得相同的功能而没有参照怪异，您可以使用 `Array.from`。

常量数组 = array.from({ 长度：3 }, () => []);
数组[0].push("字节"); // [ ["字节"], [], [] ]

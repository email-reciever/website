### 德诺的困境

在外面，Deno 的一切都很顺利。 他们每月有超过 25 万活跃用户，他们从一些大牌 VC 筹集了 2600 万美元，而且他们提供的新版本比我在 Prune Juice 清洁后更有规律。

但在内心深处，有一场战斗在迪诺的灵魂上肆虐。 好吧，这可能有点戏剧化，但这个部门全都源于一个问题：**Deno 应该在多大程度上拥抱它的恶魔（节点和 npm）？**

大多数迪诺顽固分子可能会说，“一点也不”。 这是有道理的，考虑到 Deno 最初的宣传是利用 Web 标准 API（而不是 Node 的非标准 API）并在默认情况下是安全的（与 npm 生态系统不同）。

但几年后，Deno 团队发现网络效应仍然不败——如果不支持 npm 包和节点模块，大多数主流开发人员根本不会使用 Deno。 因此，为了扩展 Deno 帐篷，该团队选择回到其根源并拥抱其具有合意的 Sister Runtime。

以下是如何发生的快速时间表：

*   ** 2022 年 8 月：** DeNo 宣布了它正在开发 Node 和 NPM 兼容性的重大消息。 他们承认并非所有 Deno 用户都会对此感到高兴，但分享说他们认为这是整个运行时的最佳选择。
    
*   **2022 年 11 月：** Deno 宣布稳定的 NPM 兼容性，允许用户将超过 130 万个 NPM 模块导入 Deno。 并在一月份发布了对内置节点模块的支持。 他们声称以更安全的方式同时做到这两点，并且仍然优先考虑 ES 模块和 Web 标准 API。
    
*   **上周：** Deno 发布 [v1.31](https://deno.com/blog/v1.31) 支持 `package.json`。 这允许 Deno 在您的代码库中自动发现 `package.json` 并使用它来安装和解决依赖关系。 它还可以更轻松地将现有节点项目迁移到 Deno。 许多铁杆 Deno Stans 是…… [not thrilled](https://twitter.com/AashutoshRathi/status/1629149045062238208?s=20) 关于这一点。
    

**底线：**当你喜欢的东西做出权衡以增加其主流吸引力时，总是会有成长的痛苦——无论是 OSS 还是 2000 年初的绿日。 Deno 的重大变化会因采用大幅提升而得到回报吗？ 继续关注。

2.  想要符合 SOC 2 和 HIPAA 等安全框架吗？ 通常需要几个月的时间，但是 [Secureframe automated the whole process](https://secureframe.com/request-demo?utm_source=partner&utm_medium=newsletter&utm_campaign=030223-bytes-newsletter) 让您快速无痛。 _Yay，软件。_ \[赞助\]
    
3.  [Remix v1.14](https://github.com/remix-run/remix/releases/tag/remix%401.14.0) 刚刚推出了热模块替换和热数据重新验证（他们使用的新术语用于数据加载器的 HMR）。
    
4.  Emil Widlund Created [nodl](https://github.com/emilwidlund/nodl)，一个用于创建可视节点图的新框架——而不是一种新的意大利面。
    
5.  John Dewyze 写了关于他的团队在 Shopify 关注的 [The 25% Rule for Tackling Technical Debt](https://shopify.engineering/technical-debt-25-percent-rule)。 这就像谷歌的 20% 规则，但你不是在做一些有趣的事情，而是重构了令人讨厌的旧代码。
    
6.  TLDRAW 刚刚发布了 [Signia](https://tldraw.substack.com/p/introducing-signia)，一个用于 TypeScript 的可扩展信号库。 这一切都让我想起了我的生活教练一次告诉我的事情。 如果您正在社交并且您没有话要说，请记住“STST”——信号、类型安全或顺风。 永远不会失败。
    
7.  Chrome 团队的 Jhey Tompkins 写了关于如何做到的 [Tether elements to each other with CSS anchor positioning](https://developer.chrome.com/blog/tether-elements-to-each-other-with-css-anchor-positioning/)。
    
8.  安迪·江在迪诺博客上写了一篇名为[You Don’t Need a Build Step](https://deno.com/blog/you-dont-need-a-build-step)的文章。 好的，但是我什么时候有时间为 _mixed signals_ 试播集编写这个脚本？

### 奇点的现场音符

在前五天达到 100 万用户之后，ChatGPT 显然是 JavaScript-land（和世界其他地区）目前最大的故事。

可悲的是，我们的自尊心没有新造的 [AI Experts™️](https://twitter.com/netcapgirl/status/1600221793033207808)（FKA 加密专家）那么大——所以我们没有写一篇关于“人工智能肯定会改变科技行业的 10 种方式的半生不熟的思考文章 🧵👇。” 但是，随着奇点的临近，这里有一个快速回顾，可以帮助您至少比您的同事更了解情况。

**快速背景：** 像 GitHub Copilot 一样，ChatGPT 是在 OpenAI 的 Codex 上训练的，它由数十亿行开源代码组成。 不是每个人都很高兴他们的 OSS 工作被用来训练一个可能不像我们所有人想象的那样“自由和开放”的 AI 模型，但值得注意的是，OpenAI 可能 [isn’t](https://www.fsf.org/licensing/copilot/copyright-implications-of-the-use-of-code-repositories-to-train-a-machine-learning-model) 违反了任何版权法（正如我们所写的 [last summer](https://bytes.dev/archives/109)）。

**好吧，这很酷，但它能做什么？** 以下是我们见过的一些最酷的开发人员在文本框中做的事情：

*   [Debug code](https://twitter.com/amasad/status/1598042665375105024) 通过识别错误、修复它们并解释修复的原因。 很酷，但如果我们发现您在 _spot the bug_ 部分上作弊，您将立即被送到校长办公室。
    
*   乔纳斯·德格雷夫 [built a virtual machine directly inside ChatGPT](https://www.engraved.blog/building-a-virtual-machine-inside/)。 （VMware 在 Shambles RN 中。）
    
*   Víctor Escobar 将其引导至 [fully generate a new repo](https://github.com/vrescobar/chatGPT-python-elm) 进行实验性新编程语言。
    
*   Gabe Ragland 立即使用它 [build a 3-column footer with Tailwind](https://twitter.com/gabe_ragland/status/1598068207994429441)，然后在 React 中创建了相同页脚的完全响应移动版本。
    

**AI 会接受我的工作吗？** 我不知道，更重要的是，我有一条禁止在工作周内娱乐生存恐惧的规则。

但我很喜欢 Jason Werner（GitHub 的前 CTO）[perspective](https://twitter.com/jasoncwarner/status/1600543582703603713?s=20&t=Qngo06fJ8sqIgyCJejLsew)，当他推测 AI 将取代开发人员的工作时，就像 C 和 JavaScript 等语言“取代”了早期开发人员编写汇编代码的工作一样。 他们并没有真正取代这些开发人员，他们只是引入了另一层抽象和自动化，这从根本上改变了他们编程和与计算机交互的方式。

**底线：** 归根结底，如果手写 JavaScript 变得一文不值，我们将把这份时事通讯转为关于运动的内容。 说到昨晚有没有人抓到 CS 得到 CS 的儿子？

本周趋势
------------------

#### 由 \[Sponsored by [Datadog](http://datadoghq.com/bytes) 赞助

_他们写了这篇[Continuous Testing Brief](http://datadoghq.com/bytes)来教你如何以快速、可靠和_\*无代码\*_的方式测试你的应用程序。 这令人印象深刻。_

![Cypress vs playwrite vs selenium vs webdriverio](https://bytes.dev/images/content/e2e-testing-trend.jpg)

E2E 测试领导者 – [npmtrends.com](https://npmtrends.com/cypress-vs-playwright-vs-selenium-webdriver-vs-webdriverio) 的数据

过去几年的增长趋势之一是端到端测试的兴起。 随着 JS 生态系统完全接受 CICD，这些 E2E 框架非常适合构建管道，在代码发布之前自动测试代码。 今天最大的玩家是 Selenium (The OG)、WebDriverio、Cypress 和 Playwright 🎭。 但除了人气，哪个框架对您的应用最有意义？

*   **Developer Experience:** 你编写、调试和运行测试的速度都是关键的 DX 指标。 赛普拉斯在这里比硒要好得多，所以他们去月球也就不足为奇了。 也就是说，Playwright 的 VSCode 插件和语言支持使其成为竞争者。 所以这是剧作家和柏树之间的联系。
    
*   **兼容性：** 由于大多数 E2E 框架都使用无头浏览器，因此它们会遇到与现实世界中相同的跨浏览器怪癖。 Playwright 是唯一支持所有主要浏览器 OTB 的解决方案，因此它在这里得到了 W。
    
*   **可靠性：** 大多数测试解决方案都设计用于运行同步进程，让开发人员编写手动 `wait` 命令，以便页面完成加载。 这会导致测试（无缘无故的东西失败）。 Playwright 被设计为默认为异步的，这消除了很多这种不稳定。 另一个配音🎭。
    
*   **速度和成本：** E2E 测试最糟糕的部分是它们永远需要。 快速完成所有测试的方法是并行进行所有测试，但不幸的是，您通常必须为此支付额外费用（Cypress、WDIO 和 Selenium 为此提供了付费服务。Playwright 允许您自己滚动）。 让我们称之为平局。
    

**外卖：** 令人惊讶的是，最受欢迎的图书馆不一定是最好的。 拥有“异步优势”，Playwright 似乎就像获胜者前进（直到有人发布 ChatGPT 集成，这样您的产品经理就可以开始编写自己该死的测试）。

很酷的位
----------

1.  [State of CSS Survey](https://2022.stateofcss.com/en-US/) 刚刚出来——老实说，我们有点惊讶你们中有 65% 的人将 `margin-left` 投票选为“2022 年最性感的 CSS 属性”。 但我想我可以看到它。 提醒 如果您感到无聊，您可以在当前 [State of JS survey](https://stateofjs.com/en-us/) 的“资源”部分投票选出字节。
    
2.  Rahul Gupta 创造了 [The Ultimate Guide for RegEx](https://www.thecodingdev.com/2022/11/the-ultimate-guide-for-regular.html) 并真正将“没有痛苦，没有收获”这个词提升到了一个全新的水平。
    
3.  [Nextra just released v2](https://nextra.site/) 用于创建基于 next.js 的文档站点和内容站点的框架。 这听起来也像是一个虚构的邪恶巨型公司的名字，它在每部间谍电影中都在秘密地试图占领世界。
    
4.  [Papanasi](https://papanasi.js.org/) 是一个新的跨框架 UI 库，它基于有丝分裂库，与 _all_ 框架（甚至是 Web 组件）一起使用。 直到 Papanasi 也是罗马尼亚和摩尔多瓦奶酪甜甜圈的名称，它以一种新的和令人兴奋的方式结合了我最喜欢的两件事。
    
5.  [Bun v0.3.0](https://bun.sh/blog/bun-v0.3.0) 随附的内存使用量减少，导入时自动安装 npm 软件包等等。 希望这个项目不会很快关闭，因为他们用完了_dough_。 是的，Chatgpt 写的，起诉我。
    
6.  [Codux](https://dev.to/codux/introducing-codux-15j5) 是专门为 React 项目创建的新 Visual IDE。
    
7.  Michelle Barker 为 [Optimizing A Vue App](https://www.smashingmagazine.com/2022/11/optimizing-vue-app/) 写了一些有用的提示。 但我更喜欢盲目地相信 ChatGPT 给我的输出，TYVM。
    
8.  [Full page prerenders are coming back to Chrome](https://developer.chrome.com/blog/prerender-pages/)，因为浏览器供应商和任何好莱坞高管一样喜欢翻拍。

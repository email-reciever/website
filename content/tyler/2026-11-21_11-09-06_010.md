是时候点燃了

### 点亮 3

现在不要看，但人们第一次开始使用 Web 组件。

_这是个笑话_——所以请放下干草叉。 在过去的十年中，许多开发人员一直在热心地使用 Web 组件传福音，但直到最近，用于构建它们的工具和库经常令人费解且难以使用。

**快速回顾：** 2015 年，谷歌发布了聚合物库。 几年后，Polymer 团队开始听很多 Travis Scott（可能），并发布了一个名为 Lit-HTML 的新库来涵盖 Polymer 的一些缺点。 一年后，_another_ 图书馆被称为 Litelement，WC 的生态系统比以往任何时候都更加破碎和混乱。

值得庆幸的是，在 2021 年，他们通过将 Polymer 项目日落，并将 Lit-HTML 和 Litelement 组合到一个名为 Lit 2.0 的库中结束了疯狂——他们恰当地发布了 4/20 周。

LIT 为流式传输 SSR 和灵活的客户端补水引入了新的基础，但问题仍然存在：它是否能够让 Web 开发人员尝试 Web 组件？

**到目前为止，答案是肯定的。**

如今，LIT 的售价略低于 120 万 [weekly npm downloads](https://npmtrends.com/lit)，几乎是两年前的 24 倍。 它的增长曲线是如此完美的曲棍球棒，它应该为 VC 员工提供 NSFW 警告。

现在，他们正在为 [Lit 3.0 release](https://lit.dev/blog/2023-09-27-lit-3.0-prerelease-2/) 做准备，在接下来的几周内保持稳定。 它不会引入许多重大更改，但它确实具有一些令人兴奋的新功能：

*   ** 对 TC39 标准装饰器的新支持，** 它将允许 lit 使用不需要编译器的装饰器实现。
    
*   **新的 LIT 模板编译器** 使用 TypeScript 转换来提高渲染性能。
    
*   **Preact 信号集成** 与提供三种不同方式的新 `@lit-labs/preact-signals` 包一起使用 LIT 信号。
    

**底线：** 现在是点燃的最佳时机。

答案：150.29999999999998

我们预计会看到 20.00，但由于 JavaScript 中的浮点算术，我们得到了意想不到的结果。 要解决此问题，我们可以将货币表示为整数（例如，cents）并使用 Math.round 来避免浮点计算的陷阱。 这是更新的代码：

类银行账户 {
构造函数（初始平衡）{
this.balancecents = math.round(initialbalance * 100);
this.MinimumBalancecents = 2000；
}
    
存款（金额）{
this.balancecents += math.round(金额*100);
}
    
提款（金额）{
const 提款= math.round(金额*100);
    
如果（
Math.Round(this.balancecents - 提款) < this.minimumbalancecents
){
返回假；
} 其他{
this.balancecents -= 提款；
返回真；
}
}
    
getBalance（）{
返回 this.balancecents / 100;
}
}
    
const myAccount = 新银行帐户(150.0);
myAccount.deposit(0.1);
myAccount.deposit(0.2);
myAccount.Withdraw(130.3);
    
// 显示剩余余额，应为 20.00

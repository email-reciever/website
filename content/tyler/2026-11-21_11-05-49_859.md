### Google I/O 网络好东西

上周的 Google I/O 感觉像是 AI 发布、Android 更新和…… Twitter 上的人们对 Marc Rebillet DJ 套装的狂热梦想？

但不要担心，这就是为什么你付给我们大笔钱的原因。

所以坐下来，让我们剪掉 Sundar _noise_ 的所有单调演讲，以赶上 Google I/O 中最有趣的 5 个最有趣的 Web 开发公告。

[LLM integration coming to Chrome 126](https://developer.chrome.com/docs/ai/built-in)：Chrome 团队正在开发 Web 平台 API 和其他浏览器功能，用于将 LLM 直接集成到浏览器中。 他们正在优先考虑他们的 Gemini Nano 模型，该模型可以在本地运行，并帮助您向用户提供 AI 功能，“无需担心微调、容量或成本”（至少对于 Chrome 用户而言）。

[CSS Anchor Positioning just landed in Chrome 125](https://developer.chrome.com/release-notes/125)：这使您可以使用 CSS 属性将绝对定位到页面上的一个或多个其他元素的元素以声明性的方式（不含 JavaScript）的方式绑定。 一种用例是在调用它的元素（或锚点）旁边放置一个工具提示。

[3D maps added to the Maps JavaScript API](https://mapsplatform.google.com/resources/blog/access-3d-maps-in-maps-javascript-api-starting-today/)：我经常认为自己是 JavaScript 的麦哲伦，所以我很高兴看到他们将长期要求的逼真的 3D 地图添加到 Maps API。

[Firebase has SQL now](https://www.youtube.com/watch?v=7OdVatEI85o)：这是他们新的 Data Connect 平台的一部分，可让您轻松定义数据模型、查询和突变。 然后，它使用该信息在 Cloud SQL、强类型 SDK 和运行在 Google 的安全基础设施上的 API 服务器中生成 Postgres DB。 你的举动，Supabase。

[New Web Platform Dashboard](https://webstatus.dev/)：这将整个 Web 平台映射为一组功能，因此您可以跟踪他们的开发，检查他们的互操作状态，并写信给您当地的国会议员，询问为什么 Firefox 需要这么长时间来支持您最喜欢的功能。

在 JavaScript 中，具有相同延迟的 `setTimeout` 回调的执行顺序不是确定性的。 这意味着我们不能保证第一个超时回调将首先执行（这可能是一些令人讨厌且难以重现错误的原因）。 实际上，它几乎总是您所期望的（“共享变量已经更新”），但最好不要依赖这种行为。

这是 Philip Roberts 的 [famous talk](https://www.youtube.com/watch?v=8aGhZQkoFbQ)，用于了解有关事件循环以及 JavaScript 如何处理异步代码的更多信息。

### 重新混音 React 路由器混音

上周我们在 Remix [released v1.10.0](https://github.com/remix-run/remix/releases/tag/remix%401.10.0) 的朋友完成了“React Router-ing of Remix”。 对于那些没有关注的人，我们已经从 React Router 到 Remix 从 Remix 到 React Router，现在我们又回到了 Remix（Snip Snap、Snip Snap）——这有很多内容要吸收。让我们分解一下。

在创建混音之前，Ryan / Michael and Co. 正在开发 React 生态系统中最大的库 React 路由器。 经过多年的“免费工作”，他们决定是时候获得报酬（🫡）并为他们在大流行期间建立的项目筹集资金了，Remix。

Remix 的最初推介是一个 SSR 框架，主要基于标准化的 Web API。 通过其简单而强大的 API，Remix 获得了不断发展和充满激情的社区的一致采用。 激情如此强烈，以至于像 Next.js 这样的其他框架很快发现自己陷入了克莱顿克里斯滕森的狂热梦想，需要追赶 API 追赶。

不幸的是，问题在于提高 VC 通常是一个残忍的情妇，有一种独特的、贪得无厌的成瘾——[growth](http://www.paulgraham.com/growth.html)。 最快的混音方式是什么？ 想办法让所有这些 React 路由器用户成为 Remix 用户。 有了这个，我们有第一个剪辑。

**✂️：重新混音 React Router** 为了满足上述情妇，团队决定将 `loaders` 和 `actions` 的所有 Remix 数据 API 移动到 React 路由器，以便它可以拥有整个应用程序的数据编排 - 哦，是的，让 React路由器用户采用remix非常简单。 为此，他们必须再次从头开始重新编写 React Router（不破坏任何内容）。

**✂️：React Router'ing Remix** 在释放 [React Router v6.4](https://remix.run/blog/react-router-v6.4)（并将他们的公司出售给 Shopify）后，Remix 团队忙于他们旅程的最后阶段，将 React Router 集成回 Remix。 他们本周结束了这段旅程，为流媒体和 [deferred rendering](https://twitter.com/ryanflorence/status/1529101442455425027?s=20) 等新功能铺平了道路，但更重要的是，现在 React Router 用户拥有更无缝的 Remix 路径。

**底线：** React 路由器仍然主导着 React 生态系统，每周 npm 下载次数超过 900 万次。 如果所有这些重写都可以说服大部分用户尝试混音，那么迈克尔和托比可能会走到一起。

#### 由 Datadog 赞助的 [Continuous Testing Brief](http://datadoghq.com/bytes)

`reducer` 函数被调用了多少次？

常数数 = [2,4,6]
    
const reducer = (prev, current) => {
console.count('调用')
返回上一个 + 电流
}
    
nums.reduce(减速器)
    

答案：**两次**

如果未提供初始值，则数组中的第一个元素将用作初始值，并且将跳过 reducer 函数的第一次调用。

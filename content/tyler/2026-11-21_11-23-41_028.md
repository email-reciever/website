他来了，他看到了，他征服了

**所有道路都通向……** JavaScript，显然。 但罗马希望帮助您的 JS 之旅比以往任何时候都更顺畅、更简单。

[Sebastian McKenzie](https://twitter.com/sebmck) 上周宣布了罗马的第一个测试版，并称其为“巴别塔的精神继承者”（他被允许这么说，因为他创造了巴别塔）。 Sebastian [has long maintained that his original plan for Babel was to use it to consolidate multiple frontend tools into one](https://mobile.twitter.com/sebmck/status/879282797915119616)，但由于各种原因，这从未发生过。 嗯，现在正在发生。

罗马的第一个版本只是 JavaScript 和 TypeScript 的简单 linter，但它最终希望成为满足您所有前端工具需求的一站式商店。

**这实际上是什么样子的？**

Rome 无需使用一组工具来编译、捆绑和测试您的前端代码，而是将在一个从头开始构建的单个软件包中提供所有这些功能。 罗马将其称为“工具链”。

### 底线

“罗马旨在取代 Babel、Eslint、Webpack、Prettier、Jest 和其他人”——有人会说这是一个不可能的目标。 然而，与奥古斯都类似，Sebastian 发现 JavaScript 是一种砖块语言，他计划将其留给大理石语言。

[React Fixes Tech Debt](https://reactjs.org/blog/2020/08/10/react-v17-rc.html)
-------------------------------------- --------------------------------------

![react 17](https://bytes.dev/images/content/react17.png)

[@bradypp](https://twitter.com/bradypp/status/1294349163451293698/photo/1)

自上次主要版本以来 3 年多后，React V17.0 (RC) 终于来了，让我告诉你——这**值得等待**。

嗯？ 有没有新功能？ 2020年如何。

就像你高中时的男朋友一样，React 17 是未来升级的“垫脚石”。 这是一个回顾。

*   **渐进升级**：通常在升级主要版本时，您必须升级整个应用程序。 React 17 将使您的应用程序逐件升级变得更容易，而不是一次全部升级。
*   **新事件委派**：传统上，React 不会将事件附加到要声明它们的 DOM 节点，而是将事件附加到 `document` 节点本身。 这很好用，除非您的应用中有各种 React 版本。 在 R17 中，React 会将事件附加到渲染 React 的根 DOM 容器，从而修复多个版本问题。
*   **新的JSX变换**：新的React开发人员的一个问题是，即使您没有直接使用`React`包，您仍然需要`import React`因为JSX。 对于新的 `react/jsx-runtime`，这是过去的问题。
*   **删除事件池**：历史上 React 已经回收了合成事件对象。 同样，这通常很好，除了您希望在更新器函数中“稍后”访问事件的罕见情况。

### 底线

虽然不是我们所希望的版本，但 React 17 将所有正确的部分都放在了适当的位置，以便在未来获得更好的版本。

发现错误 - 解释
---------------------------

如上所述，React 17 删除了“事件池”。 这是 React 16 中事件池可能出错的一个示例。因为 React 用于回收合成事件对象，当我们想要访问它时，`e.target.value` 将消失。 要解决此问题，我们可以升级到 React 17 (RC)，在事件上调用 `.persist()`，或者按照下面的代码执行操作。

...
    
常量句柄变化 = (e) => {
常量名称 = e.target.value
    
setData((用户) => ({
...用户，
名称
}))
}
    
...

### remix 采取它的维特阿明斯

在万圣节，Remix 宣布 Spooky _experimental_ [support for Vite](https://remix.run/blog/remix-heart-vite) 作为其当前基于 ESBuild 的编译器的潜在替代方案。

这得到了#ViteHive Hyped AF，它让我们思考了两个问题：1）为什么 Remix 会这样做？ 2) 为什么现在？ 让我们深入挖掘。

**为什么这样做？**

*   **Vite 快速且令人敬畏（显然）。** 早期测试显示它为 Remix 项目提供了 10 倍的 HMR 和 5 倍快的 HDR，以及许多其他 DX 升级。
    
*   **Vite 插件为 Remix 提供了大量免费的功能。 事实上，Remix 本身现在只是一个 Vite 插件。
    
*   **Vite 应该有助于促进 Remix 的采用。** 此举让已经使用 Vite 尝试混音的开发人员更容易。 Remix 团队已经成功地说服了许多 React 路由器用户采用 Remix，这将有助于使特定的过渡更加顺畅。
    

**为什么是现在？ 因此，他们在Rollup之上构建了自己的编译器，后来在2021年将其切换到了Esbuild。

快进到 2023 年初，Remix 团队正在努力改进编译器以解决一些瓶颈问题。 在这一点上，Vite 现在支持了 Remix 所需的几乎所有功能，Remix 意识到改进自己的编译器需要在 ESBuild 之上构建更多功能——只是为了创建他们所说的“更糟糕的 Vite”。

所以他们做了聪明的事情，并开始为remix开发一个Vite插件。 最后一块将为 Vite 添加 Cloudflare 支持，Remix 团队目前正在与 Cloudflare 核心团队合作，以实现这一目标。

**底线：** 对于 Remix，这似乎是一个不费吹灰之力的明智之举，它提供了大量的好处，如果有的话，不利的一面。 对于 Vite，这是朝着成为“网络生态系统中更高层次创新的共享基础”的目标的又一个积极的步骤。 永远不要与#ViteHive 打赌。

}
    
介绍（）{
控制台.log(`Hello, my name is ${this.#name}.`);
}
    
_getname() {
返回 this.#name;
}
}

云是天堂吗？
---------------------

上周，GitHub 宣布 [they’re sunsetting Atom Editor](https://github.blog/2022-06-08-sunsetting-atom/)。 为失去我们多年来喜爱的工具而哀悼总是很奇怪，但至少你的孩子不会问你原子是否要去天堂（就像 Petey the Fish 死了一样）。

GitHub 决定从 Atom 继续前进，说明了我们作为一个行业的发展方向，甚至更多地了解了我们的发展方向。 让我们潜入。

**我们是如何到达这里的？** Atom 在 2014 年问世时是一件大事。它是第一个“可黑客”的 IDE——通过编写浏览器代码（HTML、CSS、JS）来扩展编辑器功能的想法是一个启示。 为了实现这一点，GitHub 构建了一个名为 Atom Shell（又名 Electron）的平台——它使您的笔记本电脑风扇 Go BRRRR 基本上为每个应用程序开发人员使用（Slack、Discord、VS Code 等）提供支持。

**那么为什么 GitHub 关闭它？** 显而易见的原因是微软在购买 GitHub 时已经有 VS Code，没有人需要 2 个编辑器🙃。 但更有趣的是，GitHub 说，“我们决定将 Atom 设置为 Sunset，以便我们可以专注于使用 GitHub Codespaces 增强云中的开发人员体验。” 这里的更大图景是所有开发工具的 [moving to the cloud](https://dx.tips/the-end-of-localhost)。

**这对我们所有人来说意味着什么：**

*   更容易设置和运行代码（GitHub 是 [building CodeSpaces with CodeSpaces](https://github.blog/2021-08-11-githubs-engineering-team-moved-codespaces/)... 非常元。）
    
*   更多的“本地开发”将通过在云中运行您的代码的瘦客户端完成（如 Cloudlare 的 [wrangler cli](https://twitter.com/threepointone/status/1533914337290735616?s=20&t=f2Xqvh3SZ7n3mp43CKdx-g)）
    
*   从朋友那里获得帮助来调试问题应该比缩放屏幕共享要好得多（[we already have this](https://code.visualstudio.com/blogs/2017/11/15/live-share)，但这种体验应该成为默认的）
    
*   Microsoft 将打印出比以往更多的现金
    

**底线：** Atom 现在在天堂，但也许我们会在那里看到它，因为我们都会在云中闲逛。 无论哪种方式，感谢您为我们提供了有史以来最好的语法主题（Atom Dark）。

Million.js 想让 vdom 再次酷
---------------------------------------

不再是 2015 年了。 我们已经停止在衬衫上的顶部按钮，Yik Yak 应用程序无法在我的 iPhone 6s 上打开，而 React 曾经革命性的虚拟 DOM 在许多圈子中都有 [fallen out of favor](https://svelte.dev/blog/virtual-dom-is-pure-overhead)。

最后一个事实主要是由于 VDOM 的更高计算成本（与生活中最好的事情不同，[diffing](https://medium.com/@gethylgeorge/how-virtual-dom-and-diffing-works-in-react-6fc805f9f84e) 不是免费的）。 这是 Svelte 和 Solid.js 等较新框架的主要吸引力之一——它们根本没有虚拟 DOM。 相反，他们使用编译器预先预渲染，并且只生成他们需要的代码，在大多数情况下使它们更快。

但是，随着 [Million.js](https://millionjs.org/) 的出现，虚拟 DOM 只是在手臂上获得了虚拟镜头——一种新的、编译器增强的虚拟 DOM，由 Vercel 赞助并由 17 岁的 [Aiden Bai](https://twitter.com/aidenybai) 创建。

Aiden今年夏天即将开始在Vercel实习（因为他当然是），他将Million.js描述为“React的API和Svelte的编译器有一个超快的婴儿。”

翻译：您仍然可以获得 React 的 VDOM 的所有声明性（真实单词？），但是通过使用快速的、类似于 Svelte 的编译器来计算 UI。

百万刚刚在 React 18 中变成 [officially compatible](https://stackblitz.com/github/aidenybai/million-react-compat?file=README.md)，但您可以将它与任何库一起使用。 它是可扩展的，它支持所有编译器优化，因此如果您喜欢这种事情，您可以轻松地在百万之上创建自己的自定义编译器。

**底线：** 在一天结束时，我们都在这里尝试渲染列表。 这只是 [a _million_ ways](https://youtu.be/M1_CLW-NNwc?t=11) 中的另一项。 将其留给 Z 世代，将旧趋势回收到时尚和现代的事物中。

JS Quiz解决方案 — 由 [BugHerd](https://bugherd.com/li/contextual-web-feedback-tool-dev) 赞助
--------------------------------------------- ---------------------------------------------

const friends = ['aliyah', 'alex', 'ben', 'cassidy', 'carlos']
    
const { length, 0: first, [length - 1]: last } = friends
    
console.log(first) // aliyah
console.log(last) // Carlos
    

由于数组只是具有数字键和 `length` 属性的对象，因此我们可以使用解构和计算属性名称来抓取任何数组中的第一个和最后一个元素。 有点无价值，但有点酷。

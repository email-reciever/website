### 运行时间隆隆声

在过去的几个月里，感觉就像我们看到新的 JavaScript 运行时比新的 JavaScript 框架弹出的速度更快。

我们之前写过其中的一些，但今天，我们将把所有下一代运行时间放在一个地方，做我继父过去对我和我的兄弟姐妹所做的事情——让他们互相对抗，看看哪一个会出现最强。

让我们准备隆隆声。

**WinterJS：**我们的大逃杀的最新竞争者是建立在SpiderMonkey JS引擎上的，几周前[just released v1.0](https://wasmer.io/posts/winterjs-v1)。 它声称是所有运行时间中最炽热的运行时，但有些人指出他们的基准看起来 [a little suspicious](https://x.com/justjs14/status/1767346036471673023?s=20) 并质疑运行时在其 [proprietary hosting platform](https://wasmer.io/products/edge) 之外的有用性。 但由于它与社区驱动的 [WinterCG spec](https://wintercg.org/) 的兼容性以及对 Next.js、服务器组件和 Wasm 的支持，它看起来仍然令人生畏。

**workerd:** 很可能是第一个被扔出戒指的人，[Workerd](https://github.com/cloudflare/workerd) 严重依赖其 Big Bro Cloudflare 的支持来有用。 它有助于引导运动在服务器上使用 Web API（通过隔离），但很难在 Cloudflare 平台之外看到使用它的真正理由。

**deno:** 有点像 Eddie Guerrero [turned on Rey Mysterio](https://www.youtube.com/watch?v=QxvnekDuFm0) 时，Ryan Dahl 在离开 Node 时开创了这种下一代运行时的狂热，重新安排了给 Deno 的信件，并着手解决了他的 OG 运行时的问题。 如今，Deno 拥有顶级运行时安全性、一流的 TS 支持以及强大的多功能性，能够在边缘或服务器上运行。 但问题仍然存在——它是否足以取消节点并阻止热门新人？

**llrt:** 在大逃杀中参加比赛时，您需要能够快速热身。 这对亚马逊的 [LLRT runtime](https://github.com/awslabs/llrt) 来说是个好消息，它的冷启动速度极快。 但因为它只暴露了其他运行时支持的一小部分 API，你肯定会牺牲一些力量来获得一些额外的速度和 AWS 生态系统的便利性。

**Bun:** 现在，Bun 看起来像是 Node 的顶级挑战者，只需从所有其他竞争者那里窃取最佳动作 _features_ 并让它们更快。 我们之前写过 Bun 如何通过扩展 Safari 的 JavaScriptCore 引擎、利用 Zig 和疯狂地进行优化来赢得基准之战。 它结合了 Web 和 Node API 的混合，让它作为边缘运行时或在服务器上运行，并且它得到了 [very close](https://isbunwindowsyet.com/) 到完整的 Windows 支持。 BUN 仍在疯狂增长，但一旦它为 Next.js 和 Remix 等框架添加了全面支持，我们将真正测试它的受欢迎程度。

**底线：** 像大多数笼子比赛一样，我们有很多有前途的竞争者，但他们还有很长的路要走才能抓住顶级的狗 Node.js。 目前，网络效应和先发优势仍然使节点稳居领先地位，但所有这些竞争都在推动整个生态系统中的一些有前途的创新。

发现错误：解决方案
-----------------------

#### 赞助[CodeRabbit](https://coderabbit.ai?utm_source=newsletter&utm_medium=bytes2)

这一款是给初学者的。

函数 safeUpdate(obj, key, value) {
if (!obj.hasownProperty(key)) {
obj.key = 价值；
}
}
    

我们的错误是我们正在为我们的对象添加一个文字 `key` 属性。

console.log(user.key) // “美国”
    

在 JavaScript 中，如果要将变量用作对象的键，则需要使用括号表示法而不是点符号。

函数 safeUpdate(obj, key, value) {
if (!obj.hasownProperty(key)) {
obj[key] = 值；
}
}

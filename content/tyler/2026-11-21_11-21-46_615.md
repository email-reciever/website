ElectronJS 发布 V12
------------------------

![Jimmy Neutron](https://bytes.dev/images/content/jimmy.png)

很容易我们迄今为止最诅咒的模因

**必须爆炸……** 进入电子的另一个主要版本。 此更新将我们带到 v12.0 并包括一些主要的堆栈升级，以及其他一些 API 更新和重大更改。

**快速评论：** Electron 早在 2013 年就由 GitHub 创建，并迅速成为在 JavaScript 中构建跨平台桌面应用程序的首选选项。 该框架对 Chromium 和 Node.js 的捆绑导致了一些有据可查的尺寸和性能问题，但如果它对于 [VSCode, Discord, and Twitch](https://www.electronjs.org/apps) _(The Developer Holy Trinity™)_ 来说已经足够好，那么它可能对您的 Spotify 克隆来说已经足够了。

**[Electron 12](https://github.com/electron/electron/releases/tag/v12.0.0)中的新增功能：**

*   **堆栈升级** — Node.js 从 V12 升级到 V14（使用 V8（引擎，不是 Juice）8.9），它现在也运行 Chromium 89。 将所有这些捆绑在一起总是会导致一些膨胀，但保持最新状态应该有助于电子最小化肠道。
    
*   **新的 API 功能和更改** — 一个新的 `webFrameMain` API 可让您在现有 `WebContents` 实例中查找帧。 V12 还对现有 API 进行了许多细微的更改和更新，例如 `app`、`BrowserWindow` 和 `session` API。
    
*   **其他显着的更改** — V12 删除了对 Flash 的支持（_Steve Jobs Smiles in Heaven_），将 `contextIsolation` 和 `worldSafeExecuteJavaScript` 的默认值设置为 `true`，并使 `exposeInMainWorld` 方法可以公开非对象 API。
    

### 底线

ESBuild 发布 v0.9
----------------------

![Usain Bolt](https://bytes.dev/images/content/usain.png)

2 快 4 这些 b3nchmark

**进入热点……** Esbuild 上周刚刚发布了 v0.9，最近得到了很多炒作，所以我们决定自去年 7 月第四期以来第一次写下它。

**快速回顾：** Esbuild 是一个 JavaScript 捆绑器和最小化器，由 Evan Wallace（首席技术官和 Figma 的联合创始人）创建的速度比现有的捆绑器“数量级”快。

事实证明，“数量级”，Evan 的意思是“比其他人快 100 倍”（他的话，不是我们的话）——至少根据 [this benchmark](https://esbuild.github.io/)。

Bundler/Minifier 开始用于多个知名项目——例如，它是 [Vite](https://vitejs.dev/guide/features.html) 和 [Snowpack](https://www.snowpack.dev/posts/2021-01-13-snowpack-3-0) 的最新主要版本的重要组成部分。

**是什么让它这么快？**

让我们直接转到这篇自述：

*   它是用 Go 编写的，一种编译为本机代码的语言
*   解析、打印和源图生成都是完全并行的
*   在没有昂贵数据转换的情况下，很少通过
*   代码主动避免不必要的分配

**v0.9 是一个 [minor release](https://github.com/evanw/esbuild/releases/tag/v0.9.0)**，它包括支持 `package.json` 文件中的 Node 的新 `exports` 字段、对 CSS 横幅和页脚的支持、简化的 JavaScript API 等。

### 底线

发行说明还提到，Esbuild现在将始终默认打印摘要，因为（根据Evan的说法），“人们在首次尝试运行速度如此之快的地方时遇到了这个问题，以至于他们认为它必须被破坏，但后来才发现它确实可以正常工作。” [champagne problems](https://www.youtube.com/watch?v=wMpqCRF7TKg)。

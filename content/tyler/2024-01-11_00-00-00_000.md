Rails 开发人员终于首次使用 Redux

### 超胶和斯德哥尔摩综合症

想象一下，您是 Rails 开发人员。

每天早上，您醒来，亲吻墙上签名的 DHH 海报，并开始构建具有所有模型视图控制器优点的服务器端应用程序。

但今天是不同的。 您正在构建一个更复杂的全栈应用程序，并且您希望能够添加一些现代客户端交互性。

你立即伸手去拿你值得信赖的一组 Rails 批准的 [Hotwire](https://hotwired.dev/) 库，但是你又感觉到了——这_yearning_ 寻找新的东西。

突然间，如果您可以构建一些声明式 UI 组件，您将无法停止思考生活会是多么美好的生活。 当然，你喜欢 Hotwire 如何让你直接操纵 DOM——但对于更复杂的项目，你希望你可以把状态作为一个简单的数据结构来处理。

好的，你真的希望你可以使用 React (The Good Parts™)。

Rails 开发人员大声说出这一点是一级的异端邪说，但幸运的是，你并不孤单。 这就是为什么 Johny Ho 和他的团队在 Thoughtbot 创建了 [Superglue](https://thoughtbot.github.io/superglue/) 的原因——一个实验性的新库，可让您使用经典 Rails 构建丰富的 React Redux 应用程序。

Johny [describes](https://thoughtbot.com/blog/introducing-superglue#it%E2%80%99s-turbolinks-and-ujs) Superglue 作为 TurboLinks 3 库的分叉，“但不是将 `foobar.html.erb` 通过线发送并交换 `<body>`，而是通过线将 `foobar.json.props` 发送到您的 React 和 Redux 应用程序并交换页面组件。”

Superglue 没有使用 API，而是利用 Rails 在同一路线上响应不同 MIME 类型的能力。 它还为您提供 Rails 表单助手、标签助手、Cookie Auth 和其他 Rails 功能。

**底线：** Superglue 旨在为您提供使用 React 组件和 Redux 状态管理构建具有丰富交互性的现代站点的好处，同时仍然严重依赖于您的应用逻辑的 Rails。 有些人可能称之为斯德哥尔摩综合症，但 Rails 开发人员称之为家乡❤️。

#### 赞助[Clerk](https://clerk.com/docs/quickstarts/nextjs?utm_source=sponsorship&utm_medium=newsletter&utm_campaign=bytes.dev&utm_content=01-11-2024)

带有“按钮”类型的按钮将不会提交表单。 仅当类型为“提交”时才会提交表单。

<!doctype html>
    <html>
      <body>
        <form id="myForm" onsubmit="submitHandler(event)">
<label for="inputField">输入：</label>
          <input type="text" id="inputField" name="inputField" />
    
<按钮
id="我的按钮"
类="btn"
name="操作按钮"
值="点击值"
type="提交"
title="点击这个按钮"
style="background-color: 蓝色; 颜色: 白色"
          >
点我
          </button>
        </form>
    
        <script>
函数 submitHandler(e) {
e.PreventDefault();
const formData = new FormData(e.currentTarget);
警报（formData.get（“输入字段”））；
}
        </script>
      </body>
    </html>
    

奖励：有一个额外的按钮类型“重置”，它完全符合您的想法，并将表单重置为其初始状态。

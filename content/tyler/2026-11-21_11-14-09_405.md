### Interitia.js 是物质的属性

我们都知道 JavaScript 客观上是地球上最伟大的编程语言。 现在我们有更多的证据证明上周发布的 [Inertia.js 1.0](https://inertiajs.com/) ——一种“现代整体”，使后端开发人员更容易将其服务器驱动的 Web 应用程序连接到 _✨ 美丽的 ✨_ JS 前端。

从历史上看，如果 Laravel 或 Rails 开发人员想要用基于 JavaScript 的 SPA 替换其服务器端渲染视图，他们将需要构建 REST 或 GraphQL API，找出身份验证和状态管理，设置新的 Git 仓库，并……希望是最好的。

但是 Inertia 的服务器和客户端适配器为我们的后端 BFF 提供了 Laravel-Land 和 React、Vue 和 Svelte 的多汁 JavaScript 优点之间的桥梁。 以下是[how it works](https://inertiajs.com/how-it-works)：

*   后端开发人员仍然像往常一样使用服务器框架构建应用程序。 他们使用相同的功能来进行路由、控制器、中间件以及他们多年来欺骗自己喜欢的其他粗俗的_interesting_功能。
    
*   惯性取代了服务器应用程序的视图层，因此它返回的视图是 JavaScript 页面组件。 这允许开发人员使用 React、Vue 或 Svelte 构建前端，同时仍然享受他们所知道和喜爱的后端框架的生产力。
    
*   在其核心，惯性将自己描述为客户端路由库。 因此，它还允许您通过其 `<Link>` 组件进行页面访问，而无需强制重新加载整个页面。 这为您的应用程序提供了完整的 JavaScript SPA 体验。

您将如何从此数组中删除重复的元素？

常量列表 = [
{名称：'约翰'}，
{名称：'sara'}，
{名称：'sara'}，
{ 名称：'Lynn' }，
{名称：'杰克'}
];
    

有几种方法可以做到这一点。 你的第一个直觉可能是做这样的事情。

const uniqueList = array.from(新集(list))
    

这是正确的想法，因为创建 `Set` 将确保我们的集合仅包含 _unique_ 值，并且 `Array.from` 允许我们创建一个新的浅层复制数组。 不幸的是，`Sets` 只为原始值强制执行唯一性，但我们的列表中充满了对象。

相反，我们可以做这样的事情。

常量列表 = [
{名称：'约翰'}，
{名称：'sara'}，
{名称：'sara'}，
{ 名称：'Lynn' }，
{名称：'杰克'}
];
    
常量映射 = 新地图（）；
    
list.forEach(项目=> {
map.set(item.name, item)
});
    
const uniqueList = array.from(map.values())
    

请注意，我们在这里使用 `Map`。 由于 `Map` 的保留顺序，我们的 `uniqueList` 将具有与原始列表相同的顺序，但由于我们使用 `name` 作为键，因此没有重复项。

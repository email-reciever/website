Javascript 25 岁
--------------------

![Brendan Eich](https://bytes.dev/images/content/25.png)

我们不应该超过 25

**”……笑话在你，JS 还活着”** \-Kanye West -Brandon Eich。 ​ 那一年是 1995 年。邪典经典 [Heavy weights](https://www.youtube.com/watch?v=uD4GclR6ZEo) 在影院上映，尼古拉斯·凯奇刚刚获得奥斯卡奖，网站通常看起来 [something like this](https://berkshirehathaway.com/)。

当时，Netscape Navigator 是最受欢迎的 Web 浏览器，市场份额接近 80%。 Netscape Navigator 背后的公司 Netscape 的创始人是 Marc Andreessen。 他对网络的未来有远见。 他设想了一个具有客户端交互性的更动态的平台。 为了帮助实现他的愿景，他召集了大炮并聘请了剧本的守护神布兰登·艾希。

如图所示，经过 _10 天的黑客攻击，Mocha Livescript **JavaScript** 诞生了。

它具有一些来自Scheme、Smalltalk的面向对象和Java语法的功能。 一个真正的科学怪人的爱兴斯坦的脚本语言怪物。

问题在于 - JavaScript 在 Netscape Navigator 中工作，但如果您想为 IE 构建，则需要编写 JScript。 JScript 与 JavaScript 相似，但不幸的是，Similar-ish 没有编译。

那么他们是如何解决这个问题的呢？ 就像任何优秀的程序员一样，他们创建了一个“在 Netscape 中查看”的横幅，供其他人使用并希望获得最好的结果。

值得庆幸的是，这些黑暗时代并没有持续太久，在 1996 年，Netscape 将 JavaScript 提交给 ECMA（一个致力于信息和通信系统标准化的协会），以建立一个标准的通用规范。

ECMA 成立了 TC39 委员会，负责监督 JavaScript 的演变和新功能的实现。 TC39（又名Spec Fellowship）忠实地迎来了JS黄金时代，如今JavaScript是[the most popular programming language in the world.](https://insights.stackoverflow.com/survey/2020#technology)

2045 年的 5-0 大比分见。

[RTK Query - Powerful data fetching and caching for Redux](https://rtk-query-docs.netlify.app/)
-------------------------------------------- --------------------------------------------

![monkey knife fight](https://bytes.dev/images/content/fight.jpg)

猴子刀斗的简单乐趣

**也许是美宝莲……** 或者也许每个人都厌倦了用 `React.useEffect` 给自己的服务器加糖……但无论如何，另一个数据提取/缓存库已经进入了竞技场。

满足 React RTK Query - “一种高级数据获取和缓存工具，旨在简化在 Web 应用程序中加载数据的常见情况”。

它具有您期望的所有功能-

*   **Caching:** 默认情况下，请求只会发出一次。 初始请求后 RTK 查询将从缓存中获取数据。
    
*   **自动重新获取：** RTK 查询将智能地重新获取数据并更新其缓存，因此与大爆炸理论不同，您无需担心陈旧。
    
*   **Polling:** RTK 查询带有“轮询”，或以指定间隔查询“实时”效果的数据的能力。
    
*   **乐观更新：** 因为 RTK 查询严重依赖缓存，您可以免费获得乐观的更新（在请求实际成功之前立即更新 UI 更新）。
    
*   **\+ 更多：**依赖查询、预取、跳过查询等。
    

比它的功能更有趣的是它发送的信号。 RTK Query 代表了一个软枢轴，远离传统的“获取服务器状态，然后在客户端上管理它”的哲学，“使获取和缓存更容易，这样您就不必在客户端上进行管理”。 一种适用于 React Query 和 SWR 的策略。

如果您已经是一个快乐的 Redux 用户，并且您需要与 Redux 生态系统紧密集成的数据获取/缓存策略，那么 RTK 查询将是一个可靠的选择。

### 底线

考虑到所有因素，我们对 RTK 查询感到兴奋。 不是因为它是任何革命性的，而是因为它使 Redux 生态系统与整个 Web 生态系统现在似乎走向的方向保持一致。 ​

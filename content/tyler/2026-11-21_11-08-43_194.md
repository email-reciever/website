### 反应忘记关于Tittt

React 团队开始开发 React Forget 已经两年了，该编译器会自动记忆您的组件和钩子——但它仍然没有开源。

漫长的等待让我们中的一些人失去了希望，想知道 React 团队是否完全拥有 [forgotten](https://www.reddit.com/r/reactjs/comments/16nnh4z/did_the_react_team_forget_the_react_forget/) 项目 (🥁)。 这只是另一个看起来很有希望但注定要淹没在复杂的海洋中的白日梦吗？

不完全是。 而在上周的 React Advanced 会议上，来自 React 团队 [took the stage](https://www.youtube.com/watch?v=hn_L56ypX1A&t=5916s) 的 Joe Savona 和 Mofei Zhang 最终让怀疑者保持沉默。

他们告诉我们，是的，他们仍在 React Forget 上取得进展，他们让我们偷看了引擎盖下的一瞥，以展示它如何比他们最初预期的更强大。

但在我们到达那里之前，让我们备份并回答一个你之前可能很尴尬而无法问的问题：** React 是什么问题 Forget 试图解决？**

React 的核心思想是将 UI 定义为当前状态的函数。 这意味着每当你的应用程序的状态发生变化时，React 就会重新渲染，但也意味着 React 可以重新渲染 _Too 的 _ degrading 性能。

我们可以通过使用 `useMemo` 和 `React.memo` API 来防止这种情况，但手动记忆仍然有缺点：

*   它使您的代码不那么简洁、不清晰和可组合，尤其是在您的团队/代码库扩展时。
    
*   它要求你命令式地告诉 React _how_ 处理你的代码，从而杀死一些 React 的声明性魔法。
    

在他的演讲中，Joe 解释说：“手动记忆是一种妥协：我们牺牲了一些简洁、简洁的原创 React 逻辑来获得更好的性能。”

**这就是 React Forget 的用武之地。

这样，您就会知道您的应用程序始终被完全记忆化，而不必担心您是否只是因为错过了一个 `useCallback` 而使 50 个组件失效。

**那么今天的情况在哪里？ 他们是否接近开源？** 它正在到达那里。 Mofei Zhang 解释说，编译器目前正在用于两个元属性的生产中——Instagram Web 应用程序和 Quest VR 设备的 App Store（大型 React 本地代码库）。

好消息是，到目前为止，React Forget 的性能提升有 [exceeded expectations](https://youtu.be/hn_L56ypX1A?t=6862)。 _less 好消息是，他们仍然需要在所有其他元属性上测试它，并根据反馈进行额外的调整和更改，然后他们会将其开源给像你我这样的平民。 所以还是要有一段时间。

**这对 React 的未来意味着什么？** 对于大多数开发人员来说，React Forget 应该兑现其更好的性能和更好的 DX 的承诺。 但仍然没有免权衡的午餐。

在这种情况下，这意味着在开发人员手动记忆的复杂性中进行交易，以换取编译器自动记忆的复杂性。 这是一个很好的交易，但它可能会使 React ToolCahin 变得更加复杂——这是元框架和构建工具（如 Next.js 和 Vite）最能感受到的成本。

**底线：** 对于一些痴迷的_Passionate_ React 开发人员，忘记可能会感觉像亚哈船长的白鲸。 但是，如果我在高中时从阅读 _moby dick_ sparknotes 中学到了一件事，那就是你可能不应该太专注于你无法控制的事情。

此外，19 世纪的那些家伙对鲸鱼的生物学有点太着迷了。

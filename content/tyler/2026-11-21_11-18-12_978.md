谷歌 I/O 好东西
-------------------

当你们都忙于观看 Johnny Depp 的时候——Amber Heard 审判（Sickos）、“One Take Jake”和 Google 团队的其他成员刚刚结束了另一个 I/O。 今年他们能够（大部分）避免抱有希望，然后用不可避免的“它在一面旗帜后面可用”来粉碎我们，这要归功于 [Interop initiative](https://web.dev/interop-2022/) （这可能是没有人谈论的最重要的事情）。

**TLDR：** 浏览器供应商在 2019 年放弃了分歧，开始共同努力修复 Web 平台中的缺陷。 到目前为止，它导致了_all_主要浏览器支持的新功能和修复的爆炸式增长。 事实证明，Google Devrels 毕竟一直在听您的子推文反馈。

让我们分解一些来自 I/O 2022 的很酷的、新的（主要是）非标记功能。

**HTML & CSS:**

*   Dialog 元素允许您创建与开箱即用的表单一起使用的可访问模式。 诺伊丝。
*   您现在可以使用 `accent-color` 设置复选框、收音机等样式
*   Container queries - 它们就像媒体查询，但对于容器元素（仍然需要 polyfill，但在其他方面很大）
*   `:has and :is`选择器 — 非常有用（Go Look [them](https://developer.mozilla.org/en-US/docs/Web/CSS/:has) UP）

**JavaScript：**

*   顶级等待（不再是异步函数闭包）- LFG！
*   所有热爱类异教徒的私有类方法
*   使用 `arr.at(-1)` 访问数组中的最后一项变得更容易（也适用于字符串）
*   新型实用程序，如 StructuredClone 和 CreateImageBitmap

**我们还不能做的事情，但已经承诺了：**

*   导航和 [page transition](https://www.youtube.com/watch?v=JCJUPJ_zDQ4) API
*   选择我们可以设计风格的菜单🙏（我们一生都在等待）
*   css锚定定位（将在每个应用中节省100万行js）

**底线：** 如果 I/O 的目标是让我们对网络平台的未来大肆宣传，任务就完成了。 唯一缺少的是 Google Devrel 版本的 _(Tech) 名人阅读平均推文。_ 总有明年。

Solid.js 炒作的背后是什么？
--------------------------------

如果您最近在 Tech Twitter 上花费了任何时间，您可能已经注意到两件事：

1.  过去几周对Solid.js充满了热爱
2.  你的幸福水平与你在科技Twitter上花费的时间完全成反比

但既然我们都知道_`coRreLaTioN != cAuSaTiOn`_，让我们忽略第2点并深入了解Solid.js背后的炒作——或者正如它的朋友喜欢称之为“反应：好的部分”。

就像 React 一样，你用组件构建可靠的应用程序，这些组件（对于两个框架）都指的是返回 JSX 的 JavaScript 函数。 Solid还借用了一堆其他的React功能，如SSR & Hydration、Concurrent Rendering、Context等。

但是 _unlike_ 反应，没有虚拟 DOM 也没有钩子规则。 相反，Solid 使用编译器（类似于 Svelte）将 JSX 转换为普通 JS。 这使得 Solid 比现代 React 和很多 [faster](https://github.com/krausest/js-framework-benchmark) 简单得多。

但 Solid 已经存在了一段时间（2018 年）。 那么为什么我们现在听到这么多关于它的消息呢？

两个词：反应疲劳。

众所周知，即使是顽固的 React 粉丝也开始对 Hooks 周围的 [growing complexity](https://bytes.dev/archives/99) 感到有点失望。 因此，在 React 团队发布了一个用于新钩子的 RFC 之后，我们开始听到很多关于 Solid 简单性的好消息，`useEvent`，它收到了……_Mixed_ 评论。 （是的，我仍然知道_`coRreLaTioN != cAuSaTiOn`_，感谢您的检查。）

**底线：** 这绝对是 Solid 的蜜月相（他们刚刚发布 [v1.4](https://github.com/solidjs/solid/releases/tag/v1.4.0)）。 与像 React 这样更成熟和流行的框架一样，像 Solid 这样的框架更容易从开发和采用生命周期的早期阶段宣扬速度和简单性的优点。

也就是说，Solid 看起来确实很棒。 它结合了两个心爱的框架（React 和 Svelte）的最佳部分，以创建一个简单、快速和强大的新框架。 我们总是可以欣赏 [a good mash-up](https://www.youtube.com/watch?v=maK7AgGm0Xw&list=PLjV_f9YWvndVMt_e9i9Uc6bxNUvb-peaE)。

🔬 发现（TypeScript）错误解决方案 — 由 [Courier](https://help.courier.com/en/articles/4270644-setting-up-slack-as-a-notification-channel?utm_campaign=Add%20Slack%20Channel&utm_source=email&utm_medium=bytes-newsletter-5-20&utm_content=add-slack) 赞助

函数 addTriple(inputs: number[]): number {
返回输入[0] + 输入[1] + 输入[2]；
}
    

TypeScript 会警告我们，如果我们将除数字数组以外的任何内容传递给该函数，但如果该数组中的项目少于 3 个，则第三个项目将是未定义的，我们的函数将返回 `NaN`。 TypeScript 无法知道数组中有多少项，因此它无法警告我们。

对此有许多解决方案。 人们会让我们将类型签名更改为元组类型而不是数组。 如果我们的数组没有足够的选项，TypeScript 可以警告我们。

函数 addTriple(inputs: [number, number, number]): number {
返回输入[0] + 输入[1] + 输入[2]；
}
    

另一个选项是启用 `noUncheckedIndexedAccess` TypeScript 编译器选项，这将迫使我们检查每个项目是否未定义。

函数 addTriple(inputs: number[]): number {
如果（
输入[0] ===未定义||
输入[1] === 未定义||
输入[2] === 未定义
){
抛出新错误（“无效输入”）；
}
    
返回输入[0] + 输入[1] + 输入[2]；
}

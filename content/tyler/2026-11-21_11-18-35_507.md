Richie Rich-Text 回到实验室

词汇
--------

如果您以前必须建立丰富的文本编辑体验，您就会知道只有 [one word](https://youtu.be/Ud4HuAzHEUc?t=7) 来描述它。 这可能就是 Facebook 放弃 [Draft.js](https://draftjs.org/) 的原因（以及他们所有 40 岁以下的用户）。

但上周，Dominic Gannaway（前 React 核心团队成员）在开源名为 [Lexical](https://lexical.dev/) 的新改进的富文本编辑器框架时改变了游戏。

如果你从来没有经历过自己建造这个的痛苦，这听起来可能没什么大不了的——所以让我给你画一幅画。

在处理富文本时，管理选择状态是一场噩梦。 您必须在文本字符串和它所代表的 HTML 之间来回翻译选择，同时跟踪更改的历史记录。 以前的框架，如 Draft 提供了一个解决方案，但它很慢，它在移动设备上不起作用，你必须使用 immutable.js (lol)。

那么是什么让词汇与众不同呢？ 最重要的是，Dominic（又名 _richie rich-text_）确保它没有任何行李依赖关系，这可以解锁一些很酷的功能：

1.  **speed:** lexical 是 [up to 70% faster](https://news.ycombinator.com/item?id=31020205) 比 draft 并且只有 22kb 的线程，这意味着您将有大量字节在状态管理库上浪费。
    
2.  **Framework Agnostic:** 它适用于（或不使用）您选择的 JavaScript 框架。 它已经带有开箱即用的 React 绑定，其他流行框架的绑定正在进行中。
    
3.  **可访问性：** 与许多丰富的文本编辑器不同，Lexical 遵循所有 WCAG 最佳实践，并与屏幕阅读器和其他辅助技术兼容。
    
4.  **插件：**您可以轻松扩展核心功能以添加@提及、#hashtags、撤消/重做——所有将[get your PM excited](https://twitter.com/HoodComedyEnt/status/1513228276675891202)的好东西。
    

**底线：** _\*实际上\*_ 有效的丰富文本编辑器框架？ 现在我们只需要弄清楚如何让麦考利·卡尔金在词汇电影中扮演多米尼克。

打字稿 4.7 进入热点
-----------------------------

我们明白了——打字稿很棒，而且 [it’s taking over the world.](https://www.youtube.com/watch?v=EUlM3wx546o)

但最近的几个版本一直很无聊，而不是令人兴奋的新功能更专注于增量改进。 值得庆幸的是，上周的 [v4.7 beta release](https://devblogs.microsoft.com/typescript/announcing-typescript-4-7-beta/) 热火朝天地推出了一些长期要求的新功能和功能，这些功能和功能实际上应该让我们的生活更轻松。

以下是您应该了解的关于 TS 4.7 的 3 件最有趣的事情：

*   ** 对传统模块的更好支持** — 技术中的年龄歧视是一个严重的问题，因此很高兴看到 TypeScript 寻找老年人模块。 4.7 使将旧版 CommonJS 文件导入更现代的 ES 模块变得更好。 它还添加了对 `.cjs` 和 `.mjs` 文件扩展名以及 package.json 中的 `type` 和 `exports` 属性的支持。
    
*   **两个关键领域的重大改进** — TypeScript 如何分析计算的对象属性以及在对象中定义函数时 TS 如何处理推理问题。 有很多事情要做这两件事，但你需要知道的是，打字稿现在应该少对你大喊大叫。
    
*   **增强的泛型功能**允许您将泛型类型参数传递给函数，而没有 _calling_ 函数本身，允许您从现有的泛型函数中创建更窄类型的函数（不要与此 [generic-looking function](https://external-preview.redd.it/wD2iKtXEeF5IyrjDJeVacYbth-4-5yFG2a09Fp0aCJE.jpg?auto=webp&s=da2d9848dec538d37db3f4c349df3fd566f76737) 混淆）。
    

**底线：** 你知道让这些 TypeScript 更新读起来有多难吗？ 这是 JavaScript 生态系统的 IRS。 无聊，主要是对你大喊大叫，但有必要让事情始终如一地运作（有人告诉我）。

🔬 发现错误解决方案 — 由 [Retool](https://retool.com/?utm_source=sponsor&utm_medium=newsletter&utm_campaign=bytes) 赞助
------------------------------------------------------------ --------------------------------------------------------------

`todos` 变量在同一块中被重新声明。 用 `const` 和 `let` 声明的变量是块作用域的，这意味着它们不存在于它们被调用的块之外。块是用 `if/else` 语句、循环和函数周围的 `{}` 括号创建的。

有许多解决方案，包括在不同情况下更改变量名称或完全删除变量。 我们还可以将每个案例包装在一个块中以隔离变量。

函数 todoreducer(状态, 动作) {
切换（动作.type）{
案例 "add_todo": {
const todos = state.todos;
return { ...state, todos: todos.concat(action.payload) };
}
案例“remove_todo”：{
const todos = state.todos;
const newtodos = todos.filter((todo) => todo.id !== action.id);
return { ...state, todos: newtodos };
}
默认：
返回状态；
}
}

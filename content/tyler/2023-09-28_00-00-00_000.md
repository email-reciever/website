### Turso想给你500个数据库（免费）

_“好吧，那很好……”_我能听到你说，_“但我到底为什么要那个？还有，什么是 Turso？”_

两个好问题。 [Turso](https://turso.tech/) 是基于其开源的 SQLite 分叉的边缘托管的分布式数据库，称为 [libSQL](https://github.com/tursodatabase/libsql)。 周一，他们宣布他们的免费套餐现在高达 [500 databases](https://blog.turso.tech/turso-radically-increases-the-amount-of-databases-available-on-their-starter-and-scaler-plans-10a69ad94055)，他们的 29 美元/月级包含 10,000 个数据库。

这给我们带来了第一个问题：_为什么？？_

事实证明，主要有以下三个原因：

**1\。 您可以为您拥有的每个项目建立一个全新的数据库**——不是新模式，不是新实例，而是一个完全独立的数据库，可以拥有自己独特的逻辑。 现在为您的项目获取新数据库比获得新域更容易（而且更便宜）。

**2\。 它使构建多租户 SaaS 应用程序变得更加简单。

**3\。 如果您运行任何类型的平台，用户可以部署他们自己的计算，您可以为用户提供他们自己的数据库**。 这就是[Val Town did](https://www.val.town/v/std.turso)。 它们是一个热门的新型无服务器函数平台，它使用 Turso 为每个用户（甚至是免费层上的用户）提供自己的 SQLite DB。

_“好吧，但是他们怎么能免费做到这一点，当我用 Firebase 设置 500 分贝时，我需要半个肾脏？”_

你的另一个好问题。 这一切都归结为 SQLite/LibSQL 的魔力。 因为每个 SQLite 数据库都只是一个文件，因此它们比 Firebase 等平台使用的 NoSQL 数据库更便宜、更容易启动。 它也更便携，因为您可以轻松下载自己的所有数据。

SQLite 确实引入了一些权衡，但通过分叉创建 LibSQL，Turso 能够克服其大部分缺点，同时也使其边缘兼容。 借助他们的新 [Embedded Replicas](https://blog.turso.tech/introducing-embedded-replicas-deploy-turso-anywhere-2085aa0dc242)，您可以获得 SQLite 的所有本地速度，并且您可以在任何地方部署的远程数据库的便利性。

**底线：** Drizzle 可能 [said it best](https://twitter.com/DrizzleORM/status/1706409297091948794) 当他们在推特上说 Turso 现在可以构建“500 个有 0 个用户的初创公司，并且仍然为无服务器数据库支付 0 美元时，它可能会在何时存活。”

#### 赞助[Secureframe](https://secureframe.com/request-demo-4?utm_source=partner&utm_medium=newsletter&utm_campaign=092823-bytes-newsletter)

在初始示例中，我们在创建 DOM 时将每个列表项附加到 DOM。 这是效率低下的，因为每次我们附加一个新列表项时，DOM 都会更新。 相反，我们可以创建一个文档片段并将所有列表项附加到片段中。 然后，我们可以将片段附加到 DOM。 这样，DOM 只更新一次。

<!doctype html>
    <html lang="en">
      <head>
        <meta charset="UTF-8" />
        <meta name="viewport" content="width=device-width, initial-scale=1.0" />
<title>动态列表</title>
      </head>
      <body>
        <ul id="myList"></ul>
    
        <script>
让项目 = [...array(1000).keys()].map((i) => `Item ${i}`);
    
让 ul = document.getElementById("myList");
让 fragment = document.createDocumentFragment();
    
对于（让项目项）{
让 li = document.createElement("li");
li.TextContent = 项目；
片段.appendchild(li);
}
    
ul.appendchild(片段);
        </script>
      </body>
    </html>

### 作为前端开发人员，我为什么要关心数据库？

我相信在未来的某个时候，一种或另一种方式，你必须这样做。 我开始使用 Turso 以确保在拐点到来时，您将至少提供一种简单、快速且具有成本效益的数据库。 过去，数据库是一个非常小众的东西：出了名的难以操作和配置，（曾经有一个名为 DBA 的整个工作角色！），反复无常且易于破坏。 如此之多，以至于后端开发人员的很大一部分角色是确保这些东西不会破坏数据库。

这种情况正在迅速变化：像 Vercel 和 Cloudflare 这样的平台使您的后端处理变得非常简单，因此数据库是下一个前沿……如果 SQL 本身就是问题所在……ChatGPT 就是拯救（它生成了令人惊讶的良好 SQL 代码！！）。

有了 Turso，我们希望让每个人都可以更容易地访问数据库。 我们围绕 SQLite 构建了我们的产品，这实际上只是一个库。 使用嵌入式副本，您可以拥有自己的数据库副本，并以您想要的任何方式将其残忍化。

我们将继续构建开发人员，并将继续尽最大努力使数据库成为您在代码中调用的函数，就像任何其他函数一样。 当你掌握它时，你将能够更深入地了解堆栈。

– [Glauber, Turso CEO](https://twitter.com/glcst)

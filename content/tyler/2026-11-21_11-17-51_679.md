为我们所有人带来的构建工具
--------------------------------

你所看到的任何地方，它都在那里。 没有逃避它，无处可藏。

不，我说的不是你的“我买的我知道的”血红色科技股票/加密投资组合，我说的是 Vite（发音为 Vite）——正在接管网络的工具感。

**快速评论：** Vite 由 Evan You（从未听说过他）发起，以解决基于 JavaScript 的工具的“性能瓶颈”问题——也就是构建时间足以烹制一顿完整的英式早餐。 它以两个关键方式做到这一点：1）在浏览器中利用本机ES模块，以及2）使用新的FAST-AF工具，如构建和捆绑。

这使它能够创建独特的速度和出色的 JavaScript 开发人员体验的组合。 您不需要任何专业知识，如 Rust 或 Go 来采用或自定义 Vite（作为 Eric Simons [wrote](https://blog.stackblitz.com/posts/why-were-backing-vite/) 宣布 Stackblitz 成为 Vite 最大的支持者时）。

这只是 Vite 最近积累的众多 W 之一。 让我们再回顾几下：

*   上个月达到每周100万次下载的里程碑（比一年前增加10倍）。
    
*   采用多个备受瞩目的项目，包括 Svelte/Sveltekit、Astro、[Hydrogen](https://shopify.engineering/developer-experience-with-hydrogen-and-vite)、Storybook、Vue/Nuxt（显然）等等。
    
*   发布 [Vitest](https://vitest.dev/) — 一个超快、Vite 原生单元测试框架，每周刚刚通过 20 万次下载。
    

**底线：** 记住，Vite Rhymes with “feet”——所以在告诉你的伴侣你将参加几年后的“第一届年度 _Vite_ Conf”时，一定要非常清楚地表达你的话。

React现在正在玩自己的游戏
--------------------------------

React 在 JavaScript 图表中处于领先地位已近十年。 但就像Daddy Warzucks一样，React团队已经了解到“你不会在没有敌人的情况下结交5亿个朋友。”

而“敌人”，我们主要是指“在推特上生气的开发人员”——但你明白了。

也就是说，近年来对 React 的许多批评都是公平的。 在 React 启动的 5 年多时间里，竞争框架通过引入更小的捆绑包、更快的基准测试和提高的易用性来升级——而 React（有人可能会争论）在这些领域落后了。

**但是这些事情真的很重要吗？** 根据 React 团队的说法，答案是，_没有你想象的那么多。

相反，React 团队，就像我的岳母一样，更专注于“整体改进”。 具体来说，影响整个应用程序（不仅仅是框架）的改进，他们在最近的一篇关于 [what they’ve been working on](https://reactjs.org/blog/2022/06/15/react-labs-what-we-have-been-working-on-june-2022.html) 的博客文章中强调了这一点。

我们很失望地看到精油和能量疗愈没有包含在这些“整体改进”中，但这里有一些有趣的事情他们确实提到了：

*   **Server Components** — 通过提供将代码从客户端移动到服务器的无缝体验来减少捆绑。
    
*   **asset loading** — 利用悬念加载第三方资产，如样式、字体和其他脚本，没有“jank”。
    
*   **编译器** — 研究如何摆脱“微调”性能问题的需求。
    
*   **Offscreen** — 无需安装/卸载组件，您可以将它们“藏起来”（对某些 [more advanced use-cases](https://reactjs.org/blog/2022/06/15/react-labs-what-we-have-been-working-on-june-2022.html#offscreen:~:text=Instant%20transitions.,a%20modal%20overlay.) 非常有用）。
    

**底线：** 任何人（包括 React 团队）都可以很方便地采取“我们不擅长的事情实际上并不重要”的立场。 这并不意味着他们错了（他们提出了一些很好的观点），它只是意味着它……方便。

`Woof Woof` 记录。

在 JavaScript 将属性的查找委托给构造函数的 `prototype` 之前，它首先检查该属性是否存在于从构造函数返回的对象上。 在这种情况下，它会调用它。

欲了解更多信息，请查看 [A Beginner’s Guide to JavaScript’s Prototype](https://ui.dev/beginners-guide-to-javascript-prototype)

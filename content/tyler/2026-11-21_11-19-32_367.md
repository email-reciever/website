十一希望你停止使用这么多的javascript
-----------------------------------------------

十一刚刚发布了它的[simpler static site generator](https://www.11ty.dev/)的v1——“更简单”的意思是“不那么疯狂的JavaScript”。

**快速评论：** 2018 年初，十一作为 JavaScript 替代 Jekyll（错过了将其命名为“Hyde”TBH 的机会）出现在现场。 它得到了很多[hype](https://www.11ty.dev/docs/testimonials/)，因为它帮助你快速启动了一个静态站点（如Gatsby和其他JavaScript SSG），但默认情况下提供了零客户端JS（非常_Unlish_Gatsby和其他JavaScript SSG）。

但是当网络最需要它时，它就消失了。

好吧，不是真的，但在 [v1.0 came out last week](https://github.com/11ty/eleventy/releases/tag/v1.0.0) 之前，我们似乎越来越少听到关于 110 的消息（在它最初发布 4 年后）。 自 2018 年以来，网站还没有 [used _less_ JavaScript](https://httparchive.org/reports/page-weight?start=earliest&end=latest#bytesJs)，所以让我们更深入地了解一下是什么让 eleventy 与众不同：

*   **不是框架** — 它在 Node.js 中使用 JavaScript 将模板转换为内容，但它会提供零客户端 JavaScript，除非您自己添加自定义 `<script>` 标记。 这几乎总是会比传统的 JS 框架得到一个 [performance edge](https://twitter.com/zachleat/status/1482001718321852424?s=20)，但当然有很多权衡需要考虑。
    
*   **byo-templating-engine** — 与 Tony “P90X” Horton 一样，十一是 [surprisingly flexible](https://www.google.com/search?q=tony+horton+stretching&hl=en&sxsrf=AOaemvJeW9R8eLxc4LfNUEgr74k-HrZ1nw:1642437011083&source=lnms&tbm=isch&sa=X&ved=2ahUKEwjJ2PHUmrn1AhUOJ0QIHbLUC7UQ_AUoAXoECAEQAw&cshid=1642437126307964&biw=1792&bih=887&dpr=2#imgrc=nkIbvTS64LBQ9M)。 它支持 HTML、Markdown、Liquid、Nunjucks、车把和更多的模板引擎。 如果你对这种事情有点虐待狂（我们不会判断），你甚至可以混合搭配它们。
    
*   ** 适用于数据** — 很多人 [really like](https://css-tricks.com/a-site-for-front-end-development-conferences-built-with-11ty-on-netlify/#aa-i-used-11ty-to-build-the-site) 如何轻松使用前置和外部数据文件将内容注入模板中。
    

**底线：** _“但这与 Astro 有何不同？”_ 嗯，我能想到 [7 million](https://astro.build/blog/the-astro-technology-company/) 的差异。

但除此之外，TLDR 是 Astro 使用 [Islands Architecture](https://jasonformat.com/islands-architecture/) 方法在需要时为您提供按需 JavaScript 组件。 您可以获得更多的功能和灵活性，但可能需要使用更多的 JavaScript。 _💫交易。✨_

TC39 团伙是为了解开……正则表达式匹配索引的谜团？

ES2022 有什么新功能？
--------------------

没有什么_特别是_开创性的是 [coming to JavaScript](https://github.com/tc39/proposals/blob/main/finished-proposals.md) 今年（震惊），但有四个新功能值得你关注——如果没有其他原因，只是为了获得对同事的不劳而获的温暖和模糊的优越感。 像往常一样，我们在这方面为您提供了保障。

ES2022 中的第一个公告是 ECMAScript 正在提出一个 [$8M seed round](https://www.youtube.com/watch?v=dQw4w9WgXcQ) 来“帮助我们为 Web 构建更好的原语”。 其次，功能。

[Class Fields](https://github.com/tc39/proposal-class-fields) — 这使得可以在类上直接声明类属性和方法，而无需使用构造函数。 React 类组件开发人员正在笑，因为他们已经在 Babel 中使用了 _years_ 的这个功能。 但很高兴将其内置于 JavaScript 本身。

// 之前
类 MyComponent 扩展 React.component {
构造函数（道具）{
超级（道具）；
this.state = { 计数：props.InitialCount };
this.increment = this.increment.bind(this);
}
增量（）{
this.setState({ 计数：this.state.count + 1 });
}
}
    
// ES2022
类 MyComponent 扩展 React.component {
状态 = { 计数：this.props.InitialCount };
增量 = () => {
this.setState({ 计数：this.state.count + 1 });
}
}
    

此提案还包括私有类字段，用 `#` 前缀表示，该字段只能在类实例中访问。 `#cantTouchThis`

[RegExp Match Indices](https://github.com/tc39/proposal-regexp-match-indices) — 将正则表达式与 `.exec` 匹配的字符串将告诉您匹配开始的位置，但更高级的正则表达式包括捕获组，它们在匹配中进行匹配，俄罗斯娃娃样式。 该提案发明了一个新标志“`d`”，您可以将其放在正则表达式的末尾以获取捕获组的开始和结束索引。

常量正则表达式 = /a+(?<Z>z)?/d;
const 文本 = "xaaaz";
常量匹配 = 正则表达式.exec(文本);
match.indices[0][0] === 1;
match.indices[0][1] === 5;
    

[Top-level await](https://github.com/tc39/proposal-top-level-await) — 到目前为止，您只能在异步函数中使用 `await` 关键字。 使用此功能，您可以在程序的顶层使用 `await`。 这在编写脚本以执行异步操作时尤其方便，而不是使用 IIFE。

// 之前
（异步（） => {
常量结果 = 等待 doAsync();
})()
    
// ES2022
常量结果 = 等待 doAsync();
    

[.at()](https://github.com/tc39/proposal-relative-indexing-method) — Python 开发人员终于可以停止取笑我们了！ （但不能保证我们会停止取笑它们。）数组上的 `.at()` 方法让我们可以获得特定索引的值，包括负索引。 这就是魔术——负索引从数组的_end_返回一个值。 这使得抓取数组的最后一项变得更加容易。

// 之前
常量 = arr[arr.length - 1];
    
// ES2022
常量 = arr.at(-1);

### Monorepos的超级碗

我们刚刚完成了每个人都在嗡嗡作响的年度直播媒体活动——[LaunchNx Conf](https://www.youtube.com/watch?v=fy0K2Smyj5A)（显然）。

Usher 忙于被 Taylor Swift 抢风头，无法停下来，但上周的 _Monorepobowl_ 挤满了主要的版本、出人意料的公告，以及（在我的情况下）一碗我头大小的水牛鸡蘸酱。

**快速 Monorepo 审查：** 顾名思义，Monorepos 让您将相关项目分组在单个仓库中，以促进通信、重用代码和加速开发。 但是，在您遇到痛苦的缓慢构建之前，您只能使用内置的 npm/yarn/pnpm 工作区才能做到这一点——这就是 NX 的用武之地。

它内置 Rust 和 TypeScript，并提供本地和远程缓存等优化，以加快 Monorepos 的速度。 自2017年首次推出以来，NX已经发展了很多，现在每周有400万次NPM下载，并被财富500强公司的一半公司使用。

现在我们都在同一页面上，让我们来看看发布周的最大亮点。

**Big Launch #1：[Project Crystal](https://dev.to/nx/what-if-nx-plugins-were-more-like-vscode-extensions-4oh0)** — NX 插件的重大改革，使它们更强大且更易于使用。

NX 插件现在可以 [automatically infer tasks](https://nx.dev/concepts/inferred-tasks) 并根据现有的框架配置自动配置缓存输入和输出。 例如，`@nx/vite` 插件基于您的 repo 的 Vite 配置推断通过 NX 运行 Vite 的任务。 此配置已经定义了构建文件的目标，因此 nx 读取该值并为您缓存正确的输出文件。

此更改也使 _much_ 更容易开始使用插件。 只需在任何现有的 npm/pnpm/yarn 工作空间上运行 `nx init` 即可立即使用特殊的 nx 功能增强它。

**BIG LAUNCH #2：[Nx Agents](https://blog.nrwl.io/fast-effortless-ci-67812514ffb4?source=friends_link&sk=89e1b5c0388dda077e64a2eab5495d95)** — 一种付费附加组件，可为您的 CI 带来 NX 的所有功能。

它为您提供跨机器无缝分配任务、根据 PR 大小定制的机器的动态分配、细粒度的 E2E 分布以及片状测试的自动重新运行。 您可以通过一行代码启用所有这些，并观察您的 CI 瞬间变得快 80%。

**底线：**自 2017 年以来，NX 已经取得了长足的进步，但这些主要的发射应该使它比以往任何时候都更容易接近。 很高兴看到 NX 公司发布真正的创新产品来帮助资助他们的开源工作。

发现错误：解决方案
-----------------------

#### 赞助[Stream](https://getstream.io/video/?utm_source=Bytes&utm_medium=promoted_newsletter&utm_content=developer&utm_campaign=newsletter_content_ad)

常量 animal = (name, type) => {
this.name = 名称
this.type = 类型
this.age = 0
}
    
animal.prototype.birthday = 函数 () {
this.age++
}
    
const leo = new Animal('Leo', 'Lion')
    

箭头函数没有自己的 `this`。 这会导致我们的代码中出现三个错误。

首先，我们在构造函数中将属性添加到 `this`。 同样，因为箭头函数没有自己的 `this`，所以你不能这样做。

其次，我们不能使用带有箭头函数的 `new` 关键字。 这将引发 `X is not a constructor` 错误。

第三，如果该函数是箭头函数，我们不能在函数原型上添加属性，因为没有 `this`。

这是解决方案-

功能动物（名称，类型）{
this.name = 名称
this.type = 类型
this.age = 0
}
    
animal.prototype.birthday = 函数 () {
this.age++
}
    
const leo = new Animal('Leo', 'Lion')

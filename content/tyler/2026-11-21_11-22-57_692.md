[Next.js 10.0 Released](https://nextjs.org/blog/next-10)
----------------------------------------------------

![Steve Jobs](https://bytes.dev/images/content/steve.jpg)

史蒂夫·乔布斯（Steve Jobs）在Next.js Conf 1989上发表主题演讲

**Next.js 上周年满 4 岁……** 并在 Next.js Conf 上发布功能丰富的 V10 庆祝。 这个版本还让我们很好地了解了 Vercel（Next 的 Parent Co.）计划赚钱的一些新方式——考虑到他们已经筹集了一些 Bookoo Bucks（确切地说是 2100 万美元或 0.77 美元），这一点非常重要。

这里有很多东西可以解开，所以让我们**了解亮点。**

*   **新图像组件：** Next.js 与 Google Chrome 团队合作制作了 `next/image` 组件，他们将其描述为“为现代 Web 演变的 HTML `<img>` 元素的直接替代品。” 此组件自动处理延迟加载、预加载图像以及跨设备正确调整大小。
    
*   **自动图像优化：** 这让 Next.js 以 WebP 等现代格式提供图像，比 JPEG 小 30%。 最重要的是，它可以按需优化图像（根据用户的要求），而不是在构建时。 – “@我下次-盖茨比”
    
*   **国际化路由：** next.js 10 为国际化路由和语言检测提供内置支持，这应该使您的项目国际化更加自动化，痛苦少得多。 希望这样可以更轻松地构建国际化的应用程序 [Mr. Worldwide himself would approve of.](https://youtu.be/a15nUK87Tzo?t=12)
    
*   **next.js Analytics：** 一种新产品（您必须为此付费），它可以从访问者的 _actual 设备_ 中持续跟踪性能指标。 每次部署时，它都会自动为您提供实时性能评分（与 Lighthouse 相反，您必须自己运行）。
    
*   **Next.js Commerce：** 是使用 Tailwind 构建的“电子商务网站的多合一入门工具包”，并与 BigCommerce 合作构建。 似乎很容易定制并承诺尽快与 Shopify 和其他人集成。 每个页面都预设了正确的 SEO 配置，数据层已经针对电子商务进行了标准化。
    

有关 Next 10 的更多详细信息，请查看 [Guillermo Rauch’s Next.js Conf keynote from last week](https://www.youtube.com/watch?v=1-NzQ9ObsfM)。 这是我们看过的第一个主题演讲，也感觉像是[MTV Cribs.](https://www.youtube.com/watch?v=6ix3twBu17Y)的一集

[Reactime - A Time Travel Tool for State Debugging](https://reactime.io/)
---------------------------------- -----------------------------------

![Uncle Rico](https://bytes.dev/images/content/rico.jpg)

我曾经能够扔出四分之一英里的猪皮

ReacTime 是一个开源的 Chrome 扩展程序，它试图让 React 开发人员更容易进行状态调试。 它跟踪和可视化状态更改，并允许您在 React 应用中“时间旅行”到以前的状态。

它通过每次应用状态更改时拍摄快照来实现这一点，并将这些快照呈现为您可以单击（或以 JSON 格式获取）的可视层次结构。 快照也可以与之前的快照不同。

**在幕后：** Reactime 使用 React 光纤树来访问应用程序的数据。 从那里，它“使用递归的深度优先搜索算法遍历光纤节点”以提取所有有意义的数据。 然后，它塑造这些数据以适应 D3 和 Visx 的数据结构，这些库提供了可视化肌肉。

如果您使用有状态组件和道具钻取，ReacTime 有效，并且它最近为 Hooks、Recoil、Context API、条件状态路由和功能组件打开了 Beta 支持。

Reactime 上周在他们发布 V6.0 后登上了我们的雷达。 欲了解更多信息，您可以查看 [the creator’s full blog post.](https://medium.com/@CSVince/time-traveling-state-with-reactime-6-0-53fdc3ae2a20)

我们在这里为任何使状态管理更具可管理性的东西而服务。

### npm依赖关系vs开发依赖关系

#### TL；博士

`dependencies` 是您的应用程序在运行时需要的。 `react`、`redux` 和 `lodash` 等软件包都是 `dependencies` 的示例。 `devDependencies` 只需要开发和/或构建您的应用程序。 `babel`、`enzyme`和`prettier`等软件包就是`devDependencies`的例子。

#### npm 安装

当您运行 `npm install` 时，可以看到 `dependencies` 和 `devDependencies` 之间的实际差异。

如果您从包含 `package.json` 文件的目录运行 `npm install`（例如，您通常在克隆项目后执行此操作）。

> ✅ 将安装在 `dependencies` 中的所有软件包 ✅ 将安装在 `devDependencies` 中的所有软件包

如果您运行 `npm install <package-name>`（当您想要向现有项目添加新包时，通常会这样做），即 `npm install react`。

> ✅ 将安装在 `dependencies` 中的所有软件包 ❌ 安装在 `devDependencies` 中的所有软件包都没有安装

####  传递依赖

如果包A依赖于包B和包B依赖于C，那么包C是对包A的传递依赖。 但是，为了使包 B 正常运行，它需要安装包 C。 我为什么要提出这个？ well `dependencies` 和 `devDependencies` 也以不同的方式对待传递依赖性。 当您从包含 `package.json` 文件的目录中 `npm install` 时，

> `dependencies` - ✅ 下载所有可传递依赖项。 `devDependencies` - ❌ 不下载任何可传递依赖项。

#### 指定依赖关系与开发依赖关系

从 npm 5 开始，当您运行 `npm install <package-name>` 时，该软件包将自动保存在 `package.json` 文件中的 `dependencies` 中。 如果您想指定特定包应该包含在 `devDependencies` 中，则应附加 `--save-dev` 标志。

npm 安装更漂亮的 --save-dev
    

#### 在生产服务器上安装

通常，您需要在生产服务器上安装项目。 当您这样做时，您不想安装 `devDependencies`，因为您显然不会在生产服务器上使用它们。 要安装 **only** `dependencies`（而不是 `devDependencies`），您可以使用 `--production` 标志。

npm install --production

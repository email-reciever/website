### 罗马的兴衰

[Rome just launched v12](https://rome.tools/blog/2023/03/28/rome12/) 上周，这让我们思考——未来的 JavaScript 工具链最近在做什么？ 而且，有没有人真正读过 Marcus Aurelius 的 _meditations_，或者他们只是假装阅读？

但在我们回答这些问题之前，我们需要回顾一些不那么古老的罗马历史。

**我们是如何到达这里的：** 罗马由 Romulus 和 Remus Sebastian McKenzie 和 Jamie Kyle 共同创立，他们之前创建了 Babel 并帮助建造了纱线。 They released the first Rome beta in August 2020, with the promise of becoming _The one build tool to rule them all_ — aka a single monolithic toolchain that was “designed to replace Babel, ESLint, Webpack, Prettier, and Jest.”

几个月后，他们创办了一家公司，筹集了 450 万美元的风险投资来实现这一愿景。 从那时起，他们发布了格式化程序和 linter，在 Rust 中重写了罗马，并继续朝着多合一的工具链愿景努力。

**快进到今天，** 似乎罗马公司是 [no longer operating](https://twitter.com/steveruizok/status/1641714014911705089)。 不幸的是，对于许多在 2021 VC Fever Dream 期间获得资金的 OSS 初创公司来说，这可能是正确的。 但很高兴看到罗马的 OSS 项目继续发布新的更新——尽管据我们所知，现在一些核心团队成员现在在其他地方有全职工作。

以下是罗马V12的一些快速亮点：

*   JSON 文件支持，解锁各种新的工具链功能。
    
*   使用新的 `rome check` 命令通过 CLI 导入排序。
    
*   更好的诊断、VSCode 扩展和新的linter 规则。
    

**底线：** 罗马的未来看起来仍然有点不确定，但希望他们能继续取得稳固的进步，作为 OSS 项目。 我们一直在为那些试图制造更快构建工具的团队欢呼——尤其是当它们以适合大量双关语的古代文明命名时。

发现错误：解决方案
-----------------------

#### 赞助[Datadog](https://datadoghq.com/bytes)

是的，我计划单枪匹马地保留 `this` 关键字知识！

常数用户 = {
名称：“泰勒”，
年龄：32岁，
问候（）{
警报(`Hello, my name is ${this.name}`)
},
妈妈：{
名称：“一月”，
问候（）{
警报(`Hello, my name is ${this.mother.name}`)
}
}
}
    
user.mother.greet()
    

当我们调用 `user.mother.greet` 时，我们可以通过查看调用的 [“left of the dot”](https://ui.dev/this-keyword-call-apply-bind-javascript) 来判断 `this` 关键字引用的内容——在这种情况下，`mother`。

所以在 `greet` 的内部，就好像我们有 `my name is ${mother.mother.name}`，这显然是错误的。 相反，由于 `this` 关键字是引用 `mother`，我们可以只做 `this.name`。

常数用户 = {
名称：“泰勒”，
年龄：32岁，
问候（）{
警报(`Hello, my name is ${this.name}`)
},
妈妈：{
名称：“一月”，
问候（）{
警报(`Hello, my name is ${this.name}`)
}
}
}
    
user.mother.greet()

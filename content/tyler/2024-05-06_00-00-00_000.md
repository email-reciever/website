### 具有效果的类型最大化

你有没有在一个美丽的星期天早上醒来，翻身看着你的另一半，并想，“我只是希望我能想出办法让打字稿对我大喊大叫”？

不是吗？ 好吧，这就是您与最近推出 [first stable release](https://effect.website/blog/effect-3.0) 的 Type-Maxxing Sickos 之间的区别——“Typescript 的缺失标准库”。

Effect 团队认为，TypeScript 缺少大型生产应用程序的一些关键功能，这迫使开发人员用一堆 npm 软件包和时髦的代码填补空白。

因此，他们在过去的五年中建立了数据结构、实用程序和抽象的基础，以解决这些痛点，包括：

*   **内置错误处理原语**，为您提供强类型的错误作为值，用于重试和恢复的API，以及用于日志记录和跟踪的工具
    
*   **内置工具和抽象**用于并发、数据验证、流等等——它可以让您替换大量的一手
    
*   **下一级可组合性**，使您的整个代码库更具可重用性和可测试性
    

但凭借强大的力量，带来了巨大的权衡。 因为效果有很多事情要做，这意味着有很多东西要学习。

有超过 500 个函数、广泛的 API 表面和独特的编程风格，有些人认为它更像是学习 [a whole new language](https://x.com/mattpocockuk/status/1784172952893735014) 而不是库或框架。

但值得庆幸的是，Effect _is_ 实际上是一个打字稿框架。 这意味着您可以逐步采用它，也就是立即找到一些您喜欢的功能，并且永远不会费心学习其余的功能。

**底线：**如果德雷克可以迫使肯德里克近十年来第一次持续发布新音乐，也许效果最终可以帮助我们所有人成为我们一直注定要成为的类型领主。

发现错误：解决方案
-----------------------

#### 赞助[Raygun](https://raygun.com/ai-error-resolution?utm_medium=sponsorship&utm_source=bytes&utm_campaign=ai-er&utm_content=lp)

函数 removeElement(array, elementToRemove) {
for (let i = 0; i < array.length; i++) {
if (array[i] === elementToRemove) {
array.splice(i, 1);
}
}
}
    
让 myArray = [1, 2, 3, 2, 4];
removeElement(MyArray, 2);
    

这个解决方案并不理想，因为它没有考虑到阵列正在被迭代时被修改的事实。 当索引 `1` 处的元素被移除时，索引 `2` 处的元素被移至索引 `1`。

有很多方法可以让这一切变得更好，所有这些都是不同的权衡。 这可能是最好的一种，它使用 JavaScript 的 `filter` 方法在过滤掉 `elementToRemove` 后返回一个新数组。

函数 removeElement(array, elementToRemove) {
返回 array.filter((元素) => element !== elementToRemove);
}

### 捆绑者的战争

在 Bundler Land 度过了忙碌的几周，三个主要的下一代捆绑商都分享了他们的进展情况。

让我们检查每一个并尝试回答我们都在想的问题：这些基于 Rust 的构建工具中的任何一个真的能做到吗？

*   **RSpack**于2023年3月推出，作为更快、更具功能的Webpack的替代品。 他们刚刚发布了一个 [v1.0 alpha](https://www.rspack.dev/blog/announcing-1-0-alpha)，它带有一个用于 Lightning CSS 和各种输出优化的内置集成。
    
*   **TurboPack** 由 Vercel 支持，并于 2022 年 10 月首次推出，将自己作为（自称的）“基于 Rust 的 Webpack 继承者”。 本周早些时候，他们宣布他们正在移动项目的代码库 [into the Next.js monorepo](https://vercel.com/blog/turbopack-moving-homes)，以便现在专注于下一个 .js 用例。
    
*   **rolldown** 是 Vite 的 WIP 捆绑器，旨在将其两个当前捆绑器（ESBuild 和 Rollup）的最佳部分与 Rust 的所有耀眼结合起来。 他们本周一直在分享一些有前途的 [perf improvements](https://x.com/youyuxi/status/1815964252190171496)，由 OXC 提供支持。
    

这些基于 Rust 的捆绑器似乎比 Parcel、Rollup 和 Webpack 等工具更快、更强大。 但批评者可能会问，这一切对于稍微快一点的构建时间和更好的 DX 是否值得？

这些项目需要数年时间才能达到生产准备状态，并且经常被要求缩小其原始范围以专注于一种框架或用例。 这并不是一种批评——但很明显，“只是用 Rust 重写它”比听起来要复杂得多。

**底线：** 许多人（包括我们）已经预测基于 Rust 的构建工具如何接管 JavaScript 生态系统。 如果发生这种情况，必须清楚的是，果汁值得挤压。

发现错误：解决方案
-----------------------

#### 由[Unlayer Embed](https://unlayer.com/embed?ref=bytes)呈现

`this.instance` 是实例属性而不是静态属性，导致每次创建新实例时未定义它，从而无法强制执行单例模式。

为了解决这个问题，我们应该使用静态属性：

类单例 {
构造函数() {
if (singleton.instance) {
返回单例.instance；
}
this.Value = Math.Random();
singleton.instance = 这个；
退回这个；
}
    
getValue()
返回 this.value；
}
}

[Snowpack Releases v3.0](https://www.snowpack.dev/posts/2021-01-13-snowpack-3-0)
--------------------------------------- ---------------------------------------

![Snowpack](https://bytes.dev/images/content/snowflake.png)

一种不同的“雪包”，提高生产力

**这是一个忙碌的一月******************** 它被 [JavaScript Open Source Awards](https://osawards.com/javascript/2020) 命名为“#1 开发者生产力助推器”，庆祝其 v1.0 一周年，并于上周刚刚发布了 v3.0。

（旁注：我们都知道 **Caffeine + TRON 原声带** 是真正的“#1 开发者生产力助推器”。但我们也很高兴 Snowpack。）

**快速回顾：** Snowpack 是 ES 模块的超快速构建工具，可以一次构建您的所有依赖并将它们发送到浏览器。 之后，您的 JavaScript 代码中的更改会立即反映在浏览器中，而无需重新捆绑（不像 Webpack，每次更改后都必须重新捆绑）。

Snowpack 和 Webpack 之间有很多差异，我们没有时间在这里介绍，所以 **这里有一个快速的 tl;dr**

*   **Snowpack 就像 Chipotle。** 它以做一件事非常快而闻名_（捆绑 ES 模块/捆绑巨大的墨西哥卷饼），并且它以一种有意义的简单方式做到了。 它非常新颖和时尚，但它没有提供大量超出其核心功能的选项_（捆绑 ESM / 制作卷饼）。
    
*   ** webpack 就像芝士蛋糕工厂：** 这是一个慢得多的体验，部分原因是它提供了很多选项（大量的 webpack 用例/CF 上的 250 多个菜单项）。 它们，您可以合理地将两者描述为 [“post-modern design hellscape.”](https://twitter.com/MaxKriegerVG/status/931373170791198720) 它们更老和笨重，但如果您知道如何使用它们，它们仍然具有很大的功能和多功能性。
    

现在我们都渴望芝士蛋糕卷饼，**这是 Snowpack 3.0 的新功能。**

*   **Streaming Imports:** 这允许您跳过 `npm install` 步骤，只需通过 ESM 导入按需获取相关的预构建包代码。 并且由于 Snowpack 自动为您缓存了所有内容，因此您可以在第一个包获取后脱机工作。
    
*   ** 与 ESBuild 的新集成：** 现在，您可以插入 Esbuild — [“I’m-100x-faster-than-everyone-and-not-obnoxious-about-it-at-all”](https://esbuild.github.io/) Bundler — 以使 Snowpack 更快。
    
*   **新的 JavaScript API：** 这为您提供了对 Snowpack 开发服务器和构建管道的更高级控制，因此您可以在 Snowpack 上创建更强大的集成。 Sveltekit（Svelte 的新官方 Web 应用程序框架）是在这个新的 API 之上构建的。 考虑到 Svelte 刚刚加冕 [Lord of the Frameworks.](https://2020.stateofjs.com/en-US/technologies/front-end-frameworks/)（完全合法且绝对不是偏见的 JS 调查状态），这是一个相当大的问题。
    

### 底线

如果 Snowpack 发布了付费的高级版本：“Guac 是额外的”，我们已经准备好了完美的标题。

[Vno = Vue + Deno](https://github.com/oslabs-beta/vno)
--------------------------------------------------

![Vno](https://bytes.dev/images/content/vino.png)

再一杯 VNO VINO

**VNO 是一个编译器和捆绑器**，它将自己作为“第一个在 Deno 运行时编译和捆绑 Vue 单文件组件的本机构建工具”。

到目前为止，您无疑已经听到了 Deno 的炒作。 这是 Ryan Dahl 创建的现代、安全的运行时，许多人将其视为 Node.js 的继承人。 这也是[#1 most popular JavaScript project on GitHub last year.](https://risingstars.js.org/2020/en#section-all)

但即使感觉就像我们一直在听说 Deno 一样，V1.0 仍然只有 7 个月大👶。 直到两周前，还没有办法在 Deno 运行时环境中利用 Vue（2020 年最受欢迎的 JavaScript 项目）。

这就是 VNO 的用武之地。

它充当一个适配器，用于解析 Vue 组件文件并将它们编译成一个可以被浏览器读取的 JavaScript 文件。 您可以使用 VNO 模块来获得相当于 Create-Vue-App 的一些 CLI 命令（完整的示例文件结构）。 或者您可以使用它来优化现有的 Vue 项目。

### 底线

VNO 是第一个使开发人员能够在 Deno 环境中使用 Vue 的工具。 这本身就是一个很酷的概念，但它也展示了 Deno 和 Vue 各自生态系统的持续增长和出现。

2020年显然是这两项技术的重要一年，看起来2021年没有任何放缓的迹象。 所有人都在炒作火车上。

js ts提示：为什么是打字稿？
---------------------------

类型是 JavaScript 的基础； 它们会影响您编写程序的方式。 但是 JavaScript 的动态类型系统常常使错误地引用错误类型的变量来引入错误。 我们中有多少人经历过可怕的 `Undefined is not an object` 错误？

TypeScript 是为了在您运行代码之前阻止这些问题的发生而发明的。 它使用 JavaScript 作为基础，添加了一些额外的语法来定义类型，并提供了一种将代码转换回 JavaScript 的工具。 结果是编译器和linter的混合体。 TypeScript 在您编写代码时检查您的代码以确保类型正确，然后将其编译为您需要支持的任何版本的 JavaScript。

TypeScript 是 JavaScript 的超集，这意味着任何 JavaScript 程序也是一个有效的 TypeScript 程序。 这允许 TypeScript 程序导入和使用 JavaScript 代码，这意味着当您开始使用 TypeScript 时，您不必立即重写整个应用程序。 其他开发者工具（如 Babel 或 Webpack）可以配置为处理 TypeScript 文件，而新的 JavaScript 运行时则支持 TypeScript 原生支持。

打字稿如此受欢迎是有原因的。 使用它的开发人员喜欢它提供的类型安全性，同时仍然为他们提供 JavaScript 的灵活性。 以下是您可能会发现 TypeScript 有用的一些原因。

### 类型验证

TypeScript 是一个静态验证工具，如 ESLint。 任何类型的验证工具的目标是增加您对编写的程序的信心，并没有意外的错误。 由于 TypeScript 了解代码库中类型之间的关系，因此使用它可以很好地消除整个类的错误和问题。 当您编写代码时，TypeScript 可以为您提供正确编写代码的提示。 TypeScript 不会取代 ESLint 或自动化测试，但它可以让您更有信心您的代码可以正常工作，而无需运行代码。

### 编译器

TypeScript 也是一个编译器。 与 Babel 一样，它可以转换 TypeScript 和 JavaScript 代码，以支持较旧的 JavaScript 引擎的不同功能。 如果您需要支持像 IE11 这样的较旧的浏览器，TypeScript 可以转换您的代码，以便它可以正常工作。 如果您只需要支持较新的引擎，编译器将剥离类型数据并为您留下有效的 JavaScript。

重要的是要记住，TypeScript 不是一种运行时语言——所有类型都在编译时被删除。 它的目的是鼓励开发人员使用这些类型为您的程序添加检查，以便减少错误和错误。

### JavaScript 超集

TypeScript 可以用作对 JavaScript 的渐进增强。 它是 JavaScript 的超集，因此任何 JavaScript 程序都是有效的 TypeScript。 这包括 NPM 上可用的大量软件包。 但是，如果没有适当的类型注释，大多数 JavaScript 程序都会出现类型错误。 您可以将编译器配置为在将代码库从 JavaScript 转换为 TypeScript 时忽略 JavaScript 程序上的类型错误。

由于 TypeScript 是 JavaScript 的超集，因此 TypeScript 程序中存在许多 JavaScript 的怪癖。 可能并不总是可以将适当的类型注释添加到某物中。 TypeScript 提供了转义舱口，例如 `any` 类型和 `// @ts-ignore` 关闭代码的这些部分的类型检查器。 这就像编写普通的 JavaScript 一样，因此您仍然可以享受动态类型的灵活性。 但是，这也意味着您不能保证您的程序永远不会出现类型错误。 如果您想要一种真正强类型的语言，可以编译为 JavaScript，您可以使用 Rescript 或 Elm 等语言。

### 通信和文档

进入一个全新的代码库可能会令人生畏，特别是如果您不知道所有部分如何连接在一起或应该如何表现。 在代码中添加类型注释消除了很多猜测程序的工作原理，并为任何尝试在您的代码库中工作的人提供指南。

TypeScript 还可以帮助重构。 如果没有 TypeScript，您无法知道在更改某些内容时需要更新的所有不同位置。 Typescript 会根据可能受到影响的任何其他文件检查您的更改，并在任何内容损坏时发出警告。 剩下的就是遵循每个警告并进行适当的更改，而无需运行您的代码。

### 底线

简而言之，TypeScript 将通过在运行之前检查代码来帮助您编写具有较少错误的代码。 添加这些类型可能需要一些工作，但从长远来看，它肯定会得到回报。

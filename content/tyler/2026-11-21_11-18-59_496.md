打字稿回来爬行
------------------------------

自从微软决定他们不想成为 [part of the JavaScript family anymore](https://www.youtube.com/watch?v=TUCUsNx1HTs&t=138s) 并自己创建 TypeScript 已经过去了 10 年。

但是上周，TypeScript终于回来并提交了一个[official TC39 proposal](https://devblogs.microsoft.com/typescript/a-proposal-for-type-syntax-in-javascript/)，建议将“可选和可擦除的类型语法引入JavaScript”🤯

**为什么？** TypeScript 很棒，但它仍然需要一个构建步骤来 _remove_ 那些令人讨厌的类型，以便 JS 引擎可以实际运行代码。

这个“类型作为评论”提案（又名“不是我，不是你”）将允许在JavaScript中使用typescript风格的注释，但让js引擎完全忽略它们。 可以在浏览器或 nodejs 中运行而无需任何修改。

该提案将解决 [most requested JavaScript features](https://2021.stateofjs.com/en-US/opinions/#currently_missing_from_js_wins) 之一 - 但我们知道您有问题，因此我们为您提供了此常见问题解答：

*   ** JavaScript 是不是得到静态类型？
    
*   **这不会使我的JS捆绑包膨胀？** minifiers可以剥离生产代码的类型注释。 该提案在开发或较小的站点期间最有帮助。
    
*   **但我讨厌打字稿！**不是问题，而是公平。 这些类型注释是完全可选的，因此您的旧 JavaScript 代码将运行得很好。
    
*   **您是否有点担心微软可能会达到其 [old tricks](https://en.wikipedia.org/wiki/Embrace,_extend,_and_extinguish) 尝试对 Web 开发生态系统施加更大的影响？**该死的，我现在。
    

**底线：** 自从我热爱 CrossFit 的素食叔叔来过感恩节以来，我还没有看到 [this many opinions](https://twitter.com/search?q=https%3A%2F%2Fdevblogs.microsoft.com%2Ftypescript%2Fa-proposal-for-type-syntax-in-javascript%2F&src=typed_query) 的东西。

面对反应犀牛
-----------------------

对于所有在令人毛骨悚然的蒂姆伯顿电影中长大的 90 年代孩子来说，这是一个热门话题：React 18 基本上已经成为_[James and the Giant Peach.](https://www.youtube.com/watch?v=S5LgsqYQJMs&t=41s)_ 的巨型犀牛

我们来看看证据：

1.  它又大又强大，有点吓人
2.   _really_ 花了很长时间才到达这里，但不知何故总是在后台隐约可见
3.  它正在成为我们早期儿童创伤的精心隐喻（好吧，也许这只是我）

但经过几个月的等待，我们几乎是时候面对野兽了。 第一个 [React 18 RC](https://reactjs.org/blog/2022/03/08/react-18-upgrade-guide.html) 上周发布，这意味着我们离一般版本只有 _(检查注释)_“至少几周”。

**期待什么：**

*   **并发模式 _features_** — 亮点包括 [SSR with selective hydration](https://github.com/reactwg/react-18/discussions/37)（帮助您的应用加载并更快地互动）和 [`startTransition`](https://github.com/reactwg/react-18/discussions/41) （在大屏幕更新期间保持您的应用程序响应）。
    
*   **suspense** — 希望这能杀死所有“悬念正在杀死我”的双关语。 我再也受不了了。 好的，让我们继续。 _wtf 确实 `<Suspense>` \*实际上\* do?_ tl;dr — 它让您的组件“等待”某些东西（如数据）在渲染之前。 React 18 将为所有 Suspense 功能提供稳定的支持，包括令人兴奋的新内容，例如数据提取 (!!)。
    
*   **新根 API** — `ReactDOM.createRoot` 将替换 `ReactDOM.render()` 作为“启动”您的 React 应用程序的方式。 当您切换到 `createRoot` 时，您将默认获得 React 18 的所有新功能。 不错。
    

**但有好消息：** React 18 升级不应该_实际上_那么可怕，即使有所有重大的新功能。 这是因为 React 团队巧妙地选择了避免全有或全无的并发“模式”方法。 相反，他们采用了逐步的、选择性的采用并行“功能”的方式。

这意味着您可以将您的应用程序升级到 React 18 并使用 [minimal or no breaking changes](https://reactjs.org/blog/2021/06/08/the-plan-for-react-18.html#a-gradual-adoption-strategy)，然后随时开始引入花哨的新功能——一次吃一口大象犀牛。

**Botton Line:** 许多框架和库落入了认为良好的开发人员体验简单意味着“尽可能快地添加更多功能”的陷阱（_\*cough_\* Vue _\*cough_\*）。 但是，很高兴看到 React 团队对 _how_ 的考虑与创建功能本身一样深思熟虑。

花了很长时间吗？ 是的。 值得吗？ 起初我并没有完全_确定——但后来我看到 React 18 也是 [killing support for IE](https://reactjs.org/blog/2022/03/08/react-18-upgrade-guide.html#dropping-support-for-internet-explorer)，现在我 100% 参与。

🔬 发现错误解决方案 — 由 [WorkOS](https://workos.com/?utm_source=bytes&utm_medium=newsletter&utm_campaign=presenting+feb+2022) 赞助
------------------------------------------------------------------- -------------------------------------------------------------------

当您在数组上调用 `array.push` 时，它不会返回更新的数组，而是返回具有新项的数组的 `length`。 这意味着您不能将 `.sort()` 调用链接到结尾，因为 `.push` 的结果是一个数字。

有两种方法可以解决此问题。 一种选择是在 `.push` 呼叫后调用 `array.sort()`。

函数 addAndSort(数组, 元素) {
array.push(元素)
返回数组.sort();
}
    

第二个选项将该项附加到带有 `array.concat()` 的新数组，然后对新数组进行排序。

函数 addAndSort(数组, 元素) {
返回 array.concat(元素).sort();
}

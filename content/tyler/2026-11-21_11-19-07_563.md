Vueniverse 的麻烦？
---------------------------

Vue 一直像 JavaScript 生态系统中的酷 [SoundCloud rapper](https://soundcloud.com/CHANCETHERAPPER) 一样——它不像一些同时代的人那样主流，它拥有一个超级热情的粉丝社区，他们喜欢它没有一个巨大的大型公司支持的事实。

但过去几年在Vue-Land一直很困难，从2020年9月Vue 3的发布开始。

那是因为 Vue 3 是为了扩大规模。 他们完全重新编写了虚拟DOM，并引入了一组新的类似React Hooks的[APIs](https://vuejs.org/guide/extras/composition-api-faq.html)来“解决Vue在大规模应用中使用的痛点。”

但在 18 个月后，很明显，这些大规模升级已经在生态系统中造成了一些挥之不去的碎片化——Nuxt 3 仍处于测试阶段，而 Vuetify（最流行的 Vue 组件库）仅在 Alpha 中使用其 Vue 3 更新。 其他库也有 [struggled with the migration](https://www.lindsaykwardell.com/blog/coming-into-vue-whats-next-vue-3/)，这要归功于新的主要版本。

可以想象，这让 Vue 开发人员的生活变得更加不方便——他们想使用 Vue 3，但他们最喜欢的 UI 框架或组件库可能不兼容。

如果 Vue 得到一家拥有不间断货币打印机的大型科技公司的支持，您可以提出这种迁移 _Might_ 的痛苦不那么痛苦，但我也足够大，可以记住 Angular.js，所以谁知道呢。

**底线：** 许多独立艺术家努力进入主流，同时仍然忠实于获得他们的 OG 粉丝。 Vue 现在也感受到了同样的成长痛苦——但好消息是，一旦生态系统_finally_赶上了Vue 3，它们应该比以往任何时候都更强大。

世纪之光

生日快乐视觉工作室🎂
------------------------------

Visual Studio 即将 [turn 25](https://visualstudio.microsoft.com/)，和我们中的许多人一样，它是一个大器晚成的人。

早在 1997 年，它最初是 Visual Basic、Visual C++ 和 Visual FoxPro 的三个独立 IDE 的集合（我们检查了与 Starfox 没有关系）。 它们都来自单独的 CD，您必须从商店_购买_购买。 在 90 年代，“窃取软件”意味着在 [The Italian Job](https://youtu.be/thjtHfVkPAU?t=104) 中的马克·沃尔伯格 (Mark Wahlberg) 中，在当地的赛道城市设置抢劫案。 我们称之为黑暗时代是有原因的。

2002 年，我们获得了 Visual Studio .NET 版本，它带有一种名为 C# 的全新编程语言。 这个有趣的小奖金功能是由 Anders Hejlsberg 创建的，他十年后继续创建 TypeScript 🐐。

接下来的约 18 年也是如此。 一路上，Visual Studio 能够放弃 CD，但该软件本身仍然相当臃肿且相对不受欢迎。 VS 终于在 2015 年推出了 ✨glow-up✨ ，当它推出 VS_Code_ 时，我们都知道并且（大部分）喜欢打字稿作为关键成分。

快进到今天，超过 70% 的 Web 开发人员使用了 VSCode，现在我们使用了 [writes our code](https://copilot.github.com/)。 Visual Studio IDE 仍然存在，但 .NET 开发人员主要使用它来做他们所做的任何事情。

**底线：**这些都与我个人无关，因为我在完成在白板上绘制它后立即在Apple Notes应用程序中编写了所有代码 - 但我想如果您正在调试代码和其他内容，那就太酷了。

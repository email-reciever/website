### ASTRO 2起飞

上次我们写关于 Astro 的文章时，我们最喜欢的 [Diet JavaScript](https://bytes.dev/archives/113) 框架刚刚发布了 v1，并使用其岛屿架构来帮助我们所有人都摆脱了一些不需要的位。 现在，太空船员又回来了一项任务——帮助你指挥你的无法无天的降价。

如果您在大型内容或 ECOMM 网站上工作，您将非常熟悉 Markdown 的限制。 不一定是 Markdown 是坏的，而是它周围的工具很糟糕——而且我们所说的糟糕的意思是不存在。

也就是说，直到现在。

这个想法很简单，如果我们有类似 TypeScript 的经验，但 Markdown 会怎样？ 不需要大量的创造力就可以实现这将实现什么——验证、类型安全、自动完成、SEO 建议、内联类型错误，以及如果我们幸运的话，可能会得到一些积极的肯定。

这正是 Astro 2 的 [Content Collections API](https://astro.build/blog/introducing-content-collections/) 所支持的，作为在 Markdown 文件上花费的时间比我睡觉的时间更多的人，这很令人兴奋。

但这并不是 Astro 2 拥有的唯一功能，它还带有：

*   混合渲染结合了SSR和SSG，为您提供灵活性和出色的性能。
    
*   重新设计的错误叠加使调试问题更容易且更美观。
    
*   对热模块重新加载的一些不错的改进，以及对Vite 4.0的升级。
    

**底线：** 将自己与顽固型书呆子对齐是 Astro 保持炒作火箭嗡嗡声的明智方式_\*（TRPC 批准点头）\*_，我们在这里。

很酷的位

1.  在提示时，Alex MacArthur 写了一篇名为 [What I Like About Astro](https://www.macarthur.me/posts/what-i-like-about-astro) 的博客文章。 说到，我们仍在等待你们中的一个人写一篇名为“我喜欢字节的什么”的好文章。
    
2.  CallStack 创建了 [The Ultimate Guide to React Native Optimization](https://www.callstack.com/campaigns/download-the-ultimate-guide-to-react-native-optimization?utm_campaign=RN_Performance&utm_source=email&utm_content=bytes_quick_link_sponsor) — 它们确实意味着“终极”。 这本电子书长 207 页，比 Udemy 上的一半课程要好。 它也是 \*free\* 并由 React Native Core 贡献者编写，因此您知道它是合法的。 \[赞助\]
    
3.  Mokshit Jain Created [Typewind](https://github.com/mokshit06/typewind)，它（正如您可能猜测的那样）是 Tailwind 的类型安全版本。 类型书呆子的力量正在巩固。
    
4.  来自 React Core 团队的 Andrew Clark 写了一篇关于 [“If you use React, you should be using a React framework.”](https://twitter.com/acdlite/status/1617611126514266112) 的 _controversial_ 推文主题。 然后他澄清说“[You should clean your ass after pooping](https://twitter.com/acdlite/status/1617717183341289472?cxt=HHwWgIDTwaHNpPMsAAAA)”。
    
5.  Vladimir Klepov 写了一篇关于 [Making sense of TypeScript using Set Theory](https://blog.thoughtspile.tech/2023/01/23/typescript-sets/) 的深入文章。 但在你真正理解打字稿或集合论之前，你需要理解博弈论，如果不理解模拟理论，你就无法真正理解博弈论，在你理解日心说理论之前，所有这些理论都是一文不值的。 因此，如果您想擅长 TypeScript，您不妨从 Copernicus 开始。
    
6.  [Kysely](https://github.com/koskimas/kysely) 是类型安全的 SQL 查询生成器。 就像我说的，你要么与类型的书呆子保持一致，要么你被抛在后面。
    
7.  Darius Cepulis 在 MUX 博客上写了关于 [The building blocks of great docs](https://www.mux.com/blog/the-building-blocks-of-great-docs) 的文章。 说到这一点，街上的消息是，这次新的 React 文档是 [almost _done_ done](https://twitter.com/dan_abramov/status/1617858054908973056?s=20&t=HF1jwx7T24W8Kg5mdF34AQ) 是真的 [almost _done_ done](https://twitter.com/dan_abramov/status/1617858054908973056?s=20&t=HF1jwx7T24W8Kg5mdF34AQ) _(\*drink\*)_。 但从技术上讲，丹从未说过“没有回馈”——所以是的，我们可能还有几个月的时间。

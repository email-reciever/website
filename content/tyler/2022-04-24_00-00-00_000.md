**🔬 实验 #1：全局 `fetch` API** — 这提供了通过 HTTP 请求获取数据的标准，该请求类似于流行的 node-fetch 库，但“尽可能接近于浏览器规范。” 节点团队已经为此工作了 4 年，但事实证明它仍然 [impossible to please everybody.](https://twitter.com/matteocollina/status/1517617719838973953)

**🔬 实验#3：Web Streams API** — 17 个不同 API 的实现是 [a lot](https://twitter.com/tmcw/status/1515093531660062725?s=20&t=ajoM7gmXyRrtt6gagKKWjw)。 但其想法是，它允许您使用 JavaScript 以编程方式访问数据流并以多种不同的方式处理它们。

**底线：** 我们很高兴看到 Node 如此高效，尽管自从爸爸 Ryan Dahl 离开以来，他们一定一直在处理被遗弃的问题。

我的 Innie 试图弄清楚 WTF “The Edge”是

Netlify 和 Deno 正在 Edge™ 合作
-------------------------------------------

Netlify 和 Deno 刚刚宣布 [that they’re partnering](https://www.netlify.com/blog/announcing-serverless-compute-with-edge-functions) 以提供边缘功能——一种新的无服务器计算产品。 鉴于开发人员比我岳母的 Flat Earth Facebook 群组更引用“The Edge”，我们可能应该解决最重要的问题。

“The Edge”，也称为辛辣内容交付网络 (CDN)，已经存在了一段时间。 CDN 提供基础设施来缓存静态内容并将其从最近的服务器交付给最终用户。 Cloudflare 在 2017 年发布 Workers 时更改了游戏，从而可以在边缘运行 JavaScript。

从那时起，托管服务提供商一直在积极追求自己的“边缘计算”产品。 与 Workers 一样，Deno & Netlify 的新产品建立在 V8 JavaScript 引擎之上，并具有与浏览器中的服务工作者相似的 API。 以下是一些亮点：

1.  廉价 — 比标准无服务器功能便宜 24 倍（免费 300 万/月）。
    
2.  快速 — 如果没有容器的开销，边缘函数可以更快地启动并运行更接近用户，从而减少延迟。
    
3.  Web API — 因为它们是基于 Web 标准构建的，因此可以在没有许多先前权衡的情况下将代码从客户端移动到服务器。
    
4.  新范式 — 边缘渲染 [can be nearly as fast](https://twitter.com/rauchg/status/1517644556023463936) 作为服务静态文件，可能会改变开发人员对构建应用程序的看法的范式。
    

*******比我在高中时更喜欢“The Edge”（壁橱 U2 粉丝 - 糟糕的决定），但对于像 Cloudflare、Deno 和其他 Homies 这样的公司来说，“The Edge”肯定看起来像 [next big thing](https://www.youtube.com/watch?v=F7IZZXQ89Oc)。

🔬 发现错误 — 由 [PostHog](https://posthog.com/?utm_source=bytes&utm_medium=newsletter) 赞助
---------------------------------------------- -----------------------------------------------

`||` 运算符检查虚假值，`0` 是一个虚假值，它会意外应用默认税率。 要解决此问题，您可以使用 Nullish Coalescing (`??`) 运算符来检查虚假值。

函数 calcprice(价格、税收、折扣) {
税=税？？ 0.05；
折扣=折扣?? 0；
    
退货价格 - 价格 * 折扣 + 价格 * 税；
}
    

空的合并运算符是因为它在左侧操作数为 `null` 或 `undefined` （不是 0）时返回其右侧操作数，否则返回其左侧操作数。

### 评分我们的2022年预测

世界冠军健美运动员和哲学家罗尼·科尔曼 [famously said](https://youtu.be/4UlgXIL0-3g?t=11)，“每个人都想成为一个 JavaScript 思想领袖，但没有人愿意给予那些沉重的**\*。”

好吧，我们在这里认真对待我们的手艺——所以当我们接近另一个幸福的一年结束时，让我们回顾一下我们去年一月的预测，看看我们是怎么做的。

**Prediction #1:** Next.js 将不再是 React 元框架，而是更多的 _\*web\*_ 元框架。

**等级：D-.**如果有的话，Next.js在2022年变得更加同义。 Vercel 肯定是在使用其他前端框架，但 Next 本身正在加倍投入 React 的承诺（并从成为爸爸的最爱中获得好处）。

**预测 #2：** 风险投资将“解决” OSS 资金……一段时间。

**等级：A-.** 事实证明，因为有很多 GitHub 明星，给预收入 OSS 公司可能不是最可持续的投资策略。 我想 OSS 作者总是可以回到 [selling backlinks](https://bytes.dev/archives/134) 到在线赌场和杂草药房？ 平静地迎接美好时光。

**预测 #3:** Remix 将被 Netlify 收购。

**等级：B+。** 我们是如此接近。 太近了。 但如果你闭上眼睛并快速做 `prediction.replaceAll("Netl", "Shop")`，我们完全做到了。

**预测 #4：** Babel 和 Webpack 将在很大程度上被更新的工具所取代。

**等级：A.** 我们正在经历下一代构建工具的复兴，它比我们想象的更快地改变游戏。 我们让 Tobias Koppers（Webpack 的创建者）在 Turbopack 上全职工作，“Webpack 的 Rust 驱动的继任者”。 Vite 成为主流，每周下载量增加到 250 万次。 和 Esbuild、Bun 和 Rome 等其他工具也在快速增长。

**预测 #5:** Meta 将放弃对 React 的控制，并将其放在第三方基础的照顾下，就像 GraphQL 一样。

**等级：F+。** 发生了吗？ 不，它是否接近发生？ 也没有。 但是，人们是否会争辩说，Meta 将 React 的一些更实用的 DX 开发外包给了 Next.js 和 Vercel，因此放弃了对 React 的一些控制？ 当然可以，特别是如果您正在寻找任何可能的方法来旋转您在 11 个月前做出的错误预测。

**预测 #6：** Serverless 将帮助前端开发人员成为真正的全栈开发人员并（希望）获得相应的报酬。

**等级：B-.** MetaFrameworks，如 Next、Sveltekit、Astro 和 Remix 无缝集成到我们的应用程序中，为我们提供全栈超级大国。 但是我们都得到了更多的报酬吗？ 不完全是。 （该死的，杰罗姆·鲍威尔。）

**预测 #7:** React 18 将在 2022 年 _\*Launch\*_。

**等级：A+, 10/10, 💯.** 我们有时有疑问，但很高兴看到我们的 _\*Boldest\*_ 预测成真是很高兴的。

**底线：** 像这样让自己承担责任会使我们的 2023 年预测变得更好吗？ 只有一种方法可以找出答案。

1.  我们关于 [The Story of Next.js](https://www.youtube.com/watch?v=BILxV_vrZO0) 的视频即将在 YouTube 上达到 450,000 次观看。 我们在 Vercel 的前朋友仍然没有承认它的存在。 没关系，我已经有 32 年的时间试图获得我父亲的爱，所以我已经习惯了。 可能是[this clip](https://www.youtube.com/watch?v=BILxV_vrZO0&t=577s)，不是吗？
    
2.  [MelonJS 2](https://github.com/melonjs/melonJS)是流行的JS游戏引擎的新现代化版本。 不要与 _cocomelonjs_ 混淆——一个静态站点生成器，它为您的博客提供了一堆预构建的 Cocomelon 主题。 JJ 和 Yoyo 主题是免费的，但其余的费用为 9.99 美元（请记住使用我们的附属代码，`COCOBYTES`）。
    
3.  [OpenNext](https://github.com/serverless-stack/open-next) 是 Next.js 的开源无服务器适配器，这听起来也是 MTV 上有问题的 2000 年中期约会节目的完美标题。
    
4.  React 团队是 [renaming the experimental useEvent to useEffectEvent](https://github.com/facebook/react/pull/25881) 并且正在缩小其范围。 这很有趣。 我们都玩得很开心。
    
5.  Dan Christofi 写了关于 [A Few Times CSS Container Queries Would Have Helped Me Out](https://css-tricks.com/a-few-times-container-size-queries-would-have-helped-me-out/) 的文章。 如果你只是让他们帮助你，丹，这些查询会对你有所帮助。
    
6.  Tkdodo 写了他自 2018 年以来的经历 [Working with Zustand](https://tkdodo.eu/blog/working-with-zustand)，远在替代国家管理库变得酷和时尚之前。
    
7.  Jake Lazaroff 写了关于 [His First Take on Solid as a longtime React Developer](https://jakelazaroff.com/words/a-react-developers-first-take-on-solid/) 的文章。 如果您一直好奇，这是一个有用的切入点。
    
8.  NextAuth（用于 Next.js 的流行 auth 库）[is going framework agnostic](https://vercel.com/blog/announcing-sveltekit-auth)，从对 sveltekit 的实验支持开始。 当他们掉落 Cocomelonauth 时叫醒我。

### 将“P”置于 NPM 中

PNPM 周二刚刚发布了 [v9.0](https://github.com/pnpm/pnpm/releases/tag/v9.0.0)，改进了锁文件格式，更好地解决了对等依赖关系，以及一些您可能不会注意到的小改进。

但是你知道什么是不可能的_NOT_注意吗？ PNPM 的爆炸式增长。

自从我们一年前写过关于他们的文章以来，他们的每周下载量增加了 3 倍，在前一年增长了 5 倍。 对于你们数学专业的学生来说，这是一个 15 倍的跳跃 _在两年内 - 使他们每周下载 1100 万次，这是 YARN 获得的两倍多。

那么 PNPM 的独特之处是什么，是什么推动了其疯狂的增长？ 让我们潜入。

**快速背景：** 早在 2017 年，Zoltan Kochan 发布了 PNPM 的 V1，TIL 代表“性能 NPM”。 我一直认为它代表“肺炎 NPM”，因为每当我使用它时，我的肺就会充满液体——但事实证明，这只是因为我的旧办公室有一堆石棉🙃。

但“性能 npm”是一个很好的名字，因为这正是它的本质——一个更快、更有效的 npm 替代品，它带有更好的 monorepo 支持，主要感觉就像你只是在使用 npm。 这是它的工作方式：

*   使用 YARN 和 NPM，如果您有 100 个项目依赖您的机器，您将在磁盘上保存 100 个该依赖项的副本。 他们通过使用提升来展平他们的 `node_modules` 来解决这些依赖关系。 这会占用大量磁盘空间，并可能导致安装速度较慢（您可能已经经历过）。
    
*   PNPM 的主要见解是使用内容可寻址的商店，它仅将您的每个依赖项存储在您的主文件夹中的全局存储中一次。 如果您需要不同版本的软件包，则只会将不同的文件添加到存储中（而不是整个软件包）。
    
*   他们通过 [非平面 `node_modules` 目录](https://pnpm.io/symlinked-node-modules-structure) 执行此操作，它创建了一个嵌套的依赖结构，文件夹中的每个包和文件都很难链接到商店——节省了你的时间和磁盘空间🤝。
    

**底线：** 到目前为止，PNPM 9.0 看起来像是主要版本的 [exactly what you want](https://x.com/cpojer/status/1780510838459342974) - 进行了可靠的改进，具有最小的破坏性，同时易于升级。 谁知道它是否会严重挑战 NPM 的软件包管理器，但它显然达到了“易于采用”的最佳位置，并且“对于某些用例来说明显更好”。

您是否知道 Chrome DevTools 有一些由 `$` 提供支持的神奇快捷方式？ 以下是一些最有用的：

`$()` - 是 `document.querySelector()` 的别名。 它允许您选择与给定的 CSS 选择器匹配的第一个元素。 例如，`$('div')` 将返回页面上的第一个 div 元素。

`$$()` - 是 `document.querySelectorAll()` 的别名。 它返回与给定的CSS选择器匹配的所有元素的数组。 例如，`$$('div')` 将返回页面上的所有 div 元素。

`$0, $1, $2, ... $n` - 是对您最近在“元素”面板中选择的元素的引用。 `$0` 代表最近选择的元素，1 美元代表最近的第二个元素，依此类推。

`$_` - 表示控制台中最近评估的表达式的值。

`$x()` - 允许您使用 XPath 表达式查询 DOM。 例如，`$x("//div")` 将返回页面上的所有 div 元素。

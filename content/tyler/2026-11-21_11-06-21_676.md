### 向 JavaScript 添加信号

您可能听说过 Preact、Angular 和 Solid.js 等框架使用的 Reactivity 信号——但是两个 TC39 代表 Rob Eisenberg 和 Daniel Ehrenberg 只是通过提交 [an official proposal](https://github.com/proposal-signals/proposal-signals) 将本机信号添加到 JavaScript 中，将事物提升到了一个新的水平。 规格。

他们为什么要这样做？ 这是一个好主意还是一个可怕的想法？ wtf 信号真的会再次发生吗？

别担心，我们已经为您提供了保障。

**快速审查：** 信号是您向应用程序添加状态的一种方式。 但与 React 不同，每次状态更改时，您的应用程序都会重新渲染，信号会启用 _granular_ 状态更新。 这意味着当一个信号值发生变化时，只有最必要的更新 UI 的工作才会发生——没有渲染，也没有差异。

这使您的应用程序可以跳过昂贵的渲染工作，并且可以非常适合性能。 但是，将信号添加到 JS 规范的理由是什么，而不是仅仅允许各种框架以自己的方式（或根本不允许）提供信号？

该提案给出了一些令人信服的原因：

*   **互操作性** — 通过将反应模型与渲染视图分离，内置的 JavaScript 信号将允许您在不同的 JS 框架之间共享模型、组件和库。
    
*   **Better DevTools** — 您可以更好地支持从浏览器和运行时检查信号，Element Inspector 和 Memory Profilers 等现有工具可以特别突出信号。
    
*   **改进的 DX** — 拥有一个标准库意味着更小的捆绑包大小、更好的稳定性和质量、更少的框架特定内容以及 JS 开发人员更常见的词汇表。
    

**底线：** 这个阶段 0 提案的下一步将是大量的原型设计和与多个框架的集成，以查看它们是否能够真正实现上面列出的好处。

如果一切顺利，他们将继续通过不同的审批阶段进行提案，我们可能会在2029年的某个时候在我们的应用程序中使用它——假设当时没有发生奇点🫡。

发现错误：解决方案
-----------------------

#### 赞助[Knock](https://knock.app/channels/slackkit)

出现此错误是因为 `split` 方法将字符串视为 16 位单元的数组，而不是导致意外输出的字符数组：`!�� ,olleH`。 通过使用 `Array.from(str)` 或 `[...str]`，字符串被拆分为一个实际字符数组，以尊重替代对。

使用`Array.from`：

函数 reverseString(str) {
返回 array.from(str).reverse().join("");
}
    
让 ReverseDstring = ReverseString("你好，👋！");
console.log(reversedString);
    

使用扩展运算符：

函数 reverseString(str) {
返回 [...str].reverse().join("");
}
    
让 ReverseDstring = ReverseString("你好，👋！");
console.log(reversedString);

NPM 的卫生干预
------------------------------

NPM 在 1 月份年满 12 岁——而且像大多数其他青少年一样，它的卫生有时可能非常有问题。 （如果您不相信我，请查看您的 `node_modules`。）

因此，像任何好朋友一样，Feross Aboukhadijeh 和他的团队上周在他们推出 [Socket.dev](https://socket.dev/) 时对 NPM 进行了干预——这是一种新的安全工具，可以通过一些有意义的方式改善您的 `node_modules` 卫生。

**它是如何工作的：** Socket 监控对您的 npm 软件包的更新并识别恶意软件包更新。 这种类型的漏洞被称为供应链攻击（[log4j](https://www.ftc.gov/news-events/blogs/techftc/2022/01/ftc-warns-companies-remediate-log4j-security-vulnerability) 使它们出名），这通常是由于以下原因发生的：

*   **name 混淆** — noblox.js-proxied(good) vs noblox.js-proxy(bad) 或在公共 npm 注册表上镜像内部包名称
*   **被劫持的包裹** — 被盗或出售给不良演员的包裹
*   **安装脚本** — 在安装期间运行恶意代码
*   **混淆** — 发布到 npm 的代码与 GitHub 上显示的不同
*   **政治议程** — 🥲

（查看 [Socket’s article](https://socket.dev/blog/inside-node-modules) 了解完整故事。）

考虑到应用程序中约 90% 的代码来自开源，因此很高兴知道有一个现代解决方案可以避免这些问题，这会变得非常可怕。 幸运的是，Socket 对所有开源项目都是免费的，并且可以作为 GitHub 应用程序安装。

**底线：** 我猜这使 Socket.dev 成为适用于所有 npm 卫生问题的斧头身体喷雾（除了它确实有效）。 现在，他们只需要用 [Phoenix and Essence](https://www.google.com/search?q=old+school+axe+body+spray&tbm=isch&ved=2ahUKEwjQxbneqLL2AhVDsFMKHREXDNMQ2-cCegQIABAA&oq=old+school+axe+body+spray&gs_lcp=CgNpbWcQAzoHCCMQ7wMQJzoICAAQgAQQsQM6CAgAELEDEIMBOgQIABBDOgUIABCABDoHCAAQsQMQQzoLCAAQgAQQsQMQgwE6BggAEAgQHjoECAAQHlCbCFjzJGCXNWgAcAB4AYABmASIAZoTkgEKMjMuMS4xLjUtMZgBAKABAaoBC2d3cy13aXotaW1nwAEB&sclient=img&ei=rRglYpC7IsPgzgKRrrCYDQ&bih=984&biw=1792#imgrc=-ZBzOc3VuSX_WM&imgdii=Pzrjndchp6mtLM) 之类的气味命名他们的新版本即可真正推动隐喻回家。

大逃杀：React Native vs. Flutter
--------------------------------------

**让我们准备隆隆声……**跨平台风格。

最近有很多关于 Flutter vs. React Native 的嗡嗡声，所以我们也想参与这部戏剧。 [\*_Ding ding_\*](https://www.youtube.com/watch?v=e5XAY7aYU98)

**在红角**我们有 React Native。 早在 2015 年，它就突然出现，将我们的灵魂从地狱 PhoneGap 中拯救出来，使 Web 开发人员能够使用他们的 JavaScript 和 React 技能来构建跨平台的移动应用程序——最终，桌面应用程序、智能电视应用程序，甚至 [web apps](https://necolas.github.io/react-native-web/)（全圈）。

**在蓝色的角落** 我们有颤动。 它出现在2017年，将Google的Dart编程语言与[high-performance graphics engine](https://docs.flutter.dev/resources/architectural-overview#architectural-layers)编译成本地机器代码或JavaScript的[high-performance graphics engine](https://docs.flutter.dev/resources/architectural-overview#architectural-layers)相结合。 它已被用于构建从您妈妈的普锐斯的信息娱乐系统到 [Wallace & Gromit AR mobile app](https://flutter.dev/showcase/wallace-gromit-ar) 的所有内容（我不建议在食用时玩）。

React Native 一开始就取得了很大的领先优势，但 Flutter 在过去几年中一直在翻转剧本——追赶 RN 甚至 [surpassing it in popularity](https://www.statista.com/statistics/869224/worldwide-software-developer-working-hours/)（取决于你相信谁）的三个主要原因：

*   更好的开发人员体验（又名不可怕的文档）
    
*   [Better performance](https://medium.com/swlh/flutter-vs-native-vs-react-native-examining-performance-31338f081980)，由于它的C/C++渲染引擎编译为本机代码的方式
    
*   更容易的学习曲线。 这是违反直觉的，但使用 Flutter，您只需要学习如何使用 Dart 和 Flutter 相当简单的小部件系统。 React Native 允许您使用您的 React/JS 知识——但它通常需要您学习 [a bunch of other native technologies](https://www.reddit.com/r/reactnative/comments/sd3mo4/who_else_can_relate/) 才能构建您想要的内容（即使这通常可以产生更本机的 UI）。
    

React Native 近几个月来通过对其文档和核心进行了重大改进，解决了其中一些问题。 RN 仍然可以依靠其强大的生态系统和全能的 [Atwood’s Law](https://blog.codinghorror.com/the-principle-of-least-power/) 推动其向前发展。 今天有一个比 Flutter 应用程序更多的世界级 React Native 应用程序是有原因的。

**底线：** 很明显，Google 和 Meta 都有很强的经济动机继续投资这些项目，因此可能不会有一个明确的赢家。 好消息是，我们可能都会受益，因为“一次写一次，在任何地方运行”革命不断向前发展。

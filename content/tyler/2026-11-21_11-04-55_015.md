### Vitest 和测试的未来

作为一个（据称）不写任何测试的人，我可能看起来不是最有资格写上周 [Vitest 2.0 release](https://github.com/vitest-dev/vitest/releases/tag/v2.0.0) 的人。 但如果我从看布朗尼·詹姆斯打篮球的时候学到了什么，那就是“有资格”为你的工作被高估了——所以让我们系好安全带。

**快速回顾：** 在过去的几年里，Viste 已经悄悄地成为了 JavaScript 生态系统中增长最快的测试框架，每周下载量达到 500 万次。 成为 Vite 的默认测试运行器绝对有帮助，但它不仅仅是一个 Nepo 婴儿。 使用 Viste，您可以获得更现代的 Jest 版本，它更快、更容易配置，并使用您已经知道和喜爱的相同 Jest API。

Viste 2.0 继续以一个名为 **Browser Mode** 的主要新功能为基础，这是 Viste 对组件测试的看法，其中有一些有趣的转折：

*   **没有更多的“假DOM”** - 浏览器模式建立在Playwright的顶部，并在iframe中渲染组件，使用真实的浏览器事件来测试您的代码。 这使您的组件测试比 JSDOM 和快照测试更准确，更不容易出错。
    
*   **Unified Tooling** – 在 Viste 之前，组件测试要求您为 Jest、StoryBook 和 Webpack 创建单独的配置。 现在，您可以利用用于捆绑应用程序的相同配置来运行单元和组件测试。
    
*   **一个新的甜蜜点** - 历史上单元测试和端到端测试之间存在一个缺失的中间位置。 浏览器模式可能是缺少的成分，它使组件测试足够有用，可以实际投资于前进。
    

**底线：** 这是一个 Vite 世界，我们都只是生活在其中。

从事件处理程序返回 false 将禁用复选框的默认操作。 这意味着该复选框在单击时不会更改其状态。 您可以使用 `void` 运算符来防止返回值干扰默认操作：

      <p id="message"></p>
    
      <script>
checkbox.onclick = () => 无效句柄点击();
    
函数handleClick() {
如果（复选框。选中）{
message.textContent = "复选框被选中！";
返回真；
} 其他{
message.textContent = "复选框未选中！";
返回假；
}
}
      </script>
    </html>

GitHub 代码空间是未来吗？
--------------------------------

微软一直致力于控制开发人员的授权 [while now](https://www.youtube.com/watch?v=KMU0tzLwhbE)。 而随着上周的 GitHub Codespaces [announcement](https://github.blog/2021-08-11-githubs-engineering-team-moved-codespaces/)，看起来他们的总体规划终于要结合在一起了。

**WTF 是代码空间？** 它是云中功能齐全的开发环境，基本上将 Microsoft 的所有开发人员工具合二为一。 它从 Azure 配置存储和计算资源，从 GitHub 中提取代码，并为您提供 VS Code（包括扩展名）的编辑功能——直接在浏览器中。

**但不是基于云的 IDE 主要很烂吗？** 是的，这是真的（至少以前是这样）。 多年来，我们已经看到 Cloud IDE 的三个主要类别出现，其中大多数都非常有限：

*   ** HTML、CSS 和 JavaScript** ScratchPads**（如 CodePen 和 JSBin.com） — 有助于构建小型浏览器小部件，但功能不足以构建全面的应用程序。
    
*   **Container App Sandbox**（如 CodeSandbox 和 Stackblitz）——您可以在容器中运行 Node.js，但仅此而已。 你最好祈祷不要超过记忆限制。
    
*   **Provisioned IDE 服务器**（如 Cloud9） — Cloud IDE 的宜家。 您可以获得一个预配的服务器和一个二流的浏览器编辑器，但您必须自己设置和配置其他所有内容。
    

但是代码空间改变了一切。 它允许您执行本地计算机可以执行的所有操作（访问终端、运行服务器、执行测试、同步本地 VS 代码设置等）——但可以从世界上的任何计算机中执行。 这也意味着单个配置更改可以将您的开发环境从 Dinky 1 CPU 8GB RAM 服务器升级为强大的 32 内核 64GB RAM 怪物。

**底线：** CodeSpaces 是一种付费产品（免费试用将于 9 月 10 日结束），因此很难预测最终将有多少开发人员最终使用它。 但就像一枚戒指一样，很难不被它的力量所吸引。 想试一试吗？ 前往 [this repo](https://github.com/remix-run/react-router) 并按 `.`。

Next.js 现在支持 ESM
-------------------------

当Next.js上周发布v11.1时，它（遗憾地）这次没有提供吉列尔莫家的_mtv cribs_\风格的游览（猜猜我们将不得不等待下一个.js conf才能看到他的 浴室）。

但 v11.1 版本确实带来了其他一些重大新闻——团队现在正在努力在 Next.js 中支持“广泛 [ES Modules](https://www.youtube.com/watch?v=7BQWndkI1mg) 支持”这一事实。 目前，您可以使用 ESM 实验导入 npm 包，但 `esmExternals: true` 将成为 next.js 12 中的默认值。

除了 ESM Stans 的巨大胜利外，Next.js 11.1 还有一些其他很酷的新东西：

*   [Adopting SWC](https://nextjs.org/blog/next-11-1#adopting-rust-based-swc) — 这个基于 Rust 的编译器是 [super fast](https://swc.rs/docs/benchmark-transform/) 并将很快在 Next.js 中替换 Babel 和 Terser。 Vercel 甚至聘请了 [SWC’s creator](https://twitter.com/kdy1dev) 作为全职员工，因为当你在银行里有 1 亿美元时，你 [love Rust](https://twitter.com/rauchg/status/1425520232202792962) 比沙拉自己的手指还要多。
    
*   [Better performance](https://nextjs.org/blog/next-11-1#improved-performance) — SWC 尚未完全集成，但它已经导致测试中的构建速度是两倍。 但是，您应该立即注意到此版本的性能更好，特别是在预渲染、从无头 CMS 中获取内容或在应用程序中包含源地图时。
    
*   [`next/image` 改进](https://nextjs.org/blog/next-11-1#nextimage-improvements) — 静态图像导入现在自动延迟加载，内置图像优化器现在可以自动检测外部图像内容类型。
    

**商务谈话：** 德雷克在 3 月份用他的单曲 [“What’s Next”](https://www.youtube.com/watch?v=3jo8E95fDqA) 对我们大发雷霆。 因此，Vercel 的下一个业务（在购买 MTV 面包车之后）应该是付给 Drizzy 的任何钱，以便及时为下一个.js 12 版本写一首新歌——“下一步，下一步是什么？”

-----------------

我们得到 `undefined`、`Jordyn`、`Jake`，然后 `Tyler`。 这向我们展示的是，您可以将每个新的执行上下文视为拥有自己唯一的变量环境。 即使还有其他包含变量名称的执行上下文，JavaScript 引擎将首先查看该变量的当前执行上下文。

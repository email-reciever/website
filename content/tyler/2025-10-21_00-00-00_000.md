### 我超级甜蜜的下一个.js 16

本月早些时候，Vercel 暂时从中东的冲突中休息，发布了 [Next.js 16 beta](https://nextjs.org/blog/next-16-beta)——他们已将 TurboPack 正式命名为默认的 Bundler™️。

我们已经写过它如何提供高达 5-10 倍的开发刷新速度和 2-5 倍的构建速度，最好的部分是您现在可以通过零配置获得这些收益。

但 Next 16 的真实故事是其路由和导航系统的“彻底改革”，旨在使客户端过渡更精简、更智能：

*   **Layout Deduplication** – 当预取多个共享布局的 URL 时，它现在只下载一次该布局，而不是每个链接一次。 因此，具有 50 个链接的产品网格获取一种布局，而不是 50 个。网络膨胀的大幅下降。
    
*   **增量预取** – 不是提前获取整个页面，接下来的 16 个只获取尚未在缓存中的部分。 它在时序方面也变得更加智能——当链接离开视口时取消请求，在数据过期时重新预取，并在悬停时提高优先级。 你会看到更多的请求，但每一个都要小得多，这会产生更低的转移成本。
    
*   **Better Caching API** – 一个新的 `updateTag()` 和升级的 `revalidateTag()` 让您可以更明确地控制陈旧的数据更新时。 `updateTag()` 为用户操作提供即时“读写写入”，而 `revalidateTag(tag, 'max')` 处理后台 SWR 而不会阻塞。
    

**底线：** 在明天开始之前，将此视为您的开胃酒，希望黑暗三角形会对我们所有人微笑。

发现错误：解决方案
-----------------------

#### 赞助[Sentry](https://sentry.io/product/seer/?utm_source=bytes&utm_medium=paid-community&utm_campaign=seer-fy26q3-seerlaunch&utm_content=newsletter-seer-presenting-sponsor-learnmore)

在原始代码中，Service Worker 在安装时缓存资产，但当资产发生变化时，它不会更新缓存。 这意味着如果您更新 CSS 或 JS，服务工作者仍将提供旧版本。

要解决此问题，我们可以使用 `cache.put()` 方法在资产发生变化时更新缓存。

// service-worker.js
const cache_name = "site-static-v1";
const assetsToCache = ["/", "/index.html", "/css/style.css", "/js/script.js"];
    
// 安装事件
self.addEventListener("安装", (Event) => {
事件.等待直到（
caches.open(cache_name).then((cache) => {
cache.addAll(assetStocache);
})
);
});
    
// 获取事件
self.addEventListener("获取", (事件) => {
event.respondWith(
caches.match(event.request).then((CacherEsponse) => {
返回（
缓存响应 ||
fetch(event.request).then((fetchResponse) => {
返回 caches.open(cache_name).then((cache) => {
cache.put(event.request.url, fetchResponse.clone());
返回获取响应；
});
})
);
})
);
});

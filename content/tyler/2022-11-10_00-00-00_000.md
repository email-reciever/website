### 介绍人的路由器™️

在周二的 JamStack Conf 会议上，Tanner Linsley（React Query and Friends 的创作者）登上舞台，为我们所有人描绘了一幅勇敢的新（类型安全）世界的画面。

在这个世界上，我们不需要担心全局或服务器状态（至少不是那么多）——因为我们不应该像 [TBL](https://www.google.com/search?q=who+invented+urls&oq=who+invented+urls&aqs=chrome..69i57j0i22i30l2.2264j1j7&sourceid=chrome&ie=UTF-8) 那样在 URL 中存储尽可能多的状态吗？ 毕竟，链接是“便携式状态”的 OG 形式，它们本质上是可共享的、可收藏的和历史的。

Next.js 和 React Router 已经为我们提供了 API 来帮助我们管理 URL 结构中的路径参数和搜索参数，但它们仍然给我们留下了两个问题：

1.  Next 和 RR 的方法并不总是能很好地扩展，因为它们假设您使用的搜索参数、平面键值对和字符串（现实通常比这更复杂）。
    
2.  Next 和 RR 自然排除了所有非 React 框架。 （混音没有，但稍后会详细介绍。）
    

那么坦纳做了什么？ 他把自己锁在楼梯下的黑暗壁橱里几个月（哈利波特风格），直到他拿出了一些魔法。 周二，他公布了 [TanStack Router](https://tanstack.com/router/v1) — 一个可扩展的 _framework-agnostic_ 路由库，将 URL 的全部功能带给未洗过的大众。

以下是此测试版的更多亮点：

*   **100% typesafety** 表示路由器从路由定义完全推断为渲染，因此您可以在任何地方自动完成，您不必担心编写不安全的路由。
    
*   **状态管理器等级搜索参数** 带有模式和验证、自定义解析和序列化以及不变性，以使在URL中轻松存储各种状态而不会触发不必要的副作用。
    
*   **内置缓存**具有自定义缓存定时和自动预加载，以更快地加载页面。
    

**底线：** TanStack 路由器无疑建立了来自 Remix、Next 和 React Router 的流行路由模式和想法，同时将其提升到一个全新的水平，并将其扩展到 React 生态系统之外。

![lodash vs ramda vs underscore](https://bytes.dev/images/content/fp-trends.jpg)

函数式编程 OG 的数据 – [npmtrends.com](https://npmtrends.com/lodash-vs-ramda-vs-underscore)

就像超级紧身牛仔裤一样，JavaScript 中的函数式编程风靡一时。 这在很大程度上要归功于 Legend Jeremy Ashkenas——CoffeeScript（对 ES6 的设计有很大影响）、Backbone（将 MVC 模式带到 JS）和 Underscore（将更广泛的 JavaScript 社区引入函数式编程）的作者。

如果您不熟悉，下划线、Lodash 和 Ramda 是处理数据的可组合函数的集合。 那么这些天大型函数式编程库是怎么回事呢？

*   **FP 在 JS 中放慢速度：** 从趋势图中，我们看到 3 个最受欢迎的库的整体增长似乎正在放缓。 一般来说，Svelte 或 Vue 等反应性系统的普及率有所增加，它们观察突变而不是使用纯函数和不变性（另请参阅 Mobx vs Redux）。
    
*   **浏览器/ESM支持：**下划线的两个继任者，Lodash（最初是作为分叉）和Ramda（吸引了硬核FP Nerds），通过支持ESM和捆绑器对更多的浏览器和捆绑器进行了工作。 树木摇晃。 这有助于他们变得比 OG `_` 更受欢迎。
    
*   **语言更新：** JavaScript 规范添加了许多新功能，使像这样的实用程序库变得不那么必要。 话虽如此，JS 中的函数式编程故事似乎受到缺乏 [pattern matching](https://github.com/tc39/proposal-pattern-matching) 等功能的阻碍。
    
*   **未来：** 现实是 JavaScript 将继续发展，但记住我们站在巨人的肩膀上总是很好的——Lodash 和像 FP 这样的范式将继续产生影响。

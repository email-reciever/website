# But humans wrote slop too!

September 2, 2026

![Beethoven&#x27;s 9th Symphony manuscripts](/_astro/header.glsBBmGH_1g3tmV.jpeg)

That’s the argument I get every time I dare criticize code and content that’s too close to the default weights of an LLM.

> _Humans write slop too!_

If anything, this is an improvement, an increase of the baseline.

The kind of slop humans wrote is a lot sloppier than the off-the-shelf AI slop we get nowadays. Social media posts used to be full of grammatical errors, code used to be buggy and unstructured, and it barely got the job done.

I’ve written entire articles on the importance of good code comments and how to write them.

So I should be happy now.

I’m drowning in code comments.

Why get all nostalgic over organic grass-fed slop?

![Back in my day, slop was good.](/_astro/back-in-my-day-slop-was-good.g6krjo9K_Z3ccKu.jpeg)

**Because it’s proof of thought.**

Someone did the thinking.

It may not have been a lot of thinking, it may not have been great thinking, not even good thinking, but some thinking happened.

Someone put their mind to it and birthed that monstrous code that pushes the Geneva Convention to its limits. And if you find the person who created it, they would most likely tell you the reason behind every cubic inch of that garbage.

The code I read today feels like it was written by Clean Code absolutists who were finally given free rein to write the overly abstract, generic implementations they’ve been dreaming about for a decade.

Communication is becoming more generic too.

Read some posts on LinkedIn.

Take a look at some of the long messages you get on Slack.

The text looks better, it’s grammatically excellent and well-structured, but sometimes I just can’t understand what people are trying to say. Every time I get a wall of text, I know I’ll be playing the game of finding the one sentence in the whole paragraph that’s relevant to me.

> _Yes, this is true Alex, but let’s zoom out a bit and take a look at the bigger picture_

I don’t need Pangram to tell me who wrote this.

See, back in my day I’d just get one sentence.

It would be impolite, error-ridden garbage in the grammatical sense, but it would be the original thought.

* * *

The baseline has increased, but not everything needs to be at the new baseline.

I’ve been studying design this year _(UI/UX/Interactions)_, and many of the interfaces that seem beautiful at a glance suffer from the same overly-abstract sloppification that we see in code and writing.

You don’t need an eyebrow over every section title.

The same way you don’t need the custom stringify method.

The same way you don’t need two paragraphs.

I was wondering if it’s the lack of taste showing through this, because once you develop an eye for code, UIs, and prose, the slop-era software feels like you’re interfacing with public administration.

A lot of overhead for no reason.

Maybe it’s the lack of care.

Every now and then I think about Taylor Otwell’s obsession with comments in the Laravel codebase.

![](/_astro/image-3.CG6xFCVu_2uqXwR.png)

Each implementation comment needs to be exactly 3 lines, and every new line must be 3 characters shorter than the one before.

![Reddit post](/_astro/reddit-post.CRSR0feF_2nUH6U.png)

> _It is indeed intentional. I’m not sure if it’s awesome or neurotic either… :) Also, it is not just config files – it is the entire framework. Config files are the first impression of the framework once you have it installed. So, I want it to be pleasant to the eye. The symmetrical comments help with that. I don’t want your first impression of the code to “appear” disorganized or something. I dunno. It’s kind of crazy. I do it with all of the Laravel core code. If it doesn’t look pleasing to the eye, I keep working on it until it is._
> 
> **Taylor Otwell**

I started my programming career with Laravel, and I remember how well-structured Taylor’s code looked in some of the tutorial videos, and the haiku-esque comments contribute greatly.

Formatting text to make it look good is a lot of work.

Hyphenation and justification are hard to get right, so in the 1990s rs1n solved the structure problem in the Super Metroid guide with… word choice.

![I just chose words carefully](/_astro/i-just-chose-words-carefully.DlYZVHNL_1JT7A7.avif)

These are the kind of things I’m nostalgic about.

* * *

Writing is the by-product of a more abstract ability we call thinking.

> _If you’re thinking without writing, you only think you’re thinking._
> 
> Leslie Lamport

Without writing, your thoughts remain abstract and scattered. When you put them into words, they need to take a specific, pristine shape that you can show to others. Code, by extension, has that same property.

With LLMs, we can front-load that thinking and skip the physical process of writing.

But if you don’t formulate that pristine thought, then you get a result that’s as abstract as it was in your head - no matter if it’s code or prose or design.

Because if you’re writing without thinking, you only think that you’re writing.

我曾经会像圣诞节早晨的孩子一样对主要库的发布感到兴奋。我会打开文档，查看所有新的API，就像一个新的乐高套装一样。标准库的新添加，一个新的公共函数可以节省一些编写，语言类型系统的变化。

我会完全沉浸在它们中。

但是过去两年里，我已经没有这种感觉了。

现在一切都是关于人工智能。

一切都是关于最新的模型，每个公告听起来都像苹果的发布会。它总是最好的模型，相比之前的模型，它的性能提高了一个数量级，并且减少了我们编写的代码量。

我希望我能对这样的消息感到兴奋。

我真的希望如此。

但它们只是不是具体的产品。

早期依赖这些模型的软件现在暴露在复杂的代理架构中，它们提供了动力。它不再是一个模型，而是一个整个系统。

![Claude intervention notice](/_astro/claude-intervention.Dewbc_Bp_Zaf3Ai.png)

因此，在前沿模型中，产品的概念是相当流动的。

Anthropic 进行了一次调整，结果突然在某些领域表现不佳。他们再进行一次调整，情况就有所改善。他们可以阻碍特定的使用场景，如模型训练 *(刚刚读了一篇关于此的博客文章)*。

> 我们已经实施了新的干预措施，限制 Claude 在针对边缘 LLM 开发的请求中的有效性……

因此，你可以在没有版本、API 更改或甚至成本更改的情况下，故意获得工具的较差版本。

我并不对此感到兴奋，因为我并不拥有它。

我无法将其打包到我的构建中。

它是一个无版本的外部依赖，它在我脚下变化。

但要跟踪其他工具很难，因为模型的发展对我的工作影响远大于 JavaScript 库。

代码生成对我的生产力和可维护性影响更大，而不是新的 API 或框架。因此，坚持使用流行的工具（LLM 已经接受过这些工具的训练）变得更加有意义，这使我对跟踪小型新库的兴趣降低了。

我从未想到自己会成为这个行业中的保守派。

新的 API 和工具意味着代码生成的问题。它意味着我无法正确地审查代理的代码质量。它意味着我不知道使用正确的模式。

它意味着变化。

而最近一切都发生了这么多变化，以至于我渴望有一点稳定和枯燥。

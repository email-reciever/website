十年前，软件正在吞噬世界。

但当时吞噬世界的并不是复杂的软件。相反，是那些已经被编写了成千上万次的代码 - 网站、新闻稿订阅表单、支付集成和各种 CRUD 应用。

问题在于，突然每个人都需要这样的软件。

因此，我们通过增加更多的编程人员来强行推动其开发。

学术界需要 3-4 年的时间来培养工程师和问题解决者，但行业需要编码者。

我们需要能够编写代码的人，能够找到解决问题的方法并重现它的人，能够足够流利地与 CPU 交谈以向其翻译出较为优化的指令的人。

但是，同样，这些问题已经被全球无数开发人员解决过很多次，并且没有太多的问题需要解决，只需要研究和模式匹配。

我是那个时代的产物。

在潜意识层面上，我很快意识到自己正在做的只是真正的软件工程的一个子集。

有一刻，触发了我脑海中的一系列神经事件。

我的同事们正在讨论新项目中的服务如何相互通信，当有人问我有什么想法时，另一个同事说：

> Pfft, Alex, 都不知道什么是指针……

而且他是对的。

我不知道什么是指针。

我可以写代码，我可以构建应用程序，但我不知道这个基本的知识，你可以在 CS 101 中学习到。

**我只是一个搞代码的猴子。**

我的工作就是在网上寻找解决问题的方法，记住一些语法， 然后再次再次地在装配线上生产。

我在不知道什么是指针的情况下构建应用程序。

**我的工作就是这么简单。**

我就像一家快餐厅的厨师，我不知道如何制作一顿正餐，但我知道如何遵循系统。我只是把已经调味好的肉扔到烤架上，解冻汤，使用现成的混合调味料来调味沙拉。

但是我想成为更多。

我想讨论以希腊神命名的微服务 *(当时的时尚)*，模块结构，负载均衡器和 API 设计。

在过去的十年里，我看到这个行业向成千上万的人承诺，它不关心逻辑原则，基础知识是浪费时间的，他们可以记住API，并专注于某种技术作为职业。

但这是一个假承诺，很多人现在都感受到了。

人们长期以来一直将编写代码与构建软件混为一谈，而现在这个行业需要构建者。

我将坦白地说，我曾经喜欢编写代码。

也许我喜欢它有点过头了。

在很长一段时间里，这是我创造性抱负的出口，我甚至可以在非常简单的代码的边缘找到表达自己的地方。

但是我现在很少这样做了。

我不再像以前那样深入地探索技术和问题，这让我爱上了这门手艺。太想省略库API的细节，让LLM来总结它们，做一些修改，确保可维护性，避免bug，然后发布。

这不是关于工作保障的存在主义文章。

这是关于意义和满足感。

编排代理的行为对我来说太……像管理了。我离开了工程管理岗位，回到成为一名个体贡献者的角色，但似乎这只是一种自由意志的幻觉。

所有的道路都通向同一个地方。

我前几天晚上在看“**The Bear**”，其中一个角色说了一句话，这句话一直留在我的脑海里。

> 你找到了一件你爱的事情，这完全没问题，如果你现在不再爱它了……

我真的觉得自己最近在强迫自己去爱编程。

别误会，我喜欢构建东西，喜欢看到自己的想法快速变为现实，喜欢拥有无穷无尽的调试想法，喜欢看到计算机做新的事情。

但是我的一部分觉得，这又回到了当代码猴子的状态，只是方式不同。

手写代码给我提供了理解问题的深度思考的节奏。在公司工作几年后，我已经非常熟悉代码库的每一个角落，每一个服务和每一个脚本。

我发现现在很难说出同样的话。

> 如果你在不写代码的情况下思考，你只是以为你在思考。
>
> **Leslie Lamport**

我会怀念按 Tab 键添加制表符的日子，而不是接受光标建议。

在很多情况下，手写代码已经不再有意义。

Agent 更快、更便宜，而且让我可以在确定解决方案之前尝试更多的想法。我手动进行小的修改，当代码太具体无法解释时，我自己编写代码。

但是当我开始一个新功能时，我会使用 Agent 创建基本结构。我告诉它我需要什么接口、什么结构，然后我填充内容。

**但这样做让我感觉像是在别人的代码库中工作。**

所以我正在寻找安慰，学习更多关于分布式系统、UX 和如何成为一个编辑而不是作家。

我正在不同的领域寻找意义和创造性的满足感。

这并不容易。

但有一天，我会告诉我的年轻同事，我如何手写整个应用程序。

> 现在的孩子不知道什么是真正的工作。
>
> **我，未来**

我会让人无法忍受。

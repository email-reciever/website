2026年我的前端堆栈
============================

第559章 2026年5月31日

> Petar 分享了他们不断返回的 15 种工具，React 就是其中之一

[My frontend stack in 2026](https://thetshaped.dev/p/my-frontend-stack-in-2026-react-nextjs-pnpm-vite-ts-tailwind-storybook-tanstack-zustand-zod-oxlint-oxfmt-msw-vitest-playright-sentry)  
_9 分钟_ 由 Petar Ivanov

Petar 分享了他们在 2026 年在九个类别中不断使用的 15 个工具。 这些选择涵盖了从框架和样式到测试和错误监控的所有内容。 每个工具都通过做好一件事、与其他工具干净地作曲和远离来赢得自己的位置。 核心思想很简单：最好的堆栈是你停止注意到的。

[How toCancel useFetcher load on unmount in React router](https://sergiodxa.com/tutorials/cancel-usefetcher-load-on-unmount-in-react-router)  
_4分钟_由塞尔吉奥·哈兰布里

React Router V7 中的获取器在组件卸载后仍然存在，因此即使在 UI 消失后，Flight 请求也可以继续运行。 如果您的加载程序呼叫上游服务，这将变得浪费。 修复是两个步骤：将请求.signal 转发到加载器内的上游获取，然后在 useEffect 清理中调用 fetcher.reset，以便请求取消组件卸载的那一刻。

[Component architecture for React server components](https://aurorascharff.no/posts/component-architecture-for-react-server-components/)  
_23分钟_由Aurora Scharff

React 传统上在路由顶部获取数据并通过道具传递下来。 这会产生紧密耦合的组件和不受控制的加载状态。 React Server 组件提供了更好的方法：每个组件在服务器上获取自己的数据，保持组件的独立性和可重用性。 悬念边界让你有意识地设计加载体验，决定什么时候流入而不是把它留给网络。

[TanStack router and query](https://tkdodo.eu/blog/tan-stack-router-and-query)  
_8分钟_多米尼克·多夫梅斯特

Dominik 解释了 TanStack 路由器如何与 TanStack Query 协同工作，以改进 React 应用程序中的数据获取和缓存。 他强调了将路由加载器与查询一起使用以获得更快的导航、预取和更好的用户体验的好处。 他还使用 TanStack Start 介绍了缓存管理、悬念集成和服务器端渲染，同时为可扩展且高效的应用程序推荐了一种查询优先的方法。

[How a bloom filter can 404 your pages](https://darios.blog/posts/the-ghost-in-your-nextjs-router)  
_5分钟

增量 next.js 迁移同时运行两个路由器依赖于 Bloom 过滤器来决定链接是否需要完整页面重新加载或平滑的客户端转换。 此过滤器是概率性的，可能会失火，当与基本路径设置结合时，生成的硬导航会将 URL 中的前缀加倍，导致 404。将 experiment.ClientRouterFilter 设置为 false 配置中将禁用过滤器并停止问题，尽管您可能 然后需要手动管理跨路由器转换。

反应在其西格玛时代
========================

第532章 2025年11月16日

> 将红牛换成抹茶，最后学会用useEffect设置边界

[React 19.2: React in its sigma era](https://dev.to/sagi0312/react-192-react-in-its-sigma-era-op7)  
_5分钟_安居卡兰吉

React 19.2 引入了一个自动处理优化的编译器，无需手动记忆。 活动组件将组件保留在后台，而不是完全卸载它们，保留状态。 Chrome DevTools 中的新调试工具显示了渲染和组件的详细性能细分。 该框架还通过将加载状态批量批处理加载状态以获得更流畅的用户体验来改进服务器端渲染。

[MCP Authorization in 5 Easy OAuth Specs](https://workos.com/blog/mcp-authorization-in-5-easy-oauth-specs?utm_source=reactdigest&utm_medium=newsletter&utm_campaign=q42025)  
_由工作赞助_

安全地授权访问 MCP 服务器曾经是一个悬而未决的问题。 现在有一个明确的答案：OAuth。 本指南分解了使其在实践中发挥作用的五个规范，涵盖委托、令牌交换和范围访问。 WorkOS 将所有内容打包到一个 API 中，因此您可以跳过构建自己的 OAuth 堆栈。

[Synchronizing timers in React](https://www.dzialowski.eu/synchronizing-timers-react/)  
_3分钟_卡罗尔·迪亚沃夫斯基

Karol 引入了一个 React 钩子，可以跨多个组件同步定时器。 当不同组件使用具有相同延迟的单独间隔，导致它们不同步时，就会出现问题。 该解决方案创建了按延迟时间对回调进行分组的共享“桶”。 当间隔触发时，同一存储桶中的所有回调同时执行。 这在确保其计时器保持同步的同时保持组件独立。

[React 19 error boundary behaves differently](https://andrei-calazans.com/posts/react-19-error-boundary-changed/)  
_2分钟_安德烈·卡拉赞斯

React 19 更改了错误边界在同一边界内处理多个错误的方式。 以前，React 会尝试渲染每个失败的组件两次并记录重复的错误。 现在它在第一个错误发生后停止并跳过共享相同错误边界的同级组件。 这减少了不必要的资源使用并消除了重复的错误日志，允许开发人员简化其错误处理代码。

[Everything you need to know about act() in tests](https://howtotestfrontend.com/resources/react-act-function-everything-you-need-to-know)  
_11 分钟_ 如何测试前端

React() 的 act() 函数可确保在断言运行之前完全处理状态更新和副作用，从而防止测试读取陈旧的 UI。 本文解释了 act() 的作用，何时需要，以及 React 测试库如何经常自动处理它。 它还涵盖了常见的警告、调试步骤和最佳实践，以避免不必要的 act() 的使用，同时保持测试的准确性和可靠性。

[Don't blindly use useTransition everywhere](https://www.charpeni.com/blog/dont-blindly-use-usetransition-everywhere)  
_6 分钟_ 尼古拉斯·查彭特

React 的 UseTransition Hook 通常被推荐用于改善用户体验，但在被误用时会造成 UX 的糟糕情况。 基本文档示例显示了一个选项卡式界面，在其中单击慢速选项卡显示“待处理”状态，同时显示旧内容，这让人感到困惑。 Nicolas 提出了更好的方法，例如使用延迟组件来生成控制以重新进行 React，或者将其与 useTransition 相结合以获得更多控制。

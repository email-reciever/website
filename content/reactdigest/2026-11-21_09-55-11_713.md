本周的最爱
---------------------

[Clean Code vs. Dirty Code: React Best Practices](https://reactdigest.net/link/4518/{SUBSCRIBER_ID}/{MEDIUM})

简洁的代码是一种一致的编程风格，使您的代码更易于编写、读取和维护。 开发人员通常会花时间在问题上，一旦问题解决，他们就会提出拉取请求。 我认为，您的完成并不是因为您的代码“有效”。

[The Performance Cost of Server Side Rendered React on Node.js](https://reactdigest.net/link/4522/{SUBSCRIBER_ID}/{MEDIUM})

虽然我喜欢结构和有效性保证的概念，但我确实认识到它在构建单个视图服务器端的工作方式上存在很多开销。 这就是为什么我决定检查与更传统的模板引擎相比，它们在字符串上工作并且不保证结构的开销有多少。

[9 React Component Libraries You Should Know In 2018](https://reactdigest.net/link/4528/{SUBSCRIBER_ID}/{MEDIUM})

React 的虚拟 DOM，描述性地描述用户界面和建模该界面的状态的能力，以及一个像样的 JavaScript 开发人员的低门槛，所有这些都使 React 成为构建 UI 的绝佳库。

[Building a GraphQL API with Node JS and React](https://reactdigest.net/link/4530/{SUBSCRIBER_ID}/{MEDIUM})

GraphQL 是一种用于构建 Facebook 引入的 API 的新查询语言。 在某些情况下，它比 REST API 更方便，并且应该在某些区域替换 REST。 GraphQL 方法的主要优点是您只需要一个由 POST 方法驱动的端点，而不是 REST 中的几个端点和 HTTP 方法。

[Internationalization for react done right](https://reactdigest.net/link/4532/{SUBSCRIBER_ID}/{MEDIUM})

该模块断言，需要为您的组件加载所需的翻译，并且您的内容会因语言更改而被重新呈现。 基于零依赖性和构建工具 react-i18next 也最适合服务器端渲染。

[Advanced React state boundaries in a real Next.js app](https://www.nirtamir.com/articles/advanced-react-questions)  
_11分钟_ nir tamir

NIR 描述了如何跨越现代 Next.js 应用程序的边界管理状态。 他涵盖了 URL 状态、浏览器 API、TanStack 查询缓存、React Server 组件、客户端上下文和乐观更新。 主要教训是明确定义谁拥有每个状态，React 应该如何应对变化以及应用程序的不同部分如何保持同步。

[React 19 useActionState explained](https://shubhra.dev/tutorials/react-19-useactionstate)  
_13分钟_由Shubhra Pokhariya

React 19 的 UseActionState 钩子替换了手动管理表单提交状态的重复模式。 传递一个动作函数和一个初始状态，它返回当前状态、表单动作和待处理的标志。 最大的生产错误是使用本地挂起的标志而不是内置的标志，它可以让用户对重复提交进行排队。 Shubhra 建议跳过它以获得乐观的更新、多步骤向导或与表单无关的任何内容。

[Generative user interface](https://boda.sh/blog/generative-ui/)  
_13分钟_ 赵博达

生成性 UI 用适应用户实际需求的动态界面元素替换 AI 文本的墙壁。 存在三种方法：从工具结果映射的静态组件、声明式 JSON 规范以及沙盒化 iframes 中的开放式代码生成。 这些不是相互排斥的，生产应用程序可能会将这三者结合起来。

[Async hydration in Preact](https://jovidecroock.com/blog/resumed-hydration-preact/)  
_7 分钟_ 乔维·德·克鲁克

Preact 已经通过悬念边界支持异步保湿，让页面的部分独立而非一次性交互。 Hydration 2.0，在 Preact 11 中，通过在服务器 HTML 中标记确切的 DOM 范围，修复针对错误节点的边缘情况，使其更加可靠。

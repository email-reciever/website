[Critical vulnerabilities in React and Next.js](https://www.wiz.io/blog/critical-vulnerability-in-react-cve-2025-55182)  
_3分钟_吉利·蒂科钦斯基

React Server 组件中的两个关键漏洞允许攻击者在没有身份验证的情况下在服务器上远程执行代码。 使用默认设置创建的标准 Next.js 应用程序很容易受到攻击，只需精心设计的 Web 请求即可利用。 根据 Wiz 研究数据，这些缺陷会影响 39% 的云环境。 需要立即修补，因为现在可以使用硬化版本。

_8分钟_科尔比·西斯克

设计系统通过提供共享的指南、组件和标准来帮助团队创建一致的产品。 但是，构建自定义组件库会导致维护问题并减慢开发速度。 Kolby 建议从 Mantine 等开源组件库开始，然后添加设计语言、Figma 库和自定义主题。 这种方法减少了摩擦，同时保持产品的一致性。

[React has changed, your hooks should too](https://allthingssmitty.com/2025/12/01/react-has-changed-your-hooks-should-too/)  
_5 分钟_ 马特·史密斯

大多数开发人员仍然使用 React Hooks，例如旧类方法的简单替换，但它们实际上是一个更好的应用程序结构的设计系统。 最大的错误是在处理网络调用等实际副作用时过度使用 useEffect 。 Modern React 为订阅提供了更好的工具，例如用于订阅的 UseSyncExternalStore 和用于流畅用户界面的 UseEferredValue。 Custom Hooks 应专注于将业务逻辑与 UI 组件分开，使代码更简洁、更易于测试。

_17分钟_弗朗西斯科·米兰达

[Create a copy as markdown button for MDX documentation site](https://amanhimself.dev/blog/create-a-copy-as-markdown-for-mdx-documentation/)  
_10 分钟_ 由阿曼·米塔尔

Aman 解释了如何向基于 MDX 的文档站点添加“复制为 Markdown”功能。 MDX 页面通常包含动态组件，因此无法直接复制原始文件。 解决方案是获取原始 MDX、移除导入、展开场景、转换自定义组件和渲染 API 部分成纯 Markdown。 该过程使用可适用于任何文档站点的分步转换管道。

18个月的代码，消失了
==========================

第549章 2026年3月22日

> 在1.5年后重建整个产品并放弃没有测试的凌乱代码库的旅程

[18 months of code, gone. Here's what we learned.](https://tompiagg.io/posts/we-threw-away-1-5-years-of-code)  
_11分钟_汤姆·皮亚乔

Tom 分享了 1.5 年后重建 Autonoma 整个产品的旅程，放弃了一个没有测试并造成真正客户损失的混乱代码库。 由于测试、安全性、性能和可观察性方面的严重问题，他们远离了 next.js 和服务器操作。 新的堆栈使用 React、TRPC 和 Hono，将内存使用量从 8GB 减少到几乎没有。 更好的 AI 模型也使他们的旧复杂浏览器自动化代码变得不必要。

[Your auth UI should look like the rest of your app](https://go.clerk.com/StwcnSe)  
_由文员赞助_

Clerk 的预构建组件是完全可主题的——现在有一个可视化编辑器可以毫无猜测地完成它。 使用实时反馈调整颜色、排版、间距和边框，直到登录流程感觉到您的产品原生。 没有留下Auth Flavor的默认设置。

[Bippy: Toolkit to hack into React internals](https://www.bippy.dev/)  
_10 分钟_ 艾登·白

Bippy 是一个工具包，可以通过假装是 React DevTools 来访问 React Internals。 它连接到 React 读取的全局窗口对象，让您可以访问包含组件道具、状态和上下文数据的光纤树。 它适用于 React V17 到 V19，不需要更改您的 React 代码。 实用程序函数简化了遍历光纤，在运行时覆盖道具或状态，并跟踪实际渲染的组件。

[Singletons aren't as evil as you think](https://dev.to/link2twenty/react-singletons-arent-as-evil-as-you-think-44m8)  
_7 分钟_ 安德鲁·伯恩

React 中的单身人士名声不好，但他们可以通过正确的方法干净简单。 通过扩展像 EventTarget 这样的原生 JavaScript 类，Andrew 向您展示了如何构建单例，以便在其状态更改时触发事件。 将此与 React 的内置 useSyncExternalStore 钩子配对可以使您的 UI 自动同步，无需轮询或手动刷新。

[Making sense of key prop in React](https://inside-react.vercel.app/blog/making-sense-of-key-prop-in-react)  
_9 分钟_ 由 Sankalpa Acharya

React 在调解过程中使用 Key Prop 跟踪列表项。 Sankalpa 指出，如果没有键，React 将纯粹按位置匹配旧元素和新元素，这会导致它在项目移动时重用错误的组件实例。 这会导致像状态这样的错误在排序后坚持错误的项目。 一个稳定的唯一键，如数据库 ID，准确地告诉 React 哪个项目是正确更新 DOM 的。

[Let your project structure tell the story](https://thetshaped.dev/p/screaming-architecture-and-colocation-nodejs-typescript-react)  
_4分钟_由佩塔尔·伊万诺夫

按功能而不是按技术层组织代码使项目一目了然更容易理解。 文件夹结构应该揭示应用程序的功能，而不仅仅是它使用的工具。 Petar 建议将测试、类型和实用程序等相关文件保持在使用它们的代码附近，并且仅在多个功能真正需要时才将内容移动到共享文件夹中。 使用工具强制执行这些边界，以便结构随着时间的推移保持清洁。

[Still writing tests manually? Meticulous AI is here](https://www.meticulous.ai/?utm_source=react-digest&utm_medium=newsletter&utm_campaign=26q1&utm_content=secondary)

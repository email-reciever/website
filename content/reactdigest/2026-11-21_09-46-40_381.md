React 应用中的组件通信模式
=======================================================

第563章 2026年6月28日

> 正确的选择取决于组件的距离以及它们需要共享的数据类型

[Component communication patterns in React applications](https://neciudan.dev/component-communication-patterns-in-react)  
_23分钟_ 内修丹

React 组件可以通过多种方式共享数据，正确的选择取决于组件之间的距离以及它们需要共享的数据类型。 从附近组件的道具和回调开始，将状态提升到同级的共享父级，并使用组合来避免通过不相关的组件传递数据。 对于许多组件所需的数据，上下文适用于诸如主题之类的缓慢变化的值，而 Zustand 适合经常更新的全局状态，TanStack 查询处理服务器数据，URL 存储与视图相关的状态，如过滤器和分页。

[When React hooks stop scaling: Moving complex state to zustand](https://orizens.com/blog/2026-06-18-zustand/)  
_3 分钟_ 奥伦·法希

语音识别逻辑在自定义钩子中启动，直到多个组件需要相同的状态并且更新来自外部 React。 陈旧的数据错误显示，钩子已经成长为共享应用程序状态。 将状态迁移到 Zustand 给了它一个清晰的位置，因此浏览器事件直接更新商店，组件只订阅他们需要的东西。

[Module system dependency injection](https://www.jayfreestone.com/writing/module-level-dependency-injection-react/)  
_6 分钟_ 杰伊·弗里斯通

使用模块系统在构建时交换依赖项可能很有用，但它破坏了可测试性并防止在同一应用程序中有多个实现。 更好的方法是将业务逻辑保留在接受依赖作为参数的函数中，因此测试可以使用简单的内联存根。 保留模块级替换，用于在环境之间交换诸如分析或功能标志的基础设施。 在那里选择默认值，但不要隐藏其中的每个依赖项决定。

[React router v8](https://remix.run/blog/react-router-v8)  
_7分钟_ 布鲁克斯·莱布兰德

React路由器V8出来了，升级是故意简单的。 大多数重大更改已经在 V7 中作为选择加入标志可用，因此迁移意味着更新依赖项、采用这些标志以及删除一些已弃用的 API。 新的最低版本是 Node 22、React 19 和 Vite 7。展望未来，该团队计划年度主要版本，并正在努力实现稳定的服务器组件支持。

[RSC server functions are not an API boundary](https://longho.dev/posts/rsc-server-functions-are-not-an-api-boundary/)  
_7 分钟_ 由 Long Ho

React Server 组件让 Framework 将服务器调用变成了普通的函数调用。 但是这些调用仍然跨越一个网络，使用编译器生成的ID，当代码被重构或框架被升级时可以默默地改变。 这会在滚动部署期间产生真正的问题，旧客户端可能会保存新服务器不再识别的引用。 将任何需要稳定性、版本控制或广泛重用的服务器函数作为真正的 API 进行处理。

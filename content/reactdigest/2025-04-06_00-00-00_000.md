> SPA、SSR 或 RSC

[React Architecture Tradeoffs: SPA, SSR, or RSC](https://reacttraining.com/blog/react-architecture-spa-ssr-rsc)  
_9 分钟_ 布拉德·韦斯特福尔

在本文中，Brad 讨论了 React 单页应用程序与服务器端渲染的 React 框架。 他强调了 SPA 的局限性，以及 Next.js 和 React Router Framework 等框架的拥护者，这些框架结合了 SPA 和服务器端渲染的好处。 这些框架处理延迟加载、客户端导航和数据管理，无需复杂的状态管理解决方案，同时仍允许与非 JavaScript 后端集成。

[React.memo Demystified: When It Helps and When It Hurts](https://cekrem.github.io/posts/react-memo-when-it-helps-when-it-hurts/)  
_6分钟_由克里斯蒂安·埃克雷姆

在这篇文章中，Christian 研究了 React 的记忆化工具如何在幕后以及何时实际使用它们。 它消除了常见的误解，特别是记忆道具自动防止子组件重新渲染，并突出了一些可以默默地破坏记忆的陷阱，包括道具传播、处理JSX儿童和嵌套的备忘录组件。 Christian 建议仅在分析后才使用这些工具来识别实际的性能瓶颈，这表明组件的组成通常比广泛的记忆化提供更优雅的解决方案。

[Building Robust React Apps with Zustand and Immer](https://zwit.link/posts/20250301173228-building-robust-react-apps-with-zustand-and-immer/)  
_8分钟_乔瓦尼·克里萨尔菲

Giovanni 讨论了他最初反对 React 和 JavaScript 的情况，如何通过 Zustand 和 Immer 等库来欣赏它们。 Zustand 提供了简化 Redux 的复杂性的简约状态管理解决方案，而 Immer 优雅地处理了不可变的状态更新，尤其是嵌套数据结构。 他通过 Canvas 应用程序示例演示了这些工具的有效性，展示了它们如何使用干净、可维护的代码处理同步和异步操作。

[3 ways to build forms in react (without any libraries)](https://reactpractice.dev/articles/3-ways-to-build-forms-in-react/)  
_3分钟_科琳娜·乌德雷斯库

在这篇文章中，Corina 讨论了在不使用第三方库的情况下在 React 中构建表单的三种方法：使用本机浏览器功能和 FormData 的不受控制的输入，带有 React 状态的受控输入，以及带有 UseActionState 的新 React 19 Action 属性。 由于其可读性和使用本机浏览器功能，她更喜欢简单表单的不受控制的输入方法，同时注意到 React 19 方法对异步服务器操作和 SSR 实现大放异彩。

[Adaptive Video Streaming With Dash.js In React](https://www.smashingmagazine.com/2025/03/adaptive-video-streaming-dashjs-react/)  
_10分钟_由腾伟赫尔

Teng 深入探讨了如何通过实现自适应比特率流来超越标准 HTML5 视频元素的限制。 与渐进式下载不同，自适应比特率流将视频分成不同质量级别的多个段，根据网络条件自动选择最佳分辨率。 他提供了一个全面的分步指南，使用 FFmpeg 转码视频、生成必要的清单文件，并在 React 中实现与 Dash 兼容的视频播放器，即使在较慢的连接或低端设备上也能实现流畅的视频播放。

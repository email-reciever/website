[What browser translators do to a live DOM](https://github.com/alievdavlat/translate-shield/blob/main/research/article.md)  
_10 分钟_ 作者：Davlatbek Aliev

浏览器翻译器可以通过分离文本节点并将它们包装在新元素中来默默地破坏 React 应用程序，让 React 将更新写入孤立节点，没有任何显示。 Chrome、Yandex 和 Google Bundle 可以做到这一点，而 Edge 和 Firefox 将节点重写到位，因此 React 更新仍会到达屏幕。 一个普通的崩溃保护程序会阻止错误，但会使值冻结。 Translate-Shield 库通过将更新直接写入翻译器的包装器来解决此问题，保持文本正确并在没有可见闪存的情况下进行翻译。

[Native is now the future of mobile at Shopify](https://shopify.engineering/back-to-native)  
_11 分钟_ 穆斯塔法·阿里

Shopify 正在将其移动应用程序从 React Native 切换回原生 Swift 和 Kotlin。 主要原因是 AI 编码工具已经足够好，可以跨平台构建和翻译功能，消除 React Native 提供的最大优势。 使用名为 Helix 的自定义 AI 工作流程，该团队在短短 12 周内重建了一个主要应用程序。 他们的开源 React Native 库将在未来几个月内移交或存档。

[What it actually takes to migrate discord to React native's new architecture](https://swmansion.com/blog/what-it-actually-takes-to-migrate-discord-to-react-native-s-new-architecture/)  
_15分钟_卡米尔·德莱克塔

翻转 React Native 的新架构是很容易的部分。 真正的工作是之后的长尾：渲染由悄悄停止持有的旧假设引起的错误、崩溃和破碎的手势。 Kamil 展示了三个示例：在模态中分裂的坐标空间、按压中视图展平的手势以及由无人知道的类命名约定触发的死锁。 大多数修复都很小，但找到它们却不是。

[Replay input after hydration](https://kurtextrem.de/posts/replay-input-after-hydration)  
_5分钟_雅各布·格罗斯

良好的用户体验意味着网站在快速和慢速连接上都应该响应良好。 当用户在页面完成加载之前与过滤器输入交互时，会出现一个棘手的边缘情况，导致他们的输入被 React 忽略，因为事件侦听器尚未附加。 一个名为 UsereplayPreHydrationInput 的自定义钩子通过检测浏览器显示的内容与 React 所知道的内容之间的不匹配来解决此问题，然后重放用户的输入，以便正确更新过滤器和 URL。

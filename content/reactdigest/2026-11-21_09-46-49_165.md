> 在任何应用程序代码运行之前优化60KB

[Projecting React](https://tannerlinsley.com/posts/projecting-react)  
_15分钟_ 由坦纳·林斯利

在任何应用程序代码运行之前，React 大约为 60 KB。 Tanner 探索构建一个更小的替代品，以满足 TanStack Start 的需求，放弃并发渲染等未使用的功能，同时保持核心挂钩、悬念和 SSR 流。 结果比 Stock React 小了大约 85%，渲染速度更快，在真正的个人网站上提供的 JavaScript 少了三分之一，以一天的 AI 辅助工作为代价。

[From React to native web with nanotags: A migration that saved 100 KB](https://evilmartians.com/chronicles/from-react-to-native-web-with-nanotags-a-migration-that-saved-100kb)  
_13分钟_帕维尔·格林琴科，特拉维斯·特纳

Pavel 描述了使用 Astro 和 NanoStore 将营销网站从 React 迁移到本地 Web 组件。 迁移将 JavaScript 减少了 100 KB，而不会丢失功能或可访问性。 他解释了为什么 Web 组件适用于大多数静态站点、直接编写它们的挑战，以及这些挑战如何导致创建 NanoTags，这是一个简化反应性、可访问和类型安全的 Web 组件的轻量级库。

[The React2Shell story](https://lachlan.nz/blog/the-react2shell-story/)  
_18分钟_拉克兰戴维森

Lachlan 在尝试了解其“飞行”协议时发现了 React 中的一个关键远程代码执行漏洞。 该协议的松散属性查找允许制作可能诱使 React 执行任意代码的恶意对象。 经过几天的睡眠不足研究，针对任何默认的 Next.js 应用程序构建了一个有效的漏洞利用。 Meta 收到通知并在几天内修补了问题。

[Five models, one React stack: Why every LLM builds the same app](https://saschb2b.com/blog/llm-default-react-stack)  
_13分钟_由萨沙·贝克尔

AI 编码助手几乎总是建议使用相同的前端堆栈：React、Tailwind CSS 和 Shadcn/UI。 发生这种情况是因为这些工具主导了训练数据，并且它们的设计使语言模型易于正确生成。 该模式自行提供：AI 输出返回 GitHub，未来模型对其进行训练，并且相同的默认值变得更强大。 从不质疑输出的开发人员可能永远不会学习其他选项。

[Postmortem: TanStack npm supply-chain compromise](https://tanstack.com/blog/npm-supply-chain-compromise-postmortem)  
_11 分钟_ 作者：Tanner Linsley

攻击者链接了三个漏洞，发布了 2026 年 5 月 11 日发布的 42 个 TanStack NPM 软件包的恶意版本。他们通过虚假的拉取请求中毒了 GitHub 操作构建缓存，然后从内存中提取了一个身份验证令牌以直接发布到 npm 不窃取任何凭据。 恶意软件包从任何运行 npm install 的机器中获取了 AWS、GCP、Kubernetes 和其他秘密。 多亏了外部研究人员，所有 84 个受影响的版本都在大约 30 分钟内被捕获和弃用。

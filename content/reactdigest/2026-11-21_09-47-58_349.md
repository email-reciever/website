> 跨越服务器和客户端的组件

[Impossible components](https://overreacted.io/impossible-components/)  
_15分钟_丹·阿布拉莫夫

DAN 说明如何使用 React Server 组件创建跨服务器和客户端的组件。 这些“不可能的组件”封装了在服务器上运行的数据加载逻辑和在浏览器中运行的交互式状态逻辑。 DAN 提供的示例包括将服务器端文件读取与客户端状态管理相结合的 Greeting 组件，以及可排序、可过滤的博客文章列表，每个预览都可以交互式扩展。

[Simplify TanStack React Query state handling with pattern matching](https://gabrielpichot.fr/blog/simplify-tanstack-react-query-state-handling-with-pattern-matching/)  
_7 分钟_ 加布里埃尔·皮科特

Gabriel 讨论了模式匹配如何简化 TanStack React 查询中的不同状态的处理。 他提出了一个 \`matchQueryStatus\` 实用函数，而不是使用嵌套条件语句来加载、错误、成功和空状态。 此函数将详细条件渲染转换为干净的声明式模式，其中每个状态映射到特定的 UI 组件。 该方法遵循“沙漏模式”，在扩展到 UI 组件之前将复杂的查询结果缩小到简单的状态，从而提高了可读性、可维护性和类型安全性。

[React Compiler Release Candidate](https://react.dev/blog/2025/04/21/react-compiler-rc)  
_5分钟_ 陈茂飞

React 团队发布了编译器的 RC，这是一个近乎最终版本，通过自动记忆功能优化 React 应用程序，现在可以安全地进行生产使用。 关键更新包括将 eslint-plugin-react-compiler 合并到 eslint-plugin-react-hooks 中，添加对 SWC 的支持和与 OXC 一起实现无 Babel 的构建，以及扩展编译器优化以支持可选的链和数组索引 作为依赖。

[Full-Stack React Chat with AI SDK](https://www.robinwieruch.de/react-ai-sdk-chat/)  
_2 分钟_ 罗宾·维鲁克

在这篇文章中，Robin 总结了 AI SDK 与使用原始 OpenAI API 相比如何简化了构建流聊天界面。 他解释说，SDK 提供了消除样板代码的抽象层，服务器端组件自动处理流响应，React 集成提供管理消息状态和 UI 更新的 UseChat 钩子。 结果是大大减少了保持完整功能的代码，同时提高了可维护性和可读性。

[Memoizing components in React: a case for useMemo](https://gabrielpichot.fr/blog/memoizing-components-in-react-a-case-for-usememo/)  
_8 分钟_ 加布里埃尔·皮科特

React.Memo 通常用于优化组件渲染，但 UseMemo 提供了更多的控制和透明度。 在这篇文章中，Gabriel 解释了为什么 UseMemo 也可以作为 React 应用程序中的组件记忆化的解决方案，直到 React 编译器为我们处理好它。

> SSR、预渲染、水化和静态站点生成

[SSR Deep Dive for React Developers](https://www.developerway.com/posts/ssr-deep-dive-for-react-developers)  
_35分钟_ 纳迪亚·马卡雷维奇

Nadia 提供了 React 中服务器端渲染方法的综合指南，解释了 SSR、预渲染、水合和静态站点生成如何解决客户端渲染的局限性。 它展示了这些技术如何提高搜索引擎的可见性和社交媒体共享，同时可能增强性能指标，如第一次内容油漆和大型内容油漆。 她探讨了每种方法的技术实现细节、性能影响和权衡，得出的结论是，虽然实现自定义 SSR 解决方案是可能的，但使用像 Next.js 这样的已建立框架通常对生产应用更实用。

[Common React libraries architecture](https://www.felgus.dev/blog/common-react-lib-architecture)  
_4分钟_ 由费利佩·古斯塔沃

在这篇文章中，Felipe 解释了大多数 React 库如何共享由核心逻辑和 React 绑定组成的类似架构。 库通常在外部创建核心对象以避免重新呈现问题，然后通过提供程序组件通过上下文 API 将它们连接到 React 组件。 为了与 React 的渲染周期同步外部状态，库通常实现 Observer 模式并使用 UseSyncExternalStore 钩子或使用 UseEffect 和 UserReducer 构建的自定义钩子，每种方法都对 React 的并发特性进行性能折衷。

[Live Mode](https://www.openstatus.dev/blog/live-mode-infinite-query)  
_3分钟_马克西米利安·卡斯克

在本指南中，Maximilian 提供了使用 TanStack 的无限查询实现实时数据更新的实用手册，重点关注如何使用基于游标的分页来有效地获取较旧的数据和较新的数据。 它解释了 API 端点要求、客户端实现详细信息，并提供了一种自定义自动刷新机制，避免了重新获取所有页面。 他在 Logs.run 中包含了代码示例和指向实时演示的链接，读者可以在其中看到实现的实现。

[The URL is a great place to store state in React](https://iamsahaj.xyz/blog/react-state-in-the-url/)  
_5 分钟_ 由 Sahaj Jain

Sahaj 讨论了在 Web 应用程序中利用 URL 进行状态管理。 他解释说，在 URL 中存储状态提供了跨页面重新加载的可共享性、速度和持久性等优势，这对于刷新后需要保持打开状态的组件等组件很有用。 本文将基于 URL 的状态管理与替代方案进行了比较，并演示了使用 React Router 的 useSearchParams 或 Vanilla JavaScript 的 URLSearchParams 的实现。 Sahaj 最后提供了基于持久性、可共享性和导航要求的 URL 参数与其他状态管理方法的指南。

[Next.js vs TanStack](https://www.kylegill.com/essays/next-vs-tanstack/)  
_8分钟_凯尔吉尔

在这篇文章中，Kyle 解释了为什么他要从 Next.js 转移到使用 Vite 进行 Web 开发的 TanStack。 在承认 Next.js 在快速设置和大规模优化方面的优势时，他批评了较小的应用程序的不必要的复杂性、困难的学习曲线、调试挑战以及与 Vercel 云服务相关的财务激励。 他更喜欢 TanStack 的简单、透明和优雅，发现它在没有 Next.js 的情况下提供了更好的抽象，而 Vite 为大多数开发需求提供了速度和简单性。

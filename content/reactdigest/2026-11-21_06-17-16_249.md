[How we cut Next.js memory from ~5GB to ~1GB](https://reactdigest.net/links/23709/rss)  
_10 minutes_ by Rohit Kashyap

React-query v3 starts a timer for every query during server-side rendering. Node ties each request's context to that timer, keeping the entire request in memory until the timer fires, up to 5 minutes later. Setting cacheTime to Infinity on the server prevents the timer from starting, since the query client is thrown away after each render anyway. Memory dropped from 4.8 GiB to 1.2 GiB per pod after the fix.

[Six React chart libraries against hand-written SVG: What I found](https://reactdigest.net/links/23711/rss)  
_9 minutes_ by Pavel Gusev

Pavel compares six popular React chart libraries with hand-written SVG to evaluate their performance, code size, and ease of use. Tests show that most perform similarly with typical charts, but differences become significant with large datasets. TanStack Charts requires the least code, while visx and hand-written SVG offer better performance and smaller bundles. The best choice depends on project needs and priorities.

[Writable derived state: Stop synchronizing state](https://reactdigest.net/links/23713/rss)  
_5 minutes_ by Corbin Crutchley

Instead of syncing server data into local state with a useEffect, store user edits separately and fall back to server data only when local state is empty. A simple null check replaces the effect entirely. This keeps user changes safe during background refreshes, removes unnecessary code, and matches how the feature actually behaves.

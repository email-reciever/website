基于特征的 React 架构
==================================

第548章 2026年3月15日

> 将组件和查询绑定到单个功能使代码更简洁且更易于维护

[Feature-based React architecture](https://www.robinwieruch.de/react-components-database-relations/)  
_3分钟_罗宾·维鲁克

数据库关系直接影响了 React 组件的结构。 使用 React Server 组件，您可以通过将帖子和评论拆分为聚焦组件来镜像数据库关系，每个组件都处理自己的数据提取。 随着代码库的增长，这避免了 GetPostWithComments 等混乱的函数名称。 将组件和查询与单个功能绑定在一起，使代码更简洁、更易于维护。

[Prebuilt SwiftUI and Jetpack Compose components for your Expo app](https://go.clerk.com/cLPsiHj)  
_由文员赞助_

Clerk 的 Expo SDK 3.1 提供了开箱即用的本地 UI 组件，而不是浏览器重定向和手动滚动登录屏幕。 AuthView 处理登录和注册。 UserButton 和 UserProfileView 管理会话。 包括原生 Google 登录，没有额外的套餐。 添加配置插件并发货。

[How toAccess React router context with AsyncLocalStorage](https://sergiodxa.com/tutorials/access-react-router-context-with-asynclocalstorage)  
_4分钟_由塞尔吉奥·哈兰布里

React 路由器的上下文对象通常必须通过每个需要它的函数传递。 AsyncLocalStorage 通过每个请求存储上下文一次来解决此问题，因此任何函数都可以直接访问它，而无需将其作为参数。 您使用单个中间件进行设置，然后从任何地方调用 getDB 或 GetUser 等辅助函数。 权衡是依赖性变得隐含，这可能会使隔离测试变得更加困难。

[One component. Two APIs.](https://cant-maintain.saschb2b.com/)  
_10 分钟_ 萨沙·贝克尔

这是一个简短的交互式测验，可帮助您在 React 代码中发现好的和坏的道具模式。 它从像MUI这样的真实代码库中提取示例。 目标是建立一种本能，用于编写能够随着时间的推移保持清洁和易于维护的道具。

[How state updates work internally](https://inside-react.vercel.app/blog/how-state-updates-work-internally)  
_9 分钟_ 由 Sankalpa Acharya

从钩子到批处理，深入了解 React 状态更新的真正工作方式。 React 状态更新是异步的。 调用 setState 不会更改当前变量。 它排队更新并安排重新渲染，因此在设置后立即记录状态显示旧值。

[Real-time cache invalidation](https://armand-salle.fr/post/real-time-cache-invalidation-sse-trpc-redis-bullmq/)  
_6分钟_由阿曼德·萨尔

服务器发送的事件在缓存失效时击败了 WebSockets，因为您只需要单向推送。 该模式通过 SSE 将 TRPC 订阅连接到 Redis Pub/Sub，因此任何服务器实例都可以在数据更改时通知所有连接的客户端。 它不是通过流推动新数据，而是推动小的失效信号，让 TanStack Query 处理实际的重新获取。 这在保持整个管道的完整类型安全性的同时保持微小的有效载荷。

[React's new browser API: Rendering components only in the browser](https://certificates.dev/blog/reacts-new-browser-api-rendering-components-only-in-the-browser)  
_7分钟_由Aurora Scharff

React Canary 的新 Browser() API 允许您跳过需要浏览器功能（如 LocalStorage）的组件的服务器渲染。 将组件包装在悬念中，调用 use(browser()) 并在其中呈现，然后在浏览器加载后在服务器上渲染回退。 这取代了旧的解决方法，例如检查窗口或跟踪安装状态。

[Using react-broadcast-sync in a real app](https://dev.to/idanshalem/using-react-broadcast-sync-in-a-real-app-dashboard-filters-across-tabs-38cb)  
_8 分钟_ 由 Idan Shalem

多个选项卡中的 React 应用程序各自拥有自己的 UI 状态，因此一个选项卡中的更改永远不会到达其他选项卡。 react-broadcast-sync 库通过一个简单的钩子或提供程序来修复选项卡之间的共享通道。 您首先更新本地状态，然后广播更改，并在应用之前验证传入消息。 新选项卡仍然需要从您的正常数据源加载其初始状态，因为通道仅在选项卡连接后发送消息。

[The Remix way](https://sergiodxa.com/articles/the-remix-way)  
_10分钟_由塞尔吉奥·哈兰布里

用 Remix v3 构建一个博客变成了一个为期六个月的项目，在 11 个应用程序中产生了 88 个包。 关键的见解是围绕合同而不是具体的实现进行设计，从而可以通过更改一行来轻松交换电子邮件提供商、数据库或计费系统。 相同的模式应用于路由、后台作业和 MCP 服务器，使每个处理程序都集中且类型安全。 结果几乎没有客户端 JavaScript，依赖于 Web 标准，并且几乎没有第三方依赖。

[How fast is the web?](https://blog.cloudflare.com/how-fast-is-the-web/)  
_9 分钟

Cloudflare 发布了 Beacon，这是一个免费的数据集，该数据集由 10,000 个主要网站的数十亿个真实网络性能测量值构建。 它跟踪页面加载的速度，视觉上的稳定性，以及它们对用户输入的响应速度，按国家、浏览器和设备细分的速度。 数据显示出明显的差距，例如，非洲网络较慢导致页面尺寸较小，这表明网站适应当地条件。 研究人员可以通过 Google BigQuery 访问它。

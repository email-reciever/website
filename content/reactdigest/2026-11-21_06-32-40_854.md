[Fixing a hydration mismatch error and UI flicker](https://reactdigest.net/links/23606/rss)  
_9 minutes_ by Giorgi Moniava

Server-side rendering sends HTML to the browser before JavaScript loads, then React "hydrates" it to make the page interactive. A hydration mismatch happens when the server-rendered HTML differs from what React produces on the client, often because client-only data like localStorage was used during rendering. Common fixes include delaying rendering until after the component mounts, using an inline script to apply saved state to the DOM before hydration, or suppressing warnings where mismatches are expected and harmless.

[Optimizing TanStack start](https://reactdigest.net/links/23608/rss)  
_18 minutes_ by Sarthak Mishra

A TanStack Start home page scored 73 on mobile despite being prerendered, because the browser was downloading code and assets it never needed. The biggest gains came from removing a site-wide image manifest loaded on every page, lazy-loading closed dialogs, subsetting fonts and adding a metric-matched fallback to prevent layout shift, and stopping hidden navigation images from downloading on mobile. Critical CSS extraction and delayed hydration helped but added maintenance overhead and produced inconclusive score improvements on their own.

> 消除不必要的重新渲染

[Reactivity is easy](https://romgrk.com/posts/reactivity-is-easy/)  
_7分钟_由罗姆格尔克

romgrk 演示了如何仅 35 行代码就可以实现基于细粒度选择器的反应性，从而消除不必要的重新渲染。 该解决方案涉及创建一个简单的存储类，用于管理状态并通知组件有关更改的内容，并与 UseSelector 挂钩配对，该钩子仅允许组件订阅他们需要的特定部分。

[Clerk OAuth gets a big upgrade—now fully MCP-ready](https://go.clerk.com/QpYKkdz)  
_由文员赞助_

Clerk 的最新 OAuth 版本增加了令牌撤销、同意屏幕、动态客户端注册、公共客户端支持和完整的 MCP 兼容性。 默认情况下，此更新专为现代应用程序和安全性而构建，使 Clerk 成为适用于任何 OAuth 用例的功能强大的插入式认证解决方案。 查看新功能以及如何开始。

[Use Async Local Storage to prevent props drilling in Next.js Route handlers](https://www.nico.fyi/blog/async-local-storage-to-prevent-props-drilling)  
_3 分钟_ 尼科·普拉南塔

在这篇文章中，Nico 讨论了异步本地存储，它为处理授权的 API 请求时的道具钻孔问题提供了一个优雅的解决方案。 AsyncLocalStorage 不是通过多个嵌套函数繁琐地传递用户对象，而是创建一个可访问同一执行上下文中的所有函数的存储。

[Search params are state](https://tanstack.com/blog/search-params-are-state)  
_5分钟_ 由坦纳·林斯利

Tanner 提倡将 URL 搜索参数视为 Web 应用程序中的正确状态，而不是事后考虑。 他强调了处理搜索参数的传统方法如何容易出错且缺乏类型安全性，从而导致分裂和不一致。 Tanner 展示了 TanStack 路由器如何通过将搜索参数模式直接集成到路由定义中来解决这些问题，提供类型推断、验证和参数的层次继承。

[Rebuilding Clash of Clans’ building system in React](https://edvins.io/clash-of-clans-building-system-react)  
_5分钟_由埃德文斯·安东诺夫斯

Edvins 描述了使用 React 和 LocalStorage 从 Clash of Clans 中重新创建核心建筑机制，而无需后端。 他通过仅跟踪时间戳和构建级别而不是不断更新资源数量来解释游戏的资源生成系统如何有效地工作，使其具有高度可扩展性。

[How Imports work in RSC](https://overreacted.io/how-imports-work-in-rsc/)  
_22分钟_丹·阿布拉莫夫

DAN 为任何想要建立准确的 RSC 心理模型的人以及对模块系统感兴趣的人提供了深入的潜水。 RSC 扩展了 JavaScript 的模块系统，以弥合统一应用程序中前端和后端代码之间的差距。 它引入了诸如“使用客户端”和“使用服务器”之类的指令，这些指令允许代码从其他环境中引用模块，而无需实际导入它们，在两个模块系统之间创建“门”。

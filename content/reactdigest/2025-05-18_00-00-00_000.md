[OpenAuth with React Router](https://seanpaulcampbell.com/blog/openauth-react-router/)  
_20分钟_由肖恩·坎贝尔

使用 SST 在 React 路由器应用程序中实现 OpenAuth 身份验证的综合指南。 Sean 涵盖设置身份验证服务器、配置提供商、实施身份验证流、管理会话和创建受保护的路由。

[Getting started with Clerk Billing](https://go.clerk.com/gMUEEJP)  
_由文员赞助_

Clerk 最近发布了一项新的计费产品，用于为 B2B 和 B2C 应用程序启用 SaaS 订阅功能。 在这段视频中，Braden Sidoti（文员的联合创始人兼首席技术官）概述了该产品，并介绍了如何构建完整的计费体验。

[How to build a React Login Page Template](https://go.clerk.com/sMQu18h)  
_由文员赞助_

这本动手指南将引导您构建一个简单的 AUTH 系统，其中包含 Express 和 React，涵盖基于会话和 JWT 的方法。 您将探索最佳实践，逐步实施会话身份验证，并使用即用型 React 登录页面模板离开。 非常适合希望使用真实世界模式保护前端应用程序的开发人员。

[How to build a custom renderer?](https://blog.swmansion.com/how-to-build-a-custom-react-renderer-595dc4a9cb1c)  
_8 分钟_ Wojciech Kozyra

Wojciech 解释了如何通过实现新的 React 渲染器将自定义 API 与 React 集成。 它概述了两种集成方法：实现新的 React 渲染器或为 React Native 实现新的目标平台。

[Dependency inversion: Building truly testable components](https://cekrem.github.io/posts/dependency-inversion-in-react/)  
_3分钟_由克里斯蒂安·埃克雷姆

克里斯蒂安讨论在反应中应用依赖反演原理来减少紧密耦合。 他展示了如何重构组件以依赖于接口而不是具体的实现，以 UserRepository 接口为例。 通过将高级模块与低级实现细节分开，这种方法使组件更具可测试性、可维护性和灵活性。

[React context is not causing too many renders](https://blacksheepcode.com/posts/no_react_context_is_not_causing_too_many_renders)  
_3分钟_大卫·约翰斯顿

David 揭穿了 React Context 对状态管理效率低下的误解，并表明上下文提供者不会对所有子组件造成不必要的重新渲染。 他解释说，只有当不相关的状态捆绑到一个提供者中时才会出现问题，但使用多个上下文提供者解决了这个问题。

[Static as a Server](https://overreacted.io/static-as-a-server/)  
_3分钟_丹·阿布拉莫夫

在这篇文章中，Dan 解释说 React Server 组件可以用于静态网站，而无需服务器运行。 他澄清说，像 Next.js 这样的现代“混合”框架可以在构建过程中运行服务器组件并生成静态输出，这消除了传统的“服务器”和“静态”框架之间的区别。

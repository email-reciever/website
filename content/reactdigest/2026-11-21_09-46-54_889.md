在 MDN 新前端的引擎盖下
=======================================

第553章 2026年4月19日

> 新方法放弃SPA并使用服务器端HTML模板和Web组件

[Under the hood of MDN's new frontend](https://developer.mozilla.org/en-US/blog/mdn-front-end-deep-dive/)  
_28分钟_ 由利奥·麦卡德尔

MDN 重建了前端，以修复缓慢的构建、混乱的 CSS 和无法与自己的页面内容交互的 React 应用程序。 新方法完全放弃了单页应用程序，使用服务器端的 HTML 模板和使用 LIT 构建的 Web 组件，用于交互式元素。 每个组件仅在需要时才加载自己的 CSS 和 JavaScript，从而保持页面快速。 开发环境现在在 2 秒内开始，低于 2 分钟。

[Still writing tests manually? Meticulous AI is here.](https://www.meticulous.ai/?utm_source=react-digest&utm_medium=newsletter&utm_campaign=26q1&utm_content=primary)  
_由细致的赞助

大多数团队被迫在更好的覆盖范围和更多的维护工作之间进行权衡。 但像 Notion、Dropbox、WealthSimple 和 LaunchDarkly 这样的顶级工程团队已经发现了一种新的测试范式。 由Ex-Palantir工程师构建，精心创建和维护E2E UI测试，无需任何开发人员的努力即可覆盖您的Web应用程序的每个边缘情况 - 使其成为提高产品质量和开发速度的唯一工具。

[The uphill climb of making diff lines performant](https://github.blog/engineering/architecture-optimization/the-uphill-climb-of-making-diff-lines-performant/)  
_10分钟_卢克·根科，亚当·施沃特

GitHub 改进了拉取请求选项卡的性能，特别是对于非常大的更改。 通过简化 React 组件、减少 DOM 元素、优化数据访问和添加虚拟化，它们显着减少了内存的使用和滞后。 这些有针对性的更改使所有用户的界面更快、更流畅、更可靠，同时也能保持使用数以千计的拉取请求。

[React server components your way](https://tanstack.com/blog/react-server-components)  
_13 分钟_ Manuel Schiller 等人。

这篇文章解释了在 TanStack Start 中使用 React Server 组件的新方法。 开发人员可以像数据一样处理服务器组件，而不是让服务器控制所有内容——获取、缓存并根据需要渲染它们。 这使得应用程序更加灵活和高效。 它还引入了“复合组件”，其中服务器和客户端共享 UI 的控制，提高性能和定制。

[The vertical codebase](https://tkdodo.eu/blog/the-vertical-codebase)  
_9分钟_多米尼克·多夫梅斯特

Dominik 认为按类型（如组件或工具）构建代码无法很好地扩展。 相反，他建议将代码组织成“垂直”，按功能或目的将所有内容分组。 这提高了清晰度，降低了复杂性，并将相关代码保持在一起。 垂直结构可以帮助开发人员和 AI 工具更高效地工作，尽管它需要团队之间的仔细规划和良好的沟通。

[Contributing callsite revalidation opt-out to React router](https://programmingarehard.com/2026/04/11/contributing-to-react-router.html/)  
_5分钟_大卫·亚当斯

David 解释说，在 React Router 中添加了一个新功能，让开发人员可以更精确地控制数据重新加载。 该功能不总是在更改后始终刷新所有数据，而是允许在发出请求的地方选择退出。 这简化了代码，避免了不必要的更新，并提高了灵活性。

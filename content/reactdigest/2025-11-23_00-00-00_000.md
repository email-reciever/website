我们如何从酶迁移到反应测试库
=======================================================

第533章 2025年11月23日

> 76,000 次半年测试

[How we migrated from Enzyme to React testing library](https://product.hubspot.com/blog/migrated-from-enzyme-to-react-testing-library)  
_10分钟_查理·普格米尔

酶是测试 React 应用程序的标准，但在停止支持 React 18 功能时变得过时。 HubSpot 在两年半的时间里从 Enzyme 迁移了超过 76,000 次测试到 React 测试库。 他们使用运行时度量来按测试复杂度对包进行分类，并首先优先考虑较小的迁移。

[Tests are dead. Meticulous AI is here.](https://www.meticulous.ai/?utm_source=react_digest)  
_由细致的赞助

Meticulous 自动创建并维护一个详尽的 E2E UI 测试套件，覆盖应用程序的每个角落——无需任何开发人员干预。 Dropbox、Lattice、Bilt Rewards 和数百个组织依靠一丝不苟的前端测试。 它是从 Chromium 级别构建的，带有确定性调度引擎——使其成为唯一消除薄片的测试工具。

[Testing async React RSC components](https://howtotestfrontend.com/resources/testing-async-react-rsc-components)  
_7 分钟_ 通过 HowToTestFrontend

测试 React Server 组件的异步行为是具有挑战性的。 通常的方法是使用像 Playwright 或 Cypress 这样的端到端测试，而不是单元测试。 对于带有 React 测试库的单元测试，可以对简单的异步组件使用 render(await component())。

[Just JavaScript](https://pedrocattori.com/posts/just-javascript/)  
_6分钟_由佩德罗·卡托里

Pedro 将“Just JavaScript”定义为无需自定义转换的代码。 他认为这意味着您应该了解您的程序的功能，并且能够在不破坏事物的情况下正常重构代码。 TypeScript 和 JSX 获得了通过，因为它们现在受到 JavaScript 运行时的广泛支持。 React 路由器几乎符合条件，但使用特殊的路由模块导出来更改代码运行的位置。

[Tooltip components should not exist](https://tkdodo.eu/blog/tooltip-components-should-not-exist)  
_4 分钟_ 由 Dominik Dorfmeister

设计系统不应该提供通用的工具提示组件，因为它们太容易被滥用。 开发人员经常将工具提示添加到无法接收键盘焦点的非交互元素，从而无法访问它们。 相反，Dominik 建议，设计系统应该提供更高级别的组件，例如带有可选标题道具或专用信息图标的按钮。 这种方法可确保跨团队一致、可访问的工具提示使用情况。

[How I learned React as a junior developer](https://techhub.iodigital.com/articles/chatgpt-as-my-coding-mentor)  
_6分钟_ 艾勒诺尔·博克

Ellenoor 分享了她从一个困惑的初级开发人员学习反应到自信地使用 Next.js 构建全栈应用程序的旅程。 她描述了早期与 Hooks 的斗争如何使她在使用 AI 编码助手时发现了清晰提示、上下文设置和基于类比的解释的力量。 通过提出有针对性的问题和逐步建立理解，她开发了一种有效的学习方法和与人工智能作为导师的可靠合作伙伴关系。

> 为什么性能很重要，常见问题是什么，以及如何解决这些问题

[A Guide to Performance Optimization with Next.js](https://www.debugbear.com/blog/nextjs-performance)  
_19分钟_科里·米勒

了解为什么性能对您的网站很重要，Next.js 的常见问题是什么，以及您可以采取哪些措施来解决这些问题。 Cory 涵盖了实用的技术，包括使用 Next/Image 进行正确的图像处理、优化第三方脚本、使用 Suspense 改进加载体验以及根据内容需求选择合适的渲染方法。

[Bit: Open source framework for composable software](https://bit.dev/?utm_source=ReactDigest&utm_id=42&utm_medium=newsletter)  
_由位_赞助

用于开发可组合软件的构建系统框架。 原生于 [Harmony](https://bit.cloud/bitdev/harmony)，并支持 NodeJS、React 应用（带 Vite）、NextJS、Angular、Vue 等。 Bit 使团队能够构建、管理和维护自己的应用程序和组件。

[Server Actions with Toast (useEffect)](https://www.robinwieruch.de/react-server-actions-useactionstate-toast/)  
_8 分钟_ 罗宾·维鲁克

本教程介绍如何使用 UseActionState Hook 和 UseEffect 实现 React Server 操作的 Toast 通知。 该方法包括从包含时间戳的服务器操作返回响应对象，以防止显示过时的通知、使用 useRef 跟踪状态更改以避免重复的 toast 以及处理不同的通知类型。

[Beyond React.memo: Smarter Ways to Optimize Performance](https://cekrem.github.io/posts/beyond-react-memo-smarter-performance-optimization/)  
_6分钟_由克里斯蒂安·埃克雷姆

本文挑战了默认为 React.memo 进行性能优化的常见做法，建议基于组合的更优雅的替代方案。 克里斯蒂安解释说，理解 React 的渲染模型是关键——当他们的父母重新渲染时，组件会重新渲染，而不仅仅是在道具改变时。 推荐两种主要模式：通过将状态隔离到较小的组件来“移动状态”，并使用“儿童作为道具”来防止不必要的重新渲染。

[Building APIs with Next.js](https://nextjs.org/blog/building-apis-with-nextjs)  
_10 分钟_ 李·罗宾逊

这本综合指南引导开发人员使用 next.js 构建 API，涵盖从初始设置到部署的所有内容。 本指南说明何时创建 API 端点而不是使用服务器组件进行直接数据提取，并包括标准 Node.js 和静态导出方案的部署注意事项。

[How The New York Times migrated from Enzyme into React Testing Library](https://open.nytimes.com/how-the-new-york-times-systematically-migrated-from-enzyme-into-react-testing-library-b3ea538d001c)  
_8分钟_由纽约时报公开队

在评估了三种可能的方法（推土机、共识和零碎）之后，他们选择了零碎的方法，它涉及从最简单的案例开始战略性地更新单个文件。 这种方法使他们能够建立动力，最大限度地减少干扰，并通过建立其他人可以遵循的清晰模式来促进工程师之间的协作，最终使他们能够平衡迁移与正在进行的发展优先事项。

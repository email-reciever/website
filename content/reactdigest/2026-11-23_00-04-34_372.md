[无需框架的 React 服务器组件？](https://reactdigest.net/links/23766/rss)\
*37 分钟* by Timothée Pillard

React 服务器组件允许服务器和浏览器共享渲染 React 应用的工作。服务器组件仅在服务器上运行，永远不会将 JavaScript 发送到浏览器，从而减少包大小并启用直接数据获取。Timothée 演示了如何构建最小的 RSC 设置，而无需使用框架，涵盖了流媒体、Suspense、数据获取、路由和使用 Client Actions 处理表单。虽然该技术很强大，但作者建议在生产中采用它之前等待，因为文档有限，除 Next.js 之外的生态系统多样性较低。

[什么是 React Fiber？React 的内部工作原理](https://reactdigest.net/links/23768/rss)\
*16 分钟* by Tejas Kumar

React Fiber 是 React 从 16 版本开始使用的引擎，用于确定发生了什么变化并更新屏幕。它将组件树分解为小对象，称为纤维，让 React 暂停工作，处理紧急事项，如键盘输入，并稍后恢复。在此之前，React 必须一次完成每个更新，这可能会冻结页面。通道和两阶段渲染/提交分离使得优先级和安全、可中断的更新成为可能。

[本地视觉回归测试](https://reactdigest.net/links/23769/rss)\
*17 分钟* by Paolo Ricciuti

视觉 bug 很容易被忽略，尤其是当 AI 代理在代码库中进行更改时。像 Percy 和 Chromatic 这样的工具可以捕获这些问题，但会创建缓慢的反馈循环，并且随着 AI 增加 PR 和提交的数量而迅速增加成本。Playwright 的内置截图比较可以在本地运行，并保持紧密的循环。将其包装在 Docker 中可以确保在不同机器和操作系统上获得一致的结果，使得这种方法足够可靠以供信任。

[声明式拖拽](https://reactdigest.net/links/23770/rss)\
*2分钟* 由 Joshua Horowitz, Andrew Blinn 等。

在数字界面中拖拽和放置元素通常需要复杂的代码来处理移动、视觉和动画。这一种新的方法允许开发者简单地描述元素可以移动到的未来状态，系统会处理剩下的部分。它在后台渲染可能的结果，并将它们自动转换为平滑、响应式的拖拽交互。

[感觉恰到好处的照明](https://reactdigest.net/links/23771/rss)\
*37分钟* 由 Maxime Heckel

照明通常是场景看起来平淡或真实的关键差异。这篇文章介绍了两种全局照明方法：屏幕空间法，它使用仅可见像素跟踪射线，和探针法，它在场景中的固定点采样光线。两种方法都近似地模拟了光线在表面之间弹跳的方式，添加了颜色渗透和柔软阴影。Maxime还涵盖了反射和天空光，以实现完整的效果。

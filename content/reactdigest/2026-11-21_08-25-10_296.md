人工智能代理的抽象成本
=================================================

第576章 2026年9月27日

> 太多的代码抽象会减慢开发的速度和夸大成本

[The cost of abstraction for humans and AI agents](https://ondrejvelisek.github.io/the-cost-of-abstraction-for-humans-and-ai-agents/)  
_16 分钟_ Ondrej Velisek

太多的代码抽象会减慢开发速度并增加成本。 每一个额外的层都迫使开发人员和 AI 代理在文件、燃烧时间和金钱之间跳跃。 在四个代码库中测量 394 个 AI 代理程序，显示过度抽象的代码在 AI 代理费用中的成本高出大约 30%，某些任务的成本高出 5 倍。 Ondrej 说这个修复很简单：只有当你真正需要隐藏复杂性、重用代码或给某物取一个有意义的名字时才抽象。

[Still writing tests manually? Meticulous AI is here.](https://www.meticulous.ai/?utm_source=react-digest&utm_medium=newsletter&utm_campaign=26q1&utm_content=primary)  
_由细致的赞助

大多数团队被迫在更好的覆盖范围和更多的维护工作之间进行权衡。 但像 Notion、Dropbox、WealthSimple 和 LaunchDarkly 这样的顶级工程团队已经发现了一种新的测试范式。 由Ex-Palantir工程师构建，精心创建和维护E2E UI测试，无需任何开发人员的努力即可覆盖您的Web应用程序的每个边缘情况 - 使其成为提高产品质量和开发速度的唯一工具。

[React server functions are more than mutations](https://www.nikhilsnayak.dev/blog/react-server-functions)  
_12分钟_尼基尔·斯纳亚克

该帖子探讨了使用 React Server 函数的不仅仅是突变。 Nikhil 展示了他们如何处理查询、流数据，甚至是流 React UI，同时保留 React 的现有编码和飞行协议。 该方法支持逐行加载、保留客户端状态并允许有针对性的重试。 主要的挑战是管理请求的生命周期，因此服务器的工作一直持续到所有依赖的 UI 完成。

[From 1,256ms to 96ms: Fixing INP in a massive React dropdown](https://dev.to/subito/from-1256ms-to-96ms-fixing-inp-in-a-massive-react-dropdown-16l7)  
_7分钟_ 亚历山德罗·格罗塞尔

具有 1,175 个选项的大型 React 下拉菜单导致交互非常缓慢，InP 达到 1,256 毫秒。 问题是即使只有少数可见，也可以渲染每个选项。 该团队使用一个小的自定义虚拟化钩子修复了它，该钩子只呈现可见的行。 这将DOM从大约1,175个选项减少到13个，并将InP提高到96ms。

[Do frameworks matter anymore?](https://brookslybrand.com/posts/do-frameworks-matter-anymore/)  
_22分钟_ 布鲁克斯·莱布兰德

在 AI 编码时代，框架仍然很重要，因为如果您不使用一种，您的代理将无论如何都会构建一个。 真正的问题不是框架是否重要，而是新框架是否值得构建。 现有的工具（如 React）解决了围绕结构和约束的实际问题，但仍然存在差距，尤其是在全栈集成和 Web 标准方面。 根据布鲁克斯的说法，仍然有空间来建造更好的东西。

[A deep dive into StyleX](https://flaviocopes.com/stylex/)  
_21分钟_由弗拉维奥·科普斯

StyleX 允许您将样式编写为 JavaScript 对象，然后在构建期间将其转换为常规 CSS 类。 浏览器获得没有运行时样式注入的纯CSS。 每个 CSS 声明都变成了一个小的可重用类，因此样式表随着应用程序的扩展而缓慢增长。 样式通过 JavaScript 构成可预测性，并且在浏览器看到类列表之前冲突解决。

[Context Windows Aren’t Memory](https://fandf.co/4Ay6vzB)  
_由 Oracle_ 赞助

有了扁平的历史，每一个转弯都会重新发送整个对话，因此每个请求的成本都比以前的要高。 修复是数据库支持的代理内存，其中工作、事实和程序状态存在于存储层。 阅读第80回合中约10.7倍小的请求背后的研究。

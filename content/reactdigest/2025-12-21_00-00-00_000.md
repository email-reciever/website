===============================================

[Lessons learned from React's vulnerabilities](https://sgued.fr/blog/react-rce/)  
_6分钟_由Sostthène Guédon

在过去的几周中，React Web 应用程序框架中发现了 3 个漏洞。 第一个，服务器端的远程代码执行是 Web 框架漏洞可能遇到的最严重的问题。 另外两个是拒绝服务和源代码曝光，危险性要小得多，但仍然具有影响力。 Sosthène 探索了可能提前应用的潜在缓解措施，以防止这些脆弱性或至少限制其严重性。

[Tests are dead. Meticulous AI is here.](https://www.meticulous.ai/?utm_source=react_digest)  
_由细致的赞助

Meticulous 自动创建并维护一个详尽的 E2E UI 测试套件，覆盖应用程序的每个角落——无需任何开发人员干预。 Dropbox、Lattice、Bilt Rewards 和数百个组织依靠一丝不苟的前端测试。 它是从 Chromium 级别构建的，带有确定性调度引擎——使其成为唯一消除薄片的测试工具。

[You might not need an effect](https://react.dev/learn/you-might-not-need-an-effect)  
_22分钟_由React团队

React Effects 允许您将组件与 API 或浏览器功能等外部系统同步。 但是，您通常不需要它们。 在转换数据以呈现或处理用户事件时避免效果。 相反，在渲染期间计算值并处理事件处理程序中的事件。 这使您的代码更快、更简单。

[Introducing React Server Components explorer](https://overreacted.io/introducing-rsc-explorer/)  
_7分钟_丹·阿布拉莫夫

Dan 创建了 RSC Explorer，这是一个基于浏览器的工具，演示 React Server 组件如何在引擎盖下工作。 该工具显示了 rsc 协议的运行情况，揭示了 React 如何通过网络而不仅仅是 HTML 序列化和发送组件树。 用户可以通过示例逐步查看流式、服务器操作以及在服务器更新期间组件如何维护状态。

[React compiler’s silent failures and how to fix them](https://acusti.ca/blog/2025/12/16/react-compiler-silent-failures-and-how-to-fix-them/)  
_7分钟

React Compiler 无需在 React 应用程序中手动记忆，从而节省精神能量并提高代码清晰度。 但是，当它无法优化组件时，它会静默失败，这会损害关键领域的性能。 Marjan 建议使用名为“react-hooks/todo”的未记录的 ESLint 规则来捕获编译失败并在需要时破坏构建。

[Intro to performance of React Server Components](https://calendar.perfplanet.com/2025/intro-to-performance-of-react-server-components/)  
_13分钟_ 纳迪亚·马卡雷维奇

React Server 组件通过将工作转移到服务器并发送更少的 JavaScript 来保证更好的性能。 比较不同 React 渲染方法的研究表明，服务器组件可以显着提高初始加载时间。 最好的结果来自 next.js 和服务器端数据提取，将加载时间从 4 秒以上缩短到 1.3 秒左右。

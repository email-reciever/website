=========================================

第561章 2026年6月14日

> 解决了常见的数据获取问题，如竞争条件、重复加载状态和浪费的网络请求

[A gentle introduction to TanStack query](https://neciudan.dev/a-gentle-introduction-to-tanstack-query)  
_22分钟_由内丘丹

TanStack 查询通过共享缓存解决常见的数据获取问题，例如竞争条件、重复加载状态和浪费的网络请求。 设置它只需要几行，它的内置默认设置，如重试和背景重新获取自动处理大多数边缘情况。 对于较大的应用程序，诸如 QueryOptions 和 OpenAPI 模式的代码生成等工具会删除重复的样板。 并行查询、无限滚动和乐观更新等功能几乎涵盖了每个现实世界的用例。

[Performance is not a technical problem](https://shud.in/thoughts/performance-is-not-a-technical-problem)  
_5分钟_由舒丁

SHU 说性能不会下降，因为工程师不小心。 它的性能下降是因为代码库的增长速度比任何人都快，而且抽象隐藏了仅在生产中出现的成本。 她认为真正的问题是熵：缓慢、无形的模式传播没有个人有足够的背景来捕捉。 修复不是更好的纪律或更智能的工具。 它的构建系统可以编码来之不易的知识并始终如一地应用它，而不会感到疲劳。

[How React server components integrate with Bundler](https://reactjs-maxxing.vercel.app/blog/how-react-server-component-integrate-with-bundler)  
_6 分钟_ 由 Sankalpa Acharya

React Server 组件在编译时将应用拆分为两个单独的版本。 服务器构建用仅注册引用的轻量级替换客户端组件，因此服务器永远不会运行像钩子或事件处理程序这样的浏览器代码。 然后，客户端构建正常编译这些组件，并生成一个对真实文件的链接引用。 在渲染过程中，服务器发出一个描述 UI 的流，浏览器使用该清单来加载和填充客户端部分。

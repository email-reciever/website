谷歌对真实 React 应用的现代网络指导技能
===========================================================

第570章 2026年8月16日

> AI编码工具通常建议过时的前端模式，因为它们的训练数据落后于网络平台

[Google's modern-web-guidance skill against a real React app](https://alfy.blog/2026/07/25/modern-web-guidance.html)  
_14 分钟_ 艾哈迈德·阿尔菲

人工智能编码工具通常建议过时的前端模式，因为它们的训练数据落后于网络平台。 谷歌浏览器的现代网络指导工具通过让您在编写代码之前搜索一组精选的最佳实践指南来解决这个问题。 针对真正的 React 应用程序进行了测试，它捕获了缺少黑暗模式声明、缺少原生提交处理的表单和陈旧的验证方法，同时正确标记了现有代码已经正确的标记。 它最有用的功能是将浏览器支持建议绑定到具体的基线日期，因此您可以确切知道何时可以安全地发布模式而没有后退。

[Cut AI Coding Token Costs by up to 36% with Sonar Vortex](https://fandf.co/3TSCp9f)  
_由声纳赞助_

Sonar Vortex 在 AI 编码代理的内部推理循环中运行，在编写代码之前提供深层架构上下文，然后实时验证输出。 在测试中，软件缺陷减少了 92%，令牌消耗减少。 在 LLM 调用上花费更少的时间构建更安全的代码。

[React doesn't need a state management tool. Then I built one.](https://granat.blog/posts/2026-07-24-react-arven/)  
_9 分钟_ Štěpán Granát

Štěpán 解释了为什么大多数 React 应用程序不需要状态管理库，但有些复杂的案例受益于集中状态。 他介绍了 React-Arven，这是一个结合现有 React 状态的小型库，无需创建另一个状态源。 它使用选择器和稳定动作来减少不必要的重新渲染，同时保留 React 熟悉的钩子和上下文模型。

[Experimenting with RSCs for performance and UX in Next.js](https://aurorascharff.no/posts/experimenting-with-rsc-for-performance-and-ux-in-nextjs/)  
_23分钟_由Aurora Scharff

Aurora 探讨了 React Server 组件如何在 Next.js 中提高性能和用户体验。 她展示了如何在服务器上使用小型客户端组件进行交互的同时保持服务器上的数据获取和渲染。 她的示例包括加载更多帖子、流式搜索结果和服务器呈现的邮件预览。 她还解释了 URL、悬念和服务器功能如何创建快速、响应的界面。

[Making referential stability a type](https://jovidecroock.com/blog/referential-stability-types/)  
_9 分钟_ 乔维·德·克鲁克

内联数组和传递给记忆化组件的回调会导致难以捕获的无声重渲染。 Jovi 的实验添加了一种名为 Stable 的品牌类型，该类型将参考标记为保证在不相关的渲染中幸存下来。 用于 React 和 Preact 钩子的严格包装器，然后在它们出现的确切行中拒绝不稳定的依赖项，并附有错误消息，说明如何修复它。 目标是将该合约从注释和 lint 规则转移到类型系统本身。

[We stopped using RSC on TanStack](https://tanstack.com/blog/we-stopped-using-rsc-on-tanstack-com)  
_7 一分钟_ 作者：Tanner Linsley

TanStack 在缩小了 Markdown 和代码渲染工具后停止使用 React Server 组件。 React Server 组件通过使客户端远离客户端而提高了性能，但它也增加了架构的复杂性。 对于较小的软件包，常规的服务器端渲染变得更加简单，同时保持站点快速。 经验表明，React Server 组件对于繁重的服务器端工作很有用，但当更简单的解决方案足够时，不应使用它。

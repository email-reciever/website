我们刚刚发布了 Astro 2.5，其中包含大量功能，包括：

*   **[Data collections and references](#data-collections-and-references)**：您的 `src/content/` 文件夹现在可以包含用于存储数据的 JSON 和 YAML 文件。 您可以从其他集合中引用此数据。
*   **[Hybrid rendering (experimental)](#static-by-default-hybrid-rendering-experimental)**：在您的大部分静态站点中允许服务器路由。
*   **[Custom client directives (experimental)](#custom-client-directives-experimental)**：用于集成的新 API，用于为 `client:` 指令定义自己的加载机制。
*   **[HTML minification](#html-minification)**：允许您缩小 Astro 模板的选项。
*   **[Parallelized rendering](#parallelized-rendering)**：ASTRO 现在并行运行同级组件，当您有多个组件自己加载数据时，加速渲染。
*   **[Polymorphic type helper](#polymorphic-type-helper)**：定义接受与内置元素相同的道具的组件。

数据收集和参考
------------------------------

内容集合是 Astro 管理和创作内容的一流解决方案。 Astro 2.5 通过 **新的数据格式和收藏参考文献进一步介绍了这个故事。**

首先，我们引入了一个新的 `type: 'data'` 属性，将 JSON 和 YAML 等数据格式存储在它们自己的集合中。 这可以使用集合来解锁新形式的内容，包括作者资料、可重复使用的图像替代文本、翻译字典等。

在现有内容集合旁边创建数据集合：

src/content/blog/ week-1.md week-2.md 作者/ Grace-hopper.json alan-turing.json

使用新的 `type: 'data'` 属性配置它们：

src/content/config.ts

导入 { defineCollection, z } 来自 "Astro:Content"
const authors = defineCollection({ type: "data", schema: z.object({ name: z.string(), sociallink: z.string().url(), }),})
const blog = defineCollection({ type: "content", schema: z.object({ /* ... */ }),)
导出 const 集合 = { 博客：博客，作者：作者 }

您可能还需要“引用”相关条目。 一个常见的例子是一篇博客文章，它引用了在数据集合中存储为 JSON 的可重用的作者配置文件，或者存储在同一集合中的相关帖子 URL。 您可以使用新的 `reference()` 函数配置这些关系：

import { defineCollection, 引用, z } 来自 "Astro:Content"
const blog = defineCollection({ type: "content", schema: z.object({ title: z.string(), // 引用 `authors` 集合中的一个作者: reference("authors"), // 引用 `blog` 集合中的相关帖子数组 通过 `slug` 相关帖子：z.array(reference("blog")), }),})
const authors = defineCollection({ type: "data", schema: z.object({ /** ... */ }),)
导出常量集合 = { 博客，作者 }

现在，每个博客文章都可以通过类型安全验证引用相关条目：

src/content/blog/welcome.md

---标题：“欢迎来到我的博客”作者：Ben-Holmes # references `src/content/authors/ben-holmes.json`relatedposts: - about-me # references `src/content/blog/about-me.md` - my-year-in-review # references `src/content/blog/my-year-in-review.md`---

查看 [updated content collections guide](https://docs.astro.build/en/guides/content-collections/) 以获取深入的示例。

默认情况下混合渲染（实验性）
---------------------------------------------

在 2.0 中，我们添加了在 SSR 应用程序中预渲染单个页面的功能。 现在在 2.5 你也可以做相反的事情； 在大部分静态站点中，您可以指定一些要预渲染的路由。

这个新的 `'hybrid'` 服务器输出选项翻转了 SSR 的默认预渲染行为，这样您就不再需要标记要预渲染的每个静态路由。 当我们稳定边缘情况时，此选项将在短时间内标记为实验性的。 您可以通过在配置的 `experimental` 部分中启用 `hybridOutput` 标志并添加适配器来使用它：

**astro.config.mjs**

从“astro/config”导入 { defineConfig } 从“@astrojs/node”导入nodejs
导出默认值 defineConfig({ 输出：“hybrid”，适配器：nodejs()，实验性： { hybridOutput: true, },})

完成后，您的整个网站将默认预渲染。 您可以通过将任何页面或端点的 `prerender` 导出设置为 `false` 来 _opt out_ 预渲染：

**SRC/页面/联系方式.ASTRO**

---export const preRender = false
if (astro.request.method === "post") { // 处理表单提交}---
<form method="POST"> <input type="text" name="name" /> <input type="email" name="email" /> <button type="submit">提交</button></form>

自定义客户端指令（实验）
--------------------------------------

自定义客户端指令允许集成作者定义新的 `client:` 指令，以在组件加载时获得更好的控制。

集成可以通过 `astro:config:setup` Hook 的新 `addClientDirective()` API 添加这些内容。 要使用此 API，请在配置的 `experimental` 部分中启用 `customClientDirectives`。

**astro.config.mjs**

从“astro/config”导入 { defineConfig } 从“astro-click-directive”导入 onClickDirective
导出默认的 DefineConfig({ 集成：[onClickDirective()]，实验性：{ CustomClientDirectives: true, },})

**ASTRO-Click-指令**

导出默认函数 onClickDirective() { return { hooks: { "astro:config:setup": ({ addClientDirective }) => { addClientDirective({ name: "click", entrypoint: "astro-click-directive/click.js", }) }, }, }}

现在，您可以在任何具有完整类型支持的框架组件上使用 `client:click`。

    <Counter client:click />

请参阅 [client directives documentation](https://docs.astro.build/en/reference/directives-reference/#custom-client-directives) 了解如何构建这些类型的集成。

html 缩小
------------------

您现在可以选择最小化由您的 Astro 组件生成的 HTML。

使用 `compressHTML` 选项，Astro 将从您的 HTML 中删除所有空格，包括换行符。

我们希望在不牺牲性能的情况下实现最小化。 对于服务器渲染的应用程序，在每次渲染上进行最小化可能会很昂贵。 使用 `compressHTML` 您的组件仅由 Astro 编译器压缩一次，然后在构建过程中进行压缩。

您可以在配置中启用此功能：

从“astro/config”导出默认 defineConfig({ compressHTML: true,})

注意：压缩在开发模式和最终构建中进行。

虽然这个选项 _will not_ 压缩由框架组件生成的 HTML，但您可以编写一个 [middleware](https://docs.astro.build/en/guides/middleware/) 来压缩 HTML 响应。

并行渲染
-----------------------

Astro 现在将并行渲染组件，以便树中更高的数据加载组件将不再阻塞也加载数据的其他组件，如下例所示：

    <Delayed ms={30} /><Delayed ms={20} /><Delayed ms={40} /><Delayed ms={10} />

此 `<Delayed />` 组件等待数毫秒。 以前，每个组件在开始渲染之前都需要等待之前的完成。 在 2.5 中，这些现在都将同时渲染。

有趣的事实：我们过去试图添加这种优化，但缺乏良好的基准来确保这实际上并没有_减慢渲染速度。 最近对基准 CI 基础设施的改进使我们能够充满信心地实施这一点。

多态类型助手
------------------------

Astro 现在包含一个 TypeScript 助手 (`Polymorphic`)，以便更轻松地构建可以以完全类型安全性呈现不同 HTML 元素的组件。 这对于像 `<Link>` 这样的组件很有用，可以根据传递给它的道具呈现为 `<a>` 或 `<button>`。

下面的示例实现了可以呈现为任何 HTML 元素的完全类型化的多态组件。 HTMLTag 类型用于确保 `as` 属性是有效的 HTML 元素。

---import { htmltag, polymorphic } 来自 "Astro/Types"
type props<Tag extends HTMLTag> = 多态性<{ as: tag }>
const { as: tag, ...props } = astro.props---
    <Tag {...props} />

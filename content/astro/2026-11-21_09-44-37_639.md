WP Engine 是世界上最大的托管 WordPress 托管服务提供商。 [8% of all humans online visit a WP Engine site each day](https://wpengine.com/blog/all-hands-2021-one-day-day-one/)。 保持良好的文档在这个规模上是必不可少的。 但 WP 引擎团队有一个问题：他们花费的时间比编写实际文档更多地维护文档代码库。 有些事情必须改变。

[Starlight](https://starlight.astro.build/) 是一个功能齐全、环保、默认可访问的文档主题，基于 [Astro](https://astro.build/)。 WP Engine 选择 Starlight 为 WP Engine 的无头 WordPress 应用程序托管解决方案 [Atlas](https://developers.wpengine.com/docs/atlas/overview/) 构建他们的新文档站点。 结果不言自明。

Starlight 使 Atlas 团队的移动速度是 50% 以上的两倍，开发成本降低了 50%。 今天，团队将 95% 的时间花在内容上，在代码维护和配置上几乎为零时间。

![](/_astro/wp-engine-results-summary.OTicG1TH_P5O1q.webp)

内容操作的速度是开发成本的两倍，而开发成本降低了 50% 以上。

挑战
-----------

WP Engine 在他们以前的 Docs 网站上遇到了三个主要问题。

首先，他们的文档过去保存在与提取这些文件的 next.js shell 不同的 GitHub MDX 存储库中。 每次更改 MDX 文件时，它不会触发自动站点重建或预览。 为了解决这个问题，团队有一个专门的开发环境，他们在部署之前测试了更改。 但是，这意味着额外的 Git 分支管理。

其次，Docs 站点的视觉和功能变化都需要很长时间。 最重要的是，以前的文档网站看起来不太好，也没有他们希望用户拥有的所有功能。

第三，由于MDX to React 解决方案，只有开发人员才能做出贡献。 这使 PMS 或客户支持人员等关键文档贡献者无法自行进行更改。

要求
-------------

为了解决 WP Engine 的三大挑战，他们需要一个低门槛的解决方案，以提高 Docs 维护者和贡献者的易用性。 它需要消除在前端开发上花费不必要的时间作为好文档的障碍。

值得庆幸的是，WP Engine 的开发人员 Jeff Everhart 知道了一个解决方案。

解决方案和实施
----------------------------

2023 年 8 月，Astro 推出了 Starlight on Product Hunt，以提供用于构建现代文档网站的开源 Web 框架。 Jeff 熟悉 Astro，但还没有充分的理由使用它。 星光提供了完美的机会。

![](/_astro/starlight-homepage.fi82h_Il_I3ITL.webp)

星光的主页。

Starlight 非常适合 WP 发动机，因为它配备了他们需要的每个可重复元素。 它带有导航、搜索、i18n、语法突出显示、黑暗模式等开箱即用的功能。 更重要的是，每一个元素看起来都不错！ 还有许多自定义选项，包括能够轻松指定明暗模式徽标。 如果有的话，这一切都是可能的，而无需编写太多自定义 CSS。 这将使 WP Engine 能够主要专注于编写内容，而不是花费几个 Sprint 来构建用户界面。

![](/_astro/starlight-docs-example.BSK4NS2Z_M9E9r.webp)

星光的文档示例。

Starlight 框架也是一个完全静态的解决方案，仅提供 HTML。 这降低了文档维护者和贡献者在对网站进行更改时的入职时间，因为双方都不必学习 JavaScript 也不必做出反应来发货。

迁移他们之前的解决方案并进入 Astro 几乎是无痛的。 Jeff 的团队所要做的就是将约 100 个 MDX 文件的现有文件夹复制到 Starlight 模板中，他们有一个实时站点。 他们可以通过配置和简单的 CSS 样式表来管理他们需要的一切。 由于使用起来很容易，他们的文档团队需要最少的培训才能登上 Starlight。

结果
--------

借助 WP Engine 之前的解决方案，他们的团队花费更多时间来管理 Docs 网站，而不是处理实际内容。 如果之前写作内容与管理网站的比例为 30:70，现在接近 95:5。 Astro 的 Starlight 框架将摩擦减少了一个数量级，以至于 WP Engine 团队的 PM 对新的 Web 框架有这样的看法：

> “对于我们的客户来说，这在体验方面要好得多，但它也节省了我生命中的许多时间，否则我不得不花时间仔细测试和塑造 Atlas Docs 的新页面。”

— WP Engine 的产品经理

由于删除了如此多的 Git 程序和手动测试步骤，WP Engine 的内容操作速度快了 2 倍*******。 因为这个过程更容易，人们也更愿意做出贡献。 Starlight 还帮助**将开发成本降低了 50% 以上**，因为它提供了开箱即用的所有 UI 元素 WP 引擎。 保持他们的解决方案的最新状态也比以前容易得多。 以前，他们必须管理与不同 UI 元素相关的几个依赖项，即下拉。 结果，他们有更多的 Dependabot 票要解决。 使用 Starlight，他们只需要更新一个框架。

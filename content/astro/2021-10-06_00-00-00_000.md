Astro V0.21.0 将是我们迄今为止最大的版本。 在高层次上，它包括：

*   [A new build engine, powered by Vite](#hello-vite)
*   [A new WASM compiler, written in Go](#hello-wasm)
*   [Brand new features, like Components-in-Markdown](#components-in-markdown)
*   [A new system for HTML live-updating via HMR](#hmr-meet-html)

您可以在计算机上的新项目目录中试用我们的最新版本 [in the browser](https://gitpod.io#snapshot/5e7cf2f1-8108-4fa5-99d3-ed8de70d8c23) 或在新项目目录中运行 `npm install astro@next--compiler`。

Astro 正在迅速成为构建更快、以内容为重点的网站的生产框架。 为了庆祝这一里程碑，这里有一些关于您在 Astro v0.21.0 及更高版本中可以期待的亮点和细节。

你好，维特！
-------------

Astro 0.21 正在升级内部构建引擎，用 [Vite](https://vitejs.dev) 替换 Snowpack。

我们对 Vite 进行了一些早期的实验，并留下了深刻的印象。 Vite 维护良好、文档完善、速度更快、错误信息非常好，并且一直在跨多个框架建立清晰的社区支持。 SSR 处理可能有点不稳定，但 Vite 团队意识到这一点并积极致力于它。

所以现在，当 Evan 你在推特上说他们正在制作时，你可以确定同样的速度也会出现在 Astro 上。

反过来也是如此：我们现在可以为更大的 Vite 社区提供修复和改进。 现在，当我们修复 Astro 中的 SSR 错误时（如 [adding support for ESM-only npm packages](https://github.com/vitejs/vite/pull/5197)），我们还为其他 Vite 用户修复它，包括 [SvelteKit](https://kit.svelte.dev/docs#routing-endpoints)。

选择 Vite 还有另一项巨大的好处：Rollup 插件。 从 v0.21.0 开始，您将能够将 Rollup 插件的整个生态系统连接到 Astro。 只需几个简单的插件即可启用 [image optimizations](https://github.com/JonasKruckenberg/imagetools/tree/main/packages/vite) 和 [icon loading](https://github.com/antfu/unplugin-icons) 等新功能。 魔法!

从 Snowpack 到 Vite 的这种转变可能会让一些人感到惊讶：Drew 和我自己都是这两个项目的维护者。 这是我们制作的[a hard decision](https://dev.to/fredkschott/5-more-things-i-learned-building-snowpack-to-20-000-stars-5dc9)。 但最终，在使用这两种工具之后，我可以自信地说 Vite 将是 Astro 未来的绝佳选择。

你好，Wasm！
-------------

Astro 0.21 具有另一个巨大的低级改进：全新 [@astrojs/compiler](https://github.com/withastro/astro-compiler-next)。 Astro 的新编译器是用 Go 编写的，并以 Wasm 的形式分发。 您可以在浏览器中或在 Node.js 和 Deno 的服务器上直接运行它。

新的 [@astrojs/compiler](https://github.com/withastro/astro-compiler-next) 解锁：

*   **灵活性：**使用WASM在任何地方运行编译器。
*   **speed:** 利用 Go 的编译语言性能构建站点更快。
*   **稳定性：** 编写我们自己的编译器允许我们修复一些长期存在的错误。

您可以在 [https://astro.build/play](https://astro.build/play) 的浏览器中使用新的编译器。 当你有一个快速的、任何地方的编译器时，这个 REPL 只是现在可能的一个例子。

Markdown 中的组件
-----------------------

我们最需要的功能 **_by far_** 是能够直接在 Markdown 中使用组件。 经过几个月的工作，我们很高兴地宣布这个功能终于来到了 Astro。

从 v0.21.0 开始，您可以通过可选的 `setup` 脚本在 Markdown FrontMatter 中导入组件。 导入后，您的组件可以在页面上的任何地方使用：

---标题：“Astro 0.21 早期预览”设置：| 从 '../components/logo.astro' 导入徽标； 从 '../components/counter.jsx' 导入 ReactCounter;---
    # ASTRO现在支持Markdown中的组件！
    <Logo />
    - 返回 Markdown。- 支持静态 Astro 组件。- 支持动态 React/Vue/Svelte 组件！
    <ReactCounter start={0} client:load />

这个新的 `setup` 脚本旨在最大限度地灵活性。 我们将继续改进此 API，并计划支持默认组件、默认布局和 Markdown 组件覆盖。

HMR，认识 HTML
---------------

从 v0.21.0 开始，Astro 将支持 Astro 组件和页面的完整 HMR。 更改代码库中的任何 `.astro` 文件，并观察开发服务器在没有完全刷新且不会丢失任何客户端状态的情况下更新页面。

Astro 一直支持 React、Preact、Svelte、Vue 和 Solid.js 等客户端 JavaScript 组件的强大 HMR 更新。 但是为 Astro 添加此功能是一个有趣的挑战，因为 Astro 组件只是静态 HTML。 我们的“零 JavaScript”方法意味着没有“Astro Runtime”可以连接以获取更新。 我们必须发挥创造力。

现在，Astro 的开发服务器将 HTML 更新发送到浏览器，然后运行一个小脚本来根据当前页面进行这些更新。 这会创建一个更细粒度的组件级 HMR 更新，不会影响页面的其余部分。

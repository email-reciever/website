SVG 优化器
--------------

Astro 的实验性 SVG 优化已重新设计，使用新的 `svgOptimizer` 选项替换以前的 `svgo` 标志。 新的 API 不是直接绑定到 SVGO，而是引入了一个 `SvgOptimizer` 接口，任何优化库都可以实现。 Astro 附带基于 [SVGO](https://svgo.dev/) 的内置 `svgoOptimizer()`，但您现在可以交换 [OxVG](https://github.com/noahbald/oxvg) 等替代方案。

astro.config.mjs

从“astro/config”导入 { defineConfig, svgooptimizer };
导出默认值 defineConfig({ 实验性: { svgOptimizer: svgoOptimizer() }});

启用后，所有用作组件的导入的 SVG 文件都会在构建时进行优化，以实现更小的文件大小和更好的性能。 您可以通过 [SVGO configuration object](https://svgo.dev/) 来自定义优化：

astro.config.mjs

从“astro/config”导入 { defineConfig, svgooptimizer };
导出默认的 defineConfig({ 实验性: { svgOptimizer: svgooptimizer({ plugins: ["preset-default", { name: "removeViewBox" }] }) }});

如果您之前使用 `experimental.svgo`，请更新您的配置以使用新的 `svgOptimizer` 选项。

有关详细信息，请参阅 [experimental SVG optimization docs](https://docs.astro.build/en/reference/experimental-flags/svg-optimization/)。

实验记录器
--------------------

现在可以使用自定义记录器控制 Astro Logger。 作为实验功能的一部分，Astro 附带内置记录器，例如 JSON Logger。 如果您使用编码代理来使用 Astro，结构化日志肯定会帮助您的工作流程。

### JSON 记录器

您可以使用 `experimental.logger` 或通过 CLI 使用标志 `--experimentalJson` 通过配置启用 JSON 日志记录：

astro.config.mjs

从“astro/config”导入 { defineConfig, loghandlers };
导出默认 defineConfig({ 实验性: { logger: loghandlers.json() }})

Astro Dev --experimentalJsonAsto 同步 --experimentalJsonAsto 构建 --experimentalJSON

### 自定义记录器

您还可以通过实现正确的接口来创建自己的自定义记录器：

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ 实验性: { logger: { entrypoint: "@org/custom-logger" } }})

@org/custom-logger.ts

导入类型 { AstrologgerDestination, AstroLoggerMessage } 来自 "Astro";import { MatchesLevel } 来自 "Astro/Logger";
函数 customLogger(level = 'info'): AstroLoggerDestination { return { write(message: AstroLoggerMessage) { if (MatchesLevel(Message.Level, level)) { // 在某处写消息 } } }}
导出默认 CustomLogger；

有关在项目中启用和使用此功能的更多信息，请参阅 [Experimental Logger docs](https://docs.astro.build/en/reference/experimental-flags/logger/)。

有关此实验 API 的完整概述并提供反馈，请参阅 [Custom logger RFC](https://github.com/withastro/roadmap/blob/logger/proposals/0059-custom-logger.md)。

Astro V7 阿尔法
---------------

Astro下一个主要版本的工作已经开始。 第一个 Astro 7 Alpha 包括两个重大变化：

### 邀请 8 支持

Astro 7 升级到 [Vite 8](https://vite.dev/blog/announcing-vite8)，这是为 Astro 提供动力的最新主要版本。 对于依赖 Vite 内部的 Astro 集成和插件来说，这是一个重大变化，但大多数 Astro 用户应该能够在不对其项目代码进行任何更改的情况下进行升级。

### 稳定的 Rust 编译器

基于 Rust 的 Astro 编译器，以前作为实验标志 (`experimental.rustCompiler`) 提供，现在是 Astro 7 中的默认编译器。与以前的基于 Go 的编译器相比，Rust 编译器提供的构建时间明显更快。 不再需要 `experimental.rustCompiler` 标志，可以从您的配置中删除。

### 试试看

Astro 7 Alpha可用于早期测试：

npm 安装 astro@alpha

我们很想听听您的反馈！ 请报告您在 [GitHub](https://github.com/withastro/astro/issues) 上遇到的任何问题。

其他改进
-------------------

*   **`allowedHosts` 用于预览服务器**：ASTRO 的 [`server.allowedHosts`](https://docs.astro.build/en/reference/configuration-reference/#serverallowedhosts) 选项现已传递给适配器预览服务器，让您控制在反向代理或自定义本地域运行 `astro preview` 时接受哪些主机名。 如果您是适配器作者，则 `allowedHosts` 现在可以在传递到预览入口点的 `options` 对象上使用。 有关详细信息，请参阅 [adapter reference](https://docs.astro.build/en/reference/adapter-reference/#previewserver)。
*   **`"jsx"` 选项 `compressHTML`**：`compressHTML` 选项现在接受使用 JSX 规则剥离空白的 `"jsx"` 值，因此空格在 `.astro` 和 `.tsx` 文件中的行为方式相同。 多行缩进文本折叠成单行，单词之间有空格，而 `<pre>` 标签内的空格被保留。

有关错误修复和较小改进的完整列表，请参阅 [the full changelog](https://github.com/withastro/astro/blob/main/packages/astro/CHANGELOG.md)。

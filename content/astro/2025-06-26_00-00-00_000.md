**实时内容集代表Astro中内容的下一次演变，为您熟悉和喜爱的熟悉的内容集合API带来实时数据功能。**

Astro 中的内容集合已经经历了几个进化阶段。 它们最初是作为一种非常简单且强大的方式来管理磁盘文件中的结构化内容的。 最初支持 Markdown、MDX 和 JSON 文件，它们允许您构建具有丰富的开发人员经验和类型安全数据的博客、文档站点等。

借助 Astro 5.0，内容集合扩展到一个成熟的内容层，支持各种数据源（包括 API、CMSS 等）的可插拔加载器。

在 Astro 5.10 中，内容集合采取了下一步行动，并对 **Live 内容集合进行了实验性支持。 有了这些，您现在可以在运行时而不是构建时获取内容，为动态、个性化和实时内容体验开辟全新的可能性。

无论您是构建一个频繁变化的库存的电子商务网站，一个更新的新闻网站，还是一个带有实时指标的仪表板，Astro的新实时内容集合提供了您所需的灵活性，同时保持了使Astro与众不同的类型安全性和开发人员体验。

实时内容集的基础
-----------------------------------------

在深入了解实时内容集之前，值得了解它们的基础：[loaders](https://docs.astro.build/en/reference/content-loader-reference/)。 Astro Content Collections 使用加载器来管理项目中的结构化数据和内容。 每个内容集合都依赖于其加载器来定义条目的填充方式。 在 `astro build` 期间，这些加载器运行以获取数据并填充本地数据存储。 然后，您的页面使用 `getCollection()` 和 `getEntry()` 函数查询此不可变快照。

实时内容集合使这一概念更进一步：它们不是在构建时获取数据，而是在请求时获取数据，让您可以访问最新鲜的数据。 有时您需要静态内容的速度和可靠性，但有时您需要实时数据的灵活性和动态性。 正如您可以在 Astro 中的静态和按需渲染页面之间进行选择一样，您现在可以在构建时和实时内容集合之间进行选择。

无论您做出哪种选择，您都可以从现有的内容集合中获得相同的熟悉的 API。 如果您知道如何使用 `getCollection()` 和 `getEntry()`，您就已经知道您需要使用 `getLiveCollection()` 和 `getLiveEntry()` 的大部分内容。

现场收藏的架构
----------------------------------

与在构建过程中填充静态数据存储的构建时内容集合不同，实时内容集合的工作原理不同：

当请求使用实时内容集合的页面时：

1.  页面调用`getLiveCollection()`或`getLiveEntry()`获取数据。
2.  从外部源（API、数据库等）获取数据。
3.  结果被处理并根据您的模式进行验证。
4.  数据返回到您的页面组件。

这种体系结构意味着您总是在处理新数据，但也意味着每个请求都涉及对数据源的网络调用。 这种权衡非常适合数据新鲜度比绝对性能更重要的用例。 您可以通过页面缓存来缓解性能问题，实时集合通过提供可用于优化此功能的缓存提示来提供帮助。 随着这个实验功能的发展，Astro 最终将为您处理更多这样的事情。 目前，您可以使用 `Cache-Control` 和其他标头来控制数据在浏览器和 CDN 中缓存的时间。

构建实时内容加载程序
------------------------------

创建自定义实时加载程序允许您连接到任何 API 或数据源，从而使您可以完全控制数据的获取和处理方式。 API 设计简单、灵活且类型安全，因此您可以构建适合您特定需求的加载器，同时保持 Astro 众所周知的易用性和类型安全性。 我们希望看到人们尝试实验 API 并对其进行反馈，以便我们可以在它变得稳定之前对其进行改进。

实时收藏与构建时集合
----------------------------------------

了解何时使用实时收藏与传统的构建时集合对于构建高性能应用程序至关重要：

### 在以下情况下使用实时收藏：

*   **数据频繁更改**：库存水平、用户生成的内容、实时指标
*   **需要个性化**：用户特定的建议，仪表板数据
*   **实时准确性至关重要**：新闻提要、社交媒体内容、实时得分
*   **需要动态过滤**：搜索结果，过滤产品目录

### 在以下情况下使用构建时集合：

*   **内容相对静态**：博客文章、文档、营销页面
*   **性能是最重要的**：每毫秒重要的高流量站点
*   **您需要图像转换或 MDX 渲染**：实时集合不支持图像转换或 MDX 渲染

### 混合方法

您可以将两种方法组合在同一项目中，甚至在同一页面中。 例如，您可以将构建时集合用于博客文章等静态内容，而将实时集合用于评论或用户配置文件等动态功能。

性能考虑和最佳实践
-------------------------------------------

在使用实时内容集合时，考虑性能影响非常重要，尤其是在使用较慢或更复杂的 API 时。 以下是一些需要牢记的最佳实践：

### 使用缓存提示进行缓存

实时内容集合支持允许您为响应提供缓存元数据的缓存提示。 这有助于通过启用适当的缓存标头和缓存失效策略来优化性能。 在 Astro 的未来版本中，这些缓存提示将用于自动缓存页面，但现在您可以使用它们在页面中设置适当的 HTTP 标头。

src/loaders/cached-store-loader.ts

从“astro:content”导入类型 { liveloader };
接口产品{ID：字符串； 名称：字符串； 价格：编号； lastmodified：字符串； 类别：字符串；}
导出函数 createStoreLoader(baseUrl: string): liveloader<Product> { return { loadCollection: async (filter) => { try { const response = await fetch(`${baseUrl}/products`); if (!response.ok) { return { error: new error( `Failed to fetch products: ${response.statusText}`, ), }; }

加载条目：异步（ID）=> { { const 响应 = await fetch(`${baseUrl}/products/${id}`); if (response.status === 404) { return { 条目：null }; } if (!response.ok) { return { error: new error(`Failed to fetch product: ${response.statusText}`), }; }

实时内容集合的未来
------------------------------------

实时内容集合目前是实验性的，但它们代表了 Astro 进化的重要一步，为在 Astro 上使用动态实时内容构建站点开辟了更多用例，同时保持您喜爱的开发人员体验。

下一步
-----------

实时内容集在 Astro 5.10 中是实验性的，我们需要您的反馈。 参与：

*   [Read the docs](https://docs.astro.build/en/reference/experimental-flags/live-content-collections/) 开始在您的 Astro 项目中使用实时内容集合。
*   [Read the RFC](https://github.com/withastro/roadmap/blob/feat/live-loaders/proposals/0055-live-content-loaders.md) 和 [share your feedback](https://github.com/withastro/roadmap/pull/1164)。
*   查看我的 [live RSS feed loader](https://github.com/ascorbic/astro-loaders/tree/main/packages/feed) 和 [Bluesky loader](https://github.com/ascorbic/astro-loaders/tree/main/packages/bluesky) 包，了解它们是如何工作的，并了解您可以使用的一些模式。
*   建立自己的装载机，与社区分享！ 让我们知道您构建的内容，我们可以帮助推广它。

实时内容收藏为构建动态的实时网络体验开辟了令人兴奋的新可能性，同时保持您喜爱的开发人员体验。 无论您是在构建电子商务网站、新闻平台还是数据仪表板，实时收藏都提供了创建真正动态 Web 应用程序所需的灵活性和功能。

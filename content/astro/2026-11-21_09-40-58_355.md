实验静态 `import.meta.env`
-----------------------------------

环境变量可能很复杂！ Astro 的 `astro:env` API 允许您配置 [type-safe schema for your environment variables](https://docs.astro.build/en/guides/environment-variables/#type-safe-environment-variables)，并将通过 `astro:env` 导入的变量转换为预期类型。 这是在 Astro 中使用环境变量的推荐方式，因为它允许您轻松查看和管理您的变量是公共的还是秘密的、客户端或仅在构建时的服务器上以及您的值的数据类型。

但是，如果需要，您仍然可以通过 `process.env` 和 `import.meta.env` 直接访问您的环境变量。 这是在 Astro 5.0 中添加 `astro:env` 之前在 Astro 中使用环境变量的唯一方法，它对 `import.meta.env` 的处理包括一些用于不再需要的早期版本的 Astro 的逻辑。

Astro 5.13 包含一个新的 `experimental.staticImportMetaEnv` 标志，用于更新 `import.meta.env` 的行为以与 [Vite’s handling of environment variables](https://vite.dev/guide/env-and-mode.html#env-variables) 保持一致，并与 Astro 的当前实现和功能更容易使用。 该标志取代了之前的 `rawEnvVariables` 作为处理私有元环境变量的更完整的解决方案。 **这将成为 Astro 6.0** 中的默认行为，并且这个早期预览是作为一个实验功能引入的。

目前，非公共 `import.meta.env` 环境变量被引用 `process.env` 替换。 此外，Astro 还可以转换通过 `import.meta.env` 使用的环境变量的值类型，这可以阻止某些值的访问，例如字符串 `"true"`（转换为布尔值）和 `"1"`（转换为数字）。

`experimental.staticImportMetaEnv` 标志简化了 Astro 的默认行为，使其更易于理解和使用。 Astro 将不再用 `process.env` 调用替换任何 `import.meta.env` 环境变量，也不会强制值。 相反，您的私有元环境变量将始终内联。

要启用此功能，请在 Astro Config 中添加实验标志，并在启用后删除 `experimental.rawEnvValues` 标志：

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ 实验性：{ staticImportMetaEnv: true, rawEnvValues: true }});

有关选择此早期功能预览以及如何相应更新项目代码的更多信息，请参阅 [实验静态 `import.meta.env` 文档](https://docs.astro.build/en/reference/experimental-flags/static-import-meta-env/)。

您可以在 [environment variables documentation](https://docs.astro.build/en/guides/environment-variables/) 中了解有关在 Astro 中使用环境变量的更多信息，包括 `astro:env`。

实验 Chrome DevTools 工作区支持
-------------------------------------------

Chrome 工作空间文件夹允许您通过连接的工作空间文件夹将 DevTools 中所做的更改保存回项目代码。 这使您无需离开浏览器选项卡即可应用CSS调整等编辑！

Astro 5.13 为 Astro Dev Server 带来了一个新的实验选项，可以为您的项目自动配置 Chrome DevTools 工作空间。 您的项目文件夹将显示为工作区源，无需手动配置，即可连接。 然后，您在“源”面板中所做的任何更改都会自动保存到您的本地源文件中。

要启用此功能，请将实验标志 `chromeDevtoolsWorkspace` 添加到您的 Astro 配置：

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ 实验性: { chromeDevToolsWorkspace: true }});

有关详细信息，请参阅 [experimental Chrome DevTools workspace feature documentation](https://docs.astro.build/en/reference/experimental-flags/chrome-devtools-workspace/)。

多个站点地图
------------------

`@astrojs/sitemap` 集成一直支持将外部生成的页面包含在 Astro 生成的 `sitemap-index.xml` 文件中的选项。 这允许您在站点地图中包含属于已部署站点但不是由 Astro 创建的页面的页面。

该集成的最新版本添加了一个新的 `customSitemaps` 配置选项，以在 `sitemap-index.xml` 文件中包含外部生成的站点地图以及 Astro 生成的 Sitemap 条目。

这对于与您的 Astro 站点 (`example.com`) 在同一域中的多框架设置很有用，例如 `example.com/blog` 的博客，其站点地图由另一个框架生成。

您可以在 `sitemap` 配置中指定任何其他站点地图：

astro.config.mjs

从“astro/config”导入 { defineConfig }；从“@astrojs/sitemap”导入站点地图；
导出默认的 defineConfig({ site: 'https://example.com', 集成: [ sitemap({ customsitemaps: ['https://example.com/blog/sitemap.xml', 'https://example.com/helpcenter/sitemap.xml' ] }) ]});

在 [`@astrojs/sitemap` 配置文档](https://docs.astro.build/en/guides/integrations-guide/sitemap/#configuration) 中了解更多信息。

感谢贡献此功能的 [Gourav Khunger](https://github.com/gouravkhunger)。

实验托管错误页面
------------------------------

Node.js 适配器的最新版本附带了从任何指定主机加载预渲染的自定义错误页面的实验性支持。

Astro 需要能够加载您的 404 页面才能在响应中返回它。 默认情况下，Astro 将从与请求请求的同一主机加载预渲染的自定义错误页面。 例如，如果向 `https://example.com/nonexistent-page` 发出请求，Astro 将尝试从 `https://example.com/404.html` 加载预渲染错误页面。

`@astrojs/node@9.4.0` 现在处理您的自定义错误页面必须从其他主机加载的情况，例如当服务器在反向代理后面运行或可能无法访问外部主机 URL 的容器中。 当从本地主机而不是通过公共互联网加载预渲染错误页面更有效时，您也可以使用此选项。

要使用此功能，请将 Astro 配置中的 `experimentalErrorPageHost` 适配器选项设置为所需的主机 URL。 例如，如果您的服务器在 localhost 上运行并通过代理提供服务，您可以确保通过 localhost url 获取预渲染的错误页面：

astro.config.mjs

从“astro/config”导入 { defineconfig }；从 '@astrojs/node' 导入节点；
export default defineConfig({ adapter: node({ // 如果你的服务器在 localhost 上运行并通过代理服务) // 像这样设置主机，以确保通过 localhost urlexperienerErrorPageHost 获取预渲染的错误页面：'http://localhost:4321' })});

有关启用和使用此实验功能的更多信息，请参阅 [`@astrojs/node` 适配器文档](https://docs.astro.build/en/guides/integrations-guide/node/#experimentalerrorpagehost)。

Astro DB 表中的枚举支持
------------------------------

我们相信您会 `({ enum: ['happy', 'thrilled', 'over the moon'] })` 了解 Astro DB 的此更新！

最新版本的 `@astrojs/db` 为 Astro DB 表中的文本列提供了期待已久的 Enum 支持。 这种行为更好地符合用户的期望和底层的毛毛雨实现。

请注意，这专门用于生成类型，不会执行运行时验证。 删除、添加和更改值应在您自己的项目代码中处理。

astro.config.mjs

从“astro:db”导入 { 列，定义表 }；
// 表定义Const UserTable = defineTable({ columns: { id: column.number({ primaryKey: true }), name: column.text(), rank: column.text({ enum: ['user', 'mod', 'admin'] }) }});
// 结果类型 DefinitionType UserTableInferInsert = { id?: string; 名称：字符串； 等级：“用户”| “模组”| “管理员”;}

Cloudflare KV 的本地支持
------------------------------

Cloudflare 适配器的最新版本在运行 `astro dev` 时包含对 [Cloudflare Workers KV](https://developers.cloudflare.com/kv/) 的本地支持。 此内部重构是为 Astro 会话供电的临时替代品，并且不需要对现有项目代码进行任何更改。

但是，您现在可以根据需要选择连接到远程 [Cloudflare KV Namespace](https://developers.cloudflare.com/kv/concepts/kv-namespaces/) 并在本地开发期间使用生产数据。

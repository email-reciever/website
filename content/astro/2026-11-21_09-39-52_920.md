配置开发工具栏放置
------------------------------

开发工具栏现在支持项目范围的 `placement` 配置选项，允许您设置在团队成员和环境中持续存在的默认位置。

以前，工具栏放置只能通过 UI 控制，首选项存储在 `localStorage` 中。 这意味着每个团队成员都必须手动调整位置，并且在清除浏览器数据时将丢失设置。 具有底部中心 UI 元素（如聊天小部件或 Cookie 横幅）的网站无法避免与工具栏发生冲突。

将新的 `devToolbar.placement` 选项添加到您的 Astro 配置中：

astro.config.mjs

导出默认定义配置({ devtoolbar: { 位置：'bottom-left', },});

配置作为项目默认值，同时仍然尊重用户偏好。 如果需要，单个开发人员可以通过工具栏 UI 覆盖设置。

阅读我们的[Astro dev toolbar](https://docs.astro.build/en/guides/dev-toolbar/)指南，了解有关可用放置选项和使用情况的更多详细信息。

感谢贡献此功能的 [Tony Narlock](https://github.com/tony)！

在 `file()` 加载器中进行异步解析
----------------------------------

`file()` 加载程序中的 `parser()` 选项现在支持异步功能，支持更复杂的数据处理工作流。

此增强功能允许您在分配从文件加载的最终数据期间执行异步操作，例如获取其他数据或进行 API 调用：

astro.config.mjs

从“astro:content”导入 { defineCollection }；从“astro/loaders”导入 { file }；
const data = defineCollection({ loader: file('src/data/products.json', { parser: async (text) => { const products = json.parse(text);
// 异步获取附加数据 const 丰富的产品 = await Promise.all( products.map(product) => { const details = await fetchProductDetails(product.id); return { ...product, ...details }; }) );
退货丰富的产品； }, }),});

现有的同步解析器功能可以在不修改的情况下继续工作，但您现在可以利用更高级的场景异步功能。

感谢贡献此功能的 [Patrick Arlt](https://github.com/patrickarlt)！

分区 cookie 支持
----------------------------

Astro 现在通过 `Astro.cookies.set()` 上的新 `partitioned` 选项支持分区 cookie，为嵌入式上下文实现更好的隐私控制。

分区 cookie 是隐私沙盒计划的一部分，允许每个顶级站点隔离 cookie。 当您的Astro应用程序嵌入在iframe中时，这特别有用，因为分区cookies提供了一种在尊重现代隐私标准的同时维护会话状态的方法：

---// 设置分区 cookieeastro.cookies.set('session', sessionId, { partitioned: true, secure: true, // 分区 cookie 需要 sameSite: 'none', // 通常与分区 cookie 一起使用});---

当 `partitioned` 设置为 `true` 时，cookie 将绑定到顶层站点的分区，防止跨站点跟踪，同时仍允许在嵌入式场景中实现必要的功能。

阅读我们关于 [cookies in Astro](https://docs.astro.build/en/guides/on-demand-rendering/#cookies) 的部分，了解有关有效使用 cookie 的更多信息。

感谢贡献此功能的 [John Mortlock](https://github.com/jmortlock)！

图像转换的背景颜色
----------------------------------------

图像转换的新 `background` 属性允许您在将图像转换为不支持透明度的格式时控制背景颜色。

以前，转换为 JPEG 等格式的图像将使用黑色背景。 您现在可以使用标准的 CSS 颜色语法指定任何颜色：

---从'./my-image.png'中导入{image}；
<!-- 转换为 jpeg 时使用白色背景 --><Image src={myImage} format="jpeg" background="white" alt="Product" />
<!-- 或使用任何 CSS 颜色语法 --><Image src={myImage} format="jpeg" background="rgb(248 250 252)" alt="Hero" /><Image src={myImage} format="jpeg" background="#f8fafc" alt="Banner" />

使用 `getImage()` 时具有相同的属性：

从“astro:assets”导入 { getImage }；从 './hero.png' 导入 HeroImage；
const optimizedimage = await getImage({ src: heroImage, 格式: 'jpeg', 背景: 'white',});

如果您想查看可用于图像转换的所有其他选项，请查看我们文档中的 [Astro Images guide](https://docs.astro.build/en/guides/images/)。

感谢贡献此功能的 [Julien Cayzac](https://github.com/jcayzac)！

用于调整图像大小的清晰内核选择
----------------------------------------

Sharp Image Service 现在支持通过新的 `kernel` 配置选项配置 Resize 内核算法，让您对图像质量进行细粒度控制。

默认情况下，Sharp 使用 `lanczos3` 内核进行缩小。 根据源图像的特性，不同的内核可以产生明显不同的结果：有些擅长保存锐利的边缘，而另一些则产生更平滑的结果。

在图像服务配置中设置您喜欢的内核：

astro.config.mjs

导出默认 defineConfig({ image: { service: { entrypoint: 'astro/assets/services/sharp', config: { kernel: 'mks2021' } }})

请注意，此配置适用于您网站上的所有图像，目前无法按图像进行配置。

每个内核在清晰度、平滑度和性能之间提供不同的权衡。 有关所有可用内核选项的详细信息，请参见 [Sharp’s resize documentation](https://sharp.pixelplumbing.com/api-resize/#resize)。

感谢贡献此功能的 [Mark Ignacio](https://github.com/mark-ignacio)！

`retainBody` `glob()` 装载机选项
--------------------------------------

`glob()` 加载器现在包含一个 `retainBody` 选项，以帮助减少数据存储的大小，特别是对大型内容收集有益。

默认情况下，除了渲染的 HTML 之外，Astro 还将每个内容文件的原始正文存储在 `entry.body` 中。 对于集合非常大的网站，这可以显着增加部署的数据存储大小。

为防止这种情况，请在 `glob()` 加载程序中将选项 `retainBody` 设置为 false：

astro.config.mjs

从“astro:content”中导入 { defineCollection }；从“astro/loaders”导入 { glob }；
const blog = defineCollection({ loader: glob({ pattern: '**/*.md', base: './src/content/blog', retainbody: false }),});

当 `retainBody` 设置为 `false` 时：

*   `entry.body` 将是 `undefined` 而不是包含原始文件内容
*   Markdown 文件的 `entry.rendered.html` 中仍可使用渲染的 HTML
*    `entry.filePath` 属性仍然指向原始文件
*   对于 MDX 集合，这可以显着减少数据存储大小

这对于遇到 JSON 字符串大小限制或想要优化其部署大小的非常大的站点特别有用。 该选项默认为 `true` 以保持向后兼容性。

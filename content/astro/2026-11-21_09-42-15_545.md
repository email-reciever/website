Markdown中的远程图像优化
-----------------------------------

Astro 的 Image Service 已经处理了优化本地 Markdown 图像的操作。 现在，它也可以对远程图像做同样的事情！

以前，当您对远程图像使用 `![Houston](https://images.unsplash.com/photo-1530089711124-9ca31fb9e863)` 之类的标准 Markdown 语法时，Astro 将简单地通过它们而不进行任何处理。 这与 `Image` 组件的工作方式不同，这意味着您不能利用 Astro 对存储在 CMS 或其他外部位置中的图像的图像优化。

借助 Astro 5.4，Image Service 现在也会自动处理和优化 Markdown 和 MDX 文件中的远程图像。 您将获得 Astro 图像优化的所有好处，而无需更改编写内容的方式。

默认情况下启用此功能 - Markdown 和 MDX 文件中的任何现有远程图像将自动优化。 如果您需要选择退出特定图像，可以使用 HTML `<img>` 标签而不是 Markdown 语法。

请注意，`public/` 文件夹中的图像仍未按照 Astro 的正常行为进行处理。

感谢 [PolyWolf](https://github.com/p0lyw0lf) 的巨大贡献！

Markdown中的实验性响应图像支持
---------------------------------------------

以前，实验响应图像功能仅在 `Image` 和 `Picture` 组件中得到完全支持。 在 Astro 5.4 中，我们也将此支持扩展到 Markdown 和 MDX 文件！

在 Astro Config 中使用 `experimental.responsiveImages` 选项时，Astro 现在将为 Markdown 和 MDX 文件中的图像生成响应图像，应用正确的属性和样式以使其响应。

再次感谢 [PolyWolf](https://github.com/p0lyw0lf) 也贡献了此功能！

面向开发和预览服务器的 AllowList 主机
-----------------------------------------

为了增强安全性，Astro 5.4 引入了一个新选项来限制开发和预览服务器将响应的主机名。

新的 `server.allowedHosts` 配置选项允许您指定允许的主机名列表。 这将检查传入请求的 `Host` 标头，并且仅响应具有匹配主机名的请求。 这有助于防止 [DNS rebinding attacks](https://en.wikipedia.org/wiki/DNS_rebinding)，例如 [GHSA-vg6x-rcgg-rjx6](https://github.com/vitejs/vite/security/advisories/GHSA-vg6x-rcgg-rjx6)。

您可以在 `astro.config.mjs` 中配置：

astro.config.mjs

从“astro/config”导入 {defineConfig}；
导出默认 defineConfig({ 服务器：{ allowedHosts: ['hello.world.example.local', 'hello.example.local'] }})

或直接在 CLI 中：

astro dev --allowed-hosts=hello.world.example.local,hello.example.localastro 预览 --allowed-hosts=hello.world.example.local,hello.example.local

您应该仅将此用于您控制的域。 允许第三方域可以让您面临安全风险。

如果您需要有关其在引擎盖下如何工作的更多详细信息，请查看 [Vite documentation](https://vite.dev/config/server-options.html#server-allowedhosts)，因为实现是相同的。

Vercel ISR 的正则表达式支持不包括
------------------------------------

如果您在 Vercel 适配器中使用 [Incremental Static Regeneration (ISR)](https://docs.astro.build/en/guides/integrations-guide/vercel/#isr)，您现在可以更灵活地定义应从 ISR 缓存中排除哪些路由。

以前，您必须在 `isr.exclude` 选项中明确列出要排除的每个路由。 对于需要服务器端渲染的许多路由的站点，这可能会变得笨拙：

astro.config.mjs

从'@Astrojs/Vercel'导入Vercel；
导出默认 defineConfig({ 输出：'server'，适配器：vercel({ isr: { exclude: [ '/api/users', '/api/posts', '/api/comments', // ...更多的 API 路由 ] } })});

现在，您可以使用正则表达式创建强大的基于模式的排除项：

astro.config.mjs

从'@Astrojs/Vercel'导入Vercel；
导出默认值 defineConfig({ output: 'server', adapter: vercel({ isr: { exclude: [ '/preview', // 特定路由 '/auth/[page]], // 动态路由 /^\/api\/.+/, // regexp: 所有路由以开始 /api/ ] })});

这使大规模管理 ISR 排除变得更加容易，特别是对于具有许多 API 路由或动态页面的网站。

感谢 [Slawek Kolodziej](https://github.com/slawekkolodziej) 的贡献！

新的配置助手和构建选项
----------------------------------

Astro 5.4 引入了新的 API，可以更轻松地以编程方式使用 Astro，特别是在测试和脚本化场景中。

### 配置助手

现在从 `astro/config` 导出了两个新的辅助函数：

*   `mergeConfig`：允许您在基本配置的顶部合并部分定义的 Astro 配置，遵循与集成可用的 `updateConfig` 函数相同的规则。
*   `validateConfig`：验证给定值是有效的 Astro 配置，并根据需要填写默认值。

这些帮助器对于集成作者和编写需要以编程方式操作 Astro 配置的脚本的开发人员特别有用。

### 程序化构建选项

`build` API 现在接受具有两个选项的第二个可选 `BuildOptions` 参数：

*   `devOutput`：设置为`true`时，输出类似于`astro dev`中的代码转换的基于开发的构建。 默认为`false`。
*   `teardownCompiler`：控制是否在构建后拆除编译器 WASM 实例。 默认为`true`。

这些选项在以编程方式运行 Astro 构建时提供了更多控制，特别是用于测试场景或自定义构建管道。

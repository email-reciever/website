自 Astro 1.0 首次推出以来，开发人员不得不在生成 [static (SSG)](https://docs.astro.build/en/core-concepts/routing/#static-ssg-mode) 或 [server (SSR)](https://docs.astro.build/en/guides/server-side-rendering/) 输出之间进行选择。 静态网站通过提前构建您的网页，提供令人难以置信的性能。 服务器利用它们的动态功能来按需生成 HTML，每个请求都独一无二。

到目前为止，这是一个全有或全无的决定——这是完全静态的还是我应该部署服务器？

[Astro 2.0](/blog/astro-2) 使用 **Hybrid 渲染**解锁两全其美。 在静态页面的性能或您网站的每个页面的服务器渲染的完全灵活性之间进行选择。

在这篇文章中，我们将通过探索 Astro 2.0 中实现的一些新功能和性能改进来讨论混合渲染的工作原理。

Astro 的构建过程如何运作？
----------------------------------

Astro 的构建过程发生在多个阶段，从 [Vite](https://vitejs.dev) 生成的服务器端 JavaScript 包开始。 为了稍微简化事情，这个包的输出包括：

*   **用于渲染HTML的服务器端JavaScript**
*   使用静态分析来收集客户端交互所需的所有组件的**客户端清单**
*   **CSS 和其他资产**

接下来，Astro 使用客户端清单来启动第二个构建过程，该流程捆绑了优化的客户端 JavaScript。

如果您配置的 [`output`](https://docs.astro.build/en/reference/configuration-reference/#output) 是 `static`，Astro 将执行服务器端 JavaScript 并将输出写入 `.html` 文件。 服务器端的 JavaScript 然后被丢弃。

![Flow diagram of Astro's static build process](/_astro/static.C0I_Dov4_ZwLg5L.webp)

如果您配置的 [`output`](https://docs.astro.build/en/reference/configuration-reference/#output) 是 `server`，则 Astro 将服务器端 JavaScript 传递给 [`adapter`](https://docs.astro.build/en/reference/configuration-reference/#adapter) 以进行进一步处理。 适配器确保您的服务器端 JavaScript 与特定主机提供商的 JavaScript 运行时兼容。 请注意，在这种情况下，最终输出不是一组 `.html` 文件，而是呈现 HTML 所需的 JavaScript 代码。

![Flow diagram of Astro's server build process](/_astro/server.D2Qe3bq5_2ic1vB.webp)

不幸的是，这种设置非常严格，不允许在同一项目中混合静态和动态路线。 我们真正需要的是一个能够并行实现两种模式的过程。

混合渲染如何工作？
------------------------------

在 Astro 2.0 中，我们改进了 `astro build` 管道来处理混合渲染。 在最初的捆绑过程中，一个新的静态分析步骤确定应预渲染哪些页面。 这允许我们将您的路由拆分为单独的块，这取决于 _when_ 应该呈现它们。

与原始 `static` 过程非常相似，执行预渲染块并将输出写入 `.html` 文件。 然后丢弃该块。

与原始 `server` 过程非常相似，服务器块被传递给 [`adapter`](https://docs.astro.build/en/reference/configuration-reference/#adapter) 进行进一步处理。 根据您的适配器，它最终将作为无服务器或边缘功能部署。

![Flow diagram of Astro's new hybrid build process](/_astro/hybrid.BUuwbKmd_6Xta4.webp)

为什么要使用静态分析？
-------------------------

静态分析是一种用于分析源代码而无需实际执行的技术。 Astro 在许多地方都依赖这种方法，但在构建过程中尤其重要。 出于性能原因，Astro 必须能够在不执行其源代码的情况下对页面进行分类。 对于较小的项目，执行可能不是一个问题，但在规模上它很快就会成为瓶颈。

混合渲染是专门考虑静态分析设计的，尽管我们做了[entertain alternative APIs](https://github.com/withastro/roadmap/blob/main/proposals/0029-prerender-api.md#alternatives)。 Astro 的构建过程能够检查 `export const prerender = true` 语句的存在，以确定应预渲染哪些页面。 为了有效地做到这一点，我们依赖于精彩的 [`es-module-lexer`](https://github.com/guybedford/es-module-lexer) 库，该库也在 Node 的内部使用。

---// 此路由应在构建时生成！export const prerender = true
const text = await fetch("https://example.com/").then((res) => res.text())---
    <article set:html={text} />

混合渲染用例
------------------------------

混合渲染解锁了一组全新的可能用例，但我们想强调一些我们特别兴奋的情况。

用例：提高热门页面的渲染性能
-------------------------------------------------

考虑一个由 Astro 构建的小型/中型电子商务网站，具有数千种不同的可能产品和变化。 如果您要使用静态网站生成，每次这些产品之一更改或缺货时，您都会被困住重建您的网站。

这种项目需要服务器端渲染，这将允许您的产品页面在每个请求中都得到新鲜的生成。 但现在我们有一个新问题：您的主页不再是静态的。 加载性能对于推动销售仍然至关重要，而且您的主页没有任何动态内容，实际上需要在每个请求中重新构建它。

混合渲染通过提前将主页呈现为静态 HTML 来解决我们的性能问题，同时保持网站的其余部分按需渲染。

用例：将 API 添加到您现有的静态站点
---------------------------------------------

随着静态网站的增长，您可能会发现需要托管公共 API。 从历史上看，向静态站点添加 API 需要特定于主机的配置，但在 Astro 2.0 中，我们可以在不牺牲静态页面的情况下添加 [server endpoints (API routes)](https://docs.astro.build/en/core-concepts/endpoints/#server-endpoints-api-routes)。

事实上，服务器端点可以通过我们的 [Integrations API](https://docs.astro.build/en/reference/integrations-reference/) 的 [`injectRoute`](https://docs.astro.build/en/reference/integrations-reference/#injectroute-option) 钩自动添加。 我们很高兴用这些新原语培育一个强大的第三方集成生态系统！

用例：提高大型站点的构建性能
----------------------------------------------

静态生成可能很难扩展到数千页，因为每个页面都必须在构建过程中呈现。 服务器端渲染将页面渲染推迟到请求时间，从而消除了构建过程中的潜在瓶颈。

当 `getStaticPaths` 生成数百条路由时，服务器端渲染可能会带来显着的性能提升。 在我们的内部测试中，通过将动态路由切换到服务器端渲染，我们看到构建时间提高了 30%。

混合渲染入门
-----------------------------------

混合渲染今天在 Astro 2.0 中可用！ 您可以前往我们的 [server-side rendering guide](https://docs.astro.build/en/guides/server-side-rendering/) 了解有关 Astro 的 SSR 功能的更多信息。 Astro 的官方适配器也已更新以支持混合渲染，因此请务必安装最新版本的 [adapter](https://docs.astro.build/en/guides/server-side-rendering/#adding-an-adapter)。

为了庆祝发布，我们的朋友 [SST](https://sst.dev/) 刚刚推出了他们的官方 AWS 适配器 [astro-sst](https://www.npmjs.com/package/astro-sst)。 查看他们的 [announcement video & walkthrough](https://www.youtube.com/watch?v=AFP3ZHxO7Gg) 以了解更多信息并开始使用 AWS + SST。

我们欢迎您的反馈！ 我们在 [Prerender API RFC](https://github.com/withastro/roadmap/blob/main/proposals/0029-prerender-api.md) 期间收集了一些精彩的意见，并邀请您使用我们的新 [public roadmap](https://github.com/withastro/roadmap) 或 [Discord community](https://astro.build/chat/) 提出未来的想法。

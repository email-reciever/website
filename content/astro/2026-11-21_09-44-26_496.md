Astro 4.2 现已上市！ 此版本包括可试用的新实验功能、可访问性规则的改进、备注插件在 Markdown 中自定义图像优化的功能，以及更多改进和错误修复。

亮点包括：

*   **[(Experimental) Support for prerendering pages using the Speculation Rules API](#experimental-prerendering-pages-using-the-speculation-rules-api)**
*   **[(Experimental) Reworked routing priority for injected routes](#experimental-reworked-routing-priority-for-injected-routes)**
*   **[新 `redirectToDefaultLocale` 配置选项](#new-redirectToDefaultLocale-config-option)**
*   **[Improved accessibility rules](#improved-accessibility-rules)**
*   **[Customizable image optimization in Markdown](#customizable-image-optimization-in-markdown)**

这标志着几乎所有社区构建功能的 Astro 版本，只有一个亮点由 Astro Core 维护者带给您。 这对我们来说是一个巨大的里程碑，因为这意味着 Astro 现在足够大，可以拥有一个能够引领发布的蓬勃发展的贡献者社区。 感谢所有为本次发布做出贡献的人！

如何升级
---------------

要利用最新功能，请确保您运行的是最新版本的 Astro。 您可以通过运行 `@astrojs/upgrade` 命令升级到 Astro 4.2：

npx @astrojs/升级

或者通过为您的包管理器运行升级命令：

npm install astro@latestpnpm 升级 astro --latestyarn 升级 astro --latest

（实验）使用投机规则 API 预渲染页面
--------------------------------------------------------------

多亏了 [Ross Robino](https://github.com/rossrobino)，Astro `prefetch` 功能现在对使用当前 Chromium 独家 [Speculation Rules API](https://developer.mozilla.org/en-US/docs/Web/API/Speculation_Rules_API) 的预渲染页面进行了实验支持。 此 API 允许您在客户端上预渲染页面，甚至在用户可能访问的页面上运行客户端 JavaScript，从而提供更快的浏览体验。

要启用此功能，请将以下内容添加到 `astro.config.mjs` 文件中：

从“astro/config”导入 { defineconfig }；
// https://astro.build/configexport default defineConfig({ prefetch: true, experimental: { clientPrerender: true, },});

这将尊重您现有的 `prefetch` 配置选项，但现在将使用客户端上的 `data-astro-prefetch` 属性预渲染所有链接。 为尚不支持投机规则 API 的浏览器提供内置回退。

此外，您可以使用 `<script>` 标签中的 `document.prerendering` 属性来检查页面是否预渲染：

<script> if (document.prendering) { // 启用预渲染 }</script>

有关此实验功能的更多信息，请参阅 [`experimental.clientPrerender` 文档](https://docs.astro.build/en/reference/configuration-reference/#experimentalclientprerender)。

（实验）注入路由重新设计的路由优先级
--------------------------------------------------------

以前，使用 [`injectRoute()` API](https://docs.astro.build/en/reference/integrations-reference/#injectroute-option) 注入的路由将被赋予最高优先级，这意味着它们将在任何其他路由之前进行匹配。 虽然这在当时似乎是个好主意，但不幸的是，它导致了许多难以调试的问题，其中路由无法按预期进行匹配。

从历史上看，由于路由系统可能会导致多少意外问题，我们一直在犹豫要改变这种行为。 但是，由于 [Luiz Ferraz](https://github.com/Fryuni) 仔细实施修复，Astro 4.2 带来了一个实验标志，为 Astro 中的新的和改进的默认路由系统奠定了基础！

启用此标志后，使用 `injectRoute()` API 以及重定向的路由现在将遵循相同的 [priority order that routes from the filesystem do](https://docs.astro.build/en/core-concepts/routing/#route-priority-order)。 这应该为您的所有项目路线提供更稳定的优先级订购规则。

通过将新的 `experimental.globalRoutePriority` 选项添加到 `astro.config.mjs` 文件以选择加入新行为，立即尝试 Astro 的未来：

从“astro/config”导入 { defineconfig }；
// https://astro.build/configexport default defineConfig({ 实验性：{ globalRoutePriority: true, },});

还添加了额外的日志记录，以通知您两条路由尝试构建相同 URL 的任何路由冲突。

有关详细信息，请参阅 [`experimental.globalRoutePriority` 文档](https://docs.astro.build/en/reference/configuration-reference/#experimentalglobalroutepriority)。

新的 `redirectToDefaultLocale` 配置选项
-----------------------------------------

自引入 [internationalization support in Astro 4.0](https://astro.build/blog/astro-4/#internationalization-i18n-routing) 以来，一个常见的请求是在设置 `prefixDefaultLocale: true` 时，可以禁用根 URL (`/`) 到默认区域设置的自动重定向。

现在可以使用新的 `redirectToDefaultLocale` 选项：

从“astro/config”导入 { defineconfig }；
// https://astro.build/configexport default defineConfig({ i18n:{ defaultLocale: "en", locales: ["en", "fr"], 路由: { prefixDefaultLocale: true, redirectToDefaultLocale: false } }});

重定向，或者不！ 现在由你决定。 默认情况下启用此选项。

改进的可访问性规则
-----------------------------

在 4.0 中添加到 Astro Dev 工具栏中的可访问性规则已被改进以更加准确。 感谢 [Oliver Speir](https://github.com/OliverSpeir) 仔细阅读 WCAG 指南并改进这些规则！ 可访问性问题在本次更新中被错误地报告为以前版本中的开发工具栏的误报，并且正在积极开发中进行了更多改进。

Markdown中的可定制图像优化
-----------------------------------------

同样由 Oliver 撰写的 Remark 插件现在可以自定义在 Markdown 文件中优化图像的方式。 以前，使用本机语法 (`![alt](src)`) 包含在 Markdown 文件中的每个图像都使用 Astro 的默认设置进行图像优化。 通过此更新，备注插件现在可以将属性添加到 `image` 节点以自定义它们的优化方式。

例如，下面的备注插件会将每个图像的 `width` 和 `height` 属性设置为 `100`：

从“unist-util-visit”导入 { 访问 }；
导出默认函数 remarkPlugin() { return (tree) => { visit(tree, 'image', (node) => { node.data.hproperties = node.data.hproperties || {}; node.data.hproperties.width = "100"; node.data.hproperties.height = "100"; }); };}

这目前是 Markdown 文件独有的，但我们希望在未来的版本中添加对 MDX 的支持。

新的路线数据范式
--------------------------

Starlight 的 [component override](https://starlight.astro.build/guides/overriding-components/) 系统允许用户使用自己的组件自定义站点的外观。 这对于扩展 Starlight 的 UI 非常有用，但随着时间的推移，我们看到一种模式发展，人们还使用覆盖来修改组件数据，同时仍在重用 Starlight 的内置组件。

为了使这个用例更容易，v0.32 引入了 **一个新的路由中间件系统**，它提供了对 Starlight 数据模型的完全访问权限，而无需覆盖任何组件。 这对于插件特别有用，因为它避免了几个插件试图覆盖相同组件的常见冲突。

与 Astro 的中间件系统类似，每个 Starlight 页面渲染都会调用 Route 中间件，并让您有机会在任何数据渲染之前修改数据。 这是目前仅通过配置无法实现的自定义逻辑的强大方法。

在以下示例中，我们尝试通过在每个页面标题的末尾添加感叹号来使我们的文档更令人兴奋！！！

从 '@ASTROJS/STARLIGHT/ROUTE-DATA' 导入 { definerOutMiddleware }；
export const onRequest = defineRouteMiddleware((context) => { // 获取此页面的内容集合条目。 const { entry } = context.locals.StarLightRoute; // 更新标题以添加感叹号。 '!!';});

有关如何编写路由中间件的完整详细信息，请参阅 [“Route Data”](https://starlight.astro.build/guides/route-data) 指南。

### 突破性变化

为了更好地支持路由中间件，我们更新了 Starlight 的默认组件如何接收路由数据。

以前，Starlight 的所有模板组件，包括用户或插件覆盖，都可以通过 `Astro.props` 访问当前路由的数据对象。 此数据现在可以作为 `Astro.locals.starlightRoute` 提供。

有关如何迁移到此新方法的完整详细信息，请参阅 [Starlight changelog](https://github.com/withastro/starlight/blob/main/packages/starlight/CHANGELOG.md)。

用于插件的新 i18n API
--------------------------

此版本使插件能够完全访问 Starlight 强大的内置 [internationalization system](https://starlight.astro.build/guides/i18n/)。

插件现在可以在 `config:setup` 钩子中调用 [`useTranslations()`](https://starlight.astro.build/reference/plugins/#usetranslations) 来访问 Starlight 的任何 UI 字符串。 这为本地化日志记录、使用 Markdown 插件中的翻译开辟了可能性。

本示例插件记录 Starlight 的默认“使用 Starlight 构建”文本字符串，并在可用时使用与用户语言环境匹配的翻译：

导出默认 { name: 'localizedplugin', hooks: { 'config:setup'({ useTranslations, logger }) { // 检测当前用户的首选语言环境。 const userLocale = intl.DateTimeFormat().ResolvedOptions().locale; // 获取语言环境的 `t()` 函数。 const t = useTranslations(用户本地); // 记录本地化的字符串。 logger.info(t('BuiltWithStarLight.Label')); }, },};

更新的插件挂钩
---------------------

作为支持在插件中使用翻译的一部分，我们将旧的 `setup` 钩子分为两个：[`i18n:setup`](https://starlight.astro.build/reference/plugins/#i18nsetup) 和 [`config:setup`](https://starlight.astro.build/reference/plugins/#configsetup)。 使用 `setup` 钩子被弃用，插件应该迁移到使用 `config:setup` 来代替：

导出默认 { 名称：'starlight-plugin'，钩子：{ 'setup'({ config }) { 'config:setup'({ config }) { // 你的插件配置设置代码 }, }, };

使用 `injectTranslations()` 实用程序的插件需要将其移动到专用 `i18n:setup` 钩子：

导出默认 { name: 'plugin-with-translations', hooks: { 'config:setup'({ injectTranslations }) { 'i18n:setup'({ injectTranslations }) { injectTranslations({ en: { 'myplugin.dothing': '做事' }, fr: { 'myplugin.dothing': 'faire le truc' }, }); }, }, };

多站点搜索支持
-------------------------

Starlight 使用 [Pagefind](https://pagefind.app/) 提供开箱即用的网站搜索。 此版本公开了 PageFind 的多站点搜索配置，因此您可以支持跨多个站点进行搜索。

例如，如果您在 `example.com` 中的主站点与 PageFind 和您的 Starlight 站点部署到 `docs.example.com` 子域中，您可以使用 `mergeIndex` 配置选项在文档中显示您的主站点的搜索结果：

astro.config.mjs

从“astro/config”导入 { defineconfig }；从 '@astrojs/starlight 导入星光；
导出默认 defineConfig({ site: 'https://docs.example.com/', 集成：[ starlight({ title: 'docs with multisite search', pagefind: { mergeIndex: [{ bundlePath: 'https://example.com/pagefind' }], }, }), ],});

有关可用配置选项的完整详细信息，请参阅 PageFind 的 [“Searching multiple sites”](https://pagefind.app/docs/multisite/) 指南。

实验：天文动作
----------------------------

此版本包括期待已久的功能的第一个预览：Astro Actions！ 操作可以轻松地从客户端代码中定义和调用具有完整类型安全性的后端函数。

要使用此功能，[add a server build output](https://docs.astro.build/en/basics/rendering-modes/#on-demand-rendered) 并在 Astro Config 中启用 `experimental.actions` 选项：

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ 输出："hybrid", // 或 'server' experiment: { actions: true, },});

然后，使用 `defineAction()` 在 `src/actions/index.ts` 文件中定义操作。 您可以定义接受 JSON 或表单请求的操作，并使用类型安全输入调用 `handler` 函数。

另外，没有更多的铸造 `formData.get()` 结果。 Astro 将使用您的 ZOD 模式自动解析表单请求到对象。 以下是通讯注册操作的示例：

src/actions/index.ts

从“Astro:Actions”导入 { defineAction, z }；
export const server = { newsletter: defineAction({ accept: "form", 输入：z.Object({ email: z.string().email(), receivePromo: z.boolean(), }), handler: async ({ email, receivePromo }) => { // 调用 邮件服务，或存储到数据库 return { success: true }; }, }),};

您可以使用 `astro:actions` 中的 `actions` 对象从任何客户端组件调用操作。 使用 JSON 时可以传递类型安全对象，或在使用 `accept: 'form'` 时传递 `FormData` 对象。 您还可以 [添加 `getActionProps()` 以进行渐进增强](https://github.com/withastro/roadmap/blob/actions/proposals/0046-actions.md#add-progressive-enhancement-with-fallbacks)：

src/组件/通讯.tsx

导入 { 动作, getActionProps } 来自 "Astro:Actions";
导出函数 newsletter() { return ( <form      method="POST"      onSubmit={async (e) => { e.PreventDefault(); const formData(e.target as HTMLFormElement); const result = await actions.newsletter(formdata); }} > <input {...getActionProps(actions.newsletter)} /> <label htmlFor="email">email</label> <input name="email" type="email" id="email" />
<label htmlFor="receivePromo">接收促销电子邮件</label> <input name="receivePromo" type="checkbox" id="receivePromo" checked />
<button type="submit">注册</button> </form> );}

有关 Astro Actions 的更多信息，请访问 [the experimental actions docs](https://docs.astro.build/en/reference/configuration-reference/#experimentalactions)。

实验：请求重写
------------------------------

Astro 4.8 引入了对请求重写的实验支持。 重写是一种路由功能，允许您显示与当前网址不同的页面的内容。 这对于根据用户的位置、设备或其他条件自定义内容非常有用，而无需多个不同的 URL。 在其他框架中，此功能有时也称为“重新路由”。

要启用此功能，请在 Astro Config 中配置 `experimental.rewriting` 选项：

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ 实验性：{ 重写：true, },});

然后，您可以从页面和端点访问 Astro 全局或上下文对象上的 `rewrite()` 方法：

---if (!astro.props.allowed) { return astro.rewrite("/")}---

导出函数 get(ctx) { if (!ctx.locals.allowed) { 返回 ctx.rewrite("/"); }}

通过将参数传递给与 `rewrite` 方法相同类型的 `next()` 方法，也可以在中间件内部使用此功能。

导出函数 onRequest(ctx, next) { if (!ctx.cookies.get("allowed")) { return next("/"); } 返回 next();}

有关重写的更多信息，请访问 [the experimental rewriting docs](https://docs.astro.build/en/reference/configuration-reference/#experimentalrewriting)。

性能改进
-------------------------

得益于 [@bluwy](https://github.com/bluwy) 在 JavaScript 生态系统和 Astro 本身中最近的辛勤工作，Astro 比以往任何时候都快！ 此版本包括一些性能改进，全面缩短构建和渲染时间。

在我们自己的基准测试中，我们观察到特定情况下的构建时间提高了 20%。 无需更改即可利用这些改进 - 只需升级到 Astro 4.8 并享受更快的构建！

能够定义具有相同入口点的多条路由
------------------------------------------------------

Astro 集成作者发现，尝试使用 [`injectRoute`](https://docs.astro.build/en/reference/integrations-reference/#injectroute-option) 函数注入具有相同入口点的多条路由将导致在构建时出现意外行为，其中最后一次注入的路由将覆盖之前的路由。

这个问题自从引入`injectRoute`函数以来就一直存在，大约两年前（在Astro 1.0中），但由于[@goulvenclech](https://github.com/goulvenclech)的贡献，它现在终于在Astro 4.8中修复了！

随着我们蓬勃发展的开发人员社区和许多新的集成不断被构建，ASTRO 是一个伟大的平台，我们很高兴这为未来的更多集成铺平了道路！

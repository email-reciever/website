动态文件路由
--------------------

您现在可以使用 Astro 的新 **文件路由** 在项目中构建动态的非 HTML 文件。 使用文件路由在构建过程中动态生成文件，用于 JSON、XML 甚至图像等非文本资源。 自 Astro 早期以来，此功能一直是我们最受欢迎的功能之一！

要在 Astro 项目中创建文件路由，请在 `src/pages` 目录中创建一个新的 JavaScript 或 TypeScript 文件。 文件路由利用 Astro 现有的基于文件的路由器，因此请确保在文件名中包含最终构建的文件扩展名。

src/pages/builtwith.json.ts

// 输出：/builtwith.json
// 文件路由导出一个 get() 函数，它被调用以生成文件。// 返回一个带有 `body` 的对象以将文件内容保存在您的最终 build.export 异步函数 get() { return { body: json.stringify({ name: "Astro,, URL: "https://astro.build/", }), }}

此功能仅适用于 `--experimental-static-build` 标志。 [To learn more, check out the docs.](https://docs.astro.build/en/core-concepts/astro-pages/#non-html-pages)

自动 XSS 保护
-------------------------

Astro v0.23 开始我们向自动 HTML 转义的 Astro 模板表达式的迁移。 这项新功能将保护您免于意外地将不受信任的 HTML 注入您的页面。 没有它，您可以打开自己的跨站点脚本 (XSS) 攻击，恶意用户可以劫持您的网站以在页面上运行不受信任或意外的代码。

<!-- 不受信任的 HTML 注入示例 --><div>{`<span>Hello, dangerous HTML</span>`}</div><div>{`<script>alert('oh no');</script>`}</div><div>{UntrustedHTML}</div>

由于 React 和其他基于组件的 UI 库，XSS 漏洞正在成为过去。 Astro 很高兴能满足同样的零努力、内置、自动 XSS 保护的酒吧。

为了帮助我们的用户迁移，当模板表达式中遇到未转义的 HTML 时，Astro V0.23 会将警告记录到控制台。 在下一个版本中，模板表达式将始终转义其内容。

新的 `set:html` 和 `set:text` 指令
---------------------------------------

引入了两个新指令，以在需要时支持更好的 HTML 注入。 正如我们在上一节中介绍的，直接设置 HTML 是有风险的。 但是，在某些特殊情况下可能需要它。 Astro 为这些情况创建了新的 `set:html` 指令。 你可以把它想象成 React 的 `dangerouslySetInnerHTML`。

<!-- 显式 HTML 设置示例 --><div set:html={[0]} /><div set:html={[1]} /><div set:html={trustedOrAlreadyEscapedHtml} />

如果您不想要 `<div>` 包装器，还可以在 Fragment 组件上使用 `set:html` 来实现零包装 HTML：

    - {`<span>Hello, dangerous HTML</span>`}+ <Fragment set:html={[1]} />

`set:text` 也可以直接设置元素文本，类似于在浏览器中的元素上设置 `.text` 属性。 总之，这两个指令让您在需要时对 Astro 输出进行了更多控制。

安全访问敏感环境变量
-------------------------------------------

为了安全起见，Vite 仅加载明确选择加入以使用 `PUBLIC_` 前缀公开的环境变量。 这种限制在浏览器中是有意义的，可以保护您免受意外泄漏的秘密令牌和值。 但是，这也意味着您根本无法使用私有环境变量，即使是在服务器渲染的 Astro 组件内部也无法使用。

在 Astro v0.23 中，`import.meta.env` 现在允许您访问 Astro 中的私有环境变量，并随时在本地或服务器上呈现代码。 Astro 将继续在客户端上保护您，并且仅将 `PUBLIC_` 变量暴露给您的用户。

// db_password 仅在构建站点时可用。// 如果任何代码尝试在浏览器中运行它，它将为空。const data = await db(import.meta.env.db_password)
// public_pokeapi 在任何地方都可以使用，这要归功于 public_prefix!const data = fetch(`${import.meta.env.PUBLIC_POKEAPI}/pokemon/squirtle`)

请参阅我们的 [Environment Variables documentation](https://docs.astro.build/en/guides/environment-variables/) 以了解更多信息。

使用 Vite v2.8 实现更好的构建
-----------------------------

Astro V0.23 带有内部 Vite 升级，带来了新功能和巨大的稳定性改进。 Vite 的 npm 包处理也得到了提升，因此更多的包应该可以在更多项目中使用。 [Check out their changelog](https://github.com/vitejs/vite/blob/main/packages/vite/CHANGELOG.md) 了解更多。

@Astro/Compiler v0.11更好的稳定性
-----------------------------------------

Astro v0.23 还进行了编译器升级，这将导致所有项目的性能和稳定性提高。 [Check out the changelog](https://github.com/withastro/compiler/releases) 了解更多。

更好的构建性能
-------------------------

您可能已经注意到上面对 `--experimental-static-build` 的引用，以及某些新功能仅在此标志后面可用的事实。 该标志在 v0.23 中并不新鲜，但随着我们越来越接近该功能的正式发布，它继续改进。 这种新的“静态构建”策略将很快成为 Astro 中的默认构建行为。

如果您还没有在您的构建中尝试过 `--experimental-static-build` 标志，请尝试一下，并在 Discord 中留下反馈。 查看我们的博客文章 [Scaling Astro to 10,000+ Pages](/blog/experimental-static-build) 以了解有关 Astro 未来构建策略的更多信息。

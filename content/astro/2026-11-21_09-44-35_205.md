Astro 继续发展其与社区合作的方式。

我们的社区奖项使我们能够回馈那些自愿提交代码和错误修复的人，热情和乐于助人，翻译文档，丰富每个人的 ASTRO 体验。

以前是季度活动，Astro 最近承诺每月颁发这些奖项。 我们还从同行提名的奖项转变为由我们的核心维护者选择的获奖者。

这听起来可能不那么民主，但我们将其视为维护者感恩日记：**我们确保我们的核心维护者积极反思并寻找下一批后起之秀**。 我们很自豪地说，我们将时间花在开源社区的健康、增长和可持续性上。

社区奖很不错，但直到现在，这种认可主要是留在我们的社区中。 我们想要一个更好、更公开、更永久的社区认可场所。 你可以在某个地方向朋友和家人炫耀，也许是为了解释所有这些夜晚和周末的去向！

我们很高兴宣布推出我们的第一个公共社区空间：[https://community.astro.build](https://community.astro.build) 由我们的第一位社区工程师 Elian Van Cutsem 建造。

今天，您可以访问并庆祝帮助 Astro 成为您喜欢使用的项目的人。 请继续关注更多令人兴奋的社区倡议，随着我们的发展和扩展网站，它们将在那里找到家！

![A screenshot of the Astro Community Microsite](/_astro/community-microsite.D_My_PJx_nv9DV.webp)

维护者项目
--------------------

在我们的社区电话中，每周我们都会强调和庆祝我们的社区构建的所有东西_with_Astro。 今天，我们要认识到一种非常特殊的社区贡献，你通常不会看到：我们自己的维护者为 _working 和 _contributing 的个人实验和副项目

维护一个开源项目意味着在我们的代码编辑器、PR 和 GitHub 上花费大量时间，在文档中查找内容，跟踪正在进行的工作，并与其他人协作。

我们想展示一些我们为我们的_own_使用构建的工具，因为我们为您（以及！）您构建Astro。 其中一些使日常任务变得更容易，有些只是让它们更有趣……因为这也是重点的一部分！

天文自动化

[github.com/withastro/automation](https://github.com/withastro/automation)

![](/_astro/automation.B6NU2QBl_u0sGA.webp)![](/_astro/bg.BSI2111J_Z2mbajE.webp)

由 [Nate & Chris](https://github.com/withastro/automation) 创建

可重用的 GitHub 操作工作流的集中存储库。 这些操作帮助我们在 WithaStro GitHub 组织中的许多不同存储库中自动化通用工作流。 在单个位置使用通用工作流程的主要好处是维护在一个位置进行，并自动推广到我们所有的存储库中。 集中化的工作流程还使为全新的存储库设置自动化工作流程变得更加容易。

> 当我们第一次开始构建Astro时，我们的所有代码和文档都有一个中央Astro Monorepo。 这使得共享工具和配置变得容易，但随着项目的发展，在许多不同的重点领域进行协作变得越来越困难。 虽然复制和粘贴工作流文件适用于少数存储库，但存储库的数量在 2023 年夏季开始增长。我们所有的存储库都使用此自动化存储库在我们的 Discord 中共享合并通知（恭喜）， 用更漂亮的（格式）格式化我们的源代码，并自动化问题标签（问题打开和问题标记）

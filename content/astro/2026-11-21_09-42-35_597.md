介绍
-------------

Astro 是一个非常适合内容驱动网站的 Web 框架。 它的岛屿架构允许您将静态页面与动态元素相结合，在性能和交互性之间取得平衡。 除此之外，您还可以利用 SSR、中间件和端点来构建在服务器端运行的应用程序。

最近的更新特别强调了构建动态站点的功能，暗示了 Astro 向强大的全栈框架的演变。 有关 Astro 的更详细介绍，请查看官方 [Why Astro?](https://docs.astro.build/en/concepts/why-astro/) 文档。

在这篇文章中，我将总结我认为 2024 年 Astro 生态系统中最重要的事件。据我所知，我还将谈谈 2025 年可能会发生的事情。

如果您有兴趣，我还发布了这篇文章的 [2023 edition (in Japanese)](https://zenn.dev/morinokami/articles/astro-2023-2024)。 随意查看，以回顾 Astro 在 2023 年的进展情况。

项目健康指标
--------------------------

### 发布版本

截至 2024 年初，Astro 处于 [v4.0.8](https://github.com/withastro/astro/releases/tag/astro%404.0.8) 状态，到年底撰写本文时，[v5.1.1](https://github.com/withastro/astro/releases/tag/astro%405.1.1) 已发布。 包括测试版，**2024年共有169个版本**。 这几乎与2023年的175次发布数量相当。

2023年，主要版本从1跃升至4，给人一种功能添加和改进速度的印象。 2024年，主要版本仅从4到5，版本颠簸的速度似乎有所缓和。

对于那些对每个版本的细节感到好奇的人，您可以检查 [the full list of Astro releases on GitHub](https://github.com/withastro/astro/releases)。

### GitHub 明星

根据[GitHub Star History](https://star-history.com/#withastro/astro&Date)，Astro的GitHub星在2024年初约为37,000，但到年底增加到48,000。 尽管这比 2023 年的 15,000 人增长要慢一些，但全年仍有超过 10,000 人的增长。 公平地说，Astro 的明星数量仍处于健康的上升趋势。

新功能和更新功能
-------------------------

### 内容层

[Content Collections](https://docs.astro.build/en/guides/content-collections/)在[Astro 2.0](/blog/introducing-content-collections/)中引入作为一种对以Markdown等编写的本地内容进行类型安全处理的方式。在[Astro 5.0](/blog/astro-5/)中，添加了新的Content Layer API以扩展内容的定义方式，使其在各种用例中更加灵活和强大。

以前，Astro 的内容集合只能处理位于保留 `src/content` 目录中本地的 Markdown 或 MDX 文件之类的内容：

    - src/内容/ - 博客/ - post-1.md - post-2.md

然后，您的内容配置架构可以验证每个 Markdown 文件的 FrontMatter，在处理 [`getCollection`](https://docs.astro.build/en/reference/modules/astro-content/#getcollection) 函数检索到的内容数据时提供编辑器自动完成等。

使用 v5.0 中引入的新内容层 API，您可以在扩展内容的定义时保留验证和自动完成的优势。 例如，您现在可以使用新的 `loader` 属性将外部 API 数据“加载”为集合：

src/content.config.ts

导入 { defineCollection, z } 来自“Astro:Content”；
const 国家 = definedCollection({ loader: () => fetch("https://api.example.com/countries").then(res => res.json()), schema: z.object({ /* schema definition */ }),});
导出常量集合 = { 国家 };

在这个新的内容层下，`type`（您之前提供给 `defineCollection` 的）现在被视为旧版，`loader` 是您指定如何加载数据的位置，从而可以处理任何类型的数据源，而不仅仅是本地文件。

在 v5 中，您的本地内容 `glob()` 和 `file()` 获得两个 [built-in loaders](https://docs.astro.build/en/guides/content-collections/#built-in-loaders)，使您可以轻松执行以下操作：

src/content.config.ts

const blog = defineCollection({ loader: glob({ pattern: "**/*.md", base: "./src/data/blog" }), schema: z.object({ /* schema definition */ }),});

这个博客集合的行为类似于旧的本地基于文件的方法。 同时，因为 `loader` 可以是任何功能，您还可以从外部 API 或数据库中提取数据，甚至可以即时生成内容。

通过这种方式，新的内容层概括了在 Astro 中处理内容的方式，还允许您自由定义和分发自定义数据加载器，从而显着扩展 Astro 围绕内容的功能。 用于构建自定义加载程序的 [Content Loader API](https://docs.astro.build/en/reference/content-loader-reference/) 还具有 [`meta`](https://docs.astro.build/en/reference/content-loader-reference/#meta) 键值存储的方便功能，用于存储有关内容的元数据和用于存储渲染输出的 [`rendered`](https://docs.astro.build/en/reference/content-loader-reference/#rendered) 字段。

使用 Content Layer API 支持的新更新的内容集合，继续创建您自己的加载程序 - 如果结果很好，请将其发布为 npm 包并与 Astro 社区共享 [in the “Content Loaders” category of the integrations library](https://astro.build/integrations/?search=&categories%5B%5D=loaders)！ 例如，[Storyblok](/blog/storyblok-loader/)、[Cloudinary](/blog/cloudinary-loader/) 和 [Hygraph](/blog/hygraph-loader/) 已经发布了自己的加载器，因此您可以从这些服务中获取数据，而无需从头开始编写自己的加载程序。

[Check out the official docs to learn more about Content Collections](https://docs.astro.build/en/guides/content-collections/)。

### 星际行动

Astro 已经提供了 [endpoints](https://docs.astro.build/en/guides/endpoints/) 用于处理服务器端的 HTTP 请求。 但在 [v4.15, Astro Actions were introduced](/blog/astro-4150/) 中，可以更轻松地调用后端服务更少的样板和更安全的样板。 Astro 行动的一些好处包括：

*   使用[Zod](https://zod.dev/)进行自动输入验证
*   自动生成调用您的动作的类型安全函数
*   通过 [`ActionError`](https://docs.astro.build/en/reference/modules/astro-actions/#actionerror) 类型和 [`isInputError`](https://docs.astro.build/en/reference/modules/astro-actions/#isinputerror) 函数进行标准化错误处理

以下是如何在 `src/actions/index.ts` 中定义动作的示例：

src/actions/index.ts

从“astro:actions”中导入 { defineAction }；从“astro:schema”导入 { z }；
export const server = { / / / 定义一个动作，取一个名字并返回一个问候语 GetGreeting: defineAction({ / // 发送到这个动作的输入的模式输入：z.object({ name: z.string(), }), // 这个动作处理程序的服务器端处理程序： async (input) => { return `Hello, ${input.name}!`; // 输入经过验证，可以安全地访问类型 } })}

请注意，您看不到用于检查 `Content-Type`、执行输入验证等的代码。Astro 操作处理该样板，以便您可以专注于核心业务逻辑。

然后，在客户端：

-------
<button>得到问候</button>
<script>// 导入包含 `getGreeting` ActionImport { actions } 的 `actions` 对象，来自 "astro:actions";
const button = document.QuerySelector("button");button?.addEventListener("click", async () => { // 调用 `getGreeting` action const { 数据, 错误 } = await actions.getGreeting({ name: "actions" }); // 如果 (!error) alert(data);})</script> 没有错误，则在警报中显示结果

通过从 `astro:actions` 导入 `actions`，您可以获得一个调用 `getGreeting` 操作的函数。 感谢您提供的模式，您可以安全地调用 `getGreeting` 类型。 当然，您可以将鼠标悬停在编辑器中的操作上以查看输入和返回类型或 `cmd+click` 跳转到其定义。

此外，您可以使用 `isInputError` 函数检查 `error` 是否是验证错误，或者在操作处理程序中抛出 `ActionError` 以设置特定的 HTTP 状态代码等。

鉴于其名称，Astro 动作受 React [Server Actions (Functions)](https://react.dev/reference/rsc/server-functions) 的影响。 两者都试图解决类似的问题，但 Astro Actions 似乎在开箱即用的验证和结构化错误处理方面更进一步。 您可能不需要在 Astro 项目中进行广泛的服务器端通信，但您可以根据需要插入操作，例如，在博客文章中添加类似功能。

[Check out the official docs to learn more about Astro Actions](https://docs.astro.build/en/guides/actions/)。

### 服务器群岛

在 [Astro 5.0](/blog/astro-5/) 中引入了一种称为 [Server Islands](https://docs.astro.build/en/guides/server-islands/) 的新渲染方法。 Astro 的岛屿架构一直允许对页面的某些部分进行选择性补水，但现在 Server Islands 扩展了这一概念，让您可以在服务器上渲染页面的一部分。 以下是[the initial announcement for Server Islands](/blog/astro-4120/)中共享的图像：

![A diagram showing a static page with server-rendered components embedded in it.](/_astro/dark-mode-server-islands-diag.CCPm1I4W_1F1hFI.webp)

如图所示，您可以将服务器呈现的内容嵌入到静态页面中。 静态部分可以通过 CDN 进行缓存，而服务器渲染的部分在初始页面加载后懒洋洋地获取，在增加内容的灵活性的同时保持快速的初始加载速度。 这种方法实现了传统 SSR 无法实现的性能水平。

要启用服务器岛，您只需将 [`server:defer`](https://docs.astro.build/en/reference/directives-reference/#server-directives) 指令添加到您的 Astro 组件中。 例如，假设您有一个组件可以在服务器端获取用户的头像：

src/components/avatar.astro

---从“../sessions”中导入{ getUserAvatar };const usersession = astro.cookies.get("会话");const avatarUrl = await getUserAvatar(userSession);---
    <img alt="User avatar" src={avatarURL} />

在使用此组件的页面中，您只需添加 `server:defer` 指令：

src/pages/index.astro

---从“../components/avatar.astro”导入头像；---
<!-- 其他内容在这里-->
    <Avatar server:defer />

就是这样！ 页面是静态生成的，而 `Avatar` 组件是按需服务器渲染的。 此外，您还可以在加载服务器岛时指定要显示的回退内容，类似于 React 的 [`Suspense`](https://react.dev/reference/react/Suspense)：

src/pages/index.astro

---从“../components/avatar.astro”导入化身；从“../components/genericavatar.astro”导入genericavatar；---
    <Avatar server:defer>  <GenericAvatar slot="fallback" /></Avatar>

如果您想更深入地解释服务器岛与 Astro 的标准预渲染或按需渲染有何不同，请查看 [my article (in Japanese)](https://zenn.dev/morinokami/articles/astro-server-islands-vs-nextjs-ppr)。 它比较了 Next.js 的渲染方法和 Astro 的服务器岛，让您对现代渲染技术有了更广泛的了解。

[Check out the official docs to learn more about Server Islands](https://docs.astro.build/en/guides/server-islands/)。

### 太空数据库

2024 年 3 月，Astro 推出了 [`@astrojs/db`](https://docs.astro.build/en/guides/integrations-guide/db/) 包进行数据库管理。 在首次发布时，生产环境将连接到名为 Astro Studio 的托管数据库服务。 截至目前，您可以连接到任何 [libSQL](https://github.com/tursodatabase/libsql) 服务器。 有关 Astro Studio 的更多信息，请参阅 [Related Projects](#related-projects)。

要使用 Astro DB，您首先需要在 `db/config.ts` 文件中定义您的表架构：

db/config.ts

从“astro:db”导入 { 定义表，列 }；
const author = defineTable({ columns: { id: column.number({ primaryKey: true }), name: column.text(), }});
const comment = defineTable({ columns: { authorid: column.number({ references: () => author.columns.id }), body: column.text(), }});
导出默认 definedB({ 表: { 作者, 评论 },});

然后，在 `db/seed.ts` 中，导出一个为数据库播种的函数：

数据库/种子.ts

从“astro:db”导入 { db, comment, author };
导出默认异步函数() { await db.insert(author).values([ { id: 1, name: "kasim" }, { id: 2, name: "mina" }, ]);
await db.insert(comment).values([ { authorid: 1, body: "希望你喜欢 Astro DB!" }, { authorID: 2, body: "enjoy!", ])}

当您启动开发服务器时，会自动创建和接种数据库。

查询数据库通过 [Drizzle](https://orm.drizzle.team/) 客户端。 从 `astro:db` 导入的 `db` 客户端自动配置为连接到正确的数据库，因此您可以立即开始查询：

---import { db, comment } 来自“astro:db”；
常量注释 = await db.select().from(comment);---
<h2>评论</h2>
{ comments.map(({ 作者，正文 }) => ( <article> <p>作者：{author}</p> <p>{body}</article> ))}

借助 Astro DB，您可以将 Astro 的简单设置与 Drizzle 强大的查询功能相结合，以管理 Astro 项目中的数据库。 尽管它似乎处于早期阶段，但 Astro DB 已经为需要数据库的较小功能提供了足够多的功能。 绝对考虑在您的下一个项目中进行测试！

[Check out the official docs for more details on Astro DB](https://docs.astro.build/en/guides/astro-db/)。

### 太空：环境

Astro 5.0 引入了 [`astro:env`](https://docs.astro.build/en/guides/environment-variables/#type-safe-environment-variables)，一种安全地处理环境变量的新方法。 使用 `astro:env`，您可以：

*   指定使用上下文（客户端或服务器）以阐明如何使用变量/在哪里
*   将变量标记为秘密，使其不会暴露给客户端或内联到服务器构建中
*   指定变量是必需的还是可选的，并验证在服务器启动时设置了所需的变量
*   定义变量类型，无需在您的应用程序中进行手动类型转换

您在 Astro 配置文件中定义您的环境变量架构：

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ env: { schema: { // ... } }});

然后使用 `envField` 助手定义字段：

astro.config.mjs

从“astro/config”导入 { defineconfig, envfield };
导出默认值 defineConfig({ env: { schema: { api_url: envfield.string({ context: "client", access: "public"", 可选: true }), port: envfield.number({ context: "server", access: "public", default: "public", default: 4321 }), api_secret: envfield.string({ context: "server", access: "secret" }), } }});

在这里，我们使用 `context`、`access` 和 `optional` 等选项来指定属性，例如可以访问变量的上下文、是否是秘密以及是否是可选的。 变量类型由 `envField.string` 或 `envField.number` 等辅助函数声明。

然后，您可以从 `astro:env/*` 导入和使用这些变量：

---import { api_url } 来自 "astro:env/client";import { port } 从 "astro:env/server";import { api_secret } 来自 "astro:env/server";---

尽管它看起来像一个小功能，但环境变量通常是应用程序开发中令人头疼的原因，因此具有内置的、类型安全的方法是非常有帮助的。

[Check out the official docs for setting up type-safe environment variables](https://docs.astro.build/en/guides/environment-variables/#type-safe-environment-variables)。

### 请求重写

[Astro 4.13](/blog/astro-4130/) 引入 [Request Rewriting](https://docs.astro.build/en/guides/routing/#rewrites)，它允许您在不将客户端重定向到新页面的情况下提供不同的路由。 这意味着浏览器 URL 保持不变，而服务器将请求重新路由到幕后的不同路径，返回结果，就好像它是对原始请求的响应一样。 此功能对于您希望在多个路径中显示相同内容而无需维护不同源文件的情况下特别有用。

您可以通过在 Astro 组件中调用 `Astro.rewrite` 函数来使用重写：

---返回 astro.rewrite("/login")---

或在中间件文件中：

从“astro”导入类型 { apiContext }；
导出函数 get({ rewrite }: apiContext) { return rewrite("/login");}

有关请求重写的更多详细信息，请查看官方文档：

*   [Routing](https://docs.astro.build/en/guides/routing/#rewrites)
*   [Middleware](https://docs.astro.build/en/guides/middleware/#rewriting)
*   [Astro render context](https://docs.astro.build/en/reference/api-reference/#rewrite)

### 容器 API

容器 API 在 Astro 的项目路线图上处于 2023 年的第 2 阶段，已在 [Astro 4.9](/blog/astro-490/) 中实现为实验功能。 此功能使您能够独立于应用程序上下文渲染 Astro 组件，就像 React 中 [`react-dom/server`](https://react.dev/reference/react-dom/server) 提供的各种方法。 如果您有兴趣了解有关 Container API 背景的更多信息，请查看 [my last year’s article](https://zenn.dev/morinokami/articles/astro-2023-2024#container-api%3A-render-components-in-isolation) 了解更多详情。

要使用容器 API，首先需要创建一个容器（将呈现组件的环境）并调用 [`renderToString`](https://docs.astro.build/en/reference/container-reference/#rendertostring) 或 [`renderToResponse`](https://docs.astro.build/en/reference/container-reference/#rendertoresponse) 的方法：

---import { experiment_astrocontainer } 来自“Astro/Container”；导入卡来自“../src/components/card.astro”；
const container = await experiment_astrocontainer.create();const result = await container.RenderToString(card);---

`result` 将包含 `Card` 组件的渲染 HTML，您可以将其用于测试目的，例如检查它是否包含特定的预期字符串。 有关如何使用容器 API 编写测试的参考资料，请查看 [the official example project](https://github.com/withastro/astro/tree/main/examples/container-with-vitest) 演示如何将容器 API 与 Viste 一起使用。

除了 `renderToString` 之外，还有一个 `renderToResponse` 方法，您可以通过各种选项传递道具或插槽数据。 有关容器 API 的更多详细信息，请参阅 [the official docs](https://docs.astro.build/en/reference/container-reference/)。

在 [Astro Together](#astro-together) 中，Matthew Phillips 的一个演示展示了如何使用容器 API 将 Astro 组件（使用 Islands！）嵌入 PHP 项目中，这非常令人印象深刻。 也一定要检查一下！

### 太空工作室

[Astro Studio](https://web.archive.org/web/20240224162616/https://studio.astro.build/) 于 2024 年初作为 Astro 的第一个管理服务推出，但遗憾的是在 9 月宣布了 [its shutdown](/blog/goodbye-astro-studio/)。 该帖子解释说，Astro Studio旨在：

1.  为所有Astro开发人员提供经济实惠的高性能SQL数据存储解决方案，易于使用并与Astro无缝集成
2.  建立可持续的商业模式来支持Astro的持续发展和增长

不幸的是，第二点没有希望的那么成功，导致决定关闭 Astro Studio。

至于关机时间线，如下：

*   邀请到 Astro Studio 将保持关闭状态。
*   现有用户将无法在2024年10月1日之后创建新的数据库。
*   现有数据库在2025年3月1日之后将不再可访问。
*   任何剩余的数据库将在2025年3月1日之后或不久之后被删除。

如果您使用的是 Astro Studio，请务必提前计划迁移到另一个数据库服务。

同时，Astro DB 仍可用于您的 Astro 项目。 在 [v4.15](/blog/astro-4150/#libsql-remotes-in-astro-db) 中，Astro DB 引入了对连接到任何 LibSQL 服务器的支持，因此您可以自主托管 LibSQL 服务器或使用 [Turso](https://turso.tech/) 之类的托管服务继续使用 Astro DB。

### 天文店面

Astro StoreFront 是一个电子商务网站项目，展示了上面提到的许多 Astro 的新功能，包括动作和 `astro:env`。 它代表了 Astro 当前能力的状态，是构建自己的 Astro 项目的重要参考。 [The Storefront source code](https://github.com/withastro/storefront) 在 GitHub 上公开可用，在生产中使用相同的代码 [the Astro Swag Shop](https://shop.astro.build/)，您可以在其中购买 Astro 商品。

Astro 最初是一个静态站点生成器，但近年来它积极扩展了其服务器端功能，现在能够在不牺牲 UX 的情况下构建具有电子商务网站等动态内容的站点。 Astro Storefront 体现了这一趋势，并在 2024 年 3 月发布了一个 [E-commerce guide](https://docs.astro.build/en/guides/ecommerce/)，以帮助您使用 Astro 构建自己的电子商务网站。

Astro StoreFront 项目的 Readme 涵盖了设计决策等，因此结合代码本身，这是学习实际 Astro 开发技术的好方法。 如果您正在计划一个严肃的 Astro 项目，请务必检查一下！

### ASTRO 生态系统 CI

生态系统 CI 是一种保护软件生态系统整体质量的机制。 它起源于 Vite 社区，主要由 [dominikg](https://github.com/dominikg) 领导：

[Play](https://youtube.com/watch?v=UgQtYT1DMiw)[Play](https://youtube.com/watch?v=7L4I4lDzO48)

Vite 的生态系统非常庞大，不断涌现出新的库和工具。 另一方面，Vite 中的任何意想不到的破坏性变化都会产生巨大的涟漪效应。 每当 Vite 发生变化时，生态系统 CI 有助于最大限度地降低风险，确保事情不会意外破裂，或者如果发生故障，它们可以与包维护者合作及时修复。

生态系统 CI 已经超越 VITE 扩展到其他项目，例如：

*   Vue：[vuejs/ecosystem-ci](https://github.com/vuejs/ecosystem-ci)
*    精巧：[sveltejs/svelte-ecosystem-ci](https://github.com/sveltejs/svelte-ecosystem-ci)
*   纽交：[nuxt/ecosystem-ci](https://github.com/nuxt/ecosystem-ci)
*   NX：[nrwl/nx-ecosystem-ci](https://github.com/nrwl/nx-ecosystem-ci)
*   试用：[vitest-dev/vitest-ecosystem-ci](https://github.com/vitest-dev/vitest-ecosystem-ci)
*   SPACK：[rspack-contrib/rspack-ecosystem-ci](https://github.com/rspack-contrib/rspack-ecosystem-ci)，[rspack-contrib/rsbuild-ecosystem-ci](https://github.com/rspack-contrib/rsbuild-ecosystem-ci)
*   生物群落：[biomejs/ecosystem-ci](https://github.com/biomejs/ecosystem-ci)
*   OXC：[oxc-project/oxlint-ecosystem-ci](https://github.com/oxc-project/oxlint-ecosystem-ci)

现在，Astro 已经通过自己的生态系统 CI 实现加入了这一趋势，可在 [withastro/astro-ecosystem-ci](https://github.com/withastro/astro-ecosystem-ci) 获得。

您可以在 [https://github.com/withastro/astro-ecosystem-ci/actions](https://github.com/withastro/astro-ecosystem-ci/actions) 处查看 CI 检查的结果。 每个工作流都有用于生态系统包的作业（例如 [Starlight](#starlight)），它们测试构建、运行等，以确保与 [withastro/astro](https://github.com/withastro/astro) 包的兼容性。

Ecosystem CI 或多或少是针对软件包开发人员的，因此如果您只是使用 Astro，则无需担心。 也就是说，如果生态系统中的一个包突然破裂，CI 生态系统可以为正在发生的事情提供一些有用的见解。 即使您没有直接参与开源开发，了解生态系统 CI 概念也可以帮助您在内部开发的软件包中保持稳定性，例如公司系统中使用的软件包。

### 会话

会话是一种临时存储用户特定数据的机制，例如登录状态或购物车。 到目前为止，您必须直接处理 cookie 或本地存储。 新提案将允许您在 Astro 中本地处理会话。 数据是服务器端存储的，只有会话 ID 作为 cookie 发送到客户端，这应该有助于安全性。

会话已经在 [Astro 5.1](/blog/astro-510/) 中通过实验引入。 要使用会话，您将使用 `Astro.session` 对象的 `get` 和 `set` 方法。 会话在许多上下文中可用，包括页面、组件、端点、操作或中间件。 以下是文章中的一个示例，演示了如何在会话中检索和更新购物车数据：

src/组件/cartbutton.astro

---export const preRender = false;const cart = await astro.session.get("cart");---
<a href="/cart">🛒 {购物车？。长度？？ 0}项目</a>

src/actions/addtocart.ts

从“astro:actions”中导入 { defineAction }；从“astro:schema”导入 { z }；
导出 const server = { addToCart: defineAction({ input: z.object({ productID: z.string() }), 处理程序: 异步 (input, context) => { const cart = await context.session.get("cart"); cart.push(input.productId); await context.session.set("cart", cart); return cart; }, }),};

由于会话仍然是实验性的，因此您必须使用 `driver` 设置明确指定存储该数据的位置。 例如，以下是部署到 Node.js 环境时指定文件系统驱动程序的方法：

astro.config.mjs

{ adapter: node({ mode: "standalone" }), 实验: { session: { driver: "fs", }, },}

哪个驱动程序可用取决于您的生产环境。 例如，您还可以将 Drivers 用于 Cloudflare KV 或 Redis。 有关驱动程序的完整列表，请参阅 [the unstorage docs](https://unstorage.unjs.io/drivers)（Astro Sessions 在内部使用）。

当会话退出实验状态时，计划是让适配器自己自动选择正确的驱动程序，因此您将来无需手动配置此功能。 如果您在尝试后发现任何问题或有改进建议，请务必在 [the PR of the proposal](https://github.com/withastro/roadmap/pull/1055) 上分享您的反馈。

### 响应图像

尽管图像是塑造用户体验的关键因素，因此在 Web 开发中必不可少，但处理它们可能非常具有挑战性。 开发人员必须考虑屏幕尺寸、分辨率和图像格式等内容，以确保图像在各种设备上正确显示。 现有的 [`<Image>`](https://docs.astro.build/en/reference/modules/astro-assets/#image-) 组件确实提供了一系列选项来处理这些复杂性，但它仍然需要开发人员付出相当多的努力。

该提案旨在引入一个 `layout` 属性，该属性可以自动生成 `srcset` 和 `sizes`，让开发人员轻松遵循图像最佳实践。

它已经在 [Astro 5.0](/blog/astro-5/#experimental-features) 中作为实验功能提供，您可以查看 [the experimental responsive image docs](https://docs.astro.build/en/reference/experimental-flags/responsive-images/) 以获取更多详细信息。

### 字体

字体是网页设计的基础，但 Astro 目前没有提供内置的处理方法。 [The official fonts guide](https://docs.astro.build/en/guides/fonts/) 可以帮助您入门，但它仍然留下了很多决定，例如在哪里托管字体、如何加载它们等，直到开发人员。 该提案旨在将字体最佳实践整合到 Astro 中，从而更轻松地在项目中使用字体。

实现细节仍在讨论中，但您可以通过配置外观的示例找到 [the Astro Fonts RFC](https://github.com/withastro/roadmap/blob/rfc/fonts/proposals/0052-fonts.md)。

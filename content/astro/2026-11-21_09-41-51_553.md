航向锚链接
---------------------

Starlight v0.34 添加了内置支持，用于在 Markdown、MDX 和 MarkDoc 内容中的标题旁边自动呈现可点击的锚链接。

![A subheading in the Starlight docs showing a pointer cursor hovering over an anchor link icon.](/_astro/starlight-anchor-links.CWJ6qEnI_Z25NhAK.webp)

我们在 [accessibility research by Amber Wilson](https://amberwilson.co.uk/blog/are-your-anchor-links-accessible/) 上构建了一种旨在为所有用户提供帮助的锚链接方法。

Starlight 将链接元素放置在 HTML 输出中的标题下方，并从 Markdown 内容中自动生成可访问的标签。 例如，以下降价：

    ## 开始

会生成这样的html：

<h2 id="get-started">入门</h2><a href="#get-started">题为“入门”的部分</a>

这确保了文档结构中的标题不会被锚链接混乱，并且链接本身仍然具有用于辅助技术的清晰标签。 我们在 Astro Docs 中使用这种方法已经有一段时间了，并且很高兴将其提供给所有使用 Starlight 构建的站点！

Tailwind V4 支持
--------------------

自从我们第一次通过自定义 Tailwind 插件发布后不久，Starlight 就支持使用 Tailwind CSS 创作样式。 我们现在更新了支持 Tailwind V4 的兼容性！

Tailwind v4 带来了一些重大变化。 现在通过 Vite 插件提供支持，并且配置已移至 CSS 文件而不是 JS 模块。 Starlight 的 Tailwind 兼容性样式现在必须直接在您的 CSS 中导入并使用 `@theme` 指令进行自定义：

src/styles/global.css

/* 在 Tailwind 的默认图层中包含“星光”层。 */@Layer Base、Starlight、主题、组件、实用程序；
/* 导入 Starlight 的兼容性样式。 */@import '@astrojs/starlight-tailwind';@import 'tailwindcss/theme.css' 层(theme);@import 'tailwindss/utilities.css' 层（实用程序）；
@theme { /* 配置星光主题变量。 */}

有关更新的详细指南，请参阅 [`@astrojs/starlight-tailwind` 更改日志](https://github.com/withastro/starlight/blob/main/packages/tailwind/CHANGELOG.md)。 您可能还希望将 [official Tailwind v4 upgrade guide](https://tailwindcss.com/docs/upgrade-guide) 和 [Starlight’s Tailwind set-up guide](https://starlight.astro.build/guides/css-and-tailwind/#tailwind-css) 放在手边。

CSS 级联层
-------------------

星光用户可以轻松自定义其网站非常重要。 从历史上看，Starlight 的内置样式和用户的 CSS 之间的冲突使定制体验不像以前那样流畅：

/* 星光内置样式（简化） */:not(h1, h2, h3, h4, h5, h6) + h2 { 边距：1.5em;}
/* 用户样式 */h2 { margin-top: 1em; /* ❌ 不适用，因为 `h2` 的特异性较低！ */}

Starlight v0.34 通过将所有内置样式移入专用 `starlight` [CSS cascade layer](https://css-tricks.com/css-cascade-layers/) 来解决冲突。 这意味着**用户样式将始终优先**优先于默认样式，我们可以挥手告别特殊性战斗。 👋

/* 星光内置样式（简化） */@layer starlight.content { :not(h1, h2, h3, h4, h5, h6) + h2 { margin-top: 1.5em; }}
/* 用户样式 */h2 { margin-top: 1em; /* ✅ 适用，因为它在顶层！ */}

此更改还意味着您可以享受使用 `@layer` 组织自己的 CSS 的好处，而无需始终覆盖 Starlight 的样式。

了解有关在 [Starlight’s “CSS & Styling” guide](https://starlight.astro.build/guides/css-and-tailwind/#cascade-layers) 中使用级联层的更多信息。

改进的 <head> API
---------------------

在 Starlight v0.33 中，我们为路由数据对象添加了一个新的 `head` 属性。 这可以解锁 [route middleware](https://starlight.astro.build/guides/route-data/#customizing-route-data) 中星光的 `<head>` 标签的完全控制，包括用于插件，允许您更轻松地添加标签和过滤默认标签。

例如，此中间件使用 Railway 的 Demo [Open Graph image API](https://og.railway.com/) 为每个 Starlight 页面添加 `og:image` 元标记：

src/routedata.ts

从 '@ASTROJS/STARLIGHT/ROUTE-DATA' 导入 { definerOutMiddleware }；
导出 const onRequest = definerOutemiddleware((context) => { const { entry, head } = context.locals.StarLightRoute;
// 使用当前页面的标题创建一个开放的图形图像 URL。 const ogImageUrl = 新网址（'https://og.railway.com/api/image?fileType=png&layoutName=simple', ）； ogimageUrl.searchParams.set('文本', entry.data.title);
// 将 `<meta property="og:image">` 标记添加到当前页面的 `<head>` 中。 head.push({ tag: 'meta', attrs: { property: 'og:image', content: ogimageurl.href }, });});

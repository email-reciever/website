背景
-----------

在过去的十年中，开发人员工具针对单一类型的项目进行了优化——JavaScript _Applications，通常是单页应用程序 (SPA)。 SPA 框架彻底改变了我们在 Web 上构建软件的方式，主导了过去十年的 Web 开发。

但即使是最好的水疗中心，也有权衡取舍，其中一些在不那么有状态的、基于内容的网站中毫无意义。 [Thoughtworks Technology Radar](https://www.thoughtworks.com/radar/techniques?blipid=202203006) 说得最好：

> “经常\[我们看到团队\] 盲目地接受**SPA 的复杂性**，即使业务需求没有证明它的合理性。” — [Thoughtworks Technology Radar](https://www.thoughtworks.com/radar/techniques?blipid=202203006)

这让我们思考……一个专为以内容为中心的网站而设计的网络框架是什么样的？ 优先考虑绩效的工具将如何改变我们的方法？ 如果我们放弃了 SPA 总是更好的概念，我们能否像 JSX 几乎 10 年前那样推动网络向前发展？

我们在 Astro 中找到了答案。

### 1\ 出色的网络性能应该是常态，而不是例外。

在 Astro 中建造一个缓慢的场地应该是不可能的（或至少是非常困难的）。

默认情况下，Astro 可以帮助您构建将 **Zero JavaScript 运送到浏览器的网站。 Astro 的内置组件语法尽可能地生成静态 HTML，仅向页面的任何交互部分发送 JavaScript。 当您构建您的第一个 Astro 网站时，您实际上需要的 JavaScript 会令您感到震惊。

Astro 还让您**自带框架。** Astro 支持 React、Svelte、Vue、Solid 和所有流行的 Web UI 框架。 您可以在页面上混合和匹配这些组件，同时仍然享受 Astro 的自动 JavaScript 缩减。 如果一个组件是 100% 静态的，Astro 会完全删除 JavaScript 并将其作为 HTML 发送。

这种独特的 JavaScript 方法（称为 _partial_ 或 _selective hydration_）解锁了一些非常引人注目的、细粒度的优化功能。 组件单独加载和水合物，因此我们可以逐个组件自定义和控制加载行为：

<!-- client:load -- 高优先级，尽快加载此组件 --><MyCriticalBuyButton client:load /><!-- client:visible -- 低优先级，仅在页面可见时加载 --><MyHeavyReactImageCarousel client:visible />

在 next.js 或 sveltekit 之类的 SPA 框架中，这种级别的控制非常困难，而且完全是 Astro 独有的。

### 2\。 简单、直接的 API 是我们的超能力。

我们将 Astro 的语言语法设计为简单，希望任何人都能接受它，无论背景或技能水平如何。 即使您只使用过前端 JavaScript 框架，习惯了更传统的后端工具，或者只是在使用 HTML 和 JavaScript 的基础知识，Astro 也会感到熟悉。

关于 Astro 的组件语言，最重要的一点是它是一个**超集的 HTML。** 一个有效的 HTML 片段是一个有效的 Astro 组件。 没有要导出的渲染函数、要返回的 JSX 或要管理的挂钩。 事实上，根本没有JavaScript！

<!-- 这是一个有效的 Astro 组件！ HTML 是最好的 :) --><p>你好，世界！</p>

您会惊讶于仅使用 HTML 就能在 Astro 中走多远！

随着您获得更多经验，您将了解 Astro 如何使用类似 JSX 的表达式和组件道具来支持动态模板化。 您还将更加熟悉我们用于在模板旁边运行服务器端代码的“FrontMatter”组件脚本。 很快，您将编写更强大的 UI 组件：

---// 在你的组件 frontMatter 中运行 javascript 代码。// 在构建时运行，所以 client!const 上没有 js = "hello, " + astro.props.name---
<p>{消息}</p>

我们将其余部分设计得同样简单：我们尽可能支持 Web 标准 API，因此您可以使用 `fetch()` API 和顶级 `await` 从外部来源获取数据。 使用显式 ESM `import` 从您的项目中读取本地数据，而不是不可见的隐式数据瀑布。

### 3\ 网络应该有一个与框架无关的基础。

前面我们提到 Astro 支持所有流行的 UI 框架——React、Vue、Svelte、Solid、Preact 和 Lit。 Astro 与框架无关的设计的含义是巨大的，我们在为 Astro 设计新功能时总是积极考虑这一点。

举个例子：[SolidJS](https://www.solidjs.com/) 于 2021 年推出，没有像 [Solid Start](https://github.com/solidjs/solid-start) 这样的官方全栈 Web 框架。 当然，您可以在新项目中使用 SolidJS，但许多工具使您无法在代码库中逐步尝试 SolidJS，而无需对新的、固体兼容的 Web 框架进行全面重写。

**Framework Lock-In** 可能是一个巨大的问题，尤其是在比我们其他人更长的时间范围内考虑技术决策的大型组织中。 在更大的开源生态系统中，Framework Lock-in 使 SolidJS 等新框架更难获得牵引力。

考虑到这一点，我们将 Astro 设计为完全与框架无关。 我们的重点是**为长期项目打下最佳基础**，让组织能够灵活地随着时间的推移改变技术和框架。 像谷歌这样的大型组织还可以从简化基础设施和仅对单个工具 (Astro) 的支持中受益，同时仍然为前端团队提供使用他们喜爱的 UI 框架的灵活性。

如果您正在为 Web 构建新的 UI 框架，请考虑在 Astro 支持下启动您的项目。

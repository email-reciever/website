[Microsoft](https://www.microsoft.com/en-ca) 是家喻户晓的名字，是 Microsoft Office 套件等流行工具的创建者。 他们的产品线包括桌面、网络和移动产品，例如 适用于 Android 和 iOS 的SDK。 为了在这些产品中保持其视觉品牌一致性，他们依赖于他们的设计系统[Fluent 2](https://fluent2.microsoft.design/)。

他们的办公室工程和经验团队在 3-4 年前创建了 Fluent 的第一个版本。 在过去的 2 年里，他们一直在努力开发最新版本 Fluent 2。由于 Island Architecture 的性能提升，Astro 是 Fluent 2 网站的最佳框架。 他们正在寻找适合现有工作流程和工具的轻量级产品。 Astro 允许 Microsoft 变得敏捷，帮助内容编辑器创建和编辑内容无痛。

![](/_astro/microsoft-products.CMuZRga7_Z15GkUJ.webp)

微软产品的徽标，包括 PowerPoint、Excel 等。

挑战
-----------

微软多次尝试使用其他框架和 CMS 构建他们的设计文档。 他们发现这些工具要么过于僵硬，要么太难维护，要么迁移是痛苦的。 其他人并没有很好地与他们的 Figma 工作流程和他们想要讲述的设计故事相结合。

该团队退后一步重新评估他们的优先事项，并确定他们应该专注于设计系统和他们实际需要的架构。 事实证明，它们的内容和设计不适合 CMS，因为它们有很多无法重用的自定义组件。 它们是独一无二的工程投入。

![](/_astro/microsoft-figma-workflow.jHLqZudt_ZUngLr.webp)

Figma 到 Markdown 工作流程。

要求
-------------

该团队希望在 DevOps 方面为 Fluent 2 网站提供一些轻量级和低维护的东西。 该工具必须支持其设计系统库，该库已发布了 React 版本。 可扩展性也很重要，即他们希望能够添加 CMS 或 DocSearch，例如 如果他们愿意，阿尔戈利亚稍后。 最后，他们希望能够支持传统的故事书 iframes 以共享代码示例，但最终能够从它们中迁移。

解决方案和实施
----------------------------

Astro 默认提供零 JavaScript，使其对 Microsoft 具有完美的轻量级和性能。 与工具无关，Astro 还支持其他框架，这意味着 Microsoft 可以继续支持使用 React 构建的设计系统库。 未来，他们希望通过重新添加CMS来改善内容编辑体验。 一些 [CMS’ supported by the Astro ecosystem](https://docs.astro.build/en/guides/cms/) 是 [Storyblok](https://www.storyblok.com/?utm_source=astro&utm_medium=display&utm_campaign=AWA_SPON_ASTR_TRA&utm_content=astro_collab)、[CloudCannon](https://cloudcannon.com/astro-cms/?utm_campaign=Astro%20out-of-beta&utm_source=astro-sponsorship) 和 [Sanity](https://www.sanity.io/guides/sanity-astro-blog)。

当被问及选择Astro最有利的部分是什么时，都铎说：

> 对我们来说，Astro能够生成完全静态文件非常重要。这对我们非常有利，因为我们希望免受DDoS攻击等多种因素的影响。因此，将大量依赖于后端服务的产品可能会导致问题。 静态网站，并在 Azure 上托管它，对于安全性和可扩展性非常有利。”

— Tudor Popa，工程经理@微软（流利2）

Astro 还使 Microsoft 能够继续支持旧版故事书 iFrames，直到团队准备好迁移。 这使微软能够在外部和内部用户更改技术堆栈时保持良好的体验。

微软在 10 个月的时间里设计并构建了新的 Fluent 2 网站，其中包括 200 多页的新内容。

结果
--------

与之前的堆栈相比，Astro 帮助 Fluent 团队在一半的时间内构建了新页面。 Astro 还帮助团队中的开发人员和设计师与 HTML、CSS 和 JavaScript 的全部功能保持一致。

Fluent 2 Design System 的使用已在公司的许多产品中使用，包括 Office 产品、Windows 和 Teams。 通过此设置，Microsoft 能够在 20-30 分钟内实现简单页面的 Figma 设计。

**使用 Markdown/MDX 很困难。** 随着您的网站的发展，在数百甚至数千个本地内容（博客文章、新闻通讯等）中保持一致的数据变得越来越困难。

内容是 Web 的重要组成部分，那么为什么我们要以低于标准的开发人员体验内容（双关语 _intended_）呢？ Astro 的使命一直是帮助开发人员快速、以内容为中心的网站……接受这一挑战是不费吹灰之力的。

Astro 2.0 引入了 **Content Collections API:** 一种使用本地 Markdown 和 MDX 的新方法。 内容集合通过内置类型的安全性（开箱即用）帮助您管理本地内容。 这是我们迄今为止最激动人心的版本，今天可供您尝试。

内容集合通过将本地内容组织到项目 `src/content` 目录中的“集合”中来工作。 这是一个特殊的目录，类似的 Markdown 和 MDX 文件可以组合在一起（例如：`blog/`、`docs/`、`newsletter/` 等）。

内置查询函数在键入时提供提示和自动完成功能。 只需几行代码，即可在 Astro 组件中获取内容并将其渲染为 HTML：

集合中的所有内容都是类型安全的，包括您的 FrontMatter。 使用可选架构定义您的集合，Astro 将确保每个文件都具有自动为您生成的 TypeScript 类型的 FrontMatter。

const blog = defineCollection({ schema: z.object({ // 定义你预期的 FrontMatter 属性 title: z.string(), // 将某些属性标记为可选的草稿：z.boolean().optional(), // 将 DateStrings 转换为完整的日期对象 publishDate: z.string().transform((val) => new date(val)) // 用描述性警告改进 SEO 描述： z.string().max(160, '短描述有更好的 seo!') // ... }),});

这种魔力要归功于 TypeScript 的强大验证库 [Zod](https://github.com/colinhacks/zod)。 使用 ZOD 的表达式架构构建器，您可以确保 `title` 之类的重要属性始终存在并正确键入。 当您出错时，Zod 提供了从缺失属性到重要的 SEO 建议的所有有用错误消息。

详细了解我们的 [docs guide](https://docs.astro.build/en/guides/content-collections/) 中的内容集合如何工作。

对每个人来说都是更好的错误
---------------------------

![](/_astro/banner-error-overlay-old.B6sAqVUo_ZTPiAD.webp)

想象一下，您正在开发您的网站，直到突然……繁荣！ 您的开发环境因此错误而停止。 发生了什么事？

如果您回答“一个随机文件在其首要内容中缺少预期的 `title`”，那么恭喜您！ 你是世界上第一个 JS 通灵者。 但如果你和我们其他人一样，追捕这个错误可能会涉及一些堆栈跟踪、反复试验、一些嘈杂的 `console.log` 陈述，以及一点运气。

现在，让我们看看 Astro 2.0 中的相同错误：

![](/_astro/banner-error-overlay.4d0L0Hqx_NtI7X.webp)

您会注意到的第一件事是 Astro 2.0 重新设计的错误叠加层。 但更重要的是，信息变得更加详细。 立即显示违规文件的确切文件名。 包含文件中的片段以帮助您理解问题，以及直接在代码编辑器中打开该文件的链接。 作为一个不错的奖励，包含文档提示可帮助您调试问题。

内容集合入门
---------------------------------------

我们刚刚发布了 Astro 1.4.0，特色：

*   **[Astro.cookies](#astro-cookies)**：在 Astro 页面和 API 路由中操作 cookie 的简化方法。
*   **[Support for strict dependency installation](#strict-dependency-installation)**：PNPM 用户现在可以在 Astro 项目中获得其默认半严格依赖安装策略的好处。
*   **[Better control over style ordering](#better-control-over-style-ordering)**：我们已修复样式排序，以便在 Astro 组件中定义的样式在捆绑的 CSS 中低于您导入的全局样式。
*   **[JSX support in Vue](#jsx-support-in-vue)**：Vue 用户现在可以使用 JSX 和 TSX 定义组件。

您可以通过运行 `npm install astro@latest` 来更新您的项目。

星际饼干
--------------

![Code example that shows off using Astro.cookies](/_astro/astro-cookies.Dxm4_Sob_ZoefBQ.webp)

使用 SSR 构建的网站能够在 Astro 中读取和设置 Cookie。 以前，读取 cookie 需要读取请求中的 `cookie` 标头（页面中的 `Astro.request`），然后使用库进行解析。 在返回的响应中将需要将 cookie 序列化为 `Set-Cookie` 标头。

鉴于 Cookie 在有状态和经过身份验证的应用程序中的重要性，我们认为 Cookie 的简化抽象将使所有这些变得更容易。

使用 `Astro.cookies` 您可以使用 [Map](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Map)\ 类似的 API 读取和写入 cookie。 在上面的示例中，我们检查 `prefs` cookie 是否存在，如果不存在，则设置默认值。 然后我们得到它的价值并在我们的模板中使用它。

查看 [the docs](https://docs.astro.build/en/reference/api-reference/#astrocookies) 以获取完整的 API 参考。

严格的依赖安装
------------------------------

如果您在 Astro 项目中使用 [pnpm](https://pnpm.io/)，您现在可以使用其严格的依赖算法安装您的依赖项。 由于 Astro 代表您运行代码，因此您以前需要 [hoist packages to the root](https://pnpm.io/blog/2020/10/17/node-modules-configuration-options-with-pnpm#the-worst-case---hoisting-to-the-root)，这意味着您的大部分依赖项（和 _他们的依赖项）都安装在顶级 `node_modules/` 文件夹中。

更严格的安装是 _correct_ ，因为包只能导入它自己定义的依赖项 `package.json`。 更严格的安装速度也更快，因为 Node.js 不需要查找尽可能多的文件夹来查找软件包。

此功能在 Astro 1.4.0 中为新项目免费提供。 现有项目可以删除 `.npmrc` 文件中可能拥有的提升配置。

更好地控制风格订购
---------------------------------

当 Astro 1.0 发布时，我们将 CSS 范围机制更改为使用 [`:where()` 伪类](https://developer.mozilla.org/en-US/docs/Web/CSS/:where)。 这使您可以使用通常的方式更好地控制特异性，例如添加类名。

进行此切换，我们没有意识到样式的默认排序并不理想：直接在组件中定义的样式出现在 CSS 输出中的导入样式之前，使组件样式的优先级低于导入的样式。

在 1.4.0 中，您在 Astro 组件中编写的样式将出现_after_ 全局样式导入。 实际上，这意味着如果您编写这样的组件：

**title.astro**

---import "../styles/global-titles.css"---
<h1>{astro.props.title}</h1><style> H1 { 颜色：AliceBlue; }</style>

当您的网站构建并捆绑了CSS时，您会得到以下内容：

/src/styles/global-titles.css

H1 { 颜色：缟玛瑙；}
/* /src/components/title.astro */h1:where(.astro-1234) { 颜色：aliceblue;}

鉴于这些选择器都具有相同的特定性，因此后面列出的一种——适用于您的 title.astro 组件的一种——将占上风。 在该组件中，`h1` 将具有 `color: aliceblue`，但在组件之外定义的任何 `h1` 都将是 `onyx`。

您可以获得两全其美：Astro 中定义的样式如果具有相同的特异性，则会更好地优先化，但您可以在需要时通过增加特异性来覆盖这一点。

输出 CSS 顺序现在是（从最低到最高优先级）：

1.  CSS 在 `public/` 文件夹中添加为 `<link>` 标签中的标签。
2.  CSS 在您的 FrontMatter 中导入，按您的导入语句的顺序（深度优先）。
3.  在天文风格标签中定义的css。

我们目前正在编写完整的文档来解释 CSS 排序是如何工作的，以及如何通过排序和特殊性控制 CSS 优先级。

Vue中的JSX支持
-------------------

![Code example that shows a JSX component defined with Vue](/_astro/vue-jsx.BmPzHAXY_IOOwN.webp)

您现在可以将 JSX 和 TSX 与 [Vue integration](https://github.com/withastro/astro/blob/d08093f7d4f9762c0edc71e14c796d7ea8038cda/packages/integrations/vue/README.md) 一起使用。 在集成选项中设置 `jsx: true` 启用 [@vitejs/plugin-vue-jsx](https://github.com/vitejs/vite/tree/main/packages/plugin-vue-jsx) Vite 插件，它完成了大部分工作，您可以使用其任何选项。

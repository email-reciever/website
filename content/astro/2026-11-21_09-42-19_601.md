更快的页面渲染
----------------------

Astro 使组件内的异步功能变得容易，但这意味着每个组件和页面都是异步呈现的，即使不需要。 当页面上的每个组件发生这种情况时，这些承诺的开销可能会真正加起来！

现在，多亏了来自 [Fora](https://fora.com) 的 [MatthewLymer](https://github.com/MatthewLymer) 的出色社区贡献，Astro 只会异步渲染组件……（a）等待它……它们实际上包含异步函数调用。

在基准测试中，这导致了渲染同步组件的显着加快。 这有利于按需和静态构建，尽管在 SSR 响应时间中看到了最大的改进。 这甚至有助于使用异步功能的页面，因为页面上的大多数组件仍然是同步的。

改进的确切数量将取决于各个站点。 具有许多组件的复杂页面将看到最大的改进，而在请求时使用较慢的外部 API 的页面可能不会改变。 在我们的测试中，除非页面查询外部 API，否则 SSR 响应通常要快 1.5-2 倍。 一些例子：

*   对于 5300 页的 [Astro docs site](https://docs.astro.build)，它**将静态构建时间减少 10-15%。**
*   在[Platformatic SSR benchmark](https://github.com/platformatic/ssr-performance-showdown)中生成一个包含3000多个组件的页面，请求速度***** 4倍**。

您不需要做任何事情来从这种改进中受益：只需坐下来享受更快的渲染时间。

自动会话存储设置
------------------------------

Astro 5.1 引入了实验性 [session storage API](https://docs.astro.build/en/reference/experimental-flags/sessions/)，它允许开发人员轻松管理服务器上的用户会话。 该功能支持数十种不同的后端存储驱动程序，由 [unstorage](https://unstorage.unjs.io) 提供支持。

以前您需要在 `astro.config.mjs` 中配置会话存储驱动程序，但现在 Astro 将在使用受支持的适配器时自动为您设置会话存储。

我们开始支持 `@astrojs/node` 适配器，它使用文件系统进行存储，`@astrojs/netlify` 使用 Netlify Blobs。 我们希望在不久的将来为更多适配器添加默认的驱动程序支持，其中托管平台包含一个存储 API。 在所有情况下，如果默认值不存在或您更喜欢使用另一台存储驱动程序，您仍然可以手动配置自己的会话存储驱动程序。

如果您还没有尝试过 Session Storage API，可以通过将 `experimental.session` 标志设置为 `astro.config.mjs` 中的 `true` 来启用此功能：

astro.config.mjs

{ Adapter: node({ mode: "standalone", }), experimental: { session: true, }, }

如果您已经在使用会话功能，则需要使用此突破性更改更新配置以获取新语法。

`experimental.session` 选项现在是一个布尔标志，您可以设置 `true` 并使用受支持的适配器享受默认会话存储驱动程序，无需进一步配置！

会话配置本身已移至顶级 `session` 键。 这允许您配置非默认驱动程序以及其他选项，例如 `base` 前缀或过期 `ttl`。

astro.config.mjs

{ Adapter: node({ mode: "standalone", }), experimental: { session: { driver: "upstash", }, session: true, }, session: { driver: "upstash", }, }

有关更多详细信息和示例，请参阅 [experimental session docs](https://docs.astro.build/en/reference/experimental-flags/sessions/)。

对 Netlify 捆绑的更多控制
---------------------------------

当 Astro 构建您的站点以部署到 Netlify 或 Vercel 等无服务器平台时，它需要捆绑运行站点所需的所有文件和依赖项。 Netlify 和 Vercel 适配器使用 [the same library for this](https://github.com/vercel/nft)，这通常擅长解决所需的问题。

它并不总是正确的：有时它会错过您需要的文件，特别是如果它是您使用文件系统函数加载的静态文件。 其他时候，它包括您不需要的文件，这可能会减慢您的构建速度并增加您的捆绑包大小，特别是如果它是一个大型二进制文件。

为此，Vercel 适配器已经有 `excludeFiles` 和 `includeFiles` 选项，允许您指定应排除或包含在捆绑中的文件。 在此版本中，Netlify 适配器中也提供这些选项。 这两个选项都接受路径或全局数组。

astro.config.mjs

{ 适配器：netlify({ includeFiles: ["src/locales/**/*.po"], excludeFiles: ["node_modules/big-package/chonky-file.bin"], }), }, },

感谢贡献此功能的 [Dani Fernández](https://github.com/dfdez)。

改进了 `HEAD` 请求的处理
----------------------------------

如果定义了 `GET` 处理程序，API 端点现在将自动处理 `HEAD` 请求。 Astro 将调用 `GET` 处理程序并以空的主体返回响应。 如果您希望以不同的方式处理 `HEAD` 请求，您仍然可以定义单独的处理程序。 有关详细信息，请参阅 [the API endpoints docs](https://docs.astro.build/en/guides/endpoints/#server-endpoints-api-routes)。

感谢 Netlify 的 [Vitalii Rybachenko](https://github.com/VitaliyR) 提供此项贡献。

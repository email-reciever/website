Astro Technology Company——Astro Web Framework 背后的公司——正在加入 Cloudflare！ Astro Web 框架的采用率每年都在继续翻倍，[Astro 6](https://astro.build/blog/astro-6-beta/) 指日可待。 在 Cloudflare 的支持下，我们将拥有更多资源和更少的干扰，以继续我们为内容驱动的网站构建最佳框架的使命。

**这对 Astro 意味着什么：**

*   ASTRO保持开源和MIT许可
*   ASTRO继续积极维护
*   ASTRO 继续支持广泛的部署目标，而不仅仅是 Cloudflare
*   ASTRO 的开放治理和当前路线图仍然存在。
*   Astro Technology Company的全职员工现在都是Cloudflare的员工，并将继续在Astro全职工作。

Astro 是如何开始的
------------------

2021年，Astro因挫折而诞生。 当时的趋势是每个网站都应该被构建为一个应用程序，然后运送到用户的浏览器中进行渲染。 这不是很高的性能，在过去的十年里，我们一直在想出越来越复杂的解决方案来解决这个性能问题。 SSR、ISR、RSC、PPR、TTI 优化通过代码分割、树木震动、延迟加载，所有这些都可以从一个运行在世界半路的预热服务器生成一个阻塞双重数据水合有效载荷。

我们的使命是设计一个专门用于构建网站的 Web 框架——我们称之为 _content 驱动的网站，_ 以更好地与数据驱动的、有状态的 Web 应用程序区分开来——引起了共鸣。 现在，Astro 每周下载近 1,000,000 次，并已被 100,000 多名开发人员用来构建快速、漂亮的网站。 今天，您将在整个网络上找到 Astro，为 Webflow、Wix、Microsoft 和 Google 等公司提供主要网站甚至整个开发者平台。

**在此过程中，我们还尝试发展业务。** 在 2021 年，我们筹集了一些资金并形成了 [The Astro Technology Company](https://astro.build/blog/the-astro-technology-company/)。 我们更大的愿景是，像 Astro 这样设计良好的框架可以位于大型开发平台的中心，与框架同步设计的可选托管原语（数据库、存储、分析）。

我们永远无法实现这一愿景。 将付费的、托管的原语引入我们的生态系统的尝试失败了，并且很少证明它们自己的存在是合理的。 我们考虑过在 Astro 的一流托管或内容管理之后更直接地进行，但知道我们会花大部分时间追赶资金充足、精明的竞争对手。 我们一直在探索不同的想法，但没有像 Astro 那样吸引用户。

这并不全是坏事。 [Astro DB](https://docs.astro.build/en/guides/astro-db/)（我们为 Astro 项目构建托管数据库产品的尝试）最终演变成开放的、内置的 Astro 数据库客户端，它今天仍然存在于核心中。 我们探索用Astro构建电子商务层最终是[open-sourced](https://github.com/withastro/storefront)。 这是有益的工作，但多年来分心造成了损失。 每次尝试新的付费产品或产品时，我和其他人都在开发开发人员每天使用和喜爱的 Astro 框架上。

**恢复焦点**
-----------------------

去年，Dane (Cloudflare CTO) 和我开始更认真地谈论网络的未来。 这些对话很快就变成了更大的事情：下一个十年是什么样的？ 框架如何适应 AI 编码和代理的世界？

很明显，即使随着网络技术的发展，**内容仍处于中心位置。** 我们意识到我们每个人都在从不同的角度朝着同样的愿景努力：

*   **Cloudflare** 一直在从 **Infrastructure** 方面解决它：在默认情况下投注全局平台，具有快速启动、低延迟和安全性内置。
*   **ASTRO** 一直在 **Framework** 方面解决它：押注在一个 Web 框架上，这使得默认情况下构建速度快的网站变得容易，而不会使事情变得复杂。

重叠是显而易见的。 通过共同努力，Cloudflare 为我们的用户提供了不断创新所需的支持。 现在，我们可以停止担心在 Astro 上建立业务的支出周期，并开始 100% 专注于代码，并有共同的愿景来推动 Web 向前发展。

**Cloudflare ❤️ Astro**
------------------------

Cloudflare 一直是 Astro 的长期赞助商和冠军。 他们在支持 Astro、Tanstack 和 Hono 等大型开源项目方面有着良好的记录，而无需试图捕获或锁定任何东西。 对我们和 Cloudflare 保持开放是不可协商的要求。

这就是为什么 Astro 将保持免费、开源和 MIT 许可的原因。 我们将继续公开运行我们的项目，为贡献者提供开放的治理模式和开放的社区路线图。 云彩。

借助 Cloudflare 的资源和支持，我们现在可以充分关注为内容驱动的网站构建最佳的 Web 框架。 网络正在快速变化，并且标准不断上升：性能、规模、可靠性以及在 Web 上发布内容的团队提供更好的体验。

当我们为即将到来的 Astro 6 版本（Beta Out Now！）和我们的 2026 路线图做准备时，您会看到这一焦点反映在我们的路线图中。 敬请期待！

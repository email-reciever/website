**介绍 Astro 6 Beta！** 我们很高兴地宣布 Astro 6 的第一个 Beta 版本，它具有重新设计的开发服务器、显着的渲染性能改进以及用于使用 CSP、字体和实时内容集的新内置 API。

**什么是 Astro？** [Astro](https://astro.build/) 是用于构建内容驱动网站的 Web 框架，包括博客、营销和电子商务。 如果您需要一个能够快速加载且具有出色 SEO 的网站，那么 Astro 适合您。

**新的 Astro 6 开发服务器重构将 Astro 的开发和生产代码路径更紧密地结合在一起，并提高了 Astro 在所有运行时的稳定性**。 现在，您可以使用与生产相同的运行时来开发您的 Astro 项目。 值得注意的是，这可以在 [Cloudflare Workers](https://developers.cloudflare.com/workers/) 上释放对 Astro 的一流支持，更多地访问特定于运行时的原语和更真实的开发体验。

要尝试 Astro 6 Beta，请运行 `create astro` 命令：

npm create astro@latest ----ref next

要将现有项目升级到测试版，请使用自动 `@astrojs/upgrade` CLI 工具：

    # 推荐：NPX @ASTROJS/升级测试版
    # 手册：npm install astro@betapnpm install astro@betayarn 添加 astro@beta

查看 [our v6 upgrade guide](https://v6.docs.astro.build/en/guides/upgrade-to/v6/) 以获取有关重大更改的完整详细信息和迁移指南。

重新设计的 `astro dev`
-------------------------

Astro 6 的标题功能是完全重新设计的开发服务器（`astro dev`）。

Astro 6 有机会显着改进 Astro 管理不同环境（客户端、服务器和 PreRender）的方式，使用 **[Vite’s Environment API](https://vite.dev/guide/api-environment)** 缩小了 prod 和 dev 之间的差距。

以前，在本地运行的代码一旦部署就可能有所不同。 特定于平台的功能通常要到部署后才能进行测试。 在某些情况下，Astro 甚至有单独的“开发”和“产品”逻辑路径，增加了边缘案例错误的机会。

通过在内部使用此 API，Astro 现在可以在您部署的同一运行时内运行您的 Web 应用程序，使用相同的 JavaScript 引擎、相同的全局变量和相同的平台 API。

此重构使 Astro 能够：

1.  **针对真实运行时运行** – 开发可以在与生产相同的运行时内执行。
2.  ** 支持更多平台** – 今天的 Cloudflare 工作人员，其基础支持未来的额外运行时间。

通过统一开发和生产代码路径，我们已经发现并修复了许多仅在开发中或仅在生产中存在的微妙错误。

此更改使 ASTRO 6 在所有运行时（包括 non-node.js 环境）中更加稳定。 由于这次升级，Astro的所有用户都将获得更大的稳定性和可靠性！

聚光灯：Cloudflare Workers上的Astro 6
---------------------------------------

Cloudflare Workers 是当今新 `astro dev` 使之成为可能的最完整示例。

到目前为止，Astro Cloudflare 集成在开发过程中模拟了 Workers 运行时。 你可以针对特殊的天文专用 API，如 `Astro.locals.runtime` 提供 Cloudflare 平台的 polyfills 和模拟，然后部署并希望在生产中一切都一样。

借助 Astro 6 Beta，`astro dev` 现在可以使用 Cloudflare 的开源 JavaScript 运行时 **Workerd** 运行您的整个应用程序。 这与在生产中为 Cloudflare 工作人员提供支持的运行时相同，而不是模拟或多填充。

在 Astro 6 中，您现在可以直接针对真实平台 API 进行开发，在开发期间而不是部署后捕获问题。 不再需要像 `Astro.locals.runtime` 这样的特殊模拟 API。

当您在 Cloudflare 支持下运行 `astro dev` 时，您现在可以访问：

*   **Durable Objects** – 本地测试有状态的无服务器对象
*   **kv 命名空间** – 针对实际的键值存储进行开发
*   **R2 存储** – 在开发中使用对象存储
*   **Workers Analytics Engine** – 测试分析集合
*   **环境变量和秘密** – 完整的配置支持
*   **热模块替换（HMR）** – workerd内运行时的实时更新

使用 `cloudflare:workers` 模块直接访问您的 Cloudflare 绑定：

---import { env } 来自“cloudflare:workers”；
// 直接访问 KV 存储 - 在 dev 和 productionConst 中工作 kv = env.my_kv_namespace;await kv.put("visits", "1");const visits = await kv.get("访问");---<p>访问：{访问}</p>

Cloudflare 适配器与新开发服务器一起得到了显着增强：

*   **`astro preview`** 现在与 Cloudflare 一起使用，让您在部署之前在本地测试构建的应用程序
*   **用于自定义入口点和开发服务器配置的集成 API 更新**
*   **当您的代码与生产行为不同时改进的错误消息**

我们正在积极改进 Cloudflare 支持，同时致力于稳定的 Astro 6 版本。 当前，预渲染（静态）构建不通过 workerd 运行，但它们将在 v6 发布之前运行。

如果您遇到问题或意外行为，请告诉我们。 当我们将运行时支持扩展到 Node.js 之外时，此反馈尤其重要。

有关详细信息，请参阅 [Cloudflare adapter upgrade guide](https://v6.docs.astro.build/en/guides/integrations-guide/cloudflare/#upgrading-to-v13-and-astro-6)，有关更改和改进的完整列表，请参见 [Cloudflare adapter changelog](https://github.com/withastro/astro/blob/next/packages/integrations/cloudflare/CHANGELOG.md)。

实时收藏（稳定）
--------------------------

Astro 5.10 的实验性实时内容集现在在 Astro 6 中稳定。这些内容基于 Astro 的类型安全内容集合，可以让您在本地或从 CMS、API、数据库和其他来源获取内容，并使用统一的 API 你所有的内容。

实时集合解锁缺失的部分：实时更新数据，无需重建。 借助自定义数据加载器，实时集合是您经常更新需要最新数据新鲜度的数据源的完美解决方案，例如实时股票价格或库存。

Live Collections 使用不同的 API，但配置和辅助函数的设计是为了让已经使用 Astro 的构建时内容集合的人感到熟悉：

src/live.config.ts

从 'Astro:Content' 导入 { defineliveCollection }；从 '@mystore/astro-loader' 导入 { StoreLoader }；
常量产品 = defineLiveCollection({ loader: storeloader({ apiKey: process.env.store_api_key, }),});
导出常量集合 = { 产品};

由于在发出实时数据请求时可能发生任何事情（例如网络问题、API错误、验证问题），因此API旨在使错误处理变得明确：

---import { getLiveEntry } 来自“astro:content”；
const { entry: product, error } = await getLiveEntry('products', astro.params.id);if (error) return astro.redirect('/404');---<h1>{product.data.title}</h1>

有关更多示例和配置选项，请参阅 [live content collections documentation](https://v6.docs.astro.build/en/guides/content-collections/#live-content-collections)。

内容安全策略（稳定）
--------------------------------

以前作为 Astro 5.9 中的实验性功能发布的内容安全策略 (CSP) 支持现在在 Astro 6 中是稳定的。CSP 通过控制可以加载哪些资源来帮助保护您的站点免受跨站点脚本 (XSS) 和其他代码注入攻击。

这是 Astro 迄今为止最受欢迎的功能请求，我们精心设计了该功能，以在所有 Astro 渲染模式（静态页面、动态页面和单页应用程序）中工作，并考虑到最大的灵活性和类型安全性。

此功能与 Astro 的所有官方适配器（Cloudflare、Netlify、Node、Vercel）兼容。 Astro 将为您生成 CSP 标头或 `<meta>` 元素，包括页面上使用的脚本和样式的散列，即使是动态加载的！

您现在可以在 Astro Config 中设置 `csp: true` 以获得默认保护，或者您可以通过使用包含其他选项的配置对象启用此功能进一步自定义安全策略：

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ csp: { scriptDirective: { 资源：[ "'self'", "https://cdn.example.com" ] } }});

有关所有可用选项，请参阅 [CSP configuration reference](https://v6.docs.astro.build/en/reference/configuration-reference/#securitycsp)。

突破性变化和迁移
-----------------------------

Astro 6 包括一些重大更改，因为我们清理已弃用的 API 并与新标准保持一致。 关键变化：

*   **删除的 API**：`Astro.glob()`、`emitESMImage()`、已弃用的 `<ViewTransitions />` 组件、传统内容集合
*   **节点版本**：需要节点 22+（掉落的节点 18 和 20 支持）
*   **集成 API**：更新适配器接口、路由数据和 SSR 清单
*   **Cloudflare 适配器**：对 `Astro.locals.runtime` 和自定义入口点模式进行中断更改
*   **I18N**：更改`i18n.redirectToDefaultLocale`的默认行为
*   **ZOD 4**：升级到 ZOD 4，不再支持 ZOD 3

有关每个更改的详细迁移步骤，请参阅 [upgrade guide](https://v6.docs.astro.build/en/guides/upgrade-to/v6/)。

稳定性和路线图
--------------------

**Astro 6 目前是 Beta 版软件。** 这是我们最初发布的这些功能，我们将在稳定的 V6.0 版本之前对其进行改进。 我们正在积极寻求反馈：

*   您是否正在使用工人开发来解决边缘情况？
*   您是否需要 Cloudflare 以外的运行时支持？
*   我们可以改进开发体验的哪些方面？

Workerd 开发支持在广泛测试中尤为重要，因为我们希望确保它能在不同的项目类型和配置中顺利运行。

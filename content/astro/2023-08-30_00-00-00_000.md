**介绍 Astro 3.0！**

**ASTRO 3.0 是第一个支持 View Transitions API 的主要 Web 框架。 直到最近，这才在 JavaScript 单页应用程序 (SPA) 中才有可能。 但是由于网络平台的进步，这些功能现在可供Astro 3.0中的每个人使用。

其他发布亮点包括：

*   **图像优化（稳定）**：未标记且比以往任何时候都好。
*   **更快的渲染性能：** Astro 组件渲染速度快 30-75%。
*   **无服务器的SSR增强功能：**连接到主机平台的新方法。
*   **JSX 的 HMR 增强功能：** 对 React 和 Preact 的快速刷新支持。
*   **优化的构建输出**：更干净、更高效的 HTML。

Astro 3.0 现在在 NPM 上可用。 访问 [astro.new](https://astro.new/) 在浏览器中尝试 Astro 3.0，或在终端中运行以下命令以开始新项目：

    # 创建一个新的Astro 3.0项目：npm create astro@latest

将现有项目升级到 Astro 3.0？ 查看 [v3.0 Upgrade Guide](https://docs.astro.build/en/guides/upgrade-to/v3/) 了解每个更改的完整详细信息和个人升级指南。

天文视图过渡
-----------------------

![](/_astro/post-asset-1.uIwlorn1_wn6rI.webp)

视图转换是一组新的平台 API，它们可以解锁页面之间的本机浏览器转换效果。 从历史上看，这只有在单页应用程序 (SPA) 中才有可能，但 Web 浏览器和规范作者在过去几年中一直在努力将本机页面转换到平台，而 Astro 3.0 是第一个将它们带入主流的 Web 框架。

使用 Astro View 转换，您可以：

*   **morph**从一页到另一页的持久元素
*   **FADE** 页面内外的内容，以减少不和谐的导航效果
*   **在页面内外滑动** 内容，更具个性
*   **Persist** 跨页面的通用 UI，有或没有刷新

Astro 中视图转换的最佳部分是它们的使用简单程度。 只需 2 行代码，您就可以添加微妙但有品位的！ — 将动画淡入您的网站。 要自己尝试，请导入 `ViewTransitions` 组件并添加到任何页面的 `<head>` 元素中：

src/pages/index.astro

---// 注意：确保将“<ViewTransitions />”组件//添加到其他页面，而不仅仅是一个.import {viewTransitions} 来自'astro:transitions';---<head> <title>我的视图过渡演示</title> <ViewTransitions /></head><body><!-----></body>

更快的渲染性能
-----------------------------

![](/_astro/post-asset-2.De6cXLTi_ZPEGsA.webp)

渲染性能在 Astro 3.0 中得到了重大提升，大多数组件渲染速度要快 30%（与 Astro 2.9 相比）。 在[complex benchmarks](https://gist.github.com/bluwy/0cf63b46915244477cea91c7b34e90ec)中，速度提高可高达75％。

实现这种加速是在 Astro 2.10 中启动并延续 Astro 3.0 的专用重构工作的结果。 我们从构建管道中的热路径中删除了尽可能多的不必要的代码，并优化了剩余的代码。 不必要的生成器和异步代码是最大的两个罪魁祸首。 每一毫秒都很重要！

**图像优化（稳定）**
------------------------------

![](/_astro/post-asset-3.Cseb8A4s_23whzH.webp)

图像优化现在在 Astro 3.0 中稳定，在所有项目中都可用。

您可以从代码库中导入图像，并将它们放在带有新内置 `<Image>` 组件的页面上。 Astro 将处理其余部分：构建管道将为您自动检测和优化每个图像。 最终渲染的图像标签将为您添加推断的宽度和高度，以防止使用自动 [Cumulative Layout Shift (CLS)](https://web.dev/cls/) 保护的布局移位。

---// 导入 <Image /> ComponentImport { image } 从 "astro:assets"// 导入对图像本身的引用 import myImage 从 "../assets/penguin.png"---
    <Image src={myImage} alt="A very cool penguin!" />

我们最后一次写关于 [image optimization](https://astro.build/blog/images/) 是在六月。 从那时起，我们获得了一些重要的改进，包括：

*   全力支持[Vercel’s built-in image service](https://vercel.com/docs/concepts/image-optimization)。 将 `imageService: true` 添加到您的 Vercel 集成配置，以查看通过其全局 CDN 优化的生产映像。
*   迁移到[Sharp](https://sharp.pixelplumbing.com/)作为我们新的默认优化库。 夏普取代了我们之前的默认 `@squoosh/lib` ，即 [no longer maintained.](https://www.npmjs.com/package/@squoosh/lib)
*   支持优化远程图像。 内容团队可以继续使用其现有的工作流和 CMS 工具来管理其图像。

在我们的新 [Images guide](https://docs.astro.build/en/guides/images/) 中了解有关图像优化的更多信息。

**无服务器的SSR增强功能**
---------------------------------

![](/_astro/post-asset-4.Rq0n_72H_23La1K.webp)

周一我们宣布了一个新的，[official hosting partnership](https://astro.build/blog/vercel-official-hosting-partner/) 和 [Vercel](https://vercel.com/)。 与 Vercel 的合作使我们能够对 Astro 3.0 中的 SSR 故事进行重大改进。 这些新功能使所有用户受益，无论他们选择在哪里托管其网站：

*   **Per-Route 代码拆分** - 为您网站中的每条路由创建更小的单独服务器文件。 无服务器用户（Vercel、Netlify、Cloudflare 等）现在可以通过减少每个请求上未使用的代码的加载来提高性能。
*   **Edge Middleware** - Astro 现在可以捆绑您的中间件以在边缘部署。 Edge Middleware 分布在全球范围内，并在尽可能接近用户的服务器上运行。
*   **主机自定义：** 由于没有两个托管提供商是相同的，我们为 Astro 添加了一个 API，帮助用户更好地理解这些差异。 托管适配器（如 `@astrojs/node` 和 `@astrojs/vercel`）现在可以告诉 Astro 他们支持哪些功能。 Astro 可以在开发过程中使用这些信息来显示更有用的、信息丰富的警告，并防止意外的生产错误。

这些功能今天都可以在 Vercel 上使用，但任何主机适配器都可以升级以添加支持。 在接下来的几个月中，我们将与我们的社区维护人员合作，帮助将这些功能带到任何可以支持它们的托管平台上。

**JSX 的 HMR 增强功能**
-----------------------------

![](/_astro/post-asset-5.2qFRUMtV_Z1upwhl.webp)

[React Fast Refresh](https://reactnative.dev/docs/fast-refresh) 现在在 Astro 3.0 中工作，这要归功于我们对内部 JSX 构建支持的重大重构。 React、Preact 和 Solid.js 用户都应该在 Astro 3.0 中看到热模块重新加载 (HMR) 和整体开发服务器稳定性的显着改进。

快速刷新是一种现代开发功能，本地更改被智能地推送到浏览器，无需页面刷新。 是什么使快速刷新与众不同（相对于常规 HMR）是这些更新被推送到浏览器 _********************************************************************************

在下面的演示中，尽管开发人员更新了模板本身，但请注意页面永远不会刷新，计数器永远不会重置为零。 这是快速刷新。

![A code editor side by side with a window showing a React component with a timer running. When the code editor saves a change, the page updates only the changed elements, meaning the timer can keep running uninterrupted.](https://www.snowpack.dev/img/guides/react/react-fast-refresh.gif)

如果您曾经构建过模态或其他多步 UI，那么您可能已经经历了每次更改后看到页面状态刷新和重置的常见挫败感。 快速刷新解决了这个问题，加快了您的开发工作流程。

**优化的构建输出**
---------------------------

![](/_astro/post-asset-6.DdNB6f20_ZyQaxh.webp)

我们对 3.0 中的整体构建输出进行了一些改进，包括：

*   **HTML 缩小：** Astro 3.0 现在将自动最小化所有 HTML 输出。 缩小的 HTML 会导致更小的有效负载和更快的整体响应时间。
*   **Component IDs:** 那些嘈杂的 `astro-XXXXXX` 类名已被新的专用 `data-astro-cid-hash` HTML 属性替换。 此更改使您的 `class=""` 属性更具可读性，整体上有更有条理的 HTML 输出。
*   **css 内联：** Astro 3.0 现在会自动将小块 CSS 内联到您的 HTML 中。 这与较旧版本的 Astro 相比，页面加载性能提高了页面加载性能，其中一个页面可能会将许多较小的 CSS 文件作为来自浏览器的单独请求加载。

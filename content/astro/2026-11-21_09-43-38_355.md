**这是我们在2024年计划为Astro计划的三个主要新功能的“Astro未来”系列系列的第1部分。这篇文章介绍了View Transitions API的更新，Astro现在可以在不需要一行JavaScript的情况下用于原生的应用程序式页面导航。**

[View Transitions API](https://developer.chrome.com/docs/web-platform/view-transitions) 是一组新的平台 API，用于解锁页面之间的本机浏览器转换。 从历史上看，这只有在 JavaScript 密集的单页应用程序 (SPA) 中才有可能，但最近的进展现在将本机页面转换带到了 Web 平台。

Astro 用户自 [Astro 2.9](https://astro.build/blog/astro-290/) 以来已经可以提前访问视图转换。 由于浏览器的初始限制，我们的早期支持通过将 JavaScript 路由器注入页面来为您管理动画。 这从来不是一个长期的解决方案，但它成功地为我们的用户创造了一个早期的游乐场：

我们打赌，主要的网络浏览器将继续改进，有一天我们可以完全删除我们的 JavaScript 路由器 shim。 有一天，当用户点击一个链接时，该点击可能会在浏览器中触发一个过渡动画，作为其正常流程的一部分。

我很高兴地宣布那一天终于到来了。 Chrome 126（上周发布）和 Microsoft Edge 126（本周发布）都支持“跨文档视图转换”在 Astro 中解锁 **Zero-JavaScript 视图转换**。

启用零 JavaScript 视图转换
--------------------------------------

要利用本机新视图过渡 API，它就像将 `@view-transition` at-rule 添加到您的网站一样简单。 这是您需要的所有CSS：

<style> @View-Transition { 导航：自动； /* 启用！ */ }</style>

_注意：某些代码编辑器（例如：VSCode）中的内置CSS语法高亮器可能难以解析较新的`@view-transition` AT-Rule语法。 您可以将 `/* enabled! */` 之类的评论添加到您的 CSS 中，作为荧光笔的短期修复程序。_

要启用跨文档视图转换，过渡的“末端”必须包含此规则。 共享页面布局组件可能是将其添加到代码库中的好地方。

升级现有项目
----------------------------

如果您已经在使用由我们的 `<ViewTransitions />` 组件提供的 Astro View 转换，那么现在可以安全地删除该组件并用 at 规则替换它。 这将从您的页面中删除注入的向后兼容的 JavaScript 路由器，从而降低了客户端代码的整体复杂性。

--- 从“astro:transitions”中导入 { viewTransitions };---<head> <ViewTransitions fallback="none" /> <style> @view-transition { 导航：auto; } <style></head>

如果您仍然希望您的视图转换在较旧的浏览器中运行，欢迎您继续使用我们的向后兼容的 `<ViewTransitions />` 组件。 您可以随时迁移。 我们目前没有计划取消对 `<ViewTransitions />` 组件的支持。

`transition:persist` 呢？
--------------------------------

[Persistent element transitions](https://docs.astro.build/en/guides/view-transitions/#maintaining-state) 成为 Astro 的热门功能。 `transition:persist` 指令告诉 Astro 在导航中保留一个元素，而不中断或破坏其状态。 这使 UI 像音频和视频播放器能够继续跨页面播放，就像 [Maxi Ferreira’s](https://twitter.com/charca) [music player demo](https://astro-records.pages.dev/) 中的那样。

不幸的是，浏览器中的本机跨文档导航尚不支持此功能。 未来可能会对持久性音频和视频播放器进行本地支持，但与此同时，如果您需要此附加功能，您可以继续使用我们的 `<ViewTransitions />` 组件。

阿斯托的未来
--------------------

使用链接进行导航是 Web 的基本行为。 我们相信这是 Chromium 和最近内存中的浏览器规范过程中最重要的进步之一。 我们很高兴能够继续与 Google Chrome 和其他浏览器供应商合作推出此新 API。

开发人员可以利用今天的本地视图转换或等待它向更多用户推出。 每当您准备好启用（或迁移）时，CSS 本质上都是一行更改。

首先，您可以了解有关 [Astro View Transitions](https://docs.astro.build/en/guides/view-transitions) 的更多信息。 我们将在接下来的几周内更新我们的文档，以包括使用这些 [new native browser APIs](https://developer.chrome.com/docs/web-platform/view-transitions)。

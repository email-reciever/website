**这是我们在2024年计划为Astro计划的三个主要功能的“Astro未来”系列的第3部分。这篇文章介绍了服务器岛：一个新的岛屿架构原型，让您提供静态的、CDN缓存的HTML页面外壳 动态内容。**

2021年，Astro开创了一种名为[Islands](https://docs.astro.build/en/concepts/islands/)的新前端架构。 孤岛是独一无二的，因为它们允许 Astro 自动从您的页面中删除所有未使用的 JavaScript，提供更快的性能，而不会迫使您在开发时放弃您喜爱的 UI 组件（React、Svelte、Vue 等）。

但前端性能并不是您在网络上遇到的唯一性能问题。 _如何_您向用户提供网站的影响力可能比您交付的内容更具影响力，开发人员经常被迫做出艰难的选择：性能还是个性化？

**性能：** 将页面作为静态 HTML，并积极缓存。 您将无法为用户个性化页面，但无法匹配静态 CDN 部署的性能优势、成本节约和简单性。

**个性化：** 将页面作为动态 HTML 提供，按需呈现。 这会迫使您通过可能位于世界半路的数据中心进行请求，这会降低性能并增加您失败 Google [Core Web Vitals](https://web.dev/articles/vitals) 的可能性。 但是，您通过动态响应解锁的控制和个性化水平可能很难拒绝。

**性能和个性化不应该相互排斥。

服务器岛
---------------

Server Islands 是我们正在探索 Astro 的一个新原型，建立在我们现有的岛屿前端架构上。 您定义一个服务器岛的方式与客户端岛相同，但不是使用 `client:*` 指令，而是使用 new `server:defer` 指令：

    <UserButton server:defer />

这告诉 Astro 在初始响应中跳过渲染此组件，并将其渲染“推迟”到以后。 这使您可以缓存具有一些初始占位符内容的 CDN 后面的静态页面。 加载动态 HTML 后，它会用延迟渲染的 HTML 结果替换页面上的服务器岛。

您可以在下面的原型中看到它运行。 静态页面会立即加载大部分页面内容（21ms，在本例中运行在 [Vercel](https://vercel.com/) 上）。 然后，动态延迟组件 HTML 将分别呈现，当延迟渲染完成时，Astro 将其全部重新拼接在一起。

从概念上讲，这类似于 React、Solid 等中 Suspense 的概念。但关键的区别是 Deferred Island 被呈现为单独的 HTTP 请求。 我们故意避免将静态内容_and_ 以单一的响应形式返回，以简化您选择的 CDN 的内容。

![A diagram showing the server island population parts of the page from the server.](/_astro/dark-mode-server-islands-diag.CCPm1I4W_1F1hFI.webp)

通过将所有动态 HTML 移至延迟服务器岛，您将拥有两全其美的优势：

*   **性能：** HTML的一个即时静态页面外壳，缓存在全局CDN中。
*   **个性化：**在页面上任意位置注入的动态内容。

服务器岛对于每个用例都没有意义。 某些页面可能需要如此多的动态内容，以至于在服务器上呈现整个页面仍然是有意义的。 其他网站可能仍希望从 API 端点获取动态内容作为 JSON。

然而，我们相信服务器岛对于内容驱动网站中的绝大多数个性化内容是有意义的。 我们看到使用 Astro 构建的网站通常会在页面上混合动态和静态内容。 对于这些目前无法利用 CDN 缓存的网站，服务器岛可能会带来巨大的性能胜利。

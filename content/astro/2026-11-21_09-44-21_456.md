Astro 4.3 现已上市！ 此版本包括一个新的实验性 i18n 功能，以及对您的构建输出、组件属性类型、Markdown 图像等的改进。

亮点包括：

*   **[Experimental: Add domain support for i18n](#experimental-add-domain-support-for-i18n)**
*   **[More control over your HTML file output](#more-control-over-your-html-file-output)**
*   **[添加 `ComponentProps` 类型实用程序](#add-componentprops-type-utility)**
*   **[Better support for relative images in Markdown](#fix-using-images-in-markdown-without-a-relative-specifier)**

如何升级
---------------

要利用最新功能，请确保您运行的是最新版本的 Astro。 您可以通过运行 `@astrojs/upgrade` 命令升级到 Astro 4.3：

npx @astrojs/升级

或者通过为您的包管理器运行升级命令：

npm install astro@latestpnpm 升级 astro --latestyarn 升级 astro --latest

实验性：为 i18n 添加域支持
----------------------------------------

Astro 4.3 添加了一个实验性的 `domains` i18n 配置。 这允许您为不同的受支持区域指定不同的域或子域。

例如，您现在可以将 `example.com` 用于您的英文网站，为您的法语网站使用 `fr.example.com`，为您的西班牙语网站使用 `example.es`。 启用实验标志 `i18nDomains` 并使用 `astro.config.mjs` 文件中的 `i18n.domains` 将您的任何或所有语言环境映射到域：

astro.config.mjs

从“astro/config”导入 {defineConfig}
导出默认的 defineConfig({ site: "https://example.com", 输出: "server", // 无预渲染页面适配器: node({ mode: 'standalone', }), i18n: { defaultLocale: 'en', locales: ['en', 'es', 'pt_br', 'pt', 'fr'], 域: { fr: "https://fr.example.com", es: "https://example.es" }, 路由: { prefixDefaultLocale: true, } }, experimental: { i18domains: true },})

请注意，此功能需要一个完全服务器渲染的站点，没有预渲染页面。 目前，`@astrojs/node` 和 `@astrojs/vercel` 适配器支持更多适配器兼容性！

有关此实验路由功能的更多详细信息和限制，请参阅我们的 [internationalization documentation](https://docs.astro.build/en/guides/internationalization/#domains-experimental) 中的更多信息。

对 HTML 文件输出进行更多控制
--------------------------------------

此版本添加了一个名为 `preserve` 的新 `build.format` 选项，使您可以更好地控制生产版本中生成的 HTML 文件。

当前的配置选项（`file` 和 `directory`）要么将所有 HTML 页面构建为与路由名称匹配的文件（例如 `/about.html`），要么将所有文件分别构建为 `index.html` 在嵌套的目录结构（例如 `/about/index.html`）中。 使用 `file` 配置选项时，无法创建单个索引页面（例如 `/about/index.html`）。

我们添加了新的 `preserve` 格式，而不是引入重大更改，它将保留文件系统的结构，并确保将其镜像到生产中：

*   `about.astro` 变为 `about.html`
*   `about/index.astro` 变为 `about/index.html`

你所看到的就是你得到的！ 此功能可与对文件的结构有严格要求的某些 Web 服务器解锁更好的兼容性。

有关详细信息，请参阅 [`build.format` 配置选项参考](https://docs.astro.build/en/reference/configuration-reference/#buildformat)。

添加 `ComponentProps` 类型实用程序
--------------------------------

Astro 现在包括一个新的 `ComponentProps` 类型的导出 `astro/types` 以获取 Astro 组件的道具类型。 这类似于 `React.ComponentProps` 或 Svelte 的 `ComponentProps`。

此类型导出允许您引用另一个组件接受的 `Props`，即使该组件没有直接导出 `Props` 类型。

---import type { componentprops } 来自 'Astro/Types';import 按钮来自 "./button.astro";
键入 myButtonProps = ComponentProps<typeof Button>;---

修复使用 Markdown 中没有相对说明符的图像
-----------------------------------------------------

以前，在 Markdown 中使用图像而不使用相对说明符（例如 `./` 或 `../`）会导致 Astro 抛出错误。

现在，您可以在 Markdown 文件中使用标准 `![](img.png)` 语法，用于位于同一文件夹中的图像：不需要相对说明符！

无需更新您的项目； 您现有的图像仍将继续工作。 但是，您可以安全地从这些 Markdown 图像中删除任何相对说明符，因为它们不再是必需的……正如 Markdown 规范所期望的那样！

![A cute dog](./dog.jpg) ![A cute dog](dog.jpg)<!-- 这只狗和我的文章住在同一个文件夹中！ -->

感谢 [Oliver Speir](https://github.com/OliverSpeir) 提供此修复程序！

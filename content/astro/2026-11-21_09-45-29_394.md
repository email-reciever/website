我们刚刚发布了 Astro 2.1，特色：

*   **[Built-in Image Support](#built-in-image-support)**：（实验）自动图像优化登陆 Astro Core。
*   **[Markdoc Integration](#markdoc-integration)**：（实验）来自 Stripe 的新内容格式，针对大型项目进行了优化。
*   **[`astro check --watch`](#astro-check-watch)**：在开发过程中使用此标志键入检查您的 `.astro` 文件。
*   **[Inferred types for dynamic routes](#inferred-types-for-dynamic-routes)**：在不定义类型两次的情况下获取参数和道具。

Astro 2.1 今天在 NPM 上提供。 运行 `npm i astro@latest` 升级现有项目或在终端中运行 `npm create astro` 以启动新事物。

内置图像支持
-----------------------

Astro 2.1 为 Astro 带来了内置图像优化的实验支持。 要在您的项目中启用它，请使用 `--experimental-assets` 标志运行 Astro 或在 Astro 配置文件中设置 `experimental.assets` 布尔标志。

如果您已经熟悉我们最初的 `@astrojs/image` 集成，Astro 的新内置 `<Image>` 组件应该会感到熟悉，但有一些显着的改进。 您现在可以使用 `width` 和 `height` 道具调整图像的大小，而无需更改其纵横比，并使用新的 `quality` 道具控制图像优化的水平。

---import { image } 来自 "~/assets/penguin.png"
    <Image src={penguin} quality="high" alt="a high-quality penguin" />

生成的图像将以现代 Web 格式自动为您优化，以获得最大的性能和最小的 [Cumulative Layout Shift (CLS)](https://web.dev/cls/)。

此外，可以将内置的映像支持换成另一个提供商，允许您将其连接到生产映像 CDN，如 [Cloudinary](https://cloudinary.com/) 或 [Vercel](https://vercel.com/) 之类的主机，以利用其图像优化服务。

Astro 2.1 还回答了原始 2.0 发布中最需要的功能之一：**内容集合中的图像处理。

import { image, defineCollection, z } 来自 "Astro:Content"
const blogCollection = defineCollection({ schema: z.object({ title: z.string(), cover: image(), }),})
导出常量集合 = { 博客：博客集合，}

如果您在 FrontMatter 中引用的图像不存在，Astro 会通知您。 您可以进一步优化架构以检查图像尺寸和文件扩展名等内容：

封面： image().refine((img) => img.width === 800 && img.height === 600, { 消息：“封面需要 800x600 像素！”，}）

要亲自尝试，请查看我们的新 [Assets Guide](https://docs.astro.build/en/guides/assets/) 中的迁移说明。 我们将继续修改和改进对图像的支持，直到该功能稳定并且在未来的主要版本中旗帜下降。 您可以通过评论 [Image RFC](https://github.com/withastro/roadmap/pull/500) 来贡献您的反馈。

MarkDoc 集成
--------------------

![The logo for the Markdoc project](/_astro/markdoc.Uek4AoYx_Z28RcB6.webp)

与 Astro 2.1 一起发布了一个新的实验 [Markdoc](https://markdoc.dev/) 集成。 您可以通过在项目目录中运行 `npx astro add markdoc` 将 `@astrojs/markdoc` 添加到您的项目中。

[Markdoc](https://markdoc.dev/) 是 [Stripe](https://stripe.com/) 在他们需要与其规模相匹配的东西时开发的一种有前途的新内容格式。 虽然我们仍然喜欢 MDX for Astro，但我们的用户在处理大量 MDX 文件时看到明显的减速并不少见。

作为我们自己调查的一部分，我们建立了一个性能基准，以将 Astro 内部的 MarkDoc 构建性能与我们现有的内容格式进行比较：Markdown 和 MDX。 这些测试显示了令人兴奋的改进，在 MDX 渲染静态内容和交互岛时 [up to 3x faster builds](https://github.com/withastro/roadmap/pull/508#issuecomment-1458762554)。

将 `@astrojs/markdoc` 集成添加到您的项目后，MarkDoc 将在 [Content Collections](https://docs.astro.build/en/guides/content-collections/) 中使用 `.mdoc` 文件扩展名独家提供。 您可以将 MarkDoc 文件与现有的 Markdown 和 MDX 文件混合使用，以实现顺利、逐步的迁移过程。

对 MDX 的支持不会消失。 我们正在尝试两种格式，因为我们感受到了 Astro 内容的未来。 当我们试图在灵活的语法和扩展到更大的站点之间找到适当的平衡时，我们会很高兴您的反馈。 特别是如果这是您第一次尝试 MarkDoc，请告诉我们您的想法 [in the ongoing Markdoc RFC.](https://github.com/withastro/roadmap/pull/508)

Astro Check –Watch
-------------------

![CLI output of the astro check --watch command, showing no errors and that it is waiting on file changes.](/_astro/astro-check-watch.BC7r7ALD_TpV4b.webp)

`astro check` 是一个内置的 Astro CLI 命令，用于对您的项目 `.astro` 文件运行 TypeScript 类型检查。 它通常用于在合并更改或部署站点之前捕获 CI 中的错误和类型错误。

我们从一些用户那里听说，他们想要同样的功能进行开发，类似于 TypeScript 中的 `tsc --watch`。 对于某些人来说，在编辑器中获取错误很容易错过，并且在推动更改之前很容易忘记手动运行 `astro check`。

在 Astro 2.1 中，`astro check` 命令中添加了一个新的 `--watch` 标志。 这将产生一个长时间运行的过程，用于监听更改的文件并重新运行诊断程序。 您可以通过向 `package.json` 中添加脚本与开发服务器并行运行它：

{ "脚本": { "dev": "astro check --watch & astro dev" }}

动态路由的推断类型
--------------------------------

Astro 页面中的 `getStaticPaths()` 导出用于定义应在 SSG 模式下为动态路由构建哪些页面。 对于每个页面，您都返回 `params` 和 `props` 属性。

在 Astro 2.1 中，我们添加了两个新的帮助器来推断这些类型，并在模板中使用这些值时提供类型检查。

给定以下 `getStaticPaths()` 功能：

src/pages/blog/\[slug\]].astro

---导出异步函数 getStaticPaths() { const posts = await getCollection("blog") return posts.map((post) => { return { params: { slug: post.slug }, props: { draft: post.data.draft，标题：post.data.title }, } })}---

您现在可以使用新的 `InferGetStaticParamsType` 和 `InferGetStaticPropsType` 辅助类型来获取 `params` 和 `props` 值的类型定义，而无需手动定义它们：

导入 { infergetStaticParamsType, InfergetStaticPropsType }
类型 params = infergetStaticParamsType<typeof getStaticPaths>type props = infergetStaticPropsType<typeof getStaticPaths>const { slug } = astro.params as params// ^? { slug：字符串； }const { 标题 } = astro.props// ^? { 草稿：布尔值； 标题：字符串； }

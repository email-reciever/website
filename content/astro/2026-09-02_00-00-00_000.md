Starlight 是 Astro 的官方软件包，用于构建快速、可访问的文档网站，其中包含您需要的所有功能。

今天，我们为您提供了一个谜语：一个 Starlight 版本如何包含更少的 JavaScript 和更多的 JavaScript？ 继续阅读以了解！

以下是议程上的内容：

*   [**Goodbye TypeScript, hello JavaScript**](#goodbye-typescript-hello-javascript)
*   [**Performance improvements**](#performance-improvements)

要升级现有的 Starlight 站点，请使用自动 `@astrojs/upgrade` CLI 工具。 这将更新 Starlight、Astro 和您正在使用的任何其他集成：

npx @astrojs/升级

请参阅 [Starlight CHANGELOG](https://github.com/withastro/starlight/blob/main/packages/starlight/CHANGELOG.md) 了解迁移指南和破坏性更改的全部详细信息。

再见打字稿，你好 Javascript
----------------------------------

Astro 项目的一个很酷的怪癖是您可以将 TypeScript 文件发布到 npm，并且在人们安装它们时可以正常工作。 这非常适合快速原型制作——无需找出构建步骤，只需发布您的源代码——这就是 Starlight 从一开始就发布的方式。

但是，分发 TypeScript 文件是有代价的。 使用 `tsc` 进行类型检查的用户可以输入检查您的代码的类型，因为 TypeScript 将检查它找到的任何导入的 `.ts` 文件，即使它在 `node_modules` 中。 他们会使用他们的打字稿配置进行类型检查，而不是您的。 在某些情况下，编辑器中的类型性能也会受到影响。 对于像星光这样的大型项目，这些问题加起来。

所以 Starlight v0.42 带来了 100% 的 JavaScript！ 我们现在编译我们的源文件，而不是 TypeScript，用户应该看到更快的类型检查。 （不过不用担心，普通的星光站点仍然会发货 [3–13× less JavaScript to end users than comparable tools](https://httparchive.org/reports/techreport/tech?median-weight-over-time=js&tech=Starlight,MkDocs,Sphinx,VitePress,Nextra,GitBook,Docusaurus&geo=ALL&rank=ALL&page=1#comparison-page-weight)。）

性能改进
-------------------------

我们一直在努力缩短构建时间。 最近的版本包括几个增量改进：

*   最新版本的 [Sätteri](https://satteri.bruits.org/) 使我们能够优化我们的一些组件和 Markdown 插件，并减少星光的依赖计数。
*   Sidebar 数据处理现在速度快 1,400 倍，这在侧边栏较大或深度嵌套的站点中尤其明显。

可访问性改进
---------------------------

从 0.41.3 版开始，Starlight 移动菜单会在打开时捕捉焦点，以防止用户在页面下方隐藏时进入页面。 这使得小或放大视口上的键盘导航体验不如[WCAG Success Criterion 2.4.11 Focus Not Obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)的要求那样混乱。

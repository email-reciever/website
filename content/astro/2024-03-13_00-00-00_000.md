**今天，我们推出了 [the Astro Developer Portal](https://portal.astro.build)，主题作者可以提交、管理和推广他们为 Astro 构建的主题。**

在 Astro，我们致力于打造解决方案，这些解决方案不仅有利于我们构建_With_Astro 的社区，还有利于建造 _for_ astro 的社区……同时应对我们自己构建 Astro 本身的内部挑战。 一种这样的解决方案是新的开发人员门户，它将成为所有社区 Astro 开发人员的未来之家。

我们在开发人员门户中的目标是提供一个集中式平台，主题作者和最终集成构建者可以完全控制他们在 Astro 的官方目录中管理他们的列表。 该门户的另一个目标是测试 Drive Astro Studio：帮助定义其功能、尽早识别错误并向我们的平台团队提供反馈。

今天，新的 Astro 开发者门户网站上线了！ 在 [portal.astro.build](https://portal.astro.build) 中查看它。

我们过去设置的问题
-----------------------------

将主题添加到 Astro 目录中的旧方法是一个非常耗时且效率低下的过程。 主题创作者需要填写一份表格，这触发了 Astro Core 团队的手动流程。 图像和内容必须从不和谐的消息中提取，格式化并集成到我们的主题内容集合目录中。 更新主题同样繁琐，需要主题作者手动存储库分叉和 PR 提交。

这显然不是最理想的处理方式。 如果我们有某种 Astro 数据库支持的系统就好了。 。 。

解
---------

在盘点了我们的问题和挑战之后，列出了主题作者和 Astro Core 团队的所有痛点，我们勾勒出我们想要的系统。 我们提出的是一个数字门户，主题创作者可以在其中上传、更新和管理他们的主题。 我们设想了一个核心成员只需介入一次，批准一个新主题的东西，现在只需单击按钮即可。 使用 [Astro Studio](https://studio.astro.build) 和 [Astro DB](https://astro.build/db/)，我们将能够使用 Astro Web 应用程序处理整个过程，从而消除对现有手动步骤（如创建 PR 和自己管理内容）的需求。

狗食星太空工作室
------------------------

还有什么比使用您正在构建的工具来构建您正在构建的工具更强大的呢？ 这是早期识别错误和问题并测试工具极限的好方法。 与 Astro Studio 的建设正式开始。

特别是，我们有许多自己的 Astro 用户共享的两个功能要求：身份验证和图像存储。 有几个流行的选项可以很好地与 Astro 项目配合使用，但这是使用 Astro Studio 试驾它们的第一次机会。

为了原型验证，我们首先使用 Supabase 构建了一个概念验证，利用它的 OAuth 和 GitHub 进行简化访问。 然而，我们意识到利用 Astro Studio 的力量并过渡到 [Lucia](https://lucia-auth.com/) 的统一解决方案的好处。 无论您自己项目的身份验证需求是什么，我们都相信您会找到适合您的 Astro Studio 兼容解决方案！

对于图像存储，我们使用 Google Cloud 设置了一个非常简单的云存储存储桶，无需任何人工干预即可处理所有存储和图像处理。 事实证明，这足以满足我们处理主题屏幕截图和缩略图的需求，再次展示了 Astro 驱动的应用程序和数据库的强大功能。

接下来是什么
------------

展望未来，要增强开发人员门户体验还有很多工作要做。 我们的重点仍然是完善平台和整合用户反馈。 虽然我们有令人兴奋的想法在筹备中，但我们的主要目标是继续 Dogfooding Astro Studio，为使用 Astro Studio 的 Astro 开发人员提供最佳体验。

加入我们的旅程，我们努力使主题创建和管理过程更顺畅、更愉快，最终扩展到集成和 . 。 。 谁知道还有什么？ 天空是你可以建造的东西的极限，_for_，Astro！

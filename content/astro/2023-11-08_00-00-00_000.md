i18n 路由（实验）
----------------------------

现在，使用 Astro 构建多语言应用程序比以往任何时候都更容易。

Astro 的实验性 i18n 路由 API 允许您添加多语言内容，支持配置默认语言、计算相对页面 URL 以及接受访问者浏览器提供的首选语言。 您还可以在每种语言的基础上指定后备语言，以便您的访问者始终可以将其定向到您网站上的现有内容。

通过将 `i18n` 对象添加到具有默认位置和支持所有语言的列表的 Astro 配置，启用实验路由选项：

astro.config.mjs

从“astro/config”导入 {defineConfig}；
导出默认值 defineConfig({ experimental: { i18n: { defaultLocale: "en", locales: ["en", "es", "pt-br"] } }})

根据您的 `i18n.routingStrategy` 按地区组织您的内容文件夹，Astro 将处理生成您的路由并将您的首选 URL 显示给访问者。

├── src── ├── 页── ─ ├──关于.astro ────────── index.astro── ├── es── ─ ─ ├── About.Astro ─────────────────── index.astro── ├── PT-BR─. │ ─ ├── About.Astro ── ── ├── index.astro

计算新 `astro:i18n` 模块中 `getLocaleRelativeURL` 的链接的相对 URL：

---import {getRelativeLocaleurl} 来自 "Astro:i18n";const aboutUrl = getRelativeLocaleurl("pt-br", "about");---<p>了解更多 <a href={aboutUrl}>about</a> 这个网站！</p>

启用 i18n 路由还为浏览器语言检测提供了两个新属性：`Astro.preferredLocale` 和 `Astro.preferredLocaleList`。 这些结合了浏览器的 `Accept-Language` 标头和您网站的受支持语言列表，可用于自动尊重访问者的首选语言。

在我们的文档中阅读有关 Astro [experimental i18n routing](https://docs.astro.build/en/guides/internationalization/) 的更多信息。

预取
---------

[Prefetch](https://developer.mozilla.org/en-US/docs/Glossary/Prefetch) 是一种浏览器功能，可为访问者提前获取页面，以便它们甚至在导航之前就被部分加载。 对于多页应用程序，预取是保持网站快速的重要组成部分。

Astro 中的 Prefetch 以前可以通过官方集成 (`@astrojs/prefetch`) 获得。 今天，我们将预取作为一个选择加入功能，并扩展它的功能。

您可以通过在 Astro Config 中设置 `prefetch:true` 来启用预取：

astro.config.js

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ 预取：true})

除了现在是核心功能外，新的预取还具有更大的灵活性：

*   配置是否在 `tap` 上进行预取（不是完全点击的触摸），`hover`，还是在进入 `viewport` 时进行。
*   使用 `data-astro-prefetch` 属性定义在每个链接的基础上使用哪种策略。
*   默认设置在_all links_上的预取（使用`<ViewTransitions />`时的现有行为）。
*   忽略快速发生的悬停和滚动事件，以防止访问者无法点击的内容过多。

默认情况下，使用 [View Transitions](https://docs.astro.build/en/guides/view-transitions/) 时启用了预取功能，新的实现现在可以在每个链接的基础上选择退出预取：

<a href="/logout" data-astro-prefetch="false">退出</a>

访问 [Prefetch guide](https://docs.astro.build/en/guides/prefetch/) 了解更多信息。

内容集合构建缓存（实验）
-------------------------------------------

大量使用 [Content Collections](https://docs.astro.build/en/guides/content-collections/) 的大型静态站点可以尝试新的实验性构建缓存。

这包括对 Astro 构建过程的多次重构，以优化内容集合的处理方式，这应该为具有许多集合的用户提供显着的性能改进。

构建 `static` 站点的用户可以通过向 Astro 配置添加以下标志来选择预览新的构建缓存：

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ 实验性: { contentCollectionCache: true, },})

启用此实验功能后，从您的内容集合生成的文件将存储在 [`cacheDir`](https://docs.astro.build/en/reference/configuration-reference/#cachedir) 中，并在构建之间重复使用。 默认情况下，大多数 CI 环境会自动恢复 `node_modules/` 中的文件。

在我们对现实世界 [Astro Docs](https://github.com/withastro/docs) 项目的内部测试中，此功能将 `astro build` 的捆绑步骤从 **133.20s** 减少到 **10.46s**，大约 **92% 的速度**。 端到端 `astro build` 过程用于花费 **4mins 58s**，现在需要 **60s**，总减少 80%。

如果您遇到此实验功能的任何问题，请告诉我们！

您可以通过将 `--force` 标志传递给 `astro build` 来绕过单个构建的缓存。

astro 构建 --force

视图转换中的表单支持
--------------------------------

`<ViewTransitions />` 路由器现在可以处理表单提交，允许在 `<a>` 链接上已经可用的表单帖子上具有相同的动画转换和有状态的 UI 保留。 通过此添加，您的 Astro 项目可以在所有这些场景中使用动画：

*   点击页面之间的链接。
*   在表单中进行有状态的更改（例如更新站点首选项）。
*   通过 `navigate()` API 手动触发导航。

此功能目前已选择加入，但默认情况下将在 Astro 4.0 中启用。 要启用，请将 `handleForms` 道具添加到页面上的 `<ViewTransitions />` 组件：

src/layouts/mainlayout.astro

---import { viewTransitions } 来自 'astro:transitions';---
<html> <head> <!-- ... --> <ViewTransitions handleForms /> <ViewTransitions handleForms /> </head> <body> <!-- ... --> </body></html>

与链接一样，如果您不希望路由处理表单提交，您可以使用 `data-astro-reload` 属性在按表单的基础上选择退出：

src/components/contact.astro

<form class="contact-form" action="/request" method="post" data-astro-reload> <!-- ...--></form>

表单支持适用于邮政 `method="get"` 和 `method="post"` 表格。

图像优化改进
------------------------------

Astro Assets 继续进行改进，在 3.5 中，我们现在拥有：

*   从未在优化管道之外使用的最终构建中删除原始图像。 对于拥有大量这些图像（例如缩略图）的用户，这应该减少存储消耗和部署时间。
*   添加了一个新的属性，`propertiesToHash`，允许指定在进行本地转换时应该使用 `getImage()` / `<Image />` / `<Picture />` 的哪些属性来散列结果文件。 对于大多数服务，这将包括直接更改生成图像内容的 `src`、`width` 或 `quality` 等属性。
*   当原始图像采用这些格式时，`<Picture />` 组件现在将分别使用 `jpg` 和 `jpeg` 作为回退格式。

集成挂钩添加中间件
---------------------------------

现在，Astro 中的集成可以代表用户添加中间件。 以前，当第三方想要提供中间件时，用户需要自己创建一个 `src/middleware.ts` 文件。 现在，添加第三方中间件就像添加新集成一样简单。

对于集成作者，`astro:config:setup` 钩子中有一个新的 `addMiddleware` 函数。 此函数允许您指定中间件模块及其应用顺序：

my-package/middleware.js

从“astro:middleware”导入 { definiMiddleware }；
导出 const onRequest = defineMiddleware(异步(上下文) => { const response = await next();
if(response.headers.get('content-type') === 'text/html') { 让 html = await 响应.text(); html = minify(html); 返回新的响应（html，{状态：response.status，标题：response.headers }）； }
返回响应;});

您现在可以添加集成的中间件并指定它在应用程序自己定义的中间件之前或之后运行（在 `src/middleware.{js,ts}` 中定义）

my-package/integration.js

导出函数 myIntegration() { return { name: 'my-integration', hooks: { 'astro:config:setup': ({ addMiddleware }) => { addMiddleware({ entrypoint: 'my-package/middleware', order: 'pre' }); } } };}

多个代码主题（实验）
---------------------------------

Astro 最近升级使用 [shikiji](https://github.com/antfu/shikiji) 库进行语法突出显示，我们现在添加了通过新的 `markdown.shikiConfig.experimentalThemes` 选项支持多个主题的功能。

这使您能够更轻松地为语法突出显示的代码块定义明暗模式主题。 你可以像这样使用它：

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认的 defineConfig({ markdown: { shikiconfig: { 实验主题：{ light: 'github-light', dark: 'github-dark' } } }});

Qwik 集成
-----------------

从我们的社区中，现在有一个用于将 [Qwik](https://qwik.builder.io/) 与 Astro 一起使用的 Astro 集成！ 您可以通过以下方式安装 Qwik 集成：

npx astro 添加 @qwikdev/astro

或者您可以自己安装集成，并更新您的配置：

astro.config.mjs

从“astro/config”导入 { defineconfig }；从 '@qwikdev/astro' 导入 qwikdev；
导出默认 defineConfig({ 集成：[QwikDev()],});

查看 [blog post](https://www.builder.io/blog/astro-qwik) 以了解有关新集成的更多信息，如果遇到任何问题，请访问 [integration repository](https://github.com/QwikDev/astro/issues)。

**Astro 7.1 在这里！** 此版本旨在为您提供更多控制权：与新的 `--ignore-lock` 标志并排运行多个开发服务器，以及形状分页 URL 以匹配您实际部署站点的方式，并在 `paginate()` 上使用 `format` 函数。 它还为更细粒度的脚本和样式策略添加了新的 CSP 指令，降低了大型内容集合的内存使用量，以及块状内容存储的实验方法。

探索此版本中的新功能：

*   **[Finer-grained CSP control for inline scripts and styles](#finer-grained-csp-control-for-inline-scripts-and-styles)**
*   **[Full control over pagination URLs](#full-control-over-pagination-urls)**
*   **[Run multiple dev servers at once](#run-multiple-dev-servers-at-once)**
*   **[Lower memory usage for large content collections](#lower-memory-usage-for-large-content-collections)**
*   **[Experimental content storage](#experimental-content-storage)**
*   **[Community](#community)**

用于内联脚本和样式的更细粒度的 CSP 控件
---------------------------------------------------

Astro CSP 现在内置了对以下指令的支持，让您可以更好地控制资源：

*   [script-src-elem](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src-elem)
*   [script-src-attr](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src-attr)
*   [style-src-elem](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/style-src-elem)
*   [style-src-attr](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/style-src-attr)

这些资源是 `script-src` 和 `style-src` 对应物的专业版本，它们将允许您解决以前无法解决的问题。

例如，您现在可以接受内联样式为不安全的，而不会放弃外部 CSS 文件的安全性：

astro.config.mjs

从“astro/config”导入 { defineConfig }
导出默认的 defineConfig({ security: { csp: { styledirective: { 资源：[{ 资源："'unsafe-line'", 种类: "attribute" }] } }})

要了解有关新配置和 API 的更多信息，请参阅 [the runtime docs](https://docs.astro.build/en/reference/api-reference/#csp) 和 [configuration docs](https://docs.astro.build/en/reference/configuration-reference/#securitycsp)。

完全控制分页网址
--------------------------------

`paginate()` 生成的分页 URL 并不总是与您实际部署站点的方式相匹配。 例如，如果您构建静态 `.html` 文件 (`build: { format: 'file' }`) 并部署到没有 url 重写规则的主机，则返回的 `next`/`prev`/`first`/`last` url 是像 `/blog/2` 这样的干净路径，与磁盘上的任何文件都不对应。

您现在可以完全控制这些 URL，并在 `paginate()` 上使用新的 `format` 功能。 它接收每个生成的 URL 作为字符串，并允许您随心所欲地转换它，例如附加 `.html`：

一次运行多个开发服务器
--------------------------------

有时您需要第二台开发服务器而不放弃您已经运行的服务器。 例如，您正在调试某些内容，并希望使用详细日志记录暂时启动另一个实例，同时保持常规开发服务器（及其状态）。

Astro 7 引入了一个 Lockfile，这样 AI 编码代理就不会为同一项目不小心启动重复的开发服务器。 作为一个副作用，运行 `astro dev` 而另一个实例已经处于活动状态时，即使您是故意启动的也会出错。

Astro 7.1 带回了一个新的 `--ignore-lock` 标志，可以跳过 lockfile 检查，从而使该工作流恢复，因此您可以为同一个项目启动任意数量的开发服务器：

astro dev --ignore-lock

实例以 `--ignore-lock` 独立于其他运行，这意味着 `astro dev stop`、`astro dev status` 和 `astro dev logs` 不会知道它。 对于像这样的情况，您只需要一台快速、一次性的第二台服务器，而不是另一个您将长期管理的服务器。

大内容集合的内存使用率更低
--------------------------------------------

`glob()` 加载器在同步您的内容集合后立即呈现您的 Markdown 条目，并缓存呈现的 HTML，因此它不必在下一次构建中再次执行该操作。 对于大多数网站来说，这是一个很好的交易：同步有点贵，但重建速度很快。

随着收藏的增长或渲染产生的产出比其来源降价更多，这种交易变得更加昂贵。 在同步期间将所有渲染的 HTML 缓存起来。

您现在可以使用 `deferRender` 选项从急切渲染中选择单个集合：

src/content.config.ts

从“astro:content”中导入 { defineCollection }；从“astro/loaders”导入 { glob }；
const docs = defineCollection({ loader: glob({ pattern: '**/*.md', base: 'src/content/docs', deferrender: true }),});

在 `deferRender: true` 中，条目在同步过程中不渲染而存储。 当页面实际需要时，渲染会在以后按需进行，就像 `.mdx` 文件一直有效一样。 您放弃了跨版本的缓存渲染的 HTML，但对于大型、繁重的集合，这是在同步期间降低内存使用量的值得的交易。

记录器改进
--------------------

自定义记录器现在可以与您可能使用的其他 API（例如字体或会话）进行配置。 传递 URL 可以在运行时覆盖配置或使用 Vite 的内置功能：

astro.config.mjs

从“astro/config”导出默认定义配置（{ logger: { entrypoint: new url()”./src/custom-logger.js, import.meta.url) }}）

此外，您可以使用 `AstroRuntimeLogger`。 这是一个有用的类型，您可以在使用运行时Astro Logger的文件中使用：

src/utils/requestHandler.ts

从“Astro”导入类型 { AstroRuntimeLogger }；
导出函数 handleRequest(req: request, astrologger: AstroRuntimeLogger) { astrologger.info("incoming request");}

实验内容存储
-----------------------------

从历史上看，内容集合将其数据保存到一个名为`.astro/data-store.json`的反序列化文件中。 但是，对于拥有大量内容集合的用户来说，这可能是一个问题，因为有些平台会对文件的大小施加限制。

Astro 现在有一个名为 `experimental.collectionStorage` 的实验标志，允许您将数据分成多个文件：

astro.config.mjs

从“astro/config”导入 { defineConfig }
导出默认 defineConfig({ 实验性: { 集合存储："分块" }})

选择 `"chunked"` 时，Astro 每 10MB 会拆分内容收集数据。

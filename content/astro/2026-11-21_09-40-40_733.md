预渲染路线碰撞警告
----------------------------------

Astro 5.14 可以更容易地发现和修复动态路由中的常见错误，以免导致生产中出现问题。

以前，当 `/blog/[slug]` 和 `/blog/[...all]` 等两个动态路由尝试预渲染相同的路径（例如 `/blog/post-1` ）时，Astro 仅针对冲突路径渲染了 [highest priority route](https://docs.astro.build/en/guides/routing/#route-priority-order)，而另一个将被静默忽略。 这允许您的网站成功构建，尽管您可能已经发现某些页面是通过意外路由呈现的。

现在，当发生这种情况时，将显示一个警告，说明哪些路由发生碰撞以及在哪条路径上。

此外，在发生此类冲突时，可以使用新的实验标志 `failOnPrerenderConflict` 使构建失败，并出现有用的错误。 在 Astro 配置中为“休斯顿的帮助之手”设置以下标志，以强制您明确解决任何路由冲突：

astro.config.mjs

导出默认 defineConfig({ 实验性：{ failonPrerenderConflict: true, },});

在 [experimental prerender conflict error](https://docs.astro.build/en/reference/experimental-flags/fail-on-prerender-conflict/) 文档中查看更多信息。

`routePattern` 在 `getStaticPaths`
---------------------------------

Astro 5.14 使 `getStaticPaths()` 中的复杂动态路由更容易工作。

现在在 `getStaticPaths` 上下文中提供了一个新的 `routePattern` 属性。 这提供了来自 Astro 渲染上下文的路由文件路径（例如 `/[...locale]/[files]/[slug]`）中的原始动态段定义，这些上下文在 `getStaticPaths()` 的范围内是不可用的。 这对于计算每个页面路由的 `params` 和 `props` 很有用。

例如，您现在可以通过将 `routePattern` 传递给自定义 `getLocalizedData()` 辅助函数来本地化路由段并返回静态路径数组。 `params` 对象将设置每个路由段的显式值（例如 `locale`、`files` 和 `slug`）。 然后，这些值将用于生成路由，并可通过 `Astro.params` 在您的页面模板中使用。

src/pages/\[...locale\]/\[文件\]/\[slug\]].astro

---import { getLocalizedData } from "../../../utils/i18n";导出异步函数 getStaticPaths({ routePattern }) { const response = await fetch('...'); 常量数据 = 等待 response.json(); console.log(路由模式); // [...locale]/[files]/[slug] // 使用 `routePattern` 调用您的自定义助手以生成静态路径 return data.flatmap((file) => getLocalizedData(file, routePattern));}const { locale, files, slug } = astro.params;---

有关此高级路由模式的更多信息，请参阅 Astro 的 [routing reference](https://docs.astro.build/en/reference/routing-reference/#routepattern)。

感谢 [Robin Bühler](https://github.com/openscript) 贡献此功能！

Svelte的异步渲染支持
---------------------------------

此版本增加了对 Svelte 的异步渲染功能的支持。

svelte 5.36 添加了对异步渲染的实验性支持，允许您在多个新位置中使用 `await` 组件。 这已经在客户端渲染的组件中开箱即用，但服务器渲染组件需要一些额外的帮助。 此更新增加了对 Astro 中使用的 Svelte 组件中的异步服务器渲染的支持。

要使用异步渲染，您必须在 svelte 配置中启用它：

svelte.config.js

导出默认 { 编译器：{ 实验性： { 异步：true, }, },};

然后你可以在你的svelte组件中使用`await`：

src/组件/mysveltecomponent.svelte

<script> 让数据 = 等待 fetch('/api/data').then(res => res.json());</script><h1>{data.title}</h1>

有关在 Svelte 组件中使用 `await` 的更多信息，请参阅 [the Svelte docs](https://svelte.dev/docs/svelte/await-expressions)，包括 `$derived` 块内和直接在标记中。

React 19 动作集成
-----------------------------

React 19 引入了 [`useActionState()`](https://react.dev/reference/react/useActionState)，它允许您根据表单操作的结果更新状态。

新稳定的 `getActionState()` 和 `withState()` 函数将 Astro Actions 与 `useActionState()` 集成在一起，从而可以轻松构建使用 React 和 Astro 操作逐步增强的表单。

此示例调用接受 `postId` 并返回点赞数的 `like` 操作。 将此操作传递给 `withState()` 函数以应用渐进增强信息，并应用于 `useActionState()` 以跟踪结果：

import { actions } from 'astro:actions';从'@astrojs/react/actions' import { withState };从'react'import { useActionState };
导出函数 like({ postID }: { postID: string }) { const [state, action, pending] = useActionState( withState(actions.like), 0, // initial likes );
返回 (<form action={action}> <input type="hidden" name="postId" value={postId} /> <button disabled={pending}>{状态} ❤️</button> </form> );}

您还可以从操作处理程序访问 `useActionState()` 存储的状态。 使用 API 上下文调用 `getActionState()`，并可选地将类型应用于结果：

从“astro:actions”中导入 { defineAction }；从 'astro/zod' 导入 { z }；从 '@astrojs/react/actions' 导入 { getActionState }；
export const server = { like: defineAction({ input: z.Object({ postID: z.string(), }), handler: async ({ postid }, ctx) => { const CurrentLikes = getActionState<number>(ctx); // 写入数据库返回 CurrentLikes + 1; }, }),};

如果您以前使用此功能的实验版本，则需要更新代码以使用新的稳定导出：

import { experiment_getActionState, Experimental_WithState } 来自 '@astrojs/react/actions';import { getActionState, withState } from '@astrojs/react/actions';

有关将 React 19 与 Astro Actions 结合使用的更多信息，请参阅 [the React integration guide](https://docs.astro.build/en/guides/integrations-guide/react/#integrate-actions-with-useactionstate)。

SVG 组件类型
------------------

Astro 现在为 SVG 导入导出内置的 `SvgComponent` 类型。 在 Astro 组件中导入 SVG 文件时，它将被视为您可以在标记中使用的组件。 到目前为止，获得 SVG 组件的类型有点尴尬。 您现在可以直接从 `astro/types` 导入 `SvgComponent` ：

类型 svgcomponent = typeof import("*.svg")导入类型 { svgcomponent } 来自 "Astro/Types"

有关在 Astro 中使用 SVG 的更多信息，请参阅 [the SVG docs](https://docs.astro.build/en/guides/images/#svg-components)。

感谢 [ADTC](https://github.com/ADTC) 为这一改进做出了贡献！

non-node.js libsql支持Astro DB
--------------------------------------

部署到 Cloudflare 和其他非 Node.js 环境时，Astro DB 现在支持 libsql。

此版本添加了一个在基于 Web 的运行时（如 Cloudflare Workerd 和 Deno）中运行的新的 libsql `web` 驱动程序。 新的 `mode` 配置选项允许您设置客户端连接类型：`node`（默认）或 `web`。

默认的 DB `node` 驱动程序模式与以前完全相同，因此现有站点不需要任何更新。 但是，如果您以前因为需要非node.js libsql客户端而无法使用Astro DB，现在可以通过在`db`配置中设置`mode: 'web'`来安装和配置LibSQL Web驱动程序：

从 '@astrojs/db' 导入 db;从 'astro/config' 导入 { defineconfig };
// https://astro.build/configexport default defineConfig({ 积分：[db({ mode: 'web' })],});

有关详细信息，请参阅 [`@astrojs/db` 文档](https://docs.astro.build/en/guides/integrations-guide/db/#mode)。

感谢 [Adam Matthiesen](https://github.com/Adammatthiesen) 为 Astro DB 集成贡献了此功能以及更多内容！

站点地图命名空间配置
--------------------------------

默认情况下，Sitemap 标准包含几个 XML 命名空间，这些命名空间可能不是所有站点所必需的。 从 Astro 5.14 开始，您现在可以配置要包含在 Sitemap XML 中的命名空间。 不包括未使用的命名空间可以帮助创建更干净、更集中的站点地图，这些站点地图可以更快地解析和使用更少的带宽。 如果您的网站没有新闻内容、视频或多种语言，您可以排除这些命名空间以减少 XML 膨胀。

`namespaces` 选项允许您独立配置 `news`、`xhtml`、`image` 和 `video` 命名空间。 默认情况下启用所有命名空间以实现向后兼容性，无需更改现有项目。 但是现在，您可以选择简化 XML 并避免不必要的代码。

例如，要从站点地图中排除视频命名空间，请在配置中设置 `video: false`：

astro.config.mjs

从 '@astrojs/sitemap' 导入 { 站点地图 }；
export default { integrations: [ sitemap({ namespaces: { video: false, // 默认情况下保持启用其他命名空间 }, }), ],};

生成的 XML 将不包括 `xmlns:video` 命名空间。

感谢 [Julián Colombo](https://github.com/jdcolombo) 贡献此功能！

`getFontData` 用于编程字体访问
----------------------------------------

从“astro:assets”导入 { getFontData }；

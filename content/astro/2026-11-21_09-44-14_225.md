开发审计用户界面
-------------

一些 Web 性能和可访问性问题只能在浏览器中捕获。 测试这些问题可能既麻烦又慢，许多开发人员最终完全跳过或忘记了。

Astro 正在通过全新的 Dev 审计 UI 弥合功能和便利性之间的差距。 在一个新的、有条理的 UI 面板中可视化和导航审核。 按类别浏览问题并单击以查看更多详细信息，所有这些都来自您的开发浏览器，并与页面上的实际 UI 元素保持一致。

![The new audit panel in Astro 4.5. Shows the problem title, a short message explaining the problem, and a longer description as to why this is a problem.](/_astro/audit-panel.CHzLLfxh_2sDj5h.webp)

这在尝试理解页面上的某些内容被标记为问题时特别有用。 单击任何问题，您将立即滚动到页面上的该元素。 此外，每个项目都带有解释器和详细的指导。

新的开发审计 UI 首次在 [Astro 4.4](https://astro.build/blog/astro-440/#audit-list) 中进行了预览。 感谢所有在此版本之前测试和提供反馈的人！

查看过渡：重新渲染岛屿
---------------------------------

当使用视图转换时，[Astro Islands 使用 `transition:persist` 属性](https://docs.astro.build/en/guides/view-transitions/#maintaining-state) 现在可以在页面更改时使用新的道具进行更新。

这对于产品列表可能很有用，您可能希望用户设置的过滤器在页面更改之间保持不变，但要根据当前页面更新的产品列表。 以前，您必须构建组件以手动更新产品列表。 在此更新之后，当页面更改时，组件现在将自动重新渲染新的道具，同时保持相同的状态。

此功能不需要任何配置，默认启用。 如果需要，`transition:persist-props` 属性可用于选择退出此行为。

查看过渡：重新运行脚本
--------------------------------

使用视图转换时，一个常见的惊喜是，当页面更改时，内联脚本不会自动重新运行。 这导致我们每天多次链接到 [our documentation on script behavior during page navigation](https://docs.astro.build/en/guides/view-transitions/#script-behavior-with-view-transitions)。

为了让我们的用户更轻松，Astro 4.5 现在包含一个 `data-astro-rerun` 属性，该属性可以添加到内联的脚本标记中，以便在页面更改时自动重新运行脚本：

<script data-astro-rerun is:inline> console.log('此脚本将在页面更改时重新运行!');</script>

石基 1.0
----------

在之前的版本中，我们将 Astro 的语法高亮迁移到使用一个名为 [Shikiji](https://github.com/antfu/shikiji) 的 [Shiki](https://shiki.style/) 分叉。 Shikiji 最近被合并回 Shiki。 因此，我们也将回到 Shiki！

此更改对用户应该是完全透明的，并且不需要对您的代码进行任何更改。 但是，Astro 4.5 还具有语法突出显示的其他几个好处，包括：

*   `markdown.shikiConfig.experimentalThemes`选项也稳定为`markdown.shikiConfig.themes`，允许更容易的双主题支持。
*    [`<Code />` 组件](https://docs.astro.build/en/reference/api-reference/#code-) 现在接受将传递到内部 `pre` 或 `code` 元素的任意属性名称。 在渲染代码块时，这允许更容易的样式和灵活性。 感谢 [StandardGage](https://github.com/StandardGage) 提供此功能。

多 CDN 资产前缀
--------------------------

Astro 4.5 引入了为不同文件扩展名指定不同 CDN 前缀的功能。 当您希望为来自不同 CDN 的不同类型的资产提供服务时，这可能很有用，例如，使用优化的缓存策略从单独的 CDN 提供图像。

要使用此功能，请将 `build.assetsPrefix` 选项添加到 `astro.config.mjs`，文件扩展名作为键，CDN 前缀作为值：

astro.config.mjs

从“astro/config”导入 { defineConfig }
导出默认的 defineConfig({ build: { assetPrefix: { 'js': "https://js.cdn.example.com", 'png': "https://images.cdn.example.com", 'fallback': "https://generic.cdn.example.com" } }})

感谢 [Zhang Zhipeng](https://github.com/peng) 提供此功能。 有关 `build.assetsPrefix` 的更多信息，请参阅我们的 [configuration reference](https://docs.astro.build/en/reference/configuration-reference/#buildassetsprefix)。

实验：数据收集的 JSON 模式
--------------------------------------------

Astro 4.5 引入了对数据收集自动生成 [JSON schemas](https://json-schema.org/) 的实验性支持。 JSON 模式是描述数据形状的一种强大方式，可用于直接在编辑器中为数据集合提供验证、自动完成和文档。 要启用此功能，请将以下内容添加到 `astro.config.mjs` 中：

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ 实验性：{ contentCollectionJsonSchema: true }});

目前，这些模式需要手动链接到您的数据收集条目，但我们希望在未来的版本中使此过程自动。 有关如何使用此功能的更多详细信息，请参阅 [the documentation for this experimental flag](https://docs.astro.build/en/reference/configuration-reference/#experimentalcontentcollectionjsonschema)。

实验：新的脚本检测算法
------------------------------------------

在 Astro 2.10.4 中，添加了一个名为 `optimizeHoistedScript` 的实验性选项来帮助解决一个旧的问题，即尽管未使用，脚本仍可以包含在页面中。 在 Astro 4.5 中，我们将 `optimizeHoistedScript` 替换为名为 `directRenderScript` 的新实验选项，该选项现在应该涵盖所有情况且更可靠。

要尝试此新功能，请删除 `optimizeHoistedScript` 选项，并将 `directRenderScript` 选项添加到 `astro.config.mjs` 中：

astro.config.mjs

从“astro/config”导入 { defineconfig }；
export default defineConfig({  experimental: {    optimizeHoistedScript: true,    directRenderScript: true  }});

我们希望在未来的主要版本中将此功能设置为默认值。 有关此功能的更多信息，请参阅我们的 [configuration reference](https://docs.astro.build/en/reference/configuration-reference/#experimentaldirectrenderscript)。

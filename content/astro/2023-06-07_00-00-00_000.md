去年，我们与[Astro 1.0](https://astro.build/blog/astro-1)一起发布了第一个Astro Image集成([@astrojs/image](https://docs.astro.build/en/guides/integrations-guide/image/))。 目标很简单：**在 Astro 中使图像优化变得轻松。**

现在，1 年和 250 万次下载后，我们准备分享我们在 Astro 中使用图像的新愿景：完全重新设计，具有新功能、更快的性能和更好的最终用户体验：

*   [Automatic layout shift (CLS) prevention](#automatic-layout-shift-prevention)。
*   [First-class Markdown, Markdoc & MDX support](#automatic-markdown--mdx-support)。
*   [Integration with third-party services](#integrating-with-third-party-image-services)。

此新更新将适用于所有从 Astro 3.0 开始的用户，但您可以通过在配置文件中设置 `experimental.assets` 标志选择加入。 您还可以通过将 `--experimental-assets` 标志传递给 Astro CLI 来启用。

astro.config.mjs

从“astro/config”导入 { defineConfig }
导出默认 defineConfig({ 实验性: { assets: true },})

在这篇文章中，我们将介绍一些新功能和改进，这些功能将使 Astro 中的图像工作变得更加容易。 如果您更喜欢直接进入文档，请阅读我们的 [Assets](https://docs.astro.build/en/guides/assets/) 指南了解所有详细信息。

这个怎么运作
-------------

从一开始，我们就知道我们想要一个尽可能最小的图像 API。 我们从 `@astrojs/image` 集成中的原始 `<Image />` 组件 API 开始，然后在其上构建了一些新的调整和更改。

---// 导入 <Image /> ComponentImport { image } 从 "astro:assets"// 导入对图像本身的引用 import myImage 从 "../assets/penguin.png"---
    <Image src={myImage} alt="A very cool penguin!" />

<!-- 结果：--><img  src="/_astro/penguin.XXXXXX.webp"  width="300"  height="300"  loading="lazy"  decoding="async"  alt="A very cool penguin!"/>

但不要让最小的 API 欺骗您：

*   ASTRO 使用现代 [WebP](https://developers.google.com/speed/webp) 文件格式（默认情况下）优化您的图像。
*   为了可访问性，所需的 `alt` 道具有助于改善您的网站阅读器和其他工具。
*   为了更快的页面加载性能，`loading` 和 `decoding` 属性被添加为默认值。
*   对于用户体验，始终包含 `width` 和 `height` 属性以防止布局偏移（稍后将详细介绍）。

灵活性是另一个目标。 我们添加了 [`getImage()`](https://docs.astro.build/en/guides/assets/#getimage-astroassets) 函数来按需优化项目中的图像，而不使用 `<Image />` 组件。 使用此函数为您想到的任何用例构建您自己的自定义图像组件。

---// 示例：使用 css.import { getimage } 将优化图像应用到 div 中，而不是创建 `img` 标签，而不是创建 `img` 标签 优化后台图像 = await getImage({ src: myImage })---
    <div style={`background-image: url('${optimizedBackgroundImage.src}')`}></div>

自动布局移位防止
--------------------------------

[Cumulative Layout Shift (CLS)](https://web.dev/cls/) 是优化网站性能的基本指标。 它被跟踪为 Google 的 3 [Core Web Vitals](https://web.dev/vitals/) 之一，并且在 [Lighthouse](https://developer.chrome.com/docs/lighthouse/overview/) 性能评分中占有重要地位。

**ASTRO 的新 `<Image />` 组件自动保护您的站点免受布局偏移。** 它通过推断每个图像的明确高度和宽度并将它们包含在生成的 `<img>` 标记中来工作。 对于显式维度，图像无法在加载到页面时移动页面布局。

输出 HTML 始终是一个简单的 `<img>` 元素，因此您还可以将额外的 CSS 样式应用于更高级的响应式布局，例如 `fill` 和 `cover` ，而不会冒着布局转换的风险。

    <Image  src={myImage}  alt="A very cool penguin!"  style="height: 100%; width: 100%; object-fit: cover;"/>

自动降价和 MDX 支持
--------------------------------

对原始 `@astrojs/image` 集成所做的最大改进之一是完全支持 Markdown、MarkDoc 和 MDX。 您现在可以使用 Markdown 内容或 FrontMatter 中的相对图像路径来引用图像，Astro 将自动为您优化它们。

    ![A starry night sky](../../assets/stars.png)

<!-- 结果：--><img  src="/_astro/stars.XXXXXX.webp"  width="300"  height="300"  loading="lazy"  decoding="async"  alt="A starry night sky"/>

就是这样！ 您的 `stars.png` 图像将在最终 HTML 中自动优化。 如果您更喜欢对图像属性进行更精细的控制，也可以直接在 MDX 中使用 `<Image />` 组件，但在大多数情况下，默认设置足以生成具有出色图像质量的优化文件大小。

与第三方图像服务集成
-----------------------------------------

一些用户不可避免地希望将 Astro 与外部图像服务一起使用，例如 Cloudinary 或 Vercel。 考虑到可扩展性，我们构建了 Astro Image Services API，将 Astro 与您选择的第三方图像服务连接起来。

此 API 包含一小部分钩子，可以控制 Astro 内部的图像处理。 大多数 Astro 用户永远不需要直接触摸此 API，但集成作者可以使用这些来扩展 Astro 的默认行为，并使用他们自己的图像处理逻辑。

一个简单的图像服务导出一个 `getURL()` 函数来为每个指向图像服务域或自定义 URL 路径的图像创建 `src` URL：

// 示例：生成自定义 URLSexport const service = { getUrl({ src, width, height }) { return `https://mywebsitethatgeneratesimages.com/${src}?width=${width}&height=${height}` },} 的基本图像服务

更复杂的图像服务可以使用 `transform()` 之类的钩子在构建时直接生成和返回要服务的图像。 有关完整 API 的演练，请查看 [our Image Services documentation](https://docs.astro.build/en/reference/image-service-reference/)。

Vercel 用户今天可以使用 Astro 的官方 [Vercel adapter](https://docs.astro.build/en/guides/integrations-guide/vercel/) 试试这个。 使用此适配器的任何人都会看到他们的图像使用 [Vercel-specific URL endpoint](https://vercel.com/docs/concepts/image-optimization) 允许 Vercel 为您处理图像优化。

我们期待看到我们的社区使用此功能将 Astro 与他们最喜欢的服务集成在一起，并且 [add to the growing list of Astro integrations](https://astro.build/integrations)！

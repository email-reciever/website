新 `markdown.processor` API
-----------------------------

Astro 的 Markdown 管道一直围绕 [unified](https://unifiedjs.com/)（备注、重新炒作和朋友）构建。 这个生态系统功能强大，有数千个插件可用，但可能不符合您的口味。 Astro 6.4 添加了一个新的 `markdown.processor` 配置选项，让您可以完全交换该管道。

默认处理器仍然是 `unified()`，因此现有项目继续工作而没有任何变化。 您的备注和 rehype 插件继续表现相同，但它们现在直接在处理器上配置，而不是在顶级 `markdown` 配置中：

astro.config.mjs

import { defineConfig } 从 'Astro/config';import { unified } 来自 '@astrojs/markdown-remark';import remarktoc 从 'remark-toc';
导出默认 defineConfig({ markdown: { 处理器：统一({ remarkplugins: [remarktoc], }), },});

现有的顶级 `markdown.remarkPlugins`、`markdown.rehypePlugins`、`markdown.remarkRehype`、`markdown.gfm` 和 `markdown.smartypants` 选项仍然有效，但它们现在已被弃用，转而将它们传递给 `unified({...})`，并将在 Astro 8.0 中删除。

有关详细信息，请参阅更新的 [Markdown guide](https://docs.astro.build/en/guides/markdown-content/)。

利用 Sätteri 实现更快的 Markdown 构建
---------------------------------

可插拔处理器 API 也意味着 Astro 可以提供其他 Markdown 处理器。 Astro 6.4 引入了一个新的 `@astrojs/markdown-satteri` 软件包，一个基于 [Sätteri](https://satteri.bruits.org/) 的新处理器，一个用 Rust 编写的 Markdown 和 MDX 管道。

Sätteri 比默认的基于统一的流水线快得多，它本机实现了许多以前需要的插件的 Markdown 功能。 在我们自己的测试中，将 Astro 和 Cloudflare 文档站点切换到 Sätteri 的站点缩短了他们各自的构建时间。 要尝试它，安装包并将其设置为您的处理器：

npm 安装 @astrojs/markdown-satteri

astro.config.mjs

从“astro/config”中导入 { defineconfig }；从 '@astrojs/markdown-satteri 导入 { satteri }；
导出默认的 defineConfig({ markdown: { processor: satteri({ features: { 指令：true }, }), },});

Sätteri 不运行 Remark 或 Rehype 插件。 如果您依赖统一生态系统中的插件，您需要暂时保留 `unified()` 或将它们移植到 [Sätteri MDAST or HAST plugins](https://satteri.bruits.org/docs/plugins/)。

我们希望在未来主要版本的 Astro 中使 Sätteri 成为默认的 Markdown 处理器。 要提供有关 Rust 处理器和新 API 的反馈，请参阅 [Native Markdown / MDX RFC](https://github.com/withastro/roadmap/pull/1364)。

用于高级路由的 Cloudflare 助手
--------------------------------------

如果您在 Cloudflare 上使用 [experimental advanced routing](https://docs.astro.build/en/reference/experimental-flags/advanced-routing/)（添加到 [Astro 6.3](/blog/astro-630/#experimental-advanced-routing)）上，`@astrojs/cloudflare` 现在将提供一个 `cf()` 助手，为您连接 Cloudflare 特定的位：会话 KV 绑定注入、通过资产绑定提供的静态资产、`locals.cfContext`、客户端地址 `cf-connecting-ip`、`waitUntil` 和预渲染错误页面。

对于自定义 fetch 处理程序，使用 `@astrojs/cloudflare/fetch` 中的 `cf()`：

src/app.ts

导入 { astro, fetchState } 来自 'astro/fetch';import { cf } 来自 '@astrojs/cloudflare/fetch';
导出默认 { 异步 fetch(请求：请求，env: env, ctx: executionContext) { const state = new fetchState(request); 常量资产 = 等待 CF(状态、环境、CTX)； 如果（资产）回报资产； 返回天文（状态）； },};

使用 HONO 时，将 `@astrojs/cloudflare/hono` 中的 `cf()` 用作中间件。

src/app.ts

import { hono } 从 'hono';import { actions, middleware, pages, i18n } 来自 'Astro/Hono';import { cf } from '@astrojs/cloudflare/hono';
const 应用 = 新的 hono<{ 绑定：env }>();
app.use(cf());app.use(actions());app.use(middleware());app.use(pages());app.use(i18n());
导出默认应用程序；

Astro 3.2 推出了几项新改进，使 [view transitions](https://docs.astro.build/en/guides/view-transitions/) 和集成更易于使用：

*   **[Control the browser history stack](#history-replacement-on-links)**
*   **[Trigger page navigation via JavaScript](#javascript-navigation-api)**
*   **[Route announcer for screen readers](#route-announcer)**
*   **[Dynamically add integrations](#dynamically-added-integrations)**

要利用最新的 View Transitions 功能，请确保您运行的是最新版本的 Astro。 您可以通过为您选择的软件包管理器运行升级命令来升级到 Astro 3.2：

npm install astro@latestpnpm 升级 astro --latestyarn 升级 astro --latest

链接上的历史替换
-----------------------------

您现在可以配置单个链接以防止新的历史记录条目被添加到导航的浏览器堆栈中。 将 `data-astro-history="replace"` 属性添加到任何 `<a>` 标记，Astro 将改用底层 `history.replaceState` API。 将此用于更少的后退按钮，或避免将读者发送回表单提交确认等页面。

<a href="/toggle" data-astro-history="replace">切换我</a>

JavaScript Navigation API
--------------------------

您现在可以通过新的 `navigate()` API 从客户端 JavaScript 触发导航。 以前只有在用户单击锚链接时才会发生过渡。 使用新的导航 API，您可以完全控制导航发生的时间。

从 'astro:transitions/client' 导入 { navigate };
// 自动导航到选定的选项。Document.QuerySelector('select').onChange = (ev) => { let href = ev.target.value; 导航(href);};

此外，您可以通过 `history` 选项使用此方法控制历史堆栈，该选项与 `data-astro-history` 属性类似：

从 'astro:transitions/client' 导入 { navigate };
navigate(href, { history: 'replace'});

路线播音员
----------------

View Transitions 路由器现在会进行路由通知。 当使用传统的 MPA 方法在页面之间转换时，辅助技术将在页面完成加载时宣布页面标题。 这不会在客户端路由期间自动发生，因此依赖这些技术的访问者宣布路由不知道何时页面发生了变化。

View Transitions 路由播音员在 `astro:page-load` 事件之后运行，寻找要宣布的页面 `<title>`。 如果找不到，播音员会退回到它找到的第一个 `<h1>` 处，或以其他方式宣布路径名。 我们建议您始终在每页上包含一个 `<title>` 以进行可访问性。

有关如何处理可访问性的更多信息，请参阅 [View Transitions docs](https://docs.astro.build/en/guides/view-transitions/)。

## SVG 优化器

Astro 的实验性 SVG 优化已经使用新的 `svgOptimizer` 选项进行了重新设计，取代了之前的 `svgo` 标志。与其直接绑定到 SVGO，不如新的 API 引入了一个 `SvgOptimizer` 接口，任何优化库都可以实现它。Astro 附带了一个基于 [SVGO](https://svgo.dev/) 的内置 `svgoOptimizer()`，但现在你可以使用像 [OxVG](https://github.com/noahbald/oxvg) 这样的替代库。

astro.config.mjs

```js
import { defineConfig, svgoOptimizer } from "astro/config";
export default defineConfig({  experimental: {    svgOptimizer: svgoOptimizer()  }});
```

启用后，所有作为组件导入的 SVG 文件将在构建时针对更小的文件大小和更好的性能进行优化。你可以传递一个 [SVGO 配置对象](https://svgo.dev/) 来自定义优化：

astro.config.mjs

```js
import { defineConfig, svgoOptimizer } from "astro/config";
export default defineConfig({  experimental: {    svgOptimizer: svgoOptimizer({      plugins: ["preset-default", { name: "removeViewBox" }]    })  }});
```

如果你之前使用的是 `experimental.svgo`，请更新你的配置以使用新的 `svgOptimizer` 选项。

有关更多信息，请参阅 [实验性 SVG 优化文档](https://docs.astro.build/en/reference/experimental-flags/svg-optimization/)。

## 实验日志记录器

现在可以使用自定义日志记录器来控制 Astro 日志记录器。作为实验性功能的一部分，Astro 附带了内置的日志记录器，例如 JSON 日志记录器。如果您使用编码代理来处理 Astro，结构化日志将有助于您的工作流程。

### JSON 日志记录器

您可以通过配置使用 `experimental.logger` 启用 JSON 日志记录，或者通过 CLI 使用 `--experimentalJson` 标志：

astro.config.mjs

```js
import { defineConfig, logHandlers } from "astro/config";
export default defineConfig({  experimental: {    logger: logHandlers.json()  }})
```

```shell
astro dev --experimentalJsonastro sync --experimentalJsonastro build --experimentalJson
```

### 自定义日志记录器

您也可以通过实现正确的接口来创建自己的自定义日志记录器：

astro.config.mjs

```js
import { defineConfig } from "astro/config";
export default defineConfig({  experimental: {    logger: {      entrypoint: "@org/custom-logger"    }  }})
```

@org/custom-logger.ts

```ts
import type { AstroLoggerDestination, AstroLoggerMessage } from "astro";import { matchesLevel } from "astro/logger";
function customLogger(level = 'info'): AstroLoggerDestination {  return {    write(message: AstroLoggerMessage) {      if (matchesLevel(message.level, level)) {        // write message somewhere      }    }  }}
export default customLogger;
```

有关在项目中启用和使用此功能的更多信息，请参阅 [实验性日志记录器文档](https://docs.astro.build/en/reference/experimental-flags/logger/)。

有关此实验性 API 的完整概述以及提供反馈，请参阅 [自定义日志记录器 RFC](https://github.com/withastro/roadmap/blob/logger/proposals/0059-custom-logger.md)。

## 实验性： `getFontFileURL()`

您现在可以在预渲染期间使用新的 `experimental_getFontFileURL()` 辅助函数加载字体文件数据，该函数从 `astro:assets` 中导出。这使得可以使用 Astro 管理的字体与像 [Satori](https://github.com/vercel/satori) 这样的工具一起生成开放图像，在构建时，这样以前需要使用内部路径的变通方法。

src/pages/og.png.ts

```ts
import type { APIRoute } from "astro";import { fontData, experimental_getFontFileURL } from "astro:assets";import satori from "satori";import { html } from "satori-html";import sharp from "sharp";
export const GET: APIRoute = async (context) => {  const fontPath = fontData["--font-roboto"][0]?.src[0]?.url;
  if (fontPath === undefined) {    throw new Error("Cannot find the font path.");  }
  const url = experimental_getFontFileURL(fontPath, context.url);  const data = await fetch(url).then((res) => res.arrayBuffer());
  const svg = await satori(    html`<div style="color: black;">hello, world</div>`,    {      width: 600,      height: 400,      fonts: [        {          name: "Roboto",          data,          weight: 400,          style: "normal",        },      ],    },  );
  const pngBuffer = await sharp(Buffer.from(svg))    .resize(600, 400)    .png()    .toBuffer();
  return new Response(new Uint8Array(pngBuffer), {    headers: { "Content-Type": "image/png" },  });};
```

有关更多信息，请参阅 [Fonts API 文档](https://docs.astro.build/en/guides/fonts/#accessing-font-data-programmatically)。

## Astro v7 alpha

下一个 Astro 主要版本的工作已经开始。第一个 Astro 7 alpha 包括两个大变化：

### Vite 8 支持

Astro 7 升级到 [Vite 8](https://vite.dev/blog/announcing-vite8)，这是 Astro 所依赖的构建工具的最新主要版本。这是一个破坏性变化，适用于依赖 Vite 内部的 Astro 集成和插件，但大多数 Astro 用户应该可以在不修改项目代码的情况下升级。

### 稳定 Rust 编译器

基于 Rust 的 Astro 编译器，之前作为实验标志（`experimental.rustCompiler`）提供，现在成为 Astro 7 中的默认和唯一编译器。Rust 编译器相比之前的 Go-based 编译器提供了显著更快的构建时间。`experimental.rustCompiler` 标志不再需要，可以从你的配置中删除。

### 尝试使用

Astro 7 alpha 版本现已可用于早期测试：

```sh
npm install astro@alpha
```

我们非常希望听到你的反馈！请在 [GitHub](https://github.com/withastro/astro/issues) 上报告你遇到的任何问题。

## 其他改进

* **预览服务器的 `allowedHosts`**: Astro 的 [`server.allowedHosts`](https://docs.astro.build/en/reference/configuration-reference/#serverallowedhosts) 选项现在传递给适配器预览服务器，让你可以控制在运行 `astro preview` 时在反向代理或自定义本地域名后面接受哪些主机名。如果你是适配器作者，`allowedHosts` 现在在传递给你的预览入口点的 `options` 对象上可用。请参阅 [适配器参考](https://docs.astro.build/en/reference/adapter-reference/#previewserver) 以获取详细信息。
* **`compressHTML` 的 `"jsx"` 选项**: `compressHTML` 选项现在接受一个 `"jsx"` 值，该值使用 JSX 规则去除空白字符，因此 `.astro` 和 `.tsx` 文件中的空白字符行为相同。多行缩进文本被折叠成一行，单词之间用空格隔开，而 `<pre>` 标签内的空白字符被保留。

有关错误修复和小改进的完整列表，请参阅 [完整的更改日志](https://github.com/withastro/astro/blob/main/packages/astro/CHANGELOG.md)。

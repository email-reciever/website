实验性现场内容集
-----------------------------------

Astro 5.10 引入了一个新的实验功能：实时内容集。 这种强大的功能允许您在运行时而不是构建时获取内容，为动态实时内容开辟新的可能性。

内置时间内容集合非常适合不会发生太大变化的内容，或者您的网站在更改时快速且易于重建。 但是，经常更改或需要个性化向用户进行个性化的数据呢？ 实时内容集合通过让您在每个请求中获取新数据来填补这一空白。

### 它是如何工作的

实时内容集合使用一种在运行时获取数据的新型加载器。 与在构建过程中运行的现有加载程序不同，实时加载器在用户访问您的页面时执行，确保您始终拥有最新数据。

为了获得最佳性能，您仍应尽可能使用构建时集合。 但现在您可以使用实时集合来获取需要更新的数据，或者您要根据用户输入、凭据或首选项过滤或个性化数据的地方。

首先，在 Astro Config 中启用实验性实时内容集：

astro.config.mjs

导出默认 defineConfig({ 实验性: { LiveContentCollections: true, },});

创建 `src/live.config.ts` 文件以定义您的实时集合：

src/live.config.ts

从 './loaders/store' 导入 { defineliveCollection }；
导出 const products = definelivecollection({ 类型：'live', loader: storeloader({ apiKey: process.env.store_api_key, endpoint: 'https://api.mystore.com/v1', }),});

### 获取实时数据

使用新的 `getLiveCollection()` 和 `getLiveEntry()` 函数来获取组件中的数据：

src/pages/products/\[slug\]].astro

---import { getLiveEntry } 来自“astro:content”；
const { entry: product, error } = await getLiveEntry('products', astro.params.slug,);
if (error) { console.error('无法加载产品：'，错误); 返回 astro.rewrite('/404');}---
<h1>{product.data.name}</h1><p> { intl.numberformat('en-us', { 样式：'货币', 货币: 'USD' }).format( product.data.price, ) }</p>

### 呈现实时内容

Live Loaders 可以生成渲染的内容，例如构建时加载器，使在组件中显示动态数据变得非常容易：

src/pages/products/\[slug\]].astro

---import { getLiveEntry, render } from 'astro:content';
const { entry: product, error } = await getLiveEntry('products', astro.params.slug,);
if (error) { console.error('无法加载产品：'，错误); 返回 astro.rewrite('/404');}
const { 内容 } = 等待渲染（产品）；---
<h1>{product.data.name}</h1>
    <Content />

### 灵活的过滤

Live Loader 支持特定于 Loader 的查询和过滤选项，允许您将过滤逻辑推送到 API 级别，以实现更高效的数据提取。 这意味着您可以准确请求所需的数据，而不是获取所有内容并过滤客户端。

src/pages/products.astro

---import { getLiveCollection } 来自“astro:content”；
const { 条目, 错误 } = await getLiveCollection('products', { 类别: 'electronics', pricerange: { min: 10, max: 100 },});---

### 错误处理

实时内容集合提供包含数据或 `error` 对象的结果对象的显式错误处理。 这使运行时行为可预测，并帮助您优雅地处理故障。

### 类型安全

如果没有考虑到类型安全性，它就不会是Astro，因此API是完全类型安全的，具有通用类型确保您的数据和查询选项正确键入：

// 带有类型查询和数据的自定义加载程序 { entry, error } = await getLiveEntry('products', { uuid: astro.params.uuid, // 过滤器选项是类型检查的});// `entry` 将被输入

有关如何构建实时装载器的更多详细信息，请参阅 [experimental live content collections documentation](https://docs.astro.build/en/reference/experimental-flags/live-content-collections/)。 给我们您关于 [the RFC](https://github.com/withastro/roadmap/pull/1164) 的反馈。

响应图像现在稳定
--------------------------------

Astro Responsive Images 功能现已稳定，可供生产！

响应图像自动生成优化的 `srcset` 和 `sizes` 属性，并可以生成所需的样式，以确保您的图像快速加载并在所有屏幕尺寸上显示精美。 告别布局变化和缓慢加载的图像，这些图像会损害您的核心 Web Vitals 分数。

### 开始使用响应式图像

`layout` 属性定义您的响应图像应如何调整大小并确定要生成的 `srcset` 和 `sizes`。 您可以在 Astro Config 中全局设置此功能，使其默认应用于所有图像，或在 `<Image />` 或 `<Picture />` 组件中的每个图像基础上应用。 要启用此响应行为，请配置支持内置布局选项的 Astro 默认全局响应式样式：

astro.config.mjs

导出默认 defineConfig({ image: { 响应式样式：true, layout: 'constrained', },});

**布局选项：** 从 `constrained`、`fixed` 或 `full-width` 布局中进行选择以控制图像的行为方式。 在单个组件上设置此值将覆盖您的默认布局。 例如，您可以添加 `layout` 属性以创建全宽的英雄图像，同时将其余图像限制在其容器中：

    <Image  src="/hero.jpg"  alt="A panoramic view of the mountains"  layout="full-width"/>

**优先加载：** 使用新的 `priority` 属性优化出现在折叠上方的关键图像：

    <Image src="/hero.jpg" alt="Hero image" priority />

添加 `priority` 时，Astro 会自动设置 `loading="eager"`、`decoding="sync"` 和 `fetchpriority="high"` 以确保图像立即加载。 谨慎使用它——理想情况下，每页不超过一张图像应该优先加载。 在使用之前，请确保您需要这个！ 检查您的 [Largest Contentful Paint (LCP) element](https://web.dev/lcp/#lcp-element) 是否是图像，如果是，请在其上设置 `priority` 标志以使其对访问者可见。

**增强的裁剪控件：** `fit` 和 `position` 属性让您可以精确控制图像的裁剪和定位方式：

    <Image  src="/profile.jpg"  alt="Profile photo"  fit="cover"  position="center top"  width={300}  height={300}/>

### 从实验响应图像升级

如果您使用的是实验性响应图像，则必须从 `astro.config.mjs` 文件中删除实验标志，并使用其稳定版本更新任何 `image.experimental` 选项：

astro.config.mjs

导出默认的 defineConfig({ 实验性: { ResponsiveImages: True, }, Image: { ResponsiveStyles: true, },});

有关完整的详细信息，请参阅更新的 [Images guide](https://docs.astro.build/en/guides/images/#responsive-image-behavior)。

实验内容安全策略的改进
------------------------------------------------

Astro 5.9 提供了对内容安全策略 (CSP) 元标记的实验性支持，为您的 Astro 网站带来了强大的安全功能。 在 5.10 中，我们根据社区反馈进行了一些改进。 最重要的是我们现在支持生成 CSP 标头，包括静态页面。

按需渲染页面现在将发送 CSP 的响应标头，而不是元标记。 这提高了 Chrome 中的性能，并增加了对更多指令（如 `report-uri` 和 `frame-ancestors`）的支持，这些指令在元标记中不受支持。

默认情况下，预渲染页面仍将使用元标记，但现在也支持通过官方适配器为预渲染页面生成标头。 最终，这将在所有适配器中实现，但目前只有 `@astrojs/netlify` 和 `@astrojs/vercel` 适配器支持它。 要启用此功能，请确保已更新到最新版本的适配器，并将 `experimentalStaticHeaders` 选项添加到适配器配置中：

astro.config.mjs

从“astro/config”导入 { defineConfig }；从“@astrojs/netlify”导入 netlify；
导出默认的 defineConfig({ 适配器: netlify({ experimentStaticStaticHeaders: true, }), 实验: { csp: true, },});

有关详细信息，请参阅 [experimental CSP documentation](https://docs.astro.build/en/reference/experimental-flags/csp/)。

可定制的 Cloudflare 工作人员入口点
----------------------------------------

一些 Cloudflare 工作程序功能，如 [Durable Objects](https://developers.cloudflare.com/workers/runtime-apis/durable-objects/)、[Cloudflare Queues](https://developers.cloudflare.com/queues/) 和 [Cron Triggers](https://developers.cloudflare.com/workers/platform/cron-triggers/) 需要自定义 EntryPoint 文件。 因为 `@astrojs/cloudflare` 适配器生成用于服务站点的入口点，因此这些功能以前无法与 Astro 一起使用。 此版本增加了对 `@astrojs/cloudflare` 适配器使用的 EntryPoint 文件的自定义支持，使您可以完全控制 Cloudflare Workers 设置。

要自定义 EntryPoint，请将 `workerEntryPoint` 选项添加到 `astro.config.mjs` 文件中的 `@astrojs/cloudflare` 适配器配置：

astro.config.mjs

从“astro/config”导入 { defineConfig }；从“@astrojs/cloudflare”导入 Cloudflare；
导出默认定义配置({ 适配器：Cloudflare({ workerEntryPoint: { 路径：'src/worker.ts', namedExports: ['MyDurableObject'] }),});

然后，您可以在指定的路径上创建一个自定义入口点文件，该文件可以包括您的工作人员设置所需的任何其他导入或导出。 此示例配置注册持久对象和队列处理程序的自定义条目文件：

src/worker.ts

从“astro”导入类型 { ssrmanifest }；
import { app } 从 'astro/app';import { handle } from '@astrojs/cloudflare/handler'import { durableObject } from 'cloudflare:workers';
类 MyDurableObject 扩展 DurableObject<Env> { 构造函数(CTX: DurableObjectState, env: env) { super(ctx, env) }}
导出函数 createExports(manifest: ssrmanifest) { const app = new app(manifest); return { default: { async fetch(request, env, ctx) { // 你的绑定也必须在你的 `wrangler.toml`/`wrangler.jsonc` 文件中定义 await env.my_queue.send("log"); // 确保将请求传递给 Astro 的处理程序返回句柄(Manifest, App, Request, env, ctx); }，异步队列（批量，_env）{ let messages = json.stringify(batch.messages); 控制台.log(`consumed from our queue: ${messages}`); } } 满足 exportedHandler<Env>, MyDurableObject, }}

有关详细信息，请参阅更新的 [Cloudflare adapter documentation](https://docs.astro.build/en/guides/integrations-guide/cloudflare#workerentrypoint)。

感谢贡献了此功能的 [Alexander Niebuhr](https://github.com/alexanderniebuhr)，并在 `@astrojs/cloudflare` 适配器上完成了大部分工作！

**ASTRO 6.3 在这里！** 此版本带来了实验性的高级路由，让您可以完全控制您的请求管道。 编写单个处理程序，像 Hono 一样带上您自己的框架，并确定具体运行的内容和顺序。

探索此版本中的新功能：

*   [**Experimental: Advanced Routing**](#experimental-advanced-routing)
*   [**Support redirects on external image URLs**](#support-redirects-on-external-image-urls)
*   [**SVG image processing disabled by default**](#svg-image-processing-disabled-by-default)

要升级现有项目，请使用自动 `@astrojs/upgrade` CLI 工具。 或者，通过运行包管理器的升级命令手动升级：

    # 手动：npm安装astro@latestpnpm升级astro --latestyarn升级astro --latest

实验：高级路由
------------------------------

Astro 6.3 引入了对高级路由的实验性支持：完全控制请求如何流经您的应用程序，并支持 [Hono](https://hono.dev/) 等框架的一流支持。

您的应用程序会导出 Cloudflare Workers、Deno、Bun 和 Hono 使用的 Fetch 处理程序模式。 将某些路径代理到另一个服务，让 Astro 处理其余部分：

src/app.ts

从“astro/fetch”导入 { fetchState, astro };
导出默认 { fetch(request: request) { const state = new fetchState(request);
if (state.url.pathname.startsWith('/api')) { 返回 fetch(新网址(state.url.pathname, 'https://api.example.com')); }
返回天文（状态）； }}；

Astro 通常以固定顺序运行中间件、动作、i18n 和渲染。 这适用于大多数项目，但随着应用程序的增长，您最终会围绕框架工作，以在正确的位置添加身份验证、日志记录、速率限制或特定于平台的逻辑。

借助高级路由，管道的每一步都可以作为自己的处理程序使用。 混合您自己的逻辑并准确决定什么运行和顺序：

src/app.ts

import { hono } 从 'hono';import { logger } 来自 'hono/logger';import { actions, middleware, pages, i18n } from 'astro/hono';
常量应用程序 = 新的 hono();
// 您自己的中间件首先运行.app.use(logger());app.use(async (c, next) => { if (new url(c.req.url).PathName.StartsWith('/admin')) { return c.redirect('/login'); } 返回 next();});
// 按您选择的顺序进行 Astro 处理程序.App.use(Actions());App.Use(MiddleWare());App.use(Pages());App.use(i18n());
导出默认应用程序；

可用的处理程序包括 `astro`、`trailingSlash`、`redirects`、`sessions`、`actions`、`middleware`、`pages`、`cache` 和 `i18n`，从 `astro/fetch` 和 `astro/hono` 导出。

有关在项目中启用和使用此功能的更多信息，请参阅 [Experimental Advanced Routing docs](https://docs.astro.build/en/reference/experimental-flags/advanced-routing/)。

支持对外部图像网址进行重定向
---------------------------------------

优化远程图像时，如果图像 URL 返回重定向，Astro 以前会静默失败。 对于使用重定向将请求路由到正确的边缘节点或存储存储桶的 CDN 和图像服务，这是一个问题。 您的图像将在没有解释的情况下从构建中消失。

Astro 6.3 现在在获取远程图像时最多可跟踪 10 次重定向。 重定向链中的每个 URL 都针对您的 `image.remotePatterns` 和 `image.domains` 配置进行验证，因此您可以控制 Astro 可以从哪些主机获取。 如果重定向导致不在您的 AllowList 中的主机，Astro 将抛出一个有用的错误，而不是默默地忽略图像。

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ 图像：{ 域名：["example.com", "cdn.example.com"] }});

---// 重定向到 https://cdn.example.com/assets/image.png - works!// 重定向到 https://malicious.com/image.png - 抛出一个错误---<Image src="[2] width="1920" height="1080" alt="An example image." />

如果您信任所有 HTTPS 主机，则可以使用单个远程模式允许它们：

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认的 defineConfig({ image: { remotepatterns: [{ 协议：'https' }] }});

默认禁用SVG图像处理
---------------------------------------

Astro 的 Sharp 图像服务可以将 SVG 文件栅格化为 PNG 或 WebP 等其他格式。 但是，这在引擎盖下运行 `librsvg`，并且 SVG 文件可以包含嵌入式脚本和其他活动内容。 以这种方式处理不受信任的 SVG 是潜在的安全风险。

从 Astro 6.3 开始，默认禁用 SVG 图像处理。 如果将 SVG 源传递给图像优化管道，Astro 现在将抛出一个有用的错误，而不是默默地处理它。

如果您信任您的 SVG 源并希望恢复之前的行为，请设置新的 `image.dangerouslyProcessSVG` 选项：

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认的 defineConfig({ image: { dangerouslyProcesssvg: true, }});

此更改不会影响将 SVG 作为组件导入。 它仅适用于通过图像优化管道对 SVG 源进行栅格化（例如，通过 `<Image />` 将 SVG 转换为 PNG）。

其他改进
-------------------

*   ** `AstroCookies`** 的新 `consume()` 方法：此方法将 Cookie 标记为已消耗并返回 `Set-Cookie` 标头值。 消费后，任何后续的 `set()` 调用都会记录警告，因为标头已经发送。 这取代了静态 `AstroCookies.consume(cookies)` 方法，该方法现在已弃用，但保留与现有适配器的向后兼容性。

有关错误修复和较小改进的完整列表，请参阅 [the full changelog](https://github.com/withastro/astro/blob/main/packages/astro/CHANGELOG.md)。

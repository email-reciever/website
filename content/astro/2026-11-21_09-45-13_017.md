Astro 2.9 已推出并具有对 [view transitions](https://developer.chrome.com/docs/web-platform/view-transitions/) 的实验支持，以及重定向配置和改进的脚本捆绑。

*   **[View Transitions (experimental)](#view-transitions-experimental)**
*   **[Redirects](#redirects)**
*   **[Hoisted script optimization](#hoisted-script-optimization)**

如果您已经安装了 Astro，则可以通过在项目中运行升级命令（使用您选择的软件包管理器）将其升级到 2.9：

npm install astro@latestpnpm 升级 astro --latestyarn 升级 astro --latest

当您使用它时，也可以升级您安装的任何 `@astrojs/*` 集成和适配器！

Astro 现在通过新的 `<ViewTransitions />` 组件和 `transition:animate` 指令支持 [view transitions](https://developer.chrome.com/docs/web-platform/view-transitions/)。 在不牺牲 MPA 的简单性的情况下享受以前需要的客户端路由的更顺畅的转换。

通过将实验标志添加到您的配置中，启用对 Astro 2.9 中的视图转换的支持：

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ 实验性: { viewTransitions: true, },});

### <ViewTransitions />

这是一个作为页面之间转换的 _router_ 的组件。 将其添加到每个单独页面的 `<head>` 部分，其中当您导航到另一个页面时，应该在客户端_中发生过渡，而不是导致整个页面浏览器刷新。

要在整个应用程序（SPA 模式）中启用支持，请在针对每个页面 `<head>` 的一些常见布局或组件中添加组件。

**commonhead.astro**

---import { viewTransitions } 来自 'astro:transitions';---
<meta charset="utf-8" /><title>{astro.props.title}</title><ViewTransitions />

仅通过此更改，您的应用程序现在将完全在客户端中进行路由。 然后，您可以使用 `transition:animate` 指令将过渡添加到各个元素。

### 动画

将 `transition:animate` 添加到任何元素以使用 Astro 的内置动画。

    <header transition:animate="slide"></header>

在上面，Astro 的 `slide` 动画将导致 `<header>` 元素从左侧滑入，然后在离开页面时向右滑动。

您还可以使用任何 CSS 动画属性自定义这些动画，例如，通过指定持续时间：

---import { slide } 来自 'astro:transition';---
    <header transition:animate={slide({ duration: 200 })}></header>

重定向
----------

`redirects` 配置选项不再是实验性的！ 如果您之前使用的是实验性重定向，请移除以下实验标志：

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ 实验性：{ 重定向：true, }});

如果您在使用重定向之前一直在等待稳定，请不要再等待！ 您现在可以在项目中安全地使用重定向。 查看 [the docs on redirects](https://docs.astro.build/en/core-concepts/routing/#redirects) 了解如何使用此内置功能。

在您的配置中，添加一张新旧路径的地图，以便从和到：

从“astro/config”导入 { defineconfig }；
导出默认的 defineConfig({ 重定向：{ '/old-page': '/new-page' }});

提升脚本优化
----------------------------

Astro 的静态分析来确定将哪些 `<script>` 标记捆绑在一起变得更聪明了！

Astro 创建了优化页面之间脚本使用情况的捆绑包，并将它们放在文档的头部，以便尽早下载。 对 Astro 现有方法的一种限制是您无法动态使用提升的脚本。 在使用重新导出组件的库时，每个页面都收到相同的、全包的捆绑包，无论该页面上是否需要每个脚本。

现在，Astro 改进了静态分析，以考虑实际使用的进口。

例如，Astro 会先将 `<Tab>` 和 `<Accordion>` 组件中的 `<script>` 捆绑在一起，以获取以下重新导出多个组件的库：

**@matthewp/my-astro-lib**

export { 默认为 tabs } 从 './tabs.astro';export { 默认为 accordion } 来自 './accordion.astro';

现在，当一个 Astro 页面仅使用单个组件时，Astro 将仅将必要的脚本发送到该页面。 仅导入 `<Accordion>` 组件的页面不会接收任何 `<Tab>` 组件的脚本：

---import { 手风琴 } 来自 '@matthewp/my-astro-lib';---

您现在应该通过支持这种通用库重新导出模式的 Astro 看到更高效的性能。

感谢 [Ottomated](https://ottomated.net/) 的社区贡献者开发此新功能。

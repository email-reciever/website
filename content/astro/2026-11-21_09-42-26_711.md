顺风 4 支持
-------------------

随着 V4 的发布，Tailwind CSS 现在提供了一个 `@tailwindcss/vite` 插件，可以直接添加到您的 Astro 项目中。 这简化了 Astro 中的顺风体验，现在是在 Astro 中使用 Tailwind 4 的推荐方式。

Astro 5.2 添加了对这个 Vite 插件的本机支持，`astro add tailwind` 命令现在将该插件添加到您的 Astro 配置中，并创建一个默认的 CSS 文件导入 Tailwind 样式。

因此，`@astrojs/tailwind` 集成现在已被弃用，但将继续适用于旧版本的 Tailwind。 要升级到 Tailwind 4，请卸载集成并使用更新的 `astro add tailwind` 命令或遵循 [Tailwind documentation for manual installation](https://tailwindcss.com/docs/installation/framework-guides/astro)。

感谢 [Eveeifyeve](https://github.com/Eveeifyeve) 在 Alpha 中进行了第一个支持 Tailwind 4 的工作，尽管最终使用了不同的实现。

尾随斜线重定向
-------------------------

路径是否应该有尾随斜线是 Web 开发中的常见争论。 但是，每个人都同意它应该是一致的。 重复的内容对 SEO 不利，对用户来说是令人困惑的。

Astro 长期以来一直允许您配置路由是否应该匹配或不使用尾随斜杠，但以前这意味着返回错误路径的“未找到”页面，或者将其留给主机处理冲突。 Astro 5.2 会根据 `astro.config.mjs` 中的 `trailingSlash` 选项自动将按需渲染的路由重定向到正确的路径。

现在，访问者是否导航到 `/about/`、`/about` 甚至 `/about///` 都没有关系。 在生产中，它们总是会出现在正确的页面上。 对于 GET 请求，重定向将是 301（永久）重定向，而对于所有其他请求方法，它将是 308（永久性和保留请求方法）的重定向。

在开发过程中，Astro 将显示一个错误页面，而不是重定向以帮助您捕获任何错误配置和错误链接。

要启用尾斜线重定向，请在 `astro.config.mjs` 中设置 `trailingSlash` 选项：

astro.config.mjs

导出默认的 defineConfig({ 适配器: node({ mode: 'standalone' }), 尾随斜杠: 'never', // 或 'always'});

有关详细信息，请参阅 [`trailingSlash` 文档](https://docs.astro.build/en/reference/configuration-reference/#trailingslash)。

外部重定向
-------------------

Astro 现在支持直接从配置中定义外部重定向到 `http` 或 `https` 目的地。

就像 Astro 2.9 以来可用的内部重定向一样，使用适配器，您还可以提供一个对象作为值。 这允许您在新的 `destination` 之外指定 `status` 代码。

从“astro/config”导入 {defineConfig}
导出默认的 defineConfig({ 重定向：{"/about":"https://example.com/about", "/news": { status: 302, 目的地："https://example.com/news" } }})

有关详细信息，请参阅更新的 [`redirects` 配置文档](https://docs.astro.build/en/reference/configuration-reference/#redirects)。

降价中的Toml FrontMatter
-----------------------------

Astro 对 Markdown 和 MDX 的出色支持始终包括 YAML FrontMatter，无论是在文件导出还是内容集合中。 有了这个版本，Astro 现在还支持 TOML FrontMatter。 这对于从 Hugo 等另一个框架将带有 Toml FrontMatter 的现有内容文件添加到您的项目很有用，或者您可能只是更喜欢 TOML 而不是 YAML！

在您的内容文件中使用 TOML FrontMatter 无需配置：只需使用 `+++` 分隔 FrontMatter，Astro 将将其解析为 TOML。

+++日期= 2025-01-30Title = '在Astro中使用Toml FrontMatter!'[params] 作者 = '休斯顿'+++
    # 支持TOML FrontMatter在这里！

感谢贡献此功能的 [Colin Bate](https://colinbate.com/)。

实验：`astro:config`
-----------------------------

Astro 提供了从项目文件中访问配置设置的几种方法：环境变量、`.astro` 文件中的 `Astro` 全局对象以及中间件和端点中的 `context` 变量。 但是，很难记住信息在哪里可用：是 `import.meta.env.BASE` 还是 `Astro.base`？

使用 `astro:config`，我们希望提供一种 _single_ 方式从项目中的任何地方读取最有用的配置选项。 而且，因为它是 Astro，所以我们这样做是在考虑类型安全的情况下！

此虚拟模块公开了两个子模块（`/client` 和 `/server`），用于访问配置值的不同子集。 这通过仅向客户端提供一些数据来保护您的信息。

要使用这个新的虚拟模块，您需要通过实验标志启用它：

从“astro/config”导入 {defineConfig}
导出默认的 defineConfig({ trailingSlash: "always", experimental: { serializeconfig: true }})

然后，从 Astro 项目中的任何文件中，您可以使用虚拟模块：

src/utils.js

从“astro:config/client”导入{trailingslash}
导出函数 appendForwardPath(path) { if (trailingSlash === "always") { return path.endsWith("/") ? 路径：路径+“/”}返回路径}

有关此新实验功能的更多信息，请参阅 [Serialized Configuration docs](https://docs.astro.build/en/reference/experimental-flags/serialized-configuration/)。

我们希望最终弃用其他读取这些属性的方式，并使 `astro:config` 成为在 Astro 项目中访问配置值的事实上的标准。 请加入积极的讨论，在 [Serialized Config RFC](https://github.com/withastro/roadmap/pull/1106) 中留下您的反馈，并帮助塑造此功能的未来！

实验：禁用 React 流
-----------------------------------

`@astrojs/react` 集成现在允许您禁用 React 流。 如果您使用的是与流不兼容的库，例如许多 CSS-in-JS 库，这将非常有用。 要禁用 React Streaming，请升级 `@astrojs/react` 集成：

    # 推荐：NPX @ASTROJS/升级
    # 手动：npm安装@astrojs/react@latestpnpm升级@astrojs/react --latestyarn升级@astrojs/react --latest

然后将积分的 `experimentalDisableStreaming` 选项设置为 `astro.config.mjs` 中的 `true`：

astro.config.mjs

导出默认 defineConfig({ 集成：[ react({ experimentDisableStreaming: true, }), ],});

有关详细信息，请参阅 [`@astrojs/react` 文档](https://docs.astro.build/en/guides/integrations-guide/react/#disable-streaming-experimental)。

感谢来自华盛顿邮报的 [Arturo Silva](https://artfromclt.dev/) 谁贡献了这个功能。

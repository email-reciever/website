实验：会议
-----------------------

如果您已经构建了使用 Rails 或 Laravel 等框架的应用程序，您可能熟悉会话：在用户浏览您的网站时跟踪每个用户数据（如登录状态、Flash 消息或购物车）的简单方法。 会话使您可以安全地存储绑定到特定用户的临时数据，而无需客户端存储。 目前，您可能会将数据存储在 cookie 或本地存储中，但这可能不安全或麻烦——或者限制您可以存储的数据量。

会话通过在服务器上存储数据而工作，并且仅将会话 ID 作为 cookie 发送到客户端。 然后，您可以 `get` 和 `set` 在 Astro 页面和组件、API 端点、Astro 操作和中间件中的会话数据。 API 和数据对每个人都是相同的。

在 Astro 组件和页面中，您可以将 Session 对象作为 `Astro.session` 访问：

src/组件/cartbutton.astro

---export const preRender = false;const cart = await astro.session.get('cart');---
<a href="/cart">🛒 {购物车？。长度？？ 0}项目</a>

Astro Actions 中提供了相同的会话数据：

src/actions/addtocart.ts

从“astro:actions”中导入 { defineAction }；从“astro:schema”导入 { z }；
导出 const server = { addToCart: defineAction({ input: z.object({ productID: z.string() }), 处理程序: 异步 (input, context) => { const cart = await context.session.get("cart"); cart.push(input.productId); await context.session.set("cart", cart); return cart; }, }),};

会话适用于按需呈现的页面，或者它们与 [server islands](https://docs.astro.build/en/concepts/islands/#server-islands) 完美配对，让您在其他静态网站中添加个性化内容的岛屿。

---从'../组件/cartbutton.astro'导入cartbutton;---<CartButton server:defer />

### 驱动程序

Astro 会话由 [unstorage](https://unstorage.unjs.io/) 驱动程序提供支持，这些驱动程序是 Astro 用于存储会话数据的模块。 Unstorage 支持数十家提供商，为您提供存储用户数据的首选世界。

当会话成为稳定功能时，Astro 的官方适配器将自动配置默认驱动程序。 但是在这个实验阶段，您必须自己为所选的适配器配置一个 `driver`。 您还可以使用跨平台驱动程序，例如 [Upstash](https://unstorage.unjs.io/drivers/upstash) 或 [Redis](https://unstorage.unjs.io/drivers/redis)。

### 使用

要尝试实验会话，请将 `experimental.sessions` 标志添加到 `astro.config.mjs` 中：

此示例演示如何启用与 Node.js 适配器一起使用的文件系统驱动程序：

astro.config.mjs

{ adapter: node({ mode: 'standalone' }), experimental: { session: { // 必需: unstorage 驱动程序的名称: "fs", }, }, }

有关更多信息，请参阅 [the sessions docs for this experimental flag](https://docs.astro.build/en/reference/experimental-flags/sessions/)。 我们也感谢您对该功能的反馈。 有关更多详细信息，并留下反馈并参与该功能的开发，请参见 [the Sessions RFC](https://github.com/withastro/roadmap/pull/1055)。

远程图像缓存
---------------------

您已经知道并喜欢自动调整大小和优化的内置 `<Image />` 组件到 [display optimized images](https://docs.astro.build/en/guides/images/#display-optimized-images-with-the-image--component)。 虽然此组件目前会同时转换本地和远程图像，但构建之间的图像缓存仅限于本地图像。

现在，Astro 也将缓存远程图像，减少在每个版本中重新下载和重新转换图像的需要。 它使用 [conditional requests](https://developer.mozilla.org/en-US/docs/Web/HTTP/Conditional_requests#conditional_headers) 与 [`If-Modified-Since`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/If-Modified-Since) 或 [`If-None-Match`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/If-None-Match) 标头来确定图像是否仍然是新鲜的，除非源图像发生了变化，否则将使用缓存的版本。

现在，所有站点都启用了此功能，并且将与支持条件请求的任何主机一起使用。 有关详细信息，请参阅新的 [asset caching docs](https://docs.astro.build/en/guides/images/#asset-caching)。

特别感谢[@oliverlynch](https://github.com/oliverlynch)，他贡献了这个功能！

`getActionPath` 助手
-----------------------

使用 Astro Actions 就像调用 `actions.like()` 或 `actions.addToCart()` 一样简单。 但有时您需要知道操作的 URL，以便使用自定义标头发出 `fetch()` 请求，或使用 `navigator.sendBeacon()` 等 API。

Astro 5.1 引入了一个新的辅助函数，`getActionPath()` 在调用操作时为您提供了更大的灵活性。

需要授权这些喜欢吗？ 通过 `Authorization` 标头和 [`keepalive`](https://developer.mozilla.org/en-US/docs/Web/API/Request/keepalive) 选项调用您的 `like` 操作：

src/components/my-component.astro

<script>从“astro:actions”导入 { 动作，getActionPath }
await fetch(getActionPath(Actions.like), { 方法: 'post', headers: { 'content-type': 'application/json', authorization: 'bearer your_token' }, body: json.stringify({ id: 'your_id' }), keepalive: true})</script>

有关详细信息，请参阅 [新 `getActionPath()` 文档](https://docs.astro.build/en/reference/modules/astro-actions/#getactionpath)。

页面部分
--------------

一个页面组件现在可以被识别为一个**部分**页面，它将呈现其HTML内容，而无需包含`<!DOCTYPE html>`声明或任何`<head>`内容。

部分最好与渲染库结合使用，例如围绕获取 HTML 片段构建的 [htmx](https://htmx.org/) 或 [Stimulus](https://stimulus.hotwired.dev/)。

您可以通过在组件 FrontMatter 中设置 `partial` 选项将任何页面标记为部分。

---export const partial = true;---<li>这是一个单一的列表项。</li>

这将导致以下 HTML 输出：

<li>这是一个单一的列表项目。</li>

`.astro` 文件以及可以导出值的任何其他页面文件类型（例如 `.mdx`）可以标记为部分。

在我们的文档中阅读有关 [page partials](https://docs.astro.build/en/core-concepts/astro-pages/#partials) 的更多信息，并使用 Astro Page Partials 和 HTMX 查看此 [TodoMVC example](https://github.com/tony-sull/todomvc-astro-htmx)。

图像组件性能
----------------------------

Astro 现在在构建时为静态站点生成优化的图像_concurrently_，这可以显着加快有许多图像的站点的构建时间。

此外，Astro 现在将对图像的所有变体重复使用相同的缓冲区。 这应该可以提高具有许多相同图像变体的网站的性能，尤其是在使用远程图像时。

无需更改代码即可利用这些改进。

开发叠加层（实验）
---------------------------

![The dev overlay showing x-ray mode with a client component highlighted. It shows the client directive being used, and the props passed to the component.](/_astro/dev-overlay-3.4.C-NsusAT_Z1LwODX.webp)

3.4 中提供了一个新的实验性 **dev 覆盖**，它允许您检查页面岛屿，查看有关性能和可访问性的有用审计等。 还包括一个开发覆盖插件 API 以允许您向其中添加新功能和第三方集成。

此版本的重点是插件 API，以便集成作者可以开始测试它并提供反馈。 内置功能目前是有限的，但要在即将发布的版本中寻找扩展功能！

您可以通过向 Astro Config 中添加以下标志来启用对 Dev Overlay 及其 API 的访问：

astro.config.mjs

导出默认值 { 实验性: { devOverlay: true }};

阅读 [Dev Overlay Plugin API documentation](https://docs.astro.build/en/reference/dev-overlay-plugin-reference/) 以获取有关构建自己的插件以与 Astro 的 Dev Overlay 集成的信息。

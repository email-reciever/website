**我们决定关闭 Astro Studio 并打开 Astro DB 以连接到任何 LibSQL 数据库，包括 [Turso](https://turso.tech/)。 继续阅读以了解有关我们如何做出决定、接下来会发生什么以及为什么我们认为这是 Astro 和 Astro DB 的正确决定的更多信息。**

今年早些时候，我们推出了一个名为[Astro Studio](/db)的托管数据库平台。 我们的目标是让每个 Astro 开发人员都可以直接从 Astro Framework 内部轻松访问经济实惠、快速的 SQL 数据存储。 在这一点上，我们成功了。 Astro Studio 为本地开发和生产流量提供了即时数据库访问权限，具有惊人的规模和成本节约。

我们的第二个目标是将其打造成有利可图的业务，以支持 Astro 的持续发展和发展。 在这一点上，我们失败了。 Astro Studio 从未达到我们认为我们已经找到适合产品市场的地步。 成千上万的 Astro 开发人员尝试了该平台，但很少有人坚持下去。 Turso 和 Supabase 等较大的开发平台提供了类似的功能，并拥有令人兴奋的路线图，这使我们在拥挤的空间中脱颖而出的努力变得复杂化。 我们移动得太慢了。 我可以继续下去，但最终我们找不到一条清晰的道路来追求我们正在建立持久的东西。

**因此，我们正在呼吁放松并最终关闭。 您还可以自主托管 Libsql 数据库或完全移动到另一个数据库（下一节将对此进行更多介绍）。

更多细节，对于感兴趣的人：

*   邀请到 Astro Studio 将保持关闭状态。
*   现有用户将无法在2024年10月1日之后创建新的数据库。
*   现有数据库在2025年3月1日之后将不再可访问。
*   任何剩余的数据库将在2025年3月1日之后或不久之后被删除。
*   如果您是当前的 Astro Studio 用户，请在未来几天检查您的电子邮件收件箱或我们的 Discord 服务器以获取更多信息和说明。

致今年尝试 Astro Studio 的数千名开发人员：谢谢。 感谢您对我们下注。 这段经历教会了我们很多东西，我们已经在学习这些课程——并保留了我们最喜欢的工作室部分——来制定新课程并构建我们_do_认为会持续下去的东西。 下周是发布周，因此下周五与我们联系，了解我们一直在做的事情……

Astro DB：开源加倍
------------------------------------

展望未来，本公告中隐藏着_some_好消息：[Astro DB](https://docs.astro.build/en/guides/astro-db/)不会去任何地方。 它实际上正在改进。

对于不熟悉的人来说，Astro DB 是我们数据库故事的框架和软件组件。 它包括本地开发数据库、架构管理、自动迁移和具有全自动 TypeScript 类型的数据库 ORM/SDK。 它非常酷，但直到最近它才适用于 Astro Studio 平台。

随着 Astro Studio 的结束，我们现在可以投入时间和精力让 Astro DB 对每个人更加开放和强大。

从 [Astro 4.15](https://astro.build/blog/astro-4150/#libsql-remotes-in-astro-db) 开始，您现在可以将 Astro DB 连接到任何 LibSQL (SQLite) 数据库！ 这需要一些巧妙的重构，例如将数据库本身的一些重要管理元数据移动到数据库本身，以便您需要的所有内容都可以自包含。 感谢 Astro 社区成员和维护者 [@Fryuni](https://github.com/Fryuni) 为实现这一目标所做的工作！

我个人对一个 Astro DB 可以与您指向的任何数据库进行对话的世界感到非常兴奋。 有一天，Astro DB 可以与您的 MySQL 或 Postgres 数据库交谈，这完全是 Astro 框架的内置。 这种变化让我们更接近那个未来！

Astro 1.5.0 刚刚推出，它的特点是：

*   **[Adapter 支持 `astro preview`](#adapter-support-for-astro-preview)**：适配器现在可以支持 `astro preview`。
*   **[Standalone mode in Node.js adapter](#standalone-mode-in-nodejs-adapter)**：Node.js 适配器现在可以构建到独立的服务器。
*   **[HMR for Tailwind and TypeScript config](#hmr-for-tailwind-and-typescript-config)**：开发服务器现在将在 Tailwind Config 和 tsconfig 更改时自动重新加载。
*   **[API Endpoint improvements](#api-endpoint-improvements)**：API 路由 `APIContext` 对象现在更接近地与 Astro Global 匹配。
*   **[Astro.redirect status code](#astroredirect-status-code)**：您现在可以选择在使用 `Astro.redirect` 时传递状态代码。

您可以通过运行 `npm install astro@latest` 来更新您的项目。

适配器支持 `astro preview`
---------------------------------

我们正在通过一个新的集成选项在适配器中推出对 `astro preview` 命令的支持，从 node.js 适配器 [@astrojs/node](https://docs.astro.build/en/guides/integrations-guide/node/) 开始。 如果您正在使用 `@astrojs/node`，您现在可以通过运行以下命令来预览您的 SSR 应用：

npm 运行预览

### 适配器API

我们将更新其他第一方 Astro 适配器以支持随着时间的推移进行预览。 适配器可以通过 `astro:config:done` 钩子中的 `setAdapter` 功能提供 `previewEntrypoint` 来选择加入此功能。 Node.js 适配器的代码如下所示：

导出默认函数() { return { name: '@astrojs/node', hooks: { 'astro:config:done': ({ setAdapter, config }) => { setAdapter({ name: '@astrojs/node', serverEntryPoint: '@astrojs/node/server.js'，预览输入点：'@astrojs/node/preview.js'，导出：['handler'], });
// 这里有更多 } } };}

Node.js 适配器中的独立模式
---------------------------------

[@astrojs/node](https://docs.astro.build/en/guides/integrations-guide/node/) 中的新功能支持 ** 独立模式**。 使用独立模式，您可以启动生产服务器，而无需自己编写任何服务器 JavaScript 逻辑。 服务器只需运行如下脚本即可启动：

节点 ./dist/server/entry.mjs

要启用独立模式，请在 Astro Config 中将 New `mode` 选项设置为 `'standalone'`：

从“astro/config”导入 { defineConfig } 从“@astrojs/node”导入nodejs
导出默认 defineConfig({ 输出："服务器", 适配器: nodejs({ mode: "standalone", }),})

有关独立模式中可用的所有选项，请参阅 [@astrojs/node](https://docs.astro.build/en/guides/integrations-guide/node/) 文档。

现有的 @Astrojs/Node 用户使用自己的 HTTP 服务器框架（如 [Express](https://expressjs.com/)）可以通过将 `mode` 选项设置为 `'middleware'` 来进行升级，以构建与以前相同的行为和 API 的中间件模式。

从“astro/config”导入 { defineConfig } 从“@astrojs/node”导入nodejs
导出默认 defineConfig({ 输出："服务器", 适配器: nodeJS({ mode: "middleware", }),})

用于顺风和打字稿配置的 HMR
------------------------------------

即使在项目的开始阶段，HMR 也至关重要。 在最近的 ASTRO 版本中，我们确保对 `astro.config.mjs` 文件的更改导致自动重新启动服务器。 今天，我们正在通过其他配置文件扩展对 HMR 的支持。

现在，编辑 [tsconfig.json](https://docs.astro.build/en/guides/integrations-guide/tailwind/) 设置（例如，添加别名）会导致 HMR 更新。

同样，[Tailwind](https://docs.astro.build/en/guides/integrations-guide/tailwind/) 配置文件更改现在也更新。 只需编辑您的 `tailwind.config.(js|cjs|mjs)` 文件，更改即可反映出无需重新启动开发服务器的情况。

在即将发布的版本中，我们将继续关注 HMR 和开发体验。

API 端点改进
--------------------------

在 API 路由中，您现在可以在 `APIContext` 上获取 `site`、`generator`、`url`、`clientAddress`、`props` 和 `redirect` 字段，这是传递给 API 路由的第一个参数。 这样做是为了使 `APIContext` 与 .astro 页面中的 Astro Global 更紧密地对齐。

例如，您可以使用 `clientAddress`（即用户的 IP 地址）选择性地允许用户的方法。

导出函数 post({ clientAddress, redirect }) { if (!allowList.has(ClientAddress)) { return redirect("/not-allowed") }}

查看 [the docs](https://docs.astro.build/en/core-concepts/endpoints/#server-endpoints-api-routes) 以获取有关新可用字段的更多信息。

Astro.Redirect 状态代码
---------------------------

1.5 中的新功能是将状态代码传递给 `Astro.redirect` 的能力。 默认情况下，它使用 `302`，但现在您可以将另一个代码作为第二个参数传递：

**/src/pages/old-post.astro**

---// 移动了此页面，将用户重定向到新的永久页面。return astro.redirect("/posts/new-post-name", 301)---

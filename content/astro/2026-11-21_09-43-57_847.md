国际化的手动路由策略
--------------------------------------------

Astro 4.6 引入了国际化的手动路由策略。 这种新策略允许您完全控制国际化 Astro 网站的路由，以防默认路由策略无法完全满足您的需求。

要启用手动路由，请将 `astro.config.mjs` 中的 `i18n.routing` 选项设置为 `manual`：

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认值 defineConfig({ i18n: { locales: ["en", "fr"], defaultLocale: "fr", routing: "manual", },});

然后[add a middleware](https://docs.astro.build/en/guides/middleware/)到你的项目来处理路由：

src/middleware.ts

从“astro:middleware”导入 { definiMiddleware }；从“astro:i18n”导入 { redirectToDefaultLocale }；
// 将所有请求重定向到 /about pageExport const onRequest = defineMiddleware(Async (context, next) => { if (context.url.startsWith("/about")) { return next(); } else { 返回 redirectToDefaultLocale(上下文, 302); }});

或者，您可以使用 `astro:i18n` 中的新 `middleware` 函数导入 Astro 自己的中间件逻辑以构建默认路由策略：

src/middleware.js

从“astro:middleware”中导入 { definiMiddleware, sequence } ;import { middleware } 来自 "Astro:i18n"; // Astro 自己的 i18n 路由中间件
导出 const userMiddleware = definiMiddleware(() => { // 此处的自定义中间件逻辑});
导出 const onRequest = sequence( UserMiddleware, Middleware({ redirectToDefaultLocale: false, prefixDefaultLocale: true }))

查看 [internationalization documentation](https://docs.astro.build/en/guides/internationalization/) 了解有关如何在国际化中使用手动路由的更多信息。

移动开发工具栏的能力
------------------------------

Astro 4.6 引入了将开发工具栏移动到屏幕底部的不同位置的功能。 如果您有一个覆盖屏幕底部的粘性标题，或者您只是希望工具栏位于其他地方，这将很有用。 开发工具栏可以帮助您，而不是妨碍您！ 感谢 [Ming-jun Lu](https://github.com/mingjunlu) 贡献了这个请求的功能！

实验：支持 CSRF 保护
----------------------------------------

Astro 4.6 为 [CSRF protection](https://developer.mozilla.org/en-US/docs/Glossary/CSRF) 添加了实验性部分支持。 此功能目前处于实验标志之下，可能会在未来的版本中发生变化。

要启用它，请在 `astro.config.mjs` 中设置 `experimental.security.csrfProtection` 选项：

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认的 defineConfig({ 实验性: { 安全性：{ csrfProtection: { 原点：true, }, }, },});

启用此设置会使Astro 执行所有现代浏览器自动传递的“origin”标头与每个 `Request` 发送的 URL 匹配的检查。 如果没有，Astro 将以 `403 Forbidden` 状态代码进行响应。

请注意，此功能仅适用于按需渲染的页面（也称为服务器端渲染）。

饼干改进
---------------------

多亏了 [Farzard](https://github.com/fshafiee)，Astro 的删除 cookie (`Astro.cookies.delete`) 的帮助程序现在允许设置更多的 cookie 属性，而不仅仅是 `path` 和 `domain` 属性。 也许是“一口大小”的变化，但绝对可以让您沉浸其中！

已弃用对旧版本 Node.js 的支持
--------------------------------------------

根据 [our Node.js support and upgrade policy](https://docs.astro.build/en/upgrade-astro/#nodejs-support-and-upgrade-policies)，此版本的 Astro 不推荐支持：

*   Node.js 18 的版本低于 18.17.1
*   Node.js 19（奇数版本）
*   Node.js 20 的版本低于 20.3.0。

正如我们的支持政策中所述，这一决定是在仔细考虑几个因素后做出的。 我们相信这一变化将为所有用户带来更稳定和安全的 Astro 体验。

您可以继续使用已弃用的 Node.js 版本，直到 Astro (V5) 的下一个主要版本。 但是，在安装 Astro 时可能会看到警告，某些功能可能无法按预期工作。

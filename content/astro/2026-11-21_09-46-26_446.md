受 next.js 启发的基于文件的路由
--------------------------------------

Astro 一直支持基于文件的基本路由，其中 `pages/` 目录中的每个文件都将成为同一 URL 的新页面。 Astro 0.19 进一步支持您的文件名中的动态 URL 参数。

受 [Next.js](https://nextjs.org/docs/routing/dynamic-routes) 和 [SvelteKit](https://kit.svelte.dev/docs#routing-pages) 的启发，您现在可以将括号添加到您的页面文件名（例如：`src/pages/[slug].astro`）以创建与许多不同 URL 匹配的动态页面。 `[...slug].astro` 还支持 catch-all 语法。

借助此新功能，您可以为您的网站添加对 URL 参数、slugs、漂亮网址、分页等的支持。

要创建动态路由，请在 Pages 目录中创建一个文件，如 `pages/posts/[slug].astro`。 在您的页面 FrontMatter 脚本中创建一个 [`getStaticPaths()`](https://docs.astro.build/reference/api-reference#getstaticpaths) 函数，并告诉 ASTRO 为该路由构建什么路径：

src/pages/posts/\[slug\]].astro

---// 告诉 astro 为您的路由构建哪些页面 "/pages/:slug"export 异步函数 getStaticPaths() { // 生成：/pages/hello-world { params: { slug: "hello-world" } }, // 生成：/pages/my-first-blog-post { params: { slug: "my-first-blog-post" } }, // 生成：/pages/astro-ftw { params: { slug: "astro-ftw" } }, // ... ]}---
<html> <head><title>我的页面</title></head> <body>URL 参数是{ASTRO.REQUEST.PARAMS.SLUG}</body></html>

Astro 是一个静态站点构建器，因此您需要告诉 Astro 为每条动态路由构建哪些页面。 手动定义路径可能感觉像样板，但提前构建页面正是使静态网站对用户而言如此快速的原因。

`getStaticPaths()` 是一个异步函数，所以你可以 - 并且应该！ – 使用它将外部数据加载到您的网站。 我们通常喜欢在我们的示例中使用 [Pokemon API](https://pokeapi.co/)，但您可能希望使用您最喜欢的无头 CMS：

src/pages/posts/\[id\].astro

// 告诉 ASTRO 为您的路由构建哪些页面“/pages/:id”导出异步函数 getStaticPaths() { // 让从 CSS 技巧的无头 CMS 中获取帖子： const css_tricks_cms = "https://css-tricks.com/wp-json/wp/v2/posts" const allposts = await fetch(css_tricks_cms).then((r) => r.json()) // 然后，从每个 post 中创建一个新页面： return allposts.map((post) => ({ // 在页面网址中设置 URL 参数 ":id" params: { id: post.id }, // 将 post 对象作为道具传递给页面 props: { post }, }))}

要了解更多信息，请查看我们关于 [Routing](https://docs.astro.build/core-concepts/routing) 和新 [`getStaticPaths()` API.](https://docs.astro.build/reference/api-reference#getstaticpaths) 的新文档，或者，如果您更愿意通过示例学习，请查看来自 Netlify 的 Cassidy Williams 的 Chris Coyier 和 This [Shopify Ecommerce example](https://github.com/cassidoo/shopify-react-astro) 中的 Great [Wordpress Headless CMS project](https://github.com/chriscoyier/astro-css-trickzz)。

如果您以前是我们原始集合 API 的用户，这个新的基于文件的路由系统会用大量友好的警告消息完全替换集合，以帮助您升级。 我们希望这个新的 API 消除了用户使用 Collections API 报告的所有常见挫败感。

`client:only` 加载指令
------------------------------

有时，UI 组件无法在服务器上呈现。 也许是因为您在其中一个依赖项中遇到了一个错误，或者您只是使用像 D3 这样的库，该库在没有浏览器 `window` 对象的情况下无法运行。

您可以尝试使用自己的静态服务器端后备 UI 包装仅浏览器的代码。 但是，大多数用户都希望在没有额外样板的情况下渲染仅浏览器的组件。 输入，`client:only`。

Astro 0.19 随附新的 `client:only` loading 指令，无需服务器端渲染即可在浏览器中为您的组件添加水分。 这为任何仅浏览器的组件提供了简单、直接的回退。

<!-- 仅在浏览器中呈现，没有占位符 HTML --><MyReactComponent client:only />

`client:only` 现在是我们的第五个指令，让您完全控制组件加载行为。 访问我们的文档网站 [check out the entire set](https://docs.astro.build/core-concepts/component-hydration#hydrate-interactive-components) 并了解有关 [Partial Hydration](https://docs.astro.build/core-concepts/component-hydration) 的更多信息。

🎉这个很棒的功能是由[Navillus](https://navillus.dev/)的[Tony Sull](https://github.com/tony-sull)贡献的。 谢谢，托尼！

`Astro.resolve()`
------------------

Astro 0.19 包含一个新的 [`Astro.resolve()`](https://docs.astro.build/reference/api-reference#astroresolve) 辅助函数来解析模板中的相对文件引用。 使用此新功能，您可以在组件内引用相对资产（如图像），Astro 将返回浏览器的正确 URL。

以前，您总是必须将文件放置在 `public/` 目录中，并按绝对 URL 路径引用它们。 `src/` 目录中的相对路径不起作用，因为它们将按原样直接发送到浏览器。 不同的页面最终会创建不同的网址：

<!-- 这在每个页面上都一样： --><img src="/logo.png" /><!-- 但这意味着不同页面上的不同： --><img src="../logo.png" />

从 Astro 0.19 开始，您现在可以使用新的 `Astro.resolve()` 辅助函数从任何相对路径创建绝对 URL 引用：

<!-- Astro 组件输入：--><img src={Astro.resolve('../images/logo.png')} /><!-- HTML 输出：--><img src="/_astro/src/images/logo.png" />

如果有帮助，您可以将 `Astro.resolve()` 视为在浏览器中执行 `new URL(yourRelativePath, import.meta.url).pathname` 的简化替代方案。

[`Astro.resolve()`](https://docs.astro.build/reference/api-reference#astroresolve) 为您的项目构建方式提供了更多选项和更多控制权。 将来，这也将解锁我们在 `src/` 目录中提供优化图像的能力。

🎉这个很棒的功能是由[Jonathan Neal](https://github.com/jonathantneal)和[Matthew Phillips!](https://github.com/matthewp)贡献的

开放集体
----------------

Astro [the first release](https://astro.build/blog/introducing-astro) 已经过去了两个多月。 在该版本中，我们概述了我们对 **一个免费的开源 Astro** 和 **长期财务可持续性**项目的承诺。 今天，我们宣布我们的第一个长期可持续性实验：

**公司和个人现在可以通过 Open Collective 赞助 Astro 的发展。 [Visit our Open Collective →](https://opencollective.com/astrodotbuild)**

我们创建了一个开放的集体，因为企业赞助是开源中为数不多的经过验证的财务可持续性途径之一。 然而，[it’s far from a perfect model.](https://stackoverflow.blog/2021/01/07/open-source-has-a-funding-problem/) 大多数贡献只用于少数流行的项目，其余的项目从未看到任何有意义的支持。 赔率对我们不利，但我们相信 Astro、我们的社区以及围绕这个项目不断增长的兴奋。

很有可能，您的公司受益于开源软件。 通过赞助 Astro 和您使用的任何其他开源项目，投资于为您的业务提供动力的技术。 **奖金：** 数以千计的开发人员每天都会在我们的自述文件和 [astro.build homepage](https://astro.build) 上看到您的徽标。

筹集的 100% 的资金直接投资于项目和我们的社区。 您可以通过在 GitHub 上阅读我们的 [FUNDING.md](https://github.com/withastro/astro/blob/main/FUNDING.md) 文档了解更多关于如何分配资金的信息。

我们将在接下来的 48 小时内向每个点击 [“Sponsor”](https://opencollective.com/astrodotbuild) 按钮的人和公司发布个人“谢谢”消息。 我们首先非常特别感谢 CCO 和 [Sentry](https://sentry.io/) 的联合创始人 [Chris Jennings](https://twitter.com/ckj) 成为我们的第一个官方赞助商！ 🎉

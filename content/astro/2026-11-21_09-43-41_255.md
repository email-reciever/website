实验：天文：ENV
------------------------

Astro 4.10 引入了一个新的实验性内置模块 `astro:env`，以便更轻松地使用环境变量。

环境变量允许您在不同环境中使用不同的值配置应用。 但这带来了很大的复杂性：

*   客户端中需要一些变量，有些变量仅在服务器上。
*   服务器变量通常是**secrets**，例如您不希望在客户端中或内联到服务器构建中的API密钥（可以访问构建输出的任何人都可以查看）。
*   某些变量是**必需的**，您的应用程序才能正常运行； 而其他是可选的增强功能。
*   变量可以在你的外壳、`.env`文件或[build config](https://vitejs.dev/config/#using-environment-variables-in-config)中定义。
*   运行时（例如 [Cloudflare](https://docs.astro.build/en/guides/integrations-guide/cloudflare/) 和 [Deno](https://deno.com/)）具有不同的 API 用于读取变量，从而创建了您需要处理的开发/生产差异。

我们构建了 `astro:env` 以提供对环境变量的更多控制和结构。 使用架构中的架构管理这种复杂性，就在您的配置中：

从“astro/config”导入 { defineConfig, envfield };
导出默认的 defineConfig({ experiment: { env: { schema: { api_port: envfield.number({ context: 'server', access: 'secret', default: 7000 }), public_dashboard_v2: envfield.boolean({ context: 'server', access: 'public', default: false }), } } }})

定义后，您可以通过从 `astro:env/server` 和 `astro:env/client` 模块导入变量来使用变量：

从“astro:env/server”导入 { public_dashboard_v2, getSecret };
if (public_dashboard_v2) { const api_port = getSecret("api_port") // number await fetch(`https://my-secret-api.com:${API_PORT}/v2`)}

客户端 `astro:env/client` 可用于组件、脚本或运行客户端代码的任何其他地方。 例如，仅在启用了功能标志时才显示增强功能：

从 'astro:env/client' 导入 { some_feature_flag };
导出默认 function() { return ( <section> { some_feature_flag && ( <div id="fancy-enhanced-feature"></div> )}
... </section> )}

当您需要读取未在架构中定义的变量时，请使用 `getSecret()`，它适用于任何运行时（Cloudflare、Node.js、deno）。

从“astro:env/server”导入 { getCret };
函数 getServerEndpoint(num: number) { return getSecret(`BACKUP_SERVER_${num}`); // 字符串 | 未定义}

`astro:env` 是一个实验特征，与所有实验特征一样，会发生变化。 感谢 [Florian Lefebvre](https://github.com/florian-lefebvre) 成为 RFC 的拥护者并提供实现！ 在 [RFC](https://github.com/withastro/roadmap/pull/894) 上留下您的反馈，以帮助引导其发展，因为此新功能的稳定性已稳定。

重写所有 HTTP 方法
-----------------------------

重写是 4.9 中发布的新实验功能。 第一个版本针对 `GET` 请求，最常见的重写情况。 现在在 4.10 中，通过克隆初始请求，可以使用重写来更改任何请求的路由。

这是一个在中间件中重写的示例，以将您引导到版本化 API 的默认版本：

从“astro:middleware”导入 { definiMiddleware }；
导出 const onRequest = defineMiddleware(({ request, url }, next) => { if(request.method === 'post' && url.pathname === '/api') { return next('/api/v2'); }});

重写时，会创建一个指向新 URL 的新请求。 将现有的标头和正文复制到新请求中。

嵌入天文
----------------

在 4.9 中，我们引入了容器 API，这是一种在 Astro 框架的上下文之外渲染 Astro 组件的新方法。 我们最初的重点是 ***testing** 故事：使用容器 API 来测试 Astro 组件。 创建容器，使用 `container.renderToString()` 渲染组件，并检查生成的 HTML。

我们一直都知道人们会以其他方式使用容器 API，我们并不打算让人失望。 在 4.10 中，您现在可以使用此 API 来渲染使用 `astro build` 构建的任何组件，这意味着您可以在 Astro 站点之外使用它们！

为了演示这是如何工作的，我们构建了一个 [Astro-in-PHP demo](https://github.com/matthewp/astro-in-php-example) 应用程序。 不要评判代码，PHP 专家！ 😅

容器部分看起来像这样：

从 './dist/server/all.mjs' import { renderers } import * as components from './dist/server/renderers.mjs';import { manifest } from './dist/server/entry.mjs';从'astro/container'导入{experiment_AstroContainer作为AstroContainer};
const container = await astrocontainer.create({ manifest, renderers, resolve(s) { const found = manifest.entryModules[s]; if(found) { return `/astro-project/dist/client/${found}`; } return found; }});
const html = await container.RenderToString(components.ReactWrapper);
// 登录到控制台，以便 PHP 将 HTML 注入其 page.console.log(html);

容器 API 是低级的，它反映了 Astro 在内部所做的以呈现其自己的路线。 我们渴望社区建立在粗糙边缘平滑并提供更简单的嵌入Astro的方式的集成。 亲自尝试，并在您添加 Astro 的任何地方向我们展示！

容器 API 助手
----------------------

在渲染 UI 框架组件时，我们还添加了一些方便的帮助函数，用于在 Vite 环境中使用容器 API（`vitest`、Astro 集成等）。

这意味着您不再需要知道（或弄清楚！）每个包的客户端和服务器呈现脚本的单独的直接文件路径。 新的 `getContainerRenderer()` 提供了我们官方渲染器集成包（`@astrojs/react`、`@astrojs/preact`、`@astrojs/solid-js`、`@astrojs/svelte`、`@astrojs/vue`、`@astrojs/lit` 和 `@astrojs/mdx`）中的适当渲染脚本。 请务必同时升级您的集成以实现此新功能！

新 `astro:container` 虚拟模块中的 `loadRenderers()` 函数将为您从每个包中加载这些渲染器：

从“Astro/Container”导入{experiment_AstroContainer };从'../src/components/reactwrapper.astro'import { loadRenderers }导入ReactWrapper "Astro:Container";从"@Astrojs/React"导入{ getContainerRenderer };
test('reactWrapper with React renderer', async () => { const renderers = await loadRenderers([getContainerRenderer()]) const renderers = [ { name: '@astrojs/react', clientEntryPoint: '@astrojs/react/client.js'，ServerEntryPoint：'@AstroJS/react/server.js', }, ]; const container = await astrocontainer.create({ renderers, }); const result = await 容器.renderToString(ReactWrapper);
expect(result).tocontain('counter'); expect(result).tocontain('count: <!-- -->5');});

此类型更改为 `renderers` 还将允许无 Vite 环境手动加载和传递渲染器模块。

有关详细信息，请参阅 [Container API docs](https://docs.astro.build/en/reference/container-reference/)。

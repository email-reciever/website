我们很高兴宣布 [Vercel](https://vercel.com/) 作为 Astro 的新官方托管合作伙伴！

Astro 是一个 JavaScript Web 框架，用于构建以内容为中心的网站。 Astro 的 [next-gen frontend architecture](https://docs.astro.build/en/concepts/islands/) 会自动减少页面上未使用的 JavaScript，同时最大化 [Core Web Vitals](https://web.dev/vitals/) 和其他性能指标。

成千上万的 Astro 开发人员已经在利用 Vercel 的 [frontend cloud](https://vercel.com/resources/the-frontend-cloud-advantage) 平台和 [generous free tier](https://vercel.com/pricing) 进行托管。 这种新的合作伙伴关系将为 Astro 开发人员提供更多的协作、更多功能和更好的体验。

Vercel 还将每月赞助 5,000 美元用于 Astro 正在进行的开源维护和开发。 新的赞助资金将直接投资于我们的开源社区和维护，使所有人受益。

以下是Vercel的Lee Robinson对新闻的看法：

> Vercel 相信支持开源和所有 Web 框架。 在过去的两年里，我们一直很喜欢支持 Astro，并且在看到 Astro 在 Vercel 上的持续增长之后，我们很高兴能够进一步推进我们的合作伙伴关系。

— [Lee Robinson](https://twitter.com/leerob)，开发人员体验副总裁

Lee 和 [Fred K. Schott](https://twitter.com/FredKSchott)（Astro 共同创作者和项目 Steward）有机会坐下来讨论 Astro、Vercel 的未来以及这种新的合作伙伴关系对网络意味着什么。

在Vercel上解锁Astro
--------------------------

[Vercel](https://vercel.com/docs) 一直是 Astro 开发人员的绝佳选择。 去年，Vercel 为新的 Astro 项目推出了零配置设置 [automatic framework detection](https://vercel.com/blog/build-output-api)。 这个简单的更改为 Astro 用户节省了无数小时，并通过优化的站点配置为每个人提高了默认性能。

我们很高兴地宣布为部署到 Vercel 的 Astro 用户提供一套新功能，如今可用。 由于我们与 Vercel 的持续合作和赞助，这些功能成为可能。

### 边缘中间件

Astro [middleware](https://docs.astro.build/en/guides/middleware/) 现在使用 Vercel 的 [Edge Middleware](https://vercel.com/docs/concepts/functions/edge-middleware) 在边缘运行。 Edge 中间件尽可能靠近您的用户，这意味着您的用户的响应时间更快。 Edge Middleware 还允许您自定义在服务器上运行的每个请求和响应，从而可能减少发送到源服务器的流量。

Astro 用户现在可以：

*   支持多区域URL方案，将用户重定向到其本地化URL。
*   验证用户令牌并阻止未经认证的流量到服务器。
*   从 [edge-distributed global database](https://vercel.com/docs/storage/edge-config) 加载数据。
*   在代码中定义缓存策略，而不是配置。
*   在响应HTML从服务器返回时最小化响应HTML。

可以通过在 Astro 配置文件中的 Vercel 适配器中添加 [`{edgeMiddleware: true}`](https://docs.astro.build/en/guides/integrations-guide/vercel/#vercel-edge-middleware) 来启用边缘中间件。 在未来版本中，此选项可能成为默认行为。 查看 [Vercel documentation](https://vercel.com/docs/functions/edge-middleware) 以了解有关 Edge 中间件如何在 Vercel 上工作的更多信息。

### 无服务器代码拆分

由于每条路由上的无服务器代码拆分，Astro Server 应用程序现在在 Vercel 上的运行速度更快。

以前，Astro 会将您的整个服务器应用程序构建到单个 JavaScript 文件中。 这简化了我们的部署，但以牺牲无服务器性能为代价。 通过将整个应用程序捆绑在一个 JavaScript 文件中，响应时间（特别是冷启动时间）将随着代码库的增长而被未使用的代码所压倒。

将您的应用程序拆分为更小的函数可以通过删除每条路由不需要的未使用代码来提高响应时间。 部署各个路由还允许像 Vercel 这样的主机更好地分布您的工作负载跨多个较小的功能。

您可以通过在 Astro 配置文件中指定 [`{ functionPerRoute: true }`](https://docs.astro.build/en/guides/integrations-guide/vercel/#per-page-functions) 来启用此功能。 几天后，此选项将与即将发布的 Astro 3.0 一起成为默认值。

### Vercel上的图像优化

Astro 站点现在可以连接到 Vercel 的内置图像优化服务，以在 Astro 3.0 中为按需图像优化（也可在 Astro 2.x [behind an experimental flag](https://docs.astro.build/en/guides/images/) 中提供）。

通过 Astro 的内置 `<Image />` 组件和低级图像 API，可以在所有平台上实现图像优化。 Astro 开发人员可以在他们的网站上使用图像，而不必担心意外忘记优化图像。 在 `img` 标记上使用智能高度和宽度属性注释也可以自动阻止累积布局偏移。

作为构建的一部分，静态网站已经提前优化了您的图像。 但是Astro Server应用程序通常还需要将Astro的内置图像优化库[Sharp](https://sharp.pixelplumbing.com/)运送到生产中进行按需图像优化。 通过利用 Vercel 的内置图像优化服务，开发人员可以简化部署复杂性、提高图像性能并降低计算成本。

您可以通过在 Astro 配置文件中指定 [`{ imageService: true }`](https://docs.astro.build/en/guides/integrations-guide/vercel/#imageservice) 来启用此功能。 在未来版本中，此选项可能成为默认行为。

### 为每个人改进Astro

我们通过利用它们的 [Build Output API](https://vercel.com/docs/build-output-api/v3) 与 Vercel 合作构建了所有这三个功能。 我们的目标是将它们带入更多的托管平台。 这篇文章中提到的所有内容都是以与平台无关的方式设计的，因此任何人都可以采用这些相同的功能并在自己的托管平台上启用它们。

如果您有兴趣为您的托管平台启用这些功能，您可以 [reach out on Discord](https://astro.build/chat/)。

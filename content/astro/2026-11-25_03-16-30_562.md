Astro v0.21.0 将会是我们迄今为止最大的版本发布。从高层次上看，它包括：

* [一个新的构建引擎，powered by Vite](#hello-vite)
* [一个新的 WASM 编译器，使用 Go 编写](#hello-wasm)
* [全新的功能，例如 Components-in-Markdown](#components-in-markdown)
* [一个新的系统，用于通过 HMR 实时更新 HTML](#hmr-meet-html)

您可以今天就尝试我们的最新版本 [在浏览器中](https://gitpod.io#snapshot/5e7cf2f1-8108-4fa5-99d3-ed8de70d8c23) 或者在您的机器上新建一个项目目录，并运行 `npm install astro@next--compiler`。

Astro 正在迅速成为构建更快、更注重内容的网站的生产就绪框架。为了庆祝这一里程碑，我们在这里提供一些亮点和 Astro v0.21.0 及以后版本的详细信息。

## Hello, Vite!

Astro 0.21 即将获得内部构建引擎升级，使用 [Vite](https://vitejs.dev) 取代 Snowpack。

我们进行了一些早期的Vite实验，并且非常佩服。Vite维护良好，文档齐全，稍微快一点，错误消息很好，并且在多个框架中获得了明确的社区认可。SSR处理可能有点问题，但Vite团队知道这一点并正在积极地解决它。

所以，现在，当Evan You在推特上发布关于[some great performance optimization](https://twitter.com/youyuxi/status/1440718351802646550)时，你可以肯定同样的速度也会来到Astro。

反之亦然：我们现在可以将修复和改进贡献回给更大的Vite社区。当我们在Astro中修复SSR bug（如[添加对ESM-only npm包的支持](https://github.com/vitejs/vite/pull/5197)）时，我们也为所有其他Vite用户修复了它，包括[SvelteKit](https://kit.svelte.dev/docs#routing-endpoints)。

还有一个选择 Vite 的巨大优势：Rollup 插件。从 v0.21.0 开始，您将能够将整个 Rollup 插件生态系统连接到 Astro。仅需几个简单的插件，即可启用新的功能，如 [图像优化](https://github.com/JonasKruckenberg/imagetools/tree/main/packages/vite) 和 [图标加载](https://github.com/antfu/unplugin-icons)。魔术！

从 Snowpack 切换到 Vite 对一些人来说可能是一个惊喜：Drew 和我都是这两个项目的维护者。这对我们来说是一个 [艰难的决定](https://dev.to/fredkschott/5-more-things-i-learned-building-snowpack-to-20-000-stars-5dc9)。但最终，在使用了这两个工具之后，我可以自信地说 Vite 将是 Astro 未来的一个伟大选择。

## 你好，WASM！

Astro 0.21 具有另一个巨大的低级改进：全新的 [@astrojs/compiler](https://github.com/withastro/astro-compiler-next)。Astro 的新编译器是用 Go 编写的，并以 WASM 形式分发。你可以直接在浏览器中运行它，也可以在 Node.js 和 Deno 的服务器上运行。

新的 [@astrojs/compiler](https://github.com/withastro/astro-compiler-next) 解锁：

* **灵活性：** 使用WASM在任何地方运行编译器。
* **速度：** 利用Go的编译语言性能更快地构建站点。
* **稳定性：** 编写自己的编译器使我们能够修复一些长期存在的bug。

您可以在浏览器中通过 <https://astro.build/play> 立即使用新编译器。这是一个REPL示例，展示了拥有快速、可在任何地方运行的编译器所带来的可能性。

向 [Nate Moore](https://bsky.app/profile/natemoo.re "在Bluesky上关注Nate Moore") 致敬，他在这个项目中做出了令人难以置信的工作。

## Markdown中的组件

我们最受欢迎的功能 **_绝对是_** 直接在Markdown中使用组件的能力。在数月的工作后，我们很高兴地宣布，这个功能终于要来了。

从v0.21.0开始，您可以通过可选的 `setup` 脚本在Markdown前置内容中导入组件。一旦导入，您的组件就可以在页面的任何地方使用：

```markdown
---title: "Astro 0.21 Early Preview"setup: |  import Logo from '../components/Logo.astro';  import ReactCounter from '../components/Counter.jsx';---
# Astro now supports components in Markdown!
<Logo />
- Back to markdown here.- Supports static Astro components.- Supports dynamic React/Vue/Svelte components!
<ReactCounter start={0} client:load />
```

这个新的 `setup` 脚本旨在实现最大程度的灵活性。我们将继续改进这个API，计划支持默认组件、默认布局和Markdown组件覆盖。

## HMR，见见HTML

从 v0.21.0 开始，Astro 将支持 Astro 组件和页面的完全 HMR。更改代码库中的任何 `.astro` 文件，并观察开发服务器在不需要完整刷新页面且不丢失任何客户端状态的情况下更新页面。

Astro一直支持像React、Preact、Svelte、Vue和Solid.js这样的客户端JavaScript组件的强大HMR更新。但是为Astro添加这一功能是一个有趣的挑战，因为Astro组件只是静态HTML。我们的“零JavaScript”方法意味着没有“Astro运行时”可以用于更新。我们不得不想出创造性的解决方案。

现在，Astro的开发服务器将HTML更新发送到浏览器，然后运行一个小脚本来比较这些更新与当前页面。这创建了一个更细粒度的、基于组件的HMR更新，这不会影响页面的其他部分。

两周前，我们 [announced experimental support for server-side rendering (SSR) with Netlify](https://www.netlify.com/blog/astro-ssr) 作为我们在 [Netlify Functions](https://docs.netlify.com/functions/overview/) 的发射合作伙伴。 今天，我们宣布在 Netlify 的新 [Edge Functions](https://www.netlify.com/products/#netlify-edge-functions) 平台上支持 SSR。 Edge 函数今天上线了，Astro 有第 1 天的支持。

使用 SSR 和 Astro，您可以：

*   构建大型的、难以使用 SSG 扩展的 CMS 支持站点（静态站点生成）。
*   构建需要身份验证或持久状态的应用程序，例如电子商务后端。
*   仅在需要时才使用带有Sprinkles的类似HTML的语法。

使用 **Edge 渲染**，您可以让 SSR 更接近您的用户，更快地将这些第一个字节带到浏览器。 结合在边缘提供静态资产，这为您提供了最佳的网络性能。 Astro 致力于使高性能的内容站点易于实现，而 Netlify 的新 Edge Functions 平台是当今部署 Astro SSR 应用程序的理想场所。

要开始使用，请安装 Netlify 适配器：

npm 安装 @astrojs/netlify

然后在 `astro.config.mjs` 文件中添加适配器：

从“astro/config”导入 { defineConfig } 从“@astrojs/netlify/edge-functions”导入 Netlify
导出默认 defineConfig({ 适配器：Netlify(),})

从 Netlify 函数迁移
--------------------------------

Astro 已经在基于 Node.js 的无服务器运行时 Netlify 函数上可用。 借助边缘功能，您可以获得更好的性能，我们试图让切换变得尽可能容易。

### 兼容性

Netlify Edge 函数在 [Deno](https://deno.land/) 之上运行，但 _MOST_ ASTRO 应用程序不需要更改代码即可部署到新环境。 Netlify 适配器负责编译和捆绑您的源代码，以便它可以在 Deno 上运行。

如果您使用依赖于 Node.js 内置模块的依赖项，则可能无法摆脱 Netlify 函数。 如果是这样，Netlify 函数对于大多数用例来说仍然是一个很好的平台，并为 Node.js 提供了标准的 Node.js 运行时支持。

如果使用 `<Markdown />` 组件，它目前不能在非节点环境中运行。 与此同时，一种可能的替代方案是使用 `.md` 页面。

### 迁移

首先，像这样升级到最新的 `@astrojs/netlify`：

npm 安装 @astrojs/netlify@latest

然后，更新 `astro.config.mjs` 以导入 Edge Functions 适配器：

从“astro/config”导入 { defineconfig }； 从 '@astrojs/netlify/functions' 导入 Netlify； 从 '@astrojs/netlify/edge-functions' 导入 Netlify；
导出默认 defineConfig({ 适配器：Netlify()});

应该就是这样！ 下一次构建时，它将生成与边缘函数兼容的 SSR 构建，然后可以使用 `netlify deploy --build` 进行部署。

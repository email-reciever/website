今天我们发布了Astro 4的第一个测试版！ 那些喜欢冒险的人可以安装新的测试版，查看我们正在进行的升级文档，并将您发现的任何错误报告给 [Astro discord](https://astro.build/chat)。

Astro 4 会发生什么
--------------------------

我们正在发布 Astro 4 以跟上我们的内部构建工具 [Vite](https://vitejs.dev/) 的最新状态。 Astro 4 包括上个月刚刚发布的最新版本的 [Vite 5](https://vitejs.dev/blog/announcing-vite5)。

由于 Vite 5 是 _also_ 一个小的专业，大多数项目都可以升级到 Astro 4，而对您的代码进行最小的更改（如果有的话）。

此外，在 Astro 4 中，我们计划将我们在过去几个月中一直在研究的一些新功能排除在实验状态之外，并将它们标记为稳定。 继续关注更多！

试用测试版
--------------------

您可以通过运行我们的新 `@astrojs/upgrade` 软件包在现有应用中试用测试版。 此 CLI 工具将自动安装正确版本的 Astro 以及您安装的任何官方 Astro 集成。

npx @astrojs/升级 betapnpm dlx @astrojs/upgrade betayarn dlx @astrojs/upgrade beta

或者，您可以手动安装 `astro@beta` 软件包。 请务必更新您安装的任何 `@astrojs/*` 集成！

npm install astro@betapnpm install astro@betayarn install astro@beta

如果启动一个新项目，您也可以通过运行来尝试测试测试：

npm create astro@latest ----ref next

同样，用您最喜欢的包管理器代替。 我们尚未完成升级指南，但您已经可以在 [Astro 4.0 upgrade guide pull request](https://github.com/withastro/docs/pull/5481) 中找到最重要的更改。 您还可以关注其相关问题，即跟踪所有重大更改。

太空人 3.6
----------

此外，我们最近发布了 `<ViewTransitions />` 路由器中的新事件以及 `prefetch` 在缩小的数据场景中的回退的 Astro 3.6。

### 查看过渡事件

Astro 3.6 将这三个新事件添加为 `<ViewTransitions />` 路由器生命周期的一部分：

`astro:before-preparation` 在 _preparation_ 步骤之前运行，新页面的内容被加载。 这可用于覆盖加载新页面的行为，例如，显示加载旋转器。

`astro:after-preparation` 内容加载后运行。 如果添加了一个作为 `astro:before-preparation` 的一部分，这可以用于 _stop_ 加载微调器。

`astro:before-swap` 在 _swap_ 步骤之前运行，其中旧页面的内容被替换为有利于新页面的内容。 此事件包括 `event.newDocument` 属性，您可以修改的 `Document`。 此事件的一种用例是使用 `localStorage` 存储明暗模式首选项来设置暗模式类名。

查看 [this demo](https://events-3bg.pages.dev/) 显示使用新事件的可能情况，并查看文档以获取有关 [all five lifecycle events](https://docs.astro.build/en/guides/view-transitions/#lifecycle-events) 的更多信息。

### 预取回退

以前，当用户处于慢速连接或启用了数据保护程序首选项时，预取完全禁用。 在 3.6 中，我们将预取策略更改为 `tap`：当用户开始单击链接但在他们发布之前。 这让我们在获取下一页时有了一点点开始，但前提是我们很确定用户打算点击。

### 错误修复

此版本中包含其他错误修复。 查看 [release notes](https://github.com/withastro/astro/blob/main/packages/astro/CHANGELOG.md#360) 以了解更多信息。

**🎃 Astro 5.15 为适配器带来了自动 Netlify 偏斜保护、粒状字体预加载过滤和强大的新 API。

探索此版本中的新功能：

*   [**Netlify skew protection**](#netlify-skew-protection)
*   [**New adapter APIs for customizing headers and assets**](#new-adapter-apis-for-customizing-headers-and-assets)
*   [**Granular font preload filtering**](#granular-font-preload-filtering)

    # 手动：npm安装astro@latestpnpm升级astro --latestyarn升级astro --latest

Netlify 偏斜保护
------------------------

Astro 5.15 为 Netlify 部署引入了自动偏斜保护，确保您的站点的客户端和服务器版本保持完全同步。

部署偏差是当用户在服务器运行较新的代码时加载较旧的客户端资产时会发生的一个狡猾的问题。 这可能会导致难以追踪的细微错误和意外行为。 借助 Netlify 偏斜保护，这已成为过去。

部署到 Netlify 时，Astro 会自动将您的部署 ID 包含在所有资产请求和 API 调用中。 这允许 Netlify 自动检测和处理任何版本不匹配——无需配置。 即使在快速部署或用户处于可能跨部署边界加载资产的慢速连接时，您的站点也能正常工作。

如果您在应用程序中进行自定义提取请求，您还可以直接访问部署 ID：

const deployID = import.meta.env.deploy_id;const 响应 = await fetch('/api/endpoint', { headers: { 'x-deploy-id': deployID, },});

Netlify Skew Protection 可在 Astro 的所有核心功能中无缝运行，包括视图转换、服务器岛、预取和 Astro 操作，让您在整个站点中都能安心。

用于自定义标头和资产的新适配器 API
-----------------------------------------------

在幕后，Netlify 的 Skew Protection 由一组新的核心 API 提供支持，这些 API 允许适配器在 Astro 的系统中自定义标头和资产查询参数。

Astro 现在在 `AstroAdapter` 接口中公开了 `client` 配置选项，允许适配器指定：

*   **`internalFetchHeaders`** - 应自动包含在 Astro 的核心系统进行的所有获取调用中的自定义标头（操作、视图转换、服务器岛和预取）
*   **`assetQueryParams`** - 应自动附加到资产 URL 的查询参数

这为托管平台提供了实现复杂功能所需的挂钩，无需开发人员手动配置。

以下是适配器在 `astro:config:done` 钩子中配置这些选项的方式：

示例适配器/index.ts

导出默认函数 exampleAdapter() { return { name: 'example-adapter', hooks: { 'astro:config:done': async ({ setAdapter }) => { setAdapter({ name: 'example-adapter', ServerEntryPoint：'example-adapter/ssr.js'，客户端：{internalFetchHeaders：() => { const deployID = process.env.deploy_id; if (deployID) { return { 'x-deploy-id': deployId }; } return {}; }, AssetQueryParams: process.env.deploy_id ? new UrlSearchParams({ deployId: process.env.deploy_id }) : undefined, }, }); }, }, };}

Vercel 适配器现在也受益于这些新的 API。 以前，Vercel 的 Skew Protection 有一些限制和错误，它们无法在 Astro 的所有功能中正常工作。 通过此更新，当启用 `VERCEL_SKEW_PROTECTION_ENABLED` 环境变量时，Vercel 适配器现在使用相同的新 API 来提供可靠的偏斜保护，使其与 Netlify 的功能奇偶校验。

粒状字体预加载过滤
------------------------------

实验字体 API 现在支持对哪些字体变体进行预加载的细化控制。 以前，您只能选择预加载字体的所有变体或根本没有。 现在，您可以准确指定应预加载哪些权重、样式和子集，通过仅下载实际使用的内容来帮助您优化性能。

使用 `<Font>` 组件时，可以将 `preload` 数组传递给过滤器变体：

---import { font } 来自 'astro:assets';---
    <Font  cssVariable="--font-roboto"  preload={[    { subset: 'latin', style: 'normal' },    { weight: '400' },  ]}/>

此示例将仅预加载正常样式的拉丁子集和权重为 `400` 的任何字体文件。 对于可变权重字体（支持 `100`-`900` 等范围），Astro 将它们与您的过滤条件进行智能匹配。 请求权重 `400` 将包括一个涵盖 `100`–`900` 范围的可变字体，因为它支持该权重。

您可以过滤以下任意组合：

*   **`weight`** - 特定字体重量（例如，`'400'`、`'700'`）
*   **`style`** - 字体样式（例如，`'normal'`、`'italic'`）
*   **`subset`** - 字体子集（例如，`'latin'`、`'cyrillic'`）

这使您可以对字体加载策略进行细粒度控制，从而减少不必要的下载，同时保持设计灵活性。

其他改进
-------------------

*   **堆栈跟踪的复制按钮** – 错误叠加层现在包含一个复制按钮，可以轻松地与 LLMS 和 AI 编辑器共享堆栈跟踪，以加快调试速度。 感谢 [Deveesh Shetty](https://github.com/dev-shetty) 贡献此功能！ （[#14489](https://github.com/withastro/astro/pull/14489)）
*   **Wrangler Configuration Scaffolding** – 当添加 Cloudflare 集成时，`astro add` CLI 现在会自动搭建 `wrangler.jsonc`。 感谢 [Oliver Speir](https://github.com/OliverSpeir) 在更新的指导下更新我们的 Cloudflare 文档！ （[#14564](https://github.com/withastro/astro/pull/14564)）
*   **node.js 18 deprecation** – Vercel 适配器现在将 Node.js 18 标记为已弃用，转而支持较新的 LTS 版本。 感谢 [Jacob Lamb](https://github.com/jacobdalamb) 的贡献！ （[#14555](https://github.com/withastro/astro/pull/14555)）

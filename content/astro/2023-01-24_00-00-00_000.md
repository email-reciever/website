**Introducing Astro 2.0!** [Astro](https://astro.build/) 是一个流行的 Web 框架，用于构建高性能、以内容为中心的网站。 我们的下一代前端架构（称为 [Astro Islands](https://docs.astro.build/en/concepts/islands/)）可以优化您的站点以使用您已经喜欢的 UI 框架加载 [33% faster with 90% less JavaScript](https://twitter.com/jlengstorf/status/1442707241627385860)，例如 React、Svelte 和 Vue。

**ASTRO 2.0 是第一个为 Markdown 和 MDX 提供完整类型安全的主要 Web 框架。 这个新版本是任何在网络上使用 Markdown 的人的游戏规则改变者。

发布亮点的完整列表包括：

*   [Content Collections:](#automatic-type-safety-for-markdown--mdx) Markdown & MDX 的自动类型安全。
*   **[Hybrid Rendering:](#hybrid-rendering-static-meets-dynamic)** 静态？ 动态？ 获得两全其美。
*   **[Redesigned Error Overlays](#errors-redesigned)**
*   **[Improved Dev Server (HMR)](#dev-server-optimizations)**
*   **[Vite 4.0](#vite-40)**
*   **[A New Public Roadmap](#the-astro-open-roadmap)**

Astro 2.0 今天在 NPM 上提供。 运行 `npm i astro@latest` 升级现有项目，或访问 [astro.new](https://astro.new/) 从头开始（在浏览器中）启动新项目。

Markdown 和 MDX 的自动类型安全
---------------------------------------

![](/_astro/banner-content-collections.DvnGUZWy_Z1FxSBF.webp)

Astro 2.0 旨在解决现代 Web 开发中被忽视的问题：**使用 Markdown/MDX 很难。**

当您有数百个不同的文件（博客文章、时事通讯、产品）时，可能无法控制一致性。 一件丢失或拼写错误的 FrontMatter 财产和繁荣！ 您的整个网站可能会因无益的 `cannot read undefined` 错误而崩溃，供您修复。

Astro 2.0 使用我们新的 **Content Collections API 重新构想了开发者体验。

*   **模式验证**
*   **SEO 最佳实践**
*   **信息性错误信息**
*   **自动生成类型**
*   **内联类型错误，自动完成等！**

要了解有关内容收藏的更多信息，请查看我们的精选帖子：[Introducing Content Collections: Type-Safe Markdown in Astro 2.0](/blog/introducing-content-collections/)。

混合渲染：静态满足动态
------------------------------------

![](/_astro/banner-hybrid-rendering.BFXaelCa_ZmuriO.webp)

近一年来，Astro 让您在静态 (SSG) 和服务器 (SSR) 构建输出之间进行选择。 静态网站提供了令人难以置信的性能，但它们缺乏为每个请求生成 HTML 按需的能力。

Astro 2.0 结合了**混合渲染，将两全其美的结合在一起。** 混合渲染让您可以选择预渲染某些页面而不放弃您部署的服务器。 PreRendering 会提前构建页面，以便所有这些请求都立即加载。

将静态和动态内容混合在一起，为 Astro 开启了全新的可能性，包括：

*   提高热门页面的渲染性能
*   提高大型站点的构建性能
*   将 API 添加到您现有的静态站点

在我们的 [server-side rendering guide](https://docs.astro.build/en/guides/server-side-rendering/#hybrid-rendering) 中了解有关混合渲染的更多信息。 本周晚些时候回来查看与 Nate Moore 的混合渲染世界更深入的探索。

**错误，重新设计**
-----------------------

![](/_astro/banner-error-overlay.4d0L0Hqx_NtI7X.webp)

错误叠加层是Astro提供的最重要的UI部分。 当出现问题时，这是您作为开发人员看到的第一件事。 当你去调试一个问题时，它通常是你开始的第一个地方。

Astro 2.0 用全新的 Astro 外观和感觉完全重新设计了错误体验。 此外，新的错误叠加层突出了比以前更多的信息，例如解决错误的有用提示以及跳转到您最喜欢的编辑器中的代码的按钮。

开发服务器优化
-------------------------

![](/_astro/banner-improved-hmr.szxudqAX_KtKPC.webp)

Astro 2.0 强调了几个月的投资，以提高 Astro Dev 服务器的性能和可靠性，尤其是在 **热模块重新加载 (HMR)** 方面。

在过去的几个月中，Astro 用户从这些改进的逐步发布中受益，最终在今天的版本中达到顶峰。 Astro 2.0 标志着所有这些改进首次在一个版本中同时使用。

维特 4.0
---------

![](/_astro/banner-vite-4.D8Zudzvw_Z2vzJpl.webp)

Astro 2.0 包括对我们最重要的内部依赖项之一的重大内部升级：Vite。

Vite 是为 Astro 的内部构建引擎提供动力的重要工具。 Vite 4.0 - Vite Team 的最新版本 - 包括一些使所有 ASTRO 用户受益的重要改进和错误修复。

Vite 4.0 中的一些改进来自我们自己的队友 [Bjorn Lu](https://github.com/bluwy)，他也是 Vite 项目的维护者。 他对 Astro 提高 Vite 性能的研究导致 [several](https://github.com/vitejs/vite/pull/11454) [pull](https://github.com/rollup/rollup/pull/4762) [requests](https://github.com/vitejs/vite/pull/11460) 到 Vite 4.0，现在所有 Vite 用户都可以从中受益。 谢谢，比约恩！

天文开放路线图
-----------------------

![](/_astro/banner-astro-roadmap.Cj80MqL0_1dAJbI.webp)

最后但并非最不重要的一点是，我们很高兴正式为 Astro 推出新的 [Public Roadmap](https://github.com/orgs/withastro/projects/11)。

Astro 一直有一个开放的 RFC 流程。 任何人都可以为某个功能提出新的想法，我们的社区将在每周的 Discord 通话中开会讨论这些想法。

然而，在实践中，我们的 RFC 流程没有为贡献者提供足够的指导。 RFC 是冗长而详细的文档，需要付出相当大的努力来创建。 有些人发现这个过程令人生畏。 其他人创建 RFC 只是为了后来意识到他们的想法要么是不可行的。 这两种情况都让我们感到沮丧。

我们的新路线图通过降低新想法和建议的进入门槛来解决这些缺点。 在编写正式的 RFC 之前，可以讨论甚至接受（阅读：优先）新想法。 Astro 维护人员还将在此过程中更早地提供指导，以帮助解决问题并讨论功能优先级。

您可以在 [withastro/roadmap](https://github.com/withastro/roadmap) 仓库中阅读有关我们新路线图的更多信息。 如果您有 Astro 的功能请求，请前往 repo 进行参与。

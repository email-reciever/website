实验：服务器岛
-----------------------------

2021年，Astro将[islands architecture](https://astro.build/blog/introducing-astro/)的想法带入主流，允许您创建交互式客户端组件的“岛屿”，而您的大部分页面都是静态生成的。

使用 **Server Islands**，我们将同样的架构扩展到服务器。 服务器岛使高性能静态 HTML 和动态服务器生成的组件变得容易。

在任何给定的网页中，您可能拥有以下内容：

*   完全静止且永不改变。
*   动态地由一个不频繁但比你部署的更频繁的数据库支持。
*   个性化内容，为个人用户量身定制。

目前，您必须为所有这些类型的内容选择一种缓存策略，如果页面是登录体验，通常意味着根本没有缓存。 现在，使用服务器岛，您可以两全其美。

![A diagram showing the server island population parts of the page from the server.](/_astro/dark-mode-server-islands-diag.CCPm1I4W_1F1hFI.webp)

服务器岛用于最动态的内容； 用户头像、购物车和产品评论等个性化内容。 当这些组件被推迟时，您可以更积极地缓存页面本身。

这意味着用户（无论是否登录）都会立即看到页面中最关键的部分，因为他们在 Edge CDN 上缓存。 在加载动态岛之前，回退内容将在很短的时间内可见。

每个岛都独立于其他岛屿加载； 这意味着较慢的岛屿，例如连接到传统后端的一个较慢的岛屿，不会延迟其余的个性化内容被看到和交互。

Server Islands 不是像 PPR 那样在服务器上启动请求，而是从浏览器执行。 这意味着虽然服务器岛较早绘制，但它们可能比 PPR 晚完成。

服务器岛和 PPR 在这些站点中效果最好，其中主页面内容可以被边缘缓存。 它们适用于电子商务，但可能不是您想要用于社交网络提要的东西。 由于页面被边缘缓存，等待岛屿请求的时间很小。

最终，我们有信心这种权衡是 ASTRO 用户在用户体验和传递的核心 Web Vitals 中的最佳整体性能，而无需任何特殊的后端基础设施或支持即可开始使用。

### 便携性

我们在考虑便携性的情况下建造了**服务器岛**。 它不依赖于任何服务器基础结构，因此它可以与您拥有的任何主机一起工作，从 Docker 容器中的 Node.js 服务器到您选择的无服务器提供商。

我们的实现主要发生在构建时，组件内容被换成一个小脚本，几乎可以装入推文中。

标有 `server:defer` 的每个岛屿都被划分为它们自己的特殊路线，脚本在运行时获取。 权衡的是，如果它依赖于边缘处理，该岛并没有像它那样获得领先的渲染，但我们认为性能数据有利于我们迄今为止采取的更简单的方法。

### 试用服务器岛

我们仍在努力完善该功能，但您可以通过在 Astro 4.12 中启用该功能来尝试 Astro Server Islands：

从“astro/config”导入 { defineConfig }；从“@astrojs/netlify”导入 netlify；
导出默认 defineConfig({ 输出：'hybrid'，适配器：netlify()，
实验：{serverIslands: true, },})

顾名思义，服务器岛在服务器上运行，因此您需要使用 `'server'` 或 `'hybrid'` 输出。 启用该功能后，您可以使用 `server:defer` 指令在任何组件上使用它们：

    <Avatar server:defer>  <GenericUserImage slot="fallback" /></Avatar>

当 Astro 构建您的网站时，除了您用 `slot="fallback"` 标记的内容外，它将省略组件并在其位置注入脚本。 当页面在浏览器中加载时，这些组件连同您传递给它们的任何道具，将被请求到呈现它们并返回 HTML 的特殊端点。

服务器岛是普通的 Astro 组件，可以使用您期望的任何功能，如中间件、插槽、`client:` 岛。

### 参与

服务器岛有一个 [active RFC](https://github.com/withastro/roadmap/pull/963)。 我们仍在最终确定细节和功能； 例如，我们可能会添加加密的道具。 试用 4.12 中的版本，让我们知道您的想法。

将 `first` 和 `last` URL 添加到分页数据
--------------------------------------------

[paginate() helper](https://docs.astro.build/en/reference/api-reference/#paginate) 现在返回分页数据中的 `first` 和 `last` 属性。 这些属性分别包含第一页和最后一页网址。 感谢 [@tsawada](https://github.com/tsawada) 提供此功能！

添加了对 Shiki `defaultColor` 选项的支持
-----------------------------------------------

`defaultColor` 选项允许您覆盖主题的内联样式的值，仅添加 CSS 变量，以使您在应用多种颜色主题时更加灵活。 此选项可以在您的 Shiki 配置中配置以应用于整个站点，或传递给 Astro 的内置 `<Code>` 组件以设置单个代码块的样式。 感谢 [@madcampos](https://github.com/madcampos) 的贡献！

新 `inferRemoteSize` 功能
------------------------------

在 Astro 4.4 中，我们在图像和图片组件中添加了一个新属性，并 `getImage()` 自动推断远程图像的大小。 感谢 [@itsmatteomanf](https://github.com/itsmatteomanf)，此版本现在包含一个新功能 `inferRemoteSize()`，它允许您获得这些组件的远程图像的大小或 `getImage()`。

如果您使用图像宽度生成不同的密度，或者您需要用于样式的图像尺寸，这将很有用。

---import { inferremotesize, image } 来自 'astro:assets';
const { width, height } = await inferremotesize('https://...');---
    <Image src={"https://..."} width={width / 2} height={height} densities={[1.5, 2]}  />

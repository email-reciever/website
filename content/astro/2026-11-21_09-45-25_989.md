太空2.2出局了！ 此版本中包括：

*   **[CDN support for assets](#cdn-support)**：您现在可以将您的资产部署到外部 CDN，Astro 将从那里加载它们。
*   **[image() schema helper API change](#image-schema-api-change)**：（实验）`image()` 助手已被移动到与模式定义内联。

此外，Astro 2.2 包含 **8 补丁更改**，并与 **8 集成** 一起发布，并与补丁版本一起发布。

运行 `npm i astro@latest` 升级到最新版本。

CDN 支持
------------

在 2.2 中，您现在可以将 Astro 配置为指向 CDN 以加载您的资产。 在您的 Astro 配置中：

从“astro/config”导入 { defineConfig }
导出默认的 defineConfig({ build: { assetPrefix: "https://cdn.example.com", },})

运行 `astro build` 后的任何资源、脚本和样式表的链接将以配置的 URL 为前缀。 这适用于 SSG 和 SSR 模式。

    <link rel="stylesheet" href="https://cdn.example.com/_astro/global.css" />

资产仍然像往常一样构建到您的 `dist/` 文件夹中。 您需要配置部署脚本以将 `dist/_astro/` 部署到您的 CDN。

image() 模式 API 更改
--------------------------

在 2.2 实验资产 API 中的 `image()` 模式帮助程序已移至定义架构的回调。

导入 { defineCollection, z } 来自 "Astro:Content"
const blog = defineCollection({ schema: ({ image }) => z.object({ image:).refine((img) => img.width >= 200, { message: "image too small", }), }),})

以前，`image()` 是直接从 `'astro:content'` 导入的。 但是，这造成了 Astro 无法正确解析 FrontMatter 中定义的相对图像资产的错误。 将辅助程序作为回调提供与 ZOD 建议实现上下文引用的方式一致。

此新的基于回调的模式分配目前仅在启用实验资产的情况下可用。 如果您没有使用 `image()` 助手，您可以继续将模式直接分配给集合上的 `schema` 属性。

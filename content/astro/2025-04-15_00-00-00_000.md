实验字体 API
-----------------------

如今，几乎每个网站都使用自定义字体。 然而，让它们变得正确可能会非常复杂：为什么我会看到非样式文本的闪光？ 我应该添加预加载链接吗？ 预连接链接呢？ 我是自主托管还是依赖第三方提供商？

字体会对您的网站产生重大的性能影响，影响访问者的浏览体验和重要的核心 Web Vitals (CWV) 指标。 幸运的是，Web API 最近得到了很大的改进，并且由于开源社区的惊人举措（例如 [`unifont`](2]) 和 [`capsize`](https://github.com/seek-oss/capsize)，我们已经能够开始研究在 Astro 中使用字体的好方法！

此实验功能允许您通过统一的 API 使用来自文件系统和多个内置支持的提供商（例如 Google、FontSource、Bunny）的字体。 得益于合理的默认设置和包括后备字体生成在内的自动优化，保持您的站点性能。

要启用此功能，请使用一种或多种字体配置 `experimental.fonts` 对象：

astro.config.mjs

从“astro/config”导入 { defineConfig, FontProviders };
导出默认的 defineConfig({ experiment: { 字体：[{ provider: fontproviders.google(), name: "roboto", cssvariable: "--font-roboto" }] }});

然后，在 `<head>` 中添加 `<Font />` 组件和站点范围的样式：

src/组件/head.astro

---import { font } 来自 'astro:assets'---
<Font cssVariable='--font-roboto' preload /><style>body { font-family: var(--font-roboto);}</style>

还有很多东西要发现！ 如果我们还不支持您首选的字体服务，请前往 [the experimental Fonts documentation](https://docs.astro.build/en/reference/experimental-flags/fonts/) 获取完整的 API、如何开始，甚至如何构建您自己的自定义 `AstroFontProvider`。

我们也将感谢您的反馈。 参与 [Fonts RFC](https://github.com/withastro/roadmap/pull/1039) 上此功能的持续开发并帮助塑造其未来。

会话 API
-------------

Astro Sessions API 现已稳定，可供生产！

会话使您在特定用户之间导航时安全地存储绑定到您网站页面的数据。 与 Cookie 不同，会话存储在服务器上，因此您可以存储大量数据，而无需担心大小限制或安全性问题。 它们对于存储用户数据、购物车和表单状态等功能非常有用，并且它们在没有任何客户端 JavaScript 的情况下工作：

src/组件/cartbutton.astro

---const cart = await astro.session.get('cart');export const preRender = false;---
<a href="/checkout">🛒 {购物车？。长度？？ 0}项目</a>

它们可用于 Astro 组件、页面、API 端点、操作和中间件。 API对所有这些都是一样的：

src/actions/addtocart.ts

从“astro:actions”中导入 { defineAction }；从“astro:schema”导入 { z }；
导出 const server = { addToCart: defineAction({ input: z.object({ product: z.string(), }), async handler({ product }, { session }) { const cart = await session.get('cart'); session.set('cart', [...cart, product]); }, }),};

### 类型安全

当然，因为这是 Astro，您的会话也可以是类型安全的。 定义一个接口，您将获得所有会话数据的类型检查和自动完成：

src/env.d.ts

声明命名空间应用程序 { 接口 SessionData { 用户：{ ID：字符串； 名称：字符串； }; 购物车：字符串[]； }}

### 无cookie sessions

会话 ID 使用 cookie 自动跟踪，但您也可以使用 `session.load()` 方法在没有 cookie 的情况下访问会话。 这对于 API 之类的东西很有用，您可能希望使用自定义标头或参数来跟踪会话 ID：

src/pages/api/cart.ts

导出异步函数 post({ session, request }: apicontext) { const sessionId = request.headers.get('x-session-id');
// 如果有现有的会话 ID，请加载它。 否则，将创建一个 if (sessionid) { await session.load(sessionid); }
const cart = await session.get('cart'); const data = await request.json<{ 项目：字符串 }>();
if (!data?.item) { return new response('item is required', { status: 400 }); } session.set('cart', [...cart, data.item]); // 返回购物车和会话 ID 返回 response.json({ cart, sessionId: session.sessionId });}

### 存储驱动程序

Astro 会话使用存储驱动程序来保留数据，这些数据要么是零配置，要么是所有官方 Astro 适配器的最小设置。 或者，您可以使用任何 [unstorage](https://unstorage.unjs.io/) 驱动程序，它支持 Redis 和 MongoDB 等数十个存储后端。

*   **[Node](https://docs.astro.build/en/guides/integrations-guide/node/#sessions)**：零配置文件系统驱动程序
*   **[Netlify](https://docs.astro.build/en/guides/integrations-guide/netlify/#sessions)**：零配置 Netlify Blobs 驱动程序
*   **[Cloudflare](https://docs.astro.build/en/guides/integrations-guide/cloudflare/#sessions)**：最小配置工作人员 kv 驱动程序
*   **[Vercel](https://docs.astro.build/en/guides/integrations-guide/vercel/#sessions)**：最小配置 redis/upstash 驱动程序

在任何这些平台上，如果您不想使用默认值，您可以轻松地将驱动程序切换为另一台驱动程序。

astro.config.mjs

从“astro/config”导入 { defineConfig }；从“@astrojs/netlify”导入 netlify；
导出默认 defineConfig({ // ... 适配器：Netlify(), session: { driver: 'redis', options: { url: process.env.redis_url, }, },});

### 从实验课程升级

如果您使用的是实验会话 API，则应从 `astro.config.mjs` 文件中删除实验标志：

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ // ... 实验性的： { session: false, },});

查看 [sessions guide](https://docs.astro.build/en/guides/sessions/) 以了解有关如何在 Astro 项目中使用它们的更多信息。

SVG 组件
---------------

Astro现在支持本地SVG文件作为组件！ 将 SVG 直接内联到您的 HTML 之前需要额外的步骤，例如手动将 SVG 转换为 Astro 组件或安装第三方集成。 现在，Astro 支持使用任何 `.svg` 文件的默认导入，就像您使用任何其他 `.astro` 组件一样。 SVG 组件会自动将 `<svg>` 标记直接插入到您的 HTML 中。

您可以传递诸如 `width`、`height`、`fill`、`stroke` 以及 [本机 `<svg>` 元素](https://developer.mozilla.org/en-US/docs/Web/SVG/Element/svg) 接受的任何其他属性。

src/组件/myastrocomponent.astro

---从'./path/to/svg/file.svg'导入徽标;---
    <Logo width={64} height={64} fill="currentColor" />

查看 [the SVG components documentation](https://docs.astro.build/en/guides/images#svg-components) 以获取更多详细信息。

特别感谢 [Michael Stramel](https://github.com/stramel) 在这个功能上所做的工作！

### 从实验SVG升级

如果您之前使用的是实验性 SVG API，则必须从 `astro.config.mjs` 文件中删除实验标志。

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ // ... 实验性的： { svg: true, },});

请注意，[Astro 5.6](/blog/astro-560) 引入了 [some breaking changes to this flag](/blog/astro-560/#breaking-changes-to-the-experimental-svg-api)。 请检查您的代码是否使用此 API 的最新稳定版本。

配置导入
---------------

新的虚拟模块 `astro:config` 现在稳定！

虚拟模块允许您导入 Astro 配置的子集，并考虑到类型安全。 公开了两个子路径，以便受控访问您的配置：

*   `astro:config/client`：公开向客户端公开的配置信息。
*   `astro:config/server`：公开可向服务器公开的其他信息，例如文件/目录路径。

例如，您现在可以在不依赖集成的情况下构建自己的路径实用程序。 配置中设置的 `base` 和 `trailingSlash` 属性可以导入并在 `.js` 文件中使用：

astro.config.mjs

导出默认 defineConfig({ base: "store/", 尾随斜杠："always"});

src/utils.js

import { 尾随斜杠，基础 } 来自 'astro:config/client';
// 此方法向路径添加正斜杠，并在 `base`Function AddForwardSlashAndBase(Path) { let finalPath; if (trailingslash === 'always') { finalpath = path.endswith('/') ？ 路径：路径 + '/'; } else { 最终路径 = 路径； } if (base !== "/") { return base + finalpath } return finalpath}

使用此路径实用程序，该实用程序取决于整个项目的配置设置，例如，可以对页面链接进行更多控制：

src/pages/index.astro

---从“@src/utils.js”导入 { AddForwardSlashAndBase };
const carturl = addForwardSlashAndBase("cart"); // 它将返回“store/cart/”---
<a href={cartUrl}>车</a>

我们 `config` 希望您享受这种访问您设置的新功能，并使用 Astro 的商标类型安全性来帮助您正确使用！

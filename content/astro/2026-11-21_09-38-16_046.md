实验：增量静态构建
--------------------------------------

Astro 通常用于构建大型静态站点：文档、博客和营销站点，这些站点可以运行到数千个页面。 在这些网站上，一些动态路由（如 `[...slug].astro`）通常占页面的大部分，每个页面都呈现出内容集合中的条目。 随着内容的增长，即使给定的构建只改变了少数页面，构建也会也会增加。

[Astro 7](/blog/astro-7/) 已经通过滚降和基于 Rust 的 Markdown 管道使捆绑阶段变得更快。 剩下的是生成阶段，Astro 将每个预渲染的路线呈现为 HTML。 到目前为止，Astro 重新渲染了每个构建上的每个静态页面，即使该页面没有任何变化。 增量静态构建针对该阶段的目标。

使用 `experimental.incrementalBuild` 标志打开它：

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ 实验性: { incrementalbuild: true, },});

一条路由通过返回 `getStaticPaths()` 中的每条路径的 `cacheKey` 来选择加入。 每当用于渲染该路径的数据更改时，`cacheKey` 应更改。 对于内容集合，`entry.digest` 非常适合，因为每当条目内容发生变化时，它都会发生变化：

src/pages/blog/\[slug\]].astro

---import { getCollection } 来自“astro:content”；
导出异步函数 getStaticPaths() { const posts = await getCollection('blog'); return posts.map((post) => ({ params: { slug: post.id }, props: { post }, cacheKey: post.digest, }));}
const { post } = astro.props;---
<h1>{post.data.title}</h1>

`cacheKey` 涵盖您的数据。 Astro 为您处理代码端：在构建过程中，它会对每个路由的完整模块图表进行哈希处理，包括其模板、布局、组件、导入的资产以及它们拉入的包代码。如果其中任何一个发生变化，哈希会发生变化，并且路由上的每条路径都被重新渲染。 仅当此模块散列及其 `cacheKey` 与之前的版本匹配时，才会重用一个页面。

总是呈现没有 `cacheKey` 的路径，因此选择路线是一个明确的决策，现有项目完全像今天一样构建，直到您选择其他方式。 缓存位于内容层和图像缓存旁边的 `cacheDir`（默认情况下 `node_modules/.astro/`）中，因此已经保留该目录的 CI 系统可以在运行中重用它。

这是一个早期的实验性功能，我们想听听它如何在真实网站上保持下去。 要阅读完整的设计或留下反馈，请参阅 [incremental static builds RFC](https://github.com/withastro/roadmap/pull/1404)。

选择退出会话支持
---------------------------

配置会话驱动程序后，Astro 将其会话运行时捆绑到 SSR 输出中。 如果您使用 `Astro.session`，这就是您想要的，但是从不接触会话的项目仍在为每次冷启动时解析代码付费。

Astro 7.2 添加了一个 `session: false` 选项以完全退出：

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ 会话：false,});

使用 `session: false` 时，用于 Cloudflare、Netlify 和 Node 的适配器会跳过连接其默认会话驱动程序，并从捆绑包中删除会话运行时。 `Astro.session` 是 `undefined`，这是一种已经允许的状态，因此现有的 `if (Astro.session)` 检查继续工作，没有新的错误来处理。 有关详细信息，请参阅文档中的 [Disabling sessions](https://docs.astro.build/en/guides/sessions/#disabling-sessions)。

您不必为受益而设定旗帜。 Astro 现在将会话运行时移出任何没有连接驱动程序的项目，无论是 `session: false`、根本没有 `session` 配置，还是没有驱动程序的 `session` 对象。 配置驱动程序的项目没有更改。

Astro Preview的背景模式
--------------------------------

Astro 7 为 `astro dev` 添加了背景模式，以便您（或 AI 编码代理）可以启动开发服务器、继续工作并使用后续命令管理它。 Astro 7.2 为 `astro preview` 带来了同样的结果：

Astro 预览 --background

预览服务器在后台运行并写入自己的日志文件。 然后，您可以使用匹配的子命令检查或关闭它：

Astro Preview StatusASTRO 预览 logsastro 预览停止

`astro dev` 和 `astro preview` 共享相同的背景机器，因此两者的行为一致，包括代理驾驶时的自动背景模式。

相对记录器入口点
----------------------------

Astro 7.1 允许您通过将 URL 传递给 `logger.entrypoint` 来配置自定义记录器。 Astro 7.2 添加了对普通相对字符串的支持，与其他入口点样式选项的工作方式相匹配：

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ logger: { entrypoint: './src/custom-logger.js', },});

URL 表单仍然有效。 这是一个小的便利，因此当您只需要相对路径时，您不必到达 `new URL(..., import.meta.url)`。

稳定：内容层
----------------------

Astro 5.0 引入了 Astro 内容层，这是一种管理 Astro 项目中内容的新方法。 内容层是与内容交互的灵活且可扩展的方式，提供了一个统一的、类型安全的 API 来访问和定义您的 Astro 项目中的内容——无论它来自哪里——多亏了强大的加载器。

随着您的网站的增长，将您的内容放在 Git 存储库中的 Quaint Cozy Markdown 文件中可能变得越来越不实用。 您可能需要使用 CMS。 也许您网站的某些部分在某处由 REST API 提供支持，或者您优化了来自 Cloudinary 等资产管理系统的图像。 这很快就会变得一团糟，需要各种不同的 API 和数据获取策略。

内容层由加载器提供支持，它是可插入的功能，可以从任何源获取数据并将其转换为统一的、类型安全的格式，您可以在 Astro 项目中使用该格式，以便您可以从任何地方对数据的形状和类型充满信心地访问数据。

src/content/config.ts

import { defineCollection } 从 "Astro:Content";import { notionLoader } 从 "notion-astro-loader";
const database = defineCollection({ / / // 自动从一行中获取内容 // 使用 'notion-astro-loader' npm 包! loader: notionLoader({ /* ... */ }) // 可选地，为内容定义一个模式或让加载器推断 它 // 模式：z.object({ /* ... */ })});
导出常量集合 = { 数据库，}

这只是触及内容层为您的项目解锁的可能性的表面。 请继续关注本周有关此功能的更多信息，并查看我们的 [the new content collections in the v5.0 beta docs](https://5-0-0-beta.docs.astro.build/en/guides/content-collections/) 指南以了解如何开始使用。

稳定：服务器岛
-----------------------

Server Islands 是 Astro 5 的一个新原型，允许您将动态内容的呈现推迟到初始页面加载之后。 这使您可以在稍后注入的个性化内容的静态页面上提供两全其美的服务：快速、CDN 缓存的静态页面，以及个性化和动态内容。

Server Islands 建立在 Astro 的现有岛屿架构之上。 定义服务器岛就像定义客户端岛一样简单，但改用 `server:defer` 指令：

    <UserButton server:defer />

这告诉 Astro 在初始响应中跳过渲染此组件，并将其渲染“推迟”到以后。 这使您可以缓存具有一些初始占位符内容的 CDN 后面的静态页面。 加载动态 HTML 后，一个小的内联脚本会用延迟渲染的 HTML 结果替换页面上的服务器岛。

此功能对于在页面上混合动态和静态内容的内容驱动的网站特别有用。 例如，对于电子商务网站，您可以将产品推荐的呈现推迟到初始页面加载之后，提供更快的初始页面加载时间，同时仍提供个性化的内容。

有关使用此功能的更多详细信息，请访问 [server islands documentation in the 5.0 beta docs](https://5-0-0-beta.docs.astro.build/en/guides/server-islands/)。

合并的静态和混合输出模式
-----------------------------------

在 Astro 5 中，现在创建一个包含静态、缓存、高性能页面和按需渲染动态页面的网站比以往任何时候都容易。 Astro 的新 `output: 'static'` 模式，默认情况下，现在允许您通过添加适配器在服务器上的运行时渲染单个路由，不需要其他配置。

这与我们之前的 `hybrid` 模式相同：默认情况下，每个页面都是静态生成的，直到您选择退出预渲染：

---export const preRender = false; // 在请求时间渲染---

如果您的大部分页面都按需呈现，您仍然可以在 Astro 配置中将 `output: 'server'` 设置为默认设置为服务器渲染：

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ 输出：'server'});

准备好将站点部署到生产环境后，Astro 将根据 `prerender` 常量和 `output` 配置自动为每个页面生成正确的输出。 仍然需要一个适配器来提供按需呈现的页面，以`static`和`server`模式，您可以像以前一样使用`astro add`将其添加到项目中。

有关 Astro 中预渲染和服务器端渲染的更多信息，请查看我们在 [rendering modes in the 5.0 beta docs](https://5-0-0-beta.docs.astro.build/en/basics/rendering/) 上的文档。

稳定：`astro:env`
--------------------

这些天环境变量很难！ 随着项目的增长，很容易忘记哪些变量是可选的和/或敏感的。 Astro 5.0 引入了一种使用 `astro:env` 管理环境变量的新方法，这是一个内置模块，提供类型安全的定义和访问环境变量的方式。

首先使用熟悉的模式语法在Astro Config中定义您的环境变量：

从“Astro/Config”导入{defineConfig, envField }
导出默认的 defineConfig({ env: { schema: { client_api_url: envfield.string({ context: "client", access: "public" }), server_api_url: envfield.string({ context: "server", access: "public" }), api_secret: envfield.string({ context: "server", access: "secret" }), } }})

然后，使用 `astro:env` 模块访问 Astro 项目中的环境变量：

---import { server_api_url, api_secret, port } 来自 "astro:env/server";
const data = await fetch(`${SERVER_API_URL}/api`, { headers: { authorization: `Bearer ${API_SECRET}` }})---
<script> 从“astro:env/client”导入 { client_api_url }； const ClientData = await fetch(client_api_url);</script>

有关在 Astro 中处理环境变量的更多信息，请查看我们的 [type safe environment variables in the 5.0 beta docs](https://5-0-0-beta.docs.astro.build/en/guides/environment-variables/#type-safe-environment-variables) 指南。

清晰的编解码器特定图像默认值
---------------------------------

[Sharp](https://docs.astro.build/en/guides/images/#default-image-service)，Astro 的内置图像服务，一直支持细粒度的编码选项——JPEG 的 Mozjpeg 压缩、WebP 和 Avif 的努力级别、PNG 的压缩级别。 Sharp 的默认值适用于大多数项目，但如果您需要对大量图像进行一致的编码设置，唯一的选择是将它们单独设置在每个 `<Image />` 上。

Astro 6.1 在 Astro 配置中添加了 `image.service.config` 以在 Astro 配置中设置编解码器特定的默认值，应用于构建期间处理的每个图像：

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认的 defineConfig({ image: { service: { config: { jpeg: { mozjpeg: true }, webp: { 努力：6, alpha质量: 80 }, avif: { 努力：4, chrosasubampling: '4:2:0' }, png: { 压缩级别: 9 }, }, }, },});

每图像 `quality` 在设置时仍然优先，因此全局默认值和每映像覆盖可以协同工作而不会发生冲突。 有关支持的选项的完整列表，请参阅 [image service configuration reference](https://docs.astro.build/en/reference/configuration-reference/#imageservice)。

高级 SmartyPants 配置
---------------------------------

如果您的 Markdown 内容针对的是非英语受众，您可能已经注意到 [SmartyPants](https://daringfireball.net/projects/smartypants/) — Astro 用于自动将标点符号转换为其印刷等价物的库 - 采用英语约定。 如果不完全禁用 SmartyPants 并自己处理，则不可能使用 French Guillemets (`«»`)、德国引号 (`„"`) 或老式 EM-Dash 处理。

Astro 6.1 打开了完整的 SmartyPants 配置，因此您可以单独自定义每个转换：

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认的defineConfig({ markdown: { dashes: 'oldschool', openingquotes: { double: '«', single: '‹'' }, collectionquotes: { double: »', single: '›' }, 省略号：“非空格”，引号：false, }, },});

有关支持的设置的完整列表，请参阅 [`retext-smartypants` 选项](https://github.com/retextjs/retext-smartypants?tab=readme-ov-file#fields)。

用于集成的 i18n 后备路由
-----------------------------------

Astro 6.1 在 `astro:routes:resolved` 钩子中的每条路由上公开 `fallbackRoutes`，使集成访问 Astro 为在使用 `fallbackType: 'rewrite'` 时没有自己内容的区域设置时生成的附加路由。

{ 'astro:routes:resolved': ({ routes }) => { for (const route of routes) { const fallbacks = route.fallbackroutes.map((f) => f.pathname); console.log(route.pathname, '->', fallbacks); // '/about/' -> ['/fr/about/', '/de/about/'] } }}

我们已经在 `@astrojs/sitemap` 中使用了它，现在它会自动在生成的站点地图中包含 i18n 后备页面。 以前，这些路由对集成是不可见的，这意味着您的站点地图中静默地缺少回退页面。

在 Astro Docs 中了解有关 [i18n fallback routing](https://docs.astro.build/en/guides/internationalization/#fallback) 的更多信息。

其他改进
-------------------

*   **Smoother View on Mobile Transitions on Mobile** — 当浏览器已经提供自己的可视化转换（例如 iOS Safari 上的滑动手势）时，客户端路由器会跳过查看过渡动画。 这消除了用手势来回导航时可能发生的双动画闪烁。 （[#16025](https://github.com/withastro/astro/pull/16025)）
*   **VITE 8 兼容性警告** — 当在项目的顶层检测到 Vite 8 时，ASTRO 会在开发服务器启动时发出警告。 `astro add cloudflare` 命令还会自动将 `"overrides": { "vite": "^7" }` 条目添加到您的 `package.json`，以防止在使用 `@tailwindcss/vite` 等软件包时发生常见的崩溃。 （[#16062](https://github.com/withastro/astro/pull/16062)）
*   **React Hydration Fixes** — React 水合错误的多个修复，包括条件槽渲染和 `experimentalReactChildren` 不匹配。 （[#15378](https://github.com/withastro/astro/pull/15378)，[#15146](https://github.com/withastro/astro/pull/15146)）
*   **反向代理后面的 CSRF 保护** — `checkOrigin` 现在在 `astro dev` 中正确读取 `X-Forwarded-Proto` 在 TLS 终止反向代理后面，防止表单提交的错误 403 错误。 （[#16043](https://github.com/withastro/astro/pull/16043)）

有关错误修复和较小改进的完整列表，请参阅 [the full changelog](https://github.com/withastro/astro/blob/main/packages/astro/CHANGELOG.md)。

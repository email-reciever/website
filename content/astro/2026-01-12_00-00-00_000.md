### 实时内容集

Astro [v2.0](/blog/introducing-content-collections/) 中引入的内容集合是一个强大的功能，它允许您以类型安全的方式管理和使用本地内容，例如 Markdown 和 MDX 文件。

在 [v5.0](/blog/astro-5/) 中，通过引入内容层 API 重新构想了这个概念，使从外部 CMS 和 API 中获取的内容的处理方式与本地 Markdown 和 MDX 文件具有相同级别的安全性。 但是，由于这些内容是在构建时获取的，因此支持高度动态或个性化的内容很困难。

随着 [v5.10.0](/blog/astro-5100/#experimental-live-content-collections) 中实时内容集合的实验性引入，现在可以通过内容加载器在运行时而不是构建时获取数据。 这允许站点以安全类型的方式访问最新数据，而无需在更新内容时进行重建。

要在 Astro 5 中启用此功能（在 Astro 6 中默认可用），您需要配置 [on-demand rendering](https://docs.astro.build/en/guides/on-demand-rendering/)，然后将 `experimental.liveContentCollections` 标志添加到您的 Astro 配置文件中：

astro.config.mjs

{ 实验性： { LiveContentCollections: true, },}

然后，在 `src/live.config.ts` 中，使用 `defineLiveCollection()` 函数使用加载器定义您的实时集合：

src/live.config.ts

从 'Astro:Content' 导入 { defineliveCollection }；从 '@mystore/astro-loader' 导入 { StoreLoader }；
const products = defineLiveCollection({ loader: storeloader({ apiKey: process.env.store_api_key, endpoint: 'https://api.mystore.com/v1', }),});
导出常量集合 = { 产品};

完成此设置后，您可以使用 `getLiveCollection()` 和 `getLiveEntry()` 功能访问实时数据：

---export const preRender = false; // 在“服务器”模式下不需要
导入 { getLiveCollection, getLiveEntry } 来自 'astro:content';
// 获取所有 ProductsConst { 条目：AllProducts, error } = await GetLiveCollection('products');if (error) { // 正确处理错误 console.error(error.message);}
// 获取带有过滤器的产品（如果您的加载程序支持）const { 条目：电子设备 } = await getLiveCollection('products', { category: 'electronics' });---

您是否注意到与现有 API 的相似之处？ 简而言之，`src/content.config.ts` 和 `src/live.config.ts`、`defineCollection`](https://docs.astro.build/en/reference/modules/astro-content/#definecollection) 和 `defineLiveCollection` 以及 [`getCollection`](https://docs.astro.build/en/reference/modules/astro-content/#getcollection)/[`getEntry`](https://docs.astro.build/en/reference/modules/astro-content/#getentry) 和 `getLiveCollection`/`getLiveEntry` 的设计几乎相同。 这确实突出了 Astro API 设计的优雅。

但是，由于实时内容是在运行时获取的，因此您需要处理意外的错误并考虑缓存等性能优化。 好消息是 Astro 提供了 API 来帮助您做到这一点。

虽然这里没有介绍，但在定义集合和在 npm 上分发自定义加载器时，您仍然可以使用 ZOD，就像以前一样。 有关更多详细信息，请查看 [the official documentation on experimental live content collections](https://docs.astro.build/en/reference/experimental-flags/live-content-collections/)。

### 响应图像

图像是大多数网站的重要组成部分，但在各种设备上正确显示它们远非微不足道。 屏幕尺寸、分辨率和图像格式只是开发人员在屏幕上渲染图像时需要考虑的几个因素。

为了灵活应对这些挑战，在 [v5.10.0](/blog/astro-5100/#responsive-images-are-now-stable) 中，Astro 引入了一种新行为，使响应图像更容易实现。

要自动为响应图像添加全局样式，请在 Astro 配置文件中将 [`image.responsiveStyles`](https://docs.astro.build/en/reference/configuration-reference/#imageresponsivestyles) 设置为 `true`。

astro.config.mjs

{ 图像：{ 响应式样式：true, },}

这允许您在 `<Image />` 组件上指定 [A `layout` 值](https://docs.astro.build/en/reference/modules/astro-assets/#layout) 以确定图像在其容器更改大小时应如何调整大小。

在下面的示例中，设置 `layout` 属性使图像缩放以适合容器，同时保持其纵横比，而不会超过指定的尺寸。

---从'../assets/my_image.png'导入myImage ---import {图像}
    <Image  src={myImage}  alt="A description of my image."  layout="constrained"  width={800}  height={600}/>

使用新的响应行为，自动生成必要的 `srcset` 和 `sizes` 值，并应用适当的调整大小的适当样式。 此外，还将添加一个 `priority` 属性，以加载更高优先级的某些图像。

此 `<Image />` 组件将生成以下 HTML 输出：

    <img  src="/_astro/my_image.hash3.webp"  srcset="/_astro/my_image.hash1.webp 640w,      /_astro/my_image.hash2.webp 750w,      /_astro/my_image.hash3.webp 800w,      /_astro/my_image.hash4.webp 828w,      /_astro/my_image.hash5.webp 1080w,      /_astro/my_image.hash6.webp 1280w,      /_astro/my_image.hash7.webp 1600w"  alt="A description of my image"  sizes="(min-width: 800px) 800px, 100vw"  loading="lazy"  decoding="async"  fetchpriority="auto"  width="800"  height="600"  style="--fit: cover; --pos: center;"  data-astro-image="constrained">

生成的标记乍一看可能看起来很冗长，但关键点相当简单：

*   自动生成 `srcset` 属性，以便浏览器可以为当前屏幕选择最合适的图像大小。
*    `sizes` 属性反映了 `layout`、`width` 和 `height` 道具定义的布局约束。
*   ASTRO 使用 `data-astro-image` 属性应用范围样式以确保图像正确调整大小，而无需手动 CSS。

此外，Astro 生成并应用了以下全局样式，以确保您的图像正确调整大小：

:where([data-astro-image]) { object-fit: var(--fit); object-position: var(--pos);}:where([data-astro-image='full-width']) { width: 100%;}:where([data-astro-image='constrained']) { 最大宽度：100%；}

还值得注意的是，Astro [v5.7.0](/blog/astro-570/#svg-components) 引入了对将 SVG 文件作为 Astro 组件导入的支持。 这是另一个方便的功能，所以一定要试一试！

---从'./path/to/svg/file.svg'导入徽标;---
    <Logo width={64} height={64} fill="currentColor" />

### 字体

字体也是网站的重要组成部分，但有效地加载它们可能与图像一样具有挑战性。 选择正确的加载策略、定义回退和添加预加载提示都需要仔细配置。

Astro 之前没有提供用于字体的内置方法，但 [v5.7.0](/blog/astro-570/#experimental-fonts-api) 引入了实验字体 API。 借助此 API，Astro 可以处理 Web 字体优化，例如预加载链接、优化的回退和固执己见的默认设置。

要在 Astro V5 中启用此功能（在 V6 中默认可用），请使用至少一种字体对象配置 `experimental.fonts`：

astro.config.mjs

从“astro/config”导入 { defineConfig, FontProviders };
导出默认的 defineConfig({ experiment: { 字体：[{ provider: fontproviders.google(), name: "roboto", cssvariable: "--font-roboto" }] }});

然后，在 `<head>` 中添加 `<Font />` 组件和站点范围的样式：

---import { font } 来自 'astro:assets';---
    <Font cssVariable="--font-roboto" preload />
<style>body { font-family: var(--font-roboto);}</style>

使用此设置，CSS `@font-face` 规则和字体预加载标记将自动为您生成。

字体 API 还支持 Google 以外的供应商，允许对下载的字体文件进行详细控制，甚至可以构建自己的字体提供商。 一定要试试新的API！

[Check out the official docs to learn more about the experimental Fonts API](https://docs.astro.build/en/reference/experimental-flags/fonts/)。

### 会话

Astro [v5.7.0](/blog/astro-570/#sessions-api) 将 Sessions API 作为一个稳定的功能引入。 这使得可以在来自同一用户的多个请求中在服务器端存储数据，从而允许您处理用户数据、购物车和其他有状态信息，而无需担心数据大小限制。

可以从 Astro 组件、页面、API 端点、操作和中间件访问会话数据。 从 Astro 组件或页面访问会话数据时，您使用 `Astro.session`，而在其他上下文中使用 `context.session`。 在任何一种情况下，`session` 对象的行为相同。 下面的示例演示了如何在 Astro 组件中从会话中读取购物车数据：

---export const preRender = false; // 'server' outputConst cart = await astro.session?.get('cart') 时不需要;---
<a href="/checkout">🛒 {购物车？。长度？？ 0}项目</a>

在许多用例中，[`session.get()`](https://docs.astro.build/en/reference/api-reference/#get) 和 [`session.set()`](https://docs.astro.build/en/reference/api-reference/#set) 是您所需要的。 也就是说，Sessions API 还包括 [`session.regenerate()`](https://docs.astro.build/en/reference/api-reference/#regenerate) 和 [`session.destroy()`](https://docs.astro.build/en/reference/api-reference/#destroy) 来处理会话 ID 再生和清理，以及 [`session.load()`](https://docs.astro.build/en/reference/api-reference/#load) 用于按 ID 加载会话。 在 Node、Cloudflare 或 Netlify 上运行时，适配器会自动配置存储驱动程序以进行会话处理。 在其他环境中，仍然可以通过手动指定驱动程序来使用会话。

[Check out the official docs to learn more about the Sessions API](https://docs.astro.build/en/guides/sessions/)。

### 内容安全策略

内容安全策略 (CSP) 是一个重要的安全层，它有助于保护网站免受跨站点脚本 (XSS) 和其他代码注入攻击。

虽然 CSP 通常使用需要为每个请求生成服务器端生成的 `nonce` 标头实现，但 Astro [v5.9.0](/blog/astro-590/#experimental-content-security-policy-support) 引入了对使用 `<meta>` 标签的基于哈希的方法的实验性支持。 此解决方案在所有渲染模式（静态页面、服务器渲染页面和 SPA）中无缝运行，无需服务器端 Nonce 管理的复杂性。

启用 CSP 后，Astro 会自动生成一个 `<meta>` 元素，其中包含页面上使用的所有脚本和样式的哈希值，包括动态加载的。 要在 Astro 5 中启用此功能（在 V6 中默认可用），请将 `experimental.csp` 选项添加到您的 Astro 配置文件中：

astro.config.mjs

{ 实验性: { CSP: true, }}

您还可以传递一个对象以配置其他选项，例如 [`algorithm`](https://docs.astro.build/en/reference/experimental-flags/csp/#algorithm) 以指定哈希算法，[`directives`](https://docs.astro.build/en/reference/experimental-flags/csp/#directives) 应用自定义 CSP 指令，以及 [`scriptDirective`/`styleDirective`](https://docs.astro.build/en/reference/experimental-flags/csp/#styledirective-and-scriptdirective) 指定允许的源或提供其他 外部资源的哈希。

对于更高级的用例，Astro 通过 `Astro.csp` 对象提供运行时 API，允许您在每页上添加指令或哈希值。 您可以使用 [`csp.insertDirective()`](https://docs.astro.build/en/reference/experimental-flags/csp/#cspinsertdirective)、[`csp.insertStyleHash()`](https://docs.astro.build/en/reference/experimental-flags/csp/#cspinsertstylehash) 和 [`csp.insertScriptHash()`](https://docs.astro.build/en/reference/experimental-flags/csp/#cspinsertscripthash) 之类的方法来自定义单个页面的 CSP。

值得注意的是，内联脚本需要提供自定义哈希值，并且 `<ClientRouter />` 组件与此功能不兼容。 请务必使用 `astro build` 和 `astro preview` 测试您的 CSP 配置，因为 CSP 在开发模式下没有强制执行。

[Check out the official docs to learn more about experimental Content Security Policy in Astro](https://docs.astro.build/en/reference/experimental-flags/csp/)。

### Astro Docs MCP 服务器

虽然 2025 年被广泛描述为 [vibe coding](https://x.com/karpathy/status/1886192184808149383) 的年份，但 Astro 也一直在稳步向前推进，支持 AI 工具。 Astro Docs 现在包括一个新的“[Build with AI](https://docs.astro.build/en/guides/build-with-ai/)”页面，它提供了使用 AI 开发 Astro 项目的技巧。 该节目的明星是 Astro Docs MCP 服务器，下面介绍。

[Model Context Protocol](https://modelcontextprotocol.io/) (MCP) 是 AI 工具访问外部系统的标准。 借助 MCP 服务器，AI 工具可以执行搜索文档、运行代码和其他任务等操作。

Astro Docs MCP 服务器于 2025 年 7 月发布，允许 AI 工具访问官方的 Astro 文档。 通过将此服务器用作信息源，AI 工具可以避免依赖过时的建议并了解当前的最佳实践。 连接到 MCP 服务器的过程取决于所使用的工具，ASTRO 文档开始使用几个最受欢迎的编辑器、代理和助手。

[The official MCP inspector](https://modelcontextprotocol.io/docs/tools/inspector) 是快速试用 Astro Docs MCP 服务器的便捷选项。 您可以使用命令 `npx @modelcontextprotocol/inspector` 启动它，然后选择 **Streamable HTTP** 作为传输类型，并输入 `https://mcp.docs.astro.build/mcp` 作为 URL。

单击 **Connect** 后，检查器将连接到 MCP 服务器，`search_astro_docs` 工具将显示为 **List Tools** 下的可用项目。 选择它并提供任何与 Astro 相关的主题作为查询，您可以查看 AI 将收到的原始文档数据：

### `astro:config`

在 [v5.7.0](/blog/astro-570/#config-imports) 中，Astro 添加了对以类型安全方式导入 Astro 配置的子集的支持。 `astro:config` 虚拟模块提供了两个子模块，`/client` 和 `/server`，它们设计用于根据运行时环境而设计的。

目前，以下值可从 `/client` 和 `/server` 获得。 请注意，出于安全原因，故意从 `/client` 中排除了与目录路径相关的信息：

*   `/client`
    *   [`i18n`](https://docs.astro.build/en/reference/configuration-reference/#i18n)
    *   [`trailingSlash`](https://docs.astro.build/en/reference/configuration-reference/#trailingslash)
    *   [`base`](https://docs.astro.build/en/reference/configuration-reference/#base)
    *   [`build.format`](https://docs.astro.build/en/reference/configuration-reference/#buildformat)
    *   [`site`](https://docs.astro.build/en/reference/configuration-reference/#site)
    *   [`compressHTML`](https://docs.astro.build/en/reference/configuration-reference/#compresshtml)
*   `/server`

### 路由缓存

路由缓存是一个 API，旨在以独立于平台的方式提供基于 Web 标准的声明式缓存控制。 这个新功能背后的早期想法首先由 [![](/_astro/matt.DK7kFqz2.webp)Matt Kane](https://bsky.app/profile/mk.gg "Follow Matt Kane on Bluesky") 在 [his ViteConf 2025 talk](#viteconf) 中取笑。

以下是取自[the RFC](https://github.com/withastro/roadmap/pull/1245)的示例，它表明您可以在每个路由的基础上配置`maxAge`、`swr`和`tags`等值，并通过`path`或`tag`使缓存无效。 它还旨在与前面提到的实时内容集合中从 `getLiveEntry()` 返回的 `cacheHints` 一起支持缓存失效：

基本路由缓存

---// src/pages/products/[id].astroimport { getEntry } 来自“astro:content”；
const product = await getentry('products', astro.params.id);
astro.cache({ lastModified: product.updatedat, maxAge: 300, // 缓存 5 分钟 SWR: 3600, // stale-while-revalidate for 1 hour tag: ['products', `product:${product.id}`]});---<h1>{product.data.name}</h1><p>{product.data.description}</p>

按路径缓存失效

// src/pages/api/webhook.tsexport const post: apiroute = ({ cache }) => { // 路径 Cache.invalidate({ path: "/products/laptop" });
返回 response.json({ ok: true });};

按标记缓存失效

// src/pages/api/webhook.tsexport const post: apiroute = ({ cache }) => { // 按标记无效 cache.invalidate({ tag: "products" });
返回 response.json({ ok: true });};

与实时收藏集成

---// src/pages/products/[slug].AsTroimport { getLiveEntry, render } from 'astro:content';
const { entry, cachehint } = await getLiveEntry('products', astro.params.slug);
// 应用来自实时集合 loaderAstro.cache(cachehint) 的缓存提示；
const { content } = await render(entry);---<h1>{entry.data.name}</h1><Content />

尽管此 API 尚未最终确定，但与手动设置相比，声明式方法如何使配置更短且更易于理解是非常好的。 跨平台的不同缓存失效机制可以在单个 API 后面统一也很有帮助。 一旦进入 Astro，更复杂的缓存策略（例如 ISR）应该会变得更容易实施。

### Astro的跟踪钩子

这是向 Astro 核心添加低开销的通用仪表挂钩系统的提议。

分布式跟踪是识别应用程序性能瓶颈的有效方法，但将 OpenTelemetry 直接集成到 Astro 中会显着增加依赖项的数量。

相反，该提案引入了一种机制，允许使用钩子之前和之后测量页面渲染、中间件执行和组件渲染等操作。 当没有注册侦听器时，开销保持在最低限度，而可观察性仍然可以通过 `@astrojs/opentelemetry` 等集成来实现。

该提案目前处于第 2 阶段，如果您有兴趣，您可以通过评论 [the proposal](https://github.com/withastro/roadmap/issues/1208) 或 [the related pull request](https://github.com/withastro/astro/pull/13782) 来分享反馈。 如果您有任何想法或问题，请务必查看它们。

实验内容安全策略支持
------------------------------------------

[Cross-site scripting](https://developer.mozilla.org/en-US/docs/Web/Security/Types_of_attacks#cross-site_scripting_xss) (XSS) 攻击是网站面临的一些最常见的威胁。 默认情况下，网页可以从他们想要的任何地方加载他们想要的任何脚本和样式。 对XSS攻击最强大的防御是限制这一点。 内容安全策略 (CSP) 允许您使用工具将页面锁定到可信资源列表中。

虽然这些是强大的工具，但它们可能很难手动实现：如果您的框架可以为您完成，那就更容易了。 Astro 5.9 引入了对 CSP 开箱即用的实验支持，使您的 Astro 项目更容易保护。 这是 Astro 迄今为止最受欢迎的功能请求，我们当然花时间实施它。 我们希望这是值得等待的！

我们将该功能设计为适用于所有 Astro 渲染模式（静态页面、动态页面和单页应用程序），并考虑到最大的灵活性和类型安全性。 你没听错！ 您可以放弃不愉快的 `unsafe-inline` 解决方法，使用您喜欢的所有 Astro 功能，任何运行时的适配器，并为您的网站添加额外的安全层。

### 它是如何工作的

用户喜欢 Astro 的原因之一是它在任何地方都可以工作——静态主机、无服务器主机、Node.js、边缘运行时以及许多前端库（React、Vue、Svelte 等）。 因此，Astro CSP 解决方案必须与任何库一起工作。

我们首先考虑了两种支持 CSP 的常见方法：

*    [`nonce` header](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP#nonces)，为每个请求生成一个随机值并将其注入到 HTML 中。
*   计算出运送到浏览器的所有资源的 [hashes](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP#hashes)，确保仅执行您期望运行的脚本和样式。

虽然 `nonce` 标头很容易实现，但它需要一个服务器/边缘函数，该函数能够生成 `nonce` 的随机值，将 `Content-Security-Policy` 头添加到 `Response` 对象，并重写 HTML 以为每个 `<script>` 和 `<style>` 元素注入 `nonce` 值。 此解决方案不适用于从静态主机提供的网站，例如 GitHub 页面，它不适用于在应用程序的生命周期中动态注入脚本和样式的单页应用程序 (SPA)。

哈希的生成更复杂，因为它需要知道页面上每个脚本和样式表的确切内容。 但是，它可以支持比 `nonce` 标头更多的用例，因此即使道路上的另一个分叉正在等待我们，我们的选择也很清楚。

CSP 标准允许通过称为 `Content-Security-Policy` 的 `Response` 标头或使用称为 `http-equiv='content-security-policy'` 的 `<meta>` 元素将散列提供给浏览器。 正如您可能已经猜到的那样，使用 `Response` 标头对 Astro 不起作用，因为它会遗漏静态网站和 SPA。 出于这个原因，我们决定使用 `<meta>` 元素向浏览器提供 CSP。

最终的结果是Astro的CSP将为您生成`<meta>`元素，以及将在页面中使用的脚本和样式的所有哈希值，甚至是那些将被动态加载的_！

### 使用

要立即在您自己的项目中试用 Astro 的 CSP，请启用新的实验标志：

astro.config.mjs

从“astro/config”导入 { defineConfig }
导出默认 defineConfig({ 实验性: { csp: true }})

如果您已经通过中间件或其他方式在您的网站中使用 `Content-Security-Policy` 标头，您仍然可以使用它，浏览器将使用更严格的标题和 `<meta>` 元素的策略。

但我们并没有就此止步！ Astro 通过配置让您进一步控制 `<meta>` 内容。 您可以更改默认算法、插入附加指令等：

astro.config.mjs

从“astro/config”导入 { defineConfig }
export default defineConfig({ experimental: { csp: { // 改变默认算法算法："`SHA-512",            // insert additional directives            directives: [                "default-src: 'self'",                "image-src: 'https://images.cdn.example.com'"            ],            // add more information to the `style-src` 指令 styleDirective: { hashes: [ ""sha384-somehash" // 为某些外部样式生成的哈希值，例如白标等 ], // **覆盖**默认资源：["self", "https://styles.cdn.example.com"] },
// 将更多信息添加到 `script-src` 指令 scriptDirective: { hashes: [ "sha384-somehash" // 为某些外部脚本生成的哈希，例如 分析，jQuery等]， // **覆盖**默认资源：["self", "https://script.cdn.example.com"], //切换关键字`strict-dynamic` strictdynamic: true } } }})

有关详细信息，请参阅 [experimental CSP documentation](https://docs.astro.build/en/reference/experimental-flags/csp/)。

在内容加载程序中渲染降价
-----------------------------------

Astro Content Collections 一直支持使用 [`render()` 函数和 `<Content />` 组件](https://docs.astro.build/en/guides/content-collections/#rendering-body-content) 渲染 Markdown 文件，Astro 5 添加了对 [any loader to render any HTML content](https://docs.astro.build/en/reference/content-loader-reference/#rendered) 的支持。 但是，如果您想在内容加载器中呈现 Markdown 内容，则必须自己处理 Markdown 解析。 这可能会令人困惑，因为它与您网站其他部分的 Markdown 的呈现方式不一致，并且没有使用相同的 Markdown 配置。

Astro 5.9 将新的辅助函数添加到加载器上下文 - `renderMarkdown` - 允许您直接在加载器中呈现 Markdown 内容。 它使用与用于 Markdown 文件的渲染器相同的设置和插件，包括在 Astro 项目中配置的任何 Markdown 设置。

`renderMarkdown` 函数在加载器上下文中可用，并返回具有两个属性的对象：`html` 和 `metadata`。 这些与内容集合中内容条目的 [`rendered` 属性](https://docs.astro.build/en/reference/content-loader-reference/#rendered) 相匹配，因此它们可用于在加载器中轻松添加对 `render()` 的支持。

导入类型 { loader } 来自 'Astro/Loaders';import { loadFromCMS } 来自 './cms';
导出函数 myLoader(settings): loader { return { name: 'my-loader', async load({ rendermarkdown, store }) { const 条目 = await loadFromcms(); 存储.clear(); for (const entry of entry) { // 假设每个条目都有一个带有 Markdown 内容的“内容”字段 store.set(entry.id, { id: entry.id, data: entry, rendered: await rendermarkdown(entry.content), }); } }, };}

现在，即使使用您的自定义加载程序，您也可以访问 `render()` 和 `<Content />` 就像您的 Markdown 内容是在您的项目中本地存储的那样：

---import { getEntry, render } from 'astro:content';const entry = await getEntry('my-collection', astro.params.id);const { content } = await render(entry);---<Content />

有关详细信息，请参阅 [content loaders documentation](https://docs.astro.build/en/reference/content-loader-reference/#rendermarkdown)。

在实验性响应图像中禁用默认样式
----------------------------------------------------

使用 [experimental responsive images](https://docs.astro.build/en/reference/experimental-flags/responsive-images/) 时，Astro 应用默认样式以确保图像正确调整大小。 在大多数情况下，这就是您想要的——它们的应用特异性较低，因此您自己的样式会覆盖它们。

但是在某些情况下，您可能希望完全禁用这些默认样式。 在使用 Tailwind 4 时，这特别有用，因为它使用 CSS 级联层来应用样式，因此很难覆盖 Astro 的默认样式。

Astro 5.8.1 添加了一个新的 `image.experimentalDefaultStyles` 布尔配置选项来应用这些默认样式。 它默认为 `true`，提供当前的响应图像行为。 但是，如果您不想与 Tailwind 4 战斗，到处设置 `!important` 样式，您可以简单地在您的 Astro 配置中禁用此选项：

导出默认值 { image: { experimentDefaultStyles: false, }, experimental: { ResponsiveImages: true, },};

有关详细信息，请参阅 [experimental responsive images documentation](https://docs.astro.build/en/reference/experimental-flags/responsive-images/#overriding-default-styles)。

允许适配器抑制有关功能支持的日志
-------------------------------------------------

[Astro adapters](https://docs.astro.build/en/reference/adapter-reference/) 可以[declare whether or not they support certain Astro features](https://docs.astro.build/en/reference/adapter-reference/#building-an-adapter)，以及该支持是稳定的还是实验性的。

在构建过程中，如果站点使用适配器不支持的功能，Astro 将记录警告或错误。 但是，有时适配器可能需要记录更具体的消息以帮助用户解决问题。 以前这可能会令人困惑，因为这些自定义日志除了天文生成的日志之外还被打印出来，并且可能看起来与它们相矛盾。

Astro 5.9 添加了一个选项，允许适配器抑制不支持的功能的日志记录。 适配器作者可以添加 `suppress: "all"`（禁止默认和自定义消息）或 `suppress: "default"` （仅抑制 Astro 的默认消息）：

setAdapter({ name: 'my-astro-integration', supportedAstrofeatures: { staticOutput: "stable", HybridOutput: "stable", sharpImageService: { support: "limited", message: "Sharp image 服务在部署环境中不可用，但是 将被构建上的预渲染页面使用。”，抑制：“默认”，}，}})

有关更多详细信息，请参阅 [the Adapters API reference](https://docs.astro.build/en/reference/adapter-reference/#astro-features)。

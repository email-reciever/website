对内容加载器的 TOML 支持
--------------------------------

Astro 5.12 为内容集合中的 TOML 文件提供了本机支持。 Astro 的 [`file()` 和 `glob()` 内容加载器](https://docs.astro.build/en/reference/content-loader-reference/#built-in-loaders) 已经为 Markdown、JSON 和 YAML 文件提供了覆盖，现在您也可以使用 TOML 文件。

无需配置即可启用 TOML 支持：只需使用内置加载器将 `.toml` 文件添加到集合中即可。 例如，如果您有这样的 toml 文件目录：

src/内容/航天器/apollo.toml

名称 = "Apollo"launch_date = "1969-07-16"crew = ["Neil Armstrong", "Buzz Aldrin", "Michael Collins"]

然后，您可以创建包含 TOML 文件的内容集合：

src/content/config.ts

从“astro:content”中导入 { defineCollection, z };从 'astro/loaders' 导入 { glob };
const spacecraft = defineCollection({ loader: glob({ pattern: '*.toml', base: './src/content/spacecraft' }), schema: z.object({ name: z.string(), launch_date: z.coerce().date()，船员：z.array(z.string()), }),};export const 集合 = { spacecraft };

然后，您可以访问 Astro 组件中的 TOML 内容：

src/pages/spacecraft.astro

---import { getCollection } 来自“astro:content”；
const spacecraft = await getcollection('spacecraft');---
<ul> { spacecraft.map((item) => ( <li> <h2>{item.name}</h2> <p>发布日期：{item.launch_date.toLocaledateString()}</p> <p>crew: {item.crew.join(', ')}</p> </li> )) }</ul>

新的 Netlify 开发体验
---------------------------

[Netlify adapter](https://docs.astro.build/en/guides/integrations-guide/netlify/) 现在由 Netlify 自己的 [Vite plugin](https://docs.netlify.com/build/frameworks/framework-setup-guides/vite/#vite-plugin) 提供支持，将 Netlify 的整个平台和原语引入您的本地开发环境！

### Netlify在本地主机上的力量

到目前为止，在本地开发期间使用带有Astro的Netlify原语需要通过[Netlify CLI](https://docs.netlify.com/api-and-cli-guides/cli-guides/get-started-with-cli/)运行您的项目。 新适配器将这些功能直接嵌入到 Astro 的开发服务器中。

升级到最新版本的适配器后，运行 `astro dev` 将提供：

*   本地 [Netlify Image CDN](https://docs.netlify.com/build/image-cdn/overview/#local-development) 服务器。 默认情况下用于 [images](#netlify-image-cdn-support)
*   本地 [Netlify Blobs](https://docs.netlify.com/build/data-and-storage/netlify-blobs/) 服务器。 默认情况下用于 [sessions](#sessions)
*   [Redirects, rewrites](https://docs.netlify.com/routing/redirects/) 和 [headers](https://docs.netlify.com/routing/headers/#app) 来自您的 Netlify 配置
*   按需页面中的 [Netlify Edge Context](https://docs.astro.build/en/guides/integrations-guide/netlify/#accessing-edge-context-from-your-site)
*   [Environment variables](https://docs.netlify.com/environment-variables/overview/) 从您的链接的 Netlify 网站中填充

### 配置开发功能

随之而来的是一种配置它们的方法。 Netlify 适配器现在在其配置中接受 `devFeatures` 选项以自定义在开发过程中启用的功能。 目前，您可以配置的功能是：

*   `images`：在开发期间为 Astro 图像启用本地 Netlify 映像 CDN。 默认为 `true`。
*   `environmentVariables`：使用链接的 Netlify 站点自动填充开发服务器的环境变量。 默认为 `false`。

您将此作为选项传递给 Astro 配置文件中的 Netlify 适配器：

astro.config.mjs

从'@astrojs/netlify'导入'Astro/config'import netlify
导出默认的 defineConfig({ 适配器: netlify({ devfeatures: { environmentvariables: true, images: false, }, })})

现在您可以在自己的家中享受丰富的 Netlify 风味！

感谢来自 Netlify 的 [Eduardo Bouças](https://github.com/eduardoboucas) 和 [chee rabbits](https://github.com/chee) 贡献了此功能。 额外感谢 Chee 也为这篇文章做出了贡献。

实验原始环境值
---------------------------------

一个新的实验配置选项允许您在 `import.meta.env` 中选择退出 Astro 对环境变量值的自动类型强制。 默认情况下，Astro 将 `"true"`、`"false"`、`"1"` 和 `"0"` 等字符串值转换为各自的类型，但这可能是出乎意料的，因为环境变量通常被期望是字符串。

这将 Astro 的行为与 [Vite’s handling of environment variables](https://vite.dev/guide/env-and-mode.html#env-variables) 保持一致，并且可能会成为未来主要版本中的默认设置。

要启用此功能，请将 `rawEnvValues` 标志添加到您的 Astro 配置中：

astro.config.mjs

导出默认 defineConfig({ 实验性：{ rawEnvValues: true, },});

此实验选项仅影响 `import.meta.env` 对象，不会影响为 Astro 提供支持的 `astro:env` 模块 [type-safe environment variables](https://docs.astro.build/en/guides/environment-variables/#type-safe-environment-variables)。

感谢贡献此功能的 [Adam Langbert](https://github.com/adamhl8)。

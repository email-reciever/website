**介绍 Astro 4.0!** 新的 API、更快的构建、重新设计的文档以及用于 Astro 的独特新开发工具，以新的和令人兴奋的方式增强您的本地开发环境。

**什么是 Astro？** [Astro](https://astro.build/) 是用于构建包括博客、营销和电子商务在内的内容驱动网站的 Web 框架。 如果您需要一个能够快速加载且具有出色 SEO 的网站，那么 Astro 适合您。

**发布亮点包括：**

*   [The Astro Dev Toolbar](#the-astro-dev-toolbar)
*   [Internationalization (i18n) routing](#internationalization-i18n-routing)
*   [Incremental Content Caching (Experimental)](#incremental-content-caching-experimental)
*   [New View Transition APIs](#new-view-transition-apis)
*   [Redesigned logging](#redesigned-logging)
*   [Redesigned documentation](#redesigned-documentation)

Astro 4.0 现在在 NPM 上可用。 访问 [astro.new](https://astro.new/) 直接在浏览器中尝试 Astro 4.0，或在终端中运行以下命令以开始新的本地项目：

    # 创建一个新的Astro 4.0项目：npm create astro@latest

**大多数现有的代码库在升级到 Astro 4.0 时会遇到零问题。 查看 [Upgrade Guide](https://docs.astro.build/en/guides/upgrade-to/v4/) 以获取完整的演练和每个更改的详细细分。

Astro Dev 工具栏
----------------------

**Astro 4.0 引入了开发工具栏——一种强大的新方法，可以使用 Astro 增强和自定义您的本地浏览器开发体验。** 检查您的页面，捕获棘手的可访问性问题，并使用自定义应用程序和第三方工具扩展工具栏本身。

![](/_astro/post-asset-toolbar.CiKIQCQl_Z14I1h1.webp)

Astro Dev 工具栏仅在开发过程中出现在浏览器中，并且永远不会包含在您的最终生产版本中。 工具栏隐藏在页面底部，直到您需要它。 将鼠标悬停在附近，工具栏会弹出几个不同的应用程序：

**检查：** 突出显示页面上的交互式 UI 组件岛。 这个工具栏应用程序旨在利用 Astro 的独特 [island architecture](https://docs.astro.build/en/concepts/islands/)。 突出显示页面上的岛屿可以帮助您了解哪些元素是交互式的与轻量级的静态 HTML。 从那里，您可以查看道具并单击以直接在代码编辑器中打开组件。

**Sentry:** 我们与 [Sentry](https://sentry.io/) 合作设计了此工具栏的初始版本。 Sentry 是 Web 领先的应用程序监控平台，他们很高兴能与我们合作开发用于 Astro 的新独立调试工具。 _ 明天，12 月 6 日回来，了解有关我们合作伙伴关系和 Spotlight.js 正式发布的更多信息！_

**StoryBlok:** [Storyblok](https://www.storyblok.com/) — 我们的官方 CMS 合作伙伴 — 还提供了一个工具栏应用程序作为他们 [official Astro integration](https://github.com/storyblok/storyblok-astro) 的一部分。 在 Astro 4.0 中，所有 StoryBlok 用户都应该在其工具栏中看到一个新应用程序，该应用程序可为 Storyblok + Astro 提供对文档、教程和社区资源的快速访问。 期待更多的 CMS 功能将在未来登陆。

**第三方应用程序：** Astro 开发人员和第三方集成作者可以使用新的 [Dev Toolbar API](https://docs.astro.build/en/reference/dev-toolbar-app-reference/) 来构建自己的嵌入式 JavaScript 应用程序进行开发。 这为构建开发工具提供了一个全新的原语，支持以下功能：

*   在浏览器中的表面测试和linting错误。
*   使用 [localtunnel](https://github.com/localtunnel/localtunnel) 打开您的开发环境到公共 Internet。
*   轻松访问外部工具，如 [Squoosh](https://squoosh.app/) 图像优化器。
*   内部团队管理面板可自动执行常见任务，例如在开发过程中切换用户帐户。

在 [Astro integration catalog](https://astro.build/integrations/?search=&categories%5B%5D=toolbar) 中为您的工具栏发现新的发布周应用程序，并了解如何 [build your own](https://docs.astro.build/en/reference/dev-toolbar-app-reference/)。 在接下来的几个月中，我们将继续通过新功能和第三方 API 来增强工具栏。 或者，您可以更新您的配置以禁用项目中的应用程序工具栏，并运行 `astro preferences disable devToolbar --global` 以全局禁用机器上的所有项目的工具栏。

国际化 (I18N) 路由
---------------------------------

作为内容驱动网站的 Web 框架，我们经常被问到 [internationalization](https://web.dev/learn/design/internationalization)。 作为 Web 开发人员，处理国际化（通常称为“i18n”）可能意味着您的代码库有很多额外的复杂性：路由、重定向、翻译、相对链接处理……

Astro 4.0 引入了新的国际化路由，以帮助您构建更少复杂的全球可访问的网站。 利用自动 i18n 路由和低级辅助功能等新的 Astro 功能来处理 URL。

Astro 新的内置路由支持允许您通过中央配置定义您的语言环境：

导入 { defineConfig } 从“astro/config”导出默认 defineConfig({ i18n: { defaultLocale: "en", locales: ["en", "es", "pt-br"] }})

自定义您的行为：

*   **fallbacks** 用于某个区域中的内容不可用时
*   **前缀**在URL中添加语言环境名称的行为
*   ** 通用语言环境和语言代码的别名**

对于 `'server'` 与服务器端渲染 (SSR) 构建的构建，Astro 自动检测用户的首选语言，以便您可以进一步定制内容、添加重定向或进一步自定义路由处理。

国际化路由支持最初是作为 Astro 3.5 的实验功能添加的。 今天，它正在进入 Astro 4.0 的稳定版本。 阅读新的 [Astro Internationalization guide](https://docs.astro.build/en/guides/internationalization/) 以了解更多信息并尝试新的 API。

增量内容缓存（实验）
----------------------------------------

Astro 4.0 引入了 **Incremental 内容缓存** 作为一个实验性的新功能，以显着加快大型网站的构建性能。

随着时间的推移，网站代码库通常需要更长的时间来构建。 由于在每个版本中重新生成相同的页面，静态网站会更加严重地遭受这个问题。 在 Astro 4.0 中，我们决定引入缓存以帮助减少 `astro build` 命令中完成的重复、不必要的工作量。

在现实世界 [Astro Docs](https://github.com/withastro/docs) 代码库中启用内容缓存使 `astro build` 中的相关步骤从 133.20s 下降到 10.46s，速度约为 92%。 端到端的构建时间从 4 分钟 58 秒减少到刚刚超过 60 秒，**总构建时间快 80%**。 我们已经在其他现实世界场景中看到了同样令人印象深刻的结果。

![](/_astro/4.0-post-asset%202-2.73tRhX_a_13nOqP.webp)

增量内容缓存挂钩到 [Content Collections API](https://docs.astro.build/en/guides/content-collections/)。 因为 Astro 拥有用于访问和管理集合中内容的 API，因此我们的构建能够使用内部构建清单安全地跟踪集合中的更改。 Astro 可以检查每个构建上的缓存并重用未更改的内容条目。

对增量内容缓存的实验性支持首次在 Astro 3.5 中以“内容集合构建缓存”的名义引入。 随着我们继续最终确定缓存行为，此功能在 4.0 中仍然是实验性的。 如果您感觉是实验性的，请立即在项目配置中启用 `experimental.contentCollectionCache` 以实现更快的构建。

新视图过渡 API
-------------------------

Astro 3.0 将 [View Transitions](https://docs.astro.build/en/guides/view-transitions/) 作为新的 API 引入世界，以仅使用服务器呈现的 HTML 和最小的客户端 JavaScript 来构建交互式的应用程序体验。 在 Astro 中的视图转换中，您可以执行以下操作：

*   **Animate** 不同页面之间的导航，无需运送重型水疗中心。
*   **PERISIST** 跨页面（如视频播放器和地图）的有状态 UI。
*   **morph** 自动从一个页面到另一个页面的通用元素。
*   **Slide** 和 **Fade** 元素，让您的页面更加个性化。

自最初推出 View Transitions 以来，我们一直在继续改进我们的支持。 Astro 4.0 将更多可配置的 API 和新的、令人兴奋的用例，使 View 转换更进一步：

*   **Forms:** 视图转换现在可以与静态 HTML 表单和动态客户端表单组件进行交互，触发表单提交而不是链接导航的转换。
*   **预取：** 现在，您可以指定链接在悬停、点击或在页面上可见预取。 您还可以在单个链接上启用/禁用预取。
*   ** 路由播音员：** 辅助技术的内置功能。
*   一个低级的 `navigate()` JavaScript API，您可以使用它来手动触发导航。
*   您可以插入以自定义加载的完整生命周期事件系统。 您甚至可以使用它来替换内置的元素交换算法。

我们将继续倡导 View 过渡的强大功能以及它们提供仅服务器提供的 HTML 和一点 JavaScript 的繁重客户端 SPA 体验的能力。 更多功能和改进正在进行中！

Astro Core 团队希望对 [@martrapp](https://github.com/martrapp) 大声疾呼，感谢他们的贡献，并努力将这些新 API 置于 Astro 4.0 中。 阅读更新的视图转换 [guide](https://docs.astro.build/en/guides/view-transitions/) 或新的 [tutorial](https://docs.astro.build/en/tutorials/add-view-transitions/) 以了解有关如何在自己的项目中使用这些新 API 的更多信息。

重新设计的日志记录
-------------------

Astro CLI 在 4.0 版本中获得了一罐新鲜的油漆，并具有重新设计的伐木经验。 亮点包括：

*   **删除了不必要的日志记录：** 以前，一些常见的场景会导致双重日志记录和其他不必要的日志。
*   **更简洁的错误：**现在错误占用终端中的行数更少，这意味着当出现问题时在较小的终端中滚动更少。
*   **细化堆栈跟踪：** 默认情况下，错误不再包括每个堆栈跟踪中的无用 Vite 运行时内部。

结果是Astro的`dev`和`build`命令在新的Astro 4.0中更容易阅读、解析和调试。

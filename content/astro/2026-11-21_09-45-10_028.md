[Firebase](https://firebase.google.com/)是移动和Web应用开发平台。 它允许用户轻松地原型化和扩展他们的应用程序，而不必担心单个后端服务。 在谷歌的支持下，Firebase 受到数百万企业的信任，可以抽象出后端基础设施，这样用户就可以专注于日常业务的核心方面。

拥有一个可访问的博客对 Firebase 很重要，这样用户就可以随时了解最新的新闻和公告。 Astro 能够帮助 Firebase 重建他们的博客，以提高 71% 的性能，并将发布时间从数小时缩短到几分钟。

![](/_astro/firebase-lighthouse-before-after.Dbopwxag_20bo7u.webp)

Firebase 博客的灯塔分数。

挑战
-----------

Firebase 的 10 名开发人员团队曾经在 Blogger 上托管他们的博客。 有了这个 CMS，他们必须首先在 Google Docs 中写一篇博文，然后将草稿转换为 Blogger 文档。 即使是简短的博客文章也很容易在发布前完成一个小时的工作。

Blogger的编辑经验也有问题：

1.  图像和其他交互组件需要开发人员手工制作 HTML。
2.  Blogger 没有个人资料图片。 您必须插入 HTML 和 CSS 以直接将个人资料图像表示到博客文章中。
3.  有时，即使您知道出了什么问题，您也无法解决问题！ 例如，在 Blogger 中很难控制可访问性的改进。 这为用户带来了低于标准的体验。

要求
-------------

根据 Firebase 博客团队的首席工程师 David East 的说法，Firebase 需要一个具有现代开发经验的工具。 他们希望在10人的协作开发人员团队中保持更高性能的博客并更快地发布博客。

解决方案和实施
----------------------------

借助 Astro，新的团队成员能够在 30 分钟内获得设置，这要归功于文档。

> 文档是惊人的。 我确实认为非常有帮助的是，Astro 在对会议非常强大方面做得非常好。 因此，当您尝试将其用于工作时，它只是痛苦地清楚您在做什么。 你永远不会担心椅子会从你下面拉出来。 你总是可以在这些假设上发展。

— David East，首席工程师@ Firebase（博客）

Firebase 开发人员还能够使用 Astro 实现复杂且可访问的动画——这是由于其有限的模板化，他们无法在 Blogger 上完成这一壮举。 例如，该团队希望创建 Firebase 博客主页上的切片动画。 然而，这个切片动画在当今网络上很难创建。 相反，您必须将相同的内容片段放在彼此之上，并删除动画中的某些部分，例如窗帘。 屏幕阅读器将尝试阅读和标记隐藏的内容，这让用户感到困惑。 由于Astro的灵活性，Firebase能够轻松构建此动画。

与 Astro 相关的迁移部分进展迅速。 他们只是通过能够获取他们的 Google 文档内容，使用插件将其转换为 Markdown，然后将其粘贴到 Astro 文档中，从而看到了改进。 项目的大部分时间实际上都花在完善博客的设计以及构建概念验证本身上。

结果
--------

通过从 Blogger 切换到 Astro，发布标准博客文章所需的时间从几个小时到几分钟。 它还需要 6 分钟来生成一个包含 GitHub 操作的完整站点。 现在，使用 GitHub Actions 的构建时间平均为 1.5 分钟，整体构建时间减少了 75%。

**什么是 Astro？** [Astro](https://astro.build/) 是用于构建包括博客、营销和电子商务在内的内容驱动网站的 Web 框架。 如果您需要一个能够快速加载且具有出色 SEO 的网站，那么 Astro 适合您。

内容层
--------------

Astro 是内容驱动网站的最佳框架，而在 Astro 5.0 中，我们正在使它变得更好。 **Astro 内容层**是一种新的灵活且可插拔的方式来管理内容，提供统一的、类型安全的 API 来定义、加载和访问您的 Astro 项目中的内容，无论它来自哪里。

const database = defineCollection({ // 用加载器自动获取一行中的内容：notionLoader({ /* ... */ })});
const countries = defineCollection({ // //从任何地方加载数据！加载器：() => fetch('https://api.example.com/countries').then(res => res.json()),});
导出常量集合 = { 博客、数据库、国家 }

自 Astro 2.0 以来，内容集合允许您在类型安全的集合中组织静态内容，然后在您网站上的任何页面中使用它们。 但是，随着您网站的增长，将您的内容放在 Git 存储库中的 Markdown 文件中可能会变得不那么实用。 您可能希望使用 CMS、站点的某些部分由 REST API 提供支持，或者使用来自 Cloudinary 等资产管理系统的优化图像。 这很快就会变得一团糟，需要各种 API 和数据获取策略。

内容层是解决此问题的解决方案，将您的所有内容带入一个友好、类型安全的数据存储，随时可以在您的网站上使用。 它们是您知道和喜爱的内容集合，但具有**Loaders**的额外功能——可插入和转换数据的可插拔功能。 使用内容层，您可以：

*   使用 [built-in loaders](https://docs.astro.build/en/guides/content-collections/#built-in-loaders) 从磁盘上的任何位置加载内容。
*   定义您自己的加载程序以从 [just a few lines of code](https://docs.astro.build/en/guides/content-collections/#building-a-custom-loader) 中的任何 API 中获取内容。
*   使用越来越多的 [community-built and third-party loaders](https://astro.build/integrations/?search=&categories%5B%5D=loaders) 之一从 [Storyblok](/blog/storyblok-loader/)、[Cloudinary](/blog/cloudinary-loader/) 或 [Hygraph](/blog/hygraph-loader/) 等流行资源中获取内容。

当您构建站点时，Astro 将从所有这些源中加载数据，并将集合缓存到可以在页面中使用的单个类型安全数据存储中。

![](/_astro/content-layer-architecture.D58x9rAj_ZxO2cM.webp)

内容图层不只是让您从更多的地方加载您的内容。 它还为您当前网站的性能带来了重大改进。 在 Astro 5 中，您的内容集现在可以在内容繁重的网站上的 Markdown 页面上构建速度快 5 倍，MDX 的速度缩短 2 倍，而内存使用量减少了 25-50%。

内容层对内容集合的处理方式进行了重大更改，但我们内置的向后兼容性意味着大多数人不必对其现有代码进行任何更改。 有关详细信息，请参见 [the migration guide](https://docs.astro.build/en/guides/upgrade-to/v5/#legacy-v20-content-collections-api)。

要开始使用新内容图层集合，请查看 [content collections guide](https://docs.astro.build/en/guides/content-collections/)。

服务器岛
---------------

服务器岛是 Astro 帮助将主流带入主流的 [islands architecture](https://astro.build/blog/introducing-astro/) 概念的演变。 **服务器岛**将同样的想法扩展到服务器。 使用服务器岛，您可以将高性能静态 HTML 和动态服务器生成的组件组合在同一页面上。

在任何给定的网页上，您可能拥有以下内容：

*   完全静止且永不改变。
*   动态地由一个不频繁但比你部署的更频繁的数据库支持。
*   _personalized_ 内容，为个人用户量身定制。

以前，您必须为所有这些类型的内容选择一种缓存策略，如果页面是登录体验，通常意味着根本没有缓存。 现在，使用服务器岛，您可以两全其美。

![A diagram showing the server island population parts of the page from the server.](/_astro/dark-mode-server-islands-diag.CCPm1I4W_1F1hFI.webp)

服务器岛用于您最动态的内容：用户头像、购物车和产品评论等个性化内容。 当这些组件被推迟时，您可以更积极地缓存页面本身。

这意味着用户登录或不登录，将立即看到页面中最关键的部分，因为他们在 Edge CDN 上缓存。 您还可以将自定义后备内容设置为在加载动态岛之前简要显示。

每个岛屿都是独立加载的，以优化游客体验。 这意味着一个较慢的岛屿，例如连接到传统后端的一个较慢的岛屿，不会延迟其余的个性化内容被看到和交互。

在过去的几个月中，服务器岛已可用于测试。 在此期间，我们通过以下方式聆听了您的反馈和增强的服务器岛屿：

*   在岛内设置标题，允许您自定义各个岛屿的缓存寿命。
*   在执行自动页面压缩的平台上使用服务器岛。
*   通过使用服务器上生成的密钥自动加密服务器岛道具来增加隐私。

Astro 5，我们是 [rethinking what it means for a site to be “static”](#simplified-prerendering)。 服务器岛为您将来在 Astro 中构建静态项目提供了基本原语，仅在您需要的地方使用动态位。

要了解有关服务器岛的更多信息，请查看 [server islands guide](https://docs.astro.build/en/guides/server-islands/)。

### 简化的预渲染

自 Astro 2 年前发布 1.0 版本以来，Astro 支持多种输出模式：静态，在构建时将网站构建为良好的旧静态 `.html` 文件，以及服务器，其中页面在运行时呈现，允许您构建高度动态 网站。

经过多次请求，[in Astro 2.0 we made this more granular by creating a third output mode: Hybrid](https://astro.build/blog/hybrid-rendering/)，允许在同一网站中静态和服务器渲染页面混合。

随着 Astro 的发展和获得强大的功能，如动作或服务器岛，无法在纯静态输出模式中使用，我们意识到“我需要使用什么设置？”的矩阵 变得又大又累人，无法解释和记录。 我们还发现，人们最终比使用细粒度控件更容易服务器渲染，这使得他们的站点比他们需要的速度更慢。

在 Astro 5.0 中，我们很高兴地说我们已经简化了所有这些： **混合和静态选项已合并为默认 `static` 选项。

不要害怕，如果你仍然想要好的旧的静态生成的 `.html` 文件，你仍然会得到它们：Astro 默认仍然是静态的！ 但是，如果您将其中一个页面设置为 `prerender = false`，Astro 现在将动态切换其输出模式，允许您使用需要服务器端渲染的功能，而无需弄清楚您需要哪种配置模式。

想了解更多关于新的输出模式？ 查看我们的 [updated documentation on on-demand rendering](https://docs.astro.build/en/guides/on-demand-rendering/#enabling-on-demand-rendering)。

天文：环境
----------

配置应用程序是开发过程中重要但复杂的部分。 Astro 5 中的新功能是 `astro:env` 模块，它为您提供了一种类型安全的方法来定义应用程序期望和需要的环境变量。

使用 `astro:env` 您可以：

*   配置您的变量是在 **Client** 还是 **Server** 中使用，以帮助细分不同的用途。
*   将变量指定为**secrets**，例如您不希望在客户端中或内联到服务器构建中的API密钥（任何有权访问构建输出的人都可以查看）。
*   指定变量是 **required** 还是只是一个可选的增强功能，允许您在服务器完全启动之前捕获错误。
*   定义变量的 ***type**，例如字符串、数字、布尔值或枚举，以防止需要在您的应用程序中投射。

我们构建 `astro:env` 是为了提供对环境变量的更多控制和结构，并为您提供类型安全。 一旦你定义了你的变量，你可以简单地导入和在任何模块中使用它们。

从“astro:env/server”导入 { stripe_api_key }；

有关如何使用 `astro:env` 的更多信息，请参阅我们的 [type safe environment variables](https://docs.astro.build/en/guides/environment-variables/#type-safe-environment-variables) 指南。

维特 6
-------

Astro 5 是最早在一周前发布的 Vite 6 框架之一。 （不用担心：我们一直在使用 Beta 版本，因此在升级到 Astro 5 时，您可能不需要更改任何代码。）

Vite 6 的亮点是一个新的环境 API，它允许创建新环境，使开发体验更紧密地与代码在生产中的运行方式保持一致。 集成作者今天可以开始使用这个新的 API； 未来，我们希望找到在 Core 中使用它的方法，例如为 Cloudflare 用户提供更好的开发兼容性或提供边缘运行时进行本地测试。

要了解有关 Vite 6 的更多信息，请查看他们的 [official release announcement](https://vite.dev/blog/announcing-vite6)。

实验功能
----------------------

以下是我们在过去几个月中一直在制作的新实验功能。 它们现在可以通过启用 `experimental` 标志进行预览，并且将在未来的 Astro 5.x 的小版本中变得稳定。

astro.config.mjs

从“astro/config”导入 { defineconfig }；
导出默认 defineConfig({ 实验性：{ 响应图像：true, svg:true, }});

### 实验：图像裁剪支持

Astro 现在支持使用其默认的清晰图像服务进行图像处理时裁剪图像。

使用新的 `fit` 和 `position` 道具，您现在可以创建与其容器完全匹配的图像，节省宝贵的字节。

---从“../logo.png”导入徽标;---
    <Image src={logo} fit="cover" width={200} height={200} />

有关此功能的更多信息，请阅读 [our reference on experimental responsive image support](https://docs.astro.build/en/reference/experimental-flags/responsive-images/#responsive-image-properties)。

### 实验：响应式图像布局

图像很艰难：屏幕密度很多，屏幕尺寸很多……很多东西。 让图像在所有设备上看起来不错可能具有挑战性，更不用说将 4K 图像提供到小屏幕的明显性能影响。

Astro 最新的实验图像功能支持设置预定义的响应图像布局。 这些将自动生成正确的 `srcset` 和 `sizes` 值，使您的图像看起来不错，并且在所有设备上都表现良好。

---import { image } 来自 "./rocket.jpg" 的 "Asro:assets" 导入火箭 ---
    <Image src={rocket} width={800} height={600} layout="responsive" />

有关此功能的更多信息，请访问 [our reference on experimental responsive image support](https://docs.astro.build/en/reference/experimental-flags/responsive-images/#responsive-image-properties)。

### 实验：SVG 组件

你有没有希望在 Astro 中使用 SVG 更容易？ 我们也是！ 还有什么比组件更重要？

使用 Astro 5 的实验性 SVG 标志，您可以像其他任何 Astro 组件一样导入 `.svg` 文件并使用它们。 您可以传递诸如 `width`、`height`、`fill`、`stroke` 以及本机 `<svg>` 元素接受的任何其他属性自动应用它们的道具：

---从'../assets/logo.svg'导入徽标---
<!-- 传递宽度和高度以覆盖默认大小 --><Logo width={100} height={100} fill="blue" />

有关 SVG 组件以及如何使用它们的更多信息，请访问 [our reference on SVG components](https://docs.astro.build/en/reference/experimental-flags/svg/)。

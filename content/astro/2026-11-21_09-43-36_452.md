**这是我们关于 _“ASTRO 的未来”_ 系列的第 2 部分，涵盖了我们在 2024 年为 Astro Web 框架计划的三个主要进展。这篇文章为 Astro 引入了更强大的内容层：一种使用本地和远程内容源的新方法。**

在 Astro 2.0 中，我们发布了原始 [Content Collections API](https://docs.astro.build/en/guides/content-collections/)。 内容集合是围绕我们自己的经验和挫败感而设计的，他们努力在现代 Web 框架中扩展大型降价项目，包括当时的 Astro。 我们的目标是使ASTRO 中的本地内容（Markdown、MDX 等）更轻松地与任何其他 Web 框架一起使用。

内容集合将内置的内容管理功能带入了 Astro 的内容模式、FrontMatter 验证和完全支持 TypeScript 的查询 API：

从“astro:content”导入 { getCollection, getEntry };
// 从集合中获取所有条目。// 需要集合的名称作为参数。// 示例：检索 `src/content/blog/**`const allblogposts = await getCollection('blog');
// 通过请求 URL 从集合中获取单个条目。// 需要集合的名称和条目 ID slug。// 示例：retrieve `src/content/blog/future-of-astro-content-layer.mdx`const blogPostEntry = await getEntry('blog', astro.params.slug);

内容是天文中的基本原语。 但无论您的内容在哪里，使用 Astro 构建内容驱动的网站都应该很容易。 我们已经为本地降价解决了这个问题，现在内容存在于您的仓库之外的大型项目呢？ 在远程 API 中？ 在你最喜欢的 CMS 中？

**我们开始为 Astro 探索一个新的、更强大的内容层 API。 让我们深入了解它的工作原理。

更强大的内容引擎
------------------------------

当前内容集合的限制之一是我们当前的数据结构完全存储在内存中。 这适用于静态站点，但是将所有数据加载到内存中会对无服务器SSR 环境中的冷启动时间造成严重破坏。

我们目前正在探索 [LibSQL](https://github.com/tursodatabase/libsql) (SQLite) 作为 Astro 中内容的新底层存储机制。 通过在 Astro 中嵌入 SQLite，我们可以在一个项目中扩展到数百万个内容条目，而不会出汗。 此外，Sqlite 的文件存储允许我们跨版本缓存内容，将大大加快开发和构建性能。

对于开发人员来说，直接访问 SQL 数据库也会为需要它的人引入更强大的查询 API。 我们专门设计了我们自己的 `getCollection` 和 `getEntry` API 是故意简单的，这些 API 不会去任何地方。 但是，这始终将过滤和排序的责任留给用户。 内部 SQL 数据库将帮助我们弥合这一差距，并为需要它的任何人提供更高级的内置查询。

更灵活的内容源
------------------------------

从当前 `src/content` 目录中分解内容需要重新考虑我们如何在 Astro 中定义集合。 我们正在探索一种新的、更灵活的 `defineCollection()` API 的数据加载器，而不是像 Astro 中内置的那样硬编码的文件系统加载器。

defineCollection({ name: 'my-portfolio', data: (db: db, watcher: FileSystemWatcher) => { // 1. 获取你的数据 // 2. 将它插入到数据库中 // 3. 可选：在开发过程中处理内容更新 //（文件更改， CMS WebSocket 通知) },})

使用这个新的 API，您可以：

*   从文件系统中读取文件（就像我们今天已经做的那样）
*   提供一个简单的硬编码内联数据数组
*   使用`fetch()`从远程API加载数据
*   从Storyblok等外部CMS加载内容

这也将在更大的 Astro 开发者生态系统中实现可组合性。 任何人都可以将加载程序发布到 npm。 作为 Astro 开发人员，这意味着您将能够利用充满可插拔和可重用内容加载器的社区生态系统。

// 示例：来自“some-instagram-astro-content-loader”的 AstroImport Instagram 的（想象的）Instagram 个人资料加载程序；
defineCollection({ name: 'my-portfolio', data: instagram({ /* ... */ }),})

我们将与新的 Content Layer API 并行探索这个可插拔的生态系统故事。 我们很高兴为 Astro 用户提供一些可以为可组合内容提供全新机会的东西，而不会牺牲我们当前内置的 Markdown 支持您知道和喜爱的轻松。

下一步
-----------

请留意今年晚些时候将在 Astro 上推出的实验性支持。 我们经常在实验标志稳定之前推出新功能，这让我们的开发人员有足够的时间来尝试新的 API 并留下反馈。

要了解有关内容层提案的更多信息并留下早期反馈，您可以访问 [the ongoing discussion in our open roadmap repo](https://github.com/withastro/roadmap/issues/946)。 当我们开始进行官方实施时，我们将继续在那里和 [our Discord](https://astro.build/chat) 中发布更新。

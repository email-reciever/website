2026 年 11 月 19 日，Ruby 团队披露了 Ruby2Shell ([CVE-2026-132825](https://github.com/ruby/ruby/security/advisories/GHSA-34m4-m9fh-gqp5))，Ruby 以 Ruby 改变字符串大小写的方式溢出了堆缓冲区。 Ruby 对漏洞进行评级，并表示它知道在某些情况下实现远程代码执行的概念证明。 修正了[Ruby 3.3.14, 3.4.13, and 4.0.10](https://www.ruby-lang.org/en/news/2026/11/18/multiple-vulnerabilities-in-regexp-and-string/)中的问题。

范围很广。 Veria Labs 报告说，Ruby on Rails 和经典风格的 Sinatra 应用程序在任何身份验证之前都在其默认配置中到达了 Bug。 捆绑 Ruby 的自托管产品，包括 GitLab、GitHub Enterprise Server、Mastodon、OpenProject、Discourse 和 Chatwoot，在其最新版本中发布了受影响的 Ruby。

Cloudflare WAF 为所有客户（包括免费计划中的客户）阻止了 Ruby2Shell。 我们在 Cloudflare Free Managed Ruleset 和 Cloudflare 托管规则集中添加了两条规则，其中默认操作为 Block：一项用于 Ruby2Shell，另一种用于 GHSA-87FM-7W84-J2PX，Ruby 字符串大小写转换中的相关整数溢出 固定在相同的版本中。

WAF 是一种补偿控件，而不是修补的替代品。 漏洞可以通过WAF看不到的路径到达bug，唯一的完整解决办法就是升级Ruby。 我们的团队继续监控攻击流量，并将随着新技术的出现而更新规则。 您可以跟踪 [WAF changelog](https://developers.cloudflare.com/waf/change-log/changelog/) 中的规则更改，并在 [Cloudflare Zero Wire briefing](https://radar.cloudflare.com/zero-wire/ruby2shell) 中获取最新的漏洞。

Cloudflare 已经修补了自己使用 Ruby 的系统，我们没有发现任何妥协的迹象。

## 我们对 Ruby2Shell 的了解

Ruby 字符串带有编码，Ruby 仍然支持许多传统的单字节编码，例如 ISO-8859-1 (Latin-1) 和 Windows-1252，以及 UTF-8。 在单字节编码中，每个字符需要一个字节，因此更改字符串的大小写通常会产生相同长度的输出。

德国夏普 S (ß) 打破了这一假设。 它的大写形式是两个字符，ss。 在 14 个 ISO-8859 和 Windows-125X 编码中，Ruby 编写了这两个字节，但只检查了 1 个字节。 根据 Veria Labs 的说法，一个带有 21 个尖锐 S 字符的字符串将输出缓冲区溢出 1 个字节。 到达错误的方法是 `upcase`、`swapcase`、`downcase(:fold)` 和 `casecmp?`。 UTF-8 字符串采用不同的代码路径并且不受影响。

一字节溢出看起来无害。 但是，在内存腐败漏洞中，写在堆缓冲区末尾的单个字节可能足以破坏相邻的对象或分配器元数据。 Ruby 说它知道将这个缺陷转化为代码执行的概念证明，Veria Labs 表示将在披露一周后发布自己的概念证明。 我们希望扫描很快开始。

### 为什么会公开默认Rails和Sinatra应用程序

HTML 表单只能发送 GET 和 POST 请求。 为了模拟 PUT、PATCH 或 DELETE，许多 Web 框架在 POST 请求中接受 `_method` 参数。 Rack 是大多数 Ruby Web 框架构建的接口，它在其 MethodoOverride 中间件中实现了这一点，它将 `_method` 的值转换为大写。 Rails 默认包含此中间件，经典风格的 Sinatra 应用程序启用它。 攻击者可以发送一个多部分 POST 请求，其 `_method` 部分声明了一个遗留字符集并包含了一系列尖锐的 S 字符。 在任何应用程序代码或身份验证检查运行之前，框架在仍在路由请求的同时对该值进行增值。

Veria Labs 报告说，默认情况下不会公开其他框架和普通机架应用程序。 改变传统编码中字符串大小写的应用程序代码，无论字符串来自哪里，都可能受到影响。

### WAF看不到的东西

当恶意输入到达通过 Cloudflare 的 HTTP 请求时，WAF 可以阻止漏洞利用。 它无法阻止通往易受攻击代码的每条路径：

*   **绕过 Cloudflare 的流量。** 直接发送到您的源 IP 地址的请求以及内部服务之间的流量永远不会到达 WAF。 将您的来源配置为仅接受来自 Cloudflare 的流量，例如 [Cloudflare Tunnel](https://developers.cloudflare.com/tunnel/) 或 [Authenticated Origin Pulls](https://developers.cloudflare.com/ssl/origin-configuration/authenticated-origin-pull/)。
*   **同一代码中的其他入口点。** 将字符串的大小写从电子邮件、文件导入、消息队列或后台作业中更改的 Ruby 代码可以在没有 HTTP 请求的情况下到达 Ruby2Shell。

### 用WAF攻击得分加深防御力

内存损坏通常只是第一步。 要运行命令，攻击者仍然必须传递第二阶段的有效负载，例如 shell 命令或反向 shell，然后与受感染的服务器进行交互。 [WAF attack score](https://developers.cloudflare.com/waf/detections/attack-score/) 使用机器学习对远程代码执行有效负载的每个请求进行评分，这有助于捕获基于签名的规则可能错过的漏洞利用变化和开发后流量。 创建自定义规则，在企业计划中使用 `cf.waf.score.rce le 20` 或商业计划中的 `cf.waf.score.class eq "attack"` 阻止或挑战请求。

## 现在补丁

Ruby2Shell 将字符串 case 转换中的 1 字节错误计算转换为在默认 Rails 和 Sinatra 应用程序中执行代码的预验证路径。 预计几天内就会有一个公开的概念证明，补丁的窗口很短。 以下是要做的事情：

1.  **检查您的 WAF 覆盖率。** 在免费计划中，Ruby2Shell 规则已经在阻止。 在付费计划中，确认部署了 Cloudflare 托管规则集，并且规则未被覆盖。
2.  **将 Ruby** 升级到 3.3.14、3.4.13 或 4.0.10，并重新启动每个 Ruby 进程，包括后台工作人员。 重建容器镜像。 将 Ruby 3.2 或更早版本上的应用程序移至受支持的系列。
3.  **更新自托管产品** 捆绑 Ruby，例如 GitLab、GitHub Enterprise Server、Mastodon、OpenProject 和 Chatwoot，因为每个供应商都会发布修复程序。 立即重建 Discourse Docker 安装。
4.  **库存您的运行时间。** [Zero Wire briefing](https://radar.cloudflare.com/zero-wire/ruby2shell) 包括提示，您可以让 AI 代理查找您的基础设施中受影响的每个 Ruby 运行时。

随着新技术的出现，我们的 WAF 分析师将不断更新保护措施。 按照 [WAF changelog](https://developers.cloudflare.com/waf/change-log/changelog/) 进行规则更新。

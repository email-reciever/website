2026 年 11 月 19 日，安全研究公司 DepthFirst 披露了 [phpAfterShell (CVE-2026-126714)](https://depthfirst.com/research/phpaftershell)，PHP 的默认基于文件的会话处理程序中的一个漏洞，可以导致远程代码执行。 在 Common Vulnerability 评分系统 (CVSS) 4.0 下，它的得分为 9.2 分（满分 10 分）。 PHP 项目在 8.2.36、8.3.37、8.4.28、8.5.13 和 8.6.0 的版本中修复了它。 这些版本修复了 16 个其他安全漏洞，其中 6 个也被评为严重。

Cloudflare 的 [web application firewall (WAF)](https://developers.cloudflare.com/waf/) 阻止了已知的 PHPaftershell 攻击模式，包括免费计划中的客户。 保护来自于我们于 2026 年 10 月首次部署的 PHP 远程代码执行规则，用于 PHP2Shell 漏洞。 该规则在漏洞被披露之前已经检测到了部分 PHPaftershell 攻击模式，并在 11 月 19 日更新了检测逻辑以覆盖 PHPaftershell。 该规则是 Cloudflare Free 托管规则集和 Cloudflare 托管规则集的一部分，默认启用，其默认操作为 Block。

在同一个WAF版本中，我们在Cloudflare托管规则集上添加了三个用于付费计划的新规则：一种用于PHP-FPM中的请求走私漏洞（CVE-2026-129289），以及两个用于PHP的SOAP扩展中的缺陷 （CVE-2026-15353 和 CVE-2026-129506）PHP 固定在同一版本中。 默认情况下，这些规则在日志操作中启用，因为它们查找的请求模式也可能出现在合法流量中，并且默认情况下阻止可能会破坏它。 客户现在可以查看安全事件中的匹配请求，并在确认规则不影响合法流量后将操作更改为阻止。

WAF 是额外的防御层，而不是补丁的替代品。 一些关键缺陷取决于服务器配置，或者可以通过 WAF 看不到的路径到达，唯一完整的解决方法是升级 PHP 并重新启动每个工作人员。 我们的分析师继续监控攻击活动，并将随着新技术和变化的出现而更新规则。 您可以跟踪 [WAF changelog](https://developers.cloudflare.com/waf/change-log/changelog/) 中的规则更改，并跟踪专用 [Cloudflare Zero Wire briefing](https://radar.cloudflare.com/zero-wire/php-november-2026-security-release-phpaftershell) 中的漏洞如何发展。

到目前为止，似乎没有迹象表明这些漏洞已被利用。 截至 2026 年 11 月 19 日，CISA 的 [Known Exploited Vulnerabilities catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog) 中没有列出 17 个漏洞中的任何一个来源，也没有任何来源我们审查过野外的报告开发。

## 我们对phpaftershell的了解

默认情况下，PHP 将会话数据存储在文件中。 当应用程序调用 session\_start() 时，PHP 读取会话文件并将其内容反序列化为 $\_session 数组。 当请求结束时，PHP 将更新的会话写回同一个文件。

当写入中断时触发 PHPafterShell。 然后，会话文件可以保存新会话数据的开头，然后是旧的数据。 在下一个请求中，session\_start() 反序列化这个混合的内容。 如果攻击者控制了旧数据，PHP 可能会反序列化攻击者选择的对象。

试图利用该漏洞的攻击者可能首先搜索将受控数据放在会话中的方法。 PHP 的 [advisory](https://github.com/php/php-src/security/advisories/GHSA-fm2m-fjf5-v3cp) 命名两个：

*   **会话上传进度**，一种将正在运行的文件上传到会话中的信息的 PHP 功能。 远程客户端可以使用它来塑造存储的数据。
*   **在会话中存储大型用户控制字符串的应用程序**。

根据 PHP 的说法，代码执行还需要在写入的有用点和应用程序中合适的反序列化小工具链中中断。 DepthFirst 报告说，通过在 PHP 原生类中链接第二个未公开的内存腐败错误，它在没有应用程序小工具的情况下实现了代码执行。 我们审查的消息来源没有确定第二个错误是否在 11 月 19 日的版本中得到修复。

DepthFirst 说它发现并报告了 phpaftershell。 CVE 记录将 Leo Lin 和 Asahi 归功于记者。

### 受影响的人

易受攻击的版本是 8.2.36 之前的 PHP 8.2、8.3 在 8.3.37 之前、8.4 之前的 8.4.28 之前、8.5 之前的 8.6.0 版本候选版本。 部署是否公开取决于每个漏洞的条件。

PHP 8.1 和更早的生命周期结束。 DepthFirst 表示官方的 7.4、8.0 和 8.1 报废缓解分支不受 PHPafterShell 的影响，但 PHP 表示 CVE-2026-129289 是在 PHP 5.6.0 中引入的 8.2 以上的版本也可能受到 CVE-2026-115560 的影响。

Linux 发行版通常在不更改 PHP 版本号的情况下修复反向端口。 根据您的发行版的建议检查完整的软件包版本。

## Cloudflare WAF如何保护您

PHP 运行大量的 Web，通常在团队不会直接更新的内容管理系统、插件和容器映像中。 修补每个 PHP 运行时需要时间。 Cloudflare WAF 可在您修补时减少曝光。

### phpAfterShell：每个计划的保护

我们在2026年10月21日的紧急版本中发布了原始的PHP远程代码执行规则，在PHP2Shell漏洞（CVE-2026-109618和CVE-2026-109619）之后 披露。 我们于 10 月 23 日将它们扩展到 CVE-2026-115560，并在接下来的几周内多次完善它们，部分基于参与 [PHP Capture the Flag (CTF) challenge](https://blog.cloudflare.com/php-ctf) 的安全研究人员的报告。

phpAftershell 与 PHP2Shell 共享攻击技术：攻击者在会话存储中将 PHP 数据序列化，并等待 PHP 将其反序列化。 由于这种重叠，现有规则在披露之前已经与 PHPafterShell 攻击模式的一部分相匹配。 11 月 19 日，我们更新了规则的检测逻辑以涵盖 PHPafterShell 并将 CVE-2026-126714 添加到其描述中。

### WAF看不到的东西

当恶意数据到达通过 Cloudflare 的 HTTP 请求时，WAF 可以阻止漏洞利用。 它无法阻止通往这些漏洞的每条路径，包括：

*   **反序列化步骤。** PHPafterShell 的最后一步发生在 PHP 中，当它读取损坏的会话文件时。 WAF 可以阻止植入有效负载的请求，而不是读取本身。
*   ** 来自其他来源的会话数据。** 如果应用程序将用户控制的数据从数据库、队列或上游 API 复制到会话中，则该数据可能永远不会以可识别的形式穿过 WAF。
*   **由服务器状态触发的缺陷。** CVE-2026-129496、CVE-2026-129481、CVE-2026-129474 和 CVE-2026-129182 依赖于错误日志、诊断和工作生命周期。 它们没有专用的 WAF 规则，下面的补丁和配置更改是解决它们的方法。
*   **绕过 Cloudflare 的流量。** 这包括服务和直接暴露于网络的 PHP-FPM 侦听器之间的内部流量。

### 用WAF攻击得分加深防御力

[WAF attack score](https://developers.cloudflare.com/waf/detections/attack-score/) 添加了一个机器学习层，对攻击有效载荷的每个请求进行评分。 它可在商业计划（cf.waf.score.class）上使用，并且在企业计划中具有专用的远程代码执行子分数（cf.waf.score.rce）以及总分（cf.waf.score）。

攻击分数补充了托管规则。 它不会自行识别每个序列化对象或走私的 FastCGI 记录，但一个工作的漏洞利用链通常需要不止一个请求，并且后期阶段携带有效负载 模型被训练得分：

*   ** 第二阶段有效负载。 标题、查询参数或请求主体中的字符串。
*   **webshell 流量。** 攻击者经常在最初的妥协后丢弃一个小的 PHP webshell。 将操作系统命令传递给该 WebShell 的请求对攻击分数仍然可见。

## 部署保护和补丁

您可以在 [our WAF guide](https://developers.cloudflare.com/waf/get-started/) 中找到有关如何部署托管规则和攻击分数的更多信息。 简而言之：

1.  **检查 PHPaftershell 保护是否处于活动状态。** 在免费计划中，不需要采取任何行动。 在付费计划中，请确保部署了 Cloudflare 托管规则集，并且 PHP 远程代码执行攻击 #6 规则设置为阻止。
2.  **查看新规则并将它们切换为块。** CVE-2026-129289、CVE-2026-15353 和 CVE-2026-129506 规则默认处于日志模式。 在安全事件中查看它们的匹配项，然后将它们的操作更改为阻止。
3.  **Layer [attack score](https://developers.cloudflare.com/waf/get-started/#2-create-custom-rule-based-on-waf-attack-score).** 创建一个自定义规则，以低远程代码执行分数阻止或挑战请求，例如 cf.waf.score.rce le 20 on Enterprise plans 或 cf.waf.score.class eq "attack" on 商业计划。
4.  **升级 PHP.** 移动到 8.2.36、8.3.37、8.4.28、8.5.13 或 8.6.0。 重建容器映像并重新启动 PHP-FPM 主站或 Apache，以便每个工作人员加载新的二进制文件，然后验证服务 Web 请求的版本。 升级后，检查是否没有 php.ini、fpm 池或虚拟主机设置 session.upload\_progress.enabled=1，因为显式设置会覆盖新的默认值。
5.  **如果您无法立即升级，请应用临时缓解措施。** 设置 session.upload\_progress.enabled=0 并限制您存储在会话中的不可信数据。 关闭 FastCGI 连接重用。 在 PHP 8.5 上，设置 fatal\_error\_backtraces=0。 修复产生 PHP 启动警告或将 PHP 错误发送到 syslog 而不是文件的配置错误。 让 PHP-FPM 侦听器远离不受信任的网络。 这些步骤减少了暴露； 他们没有修复缺陷。

有关提示，您可以让 AI 代理清点您的 PHP 部署并检查每一项与所有七个关键 CVE 的关系，请参阅 [phpAfterShell page on Cloudflare Zero Wire](https://radar.cloudflare.com/zero-wire/php-november-2026-security-release-phpaftershell)。

## 立即更新每个 PHP 运行时间

phpAftershell 将 PHP 默认会话处理程序中的中断文件写入到执行代码的路径中，它与其他六个关键缺陷到达相同的版本。 随着技术细节的公开，我们预计漏洞利用尝试将随之而来。 Cloudflare WAF 为每个客户（包括免费计划）阻止了已知的 PHPafterShell 攻击模式，付费计划对 PHP-FPM 和 SOAP 缺陷有新的规则。 修复仍然是升级 PHP 并重新启动使用它的服务。

[通过运送更多 CSS](https://github.blog/engineering/architecture-optimization/improving-site-performance-by-shipping-more-css/ "github.blog") — GitHub 详细说明了如何从 `github․com` 中清除 `styled-components` 和 'css-in-js' 以支持 CSS 模块，从而提高了站点性能。 结果？ 运输 _more_ css，但 GitHub 报告的服务器端渲染页面的时间减少了 55%。

乔什·布莱克和玛丽·卢卡 (GitHub)

💡 [CSS Modules](https://github.com/css-modules/css-modules) 不是浏览器功能或标准，而是 [widely supported](https://github.com/css-modules/css-modules/blob/master/docs/get-started.md) Bundler 约定，其中 `.module.css` 文件中的类被重写为唯一名称，每个文件的范围样式，没有运行时成本。

马特凯恩

[Anthropic 如何使 Claude 的网络应用程序更快](https://claude.dev/blog/how-we-made-claude-ai-faster/ "Claude.dev") — 关于最近一次冲刺（克劳德做了大部分工作）如何将 Claude 的时间缩短到 75% 的故事 3.1s 到 0.55s，从跟踪布局偏移太小到 CLS 到标记，到 `:root:has()` 选择器，每次 DOM 更改花费 24 毫秒，以及由 Chrome 在错误高度预渲染页面造成的跳跃。

🔎 [网络最能容忍的功能](https://www.bocoup.com/blog/the-webs-most-tolerated-feature "www.bocoup.com") — Mike 谈到了 `zoom` 属性 — 曾经是非标准的 IE 专用功能，此后，它已经进行了 25 年的旅程 现代标准和[part of Interop 2025](https://wpt.fyi/results/css/css-viewport?label=master&label=stable&aligned&view=interop&q=label%3Ainterop-2025-webcompat)。 这篇文章讲述了这段旅程，强调了它现在如何为我们提供独特的布局能力。

迈克·彭尼西

[WASM 3.0 完成](https://webassembly.org/news/2025-09-17-wasm-3.0/ "webassembly.org") — WebAssembly 3.0 标准现在是“实时”的（并且已经与大多数浏览器一起提供）。 这个值得注意的版本引入了各种可以改进 JS 互操作性的功能，包括 64 位地址空间、垃圾收集、异常处理、类型化引用等。

[Chrome DevTools (MCP) for Your AI Agent](https://developer.chrome.com/blog/chrome-devtools-mcp "Developer.Chrome.com") — Google 的 Chrome 团队发布了新的模型上下文协议 (MCP) 服务器的公开预览，用于将 Chrome 的 DevTools 的功能引入 AI 编码 代理。 这意味着像 Claude Code、Gemini Code 或 Codex 这样的工具可以直接使用 Chrome 调试网页，并受益于 DevTools 的性能洞察。

Bynens & Hablich (Chrome 开发者)

[WorkOS Connect 解决了 MCP 中 API 密钥造成的集成痛苦](https://workos.com/blog/why-oauth-is-the-right-fit-for-the-mcp-registry?utm_source=cpff&utm_medium=newsletter&utm_campaign=q32025 "workos.com") — MCP 工具需要安全的委派访问。 用 OAuth 2.1 替换破坏用户流程和缺少范围的 API 密钥。

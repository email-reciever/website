[2025 年 11 月 18 日的 Cloudflare 中断](https://blog.cloudflare.com/18-november-2025-outage/ "blog.cloudflare.com") — 昨天，我相信你们中的许多人都知道，Cloudflare 的网络看到了一个显着的 [hours-long failure](https://www.cloudflarestatus.com/incidents/8gmgl950y3h7)，导致了广泛的错误和访问问题。 这是一个详细的验尸，解释了发生的事情——指出数据库权限更改为罪魁祸首。 这次中断仅突出了 Cloudflare 以及 AWS 如何作为现代 Web 整体基础设施的关键部分。

马修·普林斯

☁️更多关于Cloudflare中断的信息

在停机时间后，Hugo Landau 提出了 [why one might consider Cloudflare "_harmful_"](https://www.devever.net/~hl/cloudflare) 的理由，并指出这种对他们服务的依赖如何“__ 对 Web_ 的状态构成危险”。

Rik Huijzer 还撰写了一篇关于停电和 [risks of a single point of failure](https://huijzer.xyz/posts/123/do-not-put-your-site-behind-cloudflare-if-you-dont) 的快速帖子。

Kanakana 的看法略有不同，认为提供的功能（DDoS 保护、Bot 阻塞等）的必要性是这样一个集中的服务。

[![](https://res.cloudinary.com/cpress/image/upload/c_limit,w_480,h_480,q_auto/copm/aa10e657.png)](https://workos.com/blog/introducing-workos-api-keys?utm_source=cpff&utm_medium=newsletter&utm_campaign=q42025)

[Drop-in API Key Management for SaaS Apps](https://workos.com/blog/introducing-workos-api-keys?utm_source=cpff&utm_medium=newsletter&utm_campaign=q42025 "workos.com") — WorkOS API 密钥允许开发人员添加带有插入式小部件的安全密钥管理，用于创建、旋转和撤销密钥。 密钥与 WorkOS 组织和角色相关联，通过 API 或 SDK 提供范围权限和直接验证。

*   🧱 CSS 工作组已[同意使用 `display: grid-lanes`](https://github.com/w3c/csswg-drafts/issues/12022#issuecomment-3525043825) 用于砌体开关语法。

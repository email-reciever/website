设计系统在一致性上蓬勃发展，那么随机性在哪里适合呢？ 通过有机排版、弹跳字母和张开的卡片的有趣演示，Brecht De Ruyte 展示了新的 CSS `random()` 函数如何在没有 JavaScript 库或预处理器循环的情况下为 Web 带来一些不完美，从而产生数百行静态行 CSS。

在设计中，我们喜欢花几个小时沉迷于一致性、网格和对齐方式。 但是当我听说本机 **css `random()` 功能** 登陆 Safari 并在 Chrome 156 中推出时，我开始想：**随机**在网络上实际上有意义吗？ 这是我们在设计系统中想要的东西吗？ 为了找出答案，我做了我一直怀疑的事情：我构建了一堆有趣的 Codepen 演示，探索有机排版、弹跳字母、张开的卡片和朋克粉丝杂志。

作为一个喜欢构建设计系统和修补 CSS 架构的人，我日常工作的很大一部分围绕着控制展开。 我们设置了间距比例，锁定排版，设置颜色标记，并确保所有内容都在网格上对齐。 **一致性** 通常是我们作为设计工程师的基础，也是创建设计系统时的自豪技能徽章。 如果一张卡片在刷新时突然向左跳 20 像素，那就不是创造性的表达； 这是一个项目经理会记录的错误。

因此，当我第一次听说CSS值和单位级别5规范中的本机`random()`函数在Safari中发布，并且目前正在Chrome 156中推出（也有来自Firefox上的Mozilla的正信号），我的第一个反应是： 酷！_

我的第二个反应是：_等等……我实际上会在哪里使用它而不弄得一团糟？ 我如何说服设计师 Random 可能是设计系统的好主意？_

因为老实说：当我们在过去十年中试图让网络更可预测时，为什么我们会想要在样式表中随机性？ 即使在使用 Flexbox 或流体排版时，我们仍在尝试使事物尽可能对齐和统一。

事物的魅力不是 100% 直的
-----------------------------------------

如果您离开浏览器一秒钟并查看您周围的物理事物，那么没有什么是真正的统一的。

以旧的凸版印刷：墨水略微渗入纸纹中，有些字母有微小的倾斜，基线并不总是那么直。 或者想想一堆拍到的宝丽来照片放在咖啡桌上； 这些照片并不完美，可能也不是直截了当。 或者夜晚在街上闪烁的灯光怎么样？ 一点点模拟混乱是让事情感觉**活着**、**有机**和**人类**的原因。

在网络上，我们非常擅长像素完美，有时我们的界面最终会感觉有点无菌。 我们现在更加注意到这一点，由无导向的法学硕士快速创建的设计； 我们通常会得到与 10 年前相同的设计。 一切都对齐，对齐，整齐。 它有效，但坦率地说，它确实有点无聊。

css `random()` 函数的工作原理
-----------------------------------

`random()` 功能在 [CSS Values and Units Module Level 5](https://drafts.csswg.org/css-values-5/#random) 中指定。 它在您的 CSS 中生成一个伪随机值，而无需 JavaScript 或构建时 Sass 循环。

正式规范如下所示：

随机(<random-key>?, <min>, <max>, <step>? )

在实践中，在当前的浏览器实现中，您可以只编写逗号分隔的参数：

/* -3deg 和 3deg 之间的随机角度 */
旋转：随机（-3deg，3deg）；
    
/* 20px 和 80px 之间的随机宽度，步长为 10px */
内联大小：随机（20 像素，80 像素，10 像素）；
    
/* 随机动画持续时间 */
动画持续时间：随机（1.5s、3s、0.2s）；
    

### 匹配单位

对于大多数人来说，这不会令人震惊，但我想我至少应该提到**你的最小和最大范围必须共享完全相同的单位类型**。

CSS 解析器需要知道它正在处理的是哪个维度。 您可以使用长度、角度、时间、百分比或普通的无单位数字：

/* 好：两个都是角度 */
旋转：随机（-4deg，4deg）；
    
/* 好：两者都是无单位数字 */
不透明度：随机（0.3、1）；
    
/* 不！ 你不能混合单位 */
内联大小：随机（2rem，100px）； /* 无效 */
    

如果您需要组合单位，则必须在参数中触及 `calc()`，以便每一方正确解决。

### 步进和四舍五入

可选的第三个参数是步长。 如果您不添加它，浏览器将从连续范围中选择。 但是如果你提供一个步骤，它会将随机值四舍五入以离散增量：

/* 仅产生 0px、15px、30px、45px 或 60px */
顶部：随机（0 像素，60 像素，15 像素）；
    

这在您希望事物跳跃一点的情况下会有所帮助，但您仍然希望它们降落在您预定义的网格上。

### 缓存键：保持同步

通常，每次在属性上计算 `random()` 时，它都会创建一个独立的随机值。 但是可能有一个示例，您可以创建一个随机设置 `inline-size` 和 `block-size` 的框，但同时您需要它们匹配，以便元素保持完美的正方形。

这是**缓存密钥**的来源：

.card-thumbnail {
/* 两个属性共享键 --square-size */
inline-size: random(--square-size element-scoped, 60px, 120px);
block-size: random(--square-size element-scoped, 60px, 120px);
}
    

在最新的规范中，像 `--square-size` 这样的裸虚线标识在文档中的每个元素中全局共享其种子（这将使所有卡片都相同）。 为了在单个元素上保持宽度和高度链接，同时为每张卡片提供自己独立的尺寸，该规范需要将其与 `element-scoped` 关键字（例如 `--square-size element-scoped`）配对。

为了在行动中看到这一点，我创建了一个小例子。 在顶行中，图块具有未缓存的尺寸，这会将每个图块扭曲成一个不可预测的、不匹配的矩形。 在最后一行，`inline-size` 和 `block-size` 都共享 `--square-size`，保证每个瓷砖保持原始 1:1 的平方。 刷新 CodePen 几次，注意底部的卡片保持相同的随机性：

请参阅 [@utilitybend](https://codepen.io/utilitybend) 的笔 \[未缓存与缓存随机() \[分叉\]\](https://codepen.io/editor/smashingmag/pen/01a15e91-4bac-765e-b04e-a53636759163)。

请参阅 [@utilitybend](https://codepen.io/utilitybend) 的笔 [未缓存与缓存随机() \[分叉\]](https://codepen.io/editor/smashingmag/pen/01a15e91-4bac-765e-b04e-a53636759163)。

/* 未缓存：宽度和高度独立解析，创建随机矩形 */
.tile-未缓存 {
内联大小：随机（4.2rem，8.5rem）；
块大小：随机（4.2rem，8.5rem）；
旋转：随机（-3.5 度，3.5 度）；
}
    
/* 缓存：共享密钥保证干净的 1:1 平方 */
.平铺缓存 {
内联大小：random(--square-size element-scoped, 4.2rem, 8.5rem);
block-size: random(--square-size element-scoped, 4.2rem, 8.5rem);
旋转：随机（--倾斜元素范围，-3.5 度，3.5 度）；
}
    

浏览器支持和逐步增强
-----------------------------------------

你今天在哪里可以测试这个？

*   **WebKit / Safari**：Safari 是第一个获得陆地支持的人。
*   **Chrome / Edge**：现在使用**Chrome 156**发货和推出。
*   **firefox**：标准轨道上的积极信号，所以希望不会落后太远。

因为我们仍处于推出阶段，因此您需要将实验包装在 `@supports` 中：

/* 所有浏览器的基线 */
.徽章{
旋转：0度；
}
    
/* 增强了使用 random() 的浏览器 */
@supports（旋转：random（-2deg，2deg））{
.徽章{
旋转：随机（-2.5 度，2.5 度）；
}
}
    

### 未来 `random-item` 功能

规范中还有另一个函数，称为 `random-item()`。 `random()` 处理数值范围，`random-item()` 允许您从预定义的标记或关键字列表中选择：

/* 从您的调色板中挑选一种随机颜色 */
背景颜色：随机项目（--seed，oklch（75% 0.18 150），俄克拉荷马（65% 0.22 350），俄克拉荷马（85% 0.16 85））；
    

这对于从一组设计令牌中进行随机化是很方便的。 这一款目前没有任何浏览器支持，但它肯定是值得期待的。

现在是实际部分。

当我开始使用该功能时，我还在使用动画进行一些排版技巧。 这就是我的第一个想法：排版！ _如果我们只是在一个词上加一点不完美怎么办？_

想想复古书籍封面。 这些字母不会因迈尔斯而错位，但它们有小缺陷。

请参阅 [@utilitybend](https://codepen.io/utilitybend) 的笔 \[不完美随机() \[分叉\]\](https://codepen.io/editor/smashingmag/pen/01a15e92-157f-708d-a704-fa067114aaca)。

显示：内联块；
    
/* 微小的倾斜 */

我还添加了一点悬停效果。 当你阅读时，这个词感觉很有趣。 但是当你悬停在它上面的那一刻，每个角色都会弹回。

### 请不要破坏屏幕阅读器

一个快速的**可访问性警告**在这里：如果您将一个单词分成单独的 `<span>` 元素，以便您可以设置每个字母的样式，屏幕阅读器通常会将其读为单独的字符：“I - M - P - E - R - F - E - C - T - I - O - N”，或暂停 每一项之间都很尴尬。 这是一个糟糕的用户体验。

始终隐藏辅助技术的视觉跨度并提供完整的单词：

    <h1 class="word" aria-label="Imperfection">
      <span class="word-inner" aria-hidden="true">
<span class="char">我</span>
<span class="char">m</span>
<span class="char">P</span>
<span class="char">e</span>
<span class="char">R</span>
<span class="char">F</span>
<span class="char">e</span>
<span class="char">C</span>
<span class="char">T</span>
<span class="char">我</span>
<span class="char">O</span>
<span class="char">N</span>
      </span>
    </h1>
    

屏幕阅读器用户获得干净的文本，有视力的用户获得有趣的视觉怪癖。

演示 2：动画字母：纯程序反弹
-------------------------------------------------

一旦我把那些字母放在那儿，我无法抗拒：_如果我们给它动画怎么办？

我开始修补一个弹跳关键帧。 我只是在闲逛，但最终的结果给了我一点微笑。 如果您以完全相同的时间为每个字母设置动画，您将获得我们以前见过的干净的正弦波。 但如果每个字母都有自己的跳跃高度、自己的持续时间和自己的着陆壁球，突然间，这个词看起来就像一群小角色在蹦床上跳来跳去。

请参阅 [@utilitybend](https://codepen.io/utilitybend) 中使用 CSS random() \[forked\]\](https://codepen.io/editor/smashingmag/pen/01a15e92-c117-729f-9844-ddf19fc1fc96) 的笔 \[弹力不完美]。

请参阅 [@utilitybend](https://codepen.io/utilitybend) 中的笔 [带有 CSS random() \[forked\]]](https://codepen.io/editor/smashingmag/pen/01a15e92-c117-729f-9844-ddf19fc1fc96) 的弹力缺陷。

以下是跳出参数的连接方式：

@Layer演示{
.char {
显示：内联块；
变换原点：中心底部；
    
/* 程序反弹变量 */
-- 跳转：随机（元素范围，-35px，-55px，2px）；
--tilt：随机（元素范围，-8 度，8 度，0.5 度）；
--dur：随机（元素范围，1s，1.2s，0.1s）；
--delay：随机（元素范围，-3s，0s，0.1s）；
--rebound-squash：随机（元素范围，1.08、1.18、0.02）；
    
动画：字母反弹 var(--dur) 线性 var(--delay) 无限；
}
    
@keyframes 字母跳动 {
/* 顶点 */
0% {
翻译：0 var(--jump);
旋转：var(--tilt);
规模：1 1；
动画定时函数：cubic-bezier(0.65, 0.05, 0.85, 0.35);
}
    
/*着陆*/
44% {
翻译：0 0；
旋转：calc(var(--tilt) * 0.2);
规模：0.96 1.05；
动画定时功能：缓解；
}
    
/* 壁球 */
52% {
翻译：0 0；
旋转：0度；
比例：var(--rebound-squash) calc(2 - var(--rebound-squash));
动画定时函数：cubic-bezier(0.2, 0.8, 0.2, 1);
}
    
/* 备份 */
62% {
翻译：0 calc(var(--jump) * 0.2);
旋转：calc(var(--tilt) * -0.4);
规模：0.98 1.03；
动画定时函数：cubic-bezier(0.15, 0.85, 0.35, 1);
}
    
100% {
翻译：0 var(--jump);
旋转：var(--tilt);
规模：1 1；
}
}
}
    

注意负面动画延迟 (`--delay: random(-3s, 0s)`)。

如果您设置了正延迟，则字母在页面加载时处于冻结状态，等待其计时器在跳跃之前到期。 通过使用负延迟，浏览器假装动画已经运行了几秒钟。 页面加载的那一刻，每个字母都以自己的节奏弹跳。

我们已经建立了卡片。 很多卡片。 这么多卡片……投资组合网格、博客摘要、功能列表。 大多数时候，他们坐在三四个整齐、无聊的柱子里。

对于仪表板，这正是您想要的。 但是，如果您正在建立生活方式组合、儿童网站或度假照片集，我们可以变得更加有趣。 在下面的例子中，我就是这样做的：

演示 5：随机速度
------------------------

如果您曾经看过野兽派或高端时尚网站，您可能会在向下滚动页面时看到水平选框文本在屏幕上漂移。

通常，您会看到开发人员创建类 `.drift-slow`、`.drift-fast`、`.drift-reverse` 或使用大量 JavaScript 滚动侦听器来计算转换。

用 `random()` 和一点点数学，我们只需几行即可获得程序漂移速度：

请参阅 [@utilitybend](https://codepen.io/utilitybend) 的笔 \[random() 速度滚动动画 \[forked\]\](https://codepen.io/editor/smashingmag/pen/01a15e95-4cbe-77bd-9128-685d2c75cc56)。

请参阅 [@utilitybend](https://codepen.io/utilitybend) 的笔 [random() 速度滚动动画 \[forked\]](https://codepen.io/editor/smashingmag/pen/01a15e95-4cbe-77bd-9128-685d2c75cc56)。

这是CSS：

@Layer演示{
.drift-line {
空白：诺拉普；
    
/* 使用数学奇偶校验行之间的交替方向 */
--方向：calc(pow(-1, sibling-index()));
    
/* 速度距离 */
-- 旅行：随机（15%，44%）；
    
/* 绑定到页面滚动 */
动画：构造滑行线性两个；
动画时间轴：滚动（root）；
动画范围：条目 0% 覆盖 100%；
}

从{

}
{
翻译：calc(var(--direction) * var(--travel)) 0;
}
}
}
    

`calc(pow(-1, sibling-index()))` 给我们交替的方向（`1`、`-1`、`1`、`-1`），`random(15%, 44%)` 决定每行行进的速度。 当您滚动时，每条排版线都会以自己的节奏移动。

随机性在哪里有意义（以及哪里没有）
-----------------------------------------------

既然我们已经玩了 Wild Side，让我们谈谈这在我们日常工作中的实际位置。

### 好的用例

*   **装饰 UI** 的微妙微缺点**：倾斜宝丽来、粘滞便笺上的轻微角度或印刷英雄标题。
*   **Desynchronizing 环境循环**：状态信标、柔和的浮动徽章或完美一致看起来机器人的背景粒子网格。
*   **生成背景**：星场、五彩纸屑庆祝活动、浮动散景圆或纹理纹理。
*   **编辑艺术方向**：杂志传播、活动传单、野兽派布局和俏皮的登陆页面。
*   **在数学之上分层**：使用 `sibling-index()` 用于结构网格并为人类温暖添加小的随机偏移。

### 你应该在哪里避免它

*   **核心布局和网格**：不要随机化列的排水沟、表单域宽度或容器填充。 人们需要可预测的布局几何体来导航。
*   **body copy**：不要触摸长格式段落上的字体大小、行高或字母间距。 阅读疲劳是真实的。
*   **互动目标**：不要在悬停和焦点上重置它们的小按钮或链接倾斜或移动。 如果用户必须追逐移动或弯曲的按钮，则表明您失败了。

但是！ 我很高兴在这里被证明是错误的。 我鼓励你挑战现状并尝试这一点。

### 永远尊重`prefers-reduced-motion`

无论何时使用动画，您都必须尊重用户对缩小运动的偏好：

@media（首选-reduced-motion：reduce）{
.char {
动画：无；
旋转：0度；
翻译：0 0；
}
}
    

如果有人更喜欢缩小运动，那么将角度展平也可能是个好主意，而不仅仅是动画。 我可以想象，很多随机角度也会在滚动时让人心烦意乱。 设计应该很有趣，但绝不以可访问性为代价。

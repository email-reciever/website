“您需要一个库”和“浏览器执行此操作”之间的差距不断关闭。 一个实用指南，用于审核您的依赖关系并找到 Web 平台现在可以为您处理的内容。

我们中的大多数人一次安装依赖项，再也不会再看。 它完成了它的工作，测试通过了，我们继续前进。 但是 Web 平台也在不断移动，现在您 `package.json` 中的大量库现在已内置到浏览器中。

在一个典型的中型 JavaScript 应用程序中，您通常可以在 60KB 到 90KB（最小化和压缩）之间找到该平台现在可以自行处理的依赖关系。 日期和数字格式、HTTP 请求、模式、工具提示、深度克隆、分组数组：这些都是几年前真正的差距。 其中很多不再是差距。

这些库的原因不是懒惰。 大多数团队没有重新审核他们对基线节奏的依赖，或者根本不知道这些天浏览器的发货速度有多快。 您检查 `npm audit` 的安全性，但是 _this library 是否仍在执行浏览器无法执行的操作？_ 是一个很少被问到的问题。 所以图书馆留下来。

在本文中，我们将一起运行该审计。 我们不会一一处理依赖项，而是将集群工作，因为胜利往往是分组进行的。 我们将进行捆绑数学，构建一个您可以重复使用的小决策框架，并对平台仍然不足的情况保持诚实。 到最后，您将拥有一个可重复的过程，您可以自己运行 `package.json`。

“基线”的实际含义
------------------------------

在我们开始删除东西之前，让我们快速回顾一下什么是基线。 如果您已经熟悉，请随时跳过本节。

Baseline 是 [WebDX Community Group](https://github.com/web-platform-dx/web-features) 中的一个项目，简单地告诉您，Web 功能在主要浏览器（Chrome、Edge、Firefox 和 Safari）中使用的安全性有多大。 一个功能可以处于以下三种状态之一：

*   **有限的可用性**
该功能尚未在所有主要发动机中发货。 没有后备就不安全地依赖。
*   **新推出的基线**
该功能刚刚登陆所有主要发动机。 它适用于最新浏览器上的用户，但野外的旧设备可能还没有。
*   **基线广泛可用**
该功能已在所有主要发动机中运行了 30 个月。 在这一点上，你可以毫不费力地伸手去拿它。

“新”和“广泛”之间的 30 个月差距对这次审计来说非常重要。 一个广泛可用的功能是您今天通常可以删除库的功能。 一个仅新推出的功能是您可以为_IF_首先检查您的受众，或者您是否对小型功能检查感到满意。 我们将在整个过程中以不同的方式处理这两个案例。

您可以在 [webstatus.dev](https://webstatus.dev/)、[MDN](https://developer.mozilla.org/)（每个参考页面显示顶部附近的基线徽章）上查找任何功能，或者使用 `web-features` npm 包以编程方式查找任何功能。 稍后我们将在对真实项目进行审计时使用所有三个。

删除任何内容之前的决策框架
--------------------------------------------

阅读_“浏览器现在这样做”_并开始撕掉库是很诱人的。 让我们不要那样做。 在纸上看起来免费的交换可以悄悄地为您的大部分用户破坏事情，或者让您在没有意识到的情况下花费您所依赖的功能。

所以在丢弃任何图书馆之前，问三个问题。 我们将在下面的每个集群中重复使用这些。

**1\。 替换基线安全****_my_** **受众？**

不是_“它是基线”_，而是_“对于实际使用我的应用程序的人来说是否安全。”_如果本机功能广泛可用，这通常是肯定的。 如果它只是新可用的，请检查您的分析或您的 `browserslist` 配置，看看您的用户中有多少份额会错过。 一个 B2B 仪表板，每个人都在最新的浏览器上，与一个面向公众的老安卓设备的面向公众的网站截然不同。

**2\。 交换实际上的成本是多少？**

删除库并不总是免费的。 有时，本机功能还不够广泛，因此您可以使用 polyfill。 如果该polyfill比您要删除的库重，则您已将捆绑包设置为_bigger_，除非您有条件地加载它。 稍后我们将在时间上看到这一点。

**3\。 平台功能是否涵盖了我的真实用例？**

库通常比它们相似的平台功能做的更多。 `axios` 不仅仅是 `fetch` 与自动 JSON 解析； 它具有拦截器、请求取消和重试。 如果您使用这些，直接交换 `fetch` 将使您重新实现它们。 在假设它是替代品之前检查您实际使用的内容。

把这三个牢记在心。 下面的每个集群实际上都只是将这些问题应用于您依赖的不同角落。

集群1：国际化（今日最大跌幅）
--------------------------------------------------------

这是您通常会在已经广泛可用的功能之上找到最多 KB 的集群。 浏览器在 `Intl` 命名空间下提供了一系列格式化工具，许多小型流行的库变得不必要了。

以下是通常的嫌疑人以及替代它们的原因：

*   `timeago.js` (1 kB GZ) → `Intl.RelativeTimeFormat`
*   `pluralize` (2.3 kB GZ) → `Intl.PluralRules`
*   `numeral` (3.9 kB GZ) → `Intl.NumberFormat`
*   `humanize-duration` (6.6 kb Gz) → `Intl.DurationFormat`
*   列表加入助手→ `Intl.ListFormat`

让我们来看看其中的一些。

### 相对时间

`timeago.js` 存在将时间戳转换为 _“3 小时前”_。 `Intl.RelativeTimeFormat` 做同样的事情，它的基线广泛可用。

const rtf = new intl.RelativeTimeFormat("en", { numeric: "auto" });
    
rtf.format(-1, "day"); //“昨天”
rtf.format(3，“小时”); // “3小时内”
rtf.format(-2，“周”）； //“两周前”
    

`numeric: "auto"` 选项在这里是很好的触感：它为您提供“昨天”而不是“1 天前”，其中语言有一个词。 你传递一个数字和一个单位，你会得到一个本地化的字符串。

您可能想知道 `timeago.js` 是否有此代码段没有的一件事：它为您挑选单位。 给定日期，`timeago.js` 决定是说“秒”还是“天”。 `Intl.RelativeTimeFormat` 希望你做那部分。 这是几行算术（找出差异，找到适合的最大单位），一旦你写完了那个帮助，你就不再需要库了。

### 数字、货币和列表

`Intl.NumberFormat` 涵盖了大多数数字格式库的作用：数千个分隔符、货币、百分比和紧凑符号。

新 intl.numberFormat("zh-us").format(1234567.89);
//“1,234,567.89”
    
new intl.numberFormat("en-us", { 样式: "currency", 货币: "usd" }).format(
1234.5，
);
// "$1,234.50"
    
新 intl.numberFormat("en", { 符号："compact" }).format(1200000);
//“1.2m”
    

`Intl.ListFormat`，广泛可用，处理“将数组加入一个句子”的问题，包括牛津逗号，这是人们为以下内容编写的那种东西：

const lf = new intl.ListFormat("en", { 样式："long", type: "conjunction" });
    
lf.format(["Alice", "Bob", "Carol"]);
// “爱丽丝、鲍勃和卡罗尔”
    

### 一注意：持续时间

`humanize-duration` 将一个毫秒数变成_“1 小时，30 分钟”_。 平台等价为`Intl.DurationFormat`：

const df = new intl.durationFormat("en", { 样式："long" });
    
df.format({ 小时: 1, 分钟: 30 });
//“1小时30分钟”
    

要记住的一件事是，`Intl.DurationFormat` 在撰写本文时是基线 _newly_ 可用，不广泛可用。 它于 2025 年 3 月登陆所有主要引擎，并且有望在 2027 年广泛使用。因此，除非您先检查流量或添加回退，否则这个问题 1 会失败广泛受众应用程序的问题 1。 对于现代浏览器上的内部工具，今天很好。 对于带有旧设备的公共站点，请再给它一年或使用功能检查来保护它。

### 这个集群上的数学

如果您的应用程序使用全集（`humanize-duration`、`timeago.js`、`pluralize`、`numeral`），这大约是 14 KB 的依赖关系，现在大部分都可以用广泛可用的 API 替换。 国际化集群通常是整个审计中最容易的胜利。

集群 2：HTTP 客户端
------------------------

这个集群更细微，所以它是一个很好的放慢速度的集群。

人们使用的浏览器 HTTP 库是 `axios` (17 KB GZ) 和 `superagent` (19 KB GZ)。 对于大多数请求，`fetch` 加 `AbortController` 涵盖了您需要的内容，并且两者都广泛可用。

一个基本的get看起来像这样：

// axios
const { data } = await axios.get("/api/users");
    
// 获取
const res = await fetch("/api/users");
常量数据 = 等待 res.json();
    

一行 (`res.json()`) 是 `fetch` 明确的，其中 `axios` 是隐式的。 这就是整个集群的模式：`fetch` 默认情况下对您的作用较少，您可以决定是否想要它遗漏的东西。

### 超时

`axios` 有 `timeout` 选项。 `fetch` 有 `AbortSignal.timeout()`：

const res = await fetch("/api/users", {
信号：abortSignal.timeout(5000), // 5 秒后中止
});
    

### `fetch` 不替换 `axios`

这就是问题 3 完成大部分工作的地方，所以让我们具体说明这些差距：

*   **`fetch` 不拒绝 HTTP 错误。**
`404` 或 `500` 是已解决的承诺，而不是拒绝。 您必须自己检查 `res.ok`。 `axios` 拒绝任何非 2xx 状态。
*   **没有拦截器。**
如果您依靠 `axios` 拦截器将 AUTH 令牌或在一处处理 401s ，`fetch` 没有等价物。 你会在你自己的函数或类中包装 `fetch` 以获得相同的行为。
*   **没有自动重试。**
`axios`（带插件）可以重试失败的请求。 使用 `fetch`，这是您要编写的代码。
*   **没有上传进度。**
`fetch` 仍然无法以一流的方式报告上传进度。 如果您有一个带有进度条的文件上传器，这是保留库的真正原因。

我个人在我的交互式在线课程中严重依赖_interceptors_，例如[Learn JavaScript](https://learnjavascript.online/)，多年来我一直使用`fetch`上的自定义`class`解决了这个问题。 我已经将它运送给数百万用户，并看到它取得了很大的成功。

这些都不是很难重建的，大多数应用程序只使用其中的一两个。 但这正是您不应该进行盲目查找和替换的那种集群。 先看看你如何实际使用你的 HTTP 客户端。 如果它很简单，则删除 `axios` 以获得薄 `fetch` 包装可以为您节省大约 **17 kb gzipped**。

集群 3：UI 原语
-------------------------

这个集群有一些最令人满意的交换，因为平台功能不仅与库匹配，而且通常比团队手工提供的更容易访问。

这里的库是模态对话框（类似于 `a11y-dialog`、1.8 kb gz）、工具提示和弹出式库（`tippy.js`、14 kb gz，将波普尔用于定位）、`focus-trap` (6.6 kb gz) 和 `body-scroll-lock` （1.3 kb gz）。 它们被三个平台功能所取代：`<dialog>` 元素、Popover API 和 CSS 锚定定位。

###  `<dialog>` 元素

存在大量与模态相关的代码来解决可访问性问题：将焦点捕获在模态内，关闭 `Escape`，将焦点恢复到关闭对话框的前一个元素，以及渲染高于其他所有内容。 `<dialog>` 元素，广泛可用，为您完成所有这些。

    <dialog id="confirm">
      <form method="dialog">
<p>删除此文件？</p>
<button value="cancel">取消</button>
<button value="delete">删除</button>
      </form>
    </dialog>
    
常量对话框 = document.QuerySelector("#confirm");
    
对话框.showmodal(); // 焦点移动，背景变为惰性，逃逸关闭它
    
dialog.AddEventListener("关闭", () => {
console.log(dialog.returnValue); // “取消”或“删除”
});
    

调用 `showModal()` 执行 `focus-trap` 安装的工作：焦点移动到对话框中，页面的其余部分变得惰性，因此您无法将其退出，`Escape` 关闭它，焦点返回到打开它的元素。 对话框呈现在浏览器的 _top layer_ 中，因此您不会打架 `z-index`。 您还可以获得 `::backdrop` 伪元素来样式叠加。

该单个元素可以替换您的模态库 _and_ `focus-trap`。 它自己不处理的一件是将背景锁定在滚动中，这就是 `body-scroll-lock` 的用途。 现在是CSS的一行：

body:has(dialog:modal) {
溢出：隐藏；
}
    

如果您想知道为什么我们使用 `dialog:modal` 而不是 `dialog[open]`，那是因为 `open` 属性在您调用 `show()` 后立即设置，但对话框实际上不是 _modal_，因此您不想锁定滚动。 `:modal` 伪类仅在对话框实际上是 _modal_ 时才为 true，当您调用 `showModal()` 时就是这种情况。

所以三个库折叠成一个元素和一个 CSS 规则。

### Popover API和锚定位

对于不是全模态的东西（下拉菜单、工具提示、`tippy.js` 处理的小浮动面板），[Popover API](https://www.smashingmagazine.com/2026/03/getting-started-popover-api/) 为您提供光线解除行为、顶层渲染和 `Escape`\-to-close ，完全没有 JavaScript：

<button popovertarget="menu" id="options">选项</button>
    
    <div id="menu" popover>
<!-- 菜单内容 -->
    </div>
    

单击按钮可切换弹出窗口。 单击外部将关闭它。 它是新上市的基线（自 2025 年 1 月起）。

工具提示库的另一半是 _positioning_：将浮动元素固定在其触发器上，并在溢出视口时翻转它。 这就是 Popper（捆绑在 `tippy.js`）中的处理方式，现在它是一个称为锚定定位的 CSS 功能。 在这里，它直接在其触发按钮下固定相同的 `#menu` popover：

#选项 {
锚名称：--触发器；
}
    
.工具提示 {
位置锚：--触发器；
位置区域：顶部；
边距：0；
}
    

锚定位是本文中的最新功能。 它在 2026 年 1 月成为新上市的基线，当时 Firefox 147 发货（Chrome 自 125 版开始使用，Safari 自 26 版开始使用）。 因为它很新鲜，所以它完全是一个问题 1 功能：非常适合现代观众，但要检查您的流量，并注意一些更高级的部分（如位置尝试后备）在版本中的支持不均匀。 为旧版浏览器保留一个合理的回退功能。

在 `<dialog>`、Popover API 和锚定定位之间，UI 原语集群（工具提示库、模式库、`focus-trap`、`body-scroll-lock`）加起来大约为 **24 KB gzipped**，而您会从另一面获得更好的可访问性默认值 比大多数手动滚动解决方案。

集群 4：Lodash 实用程序
----------------------------

LODASH 很少再被整体导入，但它的各个功能随处可见，无论是完整的 `lodash` 包 (25 KB Gz) 还是作为 `lodash.clonedeep` 和 `lodash.groupby` 的独立安装。 一些最常见的现在具有直接的平台等价物。

### 分组

`lodash.groupby` 将数组重新组织为由某个属性键入的对象。 `Object.groupBy` 正是这样做的：

常数产品 = [
{名称：“苹果”，类别：“水果”}，
{名称：“胡萝卜”，类别：“蔬菜”}，
{名称：“香蕉”，类别：“水果”}，
];
    
const 分组 = object.groupby(products, (product) => product.category);
// {
// fruit: [{ name: "apple", ... }, { name: "banana", ... }],
// 蔬菜: [{ name: "carrot", ... }],
// }
    

当您想要 `Map` 而不是普通对象时，还有 `Map.groupBy` （如果您的键不是字符串，则很方便）。 自2024年3月以来，两者都是新的基线，并且有望在2026年底广泛使用。

### 深度克隆

`lodash.clonedeep` 创建对象的深拷贝。 `structuredClone`是平台版本，广泛使用：

const original = { user: { name: "sam", 角色: ["admin"] } };
    
常量副本 = StructuredClone（原件）；
copy.user.roles.push("编辑器");
    
原始用户角色； // ["admin"]（未更改）
    

`structuredClone` 处理跳闸 `JSON.parse(JSON.stringify(...))` 的棘手情况：它正确克隆 `Date`、`Map`、`Set`、`ArrayBuffer` 和循环引用。 知道的限制（再次问题 3）是它不能克隆函数、DOM 节点或类实例； 它抛出函数并在类实例上丢弃原型。 对于普通数据，这是大多数人的深度克隆，它是一个干净的替代品。

### 设置操作

如果您曾经为 `union`、`intersection` 或 `difference` 拉入 Lodash 助手，那么 `Set` 对象现在内置了这些对象。它们是新可用的基线，自 2024 年 6 月以来：

const admins = new set(["sam", "alex", "jo"]);
const 编辑器 = new set(["alex", "kim"]);
    
管理员.intersection（编辑器）； // 设置 { "Alex" }
admins.union（编辑器）； // 设置 { "Sam", "Alex", "Jo", "Kim" }
admins.difference（编辑器）； // 设置 { "Sam", "Jo" }
    

全套方法是 `union`、`intersection`、`difference`、`symmetricDifference`、`isSubsetOf`、`isSupersetOf` 和 `isDisjointFrom`。

### 什么是值得保留的

并非所有的 Lodash 都已进入平台。 `debounce` 和 `throttle` 仍然没有本机等价物，它们确实很有用，所以采摘 `lodash.debounce` 是合理的。 这个集群的重点不是“删除 lodash”，而是“停止运送浏览器已经拥有的部分”。 单独删除 `lodash.clonedeep` 和 `lodash.groupby` 大约是 **8 kb gzipped**，如果您要为少数功能导入完整的 `lodash`，则替换平台覆盖的功能可以让您完全放弃它。

集群 5：暂时，暂时不放弃图书馆的案例研究
-----------------------------------------------------------

到目前为止，每个集群都以“继续，放弃它”结尾。 这恰恰相反，这就是为什么它值得包括的原因：它显示了框架告诉你等待。

`Temporal` 是 JavaScript 的 `Date` 的期待已久的替代品，它是一个真正更好的 API：不可变的对象、理智的时区处理，以及不再是从零开始的月份索引。 它于2026年3月达到TC39阶段4，是ES2026规范的一部分。 Firefox 在版本 139（2025 年）中发货，Chrome 在 144 版（2026 年 1 月）发货。 Safari 尚未以稳定的形式发布它。 它在Safari技术预览中，预计在2026年晚些时候提供稳定的支持。

如果时间对您来说是新闻，请查看 [Temporal Cheatsheet](https://learnjavascript.online/temporal.html) 以快速概述 API 并与 `Date` 进行比较。

然而，`Temporal` 是 _not_ 基线。 它仍处于 _Limited Availability_ 中，因为 Safari 用户没有它。 要在今天的所有浏览器中使用它，您需要一个 polyfill，这就是数学对您不利的地方。

官方 `@js-temporal/polyfill` 大约是 **44 kb gzipped**。 内部有一个较小的聚填充物，它不依赖于 BigInt，它的重量为 **19 kb gzipped**。 像 `dayjs` 这样的轻量级日期库大约是 **3 kb gzipped**。 因此，如果您现在将 `dayjs` 换成 `Temporal` 加上它的 polyfill，您不会节省 3 KB，您将 _adding_ 大约 41 KB 到您的捆绑包中，除非您能够有条件地加载多边形填充。

通过框架运行它：

*   **问题 1（受众）：** 时间不是基线。 对于广大受众来说，这是很多人。
*   **问题 2（成本）：** polyfill 的大小是您要删除的库的十倍以上。 交换使您的捆绑包更大。
*   **问题 3（特征差距）：** 在这里实际获胜； 它的作用超过 `dayjs`。 但这并不重要，因为问题 1 和 2 失败了。

判决通常很明确：暂时保留 `dayjs`（或 `date-fns`）。 重新审视的时刻是 Safari 在稳定版本中运送时间并到达基线。 此时，您可以在原生的时间内使用临时加载的 polyfill 来加载旧浏览器上的用户。 这是一个可以在几个月后写下和再次检查的功能，今天没有采取行动。

如何自己运行此审核 `package.json`
--------------------------------------------

上面的集群是一个起始地图，但你的依赖是你自己的。 这是您本季度可以运行的可重复过程。

### 步骤1：列出您的生产依赖

首先列出实际运送给用户的内容：

npm ls --omit=dev --depth=0
    

### 第 2 步：衡量每一种的成本

对于每个包的快速编号，[Bundlephobia](https://bundlephobia.com/) 为您提供任何 npm 软件包的缩小和压缩大小。 对于真实的图片（每个依赖项在您的实际捆绑包中的成本，在树震和去重后），针对您的构建运行捆绑分析器。 `npx source-map-explorer` 适用于大多数捆绑包，`npx vite-bundle-visualizer` 适用于 Vite 项目。

Such package takes 331ms to download on slow 3G and 19ms on emerging 4G.](https://res.cloudinary.com/indysigner/image/fetch/f_auto,q_80/w_400/https://files.smashing.media/articles/how-baseline-can-help-ship-less-javascript/2-bundlephobia-website.png)](https://files.smashing.media/articles/how-baseline-can-help-ship-less-javascript/2-bundlephobia-website.png)

### 步骤3：检查每次更换的基线状态

对于每个候选者，找到可以替换它的平台功能并检查其基线状态。 最快的方式是 [webstatus.dev](https://webstatus.dev/) 或功能的 MDN 页面上的基线徽章。

### 第4步：运行三个问题

对于每个有平台替换的库，请回到框架：它对您的受众是否安全？ 交换费用是多少？ 该功能是否涵盖了您实际使用库的方式？ 您的大部分决定都将属于问题 1（根据您的 `browserslist` 检查功能的状态）和问题 3（检查您自己的使用情况）。

### 第5步：在需要的地方进行逐步增强

对于广泛可用的功能，交换和移动。 对于新可用的，要么确认您的受众在现代浏览器上，要么通过快速功能检查来保护新代码并保持回退：

if (typeof intl.DurationFormat === "函数") {
// 使用平台功能
} 其他{
// 回退到库，或更简单的格式
}
    

这样，您就可以将更少的代码运送给可以运行它的用户，而不会破坏无法运行的代码。

包起来
------------

将集群添加起来，图片是具体的。 国际化集群约为 14 KB 压缩，HTTP 约为 17 KB，UI 原语约为 24 KB，Lodash 实用程序为 8 KB 或更多，具体取决于您运送的库数量。 对于一个典型的中型应用程序，它在 60 kb 到 90 kb 的依赖关系之间，您可以将其交还给平台，如果您同时运送完整的 `lodash` 或几个这些库，则会更多。 （未压缩的数字大两到三倍，这是您在 gzip 之前的捆绑分析器中看到的。）

我为这些功能中的大多数选择了相对精简的包装，但有些单独的软件包仍然可能很重。 例如，根据您使用的内容，您的 Dialog 软件包的重量可能高达 50KB 的 gzipped。

明年有一些值得关注的功能，因为它们将进一步开放：

*   ***暂时本地化。**
一旦 Safari 以稳定版本的形式运送它并达到基线，您就可以删除您的日期库 _and_ polyfill，将今天的回归转化为真正的胜利。
*   **CSS 锚定定位成熟。**
它于 2026 年 1 月成为新推出的基线。随着它向广泛可用的年龄迈进，放弃工具提示和弹出窗口定位库对广泛的受众来说变得更加安全。
*   **`Object.groupBy` 和朋友过境广泛使用。**
2024年的批次（数组分组，设置方法）有望在2026年底广泛使用，这使他们从“检查你的受众”变成了“只使用它”。

这些都不是一次性清理。 该平台不断提供新功能，_“您需要一个库为此”_ 和 _“浏览器执行此操作”_ 之间的差距不断关闭。 值得养成的习惯很小：每季度一次，进行审计。 列出您的依赖项，检查现在的基线，并交还您可以的东西。

从本文中选择一个集群，打开 `package.json`，看看浏览器已经为您做了多少。

命名 UI 组件的实用指南，其中包含有用的资源、命名约定和结构。 您可以在 Smashing 杂志上找到更多 [useful guides](https://www.smashingmagazine.com/category/guides/) 和 [online workshops](https://smashingconf.com/online-workshops)，因此请务必浏览和探索。

命名很难。 我们使用的语言塑造了我们对事物的思考方式，也塑造了我们对它的对话。 这就是为什么我们对颜色、图标、UI 组件、功能如此混乱的原因——这就是为什么我们很难命名设计令牌、HTML 类和变量。

有时，我们选择的名称**太通用了**，因此很难理解到底是什么意思。 有时它们**过于具体**，几乎没有灵活性和重复使用的空间。 我们如何选择正确的名字？ 哪些命名约定效果最好？ 让我们仔细看看。

如何命名事物
-------------------

如果您正在寻找命名 HTML 类、CSS 属性或 JavaScript 函数的灵感，[Classnames](https://classnames.paulrobertlloyd.com/) 是一个包含了丰富想法的精彩资源，这些想法让您**跳出框框思考**。

[![Inspiration For Naming Things](https://res.cloudinary.com/indysigner/image/fetch/f_auto,q_80/w_400/https://files.smashing.media/articles/how-name-things-choose-accordion-icons/1-classnames.jpg)](https://classnames.paulrobertlloyd.com)

[Classnames](https://classnames.paulrobertlloyd.com/) 提供可用于命名的主题分组列表。 （[Large preview](https://files.smashing.media/articles/how-name-things-choose-accordion-icons/1-classnames.jpg)）

该网站提供了适合命名的主题词组列表。 你会找到术语来描述不同类型的行为、事物之间的相似性、秩序、分组和联想，但也**主题的单词集合**，在涉及代码时不会立即出现在一个人的脑海中，其中包括来自自然、艺术、戏剧、音乐、建筑、时尚和 出版。

如何命名颜色
-------------------

您将如何为给定颜色选择正确的名称？ 幸运的是，David Aerne 拥有一个 [tremendous repository of color names](https://github.com/meodai/color-names)，目前有 **30355 唯一颜色名称**，来自各种参考资料和 1000 的用户贡献。

[![Inspiration For Naming Colors](https://res.cloudinary.com/indysigner/image/fetch/f_auto,q_80/w_400/https://files.smashing.media/articles/how-name-things-choose-accordion-icons/2-color-parrot.jpg)](https://parrot.color.pizza/)

[Color Parrot](https://parrot.color.pizza/) 提供给定颜色的名称（最初通过推文，但您也可以在 URL 中输入它）。 （[Large preview](https://files.smashing.media/articles/how-name-things-choose-accordion-icons/2-color-parrot.jpg)）

当然，存储库还附带一个 [color picker and name search](https://codepen.io/meodai/full/pXNpXe) 和大量的 [other color pickers](https://github.com/meodai/color-names)。 巨大的工作，这也是一个很好的参考，可以放在附近。

如何命名图层和组
-----------------------------

什么是好名声？ Javier Cuello 总结了一组 [naming best practices](https://goodpractices.design/guidelines/naming)，以一致且可扩展的方式帮助您命名**图层、组和组件**。

[![Inspiration For Naming Things](https://res.cloudinary.com/indysigner/image/fetch/f_auto,q_80/w_400/https://files.smashing.media/articles/how-name-things-choose-accordion-icons/3-naming-guidelines.jpg)](https://goodpractices.design/guidelines/naming)

Javier Cuello 探索了所有细节 [what makes an effective name](https://goodpractices.design/guidelines/naming)。 （[Large preview](https://files.smashing.media/articles/how-name-things-choose-accordion-icons/3-naming-guidelines.jpg)）

正如哈维尔所指出的，一个好名字有一个逻辑结构，简短、有意义，每个人都知道，与视觉属性无关。 他分享**做和不做的**来说明如何实现这一点，并仔细研究在命名尺寸、颜色、组、图层和组件时需要考虑的所有精细细节。

如何命名设计令牌
--------------------------

如何构建适用于不同产品的灵活设计令牌分类法？ 这是Intuit团队面临的挑战。 Mailchimp、QuickBooks、TurboTax 和 Mint 等产品的母公司开发了一种**灵活的代币系统**，它超越了品牌主题，成为各种产品的基础系统。

[![Insiration For Naming Things](https://res.cloudinary.com/indysigner/image/fetch/f_auto,q_80/w_400/https://files.smashing.media/articles/how-name-things-choose-accordion-icons/4-design-token-taxonomy.png)](https://medium.com/@NateBaldwin/creating-a-flexible-design-token-taxonomy-for-intuits-design-system-81c8ff55c59b)

Nate Baldwin 分享了 [Intuit’s flexible design token taxonomy](https://medium.com/@NateBaldwin/creating-a-flexible-design-token-taxonomy-for-intuits-design-system-81c8ff55c59b) 的见解。 （[Large preview](https://files.smashing.media/articles/how-name-things-choose-accordion-icons/4-design-token-taxonomy.png)）

Nate Baldwin 写了一篇 [case study](https://medium.com/@NateBaldwin/creating-a-flexible-design-token-taxonomy-for-intuits-design-system-81c8ff55c59b)，其中他分享了关于 **Intuit 的设计象征性分类**的制作的宝贵见解。 它深入探讨了旧分类系统的痛点、他们为新系统定义的标准以及它是如何创建的。 保证了很多用于构建您自己强大且灵活的令牌分类法的收获。

UI 组件的频繁名称
--------------------------------

看看其他人所说的类似的东西是当你**命名时**的一个很好的开始方式。 还有什么比其他设计系统更好的来源？ 在你最终进入设计系统兔子洞之前，Iain Bean 为你做了研究并创建了 [Component Gallery](https://component.gallery/components/)。

[![Inspiration For Naming Things](https://res.cloudinary.com/indysigner/image/fetch/f_auto,q_80/w_400/https://files.smashing.media/articles/how-name-things-choose-accordion-icons/5-interface-components.png)](https://component.gallery/components/)

[The Component Gallery](https://component.gallery/components/) 从实际设计系统中收集接口组件。 （[Large preview](https://files.smashing.media/articles/how-name-things-choose-accordion-icons/5-interface-components.png)）

它是一个集合，**包含大量示例**，用于 50 多个 UI 组件——从手风琴到视觉隐藏——还列出了 UI 组件所使用的其他名称。 一个绝妙的资源，不仅仅是在命名方面。

> 奖励：[Name That UI](https://namethatui.com/)，常见 UI 组件的 **视觉词典**。

如何命名新功能
-------------------------

由于**可发现性差**，功能通常采用率低。 特征采用需要时间——首先必须发现该功能，然后理解，然后尝试、学习并最终内置到**现有的工作流程**中。 Erin Gannon 写了一篇关于如何确保所有事情都发生的有用的 [practical guide](https://uxdesign.cc/what-do-we-call-this-thing-9cb0645fbd05)。

[![So What Do We Call That Feature?: illustrated guide to naming features that people discover, understand and actually use](https://res.cloudinary.com/indysigner/image/fetch/f_auto,q_80/w_400/https://files.smashing.media/articles/how-name-things-choose-accordion-icons/6-illustrated-guide-naming-features.jpeg)](https://files.smashing.media/articles/how-name-things-choose-accordion-icons/6-illustrated-guide-naming-features.jpeg)

Erin Gannon 的“[What Do We Call This Thing?](https://uxdesign.cc/what-do-we-call-this-thing-9cb0645fbd05)”：关于人们可以发现、理解和实际使用的命名特征的实用指南。 （[Large preview](https://files.smashing.media/articles/how-name-things-choose-accordion-icons/6-illustrated-guide-naming-features.jpeg)）

好名字是由用户需求和问题驱动的。 它们应该表明一个特征的价值或结果（待完成的工作），而且——最重要的是！ — 点击用户自己的语言。 所以让人们用他们自己的话来解释一个特征，然后使用他们使用的词语。

如何命名变量（分类图）
----------------------------------

沃达丰英国设计系统团队提供了一个复杂的多品牌、多主题设计系统命名指南的一个很好的例子。 他们的 [Variables Taxonomy Map](https://www.figma.com/community/file/1339950482183709250/vodafone-uk-variables-taxonomy-map) 将设计标记**的解剖和分类分解为精心编排的集合系统。

[![Inspiration For Naming Things](https://res.cloudinary.com/indysigner/image/fetch/f_auto,q_80/w_400/https://files.smashing.media/articles/how-name-things-choose-accordion-icons/7-vodafone-variables-taxonomy-map.png)](https://www.figma.com/community/file/1339950482183709250/vodafone-uk-variables-taxonomy-map)

[Vodafone’s Variables Taxonomy Map](https://www.figma.com/community/file/1339950482183709250/vodafone-uk-variables-taxonomy-map) 适应复杂的多品牌、多主题的设计系统。 （[Large preview](https://files.smashing.media/articles/how-name-things-choose-accordion-icons/7-vodafone-variables-taxonomy-map.png)）

该地图说明了支持系统和令牌之间的连接所需的四个集合——**从品牌和原语到语义和页面**。 它建立在 [Nathan Curtis’ work on naming design tokens](https://medium.com/eightshapes-llc/naming-tokens-in-design-systems-9e86c7444676) 之上，使每个人都能够从它的名称中收集到关于在哪里使用令牌和它所代表的东西的洞察力。

如果您想探索更多命名设计令牌的方法，我整理了一个值得一试的 [list of useful Figma kits and resources](https://www.linkedin.com/posts/vitalyfriedman_ux-design-activity-7173228980534243328-fHeA)。

包起来
------------

正确的名称是团队和用户充分理解和使用的名称。 浪费了很多时间来谈论同样的事情，但在**不同的方言**——设计师的方言、开发人员的方言、产品经理的方言和用户的方言中。 这通常会导致挫败感和困惑。

因此，如果您看到采用率低，可能仅仅是因为名称。 并注意潜在的 **命名冲突**，并将它们放在积压的事情中，以便以后解决。 这是可以减少挫败感和混乱并帮助团队更好地合作的精美小细节之一。

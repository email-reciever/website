我们大多数人只安装一次依赖项，然后就不再关注它了。它完成了自己的工作，测试通过，我们就继续前进。但是，Web 平台也在不断演进，令人惊讶的是，你今天在 `package.json` 中的许多库现在已经被浏览器内置了。

在一个典型的中等规模的 JavaScript 应用中，你经常可以找到大约 60KB 到 90KB（压缩和 gzip 后）的依赖项，这些依赖项现在可以由平台自己处理。日期和数字格式化、HTTP 请求、模态框、工具提示、深度克隆、数组分组：这些几年前都是真正的缺口。但是现在，很多这些缺口已经不存在了。

这些库之所以仍然存在，并不是因为懒惰。原因是大多数团队不按基线周期重新审计他们的依赖项，或者他们 simply 不知道浏览器现在发布的速度有多快。你检查 `npm audit` 以确保安全，但是 *这个库是否仍然在做浏览器无法做的事情？* 这个问题很少被问到。所以，这些库就留下来了。

在这篇文章中，我们将一起进行审计。与其一一检查依赖项，我们将以集群的方式工作，因为优势往往成群出现。我们将进行包的数学计算，构建一个小的决策框架，你可以重用它，并对平台仍然存在不足的地方保持诚实。到最后，你将拥有一个可以在自己的 `package.json` 上运行的可重复的过程。

什么是“Baseline”的真正含义

在我们开始删除东西之前，让我们快速回顾一下什么是 Baseline。如果你已经熟悉了这一部分，可以跳过它。

Baseline 是 [WebDX Community Group](https://github.com/web-platform-dx/web-features) 的一个项目，它用简单的语言告诉你，一个 Web 功能在主要浏览器（Chrome、Edge、Firefox 和 Safari）中使用的安全性如何。一个功能可以处于三种状态之一：

* **有限可用性**\
  该功能尚未在所有主要引擎中发布。没有回退机制时，不建议依赖它。
* **基线新增**\
  该功能刚刚在所有主要引擎中发布。对于使用最新浏览器的用户来说，它是可用的，但野外的旧设备可能还没有。
* **基线广泛可用**\
  该功能已经在所有主要引擎中存在 30 个月。此时，您可以在不多加思考的情况下使用它。

这 30 个月的间隔对于这个审计非常重要。广泛可用的功能通常可以在今天放弃库。仅新增的功能可以在检查您的受众后或您对小功能检查感到满意时放弃库。我们将在整个过程中区分对待这两种情况。

您可以在 [webstatus.dev](https://webstatus.dev/)、[MDN](https://developer.mozilla.org/)（每个参考页面顶部附近都有基线徽章）或使用 `web-features` npm 包以编程方式查找任何功能。稍后，我们将在运行真实项目审计时使用这三种方法。

在删除任何内容之前的决策框架

很容易因为 *“浏览器现在支持这个功能”* 就开始删除库。但是我们不应该这样做。表面上看似免费的替换实际上可能会为一部分用户带来问题，或者在你没有意识到的情况下丢失一个功能。

因此，在删除任何库之前，问三个问题。我们将在下面的每个部分重用这些问题。

**1. 替换是否对** **_我的_** **受众 Baseline 安全？**

不是 *“它是否是 Baseline”* 在抽象意义上，而是 *“它是否对实际使用我的应用程序的人们安全”* 。如果原生功能被广泛支持，这通常是一个是。如果它只新近可用，检查你的分析数据或你的 `browserslist` 配置，查看你的用户中有多少会错过这个功能。一个所有人都使用最新浏览器的 B2B 仪表板与一个有很多旧的 Android 设备的公共网站有很大的不同。

**2. 替换实际的成本是什么？**

放弃一个库并不总是免费的。有时，原生功能尚未被广泛支持，因此您需要使用 polyfill。如果该 polyfill 比您要删除的库更重，您将使您的包 *更大*，除非您有条件地加载它。我们稍后将看到 Temporal 的这种情况。

**3. 平台功能是否涵盖我的实际使用场景？**

库通常比它们类似的平台功能做的更多。`axios` 不仅仅是带有自动 JSON 解析的 `fetch`；它还具有拦截器、请求取消和重试。如果您使用这些功能，直接切换到 `fetch` 将会让您重新实现它们。在假设它是一个直接替换之前，请检查您实际使用的内容。

请记住这三点。下面每个集群实际上只是将这些问题应用于您依赖关系的不同角落。

集群 1：国际化（今天最大的降级获胜）

这是您通常会找到最多的 KB 堆积在已经被广泛支持的功能之上的集群。浏览器在 `Intl` 命名空间下提供了一整系列的格式化工具，而许多小型流行库变得不再必要。

这里是通常的嫌疑人和它们的替代品：

* `timeago.js` (1 KB gz) → `Intl.RelativeTimeFormat`
* `pluralize` (2.3 KB gz) → `Intl.PluralRules`
* `numeral` (3.9 KB gz) → `Intl.NumberFormat`
* `humanize-duration` (6.6 KB gz) → `Intl.DurationFormat`
* 列表连接帮助函数 → `Intl.ListFormat`

让我们来看看其中一些。

### 相对时间

`timeago.js` 的作用是将时间戳转换为 *“3 小时前”*。 `Intl.RelativeTimeFormat` 做同样的事情，而且它的兼容性非常广泛。

```text
const rtf = new Intl.RelativeTimeFormat("en", { numeric: "auto" });

rtf.format(-1, "day"); // "yesterday"
rtf.format(3, "hour"); // "in 3 hours"
rtf.format(-2, "week"); // "2 weeks ago"
```

这里的 `numeric: "auto"` 选项是一个很好的功能：它可以根据语言返回 “昨天” 而不是 “1 天前”。您传入一个数字和一个单位，就会得到一个本地化的字符串。

您可能会想知道 `timeago.js` 做的一件事，这个代码片段没有做到：它为您选择单位。给定一个日期，`timeago.js` 会决定是否说 “秒” 或 “天”。 `Intl.RelativeTimeFormat` 需要您自己完成这一部分。这只需要几行算术代码（计算差值，找到最合适的单位），而且一旦您写了这个帮助函数，您就不再需要这个库了。

### 数字、货币和列表

`Intl.NumberFormat`涵盖了大多数数字格式化库的功能：千位分隔符、货币、百分比和紧凑表示。

```text
new Intl.NumberFormat("en-US").format(1234567.89);
// "1,234,567.89"

new Intl.NumberFormat("en-US", { style: "currency", currency: "USD" }).format(
  1234.5,
);
// "$1,234.50"

new Intl.NumberFormat("en", { notation: "compact" }).format(1200000);
// "1.2M"
```

并且，`Intl.ListFormat`广泛可用，处理了“将数组连接成句子”的问题，包括牛津逗号，这是人们编写复杂的辅助函数的类型：

```text
const lf = new Intl.ListFormat("en", { style: "long", type: "conjunction" });

lf.format(["Alice", "Bob", "Carol"]);
// "Alice, Bob, and Carol"
```

### 唯一的注意事项：时长

`humanize-duration`将毫秒数转换为\*“1小时，30分钟”\*。平台等效的功能是`Intl.DurationFormat`：

```text
const df = new Intl.DurationFormat("en", { style: "long" });

df.format({ hours: 1, minutes: 30 });
// "1 hour, 30 minutes"
```

需要注意的一点是，`Intl.DurationFormat`在编写时是新近可用的，而不是广泛可用。它于2025年3月登陆所有主要引擎，并且预计将在2027年成为广泛可用的功能。因此，对于广泛受众的应用程序来说，这一功能无法满足第一个问题，除非您先检查流量或添加回退。对于现代浏览器上的内部工具来说，它现在是可以的。对于具有旧设备的公共网站，请再等待一年或者使用功能检查来保护它。

### 这一集的数学计算

如果你的应用使用了全部的集合（`humanize-duration`、`timeago.js`、`pluralize`、`numeral`），那么大约需要 **14 KB gzipped** 的依赖项，其中大部分可以用广泛可用的 API 替换。国际化集群通常是整个审计中最容易获胜的部分。

Cluster 2：HTTP 客户端

这个集群更为复杂，因此值得慢下来考虑。

浏览器 HTTP 库中，人们常用的有 `axios`（17 KB gz）和 `superagent`（19 KB gz）。对于大多数请求，`fetch` 加上 `AbortController` 就可以满足你的需求，而且两者都广泛可用。

一个基本的 GET 请求看起来像这样：

```text
// axios
const { data } = await axios.get("/api/users");

// fetch
const res = await fetch("/api/users");
const data = await res.json();
```

多出来的一行（`res.json()`）是 `fetch` 显式地做了 `axios` 默认隐式做的事情。这是整个集群中的模式：`fetch` 默认不做太多事情，你决定是否需要它省略的东西。

### 超时

`axios` 有一个 `timeout` 选项。`fetch` 有 `AbortSignal.timeout()`：

```text
const res = await fetch("/api/users", {
  signal: AbortSignal.timeout(5000), // abort after 5 seconds
});
```

### `fetch` 不替换 `axios` 的地方

这是问题 3 发挥作用的地方，因此让我们具体说明差距：

* **`fetch` 不会在 HTTP 错误时拒绝。**\
  一个 `404` 或 `500` 是一个已解决的 promise，而不是拒绝。你必须自己检查 `res.ok`。`axios` 会在任何非 2xx 状态码时拒绝。
* **没有拦截器。**\
  如果你依赖 `axios` 拦截器来附加认证令牌或在一个地方处理 401 错误，`fetch` 没有等价的功能。你需要用自己的函数或类来包装 `fetch` 以获得相同的行为。
* **没有自动重试。**\
  `axios` (带有插件) 可以重试失败的请求。使用 `fetch` 时，你需要自己编写代码来实现重试。
* **没有上传进度。**\
  `fetch` 仍然不能以优雅的方式报告上传进度。如果你有一个带有进度条的文件上传器，这是一个保持库的理由。
* 我个人非常依赖 *拦截器* 在我的在线交互课程中，例如 [Learn JavaScript](https://learnjavascript.online/)，并且我使用 `fetch` 上面的自定义 `class` 已经解决了这个问题多年了。我已经将其发布给数百万用户，并看到很多成功的案例。

这些都不难重建，大多数应用只使用其中一两个。但这是一个你不应该进行盲命令查找和替换的集群。首先看看你实际如何使用你的HTTP客户端。如果只是简单的GET和POST请求，使用一个薄的`fetch`包装器代替`axios`可以为你节省大约**17 KB gzipped**的空间。

Cluster 3: UI Primitives

这个集群有一些最令人满意的替换，因为平台功能不仅匹配了库，而且通常比团队手动创建的内容更易访问。

这里的库包括模态对话框（例如`a11y-dialog`，1.8 KB gz），工具提示和弹出式库（`tippy.js`，14 KB gz，它包含用于定位的Popper），`focus-trap`（6.6 KB gz）和`body-scroll-lock`（1.3 KB gz）。它们被三个平台功能替换：`<dialog>`元素，Popover API和CSS锚点定位。

### The `<dialog>` Element

大量与模态框相关的代码存在于解决可访问性问题：将焦点困在模态框内，在按下 `Escape` 时关闭，模态框关闭时将焦点恢复到之前的元素，以及在其他所有元素上方渲染。 `<dialog>` 元素，广泛可用，替你完成了所有这些。

```text
<dialog id="confirm">
  <form method="dialog">
    <p>Delete this file?</p>
    <button value="cancel">Cancel</button>
    <button value="delete">Delete</button>
  </form>
</dialog>

const dialog = document.querySelector("#confirm");

dialog.showModal(); // focus moves in, background goes inert, Escape closes it

dialog.addEventListener("close", () => {
  console.log(dialog.returnValue); // "cancel" or "delete"
});
```

调用 `showModal()` 完成了 `focus-trap` 被安装的工作：焦点移动到对话框中，页面的其他部分变得不活动，因此你不能从中跳出， `Escape` 关闭它，并且焦点返回到打开它的元素。对话框在浏览器的 *顶层* 中渲染，因此你不必处理 `z-index` 问题。你还获得了一个 `::backdrop` 伪元素来样式化覆盖层。

单个元素可以替换你的模态框库 *和* `focus-trap`。它无法自行处理的唯一部分是锁定背景从滚动，这是 `body-scroll-lock` 的用途。现在，这只需要一行 CSS：

```text
body:has(dialog:modal) {
  overflow: hidden;
}
```

如果您想知道为什么我们使用 `dialog:modal` 而不是 `dialog[open]`，这是因为 `open` 属性在您调用 `show()` 时就会被设置，但是对话框实际上并不是 *模态* 的，因此您不希望锁定滚动。`:modal` 伪类只有当对话框实际上是 *模态* 时才为真，这是在您调用 `showModal()` 时的情况。

因此，三个库合并成一个元素和一个 CSS 规则。

### Popover API 和锚点定位

对于不是完整模态的东西（下拉菜单、工具提示、`tippy.js` 处理的小浮动面板），[Popover API](https://www.smashingmagazine.com/2026/03/getting-started-popover-api/) 提供了轻松关闭行为、顶层渲染和 `Escape`-to-close，不需要任何 JavaScript：

```text
<button popovertarget="menu" id="options">Options</button>

<div id="menu" popover>
  <!-- menu content -->
</div>
```

点击按钮会切换弹出窗口。点击外部会关闭它。它是基线新功能（自 2025 年 1 月以来）。

另一半 tooltip 库的功能是 *定位*：保持浮动元素固定在其触发器上，并在其溢出视口时翻转。这就是 Popper（内置于 `tippy.js`）处理的内容，现在它是一个叫做锚点定位的 CSS 特性。它将同一个 `#menu` 弹出窗直接固定在其触发按钮下方：

```text
#options {
  anchor-name: --trigger;
}

.tooltip {
  position-anchor: --trigger;
  position-area: top;
  margin: 0;
}
```

锚点定位是本文中最新的特性。它于 2026 年 1 月在 Firefox 147 中发布（Chrome 从版本 125 开始支持，Safari 从版本 26 开始支持）。由于它非常新，因此它完全是一个问题性特性：适合现代受众，但需要检查流量，并注意到一些高级部分（如位置尝试回退）在不同版本中支持不均匀。为较旧的浏览器保留一个合理的回退。

在 `<dialog>`、Popover API 和锚点定位之间，UI 原语集群（tooltip 库、模态库、`focus-trap`、`body-scroll-lock`）加起来大约为 **24 KB gzipped**，并且您可以在另一端获得比大多数手动解决方案更好的无障碍默认值。

集群 4：Lodash Utilities

Lodash 很少再作为一个整体被导入，但其个别函数却无处不在，既可以作为完整的 `lodash` 包（25 KB gz），也可以作为独立安装，如 `lodash.clonedeep` 和 `lodash.groupby`。其中一些最常用的函数现在都有直接的平台等价物。

### 分组

`lodash.groupby` 将一个数组重新组织为一个以某个属性为键的对象。`Object.groupBy` 完成相同的功能：

```text
const products = [
  { name: "Apple", category: "fruit" },
  { name: "Carrot", category: "vegetable" },
  { name: "Banana", category: "fruit" },
];

const grouped = Object.groupBy(products, (product) => product.category);
// {
//   fruit: [{ name: "Apple", ... }, { name: "Banana", ... }],
//   vegetable: [{ name: "Carrot", ... }],
// }
```

还有一种 `Map.groupBy`，用于当你想要一个 `Map` 而不是一个普通对象时（如果你的键不是字符串，这很方便）。两者都是 Baseline 新增功能，自 2024 年 3 月以来可用，并计划在 2026 年底成为广泛可用。

### 深度克隆

`lodash.clonedeep` 创建一个对象的深度副本。`structuredClone` 是平台版本，并且广泛可用：

```text
const original = { user: { name: "Sam", roles: ["admin"] } };

const copy = structuredClone(original);
copy.user.roles.push("editor");

original.user.roles; // ["admin"] (unchanged)
```

`structuredClone` 处理了 `JSON.parse(JSON.stringify(...))`*easyapi* 的棘手情况：它可以正确地克隆 `Date`、`Map`、`Set`、`ArrayBuffer` 和循环引用。需要注意的限制（再次是问题 3）是，它不能克隆函数、DOM 节点或类实例；它会在函数上抛出异常，并在类实例上丢弃原型。对于纯数据（大多数人深度克隆的内容），它是一个干净的替代品。

### 集合操作

如果您曾经为 `union`、`intersection` 或 `difference` 导入过 Lodash 辅助函数，那么 `Set` 对象现在内置了这些功能。它们从 2024 年 6 月开始提供：

```text
const admins = new Set(["sam", "alex", "jo"]);
const editors = new Set(["alex", "kim"]);

admins.intersection(editors); // Set { "alex" }
admins.union(editors); // Set { "sam", "alex", "jo", "kim" }
admins.difference(editors); // Set { "sam", "jo" }
```

完整的方法集包括 `union`、`intersection`、`difference`、`symmetricDifference`、`isSubsetOf`、`isSupersetOf` 和 `isDisjointFrom`。

### 值得保留的内容

并非所有的 Lodash 功能都已经集成到平台中。`debounce` 和 `throttle` 仍然没有原生等价物，它们确实非常有用，所以选择性地使用 `lodash.debounce` 是合理的。这个集群的目的不是“删除 Lodash”，而是“停止引入浏览器已经具备的功能”。仅仅放弃 `lodash.clonedeep` 和 `lodash.groupby` 就可以减少大约 **8 KB gzipped** 的大小，如果你为了使用几個函数而导入整个 `lodash`，那么替换掉已经被平台覆盖的函数就可以完全放弃它。

集群 5：Temporal，一个不删除库的案例研究

到目前为止，每个集群都以“可以删除”结尾。这一个则相反，这也是为什么它值得被包括在内的原因：它展示了框架告诉你“等待”的时候。

`Temporal` 是长期以来等待的JavaScript的 `Date` 的替代品，它是一个真正更好的API：不可变对象，合理的时区处理，不再有从零开始的月份索引。它在2026年3月达到TC39第四阶段，并成为ES2026规范的一部分。Firefox在139版本（2025年）中发布了它，而Chrome在144版本（2026年1月）中发布了它。Safari尚未在稳定版本中发布它；它在Safari Technology Preview中，以后在2026年预计会有稳定的支持。

如果 `Temporal` 对你来说是新闻，可以查看 [Temporal Cheatsheet](https://learnjavascript.online/temporal.html) ，以便快速了解API及其与 `Date` 的比较。

然而，`Temporal` 并不是 Baseline。它仍然处于 *有限可用性* 的状态，因为Safari用户还没有它。如果你想在今天所有浏览器中使用它，你需要一个polyfill，这就是数学对你不利的地方。

官方的 `@js-temporal/polyfill` 大约为 **44 KB gzipped**。还有一个更小的 polyfill ，它在内部不依赖于 BigInt ，其大小约为 **19 KB gzipped**。像 `dayjs` 这样的轻量级日期库大约为 **3 KB gzipped**。因此，如果您现在用 `Temporal` 及其 polyfill 替换 `dayjs` ，您并没有节省 3 KB，而是将大约 41 KB 添加到您的包中，除非您能够有条件地加载 polyfill。

运行它通过框架：

* **问题 1（受众）：** Temporal 不是 Baseline 。对于广泛的受众来说，这意味着有很多人。
* **问题 2（成本）：** polyfill 的大小是您要移除的库大小的十几倍。替换会使您的包更大。
* **问题 3（功能差距）：** 在这里，Temporal 实际上占优势；它可以做更多的事情比 `dayjs` 。但是，这并不重要，而问题 1 和 2 未解决。

裁决一般很明确：目前保持使用 `dayjs` (或 `date-fns`)。重新审视的时机是当 Safari 在稳定版本中发布 Temporal 并达到 Baseline 时。此时您可以原生使用 Temporal，并为旧浏览器的用户条件性加载 polyfill。这是一个需要在几个月后写下来并再次检查的功能，而不是今天就采取行动的功能。

如何在您的 `package.json` 上运行此审计

上面的集群是一个起始地图，但您的依赖项是您自己的。这里有一个可以在这个季度重复运行的过程。

### Step 1: 列出您的生产依赖项

首先列出实际发送给用户的内容：

```text
npm ls --omit=dev --depth=0
```

### Step 2: 测量每个依赖项的成本

对于每个包的快速数字，[Bundlephobia](https://bundlephobia.com/) 提供了任何 npm 包的最小化和 gzip 压缩大小。为了获得实际情况的真实图景（每个依赖项在您的实际包中花费的成本，在树摇和去重复之后），请针对您的构建运行包分析器。`npx source-map-explorer` 可以在大多数包中使用，而 `npx vite-bundle-visualizer` 可用于 Vite 项目。

![](https://files.smashing.media/articles/how-baseline-can-help-ship-less-javascript/2-bundlephobia-website.png)

### Step 3: 检查每个替换的 Baseline 状态

对于每个候选项，找到可以替换它的平台功能，并检查其 Baseline 状态。最快的方法是访问 [webstatus.dev](https://webstatus.dev/) 或查看功能的 MDN 页面上的 Baseline 徽章。

### Step 4: 运行三个问题

对于每个有平台替换的库，回到框架：是否为您的受众提供 Baseline 安全？交换的成本是什么？功能是否涵盖您实际使用库的方式？大多数决定将来自问题 1（检查功能的状态与您的 `browserslist`）和问题 3（检查您自己的使用情况）。

### Step 5: 根据需要在渐进增强后交换

对于广泛可用的功能，交换并继续。对于新近可用的功能， либо确认您的受众使用的是现代浏览器， либо使用快速的功能检查来保护新代码，并保留一个回退：

```text
if (typeof Intl.DurationFormat === "function") {
  // use the platform feature
} else {
  // fall back to the library, or a simpler format
}
```

这样，您可以在不破坏无法运行新代码的用户的情况下，减少发送给能够运行新代码的用户的代码量。

总结

将集群加起来，图景就变得清晰了。国际化集群大约为 14 KB gzipped，HTTP 大约为 17 KB，UI 原语大约为 24 KB，而 Lodash 实用工具根据您要发送的库的多少则为 8 KB 或更多。对于一个典型的中型应用程序，这意味着大约在 60 KB 到 90 KB gzipped 的依赖项可以返回给平台，如果您同时发送完整的 `lodash` 或多个库，则会更大。（未压缩的数字是两到三倍更大，这是在 bundle 分析器中看到的数字，在 gzip 之前。）

我选择了相对精简的包用于这些功能的大多数部分，但是某些个别包仍然可能很重。例如，您的对话框包，单独就可能达到 50KB gzipped，取决于您使用的内容。

在接下来的几年中，有几项功能值得关注，因为它们将打开进一步的替换机会：

* **Temporal 原生支持。**\
  一旦 Safari 在稳定版本中发布并达到 Baseline，你就可以同时放弃日期库和 polyfill，将今天的回归转变为真正的胜利。
* **CSS 锚点定位成熟。**\
  它于 2026 年 1 月成为 Baseline 新增功能。随着它逐渐变得更加普遍，放弃 tooltip 和 popover 定位库对于广泛的受众来说变得更加安全。
* **`Object.groupBy` 和相关功能进入广泛可用阶段。**\
  2024 年批次（数组分组，Set 方法）有望在 2026 年末成为广泛可用，这使得它们从“检查你的受众”转变为“直接使用”。

这些并不是一次性清理。平台不断发布新功能，“需要库来实现这个”和“浏览器已经支持这个”之间的差距不断缩小。需要建立的习惯很简单：每个季度运行一次审计。列出你的依赖项，检查什么现在是 Baseline，并归还你可以归还的东西。

选择这篇文章中的一个集群，打开你的 `package.json`，看看浏览器已经为你做了多少事情。

发现 SMIL，这是一种经常被忽视的动画 SVG，它在 `<img>` 标签内工作，并且可以在没有 JavaScript 的情况下完全为 SVG 中的所有内容设置动画。

我们知道网络上的所有内容默认都是一个盒子，但你会发现许多动画 `<div>` 假装是圆圈。 但如果你曾经遇到过真正的 `<circle>`，你就会知道他们有更多的事情要做。 穿着 SVG，它们适合更广泛的人群，而不是穿着 HTML/CSS 的不起眼的 `<div>`。 `<img>` 有严格的否 `.html` 政策。

`<img>` 标记是 [not as static as its name suggests](https://html.spec.whatwg.org/multipage/embedded-content.html#attr-img-src)。 不幸的是，如果您加载带有 `<img>` 标记的 SVG 文件，任何嵌入式 JavaScript 都无法运行，但 CSS 动画效果很好。 许多 [SVG attributes](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute) 确实有 CSS 属性对应物，并且自 2024 年以来，主要浏览器都支持 [the geometry properties](https://w3c.github.io/svgwg/svg2-draft/geometry.html)。您可能想要动画的一些属性，如 `viewBox`，还没有等价物。

除了 JavaScript 和 CSS 之外，还有另一个 [way to animate SVGs](https://www.w3.org/TR/SVG11/animate.html)：**同步多媒体集成语言 (SMIL)**。 尽管有它的怪癖，但它仍然值得学习。 与 CSS 动画一样，SMIL 动画也可以在 `<img>` 标签中运行，并且可以在 SVG 中完全动画化所有内容，**没有 JavaScript**。

如果您从未听说过 SMIL 或需要复习，请查看 [Andy Clarke’s well-named article](https://www.smashingmagazine.com/2025/05/smashing-animations-part-3-smil-not-dead/)。 然后我们将寻找一种规划动画并使 SMIL 标记更易于管理的方法。

分手
-------------

Smil 有一个问题：它很快就会臃肿。 与 CSS 和 JavaScript 不同，您可以在每个关键帧中列出多个属性并轻松重用动画，每个 SMIL 标记一次只能针对一个元素和该元素的一个属性。 可以对属性进行动画处理 [through a list of values](https://www.w3.org/TR/2001/REC-smil-animation-20010904/#AnimFuncValues)。 但它仍然是一个标签、一个元素、一种属性。 可以编写将运行的颜色和不透明度更改的最短方式如下：

<动画
attributeName="填充"
to="其他颜色"
dur="somduration"
/>
    
<动画
attributeName="不透明"
to="someothervalue"
dur="somduration"
/>
    

这还不错，但考虑到动画中包含的每个元素都需要重复它。 SMIL 动画可以快速获得比 CSS 等效的更长的时间。

为了在开始新动画时更容易，让我们计划我们想要设置动画的所有元素和属性，并为每个标记创建一个描述性 ID 列表。

--------------------------------

SMIL 的很大一部分是同步。 毕竟，它甚至在名字中。 并且有多个 [ways to specify when](https://www.w3.org/TR/SVG11/animate.html#TimingAttributes) 一个动画应该开始（这里是 [a test case to check what your browser supports](https://www.w3.org/Graphics/SVG/Test/20110816/harness/htmlObjectApproved/animate-elem-60-t.html)）。 最有用的方法之一是使用 SyncBase 值，即 SMIL 标签的 ID，后跟 `.begin` 或 `.end`，带有可选的正或负偏移。

让我们从之前的动画示例中搭载，其中包括颜色和不透明度的变化。 如果我们希望不透明度动画在彩色动画完成之前开始 `300` 毫秒，我们可以进行算术。 或者，第二个动画可以使用 SyncBase 值 `colorChange.end - 300ms`。 这样，两个动画之间的相对时间变得明确。

<!-- 绝对时间开始 -->
<动画
id="颜色变化"
begin="1"
...
/>
    
<!-- 相对于 #first 结束时开始 -->
<动画
id="不透明度"
begin="colorchange.end - 300ms"
...
/>
    

使用 SyncBase 值，动画的开头相对于其他动画的 `.begin` 或 `.end` 及时定位。 正偏移将开始向右移动（向前向前），负偏移向左移动（向后向后）。

第一步：选择图像方法
--------------------------------

浏览器广泛支持 `prefers-reduced-motion` 媒体功能和 [Val Head explains this in depth in another article](https://www.smashingmagazine.com/2020/09/design-reduced-motion-sensitivities/)。 当我们考虑移动事物时，我们绝对希望尊重这种用户偏好。 事实上，认为它是不可协商的。

在 SMIL 方面，有多种方法可以坚持用户的 `prefers-reduced-motion` 设置。 每个都有其优点和缺点。 尽早评估最适合您的用例的方法可以为您节省部分重写。

例如，我们可以考虑使用 [`<picture>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/picture) 元素而不是普通的 `<img>`，因为 `<picture>` 支持多个 `<source>` 元素，这些元素可用作 `media` 属性中的回退，以减少运动首选项。

或使用 `display: none` 在版本之间交换的内联 CSS `@media` 查询的一个 SVG 文件。 也就是说，它是[various environments](https://issues.chromium.org/issues/40493107)中的[an approach that might cause trouble](https://github.com/videojs/v10/issues/1325)。 但是浏览器在不断变化，这可能不是未来的问题。

您还可以考虑使用 CSS `background-image` ，因为我们可以将该样式包装在媒体查询中 - `@media (prefers-reduced-motion)` - 将静态图像设置为缩小运动首选项的后备。

我们可以求助于更多的选择！ 例如，SVG 的 [`<view>`](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/view) 元素也可用于将内容交换为运动首选项。

或者，如果我们更喜欢捆绑在一起的所有内容，我们可以使用 JavaScript `.matchMedia()` 和 [the handy SMIL DOM interface](https://www.w3.org/TR/SVG11/animate.html#DOMInterfaces) 来控制哪些动画开始，而不是完全切换文件。

为此，我避免了任何运动并坚持使用 `opacity` 动画，这往往会带来更少的麻烦。 对于像这样的非交互式动画，我们可以将其加载到 `<img>` 标记中。 当我们添加 Motion 时，我们可以通过 `<picture>` 路线来显示我们动画的最合适版本。

这就是时序图的好处
---------------------------------

总而言之，我们知道平衡动画的不同阶段充其量可能是困难的，最坏的情况是站不住脚的。 每当我们进入超过一两个步骤的多步骤动画时，它都是一种编排形式。 您几乎正在构建一个 Rube Goldberg 的标记机器。 使用时序图是我使用的一种策略，我希望它也会对您的项目有所帮助。 它们是期待什么和何时的概述，允许您以一种不仅有助于规划代码的方式绘制内容，而且使未来的更新和维护比没有计划的情况下更容易忍受。

虽然时序图不能降低标记的复杂性，但它可以很好地概述何时应该发生的事情。 时序图绝对不限于 SMIL 动画。 不幸的是，SyncBase 值是，即使您要使用不同的方法来实现动画，它们仍然可以提供帮助。

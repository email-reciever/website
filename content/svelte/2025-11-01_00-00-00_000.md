官方的 SVELTE MCP 服务器（满足您的所有代理需求）现在可使用自己的 [section of the docs site](/docs/ai/overview) 和 [GitHub repo](https://github.com/sveltejs/ai-tools)。 如果您还没有机会使用您选择的 AI 进行尝试，请务必尝试一下。 它应该替换通常需要LLMS编写有效的Svelte 5代码的Svelte文档的复制/粘贴，并可以通过静态分析提供有关生成代码的建议。

但是，一直在编写代码的不仅仅是 AIS； 我们的维护者也有！ 让我们看看他们在 Svelte/Kit 中所做的一切，然后再深入我们的社区展示......

Svelte 的新功能[](#What's-new-in-Svelte)
-------------------------------------------

*   `createContext` 传递具有存储上下文的类型 - 替换需要键入每个 `getContext` 返回值 (**5.40.0**, [Docs](/docs/svelte/svelte#createContext), [#16948](https://github.com/sveltejs/svelte/pull/16948))
*   `$state.eager(value)`符文将立即更新UI，而不是等待对应的`await`解析（**5.41.0**、[Docs](/docs/svelte/$state#$state.eager)、[#16849](https://github.com/sveltejs/svelte/pull/16849)）
*   API 允许您以这样的方式更改某些状态“屏幕外”，以便您可以在不将其提交到屏幕的情况下发现由状态更改产生的任何异步工作。 （**5.42.0**、[Docs](/docs/svelte/await-expressions#Forking)、[#17004](https://github.com/sveltejs/svelte/pull/17004)）

有关完整的更改列表 - 包括本月发布的数十个有价值的错误修正 - 查看 Svelte 编译器的 [CHANGELOG](https://github.com/sveltejs/svelte/blob/main/packages/svelte/CHANGELOG.md)。

sveltekit的新增功能[](#What's-new-in-SvelteKit)
-----------------------------------------------

*   `event.route` 和 `event.url` 现在可以在远程功能中使用，从而更容易知道从 (**2.44.0**、[Docs](/docs/kit/remote-functions)、[#14606](https://github.com/sveltejs/kit/pull/14606)) 调用远程函数的哪个页面
*   `form.for(id)`现在将在表单对象上隐式设置一个ID（**2.45.0**、[Docs](/docs/kit/remote-functions#form-Multiple-instances-of-a-form)、[#14623](https://github.com/sveltejs/kit/pull/14623)）
*   现在可以在无法通过模式（**2.46.0**、[Docs](/docs/kit/remote-functions#form-Programmatic-validation)、[#14624](https://github.com/sveltejs/kit/pull/14624)）完成的情况下进行表单验证。
*   新的 Signal Request 属性提供了与请求关联的 `AbortSignal` (**2.47.0**, [MDN Docs](https://developer.mozilla.org/en-US/docs/Web/API/Request/signal), [#14715](https://github.com/sveltejs/kit/pull/14715))
*   Kit 现在将在可用时使用 `fork` API。 有关详细信息（**2.48.0**，[#14793](https://github.com/sveltejs/kit/pull/14793)），请参阅上面的 Svelte 更新

[Svelte](/) 是用于构建具有较少代码的快速反应的 Web 应用程序的前端框架。 如果您是新来的，[check out the tutorial](/tutorial) 或 [examples](/examples) 以了解它。

Svelte 是 [launched 5 years ago](https://news.ycombinator.com/item?id=13069841) 并且有 [come a long way in the time since](https://www.youtube.com/watch?v=YeY5M29-WcY)。 2021年，随着使用量增加了一倍多，在一对调查中，[most satisfied](https://2020.stateofjs.com/en-US/technologies/front-end-frameworks/)开发人员被评为[most loved](https://insights.stackoverflow.com/survey/2021#section-most-loved-dreaded-and-wanted-web-frameworks)框架。 除了纽约时报、苹果、Spotify、Square、Rakuten、Bloomberg、路透社、宜家、Brave 和无数其他公司等知名公司外，Svelte 还被用来为从业余项目到嵌入式系统接口的一切提供动力。

为了帮助开发人员使用 Svelte 构建功能齐全的应用程序，而无需担心困难部分，我们一直在开发 [SvelteKit](https://kit.svelte.dev/) 应用程序框架。 在已经下载了近一百万次 Sveltekit 的早期采用者的帮助下，我们正在迅速转向 [stable 1.0 release](https://github.com/sveltejs/kit/issues?q=is%3Aopen+is%3Aissue+milestone%3A1.0)。

扩展团队[](#Scaling-the-team)
-----------------------------------

Svelte 去年开始通过 [OpenCollective](https://opencollective.com/svelte) 接受捐款，目前已捐赠超过 60,000 美元，而 [Cohere](https://cohere.ai/) 今天就捐赠了 10,000 美元。 我们希望这些资金将允许现有维护者在 Svelte 上花费更多时间，或者这些资金可以在兼职或合约的基础上支持 Svelte，我们将继续调查。

伙伴关系[](#Partnerships)
-----------------------------

多家主要云供应商正在加紧努力，使 Sveltekit 应用程序在任何地方部署成为无缝体验。 由于 Rich 的新工作，Sveltekit 将很快运行 [Vercel Edge Functions](https://vercel.com/features/edge-functions)。 Netlify 为 sveltekit netlify 适配器制作了 [big contributions](https://github.com/sveltejs/kit/pull/2113) 以及 [updated](https://github.com/dependents/node-precinct/pull/88) 他们的 zip-it-and-ship-it 工具，以更好地支持 sveltekit。 最近的 [Cloudflare Pages launch](https://blog.cloudflare.com/cloudflare-pages-goes-full-stack/) 将 Sveltekit 作为第一天的合作伙伴，通过 Svelte 维护者 [pngwn](https://bsky.app/profile/pngwn.at) 和 [lukeed](https://bsky.app/profile/lukeed.bsky.social) 撰写的 [new adapter](https://github.com/sveltejs/kit/tree/master/packages/adapter-cloudflare) 编写，后者于 2021 年加入 Cloudflare。[Begin](https://begin.com) 为 [Architect](https://arc.codes) 应用程序创建了 [SvelteKit adapter](https://github.com/architect/sveltekit-adapter)。 社区成员有[contributed adapters](https://sveltesociety.dev/packages?category=sveltekit-adapters)，用于 Firebase 和 Deno 等环境，展示了 Sveltekit 无论 JavaScript 都可以在任何地方运行的能力。

我们还与 [Vite](https://vitejs.dev) 团队密切合作，解决 sveltekit 用户发现的 SSR 问题。 Vite 是一种构建工具，可以让 Sveltekit 开发人员体验成为可能，而且由于来自多个框架代表的贡献者的辛勤工作，最近的版本解决了我们作为 Sveltekit 1.0 发布阻止程序所追踪的几乎所有问题。

值得关注的事情[](#Things-to-watch)
---------------------------------

sveltekit 继续朝着 1.0 发展，在过去的一周里，我们添加了 [improved client-only rendering](https://github.com/sveltejs/kit/pull/2804)、[routing hooks](https://github.com/sveltejs/kit/pull/3293) 和 [the ability to pass data from child components to layouts](https://github.com/sveltejs/kit/pull/3252) 等主要功能（例如支持更轻松地管理 `<meta>` 标签）。 我们目前正在开发许多其他高优先级项目，例如讨论流媒体和文件上传等功能的 API 设计，并为即将推出的 Vite 2.8 版本做出贡献。

虽然最近在 Sveltekit 上付出了很多努力，但我们继续推进整个生态系统。 [Svelte 3.46.0](https://github.com/sveltejs/svelte/blob/master/CHANGELOG.md#3460) 是我们一段时间以来最大的版本之一，添加了两个主要的新功能：[constants in markup](https://github.com/sveltejs/rfcs/blob/master/text/0007-markup-constants.md) 和 [style directives](https://github.com/sveltejs/rfcs/blob/master/text/0008-style-directives.md)。

Svelte 和 Sveltekit 的轨迹因上述众多投资而加速，未来将会有更多更新——通过 [RSS](/blog/rss.xml) 订阅 [blog](/blog) 或每月检查以成为第一个获得它们的人。

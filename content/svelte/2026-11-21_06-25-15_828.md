Version 3.0 的 SvelteKit ，Svelte 的官方应用程序框架，现在已经可用。

如果您使用过 SvelteKit 的早期版本，一切都会感觉非常熟悉 —— 它是同一个框架，仅仅是增加了一点润色、一点类型安全性和减少了一点无用代码。我们使用 [`sv migrate`](/docs/cli/sv-migrate) 命令使迁移尽可能顺畅...

```bash
npx sv migrate sveltekit-3 --tasks all --confirm
```

...它将自动迁移尽可能多的代码库，并为其余部分生成一个 TODO 列表。 (如果您倾向于使用代理，您的机器人朋友会很快完成它。)

要创建一个 *新* 的应用程序，请运行 [`sv create`](/docs/cli/sv-create)：

```bash
npx sv create my-new-app
```

与任何主要版本升级一样，有一系列需要注意的破坏性变化，这些变化在 [迁移指南](/docs/kit/migrating-to-sveltekit-3) 中有所介绍（或者，在最近的 [发布候选版本公告](sveltekit-3-release-candidate) 中有更简要的介绍）。

快速亮点：

* 配置现在位于 `vite.config.ts` 而不是 `svelte.config.js`
* `$lib` 别名现在是 `#lib`，使用标准的 [子路径导入](https://nodejs.org/api/packages.html#subpath-imports)
* [环境变量](/docs/kit/environment-variables) 更加强大，易于使用
* [服务工作者](/docs/kit/service-workers) 的样板代码减少
* 整体的错误处理得到改进

## 远程函数是否已经准备就绪？[](#Are-remote-functions-ready-yet)

还不行。但这是我们的首要任务！

[远程函数](/docs/kit/remote-functions) 是一组用于安全、高效、类型安全的客户端-服务器通信的工具。你可能在其他框架中见过类似的想法，但我们认为你会更喜欢这个。

使用它们需要 [Async Svelte](/docs/svelte/await-expressions) ，目前需要一个 `experimental` 标志。请耐心等待。

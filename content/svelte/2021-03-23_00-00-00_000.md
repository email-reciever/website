是时候了。 经过五个月和数百次提交，您终于被邀请尝试 Sveltekit 测试版。 它还没有完成——有一些已知的错误和一些缺失的功能——但我们对它的形成方式非常满意，迫不及待地想让你尝试一下。

    # 安装依赖项

    # 启动开发服务器并打开浏览器选项卡
npm 运行 dev ----open

您可以在 [svelte.dev/docs/kit](/docs/kit) 找到文档。 如果您有一个要迁移到 Sveltekit 的 [Sapper](https://sapper.svelte.dev) 应用程序，您会找到说明 [on GitHub](https://github.com/sveltejs/kit/blob/version-2/documentation/docs/60-appendix/40-migrating.md)。

源代码在 [github.com/sveltejs/kit](https://github.com/sveltejs/kit) 处可用。 当我们完成房屋整理时，问题和拉取请求被禁用，但我们将在不久的将来使其完全开放。

等等，什么是sveltekit？[](#Wait-what-is-SvelteKit)
-----------------------------------------------

将其视为 Svelte 的 [Next](https://nextjs.org/)。 它是一个用于构建应用程序的框架，包括服务器端渲染、路由、JS 和 CSS 的代码拆分、不同服务器平台的适配器等。

如果您熟悉 [Sapper](https://sapper.svelte.dev)，Sveltekit 是 Sapper 的继任者。

从积雪到维特[](#From-Snowpack-to-Vite)
--------------------------------------------

在 [announcement video](/blog/whats-the-deal-with-sveltekit) 之后，我对 [Snowpack](https://www.snowpack.dev/) 表达了抒情的一件事，是 Sveltekit 在引擎盖下使用了 [Vite](https://vitejs.dev)。 当我们开始考虑 Sveltekit 应该采取哪种形式时，当我们尝试 Snowpack 时，这是一见钟情。

Snowpack 创建了一个全新的开发工具类别。 Snowpack 不是 _bundling_ 您的应用程序正在开发中，就像我们过去几年一直在使用 Webpack 和 Rollup 所做的那样，Snowpack 是一个 _unbundled 开发服务器_，它使用浏览器的本机 `import` 并对 svelte 组件等 1:1 进行转换 苍蝇。 因此，您可以快速启动、简单的缓存和即时热模块重新加载。 一旦你经历了这种工作方式，它会毁了你其他任何事情。

Vite 与 Snowpack 属于同一类别。 虽然 Vite 1 不适用于 Sveltekit——它是以 Vue 为中心的（Vite 和 Vue 都由 [Evan You](https://bsky.app/profile/evanyou.me) 创建）并使服务器端渲染变得困难——Vite 2 与框架无关，并以 SSR 为核心设计。 它还具有强大的功能，例如CSS代码分割，我们以前必须自己实现。 当我们并排评估这两种技术时，我们被迫得出结论，Vite 与 Sveltekit 的要求更接近，并将为我们提供最佳机会来传递我们的想象力框架。

我们非常感谢 Snowpack 团队，无论是在开发早期的密切合作，还是为未来几年的 Web 开发所走的道路奠定了基础。 这是一个很棒的工具，你绝对应该尝试一下。

作为极限运动的狗食[](#Dogfooding-as-extreme-sport)
--------------------------------------------------------

Sveltekit 非常处于测试阶段，但这并不意味着它没有被用于生产。

我的日常工作是在《纽约时报》，过去十二个月的大部分时间里，我都在那里花了很多时间来研究我们的 [coronavirus tracker](https://www.nytimes.com/interactive/2020/us/coronavirus-us-cases.html)。 它使用的工作流程的定制版本为当时的大多数图形提供支持，这些图形不是为大型多页项目而设计的。 去年年底，当我们决定为美国约 3,000 个县创建页面时，我们很快意识到我们需要完全重新构建该项目。

尽管它还远未准备好，但 Sveltekit 是唯一符合我们深奥要求的框架。 （任何在新闻编辑室工作并与他们的 CMS 战斗过的人都会知道我在说什么。）今天它为我们的 [county risk pages](https://www.nytimes.com/interactive/2021/us/tom-green-texas-covid-cases.html) 提供了动力，我们正在将现有页面迁移到 sveltekit 应用程序。

使用未完成的软件构建一个会被数百万人看到的应用程序是一种风险，一般我不推荐它。 但它使我们能够更快地开发该应用程序，并且使框架本身比其他情况更强大。

通往1.0[](#The-road-to-1.0)的道路
---------------------------------

您可以在我们的 [issue tracker](https://github.com/sveltejs/kit/issues?q=is%3Aopen+is%3Aissue+milestone%3A1.0) 上看到 1.0 里程碑的未决问题列表。 除此之外，我们计划升级文档并添加更多 [adapters](/docs/kit/adapters)。

最重要的是，我们需要您的反馈来帮助我们制作最好的应用程序框架。 试一试，让我们知道缺少哪些部分。

非常感谢所有尝试 Sveltekit 的人，尽管有“这里是 Dragons”的警告和缺乏文档； 您的反向渠道反馈非常宝贵。 特别是，我想感谢 [GrygrFlzr](https://github.com/GrygrFlzr) 的工作，他们维护了非官方文档和在我们缺少时添加 Windows 支持的分叉； [dominikg](https://github.com/dominikg) 他们在 [Svite](https://github.com/svitejs/svite) 上的工作为 Sveltekit 的 Vite 整合奠定了基本基础。 两人现在都受到了团队的欢迎。

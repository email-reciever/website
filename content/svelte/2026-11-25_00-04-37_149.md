了解你的 SvelteKit 应用程序在生产环境中的行为 —— 从请求流到性能瓶颈 —— 对于构建可靠的用户体验至关重要。SvelteKit 现在具有第一类的可观察性支持：内置的 [OpenTelemetry](https://opentelemetry.io/) 跟踪，并且有一个专用的仪表设置文件，以确保你的监控工具可以无缝地工作。

要选择加入，请升级 SvelteKit 和你的适配器，并将以下内容添加到你的 `svelte.config.js` 中：

svelte.config

```js
export default {
	kit: {
		experimental: {
			tracing: {
				server: true
			},
			instrumentation: {
				server: true
			}
		}
	}
};
```

## 一级 OpenTelemetry 跟踪[](#First-party-OpenTelemetry-traces)

SvelteKit 现在可以发出 [OpenTelemetry](https://opentelemetry.io) 跟踪 для以下内容：

* [`handle`](/docs/kit/hooks#handle) hook (`handle` 函数在一个 [`sequence`](/docs/kit/@sveltejs-kit-hooks#sequence) 中运行，将显示为彼此和根 `handle` hook 的子级)
* [`load`](/docs/kit/load) 函数（包括在服务器上运行的通用 `load` 函数）
* [表单操作](/docs/kit/form-actions)
* [远程函数](/docs/kit/remote-functions)

发出 的跨度包括描述当前请求的属性，例如 `http.route`，以及周围的上下文，例如与 `load` 函数关联的 `+page` 或 `+layout` 文件。如果您认为还有其他可能有用的属性，请在 [SvelteKit GitHub 问题跟踪器](https://github.com/sveltejs/kit/issues) 上提交一个问题。

## 一个方便的仪表化主页[](#一个方便的仪表化主页)

仅发出跟踪是不够的：您还需要收集它们并将它们发送到某个地方。 在正常情况下，这可能有点具有挑战性。 由于可观察性仪表化的性质，它需要在加载应用程序代码之前加载。 为了帮助解决这个问题，SvelteKit 现在支持 `src/instrumentation.server.ts` 文件，假设您的适配器支持它，则保证在应用程序代码之前加载。

在 Node 中，您的仪表化可能看起来像这样：

```ts
import { NodeSDK } from '@opentelemetry/sdk-node';
import { getNodeAutoInstrumentations } from '@opentelemetry/auto-instrumentations-node';
import { OTLPTraceExporter } from '@opentelemetry/exporter-trace-otlp-proto';
import { createAddHookMessageChannel } from 'import-in-the-middle';
import { register } from 'module';

const { registerOptions } = createAddHookMessageChannel();
register('import-in-the-middle/hook.mjs', import.meta.url, registerOptions);

const sdk = new NodeSDK({
	serviceName: 'my-sveltekit-app',
	traceExporter: new OTLPTraceExporter(),
	instrumentations: [getNodeAutoInstrumentations()]
});

sdk.start();
```

如果您部署到 Vercel，它可能看起来像这样：

```ts
import { registerOTel } from '@vercel/otel';

registerOTel({
	serviceName: 'my-sveltekit-app'
});
```

请参阅您的平台文档以获取特定的instrumentation说明。目前，所有官方的SvelteKit适配器（抱歉，`adapter-static`）都支持`instrumentation.server.ts`。

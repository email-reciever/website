Sveltekit 3 来了！ 查看 [announcement post](/blog/sveltekit-3-is-here) 中的亮点，然后运行 [`sv migrate`](/docs/cli/sv-migrate) 为您处理大部分升级。 `sv` 自身在同一天达到 1.0，使社区附加 API 成为官方的。 下面你将找到在 3.0 之前登陆的最后一轮更改 - 适配器 API 更新、零配置部署以渲染和一些最终的突破性更改。

Svelte Summit 也回来了 Svelte 的 10 岁生日！ 它将于 11 月 19 日至 20 日在卢布尔雅那举行，里奇·哈里斯、埃利奥特·约翰逊、保罗·里丘蒂、斯坦尼斯拉夫·赫罗莫夫、PNGWN 等人的会谈。 可在 [sveltesummit.com](https://sveltesummit.com/) 获得亲自和虚拟票证。

Svelte 本身有一个安静的月份 - 5.57.1 是所有错误修复和解析器性能工作。 按照往常，展示中还有很多东西……所以让我们潜入吧！

## Sveltekit 3[](#What's-new-in-SvelteKit-3)中的新功能

*   当添加Vite插件时，Adapters接收svelte配置作为函数参数（**3.0.0-next.27**，[#16986](https://github.com/sveltejs/kit/pull/16986)）
*   适配器可以在`vite dev`和`vite preview`期间覆盖`getRequest`和`setResponse`，因此本地请求的行为更像目标平台（**3.0.0-next.27**、[Docs](/docs/kit/writing-adapters)、[#16753](https://github.com/sveltejs/kit/pull/16753)）
*   Node：静态资产现在从构建时记录的表中代替`sirv`（**adapter-node@6.0.0-next.13**、[Docs](/docs/kit/migrating-to-sveltekit-3#Adapters-adapter-node)、[#16908](https://github.com/sveltejs/kit/pull/16908)）
*   Netlify：`split`和`edge`选项现在可以一起使用（*adapter-netlify@7.0.0-next.12**、[Docs](/docs/kit/adapter-netlify#Options-split)、[#17045](https://github.com/sveltejs/kit/pull/17045)）
*   `adapter-auto` 现在支持零配置部署来渲染 (**adapter-auto@8.0.0-next.4**, [Docs](/docs/kit/adapter-auto), [#16850](https://github.com/sveltejs/kit/pull/16850))
*   `svelte-package`现在将像`#lib`这样的导入别名重写为相对导入，并在`.server.`文件或`server`目录未导入仅限服务器的模块（**package@3.0.0**、[#16360](https://github.com/sveltejs/kit/pull/16360)、[#16266](https://github.com/sveltejs/kit/pull/16266)）时发出警告
*   **最终预发行的突破性变化**
    *   当客户端请求的单次飞行突变刷新未处理时，服务器现在会出错。 使用 `requested` 上的 `ignore()` 或 `ignoreAll()` 跳过刷新（**3.0.0-next.27**、[Docs](/docs/kit/remote-functions#Single-flight-mutations-Client-requested-refreshes)、[#16892](https://github.com/sveltejs/kit/pull/16892)）
    *   环境变量现在在 `instrumentation.server.js` 被评估之前填充，并且适配器 Instrumentation API 已更新为匹配 (**3.0.0-next.27**, [Docs](/docs/kit/migrating-to-sveltekit-3#Adapters-Adapter-API-changes-Server-instrumentation), [#16303](https://github.com/sveltejs/kit/pull/16303))
    *   `builder.generateManifest`已被`builder.generateServerInstance`和`builder.manifest`替换，`Server`构造函数和`SSRManifest`类型不再公开（**3.0.0-next.27**、[Docs](/docs/kit/migrating-to-sveltekit-3#Adapters-Adapter-API-changes)、[#16875](https://github.com/sveltejs/kit/pull/16875)、[#16876](https://github.com/sveltejs/kit/pull/16876)）
    *   以 `x-sveltekit-` 开头的查询参数现在被拒绝 (**3.0.0-next.28**, [#17125](https://github.com/sveltejs/kit/pull/17125))
    *   Cloudflare：`platform` 对象已被移除。 绑定现在来自模拟的 `cloudflare:workers` 模块（**adapter-cloudflare@8.0.0-next.7**、[Docs](/docs/kit/adapter-cloudflare#Runtime-APIs)、[#16754](https://github.com/sveltejs/kit/pull/16754)）
    *   Node：仅提供构建时存在的静态资产，使用 Content-Hash `ETag` 而不是 `Last-Modified` 进行验证，并且它们仅响应 `GET` 和 `HEAD` 请求（**adapter-node@6.0.0-next.13**， [Docs](/docs/kit/migrating-to-sveltekit-3#Adapters-adapter-node)、[#16908](https://github.com/sveltejs/kit/pull/16908)）
    *   Netlify：静态文件现在是基于 `publish` 适配器选项而不是读取 `netlify.toml` 编写的 (**adapter-netlify@7.0.0-next.12**, [Docs](/docs/kit/migrating-to-sveltekit-3#Adapters-adapter-netlify), [#17078](https://github.com/sveltejs/kit/pull/17078))

升级现有应用？ [migration guide](/docs/kit/migrating-to-sveltekit-3) 涵盖了 3.0 中的每个突破变化。 对于发布的所有错误修复，请查看 [SvelteKit / Adapter CHANGELOGs](https://github.com/sveltejs/kit/tree/main/packages)。

## Svelte CLI 和 AI 工具的新功能[](#What's-new-in-the-Svelte-CLI-and-AI-Tools)

*   现在可以使用Node内置的`node:sqlite`模块（**sv@0.17.1**、[Docs](/docs/cli/drizzle#Options-client)、[#1206](https://github.com/sveltejs/cli/pull/1206)）设置sqlite
*   `sv` 1.0 出局！ 新项目使用 sveltekit 3 和 `#lib`，`sv migrate sveltekit-3` 升级现有应用程序 (**sv@1.0.0**, [Docs](/docs/cli/sv-migrate), [#1138](https://github.com/sveltejs/cli/pull/1138))
*   社区附加组件API现在是官方的，`sv create`可以从`addon`模板（**sv@1.0.0**、[Docs](/docs/cli/community)、[#1308](https://github.com/sveltejs/cli/pull/1308)）中搭建一个新的附加组件
*   `@sveltejs/enhanced-img`现在可通过`sv add enhanced-img`（**SV@1.0.0**、[Docs](/docs/cli/enhanced-img)、[#1300](https://github.com/sveltejs/cli/pull/1300)）作为官方附加组件提供
*   Svelte OpenCode 插件现在支持 OpenCode V2 (**OpenCode@0.1.15**, [#258](https://github.com/sveltejs/ai-tools/pull/258))

对于本月 Svelte 5.57.1 的所有错误修复和性能改进，请查看 Svelte 编译器的 [CHANGELOG](https://github.com/sveltejs/svelte/blob/main/packages/svelte/CHANGELOG.md)。 CLI 和 AI 工具更新可以在 [Svelte CLI](https://github.com/sveltejs/cli/releases) 和 [ai-tools](https://github.com/sveltejs/ai-tools/releases) 版本中找到。

_markdown 工具、编辑器和语法突出显示_

*   [Twinkleplop](https://twinkleplop.pngwn.at)是来自PNGWN的令人愉快的语法高亮显示器

*   [aragonite](https://www.aragonite.dev/)是一个不包裹ProSemirror或其他编辑器的svelte的from-scratch markdown编辑器库
*   [svmd](https://github.com/imlargo/svmd) 将 CommonMark Markdown 直接编译到 Svelte 组件源中，因此组件和反应式表达式在 `.md` 文件中工作
*   [Editable 2.0](https://editable.website)现在处于预览状态，允许客户端在没有CMS的苗条网站上直接编辑文本、图像和视频
*   [svedocs](https://svedocs.pwp.sh) 是使用 sveltekit 构建的可定制文档框架

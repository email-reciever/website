所有代码都是错误的。 因此，您需要编写的代码越多，您的应用程序就会越多。

编写更多代码还需要更多时间，更少的时间用于优化、优化功能或户外活动，而不是弯腰在笔记本电脑上。

事实上，[project development time](https://blog.codinghorror.com/diseconomies-of-scale-and-lines-of-code/)和[bug count](https://www.mayerdan.com/ruby/2012/11/11/bugs-per-line-of-code-ratio)随着代码库的大小而非线性增长，这被广泛承认。 这符合我们的直觉：十行拉取请求将获得很少应用于 100 线的审查。 一旦给定的模块变得太大而无法放在单个屏幕上，理解它所需的认知努力就会显着增加。 我们通过重构和添加注释来补偿——几乎总是导致 _more_ 代码的活动。 这是一个恶性循环。

然而，当我们痴迷的时候——正确的！ — 超出性能数字、捆绑包大小以及我们可以测量的任何其他内容，我们很少关注我们编写的代码量。

这种差异是不寻常的_非常明显-根据我的经验，一个React组件通常比其Svelte等价物大40％左右。 让我们看看 Svelte 设计的功能，使您能够更简洁地表达想法：

### 顶级元素[](#Yes-I'm-talking-about-Svelte-Top-level-elements)

在 Svelte 中，组件可以拥有任意数量的顶级元素。 在 React 和 Vue 中，组件必须有一个顶级元素——在 React 的情况下，试图从组件函数返回两个顶级元素会导致语法上的无效代码。 （您可以使用片段 - `<>` - 而不是 `<div>`，但它是相同的基本思想，并且仍然会导致额外的缩进级别）。

在 Vue 中，您的标记必须用 `<template>` 元素包装，我认为这是多余的。

### 绑定[](#Yes-I'm-talking-about-Svelte-Bindings)

在 React 中，我们必须自己响应输入事件：

函数 handleChangeAFunction HandleChangeA(event: any): void(event(parameter) event: any) {
setAany(+event(parameter) 事件：any.targetany.valueAny);
}

这不仅仅是无聊的管道，会占用屏幕上的额外空间，它也是虫子的额外表面区域。 从概念上讲，输入的值与 `a` 的值绑定，反之亦然，但这种关系并没有得到清晰的表达——相反，我们有两个紧密耦合但物理上分离的代码块（事件处理程序和 `value={a}` 道具）。 不仅如此，我们还要记住用 `+` 运算符强制字符串值，否则 `2 + 2` 将等于 `22` 而不是 `4`。

与 Svelte 一样，Vue 确实有一种表达绑定的方式——`v-model` 属性，尽管我们必须小心使用 `v-model.number`，即使它是一个数字输入。

锅炉板死亡[](#Death-to-boilerplate)
-------------------------------------------

这些只是 Svelte 帮助您以最少的大惊小怪构建用户界面的一些方式。 还有很多其他的——例如，反应式声明（`$:` 语句）本质上是在没有样板的情况下完成 React 的 `useMemo`、`useCallback` 和 `useEffect` 的工作（或者实际上是在每个状态更改中创建内联函数和数组的垃圾收集开销）。

怎么？ 通过选择一组不同的约束。 因为 [Svelte is a compiler](/blog/frameworks-without-the-framework)，我们不受 JavaScript 的特殊性的约束：我们可以_设计_一个组件创作体验，而不必将其与语言的语义相适应。 矛盾的是，这会导致 _more_ 惯用代码——例如自然地使用变量而不是通过代理或钩子——同时提供更高性能的应用程序。

经过数月的时间，我们即将发布 Svelte 3 的稳定版本。这是一个巨大的版本，代表了 Svelte 社区中许多人的数百小时工作，包括来自 Beta 测试人员的宝贵反馈，他们帮助塑造了设计的每一步 方式。

我们认为你会爱上它。

什么是svelte？[](#What-is-Svelte)
---------------------------------

Svelte 是一个组件框架——就像 React 或 Vue 一样——但有重要的区别。 传统框架允许您编写 _declarative_ 状态驱动的代码，但有一个惩罚：浏览器必须做额外的工作来将这些声明性结构转换为 DOM 操作，使用 [virtual DOM diffing](/blog/virtual-dom-is-pure-overhead) 之类的技术，这些技术会消耗你的框架预算并对垃圾收集器征税。

相反，Svelte 在 _build time_ 运行，将您的组件转换为高效的 _imperative_ 代码，以便通过手术更新 DOM。 因此，您可以编写具有出色性能特征的雄心勃勃的应用程序。

Svelte 的第一个版本是关于 [testing a hypothesis](/blog/frameworks-without-the-framework) 的——专门构建的编译器可以生成坚如磐石的代码，提供出色的用户体验。 第二个是一个小的升级，让事情变得更加整洁。

版本 3 是一次重大改革。 在过去的五六个月里，我们的重点一直是提供出色的 _Developer_ 体验。 现在可以用 [significantly less boilerplate](/blog/write-less-code) 编写组件而不是其他地方。 尝试全新的 [tutorial](/tutorial) 并了解我们的意思——如果您熟悉其他框架，我们认为您会感到惊喜。

为了使这成为可能，我们首先需要重新思考现代 UI 框架核心的概念：反应性。

来自[You Gotta Love Frontend Code Camp](https://www.israel.yglfconf.com/)的“重新思考反应”

将反应性移入语言[](#Moving-reactivity-into-the-language)
----------------------------------- ------------------------------------

在旧的svelte中，你会通过调用 `this.set` 方法告诉计算机某些状态发生了变化：

const { countconst 计数：任何 } = this.stateany;
this.setStateAny({

有一些重要的技术差异（正如我在上面的视频中解释的那样，React 不是反应式的），但从概念上讲它是一样的。

这一切都随着 [hooks](https://reactjs.org/docs/hooks-intro.html) 的出现而改变，它以非常不同的方式处理状态。 许多框架开始尝试自己的钩子实现，但我们很快得出结论，这不是我们想要进入的方向。钩子有一些有趣的属性，但它们也涉及一些不自然的代码，并为垃圾收集器创造了不必要的工作。 对于 [embedded devices](https://mobile.twitter.com/sveltejs/status/1088500539640418304) 中使用的框架以及动画繁重的交互式框架，这并不好。

所以我们退后一步，问自己什么样的 API 对我们有用……并意识到最好的 API 根本不是 API。 我们可以_使用语言_。 更新一些 `count` 值——以及所有依赖它的东西——应该像这样简单：

countlet 计数：数字 += 1；

由于我们是编译器，我们可以通过在幕后对作业进行检测：

countlet 计数：数字 += 1；
$$invalidateconst $$invalidate: <number>(name: string, value: number) => undefined('count', countlet count: number);

重要的是，我们可以在没有使用代理或访问器的开销和复杂性的情况下完成所有这些操作。 它只是一个变量。

新面貌[](#New-look)
----------------------

您的组件并不是唯一能进行整容的事情。 Svelte 本身具有全新的外观和感觉，这要归功于 [Achim Vedam](https://vedam.de/) 的惊人设计作品，他们创建了我们的新徽标和网站，该网站已从 [svelte.technology](https://svelte.technology) 转移到 svelte.dev。

我们还改变了标语，从“神奇的消失 UI 框架”到“网络增强的 Web 应用程序”。 Svelte 有很多方面——出色的性能、小捆绑包、可访问性、内置样式封装、声明式转换、易用性、它是编译器的事实等——专注于其中任何一个都感觉像是对其他人的不公正。 “网络增强”旨在唤起 Svelte 的总体理念，即我们的工具应该作为我们自己的智能扩展——希望有一个复古的、威廉·吉布森式的扭曲。

从版本 2[](#Upgrading-from-version-2) 升级
-------------------------------------------------

如果您是现有的 Svelte 2 用户，恐怕会涉及一些手动升级。 在接下来的几天里，我们将发布迁移指南和 [svelte-upgrade](https://github.com/sveltejs/svelte-upgrade) 的更新版本，这将尽其所能自动化流程，但这_是一个重大的变化，并非所有事情都可以自动处理。

我们不会掉以轻心：希望一旦您体验过 Svelte 3，您就会明白为什么我们认为有必要与过去决裂。

仍在[](#Still-to-come)
------------------------------

尽管这个版本很累，但我们还远未完成。 我们有大量的想法来生成更智能、更紧凑的代码和一个长功能愿望清单。 [Sapper](https://sapper.svelte.dev)，我们的 next.js 风格的应用程序框架仍处于更新中以使用 svelte 3 的过程中。[Svelte Native](https://svelte-native.technology/) 社区项目允许您在 Svelte 中编写 Android 和 iOS 应用程序，正在取得稳固的进展，但应该得到 Core 更全面的支持。 我们还没有其他框架拥有的大量编辑器扩展、语法高亮器、组件套件、开发工具等，我们应该解决这个问题。 我们 _really_ 想要添加一流的 TypeScript 支持。

但与此同时，我们认为 Svelte 3 是构建 Web 应用程序的最佳方式。 花一个小时的时间来阅读 [tutorial](/tutorial)，我们希望说服你。 无论哪种方式，我们都希望在我们的 [Discord chatroom](/chat) 和 [GitHub](https://github.com/sveltejs/svelte) 中见到您——欢迎所有人，尤其是您。

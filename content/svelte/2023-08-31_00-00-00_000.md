[view transitions API](https://developer.chrome.com/docs/web-platform/view-transitions/) 最近一直在席卷 Web 开发世界，这是有充分理由的。 它简化了在两个页面状态之间进行动画处理的过程，这对页面转换特别有用。

但是，直到现在，您无法在 Sveltekit 应用程序中轻松使用此 API，因为在导航生命周期中很难进入正确的位置。 Sveltekit 1.24 带来了一个新的 [`onNavigate`](/docs/kit/$app-navigation#onnavigate) 生命周期钩子，使视图过渡集成更容易 - 让我们深入了解。

视图转换的工作原理[](#How-view-transitions-work)
---------------------------------------------------

您可以通过调用 `document.startViewTransition` 并传递以某种方式更新 DOM 的回调来触发视图转换。 为了我们今天的目的，Sveltekit 将在用户导航时更新 DOM。 回调完成后，浏览器将过渡到新页面状态——默认情况下，它会在旧状态和新状态之间进行交叉淡入淡出。

在幕后，浏览器做了一些非常聪明的事情。 过渡开始时，它会捕获页面的当前状态并截取屏幕截图。 然后，当 DOM 更新时，它将屏幕截图固定到位。 一旦 DOM 完成更新，它就会捕获新状态，并在两个状态之间进行动画处理。

虽然它目前仅在 Chrome（和其他基于 Chromium 的浏览器）中实现，但它的 [WebKit is also in favor](https://github.com/WebKit/standards-positions/issues/48#issuecomment-1679760489)。 即使您在不受支持的浏览器上，它也是渐进增强的完美选择，因为我们总是可以回退到非动画导航。

需要注意的是，View Transitions 是一种浏览器 API，而不是 Sveltekit 的 API。 `onNavigate` 是我们今天将使用的唯一特定于 Sveltekit 的 API。 无论您为网络写作，其他一切都可以使用！ 有关 View Transitions API 的更多信息，我强烈推荐 Jake Archibald 的 [Chrome explainer](https://developer.chrome.com/docs/web-platform/view-transitions/)。

OnNavigate 的工作原理[](#How-onNavigate-works)
-------------------------------------------

在学习如何编写视图转换之前，让我们突出显示使这一切成为可能的函数：[`onNavigate`](/docs/kit/$app-navigation#onnavigate)。

直到最近，sveltekit 有两个导航生命周期函数：[`beforeNavigate`](/docs/kit/$app-navigation#beforeNavigate)，它在导航开始之前触发，以及 [`afterNavigate`](/docs/kit/$app-navigation#afternavigate)，在导航后更新页面后触发。 Sveltekit 1.24 引入了第三个：`onNavigate`，它将在新页面呈现之前对每个导航进行触发。 重要的是，它将运行 _after_ 页面的任何数据加载都已完成 - 由于开始视图转换阻止了与页面的任何交互，我们希望尽可能晚地启动它。

您还可以从 `onNavigate` 返回一个 Promise，它将暂停导航直到它解决。 这将让我们等待完成导航，直到视图过渡开始。

> 代码的工作原理
> 
> 此代码可能看起来有点吓人-如果您好奇，我可以逐行分解它，但现在知道添加它将允许您在导航期间与View Transitions API进行交互就足够了。
> 
> 如上所述，`onNavigate` 回调将在导航后立即呈现新页面之前运行。 在回调中，我们检查 `document.startViewTransition` 是否存在。 如果它不支持（即浏览器不支持），我们会提前退出。

> 在 Promise 构造函数中，我们开始视图转换。 在视图转换回调中，我们解决了刚刚返回的 Promise，这表明它应该完成导航。 重要的是导航要等到 > _after_ 开始查看过渡 - 浏览器需要对旧状态进行快照，以便它可以过渡到新状态。

> 这有点令人耳目一新，但通过不抽象，我们允许您直接与视图过渡进行交互并进行所需的任何自定义。

:root::view-transition-old(root) {
动画：
90ms 立方贝塞尔(0.4, 0, 1, 1) 都淡出，
300ms 立方贝塞尔（0.4、0、0.2、1）滑到左；
}
    
:root::view-transition-new(root) {
动画：
210ms 立方贝塞尔(0, 0, 0.2, 1) 90ms 都淡入，
300ms 立方贝塞尔（0.4、0、0.2、1）从右滑动；
}

现在，当您在页面之间导航时，旧页面将淡出并向左滑动，新页面将淡入并从右侧滑动。 这些特殊的动画样式来自 Jake Archibald 的优秀 [Chrome Developers article on view transitions](https://developer.chrome.com/docs/web-platform/view-transitions/)，如果您想了解使用此 API 可以做的所有事情，这非常值得一读。

请注意，我们必须在 `::view-transition` 伪元素之前添加 `:root` - 这些元素仅在文档的根目录上，因此我们不希望 svelte 到组件中的 [scope them](/docs/svelte-components#style)。

您可能已经注意到整个页面滑入和滑出，即使标题在旧页面上都是相同的。 为了使过渡更顺畅，我们可以给标题一个唯一的 `view-transition-name`，以便它与页面的其余部分分开进行动画处理。 在 `src/routes/Header.svelte` 中，在样式块中找到 `header` CSS 选择器并添加视图转换名称。

标题{
显示：弹性；
justify-content：空间之间；
view-transition-name：标题；
}

现在，标题不会在导航中进出，但页面的其余部分会。

过渡单个元素[](#Transitioning-individual-elements)
-------------------------------------------------------------------

我们刚刚看到给元素一个 `view-transition-name` 是如何将其与页面的其余动画分开的。 设置 `view-transition-name` 还指示浏览器在转换完成后平滑地将其设置为新位置。 `view-transition-name` 充当唯一标识符，因此浏览器可以从新旧状态中识别匹配元素。

让我们看看它是什么样的——我们的演示应用程序的导航有一个小三角形，指示活动页面。 现在，它在我们导航后突然出现在新位置。 让我们给它一个 `view-transition-name`，以便浏览器将其设置为新位置。

在 `src/routes/Header.svelte` 中，找到创建活动页面指示器的 CSS 规则并给它一个 `view-transition-name`：

li[aria-current='page']::before {
/* 其他现有规则 */
view-transition-name：活动页面；
}

通过添加单行，指示器现在将平滑滑动到新位置而不是跳跃。

减少运动[](#Reduced-motion)
--------------------------------

在网络上实现动画时，尊重用户的 [motion preferences](https://web.dev/prefers-reduced-motion/) 非常重要。 仅仅因为你可以实现一个极端的页面过渡并不意味着你应该这样做。 要禁用喜欢缩小运动的用户的所有页面转换，您可以将以下内容添加到全局 `styles.css`：

@media（首选-reduced-motion）{
::view-transition-group(*),
::view-transition-old(*),
::view-transition-new(*) {
动画：无！重要；
}
}

虽然这可能是最安全的选择，但减少运动并不一定意味着没有动画。 相反，您可以根据具体情况考虑您的视图转换。 例如，也许我们禁用了滑动动画，但保留了默认的交叉渐变（不涉及运动）。 您可以通过在 `prefers-reduced-motion: no-preference` 媒体查询中包装要禁用的 `::view-transition` 规则来做到这一点：

@media（首选-reduced-motion：无偏好）{
:root::view-transition-old(root) {
动画：
90ms 立方贝塞尔(0.4, 0, 1, 1) 都淡出，
300ms 立方贝塞尔（0.4、0、0.2、1）滑到左；
}
    
:root::view-transition-new(root) {
动画：
210ms 立方贝塞尔(0, 0, 0.2, 1) 90ms 都淡入，
300ms 立方贝塞尔（0.4、0、0.2、1）从右滑动；
}
}

下一步是什么？[](#What's-next)
-----------------------------

如您所见，Sveltekit 并没有对 _how_view 转换工作进行大量抽象——您直接与浏览器的内置 `document.startViewTransition` 和 `::view-transition` API 交互，而不是像 Nuxt 和 Astro 中的框架抽象。 我们很想知道人们如何最终在 Sveltekit 应用程序中使用视图转换，以及在未来添加我们自己的更高级别的抽象是否有意义。

通过在 Sveltekit 应用程序中添加类型注释，您可以通过网络获得完整的类型安全性——页面中的 `data` 具有从生成该数据的 `load` 函数的返回值推断的类型，而无需显式声明任何内容。 这是你开始想知道你是如何生活的事情之一。

但是，如果我们甚至不需要注释怎么办？ 由于 `load` 和 `data` 是框架的一部分，框架不能为我们键入它们吗？ 毕竟，这就是计算机的用途——做无聊的部分，这样我们就可以专注于创造性的东西。

截至今天，是的：可以。

如果您使用的是 VSCode，只需将 Svelte 扩展升级到最新版本，您就不必再次注释您的 `load` 函数或 `data` 道具。 其他编辑器的扩展也可以使用此功能，只要它们支持语言服务器协议和 TypeScript 插件。 它甚至适用于我们的 CLI 诊断工具的最新版本 `svelte-check`！

在我们深入研究之前，让我们回顾一下 Sveltekit 中类型安全的工作原理。

无类型安全类型[](#Type-safety-without-types)
---------------------------------------------------

得益于自动类型生成，我们获得了先进的类型安全性。 如果我们可以完全省略编写类型，那不是很好吗？ 到今天为止，您可以做到这一点：

src/routes/blog/\[slug\]/+page.server

从 './$types' 导入类型 { PageServerLoadEvent };
    
导出异步函数 loadFunction load(event: any): Promise<{
帖子：字符串；
}>(event(parameter) event: any: PageServerLoadEvent) {
返回{

}.getPost(method) getPost(slug: string | undefined): Promise<string>(event(parameter) event: any.paramsany.postany)

src/routes/blog/\[slug\]/+page

    <script lang="ts">
从 './$types' 导入类型 { pageData };
导出让数据：PageData；
导出出租数据；
    </script>

虽然这非常方便，但这不仅仅是关于此。 这也是关于_correctness_：在复制和粘贴代码时，很容易意外地将`PageServerLoadEvent`与`LayoutServerLoadEvent`或`PageLoadEvent`混为一谈——具有细微差别的类似类型。 Svelte 的主要见解是，通过以声明性的方式编写代码，我们可以让机器正确有效地为我们完成大部分工作。 这没有什么不同——通过利用 `+page` 文件等强大的框架约定，我们可以更容易地做正确的事情而不是做错误的事情。

这适用于 Sveltekit 文件（`+page`、`+layout`、`+server`、`hooks`、`params` 等）的所有导出，以及 `+page/layout.svelte` 文件中的 `data`、`form` 和 `snapshot` 属性。

要将此功能与 VS Code 结合使用，请安装最新版本的 Svelte for VS Code 扩展。 对于其他 IDE，使用最新版本的 Svelte 语言服务器和 Svelte TypeScript 插件。 除了编辑器之外，我们的命令行工具 `svelte-check` 也知道如何从 3.1.1 版本开始添加这些注释。

它是如何工作的？[](#How-does-it-work)
------------------------------------

使它工作需要对语言服务器（为 svelte 文件中的 IntelliSense 提供支持）和 TypeScript 插件（使 TypeScript 理解 `.ts/js` 文件中的 svelte 文件）的更改。 在这两种情况下，我们在正确的位置自动插入正确的类型，并告诉 TypeScript 使用我们的虚拟增强文件而不是原始的未键入文件。 与来回映射生成的和原始位置相结合会产生所需的结果。 由于 `svelte-check` 重用了引擎盖下的部分语言服务器，因此无需进一步调整即可免费获得该功能。

我们要感谢 Next.js 团队的 [inspiring](https://twitter.com/shuding_/status/1625263297573400578) 这项功能。

下一步是什么[](#What's-next)
----------------------------

对于未来，我们希望考虑使更多的 sveltekit 类型安全区域——例如，无论是在您的 HTML 中还是通过以编程方式调用 `goto`。

TypeScript 正在吃 JavaScript 世界——我们在这里为它！ 我们非常关心 Sveltekit 中的一流类型安全性，我们为您提供了使体验尽可能流畅的工具——一种也可以完美地扩展到更大的苗条代码库——无论您是使用 TypeScript 还是通过 JSDoc 键入的 JavaScript。

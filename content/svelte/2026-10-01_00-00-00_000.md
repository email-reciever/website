Version 3.0 的 SvelteKit，Svelte 的官方应用框架，现已推出。

如果您曾使用过 SvelteKit 的早期版本，一切都会感觉非常熟悉 —— 它是同一个框架，仅仅是更加精致了一些，类型安全性更强了一些，废弃代码也更少了一些。我们已经尽可能地使迁移过程变得无缝，以 [`sv migrate`](/docs/cli/sv-migrate) 命令...

```bash
npx sv migrate sveltekit-3 --tasks all --confirm
```

...来自动迁移代码库中尽可能多的部分，并为其余部分生成一个待办事项清单。（如果您倾向于使用自动化工具，您的机器人朋友会很快完成这项工作。）

要创建一个 *新* 的应用，请运行 [`sv create`](/docs/cli/sv-create)：

```bash
npx sv create my-new-app
```

与任何主要版本升级一样，有几个需要注意的破坏性变更，这些变更在 [迁移指南](/docs/kit/migrating-to-sveltekit-3) 中有所介绍（或者，在最近的 [发布候选版本公告](sveltekit-3-release-candidate) 中有更简短的介绍）。

快速亮点：

* 配置现在位于 `vite.config.ts` 而不是 `svelte.config.js`
* `$lib` 别名现在是 `#lib`，使用标准的 [子路径导入](https://nodejs.org/api/packages.html#subpath-imports)
* [环境变量](/docs/kit/environment-variables) 更加强大，使用也更加简单
* [服务工作者](/docs/kit/service-workers) 现在需要的样板代码更少
* 整体的错误处理得到了改进

## 远程函数已经准备好了吗？[](#Are-remote-functions-ready-yet)

还没有。但这是我们的首要任务！

[远程函数](/docs/kit/remote-functions) 是一套用于安全、效率、类型安全的客户端-服务器通信的工具。你可能已经在其他框架中看到过类似的想法，但我们认为你会更喜欢这个。

使用它们需要 [Async Svelte](/docs/svelte/await-expressions) ，目前需要一个 `experimental` 标志。请耐心等待。

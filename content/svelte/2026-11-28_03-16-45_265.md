经过几个月的等待，我们非常高兴地宣布 Svelte 3 的稳定版本发布。这是一个巨大的版本，代表了 Svelte 社区中许多人数百个小时的工作，包括来自 beta 测试者的宝贵反馈，他们在每一步都帮助塑造了设计。

我们认为您会喜欢它。

## 什么是 Svelte？[](#What-is-Svelte)

Svelte 是一个组件框架 —— 与 React 或 Vue 类似 —— 但它有一个重要的区别。传统的框架允许您编写 *声明式* 状态驱动的代码，但这有一定的代价：浏览器必须进行额外的工作来将这些声明式结构转换为 DOM 操作，使用诸如 [虚拟 DOM diffing](/blog/virtual-dom-is-pure-overhead) 的技术，这会消耗您的帧预算并给垃圾收集器带来负担。

相反，Svelte 在 *构建时* 运行，将您的组件转换为高效的 *命令式* 代码，该代码可以精确地更新 DOM。因此，您可以编写具有优秀性能特性的雄心勃勃的应用程序。

Svelte 的第一个版本主要是关于 [测试一个假设](/blog/frameworks-without-the-framework) —— 一个为特定目的而设计的编译器可以生成非常稳固的代码，提供出色的用户体验。第二个版本是一个小升级，稍微整理了一下。

版本 3 是一个重大改版。在过去的五六个月里，我们的重点是提供出色的 *开发者* 体验。现在，写组件所需的 [样板代码](/blog/write-less-code) 比其他地方少得多。尝试全新的 [教程](/tutorial) ，看看我们是什么意思 —— 如果您熟悉其他框架，我们认为您会感到愉快地惊讶。

为了实现这一点，我们首先需要重新思考现代 UI 框架的核心概念：响应性。

'重新思考响应性'来自 [You Gotta Love Frontend Code Camp](https://www.israel.yglfconf.com/)

## 将响应性融入语言[](#Moving-reactivity-into-the-language)

在旧的 Svelte 中，您需要通过调用 `this.set` 方法告诉计算机某些状态已经改变：

```js
const { count } = this.get();
this.set({
	count: count + 1
});
```

那会导致组件 *react*。说到这，`this.set` 几乎与经典（pre-hooks）React 中使用的 `this.setState` 方法相同：

```js
const { count } = this.state;
this.setState({
	count: count + 1
});
```

有一些重要的技术差异（如我在上面的视频中解释的，React 并不是响应式的）但概念上它们是相同的。

实际上，Svelte 3 基本上是 [Sunil 的责任](https://twitter.com/threepointone/status/1057179801109311488)。

但随着 [hooks](https://reactjs.org/docs/hooks-intro.html) 的出现，一切都改变了，hooks 以非常不同的方式处理状态。许多框架开始尝试使用自己的 hooks 实现，但我们很快得出结论这并不是我们想要的方向。Hooks 有一些有趣的属性，但它们也涉及一些不自然的代码，并为垃圾回收器创建了不必要的工作。对于一个既用于 [嵌入式设备](https://mobile.twitter.com/sveltejs/status/1088500539640418304) ，又用于动画密集交互的框架来说，这不是好事。

于是，我们退一步，问自己什么样的 API 会适合我们... 并意识到最好的 API 其实是没有 API。我们可以直接 *使用语言*。更新某个 `count` 值 —— 以及所有依赖于它的东西 —— 应该像这样简单：

```ts
count += 1;
```

由于我们是一个编译器，我们可以通过在幕后注入赋值来实现这一点：

```ts
count += 1;
$$invalidate('count', count);
```

重要的是，我们可以在不使用代理或访问器的开销和复杂性的情况下做到这一点。这只是一个变量。

## 新外观[](#New-look)

您的组件并不是唯一一个获得改进的东西。Svelte 本身也有了完全新的外观和感觉，感谢 [Achim Vedam](https://vedam.de/) 的出色设计工作，他创建了我们的新标志和网站，网站从 [svelte.technology](https://svelte.technology) 移动到了 svelte.dev。

我们还改变了我们的标语，从‘The magical disappearing UI framework’改为‘Cybernetically enhanced web apps’。Svelte有很多方面——出色的性能，小的包，易用性，内置的样式封装，声明式的过渡，易用性，它是一个编译器等——专注于任何一个方面都感觉像是对其他方面的不公平。‘Cybernetically enhanced’的设计是唤起Svelte的整体哲学，即我们的工具应该作为我们自身的智能扩展——希望带有一个复古的，威廉·吉布森式的转折。

## 从版本2升级[](#Upgrading-from-version-2)

如果你是现有的Svelte 2用户，我担心升级将需要一些手动操作。在接下来的日子里，我们将发布一个迁移指南和[svelte-upgrade](https://github.com/sveltejs/svelte-upgrade)的更新版本，它将尽力自动化升级过程，但这是一个重大的变化，并不是所有事情都可以自动处理。

我们不会轻视这一点：希望一旦你体验了Svelte 3，你就会理解为什么我们觉得有必要打破过去的局限。

## 尚待实现[](#Still-to-come)

尽管这个版本的发布过程非常艰苦，但我们还远远没有完成。我们有很多想法来生成更智能、更紧凑的代码，并且有一个长长的功能愿望清单。[Sapper](https://sapper.svelte.dev)，我们的 Next.js 风格的应用框架，仍然在被更新以使用 Svelte 3 的过程中。[Svelte Native](https://svelte-native.technology/) 社区项目，使你能够使用 Svelte 编写 Android 和 iOS 应用，正在取得良好的进展，但它理应得到核心的更完整的支持。我们还没有其他框架拥有的丰富的编辑器扩展、语法高亮器、组件套件、开发工具等，我们应该改善这一点。我们 *非常* 想要添加一流的 TypeScript 支持。

但是在此期间，我们认为 Svelte 3 是迄今为止构建 web 应用的最佳方式。花一个小时去完成 [tutorial](/tutorial)，我们希望能说服你同意我们的观点。无论如何，我们很乐意在我们的 [Discord chatroom](/chat) 和 [GitHub](https://github.com/sveltejs/svelte) 上见到你 — 每个人都受欢迎，尤其是你。

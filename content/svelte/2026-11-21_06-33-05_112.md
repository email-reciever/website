本月，Svelte 5.57 推出了新的 `SvelteMap` 方法和一些生活质量添加物，而 Sveltekit 3 则更接近于其发布候选者的终点线。

`sv` CLI 还获得了一个新的 `ai-tools` 附加组件，它取代了旧的 `mcp` 之一，`sv@next` 现在为现有应用程序提供了基于任务的 `sveltekit-3` 迁移。

让我们深入一点！

## Svelte的新功能[](#What's-new-in-Svelte)

*   `SvelteMap` 现在有 `getOrInsert` 和 `getOrInsertComputed` 常用“读取或初始化”模式的方法（**5.57.0**、[Docs](/docs/svelte/svelte-reactivity#SvelteMap)、[#18728](https://github.com/sveltejs/svelte/pull/18728)）
*   `createContext` 现在返回第三个 `has` 函数，因此您可以检查是否设置了上下文而不触发 `get` 错误 (**5.57.0**, [Docs](/docs/svelte/context), [#18472](https://github.com/sveltejs/svelte/pull/18472))
*   `<select>` 现在支持 `defaultValue` 属性，因此 select 在表单重置时恢复到该值 (**5.57.0**, [#18591](https://github.com/sveltejs/svelte/pull/18591))
*   `svelte/server` 现在导出用于键入服务器渲染输出和 CSP 源的 `RenderOutput`、`SyncRenderOutput`、`Csp` 和 `Sha256Source` 类型（**5.57.0**、[#18648](https://github.com/sveltejs/svelte/pull/18648)）

有关修补程序和错误修复的完整列表，请参阅 svelte [CHANGELOG](https://github.com/sveltejs/svelte/blob/main/packages/svelte/CHANGELOG.md)。

## Sveltekit 3 的 RC[](#What's-new-in-SvelteKit-3's-RC) 中的新功能

本月预发行版一直在 `@next` 线上滚动，添加了更多功能并完善了表面：

*   增强的跨页表单操作现在导航到成功和失败的操作页面，匹配本机表单行为（**3.0.0-next.17**, breaking, [#16684](https://github.com/sveltejs/kit/pull/16684)）
*    Adapter Vite 插件现在可以分成 `pre` 和 `post` 组，因此适配器可以在管道中的正确点运行转换（**3.0.0-next.18**、breaking、[#16711](https://github.com/sveltejs/kit/pull/16711)）
*   如果名称包含 `test`、`spec` 或 `stories`，则在路由期间将忽略带有 `+` 前缀的文件，因此共定位测试不会意外成为路由 (**3.0.0-next.19**, [#16715](https://github.com/sveltejs/kit/pull/16715))
*   开发-服务器响应日志现在更好地阅读和通过Vite的记录器进行路由，因此它尊重`logLevel`和`customLogger`（**3.0.0-next.20/25**，[#16744](https://github.com/sveltejs/kit/pull/16744)，[#16858](https://github.com/sveltejs/kit/pull/16858)）
*   `defineParams` 和相关类型已移动到 `@sveltejs/kit/params` (**3.0.0-next.19**, breaking, [#16716](https://github.com/sveltejs/kit/pull/16716))
*   `+server.js` 文件现在可以导出 `QUERY` HTTP 方法处理程序 (**3.0.0-next.24**, [#16782](https://github.com/sveltejs/kit/pull/16782))
*   字体的 `preload` 过滤器现在接收到项目相对源 `filename`，因此您可以按目录或组件进行过滤 (**3.0.0-next.24**, [#16443](https://github.com/sveltejs/kit/pull/16443))
*   Adapters 可以调用新的 `applyReroute` Helper for split serverless function 部署 (**3.0.0-next.25**, [#16665](https://github.com/sveltejs/kit/pull/16665))

与此同时，所有的 Sveltekit 3 文档都存在于 [next.svelte.dev](https://next.svelte.dev/docs/kit/migrating-to-sveltekit-3) 上，并且完整的更改日志都在 [version-3 branch](https://github.com/sveltejs/kit/blob/version-3/packages/kit/CHANGELOG.md) 上。 稳定的 2.x 线也继续移动，三个补丁版本（**2.70.1**、**2.70.2**、**2.70.3**） - 有关详细信息，请参见 [SvelteKit CHANGELOGs](https://github.com/sveltejs/kit/tree/main/packages)。

## Svelte CLI 和语言工具中的新功能[](#What's-new-in-the-Svelte-CLI-and-Language-Tools)

*    `mcp` 插件已被更广泛的 `ai-tools` 附加组件替换，可以为每个客户端设置 svelte 插件（克劳德代码，OpenCode）或选择单个工具（MCP 服务器、技能、子代理） （**SV@0.17.0**、[Docs](/docs/cli/ai-tools)、[#1050](https://github.com/sveltejs/cli/pull/1050)）
*   `@sveltejs/sv-utils` 拾取 `isKit3`、`resolveLibPrefix` 和 `libSubpathImports` 助手，以便附加组件可以透明地处理 sveltekit 2 和 3 (**sv-utils@0.3.3**, [#1199](https://github.com/sveltejs/cli/pull/1199))
*   `sv migrate` 已经重新设计了 Sveltekit 3 迁移的准备工作 - 它现在列出了任务，将 `sveltekit-3` 任务提升到 `$lib` 并将 `$lib` 重写为 `#lib`，添加了 `$app/state` 任务，委派了较旧的迁移 到 `svelte-migrate@1`，并创建开发人员或代理无法自动迁移时应解决的更改列表（**sv@1.0.0-next.0**、[Docs](/docs/cli/sv-migrate)、[#1138](https://github.com/sveltejs/cli/pull/1138)、[#1241](https://github.com/sveltejs/cli/pull/1241)、[#1249](https://github.com/sveltejs/cli/pull/1249)）
*   新创建的项目使用 `#lib`（节点子路径导入）代替 `$lib`，匹配 sveltekit 3 (**sv@1.0.0-next.0**, [#1185](https://github.com/sveltejs/cli/pull/1185))
*   社区附加组件不再需要范围内的包名（**sv@1.0.0-next.4**、[#1216](https://github.com/sveltejs/cli/pull/1216)）
*   现在的`experimental`附加组件的范围是启用实验性的功能，`versions`选项值被重命名为`kit-3`(**sv@1.0.0-next.0**, breaking, [#1241](https://github.com/sveltejs/cli/pull/1241), [#1185](https://github.com/sveltejs/cli/pull/1185))
*   Vite Plugin 获取当前 Vite 环境的 `dynamicCompileOptions` 参数，当您想要针对客户端、服务器或 SSR 环境进行不同编译时很有用 (**vite-plugin-svelte@7.3.0**, [#1386](https://github.com/sveltejs/vite-plugin-svelte/pull/1386))
*   `svelte2tsx`和`svelte-check`了解Sveltekit 3的扁平化配置结构，因此类型生成和诊断继续通过迁移工作 （**svelte-check@4.7.6/svelte2tsx@0.7.61/svelte-language-server@0.18.4**、[#3104](https://github.com/sveltejs/language-tools/pull/3104)、[#3106](https://github.com/sveltejs/language-tools/pull/3106)）

想深入潜水吗？ 查看 [Svelte CLI](https://github.com/sveltejs/cli/releases)、[language-tools](https://github.com/sveltejs/language-tools/releases) 和 [ai-tools](https://github.com/sveltejs/ai-tools/releases) 版本。

SvelteKit 3 已经来了！查看 [公告帖子](/blog/sveltekit-3-is-here) 以了解亮点，然后运行 [`sv migrate`](/docs/cli/sv-migrate) 来处理大部分升级工作。同一天，`sv` 本身也达到了 1.0 版本，使社区插件 API 成为官方 API。下面您将找到在 3.0 版本发布之前的最后一轮更改，包括适配器 API 更新、零配置部署到 Render 以及一些最终的破坏性更改。

Svelte Summit 也回来了，为了庆祝 Svelte 的 10 岁生日！它将于 11 月 19-20 日在卢布尔雅那举行，Rich Harris、Elliott Johnson、Paolo Ricciuti、Stanislav Khromov、pngwn 等人将进行演讲。现场和虚拟门票可以在 [sveltesummit.com](https://sveltesummit.com/) 购买。

Svelte 本身这个月相对安静 - 5.57.1 版本仅包含 bug 修复和解析器性能优化工作。如往常一样，展示中仍然有很多内容... 所以让我们开始探索！

## SvelteKit 3 中的新功能[](#What's-new-in-SvelteKit-3)

* 适配器现在在添加 Vite 插件时接收 Svelte 配置作为函数参数（**3.0.0-next.27**，[#16986](https://github.com/sveltejs/kit/pull/16986)）
* 适配器可以在 `vite dev` 和 `vite preview` 期间覆盖 `getRequest` 和 `setResponse`，使本地请求的行为更像目标平台（**3.0.0-next.27**，[Docs](/docs/kit/writing-adapters)，[#16753](https://github.com/sveltejs/kit/pull/16753)）
* Node：静态资产现在从构建时记录的表中提供，而不是从 `sirv` 中提供（**adapter-node@6.0.0-next.13**，[Docs](/docs/kit/migrating-to-sveltekit-3#Adapters-adapter-node)，[#16908](https://github.com/sveltejs/kit/pull/16908)）
* Netlify：`split` 和 `edge` 选项现在可以一起使用（**adapter-netlify@7.0.0-next.12**，[Docs](/docs/kit/adapter-netlify#Options-split)，[#17045](https://github.com/sveltejs/kit/pull/17045)）
* `adapter-auto` 现在支持零配置部署到 Render（**adapter-auto@8.0.0-next.4**，[Docs](/docs/kit/adapter-auto)，[#16850](https://github.com/sveltejs/kit/pull/16850)）
* `svelte-package` 现在将导入别名（如 `#lib`）重写为相对导入，并在 `.server.` 文件或 `server` 目录没有导入服务器仅模块时发出警告（**package@3.0.0**，[#16360](https://github.com/sveltejs/kit/pull/16360)，[#16266](https://github.com/sveltejs/kit/pull/16266)）
* **从最终预发布版本的breaking changes**
  * 服务器现在在客户端请求的单飞突变刷新未被处理时出错。使用 `ignore()` 或 `ignoreAll()` 来跳过刷新（**3.0.0-next.27**，[Docs](/docs/kit/remote-functions#Single-flight-mutations-Client-requested-refreshes)，[#16892](https://github.com/sveltejs/kit/pull/16892)）
  * 环境变量现在在 `instrumentation.server.js` 被评估之前填充，适配器 instrumentation API 已更新以匹配（**3.0.0-next.27**，[Docs](/docs/kit/migrating-to-sveltekit-3#Adapters-Adapter-API-changes-Server-instrumentation)，[#16303](https://github.com/sveltejs/kit/pull/16303)）
  * `builder.generateManifest` 已被 `builder.generateServerInstance` 和 `builder.manifest` 替换，`Server` 构造函数和 `SSRManifest` 类型不再公开（**3.0.0-next.27**，[Docs](/docs/kit/migrating-to-sveltekit-3#Adapters-Adapter-API-changes)，[#16875](https://github.com/sveltejs/kit/pull/16875)，[#16876](https://github.com/sveltejs/kit/pull/16876)）
  * 以 `x-sveltekit-` 开头的查询参数现在被拒绝（**3.0.0-next.28**，[#17125](https://github.com/sveltejs/kit/pull/17125)）
  * Cloudflare：`platform` 对象已被移除。绑定现在来自模拟的 `cloudflare:workers` 模块（**adapter-cloudflare@8.0.0-next.7**，[Docs](/docs/kit/adapter-cloudflare#Runtime-APIs)，[#16754](https://github.com/sveltejs/kit/pull/16754)）
  * Node：仅在构建时存在的静态资产被提供，它们使用内容哈希 `ETag` 进行验证，而不是 `Last-Modified`，并且它们只响应 `GET` 和 `HEAD` 请求（**adapter-node@6.0.0-next.13**，[Docs](/docs/kit/migrating-to-sveltekit-3#Adapters-adapter-node)，[#16908](https://github.com/sveltejs/kit/pull/16908)）
  * Netlify：静态文件现在根据 `publish` 适配器选项写入，而不是读取 `netlify.toml`（**adapter-netlify@7.0.0-next.12**，[Docs](/docs/kit/migrating-to-sveltekit-3#Adapters-adapter-netlify)，[#17078](https://github.com/sveltejs/kit/pull/17078)）

升级现有应用？ [迁移指南](/docs/kit/migrating-to-sveltekit-3)涵盖了 3.0 中的所有破坏性变化。有关发布中包含的所有错误修复，请查看 [SvelteKit / Adapter CHANGELOGs](https://github.com/sveltejs/kit/tree/main/packages)。

## 什么是 Svelte CLI 和 AI 工具的新功能[](#What's-new-in-the-Svelte-CLI-and-AI-Tools)

* `drizzle` 插件现在可以使用 Node 的内置 `node:sqlite` 模块设置 SQLite (**sv@0.17.1**, [Docs](/docs/cli/drizzle#Options-client), [#1206](https://github.com/sveltejs/cli/pull/1206))
* `sv` 1.0 发布！新项目使用 SvelteKit 3 和 `#lib`，并且 `sv migrate sveltekit-3` 可以升级现有应用 (**sv@1.0.0**, [Docs](/docs/cli/sv-migrate), [#1138](https://github.com/sveltejs/cli/pull/1138))
* 社区插件 API 现在是官方的，`sv create` 可以使用 `addon` 模板创建一个新插件 (**sv@1.0.0**, [Docs](/docs/cli/community), [#1308](https://github.com/sveltejs/cli/pull/1308))
* `@sveltejs/enhanced-img` 现在可以通过 `sv add enhanced-img` 作为官方插件使用 (**sv@1.0.0**, [Docs](/docs/cli/enhanced-img), [#1300](https://github.com/sveltejs/cli/pull/1300))
* Svelte OpenCode 插件现在支持 OpenCode V2 (**opencode@0.1.15**, [#258](https://github.com/sveltejs/ai-tools/pull/258))

对于 Svelte 5.57.1 本月所做的所有 bug 修复和性能改进，查看 Svelte 编译器的 [CHANGELOG](https://github.com/sveltejs/svelte/blob/main/packages/svelte/CHANGELOG.md)。CLI 和 AI 工具更新可以在 [Svelte CLI](https://github.com/sveltejs/cli/releases) 和 [ai-tools](https://github.com/sveltejs/ai-tools/releases) 发布版本中找到。

### 库、工具和组件[](#Community-Showcase-Libraries-Tools-Components)

*UI 组件*

* [Sivir UI](https://sivir.dev) (上次以 Neel/UI 的名义在 2024 年 4 月出现) 已被重写为 shadcn 风格的组件库，旨在做到尽可能的主题化
* [FluentUI Svelte](https://fluentui-svelte.pages.dev/) 将 Microsoft 的 Fluent UI 带到 Svelte，现在在 v0.4 中有 37 个组件
* [Baby UI](https://baby-ui.nexonauts.com/) 是一个以动画为主的 UI 组件的大集合
* [horizon-layout](https://github.com/play-horizon/horizon-layout) 是一个零依赖的 IDE 风格的布局管理器，具有可停靠的窗格、可拖动的标签、可调整大小的分割和弹出窗口
* [svelte5plus-calendar](https://blackman99.github.io/svelte5plus-calendar/) 和 [svelte-json-discovery](https://blackman99.github.io/svelte-json-discovery/) 分别是零依赖的日历和 JSON 结构查看器
* [Svelte-pasito](https://svelte-pasito.vercel.app/) 是一个无依赖、可自定义的步骤指示器组件
* [Theme Toggles](https://toggles.dev/) 是一套支持 Svelte 的动画灯暗主题切换按钮

*Markdown 工具、编辑器和语法高亮*

* [Twinkleplop](https://twinkleplop.pngwn.at) 是 pngwn 的一个令人愉悦的语法高亮器
* [fractalpop](https://fractalpop.vercel.app/) 是一个适用于 SvelteKit 的 SSR 安全、异步语法高亮器，支持 mdsvex，并带有编辑器和代码片段组件
* [aragonite](https://www.aragonite.dev/) 是一个从头开始构建的 Svelte markdown 编辑器库，不包装 ProseMirror 或其他编辑器
* [svmd](https://github.com/imlargo/svmd) 将 CommonMark markdown 直接编译为 Svelte 组件源代码，因此组件和响应式表达式可以在您的 `.md` 文件中工作
* [Editable 2.0](https://editable.website) 现在处于预览阶段，允许客户直接在 Svelte 站点上编辑文本、图像和视频，而无需 CMS
* [svedocs](https://svedocs.pwp.sh) 是一个使用 SvelteKit 构建的可定制文档框架

*Dev Tools*

* [Railway](https://railway.com/deploy/svelte-kit) 现在提供了一个开箱即用的 SvelteKit 模板，用于托管从静态博客到全栈应用程序的所有内容
* [svebcomponents](https://svebcomponents.dev/) 提供无需样板的、类型安全的、服务器可渲染的 Web 组件
* [svdevtools](https://github.com/hasinoorit/svdevtools) 是一个开发工具包的早期预览，它允许您检查组件、道具和状态

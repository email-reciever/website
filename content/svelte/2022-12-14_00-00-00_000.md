经过两年的开发，[SvelteKit](https://kit.svelte.dev)终于达到了1.0。 截至今天，这是构建各种形状和大小的苗条应用程序的推荐方式。

我们很高兴与您分享此版本。 无论您是从事小型项目的单独开发人员还是大型团队的一部分，这都是数千小时工作的高潮，无论是来自 Svelte 核心团队还是更广泛的社区，我们认为这是构建生产级网站的最愉快的方式。

首先，运行`npm create svelte@latest`，并访问[docs](/docs/kit)和（实验！）[interactive tutorial](https://learn.svelte.dev)。

什么是sveltekit？[](#What-is-SvelteKit)
---------------------------------------

sveltekit 是一个在 Svelte 之上构建 Web 应用程序的框架，这是一个 UI 组件框架 [that](https://insights.stackoverflow.com/survey/2021#section-most-loved-dreaded-and-wanted-web-frameworks) [developers](https://2021.stateofjs.com/en-US/libraries/front-end-frameworks/) [love](https://twitter.com/Rich_Harris/status/1589675637195042817) 的性能和易用性。

如果您使用过 Svelte 等组件框架，您就会知道它们比直接使用 DOM 更容易构建用户界面。 但他们留下了很多未解答的问题：

*   如何构建我的源代码？
*   如何添加服务器端渲染？
*   如何添加在服务器和浏览器中工作的路由？
*   如何使客户端路由可访问？
*   如何获取数据？
*   如何修改数据？
*   如何处理错误？
*   如何优化我的生产构建？
*   如何合理安全地处理环境变量？
*   如何添加 CSP 标头和 CSRF 保护？
*   如何添加知道要缓存什么的服务工作者？
*   如何准备我的应用程序进行部署？

应用程序框架旨在回答这些问题。 sveltekit 的设计理念是基于 beta 测试人员的真实世界需求（其中许多人已经在生产中运行 sveltekit 一段时间了——我们向您的勇气致敬，并感谢您提供的宝贵反馈）以及其他应用程序框架的最佳想法，包括 [Next.js](https://nextjs.org/) 和 [Remix](https://remix.run/)。

有什么不同？[](#How-is-it-different)
------------------------------------------

今天的网络开发人员被宠坏了。 除了上述框架之外，还有 [Astro](https://astro.build/)、经过战斗测试的服务器框架等选项，如 [Rails](https://rubyonrails.org/) 和 [Laravel](https://laravel.com/) 以及一百万个静态站点生成器。 这些都是很棒的工具，你应该对选择它们感觉很好。

然而，sveltekit 做的事情有些不同：

**与传统的“多页应用程序”或 MPA 框架不同，** 它在初始服务器呈现页面加载后默认为客户端导航。 这可以实现更快的页面过渡、在页面之间持续存在的状态（例如侧边栏的滚动位置），以及更少的数据使用情况。 它还避免在每个页面加载时重新运行第三方脚本，例如 Analytics。

**与传统的服务器框架不同，**它允许您使用一种语言，而不是有效地拥有两个紧密耦合的应用程序（一个用于生成HTML，一种用于处理客户端交互）。 因为 sveltekit 运行在任何 JavaScript 运行的地方，您可以将您的应用部署为传统的节点服务器，或使用无服务器功能（包括在边缘）。

**与静态站点生成器不同，** 您可以构建具有个性化或动态数据的应用程序 - 无需在页面加载后从浏览器中获取它的性能破坏、布局变化的效果。

使用 sveltekit，您可以灵活地使用。 许多框架假设有一种正确的构建应用程序的方法，但现实更加微妙。 例如，预渲染静态页面只是一个穷人的 `cache-control` ，这不是真的——它还允许您从边缘函数无法访问的文件系统中执行构建时验证或渲染数据，并充当对冲不稳定的数据库的对冲。 并非所有内容都需要服务器端渲染，这是正确的默认设置，如果您想要具有良好 SEO 的强大、高性能的应用程序，但也有无数例外。

在 Sveltekit 应用程序中，您可以根据需要以尽可能多的粒度进行这些选择——例如，您正在查看的页面是预渲染的，但 [REPL](/repl) 是用动态数据呈现的。 在两者之间切换是单行代码。 我们将使用这种方法构建的应用程序称为“[transitional apps](https://2021.jamstackconf.com/talk/c17544108e71/transitional-apps/)”。

sveltekit 可以使用什么？[](#What-can-I-use-with-SvelteKit)
------------------------------------------------------------

因为 Sveltekit 使用 [Vite](https://vitejs.dev/)，即快速构建工具，它对热模块重新加载、TypeScript 和许多其他开发人员依赖的东西具有开箱即用的支持。 您可以从 Vave Vite 和 Rollup 生态系统安装插件，以添加对其他工具的支持。

创建 sveltekit 项目时，系统会询问您是否要添加 [TypeScript](https://www.typescriptlang.org/)、[ESLint](https://eslint.org/)、[Prettier](https://prettier.io/)、[Playwright](https://playwright.dev/)（用于端到端浏览器测试）和 [Vitest](https://vitest.dev/)（用于单元测试）。 许多热门项目已经存在集成指南——例如 [Tailwind](https://tailwindcss.com/docs/guides/sveltekit) 和 [Supabase](https://supabase.com/docs/guides/getting-started/tutorials/with-sveltekit)。 您可以为组件故事使用 [Storybook](https://github.com/storybookjs/storybook/blob/next/code/frameworks/sveltekit/README.md) 和 [Histoire](https://histoire.dev/guide/svelte3/getting-started.html)。 社区维护的 [svelte-add](https://github.com/svelte-add/svelte-add) 允许您使用单个命令添加越来越多的其他集成列表。

当然，您可以访问 [npm](https://npmjs.com/) 提供的所有内容。 （请注意，某些软件包需要 Node.js，因此只能在部署到基于节点的平台时使用。）

我在哪里可以部署我的应用程序？[](#Where-can-I-deploy-my-apps)
------------------------------------------------------

任何地方！ Sveltekit CLI 需要本地安装 Node.js，但框架本身对任何平台都没有依赖关系。 这意味着您可以在 JavaScript 运行的任何地方部署它。

这可以通过[adapters](/docs/kit/adapters)实现。 默认适配器 [adapter-auto](https://github.com/sveltejs/kit/tree/master/packages/adapter-auto) 为 Vercel、Netlify、Cloudflare 页面和 Azure 静态 Web 应用提供零配置支持，未来还将推出更多平台。 社区提供的适配器添加了对 Deno、Bun、Firebase、App Engine、AWS Lambda 等的支持。

您还可以使用 [adapter-node](https://github.com/sveltejs/kit/tree/master/packages/adapter-node) 将您的应用部署为 Node.js 服务器。

如果您的整个应用程序适合预渲染，或者是单页应用程序 (SPA)，您可以使用 [adapter-static](https://github.com/sveltejs/kit/tree/master/packages/adapter-static) - 它将 Sveltekit 变成静态站点生成器 - 与包括 [GitHub Pages](https://pages.github.com/) 在内的任何 Web 服务器。

迁移[](#Migrating)
------------------------

如果您有一个使用 SvelTekit 预发布版本构建的应用程序，我们建议在升级到 1.0 之前升级到最终的预发布版本 - `@sveltejs/kit@1.0.0-next.588` - 因为稳定版本消除了用于迁移的错误和警告 预发布版本。 我们还建议咨询 [this migration guide](https://github.com/sveltejs/kit/discussions/5774)，特别是如果您目前使用的是 1.0.0-next-406 的旧版本。

下一步是什么？[](#What's-next)
-----------------------------

Sveltekit 1.0 是开始，而不是结束。 它今天已准备好供生产使用，但我们才刚刚开始。 我们的路线图包括内置的 i18n 支持、增量静态再生、对部署区域和运行时的精细控制、图像优化以及许多其他改进。 明年我们还将开始在 Svelte 4 上工作——稍后会详细介绍。

但不要让我们有最终决定权。 Svelte 是一个社区项目，我们的许多最好的想法根本不是我们的——它们是你的。 订阅 [BlueSky](https://bsky.app/profile/sveltesociety.dev) 和 [YouTube](https://youtube.com/sveltesociety) 上的 Svelte Society 以保持最新状态，并加入我们的 [Discord server](/chat) 和 [GitHub](https://github.com/sveltejs) 上的贡献。

我们迫不及待地想看看你建造了什么。

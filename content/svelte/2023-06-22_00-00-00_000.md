经过几个月的制作，我们很高兴地宣布 Svelte 4 的稳定版本。

Time Flies - Svelte 3 已于四年多前发布！ 在 JavaScript-Framework-Time 中，这就是万古。 Svelte 的新鲜度一直持续存在，但 Node.js 和浏览器 API 在那段时间里不断发展，今天我们正在更新 Svelte 以利用其中一些改进。 Svelte 4 主要是维护版本，针对最低版本要求和在特定区域收紧设计。 它为下一代 Svelte 以 Svelte 5 的形式发布奠定了基础——我们认为您会喜欢它。

如果您还没有尝试过 Svelte，请在我们的 [interactive tutorial](/tutorial)、[StackBlitz](https://sveltekit.new/) 或本地使用 `npm create svelte@latest` 中旋转。 Svelte 让您可以利用 HTML、CSS、JS 和 Svelte 编译器的强大功能轻松组合 Web UI。 观看 [Svelte Radio Live](https://www.youtube.com/watch?v=72TIVhRtyWE) 以了解有关此版本的更多信息。

新增内容[](#What's-new)
--------------------------

### 性能[](#What's-new-Performance)

此版本导致更小和更快的水合代码。 要查看影响，Sveltekit 用户可以通过检查 `.svelte-kit/output/client/_app/immutable/nodes` 文件夹查看其编译的输出缩小大小。 例如，在 [kit.svelte.dev](https://kit.svelte.dev) 上生成的整个站点的 JS 的大小减少了 12.7%（126.3 kb 到 110.2 kb）。

Svelte 4 将 Svelte 封装尺寸减少了近 75%（10.6 MB 到 2.8 MB），这意味着更少的等待 `npm install`。 对于首次加载 [our interactive learning experience](/tutorial) 的用户、Svelte REPL 的用户以及连接有限的用户，这种改进将特别明显。 剩余的大部分封装大小都是 ESLint 支持，这需要分发 CJS 版本，一旦 [the eslint rewrite](https://github.com/eslint/eslint/discussions/16557) 完成，Svelte 的封装大小可能会下降超过 50%。

Svelte 中的依赖数量从 61 个减少到 16 个。这意味着我们的用户下载速度更快，并且对供应链攻击的敏感性更低。 我们还稍微减少了最新版本的 Sveltekit 中的依赖项数量。

### 开发者经验[](#What's-new-Developer-experience)

svelte 4 使 svelte 创作体验更加直观和一致：`|local` 现在是过渡的默认设置，以避免动画阻塞页面转换，预处理器现在更容易编写，并且多个修复使 CSP 更容易设置和使用。

对于 Web 组件的用户，最大的变化是对使用 Svelte 创作自定义元素的方式进行了大修。 通过改变它们的生成方式，消除了一整类错误和不一致。

最后，我们还制作了几个 [improvements to the IDE authoring experience](https://github.com/sveltejs/svelte/pull/8702)：现在隐藏的 `svelte/internal` 文件中的 cmd+click svelte 模块中的 cmd+click

### 更新的网站、文档和教程[](#What's-new-Updated-site-docs-and-tutorial)

官方 svelte.dev 网站已经进行了大修。 它现在分为多个页面，改进了移动导航、大修的 TypeScript 文档、黑暗模式和增强的 REPL。 Sveltekit 网站也正在更新以匹配。 我们更新了所有教程链接，以指向我们新的 [tutorial](/tutorial) 体验。

请继续关注有关未来几天所有网站变化的更深入的博客文章！

迁移[](#Migrating)
------------------------

大多数与 Svelte 3 兼容的应用程序和库应该与 Svelte 4 兼容。如果 `peerDependencies` 中指定了 `svelte`，库作者将需要更新版本范围以包含 Svelte 4。 对于应用程序作者，最常见的更改将是更新工具以满足新的最低版本要求，例如 Node.js 16。许多其他迁移步骤都可以使用 `npx svelte-migrate@latest svelte-4` 来处理。

阅读 [migration guide](/docs/v4-migration-guide) 了解完整详情。

svelte 5：下一代 svelte[](#Svelte-5:-the-next-generation-of-Svelte)
---------------------------------------- ----------------------------------------

svelte 5 将重写 svelte 编译器和运行时。 Svelte 4 主要是通过采用现代工具和放弃对各种技术的遗留版本（例如旧的捆绑器）的支持为这些未来的改进奠定基础。 这些更改将以多种方式帮助我们，例如能够更轻松地比较 svelte 5 和 svelte 4 代码库，并且能够根据新实现运行现有测试。 Svelte 5 将为 Svelte 带来重大的新功能和性能改进。 这些变化仍在烘烤，尚未准备好分享，但请继续关注！

自 Sveltekit 1.0 发布以来，Svelte 团队一直在努力工作。 让我们谈谈自推出以来推出的一些主要新功能：[streaming non-essential data](/docs/kit/load#Streaming-with-promises)、[snapshots](/docs/kit/snapshots) 和 [route-level config](/docs/kit/page-options#config)。

加载函数中的流非必需数据[](#Stream-non-essential-data-in-load-functions)
------------------------------------------- -------------------------------------------

Sveltekit 使用 [load functions](/docs/kit/load) 检索给定路由的数据。 在页面之间导航时，它首先获取数据，然后使用结果呈现页面。 如果页面的某些数据比其他数据需要更长的时间来加载，这可能是一个问题，特别是如果数据不是必需的——用户在所有数据准备就绪之前不会看到新页面的任何部分。

有办法解决这个问题。 特别是，您可以在组件本身中获取慢速数据，因此它首先使用 `load` 中的数据进行渲染，然后开始获取慢速数据。 但这并不理想：由于您在客户端渲染之前才开始获取数据，因此数据会更加延迟，并且您还必须打破 sveltekit 的 `load` 惯例。

现在，在 Sveltekit 1.8 中，我们有一个新的解决方案：您可以从服务器加载函数返回嵌套 Promise，并且 sveltekit 将在页面解析之前开始呈现该页面。 完成后，结果将是 [streamed](https://developer.mozilla.org/en-US/docs/Web/API/Streams_API) 到页面。

例如，考虑以下 `load` 函数：

sveltekit 将在开始渲染页面之前自动等待 `fetchPost` 调用，因为它位于顶级。 但是，它不会等待嵌套的 `fetchComments` 调用完成 - 页面将呈现，`data.streamed.comments` 将是一个承诺，将在请求完成时解决。 我们可以使用 svelte 的 [await block](/docs/svelte/await) 在相应的 `+page.svelte` 中显示加载状态：

这里的属性 `streamed` 没有什么独特之处——触发行为所需要的只是返回对象顶级之外的承诺。

Sveltekit 只有在您的应用的托管平台支持时才能够流式传输响应。 通常，围绕 AWS Lambda 构建的任何平台（例如无服务器函数）都不会支持流式传输，但任何传统的 Node.js 服务器或基于边缘的运行时都会支持。 检查您的提供商的文档以进行确认。

如果您的平台不支持流式传输，则数据仍将可用，但响应将被缓冲，并且在获取所有数据之前页面不会开始呈现。

它是如何工作的？[](#How-does-it-work)
------------------------------------

为了使来自服务器 `load` 函数的数据到达浏览器，我们必须 _serialize_ 它。 sveltekit 使用一个名为 [devalue](https://github.com/Rich-Harris/devalue) 的库，它类似于 `JSON.stringify` 但更好地处理 JSON 无法处理的值（如日期和正则表达式），它可以将包含自身（或数据中多次存在）的对象序列化而不会破坏身份，并保护您免受 [XSS vulnerabilities](https://github.com/rich-harris/devalue#xss-mitigation)。

对于客户端导航，我们使用的机制略有不同。 来自服务器的数据被序列化为 [newline delimited JSON](https://dataprotocols.org/ndjson/)，Sveltekit 使用 `devalue.parse` 重构这些值——使用类似的延迟机制：

// 这是立即生成的 — 注意 ["promise",1]...
[{"post":1,"streamed":4},{"title":2,"content":3}"我很酷的博客文章"",...",{"comments":5},["promise",6],1]
    
// ...然后，一旦 Promise 解决，这个块会发送到浏览器
[{"id":1,"data":2},1,[3],{"comment":4},"first!"]

因为 Promises 是以这种方式本机支持的，所以您可以将它们放在 `load` 返回的数据中的任何位置（除了顶级，因为我们会自动为您等待），并且它们可以使用 devalue 支持的任何类型的数据来解决 - 包括更多的 Promise！

一项警告：此功能需要 JavaScript。 因此，我们建议您仅流入非必要数据，以便所有用户都可以使用体验的核心。

有关此功能的更多信息，请参见 [the documentation](/docs/kit/load#Streaming-with-promises)。 您可以在 [sveltekit-on-the-edge.vercel.app](https://sveltekit-on-the-edge.vercel.app/edge) （位置数据人为地延迟和流式传输）或 [deploy your own on Vercel](https://vercel.com/templates/svelte/sveltekit-edge-functions) 中看到演示，其中边缘函数和无服务器功能都支持流。

我们感谢从 Qwik、Remix、Solid、Marko、React 等先前实现的想法中获得的灵感。

快照[](#Snapshots)
------------------------

以前在 Sveltekit 应用程序中，如果您在开始填写表单后导航，返回将不会恢复您的表单状态 - 该表单将使用其默认值重新创建。 根据上下文，这可能会让用户感到沮丧。 自 Sveltekit 1.5 以来，我们有一个内置的方法来解决这个问题：快照。

现在，您可以从 `+page.svelte` 或 `+layout.svelte` 中导出 `snapshot` 对象。 此对象有两种方法：`capture` 和 `restore`。 `capture` 函数定义用户离开页面时要存储的状态。 Sveltekit 然后将该状态与当前历史条目相关联。 如果用户导航回页面，`restore` 函数将以您之前设置的状态被调用。

例如，您将如何捕获和恢复 TextArea 的值：

    <script lang="ts">
从“./$types”导入类型 { 快照 }；
    
让评论 = '';
    
导出常量快照：快照 = {
捕获：（）=>评论，
恢复：（值）=>（评论 = 值）
};
    </script>
    
    <form method="POST">
<label for="comment">评论</label>
    	<textarea id="comment" bind:value={comment} />
<button>发表评论</button>
    </form>

虽然表单输入值和滚动位置之类的东西是常见的示例，但您可以将您喜欢的任何 JSON 序列化数据存储在快照中。 快照数据存储在 [sessionStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage) 中，因此即使页面重新加载或用户完全导航到不同的站点时，它也会持续存在。 因为它在 `sessionStorage` 中，因此您将无法在服务器端渲染期间访问它。

有关更多信息，请参阅 [the documentation](/docs/kit/snapshots)。

路由级部署配置[](#Route-level-deployment-configuration)
------------------------------------ --------------------------------------

Sveltekit 使用特定于平台的 [adapters](/docs/kit/adapters) 将应用代码转换为生产部署。 到目前为止，您必须在应用范围内配置部署。 例如，您可以将您的应用程序部署为边缘函数或无服务器功能，但不能同时部署。 这使得您无法利用应用程序的某些部分的优势 - 如果任何路由需要 Node API，那么您就无法将其中的任何一个部署到边缘。 部署配置的其他方面（例如区域和分配的内存）也是如此：您必须选择一个应用于整个应用中每条路由的值。

现在，您可以在 `+server.js`、`+page(.server).js` 和 `+layout(.server).js` 文件中导出 `config` 对象，以控制这些路由的部署方式。 在 `+layout.js` 中这样做会将配置应用于所有子页面。 `config` 的类型对每个适配器都是唯一的，因为它取决于您部署到的环境。

从“some-adapter”导入类型 { configimport config }；
    
导出 const configconst config: config: configimport config = {
runtime(property) runtime: string: 'edge'
};

配置是在顶层合并的，因此您可以覆盖在树的更深处的页面的布局中设置的值。 有关更多详细信息，请参阅 [the documentation](/docs/kit/page-options#config)。

如果您部署到 Vercel，您可以通过安装最新版本的 Sveltekit 和您的适配器来利用此功能。 这将需要对您的适配器版本进行重大升级，因为支持路由级配置的适配器需要 Sveltekit 1.5 或更高版本。

npm i @sveltejs/kit@latest
npm i @sveltejs/adapter-auto@latest # 或 @sveltejs/adapter-vercel@latest

目前，只有 [Vercel adapter](/docs/kit/adapter-vercel#Deployment-configuration) 实现了特定于路由的配置，但构建块可以为其他平台实现这一点。 如果您是适配器作者，请参阅 [the PR](https://github.com/sveltejs/kit/pull/8740) 中的更改以了解需要什么。

Vercel[](#Incremental-static-regeneration-on-Vercel)上的增量静态再生
----------------------------------------- ------------------------------------------

路由级配置还解锁了另一个备受要求的功能——您现在可以将 [incremental static regeneration](/docs/kit/adapter-vercel#Incremental-Static-Regeneration) (ISR) 与部署到 Vercel 的 sveltekit 应用程序一起使用。 ISR 提供了预渲染内容的性能和成本优势以及动态渲染内容的灵活性。

在我们第一次开始谈论 Svelte 问题跟踪器上的版本 2 近一年后，终于到了进行一些重大更改的时候了。 这篇博文将解释发生了哪些变化、为什么改变以及您需要做什么才能使您的应用程序保持最新状态。

tl;dr[](#tl-dr)
----------------

下面更深入地描述了这些项目中的每一个。 如果您遇到困难，请在我们的友好 [Discord chatroom](/chat) 中寻求帮助。

*   从 npm 安装 svelte v2
*   使用 [svelte-upgrade](https://github.com/sveltejs/svelte-upgrade) 升级您的模板
*   删除对 `component.observe` 的调用，或从 [svelte-extras](https://github.com/sveltejs/svelte-extras) 中添加 `observe` 方法
*   将对 `component.get('foo')` 的呼叫改写为 `component.get().foo`
*   从您的自定义事件处理程序返回 `destroy`，而不是 `teardown`
*   确保您没有将数字字符串道具传递给组件

新模板语法[](#New-template-syntax)
-----------------------------------------

最明显的变化：我们对模板语法进行了一些改进。

我们听到的一个常见反馈是“ewww，小胡子”或“ewww，车把”。 在以前的 Web 开发时代，很多使用基于字符串的模板系统的人都不喜欢它们。 因为 Svelte 采用了这些语言中的 `{{curlies}}`，所以很多人认为我们以某种方式共享了这些工具的局限性，例如奇怪的范围规则或无法使用任意 JavaScript 表达式。

除此之外，JSX 证明了双卷曲是不必要的。 因此，我们通过采用单卷曲使我们的模板更加……苗条。 结果感觉更轻，打字更愉快：

<h1>你好{名字}！</h1>

还有一些其他更新。 但是您不需要手动制作它们 - 只需在代码库上运行 [svelte-upgrade](https://github.com/sveltejs/svelte-upgrade)：

NPX Svelte 升级 V2 SRC

这假设 `src` 中的任何 `.html` 文件都是 svelte 组件。 您可以指定您喜欢的任何目录，或针对不同的目录——例如，您需要 `npx svelte-upgrade v2 routes` 来更新 [Sapper](https://sapper.svelte.technology) 应用程序。

要查看全套更改，请参阅 [svelte-upgrade README](https://github.com/sveltejs/svelte-upgrade#svelte-v2-syntax-changes)。

计算属性[](#Computed-properties)
-----------------------------------------

人们经常发现对 Svelte 感到困惑的另一件事是计算属性的工作方式。 回顾一下，如果你有这个组件...

导出默认 {
计算（属性）计算： {
D: (A: ANY, B: Any, C: Any) => any;
}：{
d(property) D: (A: Any, B: Any, C: Any) => Any: (A(参数) A: Any, B(参数) B: Any, C(参数) C: Any) => (A(参数) A: Any = B(参数) B: any + c(参数) C: any)
}
};

...然后 Svelte 将首先查看函数参数以查看 `d` 依赖于哪些值，然后通过将它们注入函数中，编写更新 `d` 的代码。 这很酷，因为它允许您从组件的输入中推导出复杂的值，而不必担心它们何时需要重新计算，但它也是... _weird_。 JavaScript 不是这样工作的！

在 v2 中，我们使用 [destructuring](http://www.jstips.co/en/javascript/use-destructuring-in-function-parameters/) 代替：

导出默认 {
计算（属性）计算： {
d: ({ a, b, c }: {
答：任何；
B：任何；
C：任何；
}) => 任何；
}：{
d(属性) d: ({ a, b, c }: {
答：任何；
B：任何；
C：任何；
}) => 任意：({ a(parameter) a: any, b(parameter) b: any, c(parameter) c: any }) => (a(parameter) A: any = b(parameter) B: any + (parameter) C: Any)
}
};

svelte 编译器仍然可以看到 `d` 依赖于哪些值，但它不再注入值——它只是将组件状态对象传递到每个计算的属性中。

同样，您不需要手动进行此更改 - 只需在组件上运行 svelte-upgrade，如上所示。

对不起，IE11。 不是你，它是……实际上，是的。 是你[](#Sorry-IE11.-It's-not-you-it's-well-actually-yeah.-It's-you)
---------------------------------------------------------- ------------------------------------------------------------

Svelte v1 小心地只发出 ES5 代码，这样您就不会被迫使用翻译器来使用它。 但现在是 2018 年，几乎所有浏览器都支持现代 JavaScript。 通过放弃 ES5 约束，我们可以生成更精简的代码。

如果您需要支持 IE11 和朋友，则需要使用 [Babel](https://babeljs.io/repl) 或 [Bublé](https://buble.surge.sh/) 之类的翻译器。

新的生命周期钩子[](#New-lifecycle-hooks)
-----------------------------------------

除了 `oncreate` 和 `ondestroy` 之外，Svelte v2 还添加了两个 [lifecycle hooks](https://v2.svelte.dev/guide#lifecycle-hooks) 以响应状态更改：

导出默认 {
onState(method) onState({ 更改，当前，上一个 }: {
更改：任何；
当前：任何；
上一个：任何；
}): void({ changed(parameter) changed:any, current(parameter) current: any, previous(parameter) previous:any }) {
// 这在 onCreate 之前触发，并且
// 每当状态改变
},
    
onupdate(method) onupdate({ 更改，当前，上一个 }: {
更改：任何；
当前：任何；
上一个：任何；
}): void({ changed(parameter) changed:any, current(parameter) current: any, previous(parameter) previous:any }) {
// 这会在 onCreate 之后触发，并且
// 每当 DOM 被更新时
// 跟随状态变化
}
};

您还可以以编程方式收听这些事件：

componentAny.onany('state', ({ changed(parameter) changed: any, current(parameter) current: any, previous(parameter) previous: any }) => {
// ...
});

组件.get[](#component.get)
------------------------------

此方法不再采用可选的 `key` 参数 - 而是始终返回整个 state 对象：

// 之前
const foonst foo: any = this.getany('foo');
const barconst bar：any = this.getany('bar');
    
// 之后
const { foonst foo: any, barconst bar: any } = this.getany();

这种变化最初可能看起来很烦人，但这是正确的举措：除其他外，当我们在未来更充分地探索该空间时，它可能会更好地使用类型系统。

事件\_handler.destroy[](#event_handler.destroy)
--------------------------------------------

如果您的应用程序有 [custom event handlers](https://v2.svelte.dev/guide#custom-event-handlers)，则必须使用 `destroy` 方法返回一个对象，_not_ a `teardown` 方法（这将事件处理程序与组件 API 对齐）。

没有更多的类型强制[](#No-more-type-coercion)
--------------------------------------------

以前，传递给组件的数值被视为数字：

    <Counter start="1" />

这会导致意外的行为，并且已经改变：如果您需要传递一个字面数，请将其作为表达式进行：

    <Counter start={1} />

编译器更改[](#Compiler-changes)
-----------------------------------

在大多数情况下，您永远不需要直接处理编译器，因此这不需要您的任何操作。 无论如何，值得注意的是：编译器 API 发生了变化。 编译器不是具有 mish-mush 属性的对象，而是返回 `js`、`css`、`ast` 和 `stats`：

const { jsconst js: any, cssconst css: any, astconst ast: any, statsconst stats: any } = svelteany.compileAny(sourceany, optionany);

`js` 和 `css` 都是 `{ code, map }` 对象，其中 `code` 是字符串，`map` 是源图。 `ast` 是组件的抽象语法树，`stats` 对象包含有关组件的元数据以及有关编译的信息。

之前，有一个 `svelte.validate` 方法检查您的组件是否有效。 已删除-如果您想在不实际编译的情况下检查组件，只需传递 `generate: false` 选项。

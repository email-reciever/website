本月，Sveltekit 项目的配置方式发生了真正的转变。 您现在可以直接在 `vite.config.js` 中定义您的 sveltekit 配置并完全跳过 `svelte.config.js`。 我们还获得了第一个显式环境变量的预览，最终将取代 sveltekit 3 中的 `$env/*` 模块。

最重要的是，语言工具和 `sv` CLI 都赶上了 Svelte 的新 `{const ...}` 声明标签，因此整个工具链现在是同步的。

让我们潜入！

sveltekit的新增功能[](#What's-new-in-SvelteKit)
-----------------------------------------------

*   您现在可以将 sveltekit 配置直接传递给 Vite 插件，因此不再需要单独的 `svelte.config.js`，因为 kit 3 将如何要求 config 生活在 `vite.config.js` (**2.62.0**, [Docs](/docs/kit/configuration), [#15944](https://github.com/sveltejs/kit/pull/15944) 中)
*   实验性显式环境变量让您在一个地方声明和键入您的 env 变量，作为 `$env/*` 在 Sveltekit 3 中如何工作的预览 (**2.63.0**, [Docs](/docs/kit/environment-variables), [#15934](https://github.com/sveltejs/kit/pull/15934))
*   远程功能命令现在可以直接接收`File`对象，因此您无需手动包装文件即可上传文件`FormData`（**2.64.0**、[Docs](/docs/kit/remote-functions#command)、[#15978](https://github.com/sveltejs/kit/pull/15978)）
*   远程查询现在可以刷新其他查询，从而更容易在突变后使相关数据失效（**2.65.0**、[Docs](/docs/kit/remote-functions#query-Refreshing-queries)、[#16012](https://github.com/sveltejs/kit/pull/16012)）
*   预渲染的`.md`和`.mdx`文件现在与HTML、JS和CSS一起预压缩，以实现更快的交付（**2.66.0**、[Docs](/docs/kit/adapter-static#Options-precompress)、[#15893](https://github.com/sveltejs/kit/pull/15893)）
*   当远程表单模式中的布尔字段未标记为可选时，Sveltekit 会发出警告，这是导致静默提交失败的常见原因（**2.66.0**、[Docs](/docs/kit/remote-functions#form-Fields)、[#15804](https://github.com/sveltejs/kit/pull/15804)）
*   新的 `prerender.handleInvalidUrl` 选项允许您自定义在抓取过程中发现的无效 URL 的报告方式（**2.67.0**、[Docs](/docs/kit/configuration#prerender)、[#16088](https://github.com/sveltejs/kit/pull/16088)）
*   `RemoteFormEnhanceInstance`和`RemoteFormEnhanceCallback`现在是导出的类型，所以你可以直接键入你的自定义`enhance`回调(**2.68.0**、[Docs](/docs/kit/remote-functions#form-enhance)、[#15816](https://github.com/sveltejs/kit/pull/15816))
*   提交的 `submit` 字段现在将其值保存在 Action Payload 的形式中，这使得多按钮表单更容易在服务器上处理（**2.68.0**、[Docs](/docs/kit/remote-functions#form-Multiple-submit-buttons)、[#15979](https://github.com/sveltejs/kit/pull/15979)）

对于本月登陆的所有功能和错误修正，请查看 sveltekit / 适配器 [CHANGELOGs](https://github.com/sveltejs/kit/tree/main/packages)。

Svelte CLI 和语言工具中的新功能[](#What's-new-in-the-Svelte-CLI-and-Language-Tools)
--------------------------------------------- ----------------------------------------------

*   Svelte CLI 演示模板现在使用新的 `{const ...}` 声明标记，因此新创建的项目展示了最新的 SVELTE 语法 (**sv@0.16.0**, [#1110](https://github.com/sveltejs/cli/pull/1110))
*   `sv create` 现在，Scaffolds 针对 `@sveltejs/kit` `^2.62.0` 的项目，并默认将 svelte 配置移动到 Vite 插件中 (**sv@0.16.0**, [#1119](https://github.com/sveltejs/cli/pull/1119))
*   新的实验性附加组件允许您直接从 CLI (**sv@0.16.0**, [#1121](https://github.com/sveltejs/cli/pull/1121)) 切换实验标志并选择 `@next` 版本
*    `drizzle` 和 `better-auth` 附加组件现在支持 Sveltekit 的新型显式环境变量 (**sv@0.16.0**, [#1122](https://github.com/sveltejs/cli/pull/1122))
*   新的 `defineEnv` 和 `svelteConfig` 助手 `@sveltejs/sv-utils` 中的助手使从附加组件 (**sv-utils@0.3.0**) 更容易地读取和编辑项目的 svelte 配置
*   Svelte 语言服务器，`svelte-check` 和 `svelte2tsx` 现在了解 Svelte 5 的 `{const ...}` 声明标签 （**svelte-language-server@0.18.1/svelte-check@4.5.0/svelte2tsx@0.7.56**，[#3033](https://github.com/sveltejs/language-tools/pull/3033)）
*   css 补全现在可以在嵌套 `<style>` 标签中工作 (**svelte-language-server@0.18.1**, [#3022](https://github.com/sveltejs/language-tools/pull/3022))
*   语言工具现在可以直接从 `vite.config.js/ts` 中读取 svelte config，匹配 sveltekit 的新 Vite 插件配置 (**svelte-language-server@0.18.2/svelte-check@4.6.0**, [#3031](https://github.com/sveltejs/language-tools/pull/3031))
*   `svelte-check`现在接受`--config`选项指向自定义配置文件位置（**svelte-check@4.7.0**，[#3066](https://github.com/sveltejs/language-tools/pull/3066)）
*   实验 `tsgo` (TypeScript Go) 支持现在在 `svelte-check` 中支持大型代码库的类型检查 (**svelte-check@4.7.0**, [#3036](https://github.com/sveltejs/language-tools/pull/3036))

想深入潜水吗？ 查看 [Svelte CLI](https://github.com/sveltejs/cli/releases) 和 [language-tools](https://github.com/sveltejs/language-tools/releases) 版本。 对于本月 Svelte 编译器中出现的所有细微更改和错误修正，您可以阅读完整的 [Svelte CHANGELOG](https://github.com/sveltejs/svelte/blob/main/packages/svelte/CHANGELOG.md)。

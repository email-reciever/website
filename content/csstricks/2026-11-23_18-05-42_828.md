# 使用回退机制构建强健的前端

![](https://secure.gravatar.com/avatar/e03e280df2944241b15f59c0c7150efcf67c465d1d12895863bc2da298282fdd?s=80\&d=retro\&r=pg)

By [Steve Frenzel](https://css-tricks.com/author/stevefrenzel/) on Nov 23, 2026

任何在网页开发领域工作一段时间的人都对这个来自[xkcd的传奇迷因](https://www.explainxkcd.com/wiki/index.php/2347:_Dependency)很熟悉。它生动地说明了网站或应用程序的技术基础设施有多么脆弱。

这就是为什么使用回退机制来构建强健的前端如此重要，无论是悄悄地避免错误还是将其通知给用户。

强健性如此重要，以至于它实际上是[网页内容无障碍指南（WCAG）四大原则之一](https://www.w3.org/WAI/fundamentals/accessibility-principles/#robust)！那么，我们如何在不排除使用部分兼容或完全不兼容浏览器和硬件的用户的情况下提供现代化的前端体验？

答案在于在 HTML、CSS 和 JavaScript 中实现多个安全网，以便我们为最坏的情况做好准备，并为用户提供最佳的体验。

## 两个区别

使用 fallback 和 [渐进增强](https://piccalil.li/blog/its-about-time-i-tried-to-explain-what-progressive-enhancement-actually-is/) 之间的主要区别在于两种方法的目标方向。

虽然渐进增强是关于在支持的情况下自动提供某些功能（向前），fallback 则是关于当某些功能不可用或无法访问时会发生什么（向后）。

例如，我们可以提供一个新的 CSS 特性，使与我们的网站交互更加愉快。但是，如果这个特性在一些浏览器中不可用，那么没有人会注意到，因为有一个对旧浏览器支持的版本可用。渐进增强的体现！

另一个例子：如果 JavaScript 无法为关键应用程序加载，我们提供一个 fallback，要么提供基本功能，要么至少显示一条消息解释问题所在。

虽然两者并不相互排斥，但他们的方法却大不相同。我的个人建议是始终以渐进增强作为指导原则，并在可能的情况下考虑回退。

## Web 平台：跟进 Web 平台的最新发展

为了评估新功能是否适合投入生产，我们必须首先确定该功能被支持的程度。

自 2023 年以来，[Interop](https://wpt.fyi/interop-2026) 项目已经启动，主要浏览器供应商在此项目中合作，以大致同时发布 Web 平台的新功能。这提供了一个总体概述。

与此相关的是 [Baseline](https://web.dev/baseline/) 项目，它显示了特定功能被支持的程度以及它们已有的可用时间。然而，非常重要的是要注意，它并没有跟踪 Web 平台内置的无障碍功能的浏览器支持！[it does not track browser support for accessibility features](https://adrianroselli.com/2023/12/baseline-does-not-really-cover-baseline-support.html)

另一个重要的资源用于检查兼容性是 [Can I Use](https://caniuse.com/)。在这里，你可以快速了解到各种功能在不同浏览器中的支持情况。

## HTML: 错误页面和 `<noscript>`

让我们从万维网的基础：HTML 开始。现代技术栈对客户端渲染的 JavaScript 提供了强烈的重视，这可以为更复杂的应用程序提供许多好处。然而，JavaScript 可能无法加载的原因有很多，[为什么 JavaScript 可能无法加载](https://piccalil.li/blog/a-handful-of-reasons-javascript-wont-be-available/)，因此我们需要一个策略来解决这个问题。

在发生完全故障的情况下，我们应该将用户重定向到一个适当的错误页面，在那里他们可以获得有关发生了什么问题以及我们如何在未来防止这种情况的信息。如果你想知道 [如何编写错误消息以帮助用户而不是让他们感到沮丧](https://piccalil.li/blog/how-to-write-error-messages-that-actually-help-users-rather-than-frustrate-them/)，请查看 Amy Hupe 的精彩文章。

因为这种错误反馈非常重要，静态站点生成器 Astro 例如，[提供添加自定义 404 和 500 错误页面的能力](https://docs.astro.build/en/basics/astro-pages/#custom-404-error-page)。您可以与后端团队讨论其他可能的错误代码，以实现额外的安全措施。

但是，如果我们也想使个别部分或组件更强健，以防 JavaScript不可用呢？为此，我们可以使用 `<noscript>` 标签，它，[根据 Can I Use](https://caniuse.com/mdn-html_elements_noscript)，具有优秀的浏览器支持。这里有一个非常简单的虚构仪表板组件示例：

```markup
<!-- Shown if no JavaScript was detected -->
<noscript>
  <section aria-labelledby="user-statistics-heading">
    <h2 id="user-statistics-heading">User statistics:</h2>
    <p>Unfortunately, the user statistics could not be loaded because JavaScript is not available. Please click the “Refresh” button to try again. If the problem persists, click “Report problem” to contact our support team directly.</p>
    <button type="button">Refresh</button>
    <a href="mailto:[email protected]">Report problem</a>
  </section>
</noscript>

<!-- Shown if JavaScript was detected -->
<section aria-labelledby="user-statistics-heading">
  <h2 id="user-statistics-heading">User statistics:</h2>
  <!-- Actual code -->
</section>
```

如果 JavaScript不可用，我们仍将显示组件，但以简单明了的方式解释它们无法加载的原因。

我们为用户提供重新加载该特定组件的选项，以便他们可以自行解决问题。我们还为他们提供直接通过电子邮件联系我们的选项，如果问题仍然存在。

这里，你可以在 `<a>` 标签中添加预写的文本，例如，可以包括特定于该组件的内部错误代码在主题行中，并且有相应的正文文本。这样，他们只需点击按钮，就可以直接使用他们选择的电子邮件程序发送电子邮件。支持团队将拥有解决问题所需的所有必要信息，无需询问额外的详细信息。

无论你的用例是什么，这种模式都可以被普遍适应和扩展，并且即使其他一切都出了问题，它也能正常工作。

## CSS: `@supports` 规则

让我们继续使用我们的虚构仪表板组件。假设我们想使用 CSS 的 [`anchor()`](https://css-tricks.com/almanac/functions/a/anchor/) 函数来显示数据，[这是一个相当新的功能，具有坚实的，但不是非常好的浏览器支持](https://caniuse.com/css-anchor-positioning)。

由于这是一个可以包含多个属性的功能，我们需要检查我们想要使用的属性是否实际可用。这正是 [`@supports` CSS 规则](https://css-tricks.com/almanac/rules/s/supports/) 发挥作用的地方！这里，建议使用 [`and` 运算符](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@supports#the_and_operator)：它应该 *仅* 在 *所有* 属性都可用时使用。如果不是这样，则使用具有更好浏览器支持的更强大的 CSS。

这里有另一个虚构的、简化的例子：

```css
/* Fallback for unsupported browsers */
section[aria-labelledby="user-statistics-heading"] {
  position: relative;
}

/* Available in supported browsers browsers */
@supports
  (top: anchor(bottom)) and (position-anchor: auto) {
    section[aria-labelledby="user-statistics-heading"] {
      position: absolute;
      top: anchor(#target bottom);
      position-anchor: #target;
  }
}
```

这种方法也作为文档：一旦功能存在一段时间并且更加成熟，你可以直接在代码库中查找 `@supports` 规则，并检查它是否仍然必要，以及其回退。

## JavaScript: `if..else` 和条件三元运算符

Javascript 为我们提供了以最小的努力使前端更加健壮的能力。为了做到这一点，我们可以使用 [`if…else` 语句](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/if...else) 来检查是否特定的功能可用。例如，如果我们想使用相对较新的 [Navigation API](https://developer.mozilla.org/en-US/docs/Web/API/Navigation_API)，我们可以如下检查：

```javascript
if (window.navigation) {
  // Navigation API is supported in this browser
} else {
  // Navigation API is not supported in this browser, do something else or nothing
}
```

如果我们使用基于组件的方法，其中 HTML、CSS 和 Javascript 都包含在单个文件中，我们也可以使用 [条件三元运算符](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Conditional_operator) 来显示此组件或其部分，或者根本不做任何事情。

我们的虚构的仪表盘组件依赖于后端的数据，只有在数据成功到达前端时才有意义显示。因此，例如，我们可以这样做：

```javascript
// Option 1: Show component because JavaScript is not available:
{ userdata ?
  <section aria-labelledby="user-statistics-heading">
    <h2 id="user-statistics-heading">User statistics:</h2>
      <!-- Actual code -->
  </section> :

  <noscript>
    <section aria-labelledby="user-statistics-heading">
      <h2 id="user-statistics-heading">User statistics:</h2>
      <p>Unfortunately, the user statistics could not be loaded because JavaScript is not available. Please click the “Refresh” button to try again. If the problem persists, click “Report problem” to contact our support team directly.</p>
      <button type="button">Refresh</button>
      <a href="mailto:[email protected]">Report problem</a>
    </section>
  </noscript>
}

// Option 2: Don't show anything at all if no user data is available:
{ userdata ?
  <section aria-labelledby="user-statistics-heading">
    <h2 id="user-statistics-heading">User statistics:</h2>
    <!-- Actual code -->
  </section> :
null }
```

根据用例的不同，显示回退内容或根本不显示任何内容都是有意义的。您也可以根据所需的强壮程度定义更具体的条件。

## 结论

到目前为止，我在各个公司的经验是，回退和强壮性的话题并没有像它们应该的那样发挥重要作用。

这令人惊讶，因为正如我们所学到的，只要提前思考如果出了问题会发生什么（或不会发生什么），那么在前端实现各种安全网就不需要太多的工作。

HTML、CSS 和 JavaScript 为我们提供了特定的元素和函数来发布强壮的代码，从而避免让用户感到沮丧，并在最坏的情况下导致他们离开我们。

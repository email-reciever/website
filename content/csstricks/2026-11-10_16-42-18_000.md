CSS优化是一个欺骗性的话题。 一方面，感觉就像是简单的东西，我们应该已经拥有所有的工具——尤其是在缩小方面。 另一方面，我们已经利用了 CSS 优化的“一切”的想法可能被认为是幼稚的。 对于一种几乎每天都在发展的语言，这样的说法看起来很难辩护。

在本文中，我想选择一种至少[18 years old](https://meiert.com/blog/css-organization-and-efficiency/)的技术——UDJO，或者“只使用一次声明”。

知道较旧的来源吗？ 请评论！

该技术的灵感来自于 [“don’t repeat yourself”](https://webglossary.info/terms/dont-repeat-yourself/) 原理，因为它通过识别和减少（如果不是消除）声明重复来起作用。

因此，如果有 `display: flex` 之类的东西出现两次或更多次，它会在一项规则中进行核对：

.示例{
显示：弹性；
}
    
.样本{
显示：弹性；
}

…变为：

.示例，
.样本{
显示：弹性；
}

该技术的结果取决于重复数据删除的智能程度以及选择器的长度。 Intelligence 确定 UDJO 是否会导致 _Actual_ 可维护性优势——声明的更改是否真的可以对所有附加的选择器进行？ 选择器长度会影响文件大小节省的大小。

如果您有兴趣，我关于 [“DRY CSS”](https://meiert.com/blog/dry-css/) 的文章更详细地描述了这些机制。 这里的问题是：_UDJO 在今天仍然有效并且仍然相关吗？

[](#better-deduplicating-through-tooling)通过工具进行更好的重复数据删除
------------------------------------ --------------------------------------

然而，当我们尝试回答这个问题时，我们最终会遇到一个问题：当站点很复杂并且它们的样式表声明之前没有被删除重复时，UDJO 可能需要大量的工作。

为了节省一些时间，我为这项工作构建了工具。 虽然它看起来不像手动通过和测试样式表那样全面，但工具可以捕捉到_some_重复似乎很现实。

跳过前进，我创建了 [CSS Dedup](https://github.com/j9t/css-dedup) 不仅是为了识别重复，而且还要对可以安全优化的内容进行重复数据删除（CSS 重复数据删除有 [some documentation](https://github.com/j9t/css-dedup#how-it-works) ，但本质上，重复数据删除会影响选择器位置，这是 [how the cascade works](https://www.w3.org/TR/css-cascade-5/#cascade-order) 的一部分）。 那么，这给了我们一些数据：

[](#is-there-anything-to-deduplicate-in-modern-css)在现代CSS中有什么要去重的吗？
--------------------------------------------- ---------------------------------------------

第一批，我任意挑选20个网站进行分析。 然后，我使用 CSS dedup 来检查如果我们对看似 _provably_ 安全的东西进行重复数据删除，文件大小会发生什么变化，以及看起来 _probably_ 安全的内容，但前提是它导致文件大小节省。

我选择了这两个选项来提供重复数据删除的“自然”结果，但一位网站所有者可能最感兴趣的是减少重复，同时也减少转移大小。 毕竟，作为CSS优化技术的UDJO可以提高可维护性和性能。

我们能从中看出什么？

*   在所有**20个案例中，我们都能够减少声明的重复。
*   在 **18 案例**中，减少声明重复会导致文件大小增加（由于选择器重复和选择器比保存的声明长）。
*   然而，在**所有情况下，可以以也减小文件大小的方式减少声明重复(仅凭借助于这种节省的样式表)。

对于 Udjo 今天是否仍然有效的问题，这应该是一个_是的。 它甚至可以节省文件大小。

这些数据显示了什么？

*   与组织一样，在每个站点上都有一些可以安全删除的声明重复。
*   在 5 例中（50% 与 90% 相比），减少重复会导致文件大小增加。
*   然而，在所有情况下，重复也可以以导致文件大小节省的方式减少重复。

扩展此分析以获取更多样本并调查样本之间的差异将是有价值的，但是对于使用较短的选择器的网络专业人员来说，这可能会使 _more_ 能够从 UDJO 中受益。

[](#on-the-effectiveness-of-udjo-as-a-css-optimization-technique)关于UDJO作为CSS优化技术的有效性
--------------------------------------------------------- -----------------------------------------------------------

正如一开始所提到的，UDJO 的有效性通常取决于重复的类型以及选择器的长度。

然而，这可以进行管理：虽然像 CSS Dedup 这样的工具在声明用例之间没有区别（因此是钝的），但可以对其进行配置以获得性能优势。

正如本文所采用的数据所表明的那样，在大多数情况下可以节省文件大小。 考虑到这是基于安全更改，这意味着低成本性能优化向量——尤其是在应用于最小化输出时。 对使用进一步压缩（例如 gzip/brotli）的使用仍然是一个好主意，但从表面上看，重复数据删除显示了它如何减小 CSS 的大小。

对于一般对 CSS 优化、可维护性和性能感兴趣的人来说，UDJO 应该是 CSS 整体方法的一部分。 但由于该技术一直是小众的，并且由于工具是新的，因此我邀请您查看、测试和探索此向量。 似乎很难说我们已经达到了我们可以在多大程度上进行 CSS 优化的天花板。

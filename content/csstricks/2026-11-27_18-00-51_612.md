# 使用 light-dark() 而不出错

![](https://secure.gravatar.com/avatar/a8e040142716a4b44d014d80fbcf99c635b1d8faabfe469b6954a8ef2f168595?s=80\&d=retro\&r=pg)

By [Geoff Graham](https://css-tricks.com/author/geoffgraham/) on Nov 27, 2026

我老实说，没有想到会被 `light-dark()`“抓住”——尤其是当我在这个网站上大量使用它时，但 [Martin Underhill 解释](https://www.tempertemper.net/blog/using-light-dark-without-getting-caught-out)：

> 如果没有回退，通常不支持 `light-dark()` 的浏览器会在浅色模式下使用黑色文本和白色背景，在深色模式下使用白色文本和深灰色背景。它们不是我想要的确切颜色，但我的网站看起来还不错。
>
> 再次强调，这样做是有风险的，所以要彻底测试。

像 Martin 一样，我最初尝试基于媒体查询来嗅探用户首选项并实现颜色主题。但是，每次写 `prefers-color-scheme` 都变得非常繁琐。我是说，这完全是开发体验的问题。我也记得 [Sara Joy 写的那篇文章](https://css-tricks.com/come-to-the-light-dark-side/)，她鼓励我们跳入 `light-dark()` 的世界，我认为这是一个很好的建议。

做到这一点时，我遇到了另一个开发体验的烦恼：为每个 `light-dark()` 写两个颜色值。CSS 变量当然可以帮助，但即使这样，也让我感到疲惫。这可能更说明了我自己，而不是这个特性，但我不再纠结。所以，我将 Martin 的过程进一步抽象，以抽象所有事情：

```css
:root {
  --gray-1: #eaeaea; /* Light */
  /* ... */
  --gray-10: #111; /* Dark */

  --text: light-dark(var(--gray-1), var(--gray-10));
}

.article-content {
  color: var(--text);
}
```

很好，至少对于我懒惰的倾向来说。但是我遇到了另一个问题，因为有时文本需要朝相反的方向移动。继续抽象。我可以定义背景变量，它通常是文本的对比色：

```css
:root {
  --gray-1: #eaeaea; /* Light */
  /* ... */
  --gray-10: #111; /* Dark */

  --text: light-dark(var(--gray-1), var(--gray-10));
  --surface: light-dark(var(--gray-10), var(--gray-1));
}

.widget-content {
  color: var(--surface);
}
```

有效，但在控制 `color` 的属性上使用一个叫做“surface”的帮助函数仍然让我感到不舒服。我可能很懒，但我对语义有一点强迫症。因此：

```css
:root {
  --gray-1: #eaeaea; /* Light */
  /* ... */
  --gray-10: #111; /* Dark */

  --text: light-dark(var(--gray-1), var(--gray-10));
  --text-reverse: light-dark(var(--gray-10), var(--gray-1));
}

.article-content {
  color: var(--text-reverse); /* Light then dark */
}

.widget-content {
  color: var(--text-reverse); /* Dark then light */
}
```

…其中“reverse”意味着它与正常的“light-dark”调用相反，且“dark”值首先被调用。但即使这样，对于我的大脑来说仍然太复杂了，因为现在我需要记住多个令牌，如果我想让事情变得超级语义化：

```css
:root {
  --gray-1: #eaeaea; /* Light */
  /* ... */
  --gray-10: #111; /* Dark */

  --text: light-dark(var(--gray-1), var(--gray-10));
  --text-reverse: light-dark(var(--gray-10), var(--gray-1));

  --surface: light-dark(var(--gray-1), var(--gray-10));
  --surface-reverse: light-dark(var(--gray-10), var(--gray-1));
}

.article-content {
  background-color: var(--surface); /* Dark then light */
  color: var(--text-reverse); /* Light then dark */
}

.widget-content {
  background-color: var(--surface-reverse); /* Light then dark */
  color: var(--text-reverse); /* Dark then light */
}
```

所以我采用了一个更为通用的抽象：

```css
:root {
  --gray-1: #eaeaea; /* Light */
  /* ... */
  --gray-10: #111; /* Dark */

  --light-dark: light-dark(var(--gray-1), var(--gray-10));
  --dark-light: light-dark(var(--gray-10), var(--gray-1));
}

.article-content {
  background-color: var(--dark-light); /* Dark then light */
  color: var(--light-dark); /* Light then dark */
}

.widget-content {
  background-color: var(--dark-light); /* Dark then light */
  color: var(--light-dark); /* Light then dark */
}
```

完美吗？不是。但我对此还是比较满意的。

回到 Martin 和回退机制，他采用了一种经典的级联安全措施：

```css
color: black;
color: light-dark(black, white);

background-color: white;
background-color: light-dark(white, black);
```

他是绝对正确的，我也应该这样做。也许我会这样做，但我不禁想到，`light-dark()` 回退参数将会很好。当然，这只是随意的想法：

```css
color: light-dark(var(--dark-light), var(--light-dark) / var(--dark-light));
```

现在我们变得啰嗦了。但一般来说，回退机制也是如此。的确，Martin 提问，转移到 `light-dark()` 是否值得，考虑到需要思考回退机制。它真的比媒体查询更高效吗？他的字节节省是微不足道的。我决定比较在 CSS-Tricks 上会有什么不同：

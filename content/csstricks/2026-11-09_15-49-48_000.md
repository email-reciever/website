在过去的几周里，我一直在抨击更新这个网站的设计。 是时候得到一层新的油漆了，对吧？ CSS-tricks 的最后一个版本是在 _5 年前推送的。 这在网络（和狗）年份是古老的。

这不像该网站一直坐着。 我们推动了许多更改并提供了新功能，[particularly since 2024](https://css-tricks.com/thank-you-2024-edition/)，但我们从未真正将画笔从存储中取出。

现在，在有一个 _“Things not looks not look not thaaaat 不同”之前，我想说我很少喜欢完整的重建，并且倾向于倾向于迭代版本。 新的 V20 主题就是我所说的值得版本颠簸的迭代汇总。

让我们回顾一下最著名的更新，看看为什么。

[](#excavating-ghosts)挖掘鬼魂
--------------------------------------

首先，一些最大的变化是你_没有看到的。 正如您可能想象的那样，该网站在 19 年中承载了大量作品。 我决定挖掘这个主题，肯定找到了一些鬼魂要破产。

例如，全局编译的 JavaScript 文件保留了一些不再使用的脚本。 诸如在我们开始自我托管帖子之前处理嵌入式新闻通讯之类的东西。 在我们有适当的 HTML `<details>` 之前，有一些遗物专门针对 Flexbox 指南来处理切换。 有一个 jQuery lazy-loader 现在被 WordPress Core 很好地覆盖了。 我们有一些用于投放第三方广告的脚本，因为我们是自托管广告，这些广告不再需要。 诸如此类的事情。 整个 JavaScript 的精心从 151.6 KB（55.3 KB gzipped）调整到 133.8 KB（48.1 KB）。

我还决定正式退休 CSS-Tricks 论坛。 我们将其置于“存档模式”中，例如 2018 年。这些讨论对于今天的讨论来说都不是特别有价值的，因为它们是 10 多年前的，所以我停用了为它提供动力并清除数据库的 BBPress 插件…… 来自 ol' 数据库的 400 MB，更不用说它允许我从主题中删除几个自定义模板。

一路上有更多的鬼魂被破坏，可以肯定的是，仍然有一些潜伏在周围的鬼魂。 但是现在在主题目录中搜索它就不那么可怕了，从现在开始，进一步的清理应该会容易得多。

[](#modern-dev-tooling)现代开发工具
----------------------------------------

是的，是的，如果你还在吞咽，请举手。 我们是🙋‍♂️。 这本身并不是一件坏事，但在这段时间内保持固定状态并不是最大的。 我认为我们的工作流程比以前更现代，即使还有增长的空间。 对相关提交的smattering：

*   通过哈士奇+ lint-staged pre-commit hook强制执行
*   为字母CSS属性添加了StyleLint
*   添加了GitHub Actions Build Check
*   缓存破坏从重写源文件切换到 `filemtime()`

多年来，我每次启动新终端时都会忍受同样的错误。 那些已经消失了，事情运行得非常干净，更不用说很快了。 这里非常开心。

[](#security-pass)安全通行证
------------------------------

哦，这是每个人最喜欢的工作，对吧？！ 除了能够在这里和那里发现和修复一些未转义的自定义字段呼叫外，我决定请克劳德帮助我进行整体审计。 我提示它查看最近的 WordPress 安全版本说明，并确定主题可以强化以符合 WordPress 正在执行的操作的区域。

_哇，你用过AI？_是的，我确实做到了。 但是对于这样的事情，它可能是我的小地鼠，让我有更多的时间去做我最擅长的事情：前端。 我仍然可以根据输出建议自己制作大部分补丁，但是很高兴对我显然不是专家的事情进行直觉检查，例如安全性。

[](#sass-rewrite)SASS 重写
-----------------------------

我仍然非常喜欢和喜欢 sass。 我的意思是，是的，我想在任何地方都直截了当的香草 CSS，但我不能特别让自己远离部分内容。

前面的主题有一个相当不错的“平面”结构——很少的部分目录和大多数东西都在同一个顶级来源中。 完全酷。 但是像我这样的组织疯子（你应该看到我的房子）必须有一个地方让一切都可以居住。 它并不完美，但我很高兴我能够在不使建筑在此过程中平整的情况下组合在一起。

![](https://css-tricks.com/wp-content/uploads/2026/11/Screenshot-2026-11-04-at-3.35.39-PM.png)

有一些妥协。 就像，`/header` 应该真的在 `/layout` 中。 不过，订购真的很重要，我的一些理想根本不可能。 我希望最终在某种级联层结构中工作。

我很高兴看到 CSS 的整体尺寸在此过程中下降。 它从 180 kb (31.7 kb) 到 169 kb (24.6 kb)。 意义不大，但也不是_不重要。 我必须做一些棘手的事情来欺骗我的方式，比如将我将要谈论的所有表单样式提供到一个单独的 `forms.css` 文件中，并仅在 WooCommerce、Restrict Content Pro 和 Gravity Forms 的页面上提供服务。

[](#a-sort-of-design-system)一种设计系统
-----------------------------------------------

你开始注意到趋势了吗？ 我们仍在谈论相当隐形的工作。 CSS-tricks 有如此多的角落和缝隙，几乎不可能让事情全面一致。 但由于这些角落和缝隙，如此多的固定值、神奇的数字、一次性的风格和旧的实用程序都隐藏着。 我决定在重组 Sass 的同时解决其中的很大一部分。

例如，现在有语义设计令牌可以抽象出一种颜色。 这么多灰色，让我告诉你。 现在有一个可维护的调色板在整个过程中被引用。 与字体、字体样式和字体大小相同。 与填充和边距相同。 在“系统”层面做出改变的感觉要好得多，因为它相信改变在任何地方都能生效。

但这也是一些清晰可见的变化发生的地方！ 最值得注意的是，链接样式到处都是一致的，只有少数预期和维护的变化。 它不仅在视觉上更令人愉悦，而且在整个过程中都提高了可访问性，因为继承的样式默认为不仅仅依赖于颜色或不透明度变化的适当视觉线索。

哦，还有我最喜欢的作品？ 表格和表格都已重做。 在 WordPress 主题中很难做到这一点，这些组件并不总是来自一种来源。 例如，表单可能来自 Gravity Forms、WooCommerce 或限制 Content Pro 插件中的任何一种，它们都有自己的样式表。 重置这些使我能够在所有这些情况下带来一定程度的和谐。

![](https://css-tricks.com/wp-content/uploads/2026/11/css-tricks-20-tables.webp)

[](#theme-toggle)主题切换
-----------------------------

好吧，更直观的东西。 这是CSS-Tricks第一次拥有不止一种配色方案！ 它当然可以在很久以前完成，但我也认为，在过去 8 年左右的时间里，这种设计并没有真正要求进行明暗切换。 无论您的主题偏好如何，它都是明暗元素的完美结合，将两全其美。

但我不得不去刺，对吧？ 尽管内容是以白色背景为背景的，但该网站主要是黑暗的，因此我将事物视为已经存在的“黑暗”模式。 结果是一个奶油般的轻盈主题，主要只是背景和组件样式的变化。 我用我从 [the recent “toggle” debate](https://css-tricks.com/dark-mode-toggles-two-states-are-enough/) 学到的一些东西来处理系统、黑暗和浅色主题，只需一个切换即可。

![](https://css-tricks.com/wp-content/uploads/2026/11/css-tricks-20-theme-toggle-1.webp)

没有改变的是您在文章等内容中看到的主要内容容器。 即使在“黑暗”模式下，那已经是白色的，我不相信在白色和黑色之间切换它是最好的方法。 肯定的东西在雷达上。

[](#jawbreaker-texture)Jawbreaker 纹理
----------------------------------------

我希望你认为该网站的页眉和页脚很可爱。 是的，可爱。 这就是我在添加一系列彩色点作为背景时的目的。

![](https://css-tricks.com/wp-content/uploads/2026/11/css-tricks-20-header.webp)

有点像微妙的糖果质地，对吧？ 还是一群五颜六色的星星？ 我不知道，但我称它为“Jawbreaker”，因为没有更好的术语，因为它让我想起了我小时候喜欢的 Jawbreaker 糖果。 命名仍然很糟糕。

这都是同一个 SVG 的一部分。 我真的，真的（_really_）想要`random()`\-ly在周围定位点，但这会在标记中占用很多空的单个元素（例如，`<i>`）。 不是我最喜欢的。 所以，我在php中生成`<circle>`元素：

<?php echo csstricks_jawbreaker_svg(
'计数' => 90，
'种子' => mt_rand(),
'size_min' => 2,
'size_max' => 5,
)); ?>

是很多SVG…

![](https://css-tricks.com/wp-content/uploads/2026/11/jawbreaker-texture.png)

我真的，真的很想 `random()`\-ize 所有的东西，但是在每个 `<circle>` 上内联随机坐标是要走的路。 同样处理设置 `fill` 的内联样式，以及纹理中每个圆圈的大小，以及在使它们进出闪烁的微妙动画上设置 `--delay` 和 `--dur` 的变量。

我将不得不考虑使用 `<defs>` 或其他方式生成 SVG，因为该模式在页脚中也重复了。

这也贯穿了 404 页面：

![](https://css-tricks.com/wp-content/uploads/2026/11/css-tricks-20-404-scaled.png)

对 404 以前的情况进行了更新的游戏，只是不是作为光栅图像。

[](#blobs-blobs-blobs)斑点，斑点，斑点
----------------------------------------

如果您的浏览器支持 `border-shape` 和 `random()`（我认为只有 Chrome），那么主页会在作者头像网格后面为您提供一个 blobblob 形状。 将它悬停，它得到，你知道，甚至是 Blobbier。

它需要一个我称之为`.gradient-card`的现有模式：

.gradient-card {
/* 基本样式 */
}

…并在组件的 `:before` 伪上设置渐变：

.gradient-card {
/* 基本样式 */
    
&:之前{
内容：“”；
背景：线性渐变（
130度，
#FF7A18 0%，
明暗(#FF2D6B, #AF002D) 41.07%,
明暗(#00BFAE, #319197) 76.05%
);
边界半径：12px；
z 指数：1；
}
}

它位于半透明的 `:after` 伪下方，允许 `:before` 的渐变通过 smidge 显示：

.gradient-card {
/* 基本样式 */
    
&:之前{
/* 等等 */
}
    
&:在 {
内容：“”；
背景：浅色（color-mix（in sRGB，白色 72%，透明），#000）；
盒子阴影: 插图 0 2px 16px
明暗（rgba(0, 0, 0, 0.12), rgba(0, 0, 0, 0.6));
边界半径：8px；
z 指数：2；
}

不同的 `border-radius` 值允许 `:before` 在外部流血，给人的印象是整个交易的边界。 这是基本的形状。 `border-shape` 是事情变得斑驳的地方：

.gradient-card {
/* 等等 */
    
&:之前, &:在 {
边框：1px 实心透明；
边界形状：var(--blob-shape-static);
clip-path: var(--blob-shape-static);
不透明度：0.5；
}
}

那些变量？ 它们被映射到 `shape()`s。 我从[Temani Afif’s blob generator](https://css-generators.com/blob/)中抓住了第一个：

--blob-shape-static：形状（
从 50% 3% 开始，
曲线至 65.86% 11.71% 与 59.41% 2.7%，
平滑至 72.37% 27.63%，
平滑至 77.43% 38.64%，
平滑至 88% 50%，
平滑至 92.79% 67.72%，
平滑至 81.37% 81.37%，
/*等
);

它被称为“静态”，因为这是默认状态。 将鼠标悬停或聚焦在组件上，它将这些点与形状的“悬停”版本交换出来：

--blob-shape-hover：形状（
从 50% 3% 开始，
曲线到 var(--blob-point-1-x) var(--blob-point-1-y) 的曲线为 59.41% 2.7%，
平滑至 72.37% 27.63%，
平滑至 77.43% 38.64%，
平滑到 var(--blob-point-4-x) var(--blob-point-4-y)，
平滑至 92.79% 67.72%，
平滑至 81.37% 81.37%，
平滑到var(--blob-point-7-x) var(--blob-point-7-y)，
平滑至 50% 79%，
/* 等等 */
);

那些变量？ 它们被映射到 `random()` 值：

--blob-point-1-x：随机（62.86%，68.86%）；
--blob-point-1-y：随机（8.71%，14.71%）；
--blob-point-4-x：随机（85%, 91%）；
--blob-point-4-y：随机（47%, 53%）；
--blob-point-7-x：随机（60.22%，66.22%）；
--blob-point-7-y：随机（78.93%，84.93%）；
/* 等等 */

因此，每个页面加载时的悬停状态是不同的。 我们在两者之间进行动画处理：

&: 悬停,
&:focus-inside {
&:之前,
&:在 {
边界形状：var(--blob-shape-hover);
clip-path: var(--blob-shape-hover);
    
@media（首选-reduced-motion：无偏好）{
动画：缩小 1.5s var(--ease-out-3) 无限交替；
}
}
}

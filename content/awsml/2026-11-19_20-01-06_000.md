Amazon Bedrock AgentCore Harness 添加了 Strands 线束默认设置、内置工具和生命周期钩子
==================================================。 ====================================================

在构建 AI 代理时，选择模型只是第一步。 代理仍然需要工具、完成工作的说明、在长时间会话中管理上下文增长的方法，以及在执行任何后果性操作（例如发出退款）之前进行 Guardrails。

我们正在升级 Amazon Bedrock AgentCore Harness 以使用我们今年早些时候发布的开源代理 Harness 以使用 Apache 2.0 许可证。 AgentCore Harness 还引入了 Lifecycle Hooks，因此您可以在代理循环中的定义点应用自己的确定性检查和通知。

通过此次升级，依赖托管默认值的代理程序获得了推荐的模型、面向任务的系统提示、自动提示缓存（最初用于 Amazon Bedrock 上的人性模型）和主动上下文管理。 他们还获得了用于规划、Web 检索、文件系统访问、上下文卸载和任务委派的其他内置工具。 这为代理在长时间任务中提供了更大的功能，允许他们跟踪子任务、减少上下文窗口的使用和委派工作。 借助 Hooks，您可以通过在特定生命周期检查点运行确定性代码将非确定性 AI 行为转变为可预测、安全和受管理的工作流。

没有新的资源类型或集成可以采用。 您会自动在您已使用的 AgentCore 线束中获取两个更新。

在 AWS 上的 Strands 功能
-----------------------------

[Strands harness](https://strandsagents.com/docs/user-guide/harness/) 提供了包含推荐说明、工具和上下文管理的组装代理基础。 [Amazon Bedrock AgentCore harness](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness.html) 将该基础作为托管 AWS 服务运行。 结果是生产级默认代理，不需要您自己组装和操作线束或其基础设施。

您不需要配置计算、捆绑和托管代理循环、管理会话扩展或操作工具执行基础设施。 每个会话在 AgentCore 运行时中的安全、内核隔离的 MicroVM 中运行，该功能是 Amazon Bedrock AgentCore 的功能，具有托管计算、扩展和高可用性。

AgentCore 通过将线束连接到生产代理所需的服务来实现这一目标，包括会话持久性、流式响应、使用元数据、可观察性、AgentCore 内存、身份、网关、浏览器、代码解释器和客户提供的容器。 您保留对模型、指令、工具、权限和生命周期策略的控制权，同时 AgentCore 管理底层执行环境。

更有能力的管理线束
------------------------------

当您使用其托管默认值时，Harness 现在可提供更强大的体验：

*   ** 当前推荐的型号。** 当您省略模型时，Harness 使用推荐的默认模型，随着新模型的发布而演变，始终保持您的线束是最新的。 明确的线束级和每次调用模型配置继续优先。
*   **面向任务的指令。 默认系统提示随着时间的推移而改进，以支持最新的线束行为。
*   ** 自动提示缓存。 使用相同的提示符和工具表面进行重复调用可以使用价格较低的缓存读取令牌，从而减少输入处理的延迟和成本。
*   **主动上下文管理。** 默认情况下，一旦上下文窗口达到可配置的阈值，Harness 会总结较旧的对话转动，同时保留最近的上下文。 以这种方式保持上下文的精简有助于在 [about 34% lower token cost than other leading harnesses](https://strandsagents.com/blog/we-ran-94000-trials-to-measure-the-cost-of-harness-choice/) 处运行。
*   **上下文卸载。** 大工具结果可以移出立即模型上下文。 代理接收预览并在需要时检索完整的结果，减少重复的上下文使用，而不会失去对数据的访问权限。
*   **跨调用计划。** `todo_write` 工具维护一个结构化的任务计划，可以在同一会话中的后续调用中恢复，包括在会话汇总之后。
*   **专注的委派。** `subagent` 工具将独立任务委派给新工作者，并将结果返回给父代理。 worker 是调用内部的，而不是单独管理的线束资源，共享调用限制和工具调用生命周期挂钩。
*   **Web 检索。** `web_fetch` 工具从指定的网页中检索内容，为您的线束提供最新的外部上下文。
*   **Granular 文件系统访问。** 使用单独的 `read`、`write` 和 `edit` 工具，您可以仅授予代理所需的粒度文件系统功能。

客户提供的模型上下文协议 (MCP) 服务器、AgentCore Gateway（Amazon Bedrock AgentCore 的功能）、浏览器、代码解释器、内联函数、技能、内存和客户提供的容器继续通过现有的线束接口工作。

默认推荐，需要时可配置
--------------------------------------------

Harness 管理其默认值，以便使用它们的代理程序接收当前 AgentCore 推荐的经验，以改进模型、说明、上下文管理和内置功能。

显式配置始终优先：

*   配置模型ID以继续使用特定的模型。
*   配置 `systemPrompt` 以完全替换受管系统提示符。
*   配置 `truncation` 以保留特定的上下文管理策略。
*   列出单个 `allowedTools` 选择器以保持固定的刀具表面。

当 `allowedTools` 被省略或设置为 `["*"]` 时，Harness 提供了当前推荐的内置工具集。 由于该集合可以随着时间的推移获得功能，因此具有固定安全性或功能边界的应用程序应仅列出他们需要的工具。

例如，以下配置允许只读文件系统访问和 Web 检索，而无需授予 shell 访问权限或文件修改：

{
“允许工具”：[
“阅读”，
“web_fetch”
]
}

使用生命周期钩子管理后果性操作
---------------------------------------------

使用 Lifecycle Hooks，您可以在代理循环中的定义点运行自己的确定性代码。 例如，AWS Lambda 函数可以允许或拒绝请求或工具调用，Amazon Simple Notification Service (Amazon SNS) 主题或 Amazon EventBridge 事件总线可以接收通知以记录活动或启动异步工作流。

Harness 支持四个生命周期事件：

**活动**

**运行时**

** lambda 拒绝的效果**

`before_invocation`

在代理处理请求之前

用 `hook_stopped` 停止调用

`before_tool_call`

在模型提出一个工具调用和执行之前

跳过工具调用。 代理循环继续

`after_tool_call`

存在工具结果后

保留结果并在进一步推理之前停止

`after_invocation`

调用完成后

报告决定。 已流式输出无法撤回

只有 Lambda 钩子可以更改代理循环。 它们同步运行并返回允许或拒绝，有一个可选的原因。 SNS 和 Amazon EventBridge 钩子是通知，不会阻止代理循环。

例如，客户支持代理可以自行调查订单，而 `before_tool_call` 钩子会在退款工具运行之前根据批准限制检查每一次退款。 以下配置将 Lambda 函数附加到线束：

[
{
“BEFORETOOLCALL”：{
"名称": "refund_policy",
“目标”：{
“兰布达”：{
"ARN": "ARN:AWS:Lambda:US-West-2:123456789012:功能:退款政策",
“超时秒数”：10，
“失败模式”：“拒绝”
}
}
}
}
]

该函数在钩子有效负载中接收建议的工具调用并返回一个决策：

def lambda_handler（事件，_context）：
工具 = 事件["上下文"]
如果 tool["toolname"] == "issue_refund" 和 tool["toolinput"]["amount"] > 500:
return {"decision": "deny", "reason": "退款超过 500 美元的自动批准限制"}
返回 {"决定":"允许"}

当函数拒绝来电时，线束跳过退款，代理继续，因此它可以告诉客户请求已升级。 每个决定也以`hookEvent`的形式出现在`InvokeHarness`响应流中：

{
“胡克文”：{
"名称": "refund_policy",
"类型": "before_tool_call",
“决定”：“拒绝”，
“原因”：“退款超过 500 美元的自动批准限制。”
}
}

钩子也适用于子代理。 当代理委派任务时，每个工具调用子代理通过相同的 `beforeToolCall` 和 `afterToolCall` 钩子运行，因此委派不能绕过您的退款政策。 调用级别的钩子 (`beforeInvocation`, `afterInvocation`) 在整个调用中运行一次。

用 `CreateHarness` 或 `UpdateHarness` 配置钩子。 如果 Lambda 函数超时或返回错误，则该钩子将应用其 `failureMode`，默认为 Deny。 有关超时、有效负载字段和上下文限制，请参阅 [Amazon Bedrock AgentCore Developer Guide](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness-lifecycle-hooks.html) 中的生命周期挂钩。

要查看每个事件和目标类型协同工作，请尝试 Amazon Bedrock AgentCore [samples repository on GitHub](https://github.com/awslabs/agentcore-samples/tree/main/01-features/01-harness/02-use-cases/05-refund-desk-hooks) 中的退款服务台示例。 六步导览显示所有四个生命周期事件以及 AWS Lambda、Amazon SNS 和 Amazon EventBridge 目标。 它还显示了客户端提供的内联函数结果的验证以及 `failureMode` 拒绝和允许的差异。

使用 AgentCore CLI 运行多代理研究协调器
---------------------------------------------------------

创建线束需要一个命令。 您命名并设置所需的说明、上下文策略和限制。 此示例创建了一个研究协调员：具有面向任务的系统提示和基于摘要的截断的线束。 在一次调用中，它作为子代理运行研究人员、合成器和审阅者，并返回一份综合报告。 您可以在不配置基础架构或自行连接委托的情况下获得多代理编排和上下文管理。

`agentcore harness` 命令直接调用 Harness API，因此您不需要 CLI 项目或部署步骤。 使用 npm 安装 Amazon Bedrock AgentCore 的功能 AgentCore CLI：

npm install -g @AWS/AgentCore

CLI 使用您的默认 AWS 凭据。 它没有 `--profile` 标志，因此如果您想要特定的配置文件，请设置 `AWS_PROFILE` 环境变量。 将样本中的协调员的说明保存为工作目录中的 `system_prompt.md`。

### 创建线束

此命令通过协调器的系统提示符，这是一种摘要策略，它使 30 条最新消息在对话的增长中保持不变，并且对整个工作流程的限制都足够高。 因为它省略了模型、内存和执行角色，所以 Harness 使用当前的 AgentCore 推荐模型和托管内存，CLI 在 IAM 中为您创建了一个执行角色。

harness_id=$(AgentCore 线束创建 --region us-west-2 --json \
--名称研究协调员\
--system-prompt "$(cat system_prompt.md)" \
--truncation '{"策略":"summarization","config":{"summarization":{"summaryratio":0.3,"PreserverEcentMessages":30}}'\
--max-iterations 100 \
--timeout-seconds 3600 \
| jq -r '.Harness.HarnessId')

创建是异步的。 等待创建完成。 最后一个命令应该打印 `READY`：

while [ "$(agentcore harness get --region us-west-2 --id "$harness_id" --json | jq -r '.harness.status')" = 创建 ]; 做睡觉 10； 做过
    
AgentCore 线束得到 --region us-west-2 --id "$HARNESS_ID" --json | jq -r '.harness.status'

### 发送提示

使用新的会话 ID 调用您的线束。 从一个基本问题开始。 协调员直接回答它，而不是调用其子代理：

session_id=$(UUIDGEN)
AgentCore 线束调用 --region us-west-2 \
--id "$HARNESS_ID" \
--session-id "$session_id" \
--prompt “AI当前的热门话题是什么？”

然后在同一会议上索取完整的研究报告。 协调员按顺序计划工作并委派给研究人员、合成器和审稿人。 如果审阅者要求它，它最多运行一个修订周期，并交付最终报告。 重用会话 ID 在同一环境中继续对话。

AgentCore 线束调用 --region us-west-2 \
--id "$HARNESS_ID" \
--session-id "$session_id" \
--prompt “执行一份关于数据如何塑造科技行业创新的完整研究报告。使用专业的子代理来完成这项任务。在最终输出中，清楚地说明每个子代理负责的部分，然后是他们的具体发现。”

使用 `--prompt` 时，CLI 将完成的转录作为 JSON 打印。 研究运行大约需要 10 到 15 分钟。 要跟随它的工作，请省略 `--prompt`，然后 CLI 会打开交互式聊天。

Python (BOTO3) 中的相同示例，包括完整的系统提示，在 GitHub 上的 AgentCore 示例存储库中可用。

### 清理

完成后删除线束。 除非您通过 `--delete-managed-memory false`，否则这也会删除其托管内存。 CLI 创建的执行角色将保留在您的帐户中，因此如果您不再需要它，请在 IAM 控制台中删除它。

AgentCore 线束删除 --region us-west-2 --id "$HARNESS_ID"

推出和兼容性
--------------------------

11 月 11 日，AgentCore Harness 开始将 Strands Harness 支持的经验推出给新的和现有的线束。 无需客户操作。

您明确提供的配置保持不变。 省略模型、系统提示或 `truncation` 配置或使用 `allowedTools: ["*"]` 的线束接收升级的托管默认值。

如果您的应用程序需要固定的行为或固定的能力边界，请明确配置这些设置。

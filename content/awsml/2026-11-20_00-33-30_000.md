在 Amazon Bedrock 上使用带有模型的 Kimi Code CLI
================================================

[Kimi Code CLI](https://github.com/moonshotai/kimi-code) 是来自 Moonshot AI 的开源编码代理，Kimi 系列开放式基础模型的创建者。 以前，在 [Amazon Bedrock](/bedrock/) 上将 Kimi 代码与模型一起使用意味着使用 Amazon Bedrock API 密钥配置通用连接“提供者”。 对于许多 AWS 客户，这意味着引入额外的凭证来获取和保护。

借助 v2.7.0，Moonshot AI 为 CLI 添加了原生基岩提供商。 您现在可以将代理配置为使用您的标准 AWS 凭据链，包括命名配置文件和单点登录 (SSO)，而不是创建和管理单独的 API 密钥。

在这篇文章中，我们将向您展示如何使用现有 AWS 凭据将 Kimi Code CLI 连接到 Amazon Bedrock 上的模型。 我们以[Kimi K3.1 Pro Highspeed](/blogs/machine-learning/introducing-kimi-k3-1-pro-on-amazon-bedrock/)为例，支持流式化、可配置推理、图像输入和客户端工具调用。

有什么新东西
-----------

Amazon Bedrock 为来自领先供应商的一系列开放和专有模型提供按令牌付费推理，可通过 [standard APIs](https://docs.aws.amazon.com/bedrock/latest/userguide/apis.html) 获得。 处理保持在 AWS 数据边界内，详见用户指南的 [Data protection](https://docs.aws.amazon.com/bedrock/latest/userguide/data-protection.html) 部分。 [model cards](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards.html) 详细说明了每个模型支持哪些 API 和功能。

在旧版本的 Kimi Code CLI 中，您可以通过 `type = "openai"` 或 `type = "openai_responses"` 的提供商连接到 Amazon Bedrock。 这些分别使用 OpenAI 兼容的 [Chat Completions](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-chat-completions.html) 或 [Responses](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-responses-api.html) API。 这种方法要求您设置区域 `base_url` 并提供 [Amazon Bedrock API key](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys.html)。 关键可以是短期或长期，但它是您获得和管理的单独凭据。

本地提供程序更改该设置：

*   **使用您现有的 AWS 身份验证工作流程。** `bedrock` 提供程序可以通过标准 [AWS Command Line Interface (AWS CLI)](/cli/) 凭据链解决临时凭据。 您可以使用默认链或选择命名配置文件，包括由 SSO 支持的配置文件。
*   **如果需要，覆盖每个模型的协议。** 提供商从模型ID中推断出API格式和区域端点，但您可以根据本文的“覆盖端点URL和协议”部分中的详细信息进行更改。

AWS 建议使用短期凭据而不是长期凭证。 此新路径减少了对手动管理的 API 密钥的依赖，但它不会改变您保护 AWS 凭证和范围权限的责任。

这个怎么运作
-------------

本机提供程序分四个步骤处理身份验证和请求路由：

1.  **解析 AWS 凭据。 您可以设置 `AWS_PROFILE` 以选择特定的 [named profile](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html#cli-configure-files-using-profiles)。
2.  **生成一个短暂的承载令牌。 您不需要在 Kimi 代码 `config.toml` 中放置任何 AWS Access 密钥或手动生成的 Amazon Bedrock 密钥。 但是，如果您提供，则通过 `api_key` 或 `api_key_env` 给出的显式密钥优先。
3.  **构建区域端点。** 提供程序解析 `AWS_REGION` 或 `AWS_DEFAULT_REGION` 并为模型的推断 API 构建适当的 `bedrock-runtime` 端点。 对于 Kimi 模型，这将解析为推荐的 OpenAI 兼容的聊天完成路径。
4.  **调用选定的推理配置文件。** 模型别名映射到 Amazon Bedrock 模型或 [inference profile](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles.html) ID。 此示例使用全局推理配置文件 `global.moonshotai.kimi-k3.1`。 `global.` 前缀选择配置文件，而 `AWS_REGION` 确定接收您的请求的区域端点。

然后，CLI 流式传输模型响应，并可以在编码任务期间使用模型的客户端工具调用支持。 身份验证、授权、模型访问和网络连接必须全部成功才能完成请求。 由提供商生成的临时 API 密钥的有效期为 12 小时或 AWS 会话长度，以较短者为准。

先决条件
--------------

对于本演练，我们使用 Kimi K3.1 Pro Highspeed 作为示例模型，通过 [global cross-Region inference](https://docs.aws.amazon.com/bedrock/latest/userguide/global-cross-region-inference.html) 访问以获得最广泛的可用性和最低成本。 在使用模型之前，请查看 [Amazon Bedrock pricing](/bedrock/pricing/) 以了解预期成本。

要跟进，您需要：

*    支持源 AWS 区域中的目标模型和推断配置文件的 AWS 账户。 检查当前区域和推理配置文件支持的 [Kimi K3.1 Pro Highspeed model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-moonshot-ai-kimi-k3-1-highspeed.html)。
*   Kimi Code CLI v2.7.0 或更高版本。 按照 [Kimi Code CLI installation guide](https://github.com/MoonshotAI/kimi-code/blob/main/docs/en/guides/getting-started.md) 并运行 `kimi --version` 检查您的安装。
*   [AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html)，遵循本帖中的配置文件和身份检查命令。 可选的 `aws login` 工作流程需要 AWS CLI v2.32.0 或更高版本。
*    具有在您选定的 AWS 区域中调用目标模型和推理配置文件的权限的 [AWS Identity and Access Management (IAM)](/iam/) 身份（用户或假定角色）。

没有区域或帐户 ID 的基础模型 ARN 是全球跨区域路由的故意和必需的。 仅当使用 `openai_responses` 协议而不是默认 `openai`（聊天完成）时才需要 `BedrockInvokeKimiK31DefaultProject` 语句。

开始使用 `bedrock` 提供程序
--------------------------------------

准备就绪后，请按照以下步骤配置 AWS 身份验证、添加提供程序和模型以及发送测试请求。

### 步骤 1：配置 AWS 凭据

有 [different ways to authenticate with the AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/cli-chap-authentication.html)，具体取决于您组织的设置。 使用 [Named profiles](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html)，您可以配置多个 AWS 上下文并在它们之间切换。

例如：

*   如果通过[AWS IAM Identity Center](/iam/identity-center/)使用SSO，运行`aws configure sso --profile YOUR_PROFILE_NAME`设置配置文件，然后运行`aws sso login --profile YOUR_PROFILE_NAME`进行身份验证。
*   要在 AWS CLI v2.32.0 或更高版本中使用 AWS 管理控制台凭据，请运行 `aws login --profile YOUR_PROFILE_NAME`。 [console-credential login guide](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sign-in.html) 还描述了不支持缓存登录会话的工具的 `credential_process` 配置。
*   省略 `--profile` 参数以使用您的默认 AWS 配置文件而不是指定的参数。

无论您选择哪种方法，您的会话都会解析为需要先决条件的 Amazon Bedrock 权限的 IAM 身份（用户或角色）。 在 AWS CLI 配置文件中配置的区域适用于 AWS CLI 命令，但您仍必须在步骤 2 中为 Kimi 代码显式设置区域。

验证 AWS CLI 是否解析了您的预期身份。 如果使用默认配置文件，请省略 `--profile YOUR_PROFILE_NAME`：

AWS STS get-caller-identity --profile your_profile_name

### 第 2 步：添加提供者和模型

1.  在文本编辑器中打开或创建 `~/.kimi-code/config.toml`。 如果设置 `KIMI_CODE_HOME`，请改用 `$KIMI_CODE_HOME/config.toml`。 如果您有一个现有文件，请将这些条目备份并与您的当前设置合并，而不是覆盖不相关的提供商或模型。
2.  将 `YOUR_SOURCE_REGION` 替换为您支持的源区域（例如，`us-west-2`）。 要使用命名配置文件，请替换 `YOUR_PROFILE_NAME` 并取消注释 `AWS_PROFILE` 行：
    
default_model = "基石基米-K3-1"
        
[提供商.bedrock]
类型 = “基岩”
        
[提供商.bedrock.env]
aws_region = "your_source_region"
        # aws_profile = "your_profile_name"
        
[Models.Bedrock-Kimi-K3-1]
提供者 = “基岩”
模型 = "global.moonshotai.kimi-k3.1"
max_context_size = 1000000
能力 = ["always_thinking", "thinking", "image_in", "tool_use"]
    
模型别名 `bedrock-kimi-k3-1` 是 Kimi Code CLI 使用的本地名称。 模型值是 Amazon Bedrock 全局推理概要 ID。 该示例声明了一个 100 万令牌的上下文窗口和显式推理、图像输入和工具使用功能。 它省略了 `api_key`、`api_key_env` 和 `AWS_BEARER_TOKEN_BEDROCK`，因此提供程序使用环境 AWS 凭据。 配置的 Amazon Bedrock 密钥将优先。
    
3.  保存文件。 `[providers.bedrock.env]` 表提供给提供商的配置。 它不会将变量导出到您的 shell 中。

### 步骤3：发送请求并开始编码会话

1.  运行一个小的非交互式编码请求：
    
kimi --model bedrock-kimi-k3-1 --prompt "编写一个检查字符串是否为回文的 Python 函数。包括一个简短的使用示例。"
    
2.  确认CLI在没有认证、授权、区域、模型访问或网络错误的情况下流式传输响应。 此请求提供比提供者状态指示更有意义的连接检查。
3.  在项目目录中启动交互式会话：
    
cd /path/to/your/project
基米
    
因为您设置了 `default_model`，会话会自动选择 `bedrock-kimi-k3-1`。 要求代理解释存储库或提出小的更改。 在批准之前查看其建议的文件修改和 shell 命令。
    

配置最佳实践
-----------------------------

在撰写本文时，本机基岩提供者有几个配置考虑。 这些做法可帮助您避免模棱两可的状态信息和不匹配的设置。

### 使用配置文件设置提供程序

在撰写本文时，Kimi Code 的桌面和 Web 提供程序创建界面不会公开此凭据链设置使用的所有提供程序环境字段。 直接编辑 `config.toml` 以设置 Amazon Bedrock 提供商。 有关详细信息，请参阅 Kimi 代码文档中的 [Model providers](https://www.kimi.com/code/docs/en/kimi-code-cli/configuration/providers.html)。

### 明确声明模型功能

Kimi Code 不会自动检测 Amazon Bedrock 上大多数模型的功能，包括 Kimi 模型。 检查每个目标模型的 Amazon Bedrock 模型卡，并明确声明其功能让 Kimi Code 使用它们。

例如，[Kimi K3.1 Pro Highspeed](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-moonshot-ai-kimi-k3-1-highspeed.html) 支持 `always_thinking`、`thinking`、`image_in` 和 `tool_use`，但不支持 `audio_in` 或 `video_in`，如前面所示的 `config.toml` 示例中所反映的。

这些声明描述了客户端的行为。 您应该只包含每个目标模型和 Amazon Bedrock API 端点支持的功能。 验证您的应用程序的工具和图像工作流，而不是仅依靠功能标签。

### 保持区域设置一致，并尽可能首选跨区域推理

基岩提供者在 Kimi Code 的 `config.toml` 或 shell 环境中需要明确的 `AWS_REGION` 或 `AWS_DEFAULT_REGION`。 它无法推断仅在 `~/.aws/config` 或 `aws configure` 中配置的区域。

当您使用跨区域推理配置文件（带有 `global.`、`us.` 或 `in.` 等前缀）时，配置的 Kimi 代码区域控制接收请求的源区域。 有关详细信息，请参阅 Amazon Bedrock 用户指南中的 [cross-Region inference](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)。

对于没有数据驻留要求的工作负载，请从全局推理概要文件开始。 与许多其他模型一样，全球推理的价格比通过地理资料低 10%。 查看 [Amazon Bedrock pricing](/bedrock/pricing/) 了解当前费率和地理替代方案。

### 在需要时覆盖端点URL和协议

在某些情况下，提供商的自动检测可能会错误地将您想要用于特定模型的 API 协议或目标 URL 误差。 例如，您需要通过 [VPC endpoint](https://docs.aws.amazon.com/bedrock/latest/userguide/vpc-interface-endpoints.html) 或 [Mantle endpoints](https://docs.aws.amazon.com/bedrock/latest/userguide/endpoints.html) 设置不同的 URL 以使用 Amazon Bedrock。

在 Kimi 代码 `config.toml` 中，您可以：

*   将 `protocol` 字段设置为 `openai`（聊天完成）、`openai_responses` 或 `anthropic`（消息）以配置模型以使用特定支持的线路协议。 请参阅 [model cards](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards.html) 以了解哪些模型支持哪些 API。
*   设置 `base_url` 字段以更改目标 URL，其中必须包含任何附加的 API 路径，如 `/openai/v1` 或 `/anthropic`。

在以下示例中，我们显示了连接到相同模型但通过您设置的 Amazon Bedrock [VPC endpoint](https://docs.aws.amazon.com/bedrock/latest/userguide/vpc-interface-endpoints.html) 使用 OpenAI Responses API 的配置：

[Models.Bedrock-Kimi-K3-1]
提供者 = “基岩”
模型 = "global.moonshotai.kimi-k3.1"
max_context_size = 1000000
能力 = ["always_thinking", "thinking", "image_in", "tool_use"]
协议 = "OpenAI_Responses"
base_url = "https://vpce-EXAMPLE-VPCEID.bedrock-runtime.us-west-2.vpce.amazonaws.com/openai/v1"

### 将连接状态作为配置指示器进行处理

在 Kimi Code Desktop 和 Web 应用程序中，提供程序列表可以显示 `connected` 为基岩提供者。 该状态不会验证配置的 AWS 凭据、IAM 权限、区域、模型访问或网络路径。 不要将其视为成功模型请求的证明。 使用非交互式提示测试完整路径，并在失败时诊断实际响应。

净化
--------

如果您创建了新的 AWS IAM 标识或为在 Amazon Bedrock 上尝试 Kimi K3.1 Pro 而分配了新权限，请记住在完成测试后将其删除。

您可能还希望还原您设置的任何本地 Kimi Code CLI 提供程序配置或 AWS CLI 配置文件。 如果不再需要，您甚至可以完全卸载 CLI。 有关详细信息，请参阅 [Kimi Code](https://www.kimi.com/code/docs/en/kimi-code-cli/guides/getting-started.html#upgrade-and-uninstall) 和 [AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/uninstall.html) 的卸载指南。 请记住，删除本地 AWS 配置或 CLI 本身并不能撤销 IAM 权限或活动 AWS 会话。

我们展示的模型的 Amazon Bedrock 推理是按令牌收费的，因此没有持续的云基础设施部署可以进行清理。

总结
-----------

我们在 Kimi Code CLI v2.7.0 中展示了 AI 的原生基岩提供商如何通过标准 AWS 凭据链在 Amazon Bedrock 上连接到 Kimi K3.1 Pro Highspeed。 您不再需要单独管理的 Amazon BedRock API 密钥。

Amazon Bedrock 通过标准 API 使您可以访问领先供应商的开放和专有 AI 模型。 它的治理控制和 [compliance validation](https://docs.aws.amazon.com/bedrock/latest/userguide/compliance-validation.html) 程序甚至可以支持严格监管的工作负载。

如果您已经在使用 Kimi Code CLI 并想在 AWS 上运行推理，请立即升级并尝试新的简化身份验证。

有关 Amazon Bedrock 上 Kimi K3.1 Pro 的更多信息，请参阅我们的 [launch blog post](/blogs/machine-learning/introducing-kimi-k3-1-pro-on-amazon-bedrock/) 和 [Moonshot AI on AWS samples repository](https://github.com/aws-samples/sample-moonshotai-on-aws)。 要按模型探索支持的 API 和功能，请参阅 Amazon Bedrock 用户指南中的 [model cards](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards.html)。 与 Amazon Bedrock 团队讨论您的用例，[connect with us](https://pages.awscloud.com/Amazon-Bedrock-Contact-Us.html)。

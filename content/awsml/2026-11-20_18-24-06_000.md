在 Amazon SageMaker Hyperpod 中引入增强的基础设施可观察性
========================================= 。 =========================================

大规模模型训练是您可以在 GPU 上运行的最昂贵的工作负载之一，单个不健康的加速器可能会阻碍整个分布式作业。 当训练吞吐量下降时，困难的部分很少注意到有问题。 它正在弄清楚为什么以及在哪里。 团队经常花费数小时或数天的时间来筛选日志和断开的仪表板，以决定是否缓慢来自受限的 GPU、饱和的网络链接或主机上停滞的数据管道。

今天，我们宣布在 Amazon SageMaker Hyperpod 中提高可观察性，这是一种帮助您更快地诊断 GPU 培训问题的新功能。 它汇集了在 Amazon Elastic Kubernetes 服务 (Amazon EKS) 和 Slurm Orchestrator 上运行的训练工作负载的诊断和分析功能：

**诊断摘要** 使用 Amazon CloudWatch 的 DetectGroupOutliers API 来比较培训作业中的利用率、内存、温度、功率和 SM 时钟的每个 GPU，并标记偏离同行的 GPU。 静态诊断规则表面常见故障模式，如 GPU 硬件故障（XID 错误、ECC 内存错误）、EFA 吞吐量下降、热限制和过热，因此您会在退化影响训练之前捕获它。

为什么你需要它
----------------

分布式培训费用昂贵，小的低效率会导致大量的 GPU 浪费时间。 到目前为止，获得对 Hyperpod 基础设施的可见性意味着将单独的工具拼接在一起，即便如此，这些指标也告诉您，性能已经下降，但没有告诉您原因。

增强的可观察性缩小了三个差距。 无论是通过 XID 错误、ECC 内存故障还是热限制，它都会在数百或数千个 GPU 中隔离单个坏加速器，因此您将时间花在修复上而不是搜索上。

这些功能共同减少了故障排除时间，并帮助您保持昂贵的加速器忙碌。

这个怎么运作
-------------

每个能力都针对分布式培训作业的不同层次。

### 默认和高级指标

增强的可观察性在两个层次上收集遥测：

**默认指标**（自动启用）涵盖集群运行状况、CPU/磁盘/OS 级别的使用、GPU 利用率和温度以及每个作业资源的利用率。 这些指标每 30 秒收集一次，并以大约 1-2% 的 CPU 开销和 250-300 MB 的内存发送到您选择的指标存储。

**高级指标**（选择加入）提供更深入的可见性：

*   **全节点导出套件：** 综合主机级指标。
*   **所有 NVIDIA GPU DCGM 和 AWS 神经元指标：** 详细加速器遥测，包括时钟速度、功率、PCIe 活动和错误指示器。
*   **弹性结构适配器 (EFA) 指标：** 网络接口吞吐量、丢弃、重传和错误。

高级指标是可选的，因为它们增加了发送到您的指标存储的遥测量，这具有成本含义。 大多数在小集群上运行小型工作的客户可能不需要它们，但它们对于在模式随时间出现的大型集群上的长期培训工作中至关重要。

### 公制商店

您可以在两个指标存储之间进行选择：

*   **Amazon CloudWatch**（新默认设置）通过 CloudWatch SageMaker Insights 提供本机监控，因此您可以在不离开 AWS 管理控制台的情况下可视化指标。
*   **Prometheus 的亚马逊托管服务**适用于标准化 Prometheus 和 Grafana 的团队的可观察性。

以前，只支持普罗米修斯。 CloudWatch 现在是默认设置，与 Amazon Managed Service Prometheus 相比，价格更低，并且与 SageMaker 控制台进行了更紧密的集成。

### 诊断摘要

诊断摘要使用两种互补的方法来解决超足点群集的表面问题。

**GPU 离群值检测** 使用 CloudWatch 的 _DetectGroupOutliers_ API 来比较训练作业中的 GPU 利用率、内存使用率、温度、功率消耗和 SM 时钟频率。 当 GPU 显着偏离其对等体时，它会在诊断摘要中显示为异常卡。 这适用于 EKS 和 Slurm 工作。

**静态诊断规则**评估已知的故障模式并按类型组织检测到的问题：

*   **硬件：** GPU ECC 内存错误、XID 故障、加速器故障。
*   **网络：** EFA 吞吐量降级、数据包丢弃、重传。
*   **节流：** 由于热量、电路板或可靠性限制，GPU 时钟节流。
*   **过热：** GPU 温度超过配置的限制。

每个检测到的问题都标识受影响的作业、集群、节点、加速器和排名。

如何开始
-------------------

增强的可观察性作为 EKS 编排集群的附加组件和 Slurm Orchestrated 集群的扩展提供，这意味着您可以通过 AWS Identity and Access Management (IAM) 控制谁可以安装或更改它。

### 步骤 1：创建 SageMaker Hyperpod 集群

如果你已经有一个集群，你可以使用它。 要创建一个新的 SageMaker Hyperpod 集群，您可以遵循 [step-by-step outline](https://awslabs.github.io/ai-on-sagemaker-hyperpod/)。 一般来说，步骤如下：

1.  在 Amazon SageMaker AI 控制台上，在导航窗格中选择 **HyperPod 集群**。
2.  选择**创建Hyperpod**集群和**在Amazon EKS**或**由Slurm编排**。
3.  对于**设置选项**，选择**自定义设置**。
4.  对于 **Name**，输入一个名称。
5.  对于**实例恢复**，选择**自动**。
6.  选择**提交**。

### 步骤 2：配置 Hyperpod 可观察性

在**自定义设置**工作流程中，展开**HyperPod Observability**部分：

1.  **Enable Hyperpod Observability** 默认选中。 仅当您不想要可观察性时才取消选中。
2.  **可观察性指标** 显示默认指标（集群运行状况、CPU/磁盘/OS、GPU 利用率/温度、每个作业资源）以及可选的高级指标。
3.  根据需要选择高级指标：全节点导出套件、所有 NVIDIA GPU DCGM/神经元指标和 EFA 指标。
4.  **Enable Logging** 为容器和 Pod 日志创建 CloudWatch 日志组。
5.  对于 **Metric Store**，选择 **Amazon CloudWatch**（默认）或 **Amazon 托管服务的 Prometheus**。
6.  对于 **Grafana 工作区**，选择创建新的工作空间、使用现有的工作空间或选择无。
7.  配置 IAM 角色或让控制台自动创建它们。

### 步骤 3：使用 CLI 安装 Observability 插件（Alternative，EKS）

您可以从 AWS 管理控制台或通过 API 安装 HyperPod 可观察性附加 (EKS) 或扩展 (SLURM)。 或者，您可以使用 AWS 命令行界面 (AWS CLI) 安装附加组件。

以下命令创建附加组件，启用基本指标类别并关闭选择加入分析功能：

AWS EKS 创建插件 \
--cluster-name <cluster-name> \
--addon-name amazon-sagemaker-hyperpod-observability \
--区域 <region> \
--configuration-values'{
“MetricsDestination”：“Cloudwatch”，
“指标提供者”：{
"nodemetrics": {"level": "basic", "scrapeInterval": 30},
"AcceleratedComputeMetrics": {"level": "basic", "scrapeInterval": 30}
},
“配置文件提供者”：{
“主机分析”：{“启用”：假}
}
}'

验证附加组件是否处于活动状态：

AWS EKS Describe-Addon \
--cluster-name <cluster-name> \
--addon-name amazon-sagemaker-hyperpod-observability \
--区域 <region> \
--查询'addon.status'

### 第 4 步：启用指标 (EKS)

您可以随时启用或禁用任何指标类别或分析功能。 对于 EKS 集群，使用 AWS 命令行界面 (AWS CLI) 更新附加配置。 以下命令打开高级网络 (EFA) 指标：

AWS EKS 更新插件 \
--cluster-name <cluster-name> \
--addon-name amazon-sagemaker-hyperpod-observability \
--区域 <region> \
--configuration-values'{
“MetricsDestination”：“Cloudwatch”，
“指标提供者”：{
"nodemetrics": {"level": "basic", "scrapeInterval": 30},
"AcceleratedComputeMetrics": {"level": "basic", "scrapeInterval": 30},
"NetworkMetrics": {"level": "高级", "scrapeInterval": 30}
}
}'

在控制台中，选择**操作**，然后在附加卡上进行**编辑**以进行相同的更改。 下图显示了 **Actions** 按钮。

使用 AWS CLI 安装扩展程序：

AWS SageMaker create-cluster-extension \
--cluster-arn <cluster-arn> \
--extension-name sagemaker-observability \
--区域 <region> \
--configuration-values'{
“指标提供者”：{
"clustermetrics": {"level": "enabled", "collectionIntervalSeconds": 30},
"nodemetrics": {"level": "basic", "collectionIntervalSeconds": 30},
"AcceleratedComputeMetrics": {"level": "basic", "collectionIntervalSeconds": 30},
"JobMetrics": {"level": "Enabled", "CollectionIntervalSeconds": 30}
},
"profilesProvider": {"hostprofiling": {"启用": false}}
}'

要打开 EFA 指标，请更新扩展名：

AWS SageMaker Update-Cluster-Extension \
--cluster-arn <cluster-arn> \
--extension-arn <extension-arn> \
--区域 <region> \
--configuration-values'{
“指标提供者”：{
"clustermetrics": {"level": "enabled", "collectionIntervalSeconds": 30},
"nodemetrics": {"level": "advanced", "collectionIntervalSeconds": 30},
"AcceleratedComputeMetrics": {"level": "Advanced", "CollectionIntervalSeconds": 30},
"NetworkMetrics": {"level": "Enabled", "CollectionIntervalSeconds": 30},
"JobMetrics": {"level": "Enabled", "CollectionIntervalSeconds": 30}
}
}'

用 `aws sagemaker describe-cluster-extension --cluster-arn <cluster-arn> --extension-arn <extension-arn>` 检查状态。

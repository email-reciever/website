宣布 Amazon TextRact 见解：可验证的文档生成 AI
========================================。 =========================================

金融服务、保险、医疗保健和公共部门的组织依赖于文件处理。 他们将扫描的文件和纸质表格转换为其系统可以执行的结构化数据。 随着生成式人工智能的成熟，这些组织想要的不仅仅是准确的文本提取。 他们想用自己的话描述他们需要的信息，并从复杂的文件中获得可靠、可审计的答案。

今天，我们宣布 Amazon TextRact 的新生成 AI 功能 [Amazon Textract Insights](/textract/) 的一般可用性，可通过 Amazon TextRact 中的新 API 获得。 使用 Amazon TextRact Insights，您可以用自然语言描述所需的字段并提交文档或混合的多文档数据包。 您收到结构化结果，其中每个值都带有置信度分数和页面级基础，无需模型训练。

从混合数据包中提取数据的挑战
-----------------------------------------------

许多高价值的文档工作负载涉及不同的、混合的数据包，而不是干净的单一用途文件。 例如，抵押文件通常以单个扫描到达，包含 W-2、工资单、银行对账单和一页手写笔记。 每个都有自己的布局，没有固定的顺序。 索赔文件和入职包裹看起来非常相似：类型化的表格、密集的表格、扫描的收据和交织在一个文件中的自由文本字母。

团队通常采用两种方法之一，每种方法都有权衡。 第一个是结合光学字符识别、文档拆分、分类、基础模型提示和审阅步骤的自定义管道。 团队必须整合、扩展和操作所有这些。 第二个是默认使用的通用大型语言模型。 它返回流利的答案，但不能可靠地引用源页面或给出置信度评分。 如果没有可追溯的来源和校准的分数，就很难知道要自动接受哪些值以及要查看哪些值。 这种不确定性通常会限制团队的自动化程度。

Amazon TextRact Insights 专为可靠的文档处理而构建，将整个工作流带入 Amazon TextRact 上的单个异步请求中。 您的团队不是组装和操作自定义管道，而是通过一种托管 API 工作，并直接移动到所需的数据。

How Amazon Textract Insights works
---------------------------------

使用 Amazon TextRact Insights，您可以在蓝图中定义要提取的内容。 蓝图是一个 JSON 模式，其中每个字段都带有对查找内容的自然语言描述。 每个字段还具有一个推理类型，用于确定该值是从页面中逐字读取还是从文档的内容中推断出来。 您可以从 AWS 公开蓝图开始用于常见文档类型，例如 W-2、表格 1040、表格 1098、护照或出生证明。 您还可以为特定于您的业务的文档编写自己的蓝图。

对于混合数据包，您要将每个文档类型的蓝图添加到同一项目中。 然后，您从您自己的 Amazon Simple Storage Service (Amazon S3) 存储桶提交最多 3,000 页的单个文件，并启用拆分。 Amazon TextRact Insights 将数据包拆分为逻辑子文档，将每个数据包与适合它的蓝图匹配，提取请求的字段，并返回每个值的置信度分数和接地。

例如，假设您收到一份 26 页的 PDF 抵押申请，其中包含 W-2、工资单、银行对账单和信贷员的手写笔记。 您可以使用 AWS Public W-2、Payslip 和 Bank Statement Blueprints 创建 Amazon TextRact Insights 项目，为信贷员注释添加自定义蓝图，并启用拆分。 然后，您通过一个 StartDocumentInsights 调用从 Amazon S3 存储桶提交文件。 Amazon TextRact Insights 将文件拆分为其各个文档，将每一个文件与其蓝图相匹配，并将结果写入 S3 存储桶。 每个值都包含一个置信度分数以及它所绘制的页面和边界框。

可审计自动化的信心和基础
---------------------------------------------

Amazon TextRact Insights 返回两种字段：第一种是直接从页面读取的显式字段。 第二个是从文档的内容派生的推断字段。 两者都以置信度得分和基于确定页面和值的坐标返回。

由于每个值都可以追溯到其来源，因此审阅者或审计师可以根据原始文件确认任何结果。 您可以将自动化扩展到以前进行人工审查的文档，同时让人们在需要判断的地方保持在流程中。

建立在 Amazon Textract 引擎上
---------------------------------

我们更新了 [Amazon Textract’s reading engine](/about-aws/whats-new/2026/11/textract-text-detection-model/)，Amazon TextRact 核心，提高了准确性，加强了对密集表和手写的处理，并将 DetectDocumentText 和 AnalysicoCument API 的语言覆盖范围扩展到 40 种语言。 Amazon Textract 的所有这些优点现在都没有任何更改。 您的 Amazon TextRact API 保持不变。

Amazon Textract Core 现在是 [generally available in two additional AWS Regions](/about-aws/whats-new/2026/11/textract-tokyo-zurich/)、亚太地区（东京）和欧洲（苏黎世），为总共 18 个 AWS 区域带来区域内处理。 Amazon TextRact Insights 在这些 AWS 区域中尚不可用。

安全和数据处理
---------------------------

### 项目和蓝图

Amazon TextRact Insights 使用 AWS 拥有的密钥对项目和蓝图进行加密。 要使用您自己的 AWS Key Management Service (AWS KMS) 客户托管密钥，请在调用 CreateProject 或 CreateBlueprint 时在 EncryptionConfiguration 中指定它。

### 洞察力分析工作

Amazon TextRact Insights 从 StartDocumentInsights 请求中指定的 Amazon S3 存储桶中读取文档并写入结果。 中间作业数据使用 AWS 拥有的密钥进行静态加密。 如果在请求的加密配置中指定客户托管密钥，Amazon TextRact Insights 会使用它来加密作业的中间数据。 所有中间数据都是瞬态的，并且在作业完成时将被删除。 输出存储桶的默认加密适用于作业完成时写入存储桶的结果。 项目的关键不适用于其工作。

如果您禁用密钥或移除 Amazon TextRact 对它的访问权限，Amazon TextRact Insights 将无法再使用其下加密的数据。

### 跨区域推理

Amazon TextRact Insights 会自动选择您的地理位置中的最佳 AWS 区域以处理您的推理请求。 这最大限度地提高了可用的计算资源和模型可用性，并旨在提供一致的客户体验。 所有数据都通过亚马逊的安全网络进行加密传输。 Amazon TextRact Insights 将您的推理请求安全地路由到请求发起的地理区域内的可用计算资源。 例如，起源于美国的推理请求在美国内处理。 Amazon TextRact 核心 API 不变，继续处理您调用的 AWS 区域中的请求。 有关目标 AWS 区域列表，请参见 [Amazon Textract documentation guide](https://docs.aws.amazon.com/general/latest/gr/textract.html)。

开始
----------------

Amazon TextRact Insights 入门需要四个步骤。

**定义您需要的内容：** 从 AWS 公共蓝图开始或用自然语言描述您自己的字段。

**创建项目：** 将您的蓝图添加到其中。

**提交您的文档：** 通过一次 API 调用从您的 Amazon S3 存储桶发送单个文档或混合数据包。

**查看结果：** 接受符合您置信度阈值的值，并将其余部分用于审查。 在您自己的文件的代表性样本上调整您的阈值。

Amazon TextRact Insights 支持 PDF、PNG、JPEG 和 TIFF 输入和处理文档，包括英语、法语、德语、意大利语、葡萄牙语和西班牙语。 它的价格是每页而不是每个令牌，没有最低承诺。 有关 Amazon Textract 的当前费率，请参阅 [Amazon Textract pricing page](/textract/pricing/)。

使用 Amazon Bedrock AgentCore Payments 使 AI 代理商为 AWS Marketplace X402 产品付费
=================================================。 =================================================

当 Amazon Bedrock AgentCore 支付在 2026 年 8 月变成 [generally available](/blogs/machine-learning/amazon-bedrock-agentcore-payments-is-now-generally-available-enabling-agents-to-transact-safely-and-autonomously-at-scale/) 时，代理可以通过具有付款限制和完全可观察性的开放协议（如 X402 和 MPP）自动支付付费 API、MCP 服务器和 Web 内容。 今天，我们将这种自主权扩展到 [AWS Marketplace](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/payments-process-payment.html#payments-process-payment-aws-billing)，以便代理商可以发现和购买支持 X402 的软件、API、数据和内容，并按代理开发人员的 AWS 账单支付美元，从而消除对稳定币钱包或 API 密钥的需求。

图 1：显示 AWS Marketplace 上采购的新 AWS 计费集成的 AgentCore 付款概览

开发人员还可以通过 [AWS Marketplace connector in AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-target-connector-aws-marketplace.html) 配置和自动化发现。 现有的护栏延续，开发人员可以使用 AgentCore 策略设置支出限制和批准的卖家，并且支付会话上限由 AgentCore 支付强制执行，因此代理商无法超支。 交易在[AWS CloudTrail](/cloudtrail/)和[AWS Cost Explorer](/aws-cost-management/aws-cost-explorer/)中是可审计的。 由于代理采购在双方的 AWS 账户中运行，代理采购符合企业的安全性和可审计性。

AWS Marketplace 上的 X402 目录正在扩展，越来越多的可靠、经过验证的卖家。 Tavily，代理商的实时搜索提供商，是其中之一：

今天推出什么
-----------------------

今天的发布将 AWS 计费作为 AgentCore 支付中的支付选项。 代理现在可以按美元向启用 X402 的 AWS Marketplace 卖家付款，以美元支付其 AWS 账单。

当 AWS Marketplace 卖家响应 402 付款时，其响应包括签署的购买报价。 使用 AWS 计费，代理可以将卖家的 X402 响应转发到 AgentCore 付款。 AgentCore Payments 检查会话预算，然后返回支付令牌。 代理将包含包含支付令牌的请求重试，并收到成功的响应。 AWS 将费用向设置 Payment Manager 的 AWS 账户收取费用，该费用将显示在该账户的 AWS 账单上。

要设置 AWS Marketplace 采购，开发人员会创建一个带有 AWS 计费连接器的支付管理器。 连接器仅要求您设置 [service-linked role](https://docs.aws.amazon.com/marketplace/latest/buyerguide/buyer-service-linked-role-agentic-commerce.html) 以访问 AWS Marketplace。 然后，对于每个任务，开发人员可以创建一个有支出限制的支付会话，并为代理提供会话 ID。

代理人从卖家处首次购买与该卖家签订协议，AWS Marketplace 会自动跟踪后续购买。 然后，每个产品将显示为 AWS Marketplace 订单项。 如果您的组织使用 [Private Marketplace](/marketplace/features/privatemarketplace)，代理商只能购买其允许的产品。

此外，为了发现新的卖家，我们正在推出一个新的 [AWS Marketplace connector in AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-target-connector-aws-marketplace.html)。 此可选集成可帮助代理找到产品及其端点。 在发布时，AWS 计费支持 X402 _Exact_ 方案，卖家会为每个请求报价固定价格。

在这篇文章中，我们介绍了一个研究代理，该代理发现了一个工具，通过 AWS 计费支付单个请求，并使用来源回答，提前没有设置任何内容。 我们还提供了一个随附的 GitHub 示例，您可以使用它来评估您自己的 AWS 账户中的设置。

示例演练
-------------------

假设一位金融分析师询问代理人本周宣布了关于代理支付的内容。 该模型没有根据本周的新闻进行训练，因此该代理正在寻找搜索工具。 通过 AgentCore Gateway，它搜索 AWS Marketplace，从 AWS Marketplace 卖家 Tavily 中读取列表，并请求该列表的 X402 端点。

代理调用端点并接收包含价格详细信息的 X402 有效负载。 然后代理将 X402 有效负载转发到 AgentCore 支付。 AgentCore Payments 会根据剩余的会话预算检查它并返回支付令牌。 一旦通过这些检查，代理将再次发送请求，并附上令牌，并获取搜索结果。 它的答案包括来源和说明它购买的内容和成本。

在此工作流程中，代理可以应用他们的推理来决定使用哪个 AWS Marketplace 工具。

### 它是如何工作的

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/19/x402-payment-flow.png)

图 2：使用股线剂的样品溶液的端到端流程

**1\。 发现。** 代理按顺序调用三个只读网关工具：搜索列表、获取列表和列出其履行选项。 搜索列表工具仅返回接受 X402 的端点。 最后一次调用返回卖家的端点 URL 及其接受的付款协议。

**2\。 获取报价。** 代理呼叫终结点，未附加付款。 卖家用 HTTP 402 回答，并在 `PAYMENT-REQUIRED` 标头中放置一个签名引用。 AWS Marketplace 会根据卖家的注册密钥检查签名，这意味着价格更改后的报价被拒绝。

**3\。 Pay.** 代理将报价传递给 `ProcessPayment` API，其中包含付款类型 `AWS_BILLING_X402`。 如果预算仍在会话中，AgentCore Payments 会发出支付令牌。 如果没有，则呼叫失败，开发者不收费。

**4\。 REDEEM.** 代理再次发送请求，这次使用 `PAYMENT-SIGNATURE` 标头中的令牌，卖家返回内容。 支付令牌的有效期约为五分钟，因此代理人一次完成步骤 2 至 4。

**5\。 结算。 之后，它计量每笔向 AWS 账单收取的费用。 结算异步运行并显示在其 AWS 账单中。

### 先决条件

要创建 AWS 计费连接器，开发人员的 AWS 账户必须具有 AWS Marketplace 服务相关角色 [AWSServiceRoleForMarketplaceAgenticCommerce](https://docs.aws.amazon.com/marketplace/latest/buyerguide/buyer-service-linked-role-agentic-commerce.html)。 AWS Marketplace 使用此角色向其代理商对 AWS 账户进行的 AWS Marketplace 购买收费。 有关详细信息，请参阅[documentation](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/payments-prerequisites.html#payments-prereq-aws-billing)。

### 动手

`agentcore-samples` 存储库中的 [open-source GitHub sample](https://github.com/awslabs/agentcore-samples/tree/main/01-features/08-agents-that-transact/02-use-cases/pay-for-x402-aws-marketplace) 运行新功能的演示。 它可以帮助您为 AWS Marketplace、连接 TAVILY、运行代理和检查交易配置 AgentCore 支付。 您可以参考 [documentation](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/payments-process-payment.html#payments-process-payment-aws-billing) 了解更多详情。

#### 步骤 1：配置 AgentCore 支付

`setup_aws_billing.py` 创建一个具有 AWS 计费连接器的支付管理器，以及 [AWS Marketplace service-linked role](https://docs.aws.amazon.com/marketplace/latest/buyerguide/buyer-service-linked-role-agentic-commerce.html) 和三个独立的 AWS 身份和访问管理 (IAM) 角色。 会话角色可以设置预算，但无法支付。 同时代理角色可以支付但无法创建会话，因此代理无法提高自己的预算。

python setup_aws_billing.py --region us-east-1

#### 第 2 步：连接 Tavily

`setup_gateway.py` 使用 AWS Marketplace 连接器创建 AgentCore 网关，并为代理角色提供使用它的适当权限。 网关的作用仅限于三个只读的 AWS Marketplace 操作。 如果您选择跳过此步骤，则可以将环境变量中的 `SELLER_URL` 设置为卖家的端点，代理将仅支付该 URL 而不是使用 AgentCore 网关发现。

python setup_gateway.py --region us-east-1

#### 第 3 步：运行代理

脚本创建作为会话角色的支付会话，然后将代理作为代理角色运行。 默认情况下，会话预算为 0.05 美元，每个请求上限为 0.02 美元。

python strands_marketplace_agent.py “本周公布的代理支付方式是什么？引用来源。”

代理搜索、查看列表、获取端点并付款一次。 在针对 0.01 美元卖家的测试运行中，它比较了购买前的两个列表：

工具调用：search_marketplace -> get_remaining_budget -> search_marketplace -> search_marketplace -> get_listing -> get_seller_endpoints -> get_seller_endpoints -> fetch_paid_api -> get_remaining_budget
支付此运行：1，总计 $0.01

#### 第4步：检查交易

运行完成后，样本将打印出其金额、AWS Marketplace 产品 ID 和 `processPaymentId` 的付款。 AWS Marketplace Meters 会异步收费，因此 TAVILY 订单项需要片刻才能出现在您的账单上。 代理购买还将显示在 AWS CloudTrail 和 AWS Cost Explorer 中。

#### 第五步：清理

运行 `cleanup.py` 删除资源。 确保验证删除以避免产生额外的资源费用。

总结
-----------

[AgentCore payments and AWS Marketplace](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/payments-process-payment.html#payments-process-payment-aws-billing) 为可以交易的代理提供基础设施。 这篇文章中的研究代理从“我需要实时网络搜索”到自行获取答案，通过工具发现高级付费内容，以及为满足开发商 AWS 账单的请求付费。

借助 AgentCore 支付，开发人员可以使用 X402 等开放协议进行构建，从而向越来越多的受信任的、经过验证的 AWS 市场卖家打开它们。 这为代理商提供了更多的自主权和更多的控制权。 内置治理，具有每次会话支出上限和使用 AgentCore 策略的批准卖家列表，以及使其在 AWS CloudTrail 和 AWS 成本资源管理器中可审计的 IAM 身份。 代理为任务选择了正确的工具，开发人员可以保持他们已经信任的相同计费、预算和控制。

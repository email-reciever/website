在流量高峰期间，请求可以在饱和的超足点群集上排在队列中，而另一个集群（有时在另一个 AWS 区域中的 GPU）处于空闲状态。 您已经为该容量付费，但您的请求无法实现。

在 [Introducing Amazon SageMaker HyperPod Inference Gateway](https://aws.amazon.com/blogs/machine-learning/introducing-amazon-sagemaker-hyperpod-inference-gateway/) 中，我们展示了推理网关如何为每个 Amazon SageMaker HyperPod 集群提供一个单一的 GPU 感知端点。 它读取关键值（kv）缓存利用率和队列深度等实时信号，以将每个请求都放在最适合的pod上。 这解决了一个集群内的路由，但不是跨集群。

今天，SageMaker Hyperpod 引入了全球推理网关。 它是一种 SageMaker 管理的网关，可在您注册的每个集群中、一个区域或跨区域中进行路由。 网关选择集群并通过 AWS 骨干网承载请求，通过 AWS Signature 版本 4 (SIGv4) 和 AWS 身份和访问管理 (IAM) 进行自动故障转移和身份验证。 在每个集群中，推理网关不断挑选 Pod，不变。 全局推理网关是我们在第 1 部分中描述的架构的第二层。

## 挑战：跨集群和地区的容量分布

模型越来越大，为它们提供服务的 GPU 容量更难找到。 为了获得足够的它，您将其分布在更多集群和更多区域。

考虑一个团队，在两个区域中的五个 Hyperpod 集群中提供四个模型。 如果没有推理网关，客户端会跟踪 20 个端点：每个模型每个集群 1 个。 推理网关将其削减为五个，每个集群 1 个。 但是每个客户端仍然选择一个集群本身。

该选择有成本：

*   **不均匀负载。
*   **手动故障转移。** 当集群发生故障时，工程师会更改配置以将流量从其移开。
*   **自定义管道。** 跨区域传播流量意味着自己构建和维护负载平衡器、DNS 和跨区域网络。

该团队需要一个端点，将每个请求发送到最适合的集群，并将流量自行从故障集群中移出。

## 主要好处

全球推理网关可帮助您从已有的 GPU 容量中获得更多，而操作则更少。

*   ** 让空闲的 GPU 工作。
*   **自动失败。** 当集群发生故障时，网关将其流量移动到下一个最佳集群。 客户不会改变任何东西。
*   **使用一个端点进行所有操作。** 客户端调用单个 SageMaker 管理的端点，而不是跟踪每个集群或每个模型的一个端点。
*   **跳过自定义网络。** 您不构建或维护负载均衡器、DNS 或跨区域网络。
*   **默认保持私有。

## 它是如何工作的

设置网关需要两个决策：打开哪些集群进行路由，以及将哪些集群分组在一个网关后面。

1.  **发布集群。**每个集群执行一次。 打开集群现有 `InferenceGatewayConfig` 中的 `spec.globalRouting` 块。 然后，Hyperpod 推理控制器从您自己的帐户私下发布集群。
2.  **创建网关。** 您每个网关都这样做一次。 您调用 `CreateGlobalInferenceGateway` 与集群进行路由，SageMaker 返回一个端点。

只有在您发布后才能访问集群。 发布集群时，控制器会在集群的推理网关前面创建一个网络负载平衡器，在其上发布虚拟私有云 (VPC) 端点服务，并将侦听器的证书上传到您的 TLS 存储桶。 这些资源存在于您的帐户中。 如果您在发布之前在网关中列出集群，该呼叫将失败并显示一条消息，告诉您要修复什么。

###  AWS 运行的内容

您可以决定发布哪些集群，在网关后面分组，以及如何对路由进行权衡。 AWS 运行其余部分：

*   ** 路由队列。** SageMaker 提供并运行终止 TLS、验证呼叫者、对集群进行评分和转发每个请求的队列。
*   ** 私人连接。** SageMaker 每个集群创建一个专用端点，并在 AWS 主干、区域内和跨区域上承载流量。
*   **Certificates and Validation.** 使用您创建的执行角色，服务读取每个集群的 VPC 端点服务名称、证书和区域，因此您无需手动复制它们。 它在路由流量之前检查它们。
*   **运行状况和故障转移。 有关详细信息，请参阅操作网关部分。
*   **认证和速率限制。

在每个集群上，具有自己 IAM 角色的服务管理的指标发布者会将集群的负载发送到网关。

## 网关如何选择集群

对于每个请求，网关根据四个信号对每个健康集群进行评分，并将请求发送到得分最高的集群。 每个集群的指标发布者提供负载信号。

您可以通过路由权重控制每个信号的计数。 每个权重是从 0.0 到 1.0 的值，0 的权重会关闭该信号。 如果设置权重，则设置所有四个，它们必须加起来为 1.0。 如果省略它们，下表中的默认值将适用。

**重量**

**它的得分**

**默认**

`KVHeadroom`

集群上可用的 KV 缓存和 GPU 内存

0.20

`QueueDepth`

集群的备份程度

0.25

`RegionProximity`

集群与网关区域之间的距离

0.40

`ErrorRate`

集群上最近失败的请求

0.15

默认值有利于靠近网关区域的集群，同时仍将流量转移到具有可用容量的集群和远离故障的集群。 如果复原力比工作量的接近度更重要，请提高 `ErrorRate` 和降低 `RegionProximity`。 例如，以下路由块将最近的错误加权为 0.7：

```json
{"Weights": {"KVHeadroom": 0.1, "QueueDepth": 0.1, "RegionProximity": 0.1, "ErrorRate": 0.7}}
```

您传递 `CreateGlobalInferenceGateway` 的 `Routing` 参数中的权重，稍后可以使用 `UpdateGlobalInferenceGateway` 更改它们。

## 开始

要设置全局推理网关，请准备每个集群、创建执行角色并调用 `CreateGlobalInferenceGateway`。 然后，您将使用 Sigv4 签名的 OpenAI 兼容请求发送到网关端点。 有关包括 IAM 角色和策略在内的分步说明，请参阅 [AWS documentation](https://docs.aws.amazon.com/sagemaker/latest/dg/sagemaker-hyperpod-model-deployment-global-inference-gateway.html)。

## 安全性和访问权限

对网关的每个请求都与 SIGv4 签名并通过 IAM 授权。 调用者需要权限来调用网关，流媒体有自己的操作：

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": [
      "sagemaker:InvokeGlobalInferenceGateway",
      "sagemaker:InvokeGlobalInferenceGatewayWithResponseStream"
    ],
    "Resource": "arn:aws:sagemaker:<region>:<account-id>:global-inference-gateway/<gateway-id>"
  }]
}
```

将此策略附加到发送请求的每个 IAM 身份。 要允许帐户中的每个网关，请使用 `global-inference-gateway/*` 作为资源。

执行角色遵循最小权限。 它只能描述您列出的集群，仅访问其 Amazon Elastic Kubernetes Service (Amazon EKS) API，并仅读取 TLS 存储桶的 `gig/` 前缀下的路由证书，标记为由 Hyperpod 推理创建。

**身份令牌。** 如果您的集群检查 JSON Web 令牌 (JWTS)，则使用 `--customer-identity-token`（`X-Amzn-SageMaker-Customer-Identity-Token` 标头）传递令牌，没有 `Bearer` 前缀。 令牌在 SIGv4 签名内传播，因此一个无符号令牌被拒绝，有 403 和重复的令牌 400。打开 JWT 检查每个服务于模型的集群或没有一个集群，因此请求在一个集群上不会成功并失败 另一个。

请求仅通过 AWS PrivateLink 访问您的集群，如图 1 所示。网关不记录或存储提示或完成。

## 运行网关

以下是配置网关的步骤。

### 添加集群

如文档中所述，准备新集群并在其上创建执行角色的 EKS 访问项。 还将新集群添加到执行角色权限策略的 `Resource` 列表中。 然后在网关的区域中调用 `AddInferenceGateway`，即使新集群位于另一个区域：

```bash
aws sagemaker add-inference-gateway \
  --identifier <gateway-name> \
  --region <region> \
  --cluster-arn arn:aws:sagemaker:<region-3>:<account-id>:cluster/<cluster-id-3> \
  --name <gateway-config-name-3> \
  --namespace inference-gateway
```

网关验证集群并在其健康后开始路由到它。 端点、其他集群和客户端不受影响。

### 分离集群

在网关的区域中调用 `RemoveInferenceGateway`：

```bash
aws sagemaker remove-inference-gateway \
  --identifier <gateway-name> \
  --region <region> \
  --cluster-arn arn:aws:sagemaker:<region-3>:<account-id>:cluster/<cluster-id-3> \
  --name <gateway-config-name-3> \
  --namespace inference-gateway
```

网关停止向集群发送新请求，允许飞行中的请求完成，并删除私有端点。 网关始终至少保留一个集群。 要完全撤回集群，请在其 `InferenceGatewayConfig` 中设置 `globalRouting.enabled: false` 并重新应用它。

### 删除网关

呼叫`DeleteGlobalInferenceGateway`：

```bash
aws sagemaker delete-global-inference-gateway \
  --identifier <gateway-name> --region <region>
```

网关端点停止服务，每个集群的端点继续服务。 删除网关后，使用 `globalRouting.enabled: false` 撤消每个集群，然后删除执行角色和为全局路由添加的 IAM 权限。

## 最佳实践和注意事项

*   **在发布之前计划您的组。** 决定哪些集群位于每个网关后面，每个集群上的 `modelName` 应该共享一个模型的流量。 如果您希望峰值流量跨区域溢出，请在两个区域中提供集群 headroom。
*   ** 仅发布您添加到网关的集群。** 未在任何网关中的已发布集群不会接收流量，但其网络负载均衡器仍在运行并已计费。
*   **覆盖每个模型。** `InferenceGatewayConfig` 中的每个调度器将模型名称映射到为其提供服务的 pod。 无法通过网关访问任何调度程序中的模型，并且请求它会返回 404 错误。
*   ** 保持附加配置完成。 每次从当前配置开始。
*   **pass** `--context` **在每个**上** `kubectl` **命令。** 您在多个集群中工作，因此请确保每个命令都针对您的意思是针对集群运行的。
*   **在需要时保留一个区域的工作负载。** 创建一个仅包含该区域中的集群的网关。

## 结论

在这篇文章中，我们介绍了 Amazon SageMaker Hyperpod 全局推理网关：跨 HyperPod 集群的 SageMaker 管理的一个端点，位于一个或多个区域。 网关根据 KV 缓存空间、队列深度、区域接近度和错误率选择集群，并在没有客户端更改的情况下将流量移出失败的集群。

全球推理网关可在 13 个 AWS 地区使用：美国东部（弗吉尼亚州北部）、美国东部（俄亥俄州）、美国西部（加利福尼亚州北部）、美国西部（俄勒冈州）、南美洲（圣保罗）、欧洲（法兰克福）、欧洲（爱尔兰）、欧洲 （伦敦）、欧洲（斯德哥尔摩）、亚太地区（东京）、亚太地区（孟买）、亚太地区（新加坡）和亚太地区（悉尼）。

当构建一个 AI 代理时，选择一个模型只是第一步。代理仍然需要工具、完成工作的指令、管理长时间会话中上下文增长的方法，以及在执行任何有后果的操作（如发放退款）之前的防护措施。

我们正在升级 Amazon Bedrock AgentCore Harness 以使用 Strands Harness，我们的开源代理Harness，今年早些时候发布的，根据 Apache 2.0 许可证提供。AgentCore Harness 还引入了生命周期钩子，因此您可以在代理循环的定义点应用自己的确定性检查和通知。

通过此升级，依赖托管默认值的代理将获得推荐模型、面向任务的系统提示、自动提示缓存（最初适用于 Amazon Bedrock 上的 Anthropic 模型）和主动上下文管理。它们还将获得用于规划、网页检索、文件系统访问、上下文卸载和任务委派的额外内置工具。这使代理在长任务期间具有更大的能力，允许它们跟踪子任务、减少上下文窗口使用并委派工作。通过钩子，您可以通过在特定生命周期检查点运行确定性代码，将非确定性 AI 行为转换为可预测、安全和受治理的工作流。

没有新的资源类型或需要采用的集成。你将自动在已经使用的 AgentCore 组件中获得这两项更新。

## Strands capabilities, on AWS

[Strands harness](https://strandsagents.com/docs/user-guide/harness/) 提供了一个带有推荐指南、工具和上下文管理的代理基础框架。 [Amazon Bedrock AgentCore harness](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness.html) 将该框架作为一个托管的 AWS 服务进行操作。 结果是一个生产级别的默认代理，不需要您自己组装和操作 harness 或其基础设施。

您无需提供计算资源，打包和托管代理循环，管理会话缩放，或操作工具执行基础设施。 每个会话都在 AgentCore 运行时中运行，一个安全的、内核隔离的微型虚拟机（microVM），这是 Amazon Bedrock AgentCore 的一个功能，具有托管计算、缩放和高可用性。

AgentCore 实现此功能的方式是将测试框架连接到生产代理所需的服务，包括会话持久性、流式响应、使用元数据、可观察性、AgentCore 内存、身份、网关、浏览器、代码解释器和客户提供的容器。您保留对模型、指令、工具、权限和生命周期策略的控制权，而 AgentCore 管理底层执行环境。

## 更强大的托管测试框架

测试框架现在在使用其托管默认值时提供了更好的体验：

* **当前推荐模型。** 当您省略模型时，Harness 使用一个推荐的默认模型，该模型会随着新模型的发布而演化，始终保持您的Harnesses更新。显式的Harness级和每次调用模型配置继续优先。
* **任务导向的指令。** 管理系统提示鼓励代理收集相关上下文，使用适当的工具，继续直到任务解决，适应失败或被拒绝的操作，并在报告完成之前验证其工作。默认系统提示会随时间改进以支持最新的Harness行为。
* \*\*自动提示缓存。\*\*对于使用Converse on Amazon Bedrock的支持模型，Harness缓存系统提示、工具定义和对话历史。使用相同提示和工具表面的重复调用可以使用低价的缓存读取令牌，减少输入处理延迟和成本。
* **主动上下文管理。** 默认情况下，Harness在上下文窗口达到可配置阈值时总结较旧的对话回合，同时保留最近的上下文。以这种方式保持上下文精简有助于Harness以[大约34%较低的令牌成本运行，低于其他领先的Harnesses](https://strandsagents.com/blog/we-ran-94000-trials-to-measure-the-cost-of-harness-choice/)。
* **上下文卸载。** 大型工具结果可以从立即模型上下文中移出。代理接收到预览，并可以在需要时检索完整结果，减少重复上下文使用而不失去对数据的访问。
* **调用规划。** `todo_write`工具维护一个结构化的任务计划，可以在同一会话中的后续调用中恢复，包括对话总结之后。
* **集中委托。** `subagent`工具将一个自包含的任务委托给一个新工作者，并将结果返回给父代理。工作者是内部的调用，不是一个单独管理的Harness资源，并共享调用限制和您的工具调用生命周期钩子。
* **Web检索。** `web_fetch`工具从指定的网页检索内容，以提供您的Harness最新的外部上下文。
* **粒度文件系统访问。** 使用单独的`read`、`write`和`edit`工具，您可以授予代理仅需要的粒度文件系统能力。

客户提供的 Model Context Protocol (MCP) 服务器、AgentCore Gateway（Amazon Bedrock AgentCore 的一个功能）、浏览器、代码解释器、内联函数、技能、内存和客户提供的容器继续通过现有的Harness接口工作。

## 默认推荐，可根据需要配置

Harness 管理其默认值，以便使用它们的代理接收当前 AgentCore 推荐的体验，当模型、指令、上下文管理和内置功能改进时。

显式配置始终优先：

* 配置模型 ID 以继续使用特定的模型。
* 配置 `systemPrompt` 以完全替换托管系统提示。
* 配置 `truncation` 以保持特定的上下文管理策略。
* 列出单个 `allowedTools` 选择器以维护固定工具集。

当 `allowedTools` 被省略或设置为 `["*"]` 时，Harness 提供当前推荐的内置工具集。由于此集可以随时间获得新的功能，因此具有固定安全或功能边界的应用程序应仅列出它们需要的工具。

例如，以下配置允许只读文件系统访问和Web检索，而不授予shell访问或文件修改权限：

```json
{
    "allowedTools": [
        "read",
        "web_fetch"
    ]
}
```

## 使用生命周期钩子管理后果行为

使用生命周期钩子，您可以在代理循环的定义点运行自己的确定性代码。例如，AWS Lambda函数可以允许或拒绝请求或工具调用，Amazon Simple Notification Service（Amazon SNS）主题或Amazon EventBridge事件总线可以接收通知以记录活动或启动异步工作流。

Harness支持四个生命周期事件：

**事件**

**何时运行**

**Lambda拒绝的效果**

`before_invocation`

在代理处理请求之前

停止调用，返回`hook_stopped`

`before_tool_call`

在模型提出工具调用并在执行之前

跳过工具调用，代理循环继续

`after_tool_call`

在工具结果存在之后

保留结果并在进一步推理之前停止

`after_invocation`

在调用完成之后

报告决定，已经流出的输出不能被撤回

仅 Lambda hooks 可以改变 agent 循环。它们以同步方式运行，并返回 allow 或 deny，带有可选的原因。SNS 和 Amazon EventBridge hooks 是通知，不会阻塞 agent 循环。

例如，客户支持代理可以在 `before_tool_call` hook 检查每个退款是否超过批准限制之前自行调查订单，而该 hook 会在退款工具运行之前检查每个退款。以下配置将该 Lambda 函数附加到Harness：

```json
[
    {
        "beforeToolCall": {
            "name": "refund_policy",
            "target": {
                "lambda": {
                    "arn": "arn:aws:lambda:us-west-2:123456789012:function:refund-policy",
                    "timeoutSeconds": 10,
                    "failureMode": "deny"
                }
            }
        }
    }
]
```

函数在 hook有效负载中接收到拟议的工具调用，并返回一个决定：

```python
def lambda_handler(event, _context):
    tool = event["context"]
    if tool["toolName"] == "issue_refund" and tool["toolInput"]["amount"] > 500:
        return {"decision": "deny", "reason": "Refund exceeds the $500 auto-approval limit."}
    return {"decision": "allow"}
```

当函数拒绝该调用时，Harness 跳过退款，代理继续，因此它可以告诉客户该请求已升级。每个决定也出现在 `InvokeHarness` 响应流中作为 `hookEvent`：

```json
{
    "hookEvent": {
        "name": "refund_policy",
        "type": "before_tool_call",
        "decision": "deny",
        "reason": "Refund exceeds the $500 auto-approval limit."
    }
}
```

hooks 也适用于子代理。当代理委托任务时，子代理所做的每个工具调用都会通过相同的 `beforeToolCall` 和 `afterToolCall` hooks 运行，因此委托无法绕过您的退款政策。调用级别的 hooks（`beforeInvocation`、`afterInvocation`）对于整个调用运行一次。

您可以使用 `CreateHarness` 或 `UpdateHarness` 配置钩子。如果 Lambda 函数超时或返回错误，钩子将应用其 `failureMode`，默认为 deny。有关超时、有效负载字段和上下文限制的更多信息，请参阅 Amazon Bedrock AgentCore 开发者指南中的 [生命周期钩子](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness-lifecycle-hooks.html)。

要查看所有事件和目标类型如何协同工作，请尝试 Amazon Bedrock AgentCore [samples repository on GitHub](https://github.com/awslabs/agentcore-samples/tree/main/01-features/01-harness/02-use-cases/05-refund-desk-hooks) 中的 Refund Desk 示例。一个六步骤的导览展示了所有四个生命周期事件以及 AWS Lambda、Amazon SNS 和 Amazon EventBridge 目标。它还展示了对客户提供的内联函数结果的验证以及 `failureMode` deny 和 allow 之间的区别。

## 使用 AgentCore CLI 运行多代理研究协调器

创建一个测试框架只需要一个命令。您可以命名它并设置所需的指令、上下文策略和限制。这个例子创建了一个研究协调员：一个具有任务导向系统提示和摘要基于截断的测试框架。在单次调用中，它运行研究人员、合成器和审查员作为子代理，并返回一个综合报告。您可以获得多代理编排和上下文管理，而无需提供基础设施或自己编写委托代码。

`agentcore harness` 命令直接调用测试框架 API，因此您不需要 CLI 项目或部署步骤。使用 npm 安装 AgentCore CLI，即 Amazon Bedrock AgentCore 的一个功能：

```bash
npm install -g @aws/agentcore
```

CLI 使用您的默认 AWS 凭证。它没有 `--profile` 标志，因此如果您想要使用特定配置文件，请设置 `AWS_PROFILE` 环境变量。将协调员的指令从示例保存为 `system_prompt.md` 文件，并将其放在您的工作目录中。

### 创建测试框架

此命令传递协调器的系统提示，一个总结策略保持最近 30 条消息完整，随着对话的增长，并且限制足够高以适应整个工作流程。由于它省略了模型、内存和执行角色，Harness 使用当前的 AgentCore 推荐模型和托管内存，CLI 在 IAM 中为您创建一个执行角色。

```bash
HARNESS_ID=$(agentcore harness create --region us-west-2 --json \
--name ResearchCoordinator \
--system-prompt "$(cat system_prompt.md)" \
--truncation '{"strategy":"summarization","config":{"summarization":{"summaryRatio":0.3,"preserveRecentMessages":30}}}' \
--max-iterations 100 \
--timeout-seconds 3600 \
| jq -r '.harness.harnessId')
```

创建是异步的。等待创建完成。最后一个命令应该打印 `READY`：

```bash
while [ "$(agentcore harness get --region us-west-2 --id "$HARNESS_ID" --json | jq -r '.harness.status')" = CREATING ]; do sleep 10; done

agentcore harness get --region us-west-2 --id "$HARNESS_ID" --json | jq -r '.harness.status'
```

### 发送提示

使用新的会话 ID 调用您的 Harness。从一个基本问题开始。协调器直接回答它，而不调用其子代理：

```bash
SESSION_ID=$(uuidgen)
agentcore harness invoke --region us-west-2 \
--id "$HARNESS_ID" \
--session-id "$SESSION_ID" \
--prompt "What is the current trending topic in AI?"
```

然后在同一个会话中请求完整的研究报告。协调器计划工作并按顺序委托给研究员、合成器和审查员。它最多运行一个修订周期，如果审查员要求，并交付最终报告。重用会话 ID 在同一个环境中继续对话。

```bash
agentcore harness invoke --region us-west-2 \
--id "$HARNESS_ID" \
--session-id "$SESSION_ID" \
--prompt "Perform a full research report on how data shapes innovations in the tech industry. Use specialized subagents to complete this task. In the final output, clearly state which part each subagent was responsible for, followed by their specific findings."
```

使用 `--prompt`，CLI 在对话结束时以 JSON 格式打印完成的记录。研究运行大约需要 10 到 15 分钟。要跟踪其工作过程，请省略 `--prompt`，CLI 将打开一个交互式聊天界面。

同样的 Python 示例（使用 boto3），包括完整的系统提示，已在 GitHub 的 AgentCore 示例仓库中提供。

### 清理

完成后删除测试框架。这也会删除其托管内存，除非您传递 `--delete-managed-memory false`。CLI 创建的执行角色将保留在您的账户中，因此如果您不再需要它，请在 IAM 控制台中删除它。

```bash
agentcore harness delete --region us-west-2 --id "$HARNESS_ID"
```

## 推出和兼容性

11月11日，AgentCore 测试框架开始向新旧测试框架推出基于 Strands 的测试框架支持体验。无需客户采取任何操作。

您显式提供的配置将保持不变。省略模型、系统提示或 `truncation` 配置的测试框架，或者使用 `allowedTools: ["*"]`，将接收升级的托管默认值。

如果您的应用程序需要固定行为或固定能力边界，请显式配置这些设置。
